# Неочевидные места (грабли)

## B24Client НЕ потокобезопасен — все вызовы через очередь `_run`

**Где:** `server/src/adapters/b24.js`.

`B24Client` держит общую сессию (куки, `sessid`). Конкурентные запросы (доска поллит
`/dashboard` + параллельный `/users` или мутация) рвут сессию — портал отвечал **«Client Error»**.
Фикс: `B24Adapter._run(fn)` сериализует ВСЕ операции клиента через promise-цепочку. Любой новый
метод адаптера, дёргающий `this.client()`, оборачивать в `this._run(...)`. В одиночку баг не
воспроизводится (гонки нет) — не «оно и так работает».

## flock на `orch.lock` для мутаций фабрики = дедлок

**Где:** контракт мутаций (`server/src/modules/factory`, `lib/factory-cli`-логика).

Демон оркестратора держит `orch.lock` НЕПРЕРЫВНО весь `run_pipeline` (включая ожидание на
воротах). Брать блокирующий `flock` на него из кокпита — повиснуть навсегда; `-n` — всегда
отказ. Ворота одобряются именно когда лок занят. Поэтому: запуск/resume — через `factory bin`
(он берёт `launch.lock`), записи в реестр — прямой upsert (last-writer-wins, как Python-дашборд).
`pipeline-set.sh` лока не берёт вовсе.

## Контракт запуска — по состоянию, не по stdout

`factory bin` при ошибке аргументов/профиля/маршрута → `rc≠0`; при занятом локе → **`rc=0`**
(«занято» и «успех» неразличимы по коду). Исход читаем из состояния: `ORCH_PID` + `/proc/<pid>/cmdline`
(содержит `bin/factory` и номер задачи). См. `POST /api/tasks/:id/launch`.

## Service Worker кэширует — правки не видны без «Обновить»

PWA (`vite-plugin-pwa`, `registerType: 'prompt'`) кэширует ассеты. После пересборки страница
крутит СТАРУЮ версию, пока не появится баннер «Доступно обновление» → «Обновить» (`usePwaStore`).
При отладке в браузере это выглядит как «правка не применилась» — на самом деле нужно обновить SW.
`index.html` отдаётся с `no-cache`, ассеты (`/assets/*`) — `immutable`.

## Service Worker требует secure context — по `http://<IP>` PWA НЕ существует

Не «работает хуже», а не поднимается вовсе: по спеке `navigator.serviceWorker` доступен только
в secure context, исключение сделано лишь для `localhost`/`127.0.0.1`. Замер с `http://192.168.3.107:8140`:
`'serviceWorker' in navigator === false`, `isSecureContext === false`. Значит на планшете/рабочем компе
нет ни установки PWA, ни precache, ни баннера обновления, ни оповещений, ни микрофона — а на мозге
через `localhost` всё это работает, поэтому со стороны незаметно.

Следствие для архитектуры: **HTTPS (Tailscale Serve) — условие существования PWA на любом окне
кроме мозга**, а не улучшение. Нативные оболочки (Electron/Capacitor) для этого НЕ нужны и отвергнуты:
Electron на Android не собирается вообще, а упаковка `dist` внутрь пакета ломает обновления — SW
тянет новую версию только со своего origin, а у упакованного фронта origin локальный (`app://`,
`https://localhost` у Capacitor; на `file://` SW не поддерживается), обновляться неоткуда. Тонкое
окно на remote-адрес мозга + включённый SW даёт и мгновенный старт, и обновления сами.

## Осторожно: проверки окружения гоняются в песочнице с урезанным PATH и сетью

`which <пакет>` и `curl` в этой среде врут — дали ложный вывод «Tailscale не установлен», хотя
пакет стоял и демон работал. Существование хостовых пакетов проверять через `dpkg -l`/`pgrep`/
`ip addr`, доступность сети — не по одному упавшему curl.

## Установка «как приложение»: три условия, иконки — отдельный блокер

Standalone-запуск (своя иконка в лончере, отдельная карточка в «недавних», splash, БЕЗ адресной
строки) даёт только настоящая установка PWA — Android собирает WebAPK. Chrome предложит её лишь
когда выполнено всё сразу: **https** + **манифест с иконками 192 и 512** + **живой SW**.

Пункт «Добавить на главный экран» в меню Chrome доступен на любом сайте, включая http, но для
неустанавливаемого сайта делает просто закладку — открывается в браузере с адресной строкой.
Это НЕ то же самое, что установка, и выглядит как сайт.

Иконок в проекте долго не было вовсе (favicon зашит инлайном в `index.html` как `data:`-URI,
`icons` в манифесте отсутствовал) — то есть установка была бы заблокирована даже под https.
Сейчас: `web/public/icon-{96,192,512}.png` + `icon-maskable-512.png`, генератор
`web/scripts/gen-icons.py` (рисует через Pillow — растеризатора SVG в системе нет).
`maskable` обязателен отдельным файлом: Android режет иконку под форму лончера, поэтому рисунок
там вписан в safe zone (~80% полотна), иначе рамку обрезает по краям.

Кнопка установки — своя (`usePwaStore.canInstall` / `install()`, плашка `.instbar` в `AppShell`),
на плашку Chrome не рассчитываем: на Android она показывается по эвристикам и может не появиться.
Событие `beforeinstallprompt` одноразовое на загрузку — слушатель вешается в `main.js` сразу после
монтирования (`initInstall()`), позже уже поздно. В headless-браузере это событие НЕ приходит,
поэтому кнопка проверяется только на живом устройстве.

## Подразделы настроек не наследуют стили `SettingsView` (scoped CSS)

`.card`, `.row`, `button`, `.msg`, `.primary` объявлены в `SettingsView.vue` под `<style scoped>`,
поэтому на вынесенный дочерний компонент (`views/settings/*.vue`) они НЕ действуют — глобальный
только `.muted` (в `styles.css`). Симптом обманчивый: вёрстка выглядит «поехавшей» (текст
наложился на картинку, у карточек нет фона), и кажется, что дело в разметке, а не в отсутствии
правил. Новый подраздел обязан повторить эти классы у себя (сверять с `SettingsView`, чтобы вид
не расходился).

## Вход в кокпит: один пользователь, сессионная cookie, гард на ВЕСЬ /api

`lib/auth-store.js` (учётка + сессии), `plugins/auth.js` (гард), `modules/auth` (эндпоинты),
`views/LoginView.vue` + `stores/auth.js`. Пароль — scrypt-хеш в `server/.state/auth-account.json`
(0600), сессии — в `auth-sessions.json`, поэтому рестарт сервера не выкидывает с планшета.

**Закрыто ВСЁ `/api`, включая GET и upgrade вебсокета** — прежняя модель «читать свободно
в доверенной сети» не годится: кокпит отдаёт историю чатов, дифы, состояние фабрики, а терминал
даёт шелл. Хуки Fastify выполняются и для WS-роутов, поэтому терминал закрыт тем же гардом
(проверено: upgrade без сессии → `401`, а не `101`). Публичны только `/api/auth/{state,login,setup}`
и `/api/health`.

**401 вместо серверного редиректа — сознательно.** Фронт это PWA: редирект на навигации
конфликтует с service worker'ом (тот отдаёт закешированную оболочку вместо страницы логина).
Поэтому статика публична (секретов в ней нет), оболочка грузится всегда и сама показывает вход
по 401. Проверено: отзыв сессии на сервере → приложение само возвращается на экран входа.

**`COCKPIT_TOKEN` УБРАН, не возвращать.** Он обязан был дублироваться во фронт через
`VITE_COCKPIT_TOKEN`, а Vite подставляет env в бандл на сборке — секрет лежал в публичном JS
открытым текстом (проверено сборкой с тестовым значением: значение находится в `index-*.js`).
При открытом чтении это не защита вовсе. Заодно из терминала убран `?token=` — секрет в query
оседает в логах, cookie этого не делает.

**Грабля scrypt:** при `N=32768, r=8` требуется ровно 32 МиБ, и это же дефолтный `maxmem`
в Node → `error:030000AC ... memory limit exceeded`. Передавать `maxmem` явно (у нас 64 МиБ).

**КРИТИЧНО: гард решает по МАТЧЕННОМУ РОУТУ, а не по `request.raw.url`.** Роутер Fastify
декодирует percent-encoding ПЕРЕД сопоставлением, поэтому `/%61pi/terminal` попадает
в обработчик `/api/terminal`. Первая версия гарда сравнивала сырую строку с префиксом `/api/`
— и такой запрос проходил как «статика». Был полный обход входа: анонимно читались
`/api/chat/store` и `/api/tasks`, проходили POST-мутации, а PTY-вебсокет отдавал
`101 Switching Protocols`, то есть шелл на машину без пароля. Правильный источник истины —
`request.routeOptions.url` (шаблон вида `/api/tasks/:id/graph`): он не зависит ни от кодирования,
ни от query, ни от лишних слэшей. Строковые проверки сырого URL для авторизации НЕ использовать.

**`/shots/*` и `/demo/*` тоже под гардом** (`PROTECTED_STATIC`). Это скриншоты приёмки и демо
тестируемого приложения — данные проектов и содержимое задач; имена предсказуемы
(`t<номер задачи>-…`). Раньше отдавались анонимно (проверено: реальный PNG приходил без сессии).
Публичной остаётся только оболочка `web/dist` — без неё не показать экран входа.

**`trustProxy` НЕ включать без реального прокси.** С ним клиент сам назначает себе
`request.ip` через `X-Forwarded-For`, и лимит попыток входа обходится сменой заголовка
на каждый запрос. TLS терминируется в самом Fastify, прокси перед кокпитом нет.

**`/api/health` не публичный:** отдаёт имя хоста и абсолютные пути (`stateDir`, `factoryHome`),
а экрану входа не нужен — тому достаточно `auth/state`.

**Внутренний токен для дочерних процессов.** `permission-prompt-tool` чата живёт в дочернем
процессе `claude`, cookie у него нет, а достучаться до сервера обязан. Для этого в `app.js`
генерируется `internalToken` (`randomUUID()` на каждый запуск, только в памяти), уезжает в env
дочернего процесса как `COCKPIT_INTERNAL` и принимается гардом в заголовке `X-Cockpit-Internal`.
На диск и в конфиг не попадает.

**Смена пароля сбрасывает все сессии** (украденная cookie перестаёт работать), но текущему
устройству сразу выдаётся новая — иначе владелец выкинул бы сам себя. `setup` доступен ровно
пока пароль не задан: потом только `409`, чтобы никто не переустановил пароль в обход.

**Поллинги надо гасить при потере сессии** (`stopPolling` у board/system, зовётся из `App.vue`):
иначе интервалы молотят в закрытый API и сыпят 401 в консоль на экране входа (было 14 ошибок).

**Баннер обновления PWA обязан быть ВНЕ ветки авторизации** (`shared/ui/UpdateBanner.vue`,
рендерится в `App.vue` рядом с `LoginView`, а НЕ внутри `AppShell`). Иначе: service worker держит
старую сборку, пользователь на экране входа, а кнопки «Обновить» нет — оболочка с баннером
рендерится только после входа, и залипшая версия не лечится из интерфейса. Само обновление
авторизации не требует (работает с SW, `sw.js` — публичная статика). Проверено полным циклом:
новая сборка → `reg.update()` → баннер появился НА ЭКРАНЕ ВХОДА → клик → версия применилась.

**Связка с TLS:** по http пароль уходит открытым текстом, поэтому для доступа вне localhost TLS
обязателен, и от него же зависит флаг `Secure` у cookie (на http его ставить нельзя — браузер
выбросит cookie и вход сломается молча). Экран входа честно предупреждает, когда TLS выключен.

## Доступ к кокпиту с других устройств — что уже отвергнуто (2026-07-25)

Направление «открыть кокпит на планшете как приложение» откатано, но выводы стоит помнить,
чтобы не проходить круг заново:

- **Свой CA не даёт «автоматически»**: установка корневого сертификата — решение о доверии на
  уровне ОС, из браузера её не выполнить (файл → системные настройки → «Сертификат ЦС» → PIN →
  предупреждение про мониторинг сети). Для «другой человек открыл и поехало» не подходит в принципе.
  Технически работало: свой CA + лист с SAN на LAN- и tailnet-адрес, проверка цепочки проходила.
  Важная деталь на будущее: серверный лист не длиннее **398 дней**, и браузеры смотрят ТОЛЬКО
  в subjectAltName (CN игнорируется).
- **Tailscale не подходит для Android**: активным может быть только ОДНО VPN-приложение, Tailscale
  вытеснит используемый VPN. Плюс приложение недоступно в Play в ряде стран (есть прямой APK).
  На самом мозге конфликта с sing-box НЕ было: Tailscale не забирает default route (в его таблицу
  уходят только 100.64/10, MagicDNS-резолвер и tailnet-IPv6), sing-box держит свой default
  в отдельной таблице, `ExitNode: False`.
- **`tailscale funnel`** (публичная ссылка на ts.net с доверенным сертификатом, посетителю не нужно
  ничего устанавливать) — единственный путь с нулём шагов у открывающего, но включать его нельзя
  без авторизации: при пустом `COCKPIT_TOKEN` наружу уйдёт открытый PTY-терминал и открытые мутации.

## Адрес стенда: хост берём у мозга, `localhost` подставлять нельзя

`web/src/shared/sandbox.js` (`sandboxUrl(port)`) строит ссылку на песочницу из хоста МОЗГА
(`api.base || location.origin`) и всегда форсит схему `http` — стенды это обычные dev-серверы без TLS.
Раньше в `PipelineView.vue` был хардкод `http://localhost:${fePort}`: на мозге он случайно работал,
а из окна `localhost` — это само устройство-окно, поэтому стенд не открывался.

Схему форсим намеренно: когда кокпит поедет по https через Tailscale, ссылка на `http://<хост>:5193`
останется рабочей — переход по ссылке это top-level navigation, блокировка смешанного контента
на неё не распространяется (в отличие от iframe — стенд в iframe засунуть не получится).

Отдельный env-оверрайд хоста стендов НЕ добавляли: вывод из хоста мозга + форс `http` покрывает
и текущий `http://<IP>`, и будущий Tailscale-https. Появится экзотика (реверс-прокси на другой
машине) — добавить тогда, а не «на всякий случай».

## Никаких проектных хардкодов в коде

Профиль — из реестра задачи (`registry.PROFILE`), список профилей — сканом
`factory/profiles/*.graph.json` (`discoverProfiles`), портал/креды B24 — из «Настроек» (`.state`),
пути (venv, снос стенда, factory bin) — через env (`COCKPIT_*`). Пустой кокпит НЕ знает ни про
`arsenkin`, ни про `b24.discript.ru`. Не возвращать `|| 'arsenkin'` и подобное.

## Медиа: venv и модель НЕ дублируем

`server/src/lib/media/` — перенос из b24-mcp. Python-venv (492 МБ) и модель whisper (1.5 ГБ)
**переиспользуются** через `COCKPIT_MEDIA_PYTHON` (путь к `python` из venv) и `HF_HOME`
(кэш модели). `transcribe.py` берётся рядом с копией. `preflight.js` читает `COCKPIT_MEDIA_PYTHON`
на импорте — сервер должен стартовать С этим env (см. systemd-юнит). `doctor` проверяет
ffmpeg/ffprobe/venv/faster-whisper.

## Сервер — host-native, не контейнеризуется

Командует host-уровнем: `factory bin`, `/proc`, `~/.factory/state`, `docker`. В контейнере
`factory` побежал бы внутри контейнера — модель «мозга» ломается. Поэтому systemd, не Docker.
Фронт (статика) — можно отдельно (nginx/VPS), но по умолчанию его отдаёт сам сервер.

## `ttNNNN.pipeline` — призраки

В `~/.factory/state` есть файлы с двойным префиксом `tt*` (баг двойного `t`). Глоб задач —
строго `^t(\d+)\.pipeline$` (см. `FactoryStateAdapter.listTaskIds`), призраки отсекаются.

## Запуск фабрики — ТОЛЬКО в отдельный systemd-scope (иначе рестарт кокпита убивает прогоны)

Прогон #7803 умер на этапе BUILD: сервер кокпита в тот момент работал под systemd-юнитом
`cockpit-server.service`, фабрика была запущена ручкой `launch` как его потомок — и жила
в cgroup юнита. Когда юнит остановился (рестарт сервера), systemd зачистил cgroup ЦЕЛИКОМ:
TERM демону фабрики и его claude-агенту (в stages.log: «демон остановлен сигналом TERM»).
`nohup`/`setsid` от cgroup-kill НЕ спасают. Фикс в `modules/factory` launch: фабрика
спавнится через `systemd-run --user --scope --collect --unit=factory-tNNNN` — отдельный
transient scope, жизнь кокпита её не касается (fallback без systemd — detached spawn
с выводом в `state/tNNNN.launch.log`, не в пайпы). Резюм после смерти демона: повторный
POST launch — демон продолжает по реестру (цепочка начинается заново со SCOUT, стенд
переиспользуется).

## Два владельца порта 8140: systemd-юнит vs bin/restart

`deploy/install.sh` ставит user-юнит `cockpit-server.service` (Restart=always). Если гонять
сервер руками через `bin/restart` (setsid), юнит уходит в вечный crashloop по EADDRINUSE
(счётчик набил 5000+ рестартов), а в окна свободного порта успевает перехватить порт —
и тогда часть запросов обрабатывает ОН (так фабрика 7803 и оказалась в его cgroup).
Правило: на время ручной разработки `systemctl --user stop cockpit-server`, боевой режим —
только юнит. Диагноз перехвата: `journalctl --user -u cockpit-server`.

## Ромб «Песочница» на графе — статус из реальности, не из цепочки

Прогресс сборки стенда пишется в `state/tNNNN.stage` («время|шаг/всего|подпись», 11 шагов,
клон данных — самый долгий). Раньше ромб красился «done», как только тронут любой этап цепочки,
и клик показывал «этап пройден» во время сборки. Теперь `getTaskGraph` выводит статус честно:
порты в env есть → done; идёт сборка при живом демоне → run; демон умер посреди сборки → fail;
пока портов нет, футер карточки конвейера показывает «стенд строится · N/11 · подпись шага».

## VS Code в кокпите (`code serve-web` + прокси)

- **Движок:** `code serve-web` (VS Code CLI). Один экземпляр (`lib/vscode-server.js`, ленивый старт
  по `POST /api/vscode/ensure`); папку каждая задача открывает через `?folder=`. Без папки тоже поднимается.
