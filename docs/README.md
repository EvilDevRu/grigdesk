# Документация Cockpit

Документация хранится отдельно от исполняемого кода и группируется по подсистемам.
Текущую архитектуру описывают документы движка, а работу с продуктом — `cockpit/guide/`.

Общая документация описывает продукт и контракты, но не перечисляет реальные подключённые
проекты: без их названий, доменов, стеков, task ID и конкретных путей в `profiles/`.
Проектная конкретика хранится только в локальном `profiles/<name>/README.md`; в общих
примерах используются `<PROFILE>`, `<TASK>` и названия режимов `isolated`/`shared`.

Здесь лежит только канон — то, что уже внедрено. Планы, разборы и черновики живут в
`docs/plans/`: этот каталог Git игнорирует, у каждого он свой, и ссылаться на него из
канона можно только текстом, а не Markdown-ссылкой (иначе у остальных она ведёт в пустоту).

То же правило действует для базы знаний. Накопленный опыт конкретной установки лежит в
локальной базе, её карты `cockpit/*.md` Git игнорирует, а адреса `#/knowledge/<uuid>`
разрешаются только на той машине. В репозиторий попадает лишь то, что нужно любому
пользователю Кокпита, — и ссылаться из канона на карты нельзя по той же причине.

## Работа с Cockpit

- [guide/tasks.md](cockpit/guide/tasks.md) — как оформить задачу и что с ней делает триаж.
- [guide/gates.md](cockpit/guide/gates.md) — где конвейер останавливается и чего ждёт от человека.
- [guide/projects.md](cockpit/guide/projects.md) — паспорт проекта, его репозитории и API раздела.
- [guide/routes.md](cockpit/guide/routes.md) — черновики маршрутов, проверка, публикация и откат.
- [guide/knowledge.md](cockpit/guide/knowledge.md) — локальная база знаний, поиск, CLI и
  резервная копия.
- [reference/runtime-contracts.md](cockpit/reference/runtime-contracts.md) — SSH-плагин, надзорный
  доступ к базам и Telegram-пульт.

## Релизы

- [releases.md](releases.md) — версия продукта, стабильный канал и восстановление после ошибки обновления.
- [release-notes-template.md](release-notes-template.md) — шаблон заметок к GitHub Release.

`CLAUDE.md` — общий вход для всех исполнителей: Claude Code загружает строки `@...`
сам, а `AGENTS.md` направляет по тем же ссылкам исполнителей без такого синтаксиса.
Единственная строка `@` в нём ведёт в локальный `CLAUDE.local.md` с оглавлением базы
знаний: этого файла в репозитории нет, и его отсутствие — штатное состояние клона.

Целостность относительных ссылок проверяет:

```bash
node --test tests/docs/*.test.mjs
```

Все безопасные проверки перечислены в [tests/README.md](../tests/README.md).
