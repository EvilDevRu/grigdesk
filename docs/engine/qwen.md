# Qwen Code в конвейере

Раннер `engine/lib/runners/qwen.sh` использует внешний npm-пакет
`@qwen-code/qwen-code`. Собственный бинарник Qwen не собирается. Выбор CLI идёт через
`factory_external_bin`; host-wrapper `qwenRunner.mts` поставляется helper-ом `qwen-runner`.

## Каталог и запуск

Metadata-only режим wrapper-а получает тот же снимок `modelProviders`, что и чат, и
подтверждает полные native ids через ACP без prompt. `models.tsv` имеет 11 полей,
семейство `default`; default-политика — `default/latest/auto`. Неизвестные усилия не
выдумываются: model options содержит единственное пустое значение. Встроенный `high`
движка не передаётся CLI; native reasoning сохраняется из настроек модели.
Доступная модель, выбранная через `model.name` и `security.auth.selectedType` CLI,
получает первое предпочтение; одинаковые bare ids разных типов не подменяют её маршрут.

Без исходного `modelProviders` общий resolver получает каталог выбранного сервиса API
и готовит настройки только в приватной среде CLI. Ручной JSON после установки не требуется.
`GRIGDESK_QWEN_SERVICE` доезжает от сервера как параметр хоста; без выбора используется
Alibaba Model Studio в Сингапуре. Ключ остаётся в защищённом окружении. Явная конфигурация
CLI имеет приоритет и не переписывается. HTTP-отказ discovery не запускает подбор других
сервисов и не подменяется фиксированным списком моделей.

Источник discovery закрепляет `GRIGDESK_QWEN_CONFIG_ROOT`. Режим `state-only` использует
cwd=`STATE_DIR`; `workspace-write` — рабочую папку. Дополнительные roots остаются
read-only. Перед моделью wrapper проверяет private prompt и пути внутри run directory,
а также server-owned task/stage/run/epoch и канал запроса статуса.

## Защита и завершение

Требуются Linux, bwrap, ACP v1 и обязательный private final guard. Пользовательский
settings-файл в отдельном home допускает атомарное сохранение выбранной модели самим CLI.
Системный снимок настроек остаётся read-only и определяет доступные провайдеры.
Корень песочницы и служебные родители mounts тоже read-only; отдельный `TMPDIR`
остаётся доступным для временных файлов CLI. ToolSearch-мост отключён: выданные MCP
сразу объявляются прямыми инструментами и проверяются final guard.
Ключи передаются через окружение, системной службе — через `EnvironmentFile` 0600;
prompt хранится private-файлом, не в argv.

Вопросы получают немедленный отказ. Статусный helper работает вне песочницы; модели
выдаётся только приватный IPC к его MCP, без control root. Статус принимает хост по
exact identity; текст ответа модели не завершает этап. Отмена завершает собственное
дерево процессов и освобождает reader lease после выхода CLI.
При отказе вызова общий stdio-мост сохраняет request id в JSON-RPC error: клиент
получает отказ, а следующий корректный статус выполняется без ожидания тайм-аута.

`rc=0` классифицируется как `ok`, `124` — `timeout`, прочее — `unknown` без
автоматического replay. Native delegation, fanout capability и engine native resume
не заявлены. Счётчик делегирований разбирает retained JSON-события. Billing остаётся
`qwen-jsonl-unknown` / unavailable, без заимствования чужого usage dialect.

## Граница доказательств

Версия CLI 0.27.2 проверена с локальным синтетическим API: каталог, read/write/shell,
шаги, отмена, resume в новом процессе, разрешённый MCP, запрет прямого SSH и выхода
за рабочую папку. Отказ API сохраняет причину без полного ключа.

Настоящий launcher с тестовым CLI проходит `state-only` и `workspace-write`, отказ
вопроса, stale/current status MCP, файловые эффекты, timeout и частичный отказ без
повтора. Доставка двух динамических ключей проверена в systemd/detached, с access
service и без него. Source и собранный helper возвращают структурный `wrapper_error`
при некорректных аргументах.

Платный smoke, установка через карточку и браузерная приёмка требуют отдельного
подтверждения на стенде; до них допуск к реальным задачам не заявляется.
