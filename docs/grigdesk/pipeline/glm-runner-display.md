# Модель, действия и отказ GLM в конвейере

Сервер приводит составной modelRef GLM к имени модели одним помощником
`runnerModelName`: `["zai","glm-5.3"]` отображается как `glm-5.3`. Это представление
DTO реестра, попыток, карточки остановки и live-ленты. Исходный modelRef запуска,
каталог моделей и lifecycle-контракт не меняются; браузер JSON-пару не разбирает.

До запуска служебное семейство `default` получает `models.glm.label` из первой
модели `GLM_FACTORY_MODELS` — каталог публикует её с наивысшим приоритетом.
Отсутствующая модельная карта GLM использует то же штатное семейство `default`.
Если есть телеметрия GLM, подпись берётся из последней попытки этого исполнителя,
предпочитая `RESOLVED_MODEL` перед `MODEL`. Фактическая модель реестра текущего
исполнителя имеет приоритет над предварительной подписью.

`readAgentLive` понимает события host-wrapper-а GLM: `tool_call` открывает действие
с именем инструмента и статусом `run`, `tool_result` завершает последнее открытое
действие как `done`. Результат без открытого вызова пропускается. `wrapper_error`
добавляет строку ошибки с очищенным сообщением и кодом; `glm_start` обновляет модель.
Аргументы инструментов не восстанавливаются: wrapper их не публикует.

Конкретная причина GLM имеет вид `{message} ({code})` из общих каталогов RU/EN.
Существующий путь `FAILURE_*` → `DISPATCH_RESULT_DETAIL` сохраняется; класс отказа
остаётся `unknown`, автоматический повтор или переключение не разрешаются.
Сводка и граф дополняются через `enrichRunnerStall`, включая старые остановки.
`runner.attempts[].failureDetail` перекрывает общую подпись результата в журнале
окна узла и занимает отдельную строку с переносом длинной причины.
Для старой попытки без mirror сервер читает последние 256 KiB её
`events.jsonl` через тот же защищённый файловый помощник, что и карточка остановки.
Успех, таймаут, сигнальная остановка и ручное переключение не наследуют причину.

Проверки: `factory-activity.test.js`, `runner-state.test.js`, `runner-stall.test.js`,
`runner-failure.test.js`, `runner-display.test.js`,
`pipeline-runner-override.component.test.js`; публикация diagnostic mirror —
`tests/engine/integration/runner-failure-detail.sh`.
