# Обновление Git при запуске конвейера

`server/src/modules/factory/index.ts` перед резервированием слота вызывает
`maybeRefreshRepos`, если включена общая настройка `gitRefreshBeforeRun`
(«Обновлять репозитории перед запуском»). Репозитории берутся из профиля триажа.
Новый запуск через API проходит тот же шаг, что и запуск из интерфейса.

`server/src/lib/gitRefresh.ts` сначала выполняет `git fetch --quiet`, затем проверяет
текущую ветку. Чистые `master` и `main` могут обновляться через `pull --ff-only`;
на остальных ветках, включая `dev`, выполняется только fetch. Таким образом,
проверка ветки не предотвращает обращение к удалённому репозиторию.

Общий шаг не учитывает, создаёт ли конкретный профиль worktree от локальной ветки
или от ссылки origin. Если база профиля — локальная `dev`, этот fetch её не обновляет
и не нужен для получения выбранной базы задачи. Базу определяет сам профиль.

Отказ fetch возвращается в `gitRefresh` ответа запуска с `updated: false` и причиной;
сам по себе он не блокирует резервирование слота и запуск. Результат `outcome: launched`
означает, что запуск состоялся, даже если рядом есть сообщение об отказе обновления Git.

Настройка общая для новых запусков триажа и конвейера. Её отключение меняет поведение
всех профилей, поэтому устранять лишнее обращение одного профиля глобальным переключением
без решения владельца нельзя.
