# Достоверность приёмки

Повторный AUDIT/BROWSER сначала проверяет открытые findings, исправления и их последствия.
Новый доказанный дефект исходного требования остаётся блокером независимо от номера прохода.
Прошлый вердикт не является базовой ревизией; пропущенный дефект не становится deferred.
Вкусовые замечания, расширение задачи и повтор закрытого без новых доказательств исключены.

`scope_expansion_reason` в `engine/lib/attempt-stage-state.sh` ограничивает автономный ремонт:
одно расширение допускается, следующие могут остановиться через `no-progress`; исключения
для якорей новых артефактов сохранены. Остановка хранит failed-verdict и открытые findings.
Сохраняются повтор одного набора после ремонта, осцилляция, устойчивое ядро, лимиты дуг и
суммарный бюджет возвратов в target. Они не дают права объявить работу принятой.

Обязательный критерий имеет три различимых результата: поведение доказано, поведение не
выполнено, доказательство недоступно. Последний случай не доказывает дефект автора, но
препятствует полной приёмке без явного решения человека об исключении/изменении критерия.
Используются существующие `failed` с владельцами `environment`/`human` и штатный `skipped`
с остановкой у человека; доказанный дефект получает `build`/`tests` по контракту маршрута.
Зелёные тесты не заменяют обязательную браузерную проверку. Агентский и command-парсер
отклоняют failed только с deferred вместо прежнего автоматического повышения до done.
Старые события журнала остаются читаемыми. Отказ host evidence-хука после штатного
повтора сохраняет typed failed/human с открытой находкой evidence-rejected.

Для автоматического поведения проверяются штатный запуск, обработка очередей и получение
результата без ручного продвижения стадий. Прямой action/job или временный демон подтверждают
только часть цепочки. В отчёте нужны вмешательства и итог процессов/очередей. Отсутствие
обязательной инфраструктуры стенда препятствует приёмке.

Для изменённых настроек выбираются применимые проверки сохранения с новой загрузкой,
пустого выбора, всех опций OFF, режима ON/OFF, отключённых/удалённых сущностей с настройками,
пересекающихся id при разных устройствах/источниках и соответствия цены, сохранённого плана,
работы и списания. Изолированные данные создаются и очищаются разрешённым способом;
нехватка удобного набора данных не исключает обязательный сценарий.

Профиль может проверять декларацию приёмки существующим
`profile_route_node_evidence_check`. Проверка привязывается к runId/attemptId и версии
контракта закреплённого prompt. Она отклоняет отсутствующие/непроверенные обязательные строки
и ручную цепочку, заявленную как автономная. Матрица — декларация со ссылками на доказательства,
а не автоматическое доказательство семантики сценария; достоверность ссылок и полноту пунктов
свободного описания проверяет агент. Исключение критерия ссылается на явное решение human gate;
обычное модельное одобрение им не является.

Новый prompt применяется после CAS-публикации к новым попыткам. Новая проверка формата в
живом хуке включается маркером в pinned prompt, сохраняя контракт прежних попыток. Общий
движок в source подхватывает исправления при новом запуске процесса; packaged runtime требует
штатной сборки/установки и нового запуска сервера. Перезапуск из дочернего чата запрещён:
его выполняет человек после завершения хода. Существующие runtime pins отдельно не меняются; снять закрепление
остановленной попытки человек может вручную —
[ручная перепривязка рантайма](runtime-rebind.md).
