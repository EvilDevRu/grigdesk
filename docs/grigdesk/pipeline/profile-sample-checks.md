# Проверки и доказательства в образце профиля

Ручная обёртка `profile/checks.py tests <task> <файлы…>` выбирает для каждого тестового
адаптера только относительные пути, соответствующие его `match`. Сопоставление использует
те же правила glob, что VERIFY: `tests/**/*.mjs` включает и `tests/old.test.mjs`.
Выбранные пути передаются адаптеру абсолютными аргументами внутри его репозитория.
Если подходящих файлов нет, адаптер не вызывается; пустой список не запускает весь набор.
Проверки style, build и health сохраняют собственные объявленные команды.

Приёмка требует отдельного доказательства каждого `task.acceptanceCriteria`. Если список
пуст, источником критериев становится `task.description`: нумерованные (`1.`, `1)`)
и маркированные (`-`, `*`, `+`) пункты Markdown разделяются по маркеру в начале строки.
Текст до первого маркера сохраняется отдельным критерием. Без маркеров вся постановка
остаётся одним критерием. В `criterion` переносят текст без маркера, сохраняя переносы
и убирая пробелы по краям каждой строки. Вложенные пункты также требуют своих записей.

Например, постановке `1. Сохранить ответ.\n2. Сохранить правила.` соответствуют две записи:

```json
[
  {"criterion": "Сохранить ответ.", "status": "passed", "evidence": "/tmp/example-answer.txt"},
  {"criterion": "Сохранить правила.", "status": "passed", "evidence": "/tmp/example-rules.txt"}
]
```

Файлы доказательств должны существовать. Одна запись со всей постановкой вместо отдельных
пунктов, пропущенный пункт и дубликат вместо другого пункта не дают завершить приёмку.
Явные критерии имеют приоритет над разбиением постановки; точная попытка, запуск и требования
браузерной приёмки проверяются независимо от способа получения критериев.
