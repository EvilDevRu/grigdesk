# Данные фабрики

- Реестр прогона: `~/.factory/state/tNNNN.pipeline` — `KEY=VALUE` (не JSON), парс `lib/pipeline-parse`.
- Возможности профиля: `<config.profilesDir>/<profile>/graph.json`; каталог выбирается
  через `FACTORY_PROFILES_DIR` или умолчание режима установки. Содержимое профилей —
  локальная конфигурация вне Git исходников, ссылка на внешний каталог может отслеживаться
  отдельно. Поля nodes/keys/optional/routes с pos+edges описывают исторический граф;
  новый route-v2 граф читается из закреплённого bundle, а не из этих полей.
  Справочник — [профили конвейера](project-profiles.md).
- Статусы узлов: `lib/factory-graph.computeNodeStatuses` — порт `pipeline_statuses` из `dashboard.py`.
- Возвраты: `parseLoops` из `logs/tNNNN.stages.log`. Порты стенда: `tNNNN.env`.
- Стадии — глобальный каталог `lib/stages.ts` (enum), профиль оверрайдит подпись/тип.
**Арбитр типизированной остановки** (`lib/factoryArbiter.ts`, `POST /api/tasks/:id/arbitrate`)
снимает тупик вместо человека. Движок останавливает маршрут fail-closed, когда автоматический
возврат перестал давать прогресс, — остановка правильная, но человек в этот момент делает
работу курьера: собирает оба вердикта дуги, читает артефакты, формулирует указание и
возвращает курсор. Замер по журналам всех попыток: 28 типизированных остановок, медиана
ожидания 15 минут, сумма 59.7 часа, максимум 13.9 часа; пять ночных стоянок дают 53 часа
из этих 60.

Арбитр повторяет ровно этот путь и получает то, чего человеку не хватает, — **доступ к
коду**: он идёт обычным `executor.run` в рабочем дереве задачи в режиме `plan` с каталогом
состояния в `extraDirs`, поэтому проверяет спорное утверждение по коду, а не рассуждением
о нём. Это не `runUntrusted`: недоверенного внешнего ввода здесь нет, вход — сам проект и
вердикты его же узлов.

**Что арбитр может, названо по замеру, и замер пришлось переделать.** Режим `plan` даёт
чтение, поиск, обход файлов И ЗАПУСК КОМАНД ЧТЕНИЯ: живой разбор 28.08.2026 выполнил
34 команды (`ls`, `cat`, `grep`, `sed -n`, `git status`, `git log`) — все успешно.
Блокируются нативные `Write`/`Edit` и перенаправление в файл; отдельная проверка
показала, что запись через запущенную программу (`node -e "fs.writeFileSync"`) режимом
НЕ блокируется. То есть `plan` — не песочница от записи, и рабочее дерево остановленной
попытки защищено только прямым запретом в промпте (подробности и остаточный риск —
[грабли](plan-permissions-and-arbiter-timeout.md)). Промпт до этого замера утверждал обратное («запускать команды ты
НЕ можешь»), то есть сам сужал арбитра там, где ограничения не было.

**У хода есть объявленный агенту бюджет — 20 минут** (`ARBITER_TURN_LIMIT_MIN`, оно же
`budgetMin` промпта: второй копии числа быть не должно). Прежние десять минут оказались
резаком: на реальной остановке арбитр честно читал отчёт, диагностику и исходники чужой
библиотеки и был оборван на десятой минуте, не дав ничего — время живого агента
потрачено, конвейер стоит, задача ушла в часовой cooldown. Поэтому лимит поднят, но
главное не он: агент знает свой бюджет и обязан вернуть `human` с половиной разбора,
если к середине ответа нет. Оборванный ход не даёт человеку ничего, половина разбора —
даёт.

Границы проверяются до побочного действия и названы человеку словами:

- разбираются три вида остановки, и второй — не безусловно. `no-progress` — топтание на
  дуге возвратов. `human` — вызов человека, объявленный самим маршрутом по классу
  владельца провала, который назвал агент, и берётся он ТОЛЬКО при классе `human`:
  `environment`, `build` и `tests` означают отказ среды или сборки, а он чтением кода не
  снимается. Почему второй вид вообще разбирается: замер по опубликованным каталогам —
  2785 переходов ведут в `human` против 184 в `done`, то есть это самая частая объявленная
  остановка, и часть её случаев не вопрос к человеку по существу, а вопрос, который узел
  не смог проверить сам под политикой `state-only` (случай разобран в [граблях](stall-visibility-and-analysis.md)).
  Точки возврата маршрут для такой остановки не предлагает, поэтому арбитр переигрывает
  ТОТ ЖЕ узел с недостающим фактом — права прыгать через узлы он здесь не получает;
- решение «берётся или нет» принимает одна функция `stopIsArbitrable`, общая для гейта
  арбитра, кнопки в карточке задачи и автоматического вотчера. Сервер отдаёт её результат
  полем `stall.arbitrable`; кнопка, за которой стоит отказ, хуже отсутствующей кнопки;
