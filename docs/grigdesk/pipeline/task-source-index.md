# Подтверждённый источник запуска

Сервер хранит небольшой индекс `factory-task-sources.json` в каталоге данных состояния,
путь задаёт `factoryTaskSourcesPath`. Он не меняет тикет, ключи задач и протокол движка.
Запись содержит taskId, source, отпечаток тикета, dispatchId и подтверждённую attempt.
Pending сохраняется перед spawn под блокировкой запуска. Directory lock и atomic rename
защищают индекс между процессами; файл имеет режим 0600.

Сервер получает источник из identity выбранного внешнего фасада до эффектов запуска.
Явный ожидаемый source карточки сверяется с этим значением. Перед dispatch внешний контекст
повторно проверяется. Новый dispatch закрепляется существующим параметром движка.
Подтверждение и восстановление pending требуют совпадения dispatch, trusted attempt и
отпечатка существующего immutable ticket из control root. Mutable staging не является доказательством.
Resume сохраняет источник текущей попытки. CLI-запуски без такой связи остаются неизвестными.

`GET /api/tasks?sources=1` добавляет sourcesVersion:1 и подтверждённые внешние source.
Без opt-in внешний source отсутствует, как в прежнем строгом DTO. Историческая own-запись
сохраняется в индексе, но не подтверждает активный источник. Индекс читается одним снимком
на запрос, названия берутся из сохранённых тикетов. Сеть трекера на GET не нужна. Повреждение индекса диагностируется,
не скрывает список конвейера и запрещает перезаписать индекс пустым.

Доска, карточка и полка сопоставляют конвейер по паре source/id. Неизвестность не подменяется
текущим порталом. Оценки, очереди и физическое дерево фабрики по-прежнему адресуются только
номером: одновременные прогоны разных порталов с одним id этим контрактом не изолированы.
