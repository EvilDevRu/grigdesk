# Конкретная ошибка провайдера доходит до карточки остановки

Остановка по исчерпанию повторов раньше получала только класс последнего запуска.
Если адаптер возвращал `unknown`, исходное сообщение оставалось в `events.jsonl`,
а человек видел «заходы без результата, последний — unknown» и общую подсказку
про таймаут. Такое случалось, в частности, при перегрузке модели.

## Распознавание и политика

Классификатор Codex не привязан к одному номеру CLI. `CLI_VERSION` сохраняется
в metadata; смысл отказа определяется по структурированным событиям `error`,
`turn.failed` и `usage_limit_reached`. Вывод команд и сообщения агента не являются
ошибками провайдера. Продолжение хода или новой сессии снимает прежний отказ.
Непроверенный источник, повреждённый поток и неизвестная сигнатура дают `unknown`.

Общий разбор — `server/src/lib/runnerFailure.ts`; движок вызывает его через
`engine/lib/codex-failure.mjs`. Чтение классификатора ограничено64MiB, без symlink/FIFO.
Перегрузка и обычный rate limit классифицируются как `transient`: они не разрешают
автоматическую смену провайдера и не включают breaker квоты. Прежние правила
`limited`, `denied`, `context_overflow`, кодов0/124 и auth до работы сохранены.
Неизвестные события не доказывают отсутствие работы для переключения после auth.

## Новые запуски

`runtime-usage.mjs prepare` извлекает сообщение из уже проверенного retained FD
вместе с нормализацией расхода. Финальный diagnostic mirror `meta.env` получает
`FAILURE_CODE`, `FAILURE_MESSAGE`, `FAILURE_DETAIL`. Они не меняют управляющий
`RESULT_CLASS`, immutable usage schema, вердикт этапа или политику повторов.
Таймаут, успешный запуск и ручное переключение не наследуют прежнюю ошибку.
У GLM этапа источник — последнее событие `wrapper_error` host-wrapper-а
(`inspectGlmFactoryFailure`); класс при этом остаётся `unknown`, см. [GLM.md](../../engine/GLM.md).
Карточка остановки читает этот mirror для Codex и GLM; у прочих раннеров она прежняя.

Диспетчер передаёт пояснение последнего запуска через `DISPATCH_RESULT_DETAIL`.
Маршрут использует его в комментарии и строке остановки, сохраняя число попыток.
При отсутствии пояснения работает прежнее отображение класса. Сообщение очищается
от управляющих символов и типичных секретов; исходная диагностика ограничена500
символами, поле для маршрутного комментария —220.

## Уже остановленные задачи

`runnerStall.ts` дополняет сводку и граф одним способом. Он работает только с
`exhausted` и точным `ACTIVE_RUN` соответствующего этапа: проверяет task, stage,
attempt, run, epoch, окончание процесса и время текущего визита. Для старого запуска
без `FAILURE_*` читает последние256KiB журнала, отбрасывая обрезанную первую строку.
Ошибка другого запуска, старого визита, успешного хода или таймаута не подходит.

Чтение каталогов и файлов привязано к удерживаемым дескрипторам; ссылки, FIFO,
hardlink и меняющийся файл отклоняются. Недоступные доказательства оставляют прежнюю
карточку. Этот путь ничего не пишет и не пересматривает outcome/арбитраж.
Неизвестный класс сохраняет конкретный текст ошибки для человека.

Изменения движка подхватываются новым процессом. Для нового текста существующей
карточки нужен обычный перезапуск сервера GrigDesk; повтор задачи для этого не нужен.

## Регрессии

Проверяются обновляемая версия CLI, capacity после работы, неизвестный отказ,
текст внутри команды, восстановившийся поток, auth после работы/повреждения,
приоритет timeout, секреты и длина сообщения. Настоящий launcher с фиктивным Codex
проверяет публикацию `FAILURE_*`; маршрут — передачу текста при обычном бюджете
повторов; dispatcher — отсутствие смены модели и утечки причины в следующий запуск.
Серверные тесты сверяют сводку/граф старой остановки, совпадение идентичности,
временную границу, ссылки и большой журнал без мутаций состояния.
