# Авто-шип фабрики

SHIP публикует принятое изменение по `delivery` выбранного профиля: проверяет состав,
выполняет разрешённые Git-действия, сохраняет commit/PR и итог в `ship.md`. Порядок
слияния с базовой веткой и публикации определяет профиль: он может требовать сначала
push и PR, затем слияние целевой ветки в ветку задачи. Целевую ветку узел сам не меняет.
Невыполненные push или PR нельзя объявлять успешной публикацией.

Read-only Git metadata не заменяет проверку штатного запроса доступа. В поддержанном
Codex runtime `workspace-write` сохраняет песочницу и допускает адресный native
Auto-review; реальные отказы и намеренные запреты сохраняются —
[контракт доступа](codex-delivery-permissions.md).

Комментарий отправляется только при разрешённом `task-comment`. Штатный CLI —
`tracker --board <id> comment <task_id> <текст>`; при отсутствии команды в PATH —
`grigdesk-ctl tracker` с теми же аргументами. Источник задачи определяет доску,
текущий default и совпавший номер её не доказывают. Отсутствие прежней команды `b24`
не доказывает отсутствия транспорта трекера.

Повтор SHIP сверяет уже созданные commit, удалённую ветку, PR и квитанцию комментария.
Подтверждённые результаты переиспользуются; пустой коммит, второй PR и повторный
комментарий не нужны. Конкретные команды и разрешения принадлежат профилю.
