# Графовые маршруты: прогоны, ворота и хранение

Графовые маршруты — отдельный движок прогонов поверх Go-фабрики: декларативный DAG
областей вместо курсора legacy-маршрута. Namespace `graph-workflows` не пересекается
с реестром попыток и каталогом маршрутов legacy-конвейера.

Код: `utilities/factory/internal/graphworkflow` (модель, расписание, решения, аренды),
`utilities/factory/internal/state/graph_workflow.go` (доверенное хранение),
`server/src/modules/graphWorkflows` (session-only HTTP), `server/src/lib/graphWorkflowWorkers.ts`
(выдачи), `web/src/stores/graphWorkflows.ts` и `web/src/views/pipeline/GraphWorkflowRun.vue`
(живая схема). Пользовательские сценарии: [маршруты](../guide/ru/routes.md),
[конвейер](../guide/ru/pipelines.md).

## Хранение

Все записи живут под `${STATE_DIR}/graph-workflows/` и публикуются атомарно под flock
через `os.Root` (запись во временный файл + rename, проверка digest при чтении):

- `templates/<uuid>.json` — конверт `{format, digest, revision, document}`; revision
  растёт монотонно, digest считается по каноническим байтам документа. Встроенные
  `builtin-documents` и `builtin-meeting` читаются из кода и не записываются; сохранение
  поверх builtin-ID отклоняется (`builtin_readonly`).
- `runs/<uuid>.json` — конверт снимка прогона: декларации, экземпляры узлов, поколения,
  строки результатов, решения ворот, история действий. Поколение каждого ID монотонно
  и не повторяется даже после пересчёта области.
- `runs-meta/<uuid>.json` — заголовок прогона (название, тип входа, время создания).
  Повтор старта под тем же UUID дописывает первый снимок, если сохранился только заголовок.
- `active.json` — индекс активных прогонов (не более 32 UUID), резервации J05
  (opened/admitted/closing) и `faultUntil`: после сбоя транспорта приём новых выдач
  приостанавливается на 6 минут, затем индекс сам освобождает карантин.

Клиент сверяет `revision` и игнорирует поздние снимки с меньшей ревизией.
Итог строится из всех достижимых строк и читается страницами с бюджетом 64 КиБ.
Строка больше бюджета передаётся целиком отдельной страницей. Смена ревизии между страницами
даёт 409 `result_changed`. Утверждение доступно после загрузки полного текста текущих ворот
в той же ревизии и поколении, до 512 КиБ JSON строк. Превышение даёт `output_limit`.
Неполный итог имеет `incomplete=true`.

## Выдачи и отказы

- Worker сервера запрашивает выдачи RPC `claim` по одной, а модельные задания выполняет
  параллельно по готовности графа. Модельный helper запускается в отдельной сессии с
  permit-рукопожатием (fd 10/11, PID==SID==PGID и UID владельца). Срок модели — `expiresAt − 60s`.
- Для `forEach` видны все созданные ветки. Если задано положительное `parallelism`, снимок
  сохраняет допуск целых веток элементов, включая вложенные шаги и ожидание ворот.
  После завершения элемента допускается следующий по порядку входных строк. Ручной повтор
  завершившейся ветки снова проходит тот же допуск. Пропущенное поле или 0 означает
  запуск всех готовых веток, в том числе в ранее сохранённых шаблонах.
- `settle` принимает результат только с живым claimId и точным поколением; поздний
  ответ отменённой или повторённой выдачи отклоняется 409 и не меняет снимок.
- Основной сервер выбирает модель по своему каталогу и фиксирует действующий профиль доступа
  перед запуском помощника. Помощник получает снимок только по stdin и загружает один адаптер
  из сгенерированной таблицы SEA. Чтение каталога не имеет доступа к разрешению на запуск.
- Живой помощник сохраняет право закрыть выдачу после выхода исполнителя. Квитанция
  восстанавливается по моменту записи, включая рестарт после истечения срока и новую загрузку ОС.
  Прерванная работа получает `interrupted`, а известная ошибка до запуска сохраняется с её кодом.
  Следующий запуск отказавшего этапа требует ручного повтора. Пустой массив строк означает успех.
- Отказ листа виден в схеме и детали («Попыток: N»); «Повторить этап» увеличивает
  поколение только этого экземпляра и переподключает уже готовые результаты сборки.
- Возврат с ворот (`retryFrom`) пересоздаёт зависимую часть области и потомков с новыми
  поколениями и токенами; замечание доставляется только новым модельным вызовам
  затронутой области до следующей приёмки. Независимые ветки и прежние решения
  сохраняются в истории. Цель решения — полный ID экземпляра. Отказ без целей запрещает
  новые выдачи и закрывает прогон как отклонённый после завершения уже выданных работ.
- Кворум сборки считает завершённые элементы, а не запущенные; поздний отказ элемента
  после кворума сохраняет выбранные строки и помечает сводку отказом.

## Границы

- HTTP-модуль инкапсулирован и принимает только сессионный транспорт: внутренний токен
  и window-key получают 403 `session_required` и на чтение, и на запись.
- Старт идемпотентен по SHA-256 дайджесту payload: повтор того же старта возвращает тот
  же прогон, изменение входов принятого прогона при том же ID даёт 409. Форма удерживает UUID
  при потере ответа. Старты и возобновления делят один предел в 32 активных прогона.
- Модельные шаги требуют адаптера с протоколом допуска процесса (Codex или Claude) и Linux
  либо macOS. Windows отклоняет такой маршрут до создания прогона, включая вложенные модельные
  шаги. Маршруты из локальных шагов и ворот запускаются без выбора модели.
- Графовые прогоны не создают задач трекера и не меняют карточку Git legacy-конвейера.
- Лимиты декларации и исполнения: глубина областей ≤ 4, ≤ 32 объявления шагов,
  ≤ 256 экземпляров на прогон, включая ветки `forEach`. До 256 строк на один модельный
  результат с проверкой размера. Загрузка входов — до 20 документов, ≤ 64 КиБ на файл
  и ≤ 256 КиБ суммарно.

## Проверки

Профильные наборы: `tests/server/graph-workflow-*.test.mts` (executor, HTTP, worker,
crash), `tests/web/graph-workflows.component.test.js`,
`tests/web/graph-workflow-editor.component.test.js`; Go —
`utilities/factory/internal/graphworkflow` и `state` (включая `-race`).
Фикстура стенда: `tests/fixtures/graph-workflow/host.mts` (`--serve` поднимает loopback
с тестовым DSP model). В SEA-проверке собранный помощник доходит до сохранённого результата с локальным Codex CLI,
двумя тестовыми профилями, счётчиками `model/list` и `turn/start`. Проверка не использует
платный доступ. Нативный запуск на Windows и macOS проверяется отдельно.
