# Выбор модели триажа и профили доступа Codex

Настройки находятся в «Плагины → Установленные → Триаж». `triageModel` сохраняет
`{provider, model, effort?}` через общий Apply; сервер использует эту пару при каждом
новом анализе и автоматическом разборе вопросов. Claude не является запасным исполнителем.
Усилие берётся из каталога выбранной модели; несовместимый уровень при смене модели снимается.

Селект показывает исполнителей с подтверждённой `scopedWorkspace`. У нового Codex
отсутствует прежнее поле `SandboxPolicy.workspaceWrite.readOnlyAccess`, поэтому проверка
только этого поля скрывала GPT. Адаптер распознаёт два протокола по локальной схеме
`app-server generate-ts --experimental`: прежний restricted read и именованные
`permissions` в thread/start, thread/resume и turn/start с `activePermissionProfile` в ответе.
Непроверенный CLI по-прежнему не получает задачу.

GLM, Kimi и DeepSeek также объявляют эту capability и используют отдельный
[режим триажа с файловым брокером](triage-executors.md). Он сохраняет выбранную модель
и effort и не выдаёт модели штатные чатовые инструменты исполнителя.

Для нового протокола каждый запуск создаёт свой профиль: `:root = deny`, `:minimal = read`,
репозитории и входы — `read`, только каталог результата — `write`, сеть выключена.
Сам executable и обнаруженные npm-пакеты Codex разрешаются на чтение: иначе Linux
bubblewrap не может запустить CLI, установленный вне системных каталогов. Весь npm-prefix
или home разрешения не получают. Внешние MCP, hooks, уведомления и приложения выключены.
Пустой `mcp_servers` не очищает унаследованную конфигурацию CLI: адаптер получает имена
через config/read, выключает каждый сервер в конфигурации thread и проверяет статус
disabled и отсутствие инструментов в MCP-каталоге этого thread до передачи постановки.

Адаптер проверяет активный профиль, фактические grants из config/read, сеть и временные
каталоги до передачи постановки. Каждый turn повторяет `permissions`; legacy sandboxPolicy
вместе с ним не отправляется, поскольку он заменил бы выбранный профиль.

Проверки: `codex-scoped-workspace-profile.test.mts`, `codex-app-server-contract.test.js`,
`codex-installed-app-server-contract.test.js`, `settings-plugin-model.component.test.js`.
Проба настоящего CLI без модели подтвердила чтение репозитория, запрет его изменения,
запрет чтения соседнего файла и запись результата только в output.

Официальный контракт: [App Server](https://learn.chatgpt.com/docs/app-server),
[профили доступа](https://learn.chatgpt.com/docs/permissions).
