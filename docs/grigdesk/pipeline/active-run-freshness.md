# «Нет событий N мин» на штатной паузе = свежесть считали по чужому ACTIVE_RUN

Симптом: конвейер стоит у ворот, всё в порядке, а в модалке этапа отображается много часов
несуществующего молчания.
Читается как «агент завис» и толкает человека дёргать прогон.

Причина: `ACTIVE_RUN_<STAGE>` в реестре — **ещё и fencing-токен**, его намеренно не чистят
(сброс эпохи воскресил бы убитый ход прошлой попытки). `readActivity` же брала любой
непустой ключ и показывала свежесть его журнала. Единственным непустым мог остаться
`ACTIVE_RUN_BUILD` от давно отменённой попытки — отсюда ложный возраст. Исторические
пути (`ACTIVE_DIR`/`JOURNAL`, `logs/t<TASK>.orch.log`) не спасают, а подменяют цифру
свежестью чужого запуска.

Правила:
- активность считается **только** по ходу, чей этап прямо сейчас `running`; молчание —
  к тому же только у хода с живым раннером ([после TERM](dead-runner-silence.md));
- для executable route-attempt исторические источники (`ACTIVE_DIR`, `orch.log`) не используются:
  каждый ход обязан зарегистрировать `ACTIVE_RUN`, и его отсутствие означает
  «сейчас никто не пишет», а не «поищи где-нибудь ещё»;
- нет активного хода → `journalAgeSec: null`, а не цифра. Придуманная цифра хуже прочерка.
