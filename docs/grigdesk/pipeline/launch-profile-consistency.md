# «Маршрут требует файл инструментации» = форма открылась на чужом профиле

Симптом: у задачи, которую ещё ни разу не запускали, поле «инструментация» в модалке
запуска пустое, подставить нечего, а кнопка заперта текстом «Маршрут требует хотя бы один
файл инструментации». Читается как поломка маршрута или профиля, хотя оба целы.

Механика в трёх звеньях, и ломается она на первом:

- дефолтный профиль формы был `config.factoryProfile || primaryProfile()`, а
  `primaryProfile()` — это профиль **первого незакрытого реестра по номеру задачи**
  (`listTaskIds` сортирует численно). Один брошенный тестовый прогон с маленьким номером
  делается дефолтом для ВСЕХ задач, пока его не закроют;
- `instrumentationSuggestions` сопоставляет алиасы триажа (`fe:`, `be:`) с репозиториями
  ВЫБРАННОГО профиля. У чужого профиля алиасов нет — список подсказок пуст;
- explicit-маршрут (`instrument` до `proof`) без единого файла scope запускать нечем,
  поэтому валидатор формы честно запирает кнопку.

Поэтому профиль по умолчанию теперь выводится из самой задачи: `profileMatchingTriage`
сверяет каталоги, которые фактически читал триаж (`analysis.repos.<alias>.dir`), с
`source` из `profile_repositories` каждого профиля с опубликованным каталогом. Обе стороны
берут путь из одной переменной профиля (`PROFILE_TRIAGE_REPOS`), поэтому сравнение
буквальное, а не догадка по имени профиля, проекта или группы трекера — имя придумывает
человек, а путь объявляет профиль (та же грабля, что с окном модели, выведенным из имени).

Три границы, каждая намеренная:

- **явный выбор сильнее вывода**: `?profile=` и `GRIGDESK_FACTORY_PROFILE` не перебиваются;
- **неоднозначность не решается за человека**: совпало два профиля (законная схема — два
  профиля на одни репозитории) — остаётся прежний `primaryProfile()` и селектор формы;
- **нет триажа — нет вывода**: у неоценённой задачи каталогов сравнивать не с чем.

Стоимость — `bash source profile.sh` на каждый профиль-кандидат, замер 2–8 мс на профиль,
поэтому кэша нет. Сторож — `tests/server/factory-launch-profiles.test.js`.
