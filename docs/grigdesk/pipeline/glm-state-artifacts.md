# GLM: обязательные артефакты в state-only

Файловая политика `state-only` запрещает правку рабочих деревьев, но требует сохранять
артефакты узла в `STATE_DIR`. Полный `read-only` DSH запрещал и эти записи: диагноз мог
остаться только в финальном ответе, после чего проверка обязательного файла останавливала узел.

Shell-раннер GLM принимает существующий абсолютный `STATE_DIR`, раскрывает его физический
путь и передаёт wrapper-у как cwd вместе с `--mode state-only`. Wrapper закрепляет этот
корень в `factoryContext.stateDir`, сверяя cwd с `STATE_DIR` окружения хоста. Runtime
использует его как cwd и workspaceRoot DSH,
включая sandbox `workspace-write` с approval `never`. Репозитории доступны для чтения по
абсолютным путям. У `workspace-write` остаётся прежний cwd проекта.

Host-owned документ hook содержит `stateDir` только для `state-only`. Parser требует
существующий физический каталог. `write` и `edit` принимают относительные и абсолютные
пути внутри него, в том числе новые вложенные каталоги; выход через `..`, соседний каталог
с тем же префиксом и символическую ссылку отклоняется. Запись shell вне корня блокирует
песочница DSH; интерактивная эскалация в этапе запрещена.

Правило определяется файловой политикой, без списка имён узлов. Узлы наподобие
`hyposkeptic` сохраняют статус через прежний host-owned `stage_result`, но при наличии
обязательного файлового артефакта также могут записать его в `STATE_DIR`. Финальный
ответ не заменяет файл. Классификатор ошибок и политика повторов не меняются.

Ревизии Factory — `grigdesk-glm-factory-profile-v2` и
`grigdesk-glm-factory-policy-v4`; v3 ввела границу артефактов, а v4 дополнительно разрешает
[веб-инструменты](../chat/glm-web-tools.md). Версия раннера включает эти
ревизии, поэтому прежнее покрытие не допускает запуск с незамеченной сменой политики.

Проверки: `tests/engine/unit/glm-runner-launch.sh` подтверждает аргументы запуска,
STATE_DIR и отказ при неверном корне. `tests/server/glm-runner-contract.test.js` на
настоящем DSH ELF с локальной моделью проверяет DIAGNOSE и HYPOSKEPTIC: чтение исходника,
запись и правку артефакта, отказ правки проекта, соседнего корня и ссылки, shell внутри
и снаружи STATE_DIR, сохранение запроса `stage_result`. Policy, wrapper и транспорт
дополнительно проверяются профильными `glm-factory-*.test.js`.
