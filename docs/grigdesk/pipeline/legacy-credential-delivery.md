# Доставка объявленных ключей участников маршрута

При подготовке запуска `preparePipelineAccess` возвращает вычисленные id участников
вместе с доступом и rollback. Для адаптеров без `accessProfiles` список секретов
расширяется их декларациями `credentials` с `kind=secret`.

Динамические ключи разрешены только участникам маршрута. Имена объявленных секретов
всех адаптеров удаляются из `extraEnv` и наследуемого detached-окружения: ключ чужой
карточки не должен доехать до движка. Имена хоста и служебные переменные не становятся
credentials. Прежние статические ключи и profile pins сохраняют свой контракт.

Необъявленные имена с отдельными частями `KEY`, `TOKEN`, `SECRET` или `PASSWORD`
также удаляются из `extraEnv` и наследуемого окружения. Это закрывает запуск без
access service, где декларации неизвестного адаптера могут отсутствовать. Разрешённые
секреты участников возвращаются только из проверенного источника, после очистки.

При access service источником служит подготовленное `access.env`, иначе окружение
сервера. У старого запуска без service может ещё не быть графа; тогда дополнительные
динамические ключи не выдаются. Это не отменяет прежний запуск со статическими ключами.

Transient service получает секреты через атомарный `route-secrets.env` с правами 0600;
без ключей прежний файл удаляется. Detached-процесс получает тот же разрешённый набор
через env. CR, LF и NUL в значении отменяют запуск до записи или spawn.

Пути CLI Qwen, исходного home и выбор сервиса `GRIGDESK_QWEN_SERVICE` передаются как
параметры хоста в обе ветки; значения `extraEnv` не могут их заменить. Выбор сервиса
не является секретом; API-ключ по-прежнему передаётся только через защищённое окружение.
Полноту раннера Qwen эта доставка ключей не доказывает.
