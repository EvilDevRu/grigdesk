# Ответы о правах и проблемах этапа

Показанный ответ второго шага мастера должен совпадать с настройками вставленного этапа.

У роли «Проверка командой» каталог явно задаёт реакцию «Вернуть автору». Мастер выбирает
раннего исполнителя; если подходящего адресата нет, ответ меняется на «Спросить человека».
При возврате продуктовые отказы с владельцами build/tests/plan направляются выбранному
автору. Отказы человека и окружения останавливают маршрут для решения человека.

Файловые политики различаются и в подписях, и в сохраняемых значениях:

| Значение | Русская подпись | Английская подпись |
|---|---|---|
| `state-only` | Только читает код | Reads code only |
| `transactional-write` | Временные изменения с откатом | Temporary changes with rollback |
| `workspace-write` | Может менять код | May change code |

`transactional-write` допускает временную инструментацию и восстановление принадлежащих
транзакции файлов по правилам движка. Это разрешение записи; оно не означает только чтение.
Выбор подписи не преобразует значение политики. Набор доступных политик по-прежнему
определяет профиль, а для команд — декларация выбранной команды.

Команда выбирается из декларации профиля, даже если в ней нет verify или recheck из образца.
Для перепроверки ревью по умолчанию предлагается recheck, затем другая объявленная команда
с политикой state-only. Для роли команды доступные права пересчитываются при смене команды:
сохраняется допустимый ответ, иначе выбирается state-only или первая объявленная политика.
Выбранные команда и права сразу видны в полях и совпадают с подготовленным узлом.
Если после места вставки уже есть объявленная проверка, ревью использует её:
поле показывает эту команду и объясняет, что выбор определяется местом вставки.

Узел команды сохраняет исходный commandId. Его id и runKey должны соответствовать схеме:
дефисы заменяются подчёркиваниями, для начальной цифры добавляется префикс command_,
id ограничен 41 символом, runKey равен id в верхнем регистре. Например, project-check
получает project_check/PROJECT_CHECK. Verify и recheck сохраняют канонические имена.
Если имя уже занято, вставка отклоняется без добавления суффикса.

В маршруте с циклом возврат к автору для нового этапа недоступен; поле адресата скрыто.
Реакция «Вернуть автору» заменяется на «Спросить человека», и мастер объясняет ограничение.
«Поправить мелкое самому» остаётся доступным пишущему агенту; нерешённая проблема
останавливает маршрут у человека. Пара worker → lead и её существующие переходы сохраняются.
