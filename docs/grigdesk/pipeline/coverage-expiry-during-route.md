# Проверка исполнителей обновляется внутри длинного маршрута

Раньше длинный прогон мог остановиться перед очередным узлом с
`coverage_unavailable`, хотя все исполнители были доступны. Host preflight выполнялся
при `start`/`resume`, его обычный срок — 21600 с. После `EXPIRES_AT` проверка
`coverage_gate` возвращала 77, запуск узла — 79, диспетчер — 75. Агент ещё не запускался.
Один `resume` снимал остановку лишь до следующего истечения срока.

Теперь при `RUNNERS_COVERAGE=required` движок различает истечение и остальные отказы.
Если схема, revision конфигурации, связь structural/host и готовность хотя бы одного
кандидата цепочки проходят проверки, а отказ вызван только сроком, `_multi_require_coverage`
один раз выполняет полный `profile_runner_host_preflight`. Он проверяет metadata CLI,
каталог и возможности без prompt и model call. В журнале задачи видны причина
перепроверки, её успех или отказ.

После обновления движок повторно проверяет снимки с исходной revision и новым текущим
временем. Изменившаяся во время пробы конфигурация или снова истёкший срок не дают
разрешения на запуск. Полный preflight выполняется в отдельной оболочке: его загрузка
реестра раннеров и каталога не меняет состояние текущего dispatcher. Второго обновления
в рамках этого входа в узел нет.

Тот же единственный повтор запускает несовпадение сборки runtime-sensitive исполнителя
(например встроенного DeepSeek) с `RUNTIME_VERSION_<id>` свежего снимка: штатная публикация
новой сборки резерва не останавливает узлы основного исполнителя. После повтора сборки
сверяются снова, каждый готовый исполнитель цепочки один раз; чужие цепочки не проверяются.
Несовпадение и тогда даёт
`coverage_unavailable` и `FACTORY_ERROR=runtime_changed` в журнале маршрута.

Ограничения сохранены:

- свежий положительный снимок не запускает лишний полный preflight;
- отсутствующий, несовместимый или повреждённый снимок, как и записанная недоступность всей цепочки,
  останавливают узел без автоматического обновления;
- `SCHEMA=1` считается невалидной и переписывается одним полным preflight перед узлом;
  без успешной записи новой схемы модель не вызывается;
- ошибка нового preflight или повторной проверки цепочки возвращает прежний отказ
  `coverage_unavailable`, код 79 и `STALLED_HUMAN=1` до model call;
- срок действия, выбор моделей и исполнителей не меняются; `EXPIRES_AT` пишет только
  полноценная проверка, продвижение каталога по просроченному снимку запрещено.

## Общий снимок хранит именную готовность

Снимок остаётся общим на профиль, а `SCHEMA=2` хранит `PROVIDER_<id>` для каждого
провайдера. Его единственный профильный писатель `profile_runner_host_preflight` опрашивает
весь конфиг при `start`, `resume` и перепроверке перед узлом. Runtime читает только цепочку
этого узла: готовый primary идёт в работу, недоступный пропускается в пользу первого
готового failover с записью причины. Провайдер вне цепочки не останавливает узел.
Общий отрицательный код полного опроса сам по себе runtime не блокирует: свежие статусы
проверяются заново по нужной цепочке. Ошибки хранения и контракта по-прежнему закрывают запуск.

Preflight `start` проверяет цепочки всех agent-узлов закрепляемого бандла, включая нужную
разведку; `resume` — цепочки достижимых из trusted cursor узлов. Переопределения задачи
разрешает тот же `routing_resolve`, что и на узле. Сверка `RUNTIME_VERSION_<id>` ограничена
готовыми провайдерами цепочки. Публикация каталога остаётся строгой по всем провайдерам.
Полный контракт — [покрытие цепочек](runner-chain-coverage.md).

Для диагноза сверяй текущую попытку, `FETCHED_AT`/`EXPIRES_AT`, revision, связь снимков
и `PROVIDER_<id>` в обоих слоях для цепочки узла. `UNAVAILABLE` и `UNAVAILABLE_RUNNERS` —
диагностика всего профиля. Сам код 75 не различает истечение, повреждение и недоступность.
Уже остановленный старым runtime прогон продолжает штатный `resume`: новый процесс
подхватывает исправленные библиотеки и сохранённый курсор. Не нужны `goto`, новая попытка,
сброс кругов, ручное продление снимка или отключение coverage.

Регрессия `tests/engine/integration/route-coverage-refresh.sh` проходит через обычный
`run_agent` с фиктивными исполнителями. Она проверяет повторное истечение, свежий снимок,
недоступность primary и резерва, снятую модель, ошибку preflight, изменение revision,
истечение во время пробы и отказы по повреждённым снимкам без вызова модели. Для
runtime-sensitive резерва она проверяет продолжение узла после смены сборки, остановку при
нестабильной сборке и продолжение при недоступном резерве. Настоящий launcher проверяет
`resume` после ворот: task-stage override убирает снятого исполнителя из оставшихся цепочек,
а готовность исполнителя уже завершённого узла не нужна. Отдельно проверяется перепись `SCHEMA=1`.
