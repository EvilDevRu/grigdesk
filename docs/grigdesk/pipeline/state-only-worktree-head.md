# Проверяющий узел (state-only) не может сравнить файл с HEAD внутри worktree

Инцидент 26.08.2026: отладочный маршрут встал за шаг до `gate_accept`, хотя линт
отработал успешно (`runs/<TASK>/LINT.active` → `STATE=committed RESULT=done`). Узел `lint` объявлен
`filesystem: state-only`, а промпт требовал «сравни диагностику с тем же файлом из HEAD».
Анализатор стиля живёт в контейнере песочницы и видит только рабочее дерево, поэтому копии
HEAD-версии вне worktree (`/tmp` хоста, `$STATE_DIR`) контейнеру недоступны — обе попытки агент
сделал и обе оказались бесполезны, после чего написал
`git show HEAD:… > <worktree>/.head-check.bak`. Post-guard узла (`route-runtime.sh`, ветка
`policy == state-only`) увидел новую неотслеживаемую запись и вернул 75 → `node_execution_finished
status=interrupted`, `orchestrator_session_finished status=failed`, юнит вышел `75/TEMPFAIL`,
перехода `lint → gate_accept` не случилось. Диагноз лежит в
`control/guards-v2/<task>/<attempt>/lint/sequence-NN.after.diff` — одна строка `+UNTRACKED`.

Ловушка двойная: `rm`, `cp`, `mv` для `state-only` закрыты в `core.sh`, то есть убрать свой файл
агент не мог физически, а промпт вдобавок запрещал откатывать guard-запись самостоятельно.
Редирект `>` префиксными правами не выражается и потому прошёл.

Лечение (26.08.2026) — рецепт в промптах узла `lint` тех маршрутов профиля, где он есть:
HEAD-версия подаётся в контейнер через stdin во ВНУТРЕННИЙ путь контейнера, worktree не трогается:

    git show HEAD:<путь> | docker exec -i <контейнер задачи> \
      sh -c 'cat > /tmp/head-check && <анализатор> --check /tmp/head-check'

Правило шире одного промпта: если проверяющему узлу нужен файл, которого нет в рабочем дереве, а
инструмент живёт в контейнере — законный путь только через внутренний путь контейнера. Любая
запись в worktree при `state-only` роняет маршрут fail-closed уже ПОСЛЕ вердикта, и стоит это
полного хвоста от `build`.
