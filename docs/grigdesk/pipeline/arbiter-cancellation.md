# Остановка арбитра и продолжение прогона

Во время читающего разбора карточка конвейера и шапка диалога показывают
«Остановить арбитра». Кнопка доступна для ручного и автоматического разбора.
Она прерывает текущий ход модели, сохраняет полученные реплики и оставляет
возможность явно повторить разбор. Применение решения и повтор запуска этой
кнопкой не отменяются. Закрытие окна по-прежнему не останавливает модель.

`POST /api/tasks/:id/arbiter-conversations/stop` принимает только `operationId`.
Живая проекция `arbitrating.runId` содержит ID операции текущего разбора.
Отсутствующий ход даёт `not_running`, а ID прежнего хода при работающем новом —
`stale_operation`. Запоздалая команда не может остановить следующий разбор.

Сервис сериализует остановку через общую admission задачи, передаёт отмену
исполнителю через `AbortSignal` и ждёт завершения job, снятия живой отметки
и освобождения исполнителя. Сохранённое состояние — `interrupted`, операция
завершена с `error=cancelled`: интерфейс отличает явную остановку от сбоя,
незаконченные реплики также помечены `interrupted`. История объясняет причину.
Поздние callbacks и итог отменённого хода не публикуют новые предложения.
Вотчер не повторяет автоматический разбор той же exact остановки.

Все пути `resumeRouteAttempt`, включая кнопку «Продолжить прогон», массовое
продолжение, ворота и возврат, проходят через `withReadStopped`. До подготовки
стенда и запуска движка сервис останавливает читающего арбитра той же задачи
и сохраняет историю. Admission удерживается до завершения попытки запуска:
новый разбор не вклинится между отменой и продолжением. Даже отказ запуска
не возобновляет отменённый разбор.

Проверки: `arbiter-conversation-api.test.js`, `arbiter-conversation-runner.test.js`,
`factory-route-decision.test.js`, `arbiter-conversation.component.test.js` и
`pipeline-arbiter.component.test.js`. Платная модель для этих проверок не нужна.
