# Перепривязка рантайма при несовместимости поставки исполнителя

Живая попытка закрепляет движок и его helper-ы за одной поставкой сервера. Внешний
ELF исполнителя обновляется независимо: прежний helper может отвергнуть новый ELF,
хотя файлы закреплённого движка существуют. Проверка физических путей pin такую
несовместимость не обнаруживает. Устройство закрепления — в
[контракте кэша сервера](../server/server-binary-cache.md#продолжение-после-смены-сервера).

## Маркер раннера

При доказанной несовместимости поставки `probe` возвращает `4` и печатает отдельную
строку в stderr, без пробелов, префикса или пояснения в той же строке:

```text
RUNNER_SUPPLY_INCOMPATIBLE=glm
```

Общий формат — `RUNNER_SUPPLY_INCOMPATIBLE=<id>`, где id совпадает с проверяемым
раннером. Исходная диагностика helper-а также проходит в stderr. Маркер при другом
коде возврата, с чужим id или с дополнительным текстом не принимается.

[GLM](../../engine/GLM.md) выдаёт маркер только для кодов helper-а:

| Код | Причина |
| --- | --- |
| `deepseek_binary_incompatible` | ELF DSH несовместим с контрактом закреплённого helper-а. |
| `glm_runtime_incompatible` | Ревизии рантайма, профиля или политики GLM несовместимы. |
| `glm_plugin_missing` | Поставка не содержит необходимый плагин GLM. |

Отсутствие ELF (`deepseek_binary_missing`), неподдерживаемый режим
(`glm_factory_mode_unsupported`), непройденный допуск (`glm_runtime_not_admitted`),
отсутствие ключа и прочая недоступность маркера не получают. Повтор или смена
закрепления не являются способом исправления таких отказов.

## От пробы к отказу движка

`profile_runner_host_preflight` сбрасывает `PREFLIGHT_SUPPLY_INCOMPATIBLE` при каждом
вызове. `_profile_preflight_probe` добавляет в CSV-список раннеров с принятым маркером;
вызов пробы остаётся в основной оболочке, чтобы глобаль пережила захват stdout.

При rc=1 `v2_runner_preflight` движок берёт недоступных кандидатов блокирующих цепочек
из `V2_PREFLIGHT_UNAVAILABLE_RUNNERS`. Это область текущего запуска, описанная в
[покрытии цепочек](runner-chain-coverage.md), а не весь диагностический список профиля.
Только если **все** эти кандидаты присутствуют в `PREFLIGHT_SUPPLY_INCOMPATIBLE`,
stderr и журнал этапов получают:

```text
FACTORY_ERROR=runner_preflight_incompatible RUNNERS=glm
```

Смесь «несовместима поставка GLM + у другого необходимого раннера нет ключа» остаётся
`runner_preflight_unavailable`. Ошибки хранения и контрактов preflight сохраняют
`runner_preflight_failed`; голый rc=1 не разрешает перепривязку.

## Один повтор продолжения

Сервер распознаёт `runner_preflight_incompatible` через `routeFailure`. Только путь
`resumeRouteAttempt`, включая продолжение после ворот или возврата, снимает
закрепление через `unpinFactoryRuntimeAttempt` и повторяет запуск один раз.
Это одна перепривязка на запрос продолжения, без цикла автоматических повторов.

Unpin проверяет trusted task/attempt/profile и физические roots. Под global GC lock
и lock scope снимаются authority pin, производный индекс, пережившая reservation
и ссылки реестра на эту попытку. Операция идемпотентна; чужие попытки сохраняются.
Повреждённый индекс или его расхождение с authority дают отказ до удаления файлов.
Токен остаётся в пине до очистки reservation, поэтому частичный файловый отказ
допускает повтор операции.
Повторный запуск через обычный resolver закрепляет текущую поставку сервера.

Attempt ID, каталог, маршрут, каталог попытки, курсор и уже записанные решения ворот
не меняются. Для второго запуска смещение stages.log берётся заново: прежний маркер
не должен подменить новый отказ. Если текущая поставка тоже несовместима, повторный
отказ возвращается человеку. Обычный `unavailable` закрепление сохраняет.

Start не получает автоматической перепривязки. Решение `gate --commit-only` остаётся
CAS без runner preflight; продолжение после решения идёт отдельным resume.

Автоматический путь требует, чтобы закреплённый движок уже поддерживал маркер.
Старые поставки, возвращающие только `runner_preflight_unavailable`, сохраняют прежнее
поведение. Серверные изменения применяются после пересборки и ручного перезапуска.
Закрепление исправного, но отставшего движка снимает человек вручную —
[ручная перепривязка рантайма](runtime-rebind.md).

## Проверка без живого прогона

`unit/glm-runner-launch.sh` проверяет три кода поставки и три отказа без маркера.
`unit/profile-preflight-probe-retry.sh` проверяет строгий формат, id, код возврата,
сохранение и сброс глобали при полном preflight. `integration/route-coverage-refresh.sh`
проверяет полное покрытие, смешанные причины и сохранность решения ворот.

Серверные `factory-gate-cursor.test.js` проходят HTTP resume через настоящий resolver:
успех повтора, второй отказ и обычная недоступность, число запусков и неизменность
trusted файлов попытки. `server-binary-attempt-resume.test.js` проверяет снятие A,
идемпотентность и закрепление B. Живые модельные вызовы для этих проверок не нужны.
