# Арбитр запускается в режиме «Авто»

Ошибка «исполнитель арбитра не объявил режим только чтения» возникала до вызова модели:
`resolveArbiterTarget` требовал от каталога исполнителя режим с точным ID `plan`.
GLM объявляет `default` и `auto`, поэтому выбранная модель не проходила эту проверку.
Режим этапа фабрики и его модель не определяют исполнителя арбитра: он берётся отдельно
из настройки «Модель арбитра».

Арбитр остановки использует `auto`. Резолвер проверяет этот режим и возвращает его
вместе с исполнителем; `arbiterConversationRuntime` передаёт проверенное значение
в `executor.run`. Это общий путь для кнопки, обсуждения, диагностики и watcher.
Отсутствующий, повреждённый или непрочитанный каталог без `auto` даёт
`arbiter_auto_unavailable`; автоматической подмены на другой режим нет.

У каждого сохранённого хода отдельный server-owned `chatKey` из ID диалога и операции.
Runner передаёт его и `onSessionCreated` всем адаптерам, а `sessionId` оставляет пустым:
история уже собрана в prompt, повтор не возобновляет сессию прежнего хода. Callback
проверяет отмену перед передачей prompt. Это выполняет контракт GLM без привязки
разбора к пользовательскому чату; один `auto` без этих параметров давал следующий
отказ `glm_consumer_unsupported`.

`auto` определяет политику инструментов адаптера, а не согласие применить предложение
арбитра. Prompt сохраняет диагностическую роль; решение о возврате и продолжении
принадлежит человеку через apply/resume. Изоляция исходников от записи этим режимом
не обещается. Выключатель автоматического разбора `arbiter.auto` независим от режима
прав: ручной разбор также работает в `auto`.

Проверки: `factory-arbiter-mode.test.js`, `arbiter-conversation-runner.test.js` и
`arbiter-conversation-api.test.js`. GLM проходит настоящий адаптер, подготовку runtime,
запуск процесса и сохранение результата с фейковым DSH web; внешняя модель не вызывается.
