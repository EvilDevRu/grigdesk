# Ручная остановка конвейера — не сбой

Симптом: остановил прогон кнопкой «Стоп» — пришло красное «Конвейер оборвался — демона
нет, а конвейер не закрыт». Вотчер звонил на собственное решение человека и вёл
остановленную задачу в счёт аварий.

Причина: «демона нет» у `detectStall` различается только флагом `STALLED_HUMAN`
(«нужен человек»). Graceful-остановка по сигналу этот флаг не ставит, попытка остаётся
открытой, журнал не содержит «маршрут завершён» — все три признака совпадали с падением,
и остановка классифицировалась `kind: 'crashed'` (уведомление `core.pipelineCrashed` в
вотчере, «✖ Конвейер оборвался» в карточке и на графе).

Правило: штатное завершение демона по сигналу помечается в реестре.

- Движок (`v2_on_signal` в `bin/factory`) ставит `STOPPED_SIGNAL=1`, только когда
  остановка доказана: раннер погашен (`runtime_interrupt_trusted_active`, код 0) и
  инструментация снята (cleanup с кодом 0 или 3). Любой неуспех — прежний
  `STALLED_HUMAN=1`, человек всё равно увидит остановку.
- Метку снимает сам движок при любом новом заходе: свежий `--init` (start), общий
  `set_st ORCH_PID` (resume/gate) и recovery. Между TERM и следующим стартом метка
  честно говорит «остановлен штатно», после старта мёртвый демон снова означает обрыв.
- `detectStall` при `STOPPED_SIGNAL=1` возвращает null: остановленный прогон не входит
  ни в «встали», ни в аварии; карточка показывает обычное «продолжить прогон».
- Не-graceful смерть (SIGKILL по таймауту systemd, oom-killer, выключение питания
  посреди остановки) метки не получает и по-прежнему показывается как обрыв.
- Действует для всех путей остановки, которые заканчиваются TERM движку: кнопка «Стоп»
  в карточке и на телефоне, массовая остановка, `systemctl --user stop` юнита.

Проверка — `tests/server/stall-window.test.js` («штатная остановка по сигналу не
считается обрывом», «маркер остановки не живёт дольше попытки») и контракт движка
`tests/engine/contract/factory-launcher.sh` (утверждения про `STOPPED_SIGNAL`).
