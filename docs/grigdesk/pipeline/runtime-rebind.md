# Ручная перепривязка рантайма остановленной попытки

Живая попытка закрепляется за поставкой сервера authority pin-ом и по умолчанию
несёт его до конца попытки: рестарт GrigDesk, новая сборка и установка поколения
пин не меняют. Автоматическое снятие получает только доказанная несовместимость
поставки исполнителя (маркер `runner_preflight_incompatible`). Исправный, но
отставший от сервера движок маркера не даёт — попытка бесконечно воспроизводит
один и тот же отказ среды, например на новом действии инструмента этапа.

Ручную границу закрывает `POST /api/tasks/<id>/runtime-rebind` (кнопка
«Перепривязать рантайм» в диалоге этапа, секция возврата). Маршрут проходит
тот же `managedRegistry` с trusted identity, отказывает закрытой попытке
(`attempt_terminal`) и живому прогону (`run_in_progress`) — снятие пина у
работающего движка убрало бы защиту reservation. Само снятие выполняет
`unpinFactoryRuntimeAttempt`: под global GC lock и package lock удаляются
authority pin, производный индекс и ссылки реестра; операция идемпотентна.
Ответ несёт `unpinned`, `packageId` прежнего закрепления и человекочитаемый
`note` (тип `PipelineReply.note`).

## Границы

- Попытка сохраняет identity: attempt ID, каталог, маршрут, курсор и решения
  ворот не меняются. Следующий запуск (`resume`, goto «перейти сюда») через
  обычный resolver закрепляет текущую поставку сервера.
- Start новой попытки и `gate --commit-only` автоматической перепривязки не
  получают, отдельного auto-rebind после сборки сервера нет: решение всегда
  за человеком.
- Если попытка расходится с trusted ledger или pin повреждён, маршрут
  возвращает `rebind_failed` и ничего не удаляет; разбор — по журналу сервера.

## Проверка

`tests/server/factory-runtime-rebind.test.js` — pin создаётся настоящим
`prepareFactoryRouteLaunch`, маршрут снимает его и идемпотентен на втором
вызове; живой прогон получает 409 `run_in_progress` с сохранённым pin-ом.
Регресс автоматического пути — `tests/server/factory-gate-cursor.test.js`.
