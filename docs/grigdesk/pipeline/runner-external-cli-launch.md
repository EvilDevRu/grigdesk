# Запуск внешнего CLI в раннере: имя CLI подставляет helper, а не args

Раннеры (`engine/lib/runners/<id>.sh`) собирают массив `args` из аргументов CLI
и передают его в `factory_external_launch <провайдер> <default> "${args[@]}"
(`engine/lib/executor.sh`). Helper сам ставит имя CLI первым элементом:
при валидном descriptor-е внешнего CLI — дескрипторный бинарник (с lease-helper,
env пользовательского терминала), без него — имя из PATH (`default`).

## Контракт

**`args` не включают имя CLI.** Сдвоенное имя доходит до парсера провайдера как
позиционный аргумент перед настоящими флагами:

- Kimi CLI отвечает «unknown command 'kimi'. See 'kimi --help'» и завершает ход
  до обращения к модели;
- Codex CLI лишний позиционный аргумент молча проглатывает, когда дальше идёт
  знакомая подкоманда, поэтому сдвоенный «codex codex exec» внешне работает —
  контракт нарушен, хотя симптома нет;
- Claude CLI получил бы «claude» как позиционный промпт рядом с `-p`.

Ветка restricted shared-stand у Codex идёт мимо descriptor-а через alias-каталог
в PATH и ставит имя CLI в команду явно, тоже поверх `args` без имени.

## Проверенный факт (инцидент 07.11.2026)

Перевод запуска на `factory_external_launch` при оставшемся в `args` имени CLI
дал три падения подряд с «unknown command 'kimi'» за секунды после старта.
Классификатор раннера честно отвёл незнакомый stderr в `unknown` (fail-closed,
переключения исполнителя нет), и журнал попыток показал сырую диагностику CLI —
никакого отношения к квоте или доступности аккаунта отказ не имел. Прогоны
до 28.10.2026 тем же провайдером завершались `ok` на старой схеме запуска.

Приёмка: в unit-тестах раннеров Kimi, Claude и Codex зафиксирована точная
голова команды `timeout` — имя CLI ровно один раз перед аргументами
(`kimi-runner-effort.sh`, `claude-runner-sandbox.sh`, `codex-runner-sandbox.sh`);
проверка падает на старой сборке `args`.
