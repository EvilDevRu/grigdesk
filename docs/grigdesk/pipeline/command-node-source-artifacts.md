# Command-узел тянет за собой артефакт своего узла-источника

Симметричная беда к «транзакционному узлу без пары instrument», и ловится она так же поздно.

Command-узел маршрута исполняет хост по `commandId`, а хук профиля выбирает по этому id
скрипт. Скрипт при этом может зависеть от артефакта, который создаёт ДРУГОЙ узел того же
маршрута: детерминированная проверка «тесты не подменяли» читает доверенный снимок,
закреплённый на выходе red-first узла тестов. Схема маршрута такой зависимости не видит:
`commandId` — просто идентификатор, а снимок живёт в артефактах попытки, не в бандле.

Поэтому перенос готового command-узла в более короткий маршрут выглядит бесплатным и не
является им. Маршрут без узла тестов снимка не создаёт, проверка не находит указатель и
падает — уже ПОСЛЕ отработавшей сборки, то есть после потраченного часа и денег.

Правила:

- зависимость command-узла от артефакта другого узла принадлежит хуку профиля и его
  скрипту; в схеме маршрута её не выразить, значит её обязан стеречь тест определения;
- короткому маршруту нужен свой режим проверки (свой `commandId`), а не ослабление общего.
  Ослабить общий — значит потерять контроль мутации тестов там, где он и нужен: пропавший
  снимок обязан валить полный маршрут, а не молча пропускать проверку;
- у режима без снимка предмет другой и это нормально: гонять нужно тесты ИЗ diff, потому
  что писала их та же сборка. Отсутствие тестов в diff для лёгкого маршрута законно;
- гигиена diff, живость стенда и стиль своих строк одинаковы у обоих режимов — расхождение
  здесь означало бы, что лёгкий маршрут дешевле не за счёт объёма проверки, а за счёт её
  честности.
