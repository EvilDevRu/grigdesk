# Ретро оставлял файлы и ничего не менял: генератор предложений без канала решения

Симптом: после каждого принятого прогона в проект прилетал файл `docs/lessons/tNNNN.md`
(в rdesigner — 31 такой файл в репозитории), а в `~/.grigdesk/factory/state/archive/` копились
`tNNNN.lessons-proposed.md`, и никто ничего по ним не менял.

Замер 22.09.2026: 95 уроков с июля по пяти профилям, применено 14 — все в первую неделю
августа (папка `archive/lessons-applied`), дальше ни одного. Узел стоил ~2,5 мин модели
на прогон (1–5,5 мин по 31 прогону) уже после приёмки человеком. Потребителя не было ни
одного: ни движок, ни сервер, ни веб, ни узлы следующих прогонов уроки не читали; в
GrigDesk `docs/lessons/` вообще стоял в `.gitignore`, то есть задуманный путь «урок приедет
в PR» тут не работал. Содержание при этом повторялось: десять уроков просили одно и то же
для промпта `tests_red` (матрица «критерий → тест» до написания), а в промпте этого нет
до сих пор — возврат `tests_red → tcritic` жил дальше.

Корень: генератор предложений, которым требуется решение человека, без места, где это
решение принимается. Файл в архиве — не место; гранулярность «урок на прогон» — шум,
сигнал даёт только повтор через прогоны, а повторы никто не считал.

Решение: узел `retro` снят из всех маршрутов всех профилей вместе с `artifacts.lessons`,
`artifacts.lessonsRepo`, `LESSONS_DIR` и `--lessons-dir` (см. ENGINE.md, «Ретро: узла нет»).
Приёмка завершает попытку сама (`gate_accept.approved → stop('done')`), у публикующих
маршрутов хвост — один `ship`. Если разбор процесса понадобится — это отдельная
возможность поверх журналов нескольких попыток со счётчиком повторов и применением в один
клик, а не узел в каждом прогоне. Не делать: автоподмешивать уроки в промпты следующего
прогона (самоприменяемые правила) и писать урок каждого прогона в базу знаний (карты базы
идут в контекст каждого агента — затопит).
