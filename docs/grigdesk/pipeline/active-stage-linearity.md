# «Конвейер встал» при живом этапе: правило линейности гасило сам фронт

Симптом: схема конвейера показывает всё погасшим — ни одного активного узла, — а этап в это
время работает, демон жив, агент пишет в лог. Человек второй раз подряд считает прогон
умершим и идёт его «чинить».

Причина в `computeNodeStatuses` (`server/src/lib/factoryGraph.ts`). Реестр — вторичная
проекция, и в нём **легально** остаётся `running` у узла, чей заход прервали: TERM демону,
перезапуск хоста, убитый таймаутом процесс. Тогда активных узлов становится два, и включается
правило линейности «оставить более поздний — он и есть реальный фронт». Написано оно было так:

```js
chain.forEach((n, i) => { if (['run', 'wait'].includes(st[n])) st[n] = i < keep ? 'done' : 'pending'; });
```

При `i === keep` условие `i < keep` ложно, и узел, ради сохранения которого правило и
затевалось, уезжал в `pending` вместе с остальными. Гасли **оба**: и застрявший, и живой.

Хуже того, правило «более поздний» ловит только случай ДВУХ активных. Когда призрак остаётся
один (маршрут ушёл вперёд, а идущий этап на повторном заходе всё ещё несёт `done` от прошлого
круга), схема уверенно показывала работу на мёртвом узле — «повис на chairman» при живом build.

Поэтому опорная точка теперь — **курсор trusted-журнала**, а не проекция:
`computeNodeStatuses` принимает `cursorNode` и расставляет фронт по нему (прежнее правило
остаётся запасным — для исторических реестров и нечитаемого ledger), а `getTaskGraph`
досвечивает сам узел курсора: `ready` при живом демоне → `run`, `paused` → `wait`. Реестр
статус узла переписывает по завершении этапа, поэтому без досветки идущий заход не горел бы
вовсе. Остановку поверх этого по-прежнему красит `detectStall`.

Общее правило: «что показывает схема» и «где на самом деле стоит маршрут» — два разных
источника, и при расхождении верен журнал. Проверять так:

```bash
grep -E '^(ORCH_PID|WF_STATUS)=' ~/.factory/state/t<TASK>.pipeline
systemctl --user is-active factory-t<TASK>.service
tail -5 ~/.factory/state/logs/t<TASK>.stages.log
```
