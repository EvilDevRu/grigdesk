# Область настройки исполнителя этапа

Настройка исполнителя, модели, effort и скорости локальна узлу
текущего прогона. Профиль и его runners.env остаются источником наследования;
переопределение не распространяется на другие узлы, задачи и новые прогоны.

Для работающего этапа включены оба режима: сохранить параметры следующего запуска
без остановки текущего и явно перезапустить с выбранной связкой после предупреждения.
Смена только effort или скорости также создаёт новый запуск того же исполнителя.
При перезапуске движок закрепляет параметры и источник скорости до остановки старой эпохи.

Настройка сохраняется целиком по клику на исполнителя или изменению модели, effort или скорости.
Дополнительного применения нет; несовместимая пара ждёт исправления и не отправляется.
История и параметры текущего запуска отражают собственный факт независимо от будущего.
Сводка будущего запуска обновляется после подтверждения выбора, а запоздалый ответ
прежней эпохи не возвращает её скорость и предупреждение в окно.
Технический контракт и проверки описаны в [настройках модели, effort и скорости](node-model-and-effort.md).

При продолжении перепривязанной попытки Go читает ранее сохранённую связку из
защищённой записи точного узла. Предпроверка и запуск используют один снимок
выбора. Неподтверждённый перезапуск прежнего движка блокирует продолжение.

На Linux Go-движок публикует `stage-runner-settings-v1`, и редактор карточки
использует его по пину попытки. Для работающего этапа запись проверяет текущий
run и epoch. Скорость доступна с `stage-runner-speed-v1` у того же пина. Её `null`
означает наследование, прежняя запись без поля читается как раньше. Сохранённая связка
вступает в силу при следующем допущенном запуске.
Перезапуск закрывает приём статуса старой эпохи и ждёт завершения её дерева.
Затем запускается новая эпоха с отдельным правом на результат. При неясном
исходе прерванного перезапуска движок останавливается с диагностикой.
Если после подтверждённой остановки движок отказал новой эпохе из-за скорости,
исправьте настройку и продолжите ту же попытку.

Сохранение для будущего этапа возможно во время работы другого узла. Запись
сериализована с публикацией процесса выбранного этапа под task lock. Если сам
выбранный этап успел запуститься, клиенту нужен его актуальный run и epoch.
Сообщения об ошибке показываются в стандартном блоке ошибки во вкладке «Исполнители».
