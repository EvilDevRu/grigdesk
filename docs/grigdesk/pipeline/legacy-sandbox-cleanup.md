# Стенд старой задачи не сносился: попытка родилась раньше lifecycle-журнала

Симптом: у задачи, начатой давно, кнопка «снести стенд» отвечает ошибкой, и так же
отвечают «продолжить прогон» и «перейти сюда». Стенд при этом жив, демон мёртв,
реестр цел. В журнале этапов — одна строка:

```text
route: abandon: lifecycle session не открыта (код 78)
```

Механика: все три действия проходят через `v2_lifecycle_begin_session` в режиме
`resume`, а он открывает сессию, **уже неся scoped route identity** (`routeId`
+ `routeHash` закреплённого маршрута). Валидатор журнала требует, чтобы такая
identity появлялась только ПОСЛЕ события `route_selected`
(`scoped route identity appears before route_selected` в
`engine/lib/attempt-lifecycle-state.py`). У попытки, начатой до появления
lifecycle-аналитики, журнал пуст, `route_selected` в нём не будет никогда —
значит отказ детерминированный, и повтор кнопки его не лечит.

Правило: **пустой журнал означает «lifecycle этой попытке не ведём», а не «допиши
недостающее начало»**. Дописать `route_selected` задним числом нечем — ни сессии,
ни времени выбора маршрута в журнале не было, а выдуманная аналитика хуже
отсутствующей. Поэтому `v2_lifecycle_begin_session` при `resume` без единого события
в журнале возвращает 0, не открывая сессию: все события стоят за
`runtime_lifecycle_enabled_v2`, и невыставленный контекст даёт молчание, а не
половину журнала.

**Пустой журнал отличается от испорченного по коду возврата чтения**
(`v2_lifecycle_ledger_empty`): пусто — это `rc=0` и ноль строк, ошибка чтения
по-прежнему останавливает операцию. Иначе порча журнала молча превращалась бы
в «аналитику не ведём».

Как отличить этот случай от прочих 78 за один взгляд: сравни дату каталога попытки
с наличием событий —

```bash
ls ~/.factory/control/protocol-v2/tasks/t<TASK>/attempts/a_*/lifecycle/segments/*.ndjson
```

Ноль байт (или каталога нет вовсе) — это он. Сторож — три проверки `pre-ledger`
в `tests/engine/contract/factory-launcher.sh`.
