# Арбитр: приём итогов модели и видимый отказ

Итог от исполнителя проходит серверный `parseArbiterModelResult` перед строгим
`decodeArbiterResult`. Только на этой границе допускаются три отклонения оформления:

- у варианта вопроса необязательное текстовое `description` проверяется по длине
  и содержимому, затем удаляется из канонического результата;
- отсутствующий `explanation` предложения заполняется его собственным
  `expectedResult`. Пустой или повреждённый явно переданный `explanation` не подменяется;
- отсутствующий `recommended` предложения заполняется `false`: не помеченное
  рекомендованным предложение считается нерекомендованным. Явно переданное значение
  остаётся строго булевым; `null`, строки, числа и другие типы отклоняют весь итог.

Действие, цель, указание, виды предложений, количества и идентификаторы проверяются
прежним строгим декодером. Неизвестное поле, лишнее исполняемое поле или недопустимая
цель отклоняют весь итог. Хранилище и HTTP-намерения сохраняют прежний строгий контракт:
после границы модели `recommended` обязателен, как и `explanation`.
Нормализация не вызывает модель повторно и не применяет предложения.

Prompt содержит полноценный JSON-пример и текстом требует у каждого предложения
`explanation` и `recommended: true|false`, а также называет поля варианта вопроса.
Повреждённый JSON даёт `bad_model_reply` без публикации фрагмента сырого служебного
ответа. Причина отказа сохраняется в `operation.message`; системная запись остаётся
частью истории.

## Реплики

Общий `arbiterMessageText` убирает обрамляющие теги и пустые края публичной реплики.
Frontend применяет его также к ранее сохранённым сообщениям арбитра; сообщения
человека не меняются. Известный ошибочный closing `</arbriter-message>` завершает
только кадр, открытый точным `<arbiter-message>`: последующий неразмеченный текст
не публикуется. Неверный opening не открывает публичный кадр.

Разрезанные маркеры удерживаются до следующего snapshot. Если итог хода отклонён,
только незавершённые реплики получают `interrupted`; уже закрытые сохраняют `complete`.

## Панель решения

При отказе читающего хода панель показывает причину, ручной повтор и возможность
уточнить вопрос. Обещание будущих вариантов в этом состоянии скрыто. Для прежнего
диалога без `operation.message` причина берётся из системной записи его истории.
Read-only история не получает кнопку повтора.

На широком экране панель удерживается при прокрутке истории; на узком стоит перед
ней. Новый отказ прокручивается в видимую область без захвата клавиатурного фокуса.
Одинаковые пояснение и ожидаемый результат не повторяются двумя абзацами.

Проверки: `arbiter-model-result.test.js`, `arbiter-conversation-runner.test.js`,
строгие shared/store/API/apply-тесты и component/browser-сценарии диалога. Браузер
проверяет desktop/mobile, F5, явный повтор после отказа и отсутствие лишних goto.
Модель и оркестратор в нём подменены, пользовательские задачи не изменяются.
