# DeepSeek и GLM

DeepSeek и GLM используют совместимую автономную поставку Harness. Настройка доступа и оплаты зависит от выбранного сервиса.

## Перед началом

Установите совместимый бинарник через штатную поставку и подготовьте доступ в настройках соответствующего исполнителя. Отсутствие этой поставки не закрывает остальных исполнителей.

## Что делать

1. Откройте «Настройки → Исполнители», выберите сервис и заполните «Ключи доступа», если они требуются.
2. Сохраните и нажмите «Перепроверить». Прочитайте версию, доступность и сообщения о несовместимости.
3. В чате выберите доступную модель и режим. «Спрашивать» требует решения перед изменением/командой; «Авто» допускает самостоятельные действия в разрешённой папке; «Только чтение» запрещает запись и shell. У DeepSeek штатный веб-поиск и чтение публичных страниц не требуют отдельного разрешения во всех трёх режимах.
4. Для DeepSeek проверьте ресурсы счёта во всплывашке: баланс, сведения о тарифе и прогноз. Действующие условия проверяйте по ссылке поставщика из интерфейса.
5. При обрыве прочитайте сделанное и используйте предложенное продолжение в той же сессии.

## Результат

Исполнитель запускается с доступными моделями и выбранной политикой. Ключ, сохранённый окном, применяется сервером без ручной правки файлов.

## Ограничения и восстановление

Проверка metadata не делает платного запроса и не доказывает принятие ключа API. Тарифы и модели меняются; справка не фиксирует цены. Основная граница записи Harness — рабочая папка; дополнительные пути могут требовать разрешения. Проектные MCP доступны по поддерживаемому контракту и не запускаются в режиме только чтения. Совместимость обновления/отката проверяется поставкой; неизвестный исход операции не повторяется автоматически.

Если GLM сообщает об исчерпанном лимите Coding Plan, GrigDesk завершает ход и не назначает
автоматическое продолжение через минуту. Откройте лимиты GLM, проверьте время сброса и
продолжите разговор после восстановления квоты. Этот отказ распознаётся по коду ответа Z.ai,
даже если Harness пометил его как ограничение частоты. Собственные повторы запроса внутри
Harness могут пройти до того, как GrigDesk получит окончательную ошибку.
