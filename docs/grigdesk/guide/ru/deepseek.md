# DeepSeek и GLM

DeepSeek и GLM используют совместимую автономную поставку Harness. Настройка доступа и оплаты зависит от выбранного сервиса.

## Перед началом

Установите совместимый бинарник через штатную поставку и подготовьте доступ в настройках соответствующего исполнителя. Отсутствие этой поставки не закрывает остальных исполнителей.

## Что делать

1. Откройте «Настройки → Исполнители», выберите сервис и заполните «Ключи доступа», если они требуются.
2. Сохраните и нажмите «Перепроверить». Прочитайте версию, доступность и сообщения о несовместимости.
3. В чате выберите доступную модель и режим. «Спрашивать» требует решения перед изменением/командой; «Авто» допускает самостоятельные действия в разрешённой папке; «Только чтение» запрещает запись и shell. У DeepSeek штатный веб-поиск и чтение публичных страниц не требуют отдельного разрешения во всех трёх режимах.
4. Для DeepSeek проверьте ресурсы счёта во всплывашке: баланс, сведения о тарифе и прогноз. Действующие условия проверяйте по ссылке поставщика из интерфейса.
5. При обрыве прочитайте сделанное и используйте предложенное продолжение в той же сессии.

## Результат

### Допуск GLM при сборке из исходников

В `grigdesk-ctl` откройте «Сборка → DeepSeek Harness → Собрать и установить».
Штатная сборка Harness 0.2.3-alpha.2 включает GLM-5.4 автоматически.
Если у собранного кандидата нет допуска для настроенного режима GLM, терминал
предложит живую проверку. Выберите нужный режим или оба доступных режима.
Если допуск нужен обоим, проверки идут параллельно. Каждая использует ключ и квоту
своего режима Z.ai. После успеха выбранных проверок сборка продолжится с новым
допуском. При отказе от проверки действующая установка сохранится, а терминал
покажет путь собранного кандидата.

Чтобы проверить допуск для обоих режимов, откройте «Сборка → DeepSeek Harness →
Получить допуск GLM». Команды для этих действий — `grigdesk-ctl build deepseek`
и `grigdesk-ctl build deepseek-admission`.

### Доступ в чате GLM

Откройте «Что доступно в этом чате» рядом с полем ввода. Там видны права на папки,
поддержка изображений выбранной моделью, состояние настройки поиска, доступные вкладки,
проектные MCP и счётчики ошибок инструментов в загруженной истории.

- Для веб-поиска задайте в окружении службы `GRIGDESK_GLM_SEARCH_API_KEY` с ключом DeepSeek для поиска.
- Выберите проектный MCP в окне доступа или отправьте `/mcp имя запрос`.
  Подтвердите запуск сервера и каждый нужный вызов. Если служебный MCP
  `grigdesk-work` не поднялся, GLM остановится до первого запроса к модели.
- Для длительной работы отправьте `/goal описание цели`. Лента показывает раунды и итог.
  «Стоп» останавливает работу. Чтобы снова запустить цель, отправьте `/goal resume`.

Исполнитель запускается с доступными моделями и выбранной политикой. Ключ, сохранённый окном, применяется сервером без ручной правки файлов.

## Ограничения и восстановление

В профилях доступа обычный API GLM и Coding Plan считаются двумя отдельными подключениями
со своими ключами и лимитами. Одновременно активен один профиль исполнителя.
Поставка Harness 0.2.3-alpha.2 включает GLM-5.4 в обоих каталогах.
В обычном API также доступны GLM-5.3-FlashX и GLM-5.3-FlashX-Legal.
Для запуска в чате сборка должна получить допуск выбранного режима. Ответ модели
зависит от доступа на стороне Z.ai.

При повторном входе DeepSeek принадлежность нового ключа аккаунту определить нельзя.
Замена требует явного подтверждения; отмена сохраняет прежний доступ. После подтверждения
ID профиля и история остаются, а сессия исполнителя начинается заново без прежней памяти.
Повторный вход в неактивный профиль не включает его автоматически.

Проверка metadata не делает платного запроса и не доказывает принятие ключа API. Тарифы и модели меняются; справка не фиксирует цены. Основная граница записи Harness — рабочая папка; дополнительные пути могут требовать разрешения. Проектные MCP доступны по поддерживаемому контракту и не запускаются в режиме только чтения. Совместимость обновления/отката проверяется поставкой; неизвестный исход операции не повторяется автоматически.

После установки или обновления Harness список моделей может появиться с задержкой.
Первое чтение каталога ждёт, пока GrigDesk распакует и проверит новую поставку.

Если на маршруте с неработающим IPv6 GLM или DeepSeek сообщает «оборвалась связь с моделью»,
обновите автономный Harness до сборки с исправленным переключением между IPv4 и IPv6.
После установки совместимой сборки следующий ход использует её без перезапуска GrigDesk.
Откройте тот же разговор и продолжите с места остановки.

Если GLM сообщает об исчерпанном лимите Coding Plan, GrigDesk завершает ход и не назначает
автоматическое продолжение через минуту. Откройте лимиты GLM, проверьте время сброса и
продолжите разговор после восстановления квоты. Этот отказ распознаётся по коду ответа Z.ai,
даже если Harness пометил его как ограничение частоты.

Если Z.ai вернул код `1311`, выбранная модель недоступна по текущему Coding Plan.
GrigDesk покажет причину и завершит ход. Выберите доступную модель в том же разговоре.
Истечение подписки и ограничения аккаунта или типа ключа тоже получают отдельное сообщение.
При временном ограничении частоты GrigDesk может продолжить тот же ход после паузы.

Если GLM остановился с сообщением «Обязательная проверка GLM отказала» при записи
длинного текста, причина могла быть в обработке русского текста старой версией
GrigDesk. После установки версии с исправлением отправьте новое сообщение в том же
разговоре: «Продолжи с места остановки, сначала проверь сохранённые файлы».
Очищать историю и сбрасывать память для этого не требуется. Операция не повторяется
автоматически; общая ошибка проверки может иметь и другие причины, требующие диагностики.
