# Данные и резервные копии

Программа, данные сервера и настройки клиентского окна хранятся отдельно. Резервная копия должна учитывать все используемые места.

## Перед началом

Определите выбранную машину и её фактическую папку данных. По умолчанию это `~/.grigdesk`; явные настройки могут задавать другие пути.

## Раскладка папки данных

Пути относительны папки данных; переменная окружения `GRIGDESK_HOME` выбирает другую папку.
Папки создаются по мере надобности: отсутствующая папка означает, что функция ещё не использовалась.

| Папка | Содержимое |
| --- | --- |
| `.env` | Настройки машины и ключи исполнителей |
| `chats/` | История разговоров и вложения (см. ниже) |
| `state/` | Состояние сервера: настройки, реестр моделей, сессии и ключи, профили SSH/БД, журналы, данные плагинов, ресурсы речи и презентаций |
| `artifacts/` | Рабочая папка агентов: снимки, дампы, скрипты и отчёты проверок |
| `factory/` | Конвейер: состояние движка и homes исполнителей, маршруты и черновики, триаж задач |
| `qwen-runtime/` | Homes сессий Qwen Code: память и привязки сессий исполнителя |
| `runtimes/` | Кэши поставок автономного сервера и DeepSeek |
| `profiles/` | Проектные профили фабрики (бинарная поставка) |
| `plugins/` | Установленные пользовательские плагины; рабочие данные — в `state/plugins/` |
| `drivers/`, `db-engines/` | Внешние драйверы трекеров и движки баз данных |
| `telegram/`, `github/` | Архивы входящих и настройки аккаунтов; токены — в `state/` |
| `mobile/` | Доступ телефона: TLS-ключи, устройства, посредники |
| `3d/` | Библиотека раздела «3D» |
| `browser/`, `provider-cli-leases/` | Сокет браузерного relay и leases внешних CLI исполнителей |

Каждый чат — отдельный файл `chats/YYYY-MM/<id>.json`, где `YYYY-MM` — месяц создания чата;
вложения лежат в `chats/attachments/`, дефолты новых чатов — в `meta.json`, памятка удалений —
в `deleted.json`. Чтобы найти чат по ID, ищите файл `<id>.json` в папках месяцев; если месяц
создания неизвестен — просмотрите все папки `YYYY-MM/`. ID чата виден в адресе интерфейса.
Чтение переписки допускается только с явного разрешения человека.

## Что делать

1. Завершите ходы агентов, записи, установки и задания. Согласованно остановите использующие данные процессы штатными средствами владельца.
2. Скопируйте папку данных целиком с сохранением прав: настройки машины, историю и вложения, привязки устройств, архивы входящих, плагины и их состояние, модели и артефакты.
3. Отдельно сохраните рабочие репозитории, homes исполнителей, фабричное состояние и каталог маршрутов. Они могут находиться вне папки GrigDesk. Сохраните также настройки окна и выбранного сервера, если нужен перенос клиента.
4. Проверьте читаемость копии и храните её с ограниченным доступом: в ней есть ключи и переписка.
5. Восстанавливайте при остановленных процессах. Верните согласованные папки и права, затем запустите одну копию сервера и проверьте машину и историю.

## Результат

Получена согласованная копия рабочих данных, а не только бинарников программы.

## Артефакты новых ходов

На Linux GrigDesk создаёт папку `artifacts/chat-runs/projects/<проект>/<запуск>/` в общей
папке данных, вне Git. Запуски без проекта хранятся напрямую в `artifacts/chat-runs/`.
Ссылки из разговора работают после удаления рабочей копии, пока файл остаётся на диске.

Через 14 суток после завершения хода GrigDesk удаляет его папку при очередной ежедневной
проверке. Чтобы сохранить папку, создайте в ней пустой файл `.keep` или попросите
агента закрепить запуск. Размещение зависит от границ записи исполнителя. Если он
не может получить папку запуска, действует прежняя схема.

## Что занимает место в артефактах

Выполните `grigdesk-ctl artifacts-cleanup --inventory`. Команда покажет объём по
категориям и 20 крупнейших записей. Для разбивки одного каталога верхнего уровня
добавьте `--topic <имя>`, для полного списка в байтах — `--json`.

Инвентаризация учитывает выделенные на диске блоки и работает без удаления и отбора
по возрасту. Если отдельные папки недоступны, отчёт покажет уже измеренный объём и
ошибки чтения. Большой обход может занять несколько минут. Ctrl+C выводит частичный отчёт.

## Уборка старых артефактов

1. Сохраните нужные артефакты в резервной копии. Уборка необратима и не проверяет ссылки
   из переписки: картинки старых ответов могут исчезнуть после удаления их файлов.
2. Выполните `grigdesk-ctl artifacts-cleanup --dry-run`. Проверьте показанный корень,
   каждый каталог, его размер и сумму. Явная `GRIGDESK_ARTIFACTS_DIR` выбирает другую папку.
   Большой обход может идти минуты. В терминале видно этап, текущую папку, счётчики
   и время с начала. Ctrl+C безопасно отменяет предварительный просмотр и в команде, и в меню.
3. Выполните `grigdesk-ctl artifacts-cleanup`, когда список подходит. Для другого возраста
   добавьте `--older-than 12h` или `--older-than 14d`: допустимы целые минуты `m`, часы `h`
   и сутки `d`, умолчание — 7 суток. `--keep-generations 3` задаёт число последних поколений
   тестового кэша. `--json` даёт машинный отчёт для скриптов.
4. Либо выберите «Разработчику → Уборка артефактов» в терминальном меню любой установки.
   Под отчётом выделена «Отмена». Прокрутите отчёт клавишами PgUp/PgDn или Home/End.
   Чтобы продолжить, выберите строку «Удалить» стрелками и нажмите Enter. Меню повторно
   проверит показанных кандидатов и пропустит папки с ошибками. Esc отменяет уборку.
5. Проверьте отчёт. Молодые и занятые каталоги сохраняются, как и основные части кэша Node.
   Если найдены только молодые данные, уборка не блокирует запуск исполнителей.
   На время удаления новые операции с directory lock ждут завершения уборки; при занятом
   барьере другая уборка пропускает каталоги. После завершения команду можно повторить.
   Байты отчёта оценивают удалённые файлы и могут отличаться от прироста свободного места.
   При ошибке исправьте причину и повторите команду: остальные каталоги могли уже удалиться.
   Ctrl+C останавливает уборку с кодом 130, SIGTERM — 143. Начатое удаление одного каталога
   может завершиться; следующие не удаляются, уже удалённое не возвращается. Отчёт сохраняет
   сделанную часть работы; в JSON отмена отмечена полем `interrupted: true`.

Старые темы убираются вручную. Тесты DeepSeek подчищают только свои
известные старые результаты. Потерянные пользовательские файлы восстанавливаются из копии;
тестовые сборки пересоздаются штатной подготовкой.

## Ограничения и восстановление

Нельзя обещать полный backup одной папкой: фабрика и внешние исполнители имеют собственные homes. Кэши поколений сервера не заменяют историю. Не удаляйте блокировки живых процессов. Старые абсолютные ссылки на вложения могут требовать прежнего расположения.
