# Редактор маршрутов

Редактор подготавливает маршрут для будущих запусков. Черновик и опубликованная версия — разные состояния.

## Перед началом

Выберите проект и маршрут. Для изменения нужны права на настройки профиля и понимание входов и результатов этапов. Опубликованные маршруты и черновики по умолчанию находятся вместе с фабрикой в общей папке данных. Исходники скриптов маршрута остаются в выбранном профиле; явно настроенные внешние пути сохраняются.

## Что делать

1. Откройте «Маршруты», выберите проект и создайте либо откройте черновик.
2. Просмотрите схему и свойства этапов: исполнителя/команду, входы, проверки, переходы и возвраты. Укажите, где требуется решение человека.
3. Сохраните черновик. При конфликте редакций перечитайте новую версию и сопоставьте свои правки, затем сохраните согласованный вариант.
4. Запустите проверку маршрута и исправьте указанные ошибки связности, входов и доступности исполнителей.
5. Опубликуйте проверенную редакцию. В форме нового запуска убедитесь, что предлагается нужный маршрут.

В узкой панели области «Каталог / Маршрут / Свойства» переключаются компактными
вкладками, как на доске. Выбор и неприменённые поля сохраняются при переключении.
Круглый плюс в шапке каталога создаёт отдельный черновик. Такой же плюс рядом
с выбором проекта открывает создание проекта; назначение указано в подсказке.

Модель и усилие задаются политикой запуска вне каталога маршрута; инспектор показывает эффективную политику для чтения. При добавлении этапа мастер предлагает роль, требования к стенду/правам и место вставки, показывая пакет переходов до применения. Ctrl+S сохраняет применённые правки; локальный неприменённый ввод поля сначала нужно применить его кнопкой.

## Из терминала

`routes` поставляется отдельным исполняемым файлом SEA: системный Node не нужен.
В исходниках соберите его командой `npm --prefix routes run build`; результат
`bin/routes` находится вне Git. До сборки можно вызвать
`node routes/src/main.ts …`. Справка, версия и лицензия: `--help`, `--version`, `--license`.
Готовый серверный комплект включает CLI в bin своего поколения; при ручной установке ELF
положите новый файл в bin выбранной установки.

`bin/routes` возвращает JSON через тот же сервер. Используйте `editor <профиль>`,
затем при необходимости `source <профиль> --mode editor --yes` с прочитанными
`--expected-source-revision` и `--expected-catalog-hash` (none — отсутствие каталога).
Создайте `new <профиль> --from empty`, сохраните `show <профиль> --draft <id>` в JSON,
отредактируйте все пять полей контента и выполните
`apply <профиль> --draft <id> --file document.json --expected-revision <N>`.
Apply заменяет весь контент: отсутствующие маршруты удаляются. Исходная ревизия N
относится к прочитанному перед редактированием снимку, не к более свежому GET.

Запустите `validate <профиль> --draft <id> --expected-revision <новая-ревизия>`.
Exit 0 означает полученный отчёт: проверьте issues и severity. Затем снова прочитайте editor,
сопоставьте ожидания и вызовите `publish` с `--draft`, `--expected-revision`,
`--expected-source-revision`, `--expected-catalog-hash` и `--yes`.
Для отката используйте `rollback <профиль> --hash <хеш>` с ожиданиями source/current и --yes.
Перед публикацией stderr выдаёт operationId: при обрыве читайте `publications <профиль> <operationId>`,
не повторяйте запись вслепую. Конфликт требует сопоставления версий.

`profile-config get <профиль>` читает конфигурацию, а
`profile-config set <профиль> --file profile.sh --set PROFILE_LOOP_MAX_ROUNDS=40`
меняет разрешённое значение с его прочитанным from. Новые профили команда не создаёт.
Полный технический справочник в исходниках: `docs/grigdesk/pipeline/routes-cli.md`.
Живой CLI-цикл после перезапуска сервера ещё требует ручной проверки.

## Результат

Новые попытки используют опубликованный каталог. Само сохранение черновика запуск не меняет.

## Ограничения и восстановление

Публикация не переписывает уже закреплённый маршрут текущей попытки. Удалённый проект оставляет несохранённый черновик для чтения; сохранить его через сервер нельзя. Не обходите конфликт версии повторной записью вслепую.

При переносе прежней фабрики следуйте [порядку обслуживания](data-and-backups.md).
Перепубликация маршрута и ручная правка старого routesDir не заменяют перенос;
уже закреплённые версии и история попыток сохраняются.
