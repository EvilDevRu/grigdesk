# Установка приложения

В поставке v3 вместе с выбранными компонентами скачивается `control.tar.gz`.
Он содержит команду `grigdesk-ctl`. Первый переход зарегистрированной установки
на Go требует отдельного подтверждения после закрытия её окна и сервера.
В терминале используйте `--migrate-to-go`. В автоматическом режиме нужен
`--yes --migrate-to-go --expected-current-sha <sha256>` для исходного `current.json`.

С сайта скачивается небольшой терминальный скрипт. Он получает helper и только выбранные
компоненты готового выпуска. Нужен интернет; исходники и системные Node/npm не нужны.
Этот способ установки относится к выпускам Linux с сайта.

## Перед началом

Поддерживается Linux x64 с glibc 2.28 или новее. Нужны curl, gzip и coreutils.
GUI и FUSE 2 нужны для запуска окна; серверный режим работает без них.
Установщик сообщает недостающие условия и не устанавливает системные пакеты сам.
Перед переходом с прежней portable-папки закройте её окно и сервер, сохранив данные.

## Что делать

1. Скачайте `grigdesk-install` проверенного выпуска с [сайта GrigDesk](https://grigdesk.com).
2. Откройте терминал в папке загрузки и выполните `sh ./grigdesk-install`.
3. Выберите local — окно и местный сервер, remote — только окно, server — только сервер.
4. Укажите отдельные папки программы и данных. Проверьте версию, пути и объём загрузки,
   затем подтвердите. До согласия ничего не скачивается.
5. Дождитесь проверки файлов и завершения. Служба регистрируется без автоматического запуска.
   CLI и доступ внешних исполнителей настраиваются отдельно.

Для автоматизации укажите режим и согласие явно:

```sh
sh ./grigdesk-install --yes --mode server --root /выбранная/программа --data-home /выбранные/данные
```

Сохраняются `install local|remote|server` и абсолютные флаги `--root`, `--data-home`,
`--user-data`, `--bin-dir`, `--applications-dir`, `--unit-dir`. Пробелы допустимы.
`--launch` запускает окно после установки local/remote и требует GUI/FUSE заранее.
Без этого флага установка по SSH допустима с предупреждением о будущем запуске окна.

Скрипт закрепляет точные SHA и размеры индекса/helper; helper проверяет подпись выпуска
до установки компонентов. При ошибке проверки файлы не запускаются.
Не выполняйте старую команду `--verify` для shell: проверка входит в установку.

## Кандидат для Apple Silicon

В GitHub Actions в форме **Run workflow** по умолчанию отмечены Linux x64 и
macOS Apple Silicon. Чтобы получить только комплект для Mac, снимите флажок Linux.
Для Mac используется канал `dev` без публикации на сайте.

Для скачанного комплекта разработки используйте macOS 15 или новее. Откройте терминал
в распакованной папке комплекта и выполните:

```sh
sh ./grigdesk-install --source-dir "$PWD"
```

Доступны те же три режима. Установка использует скачанные файлы и системные средства
macOS. Папка данных должна быть отдельной и иметь абсолютный путь без пробелов.
Если установка прервалась, повторите команду с тем же комплектом, режимом и путями.
Для режимов с сервером `grigdesk-ctl server start --wait` запускает службу,
`grigdesk-ctl server stop` останавливает её, а `grigdesk-ctl server logs` открывает журнал.
В режимах с окном его можно открыть через `grigdesk-ctl open`.
Нативная приёмка кандидата macOS выполняется отдельно.

## Вариант: deb-пакет

Установите `grigdesk_<версия>_amd64.deb` через
`sudo apt install ./grigdesk_<версия>_amd64.deb`. Он содержит только скрипт и launcher,
требует интернет и открывает терминал при первом запуске из меню приложений.
После установки используется пользовательское окно; дальнейшие обновления не требуют apt/sudo.
Удаление deb сохраняет программу и пользовательские данные.

## Результат

Программа имеет приватную регистрацию и проверенные поколения компонентов с общим current.
Remote не скачивает сервер и не создаёт местный серверный descriptor.
Папки программы, данных и профиля окна остаются раздельными.

## Меню команды

Запустите `grigdesk-ctl` без аргументов в терминале. В шапке видны версия, сервер и окно.
Стрелки меняют выделение, Enter открывает пункт, Esc возвращает на предыдущий экран.
Сборка из меню показывает прогресс и итог на том же экране. Ctrl+C отменяет сборку.
После результата нажмите Enter или Esc, чтобы вернуться к выбранной цели.
В подтверждениях по умолчанию выбрана отмена. Для текстового оформления задайте
`NO_COLOR=1`. В терминале с `TERM=dumb` стадии работы печатаются отдельными строками.

## Проверка кандидата из исходников

В меню `grigdesk-ctl` откройте «Дистрибутив». Официальные файлы Actions выбираются каталогом,
собственная успешная сборка — UUID из вывода `dist build`:

```sh
grigdesk-ctl dist check --from /каталог/артефактов
grigdesk-ctl dist check --local-run <UUID>
```

Проверка устанавливает три режима во временных профилях. «Установить для проверки»
просит режим, отдельные пути и согласие. Локальный кандидат доверяет только собственной
приватной записи запуска и не подходит для публикации; `--from` использует официальный ключ.
`dist build` проходит полный релизный рецепт в копии исходников.
В терминале и в меню «Собрать дистрибутив» шкала показывает долю
завершённых стадий, текущую стадию и последнюю строку вывода. Путь к полным журналам
появляется после подготовки снимка, а 100% — после записи проверенного кандидата.
На Linux нативные серверные тесты создают свой scope в пользовательском systemd.
Для сборки AppImage нужны curl, unzip и 7z.

На Apple Silicon «Сборка → Всё» и `grigdesk-ctl build all` запускают
`dist build --channel dev`. Нужны macOS 15 или новее, инструменты Xcode,
нативный Node и формулы Homebrew из `tools/ci/Brewfile.macos`.
Сборка сама проверяет окружение. На новой машине или после ошибки подготовки
можно отдельно выполнить `bin/utilities/ctl dist doctor` из корня исходников
и посмотреть `ok` и `checks` в отчёте JSON.
После успешной проверки комплект можно установить командой
`dist install --local-run <UUID>` с режимом и путями. Для официальных кандидатов
действует собственный ключ подписи.

Проверка использует изолированные рабочие папки. На macOS при Ctrl+C команда
дожидается подтверждения остановки того временного сервера, который она запустила.
Это касается и службы, которая ещё запускается. Если владельца или остановку
подтвердить не удалось, команда выводит путь к сохранённой установке и её журналам.
Кэш подготовки хранится отдельно от результатов проверки.

## Ограничения и восстановление

Проверенные архивы сохраняются в приватном cache; после обрыва повтор скачивает незавершённое
целиком. Чужая или неполная папка установки не удаляется: сохраните файлы и причину отказа.
Повтор своей завершённой установки использует штатный updater и сохраняет прежний helper.
Не удаляйте данные или регистрацию ради повторного запуска.

На сайте хранятся две последние лёгкие версии каждого канала. Если давно сохранённый скрипт
больше не находит закреплённые файлы, скачайте новый с официального сайта.
Чистая VM, настоящее окно и официальный Actions-кандидат проходят отдельную приёмку владельцем.
Android устанавливается и обновляется отдельно.
