# Код и Git

Плагин «Код» показывает файлы, Git-изменения и коммиты зарегистрированных репозиториев. Просмотр исходников и сравнений работает только для чтения.

## Перед началом

Включите инструмент и зарегистрируйте пути проекта. Для Git-действий нужен доступный репозиторий на сервере.

## Что делать

1. Откройте «Код» и выберите проект, репозиторий и рабочую копию.
2. В «Файлах» выберите документ либо найдите путь/содержимое поиском от двух символов. Клик по результату открывает строку.
3. В «Изменениях» сравните индекс с HEAD и рабочее дерево с индексом: один файл может быть в обеих группах. Выберите файл либо общий «Обзор».
4. В «Коммитах» отметьте диапазон; Shift добавляет промежуток. «+ текущие» включает рабочие изменения только для диапазона до HEAD. «Вся ветка» требует доступной базы.
5. Переключайте вид рядом/в колонку кнопкой над кодом; пробелы, контекст и перенос строк находятся под значком «Вид сравнения». F7/Shift+F7 переходят по блокам, затем к соседним файлам группы.
6. Для проверки используйте «Просмотрено», прогресс и переход к непросмотренному под шапкой. В меню «Действия с кодом» доступны выделение блока, замечание, объяснение и частичный индекс. Корзина «Замечания агенту» открывается отдельно. В узкой панели подписи действий заменяются значками с подсказками; настройки расположения остаются под значком «Вид сравнения». Действия индекса, отката и коммита выполняйте только в показанной области с учётом предупреждений и подтверждений.
7. «Спросить агента» создаёт отдельный редактируемый черновик с файлом/изменениями, не отправляя его. «Ссылка» копирует путь и доступную позицию.

Над деревом изменений можно искать по пути; воронка раскрывает фильтр статуса.
В меню «Действия с деревом» рядом с поиском можно свернуть, развернуть каталоги
или показать открытый файл. Счётчик результатов и очистка появляются при фильтрации.
Выберите несколько файлов через Ctrl/Meta, Shift или кнопку выбора строки:
появится панель действий с числом выбранных файлов и кнопкой снятия выбора.

## Проверить другую ветку на основном стенде

1. Выберите основную рабочую копию нужного репозитория. Нажмите кнопку текущей ветки в шапке.
2. В «Командах запуска проекта» один раз задайте остановку, сборку, запуск в фоне и проверку готовности. Подготовка и адрес приложения необязательны. Команды выполняются через Bash в этой же папке; запуск должен поднять фоновый процесс и завершиться, а проверка — дождаться готовности и вернуть код 0. Сохранение команд стенд не запускает. Ветка возврата по умолчанию — `dev`.
3. Найдите локальную или удалённую ветку. Список показывает уже известные Git ветки; перед выбором новой удалённой ветки обновите refs круговой стрелкой fetch в «Изменениях».
4. Нажмите «Переключить и собрать» и проверьте папку, ветку и коммит в подтверждении. Стенд будет остановлен, эта же папка переключится на выбранную ветку, затем выполнятся сохранённые команды. На каждый этап отводится до 20 минут.
5. Следите за этапом и журналом. Фактическая ветка и коммит папки показаны отдельно от последнего задания. После успешной проверки доступна ссылка «Открыть приложение», если адрес настроен.
6. Закончив проверку, нажмите «Вернуться на dev»: папка переключится обратно, стенд пересоберётся и запустится теми же командами. Если ветка возврата изменена в настройках, кнопка называет её.

В одной основной папке активна одна ветка. Новая копия, отдельные порты и данные
не создаются. Для проекта с несколькими репозиториями переключается выбранный репозиторий.
Несохранённые, staged и новые файлы, незавершённый Git-переход или агент в этой папке
блокируют запуск. Занятая в другой рабочей копии ветка тоже недоступна. При выборе
удалённой ветки создаётся локальная tracking-ветка; если такая локальная уже есть,
выберите её явно.

Ошибка останавливает дальнейшие этапы. Прочитайте журнал и проверьте текущую ветку:
после отказа сборки приложение может оставаться остановленным. Автоматического отката нет;
можно исправить причину и повторить запуск либо вернуться на `dev`.
Диалог можно закрыть: задание продолжится, при повторном открытии виден его итог.
При переключении самого GrigDesk соединение пропадёт до его запуска; для такого
действия нужен доступный пользовательский systemd, иначе сервер откажет до остановки.
Старая ветка GrigDesk может ещё не содержать этот экран управления.

## Подготовить и отправить коммит

1. В «Изменениях» добавьте нужные файлы в индекс кнопкой `+`. `−` возвращает staged-файл в рабочую группу. Для каталога и частичного выбора сначала проверьте состав.
2. В нижней форме напишите сообщение. Генерация названия предлагает текст по staged diff и сама коммит не делает.
3. Выполните коммит: в него входит только уже подготовленный индекс, автоматического добавления файлов нет.
4. В нижнем ряду круговая стрелка «Проверить удалённый репозиторий» выполняет fetch: обновляет счётчики без изменения рабочих файлов. Стрелка вниз «Получить изменения» обновляет текущую ветку и файлы только через fast-forward. Для получения нужна чистая рабочая копия и настроенный удалённый upstream. При расхождении истории действие откажет с пояснением: rebase, merge-коммит и автоматическое сохранение правок в stash не выполняются. Успех или отсутствие новых изменений подтверждаются тостом.
5. Стрелка вверх выполняет push без force и может опубликовать ветку без upstream. После нажатия можно закрыть раздел «Код»: отправка продолжится, а успех или ошибка появятся общим тостом. Его можно закрыть крестиком. До завершения запроса повторная Git-команда в той же панели недоступна.
6. Для ещё не опубликованного локального HEAD доступны дополнение коммита и soft reset с подтверждением. Проверьте область и смысл действия перед применением.

«Откатить» tracked-правку возвращает файл к индексу, сохраняя staged-часть. Удаление нового файла — отдельное действие без возможности отмены. Общий откат группы новых файлов не удаляет. История файла и авторство строк доступны из действий файла; просмотр версий не разрешает конфликт автоматически.

## Результат

Изменения просмотрены с явно названными сторонами сравнения. Выбор файла и диапазона сохраняется при обновлении снимка.

## Ограничения и восстановление

Конфликт показывает нашу версию и рабочий файл; после исправления пометьте его разрешённым. Коммитный диапазон нельзя stage/unstage. При устаревшем снимке перечитайте изменения. Неизвестные файловые ссылки остаются текстом. Отсутствие upstream делает обзор всей основной ветки недоступным.
