# Подключить Qwen Code

Qwen Code использует внешний npm-CLI и ключ API выбранного сервиса модели.
Для запуска чата требуется сервер на Linux с доступной песочницей bwrap.
Внешнему CLI нужен Node.js версии 22 или новее. Для подготовки установки нужны
локальные заголовки выбранного Node; если они отсутствуют, окно покажет отказ до установки.

## Подготовить доступ и модели

1. Откройте «Настройки → Исполнители → Qwen Code» и установите CLI штатной кнопкой.
   Здесь же доступны обновление и проверка версии.
2. Во вкладке «Доступ» выберите «Сервис API и регион», соответствующие выданному ключу.
   Без выбора используется Alibaba Model Studio в Сингапуре. QwenCloud, Coding Plan,
   Token Plan и OpenRouter имеют отдельные варианты: ключи разных сервисов не взаимозаменяемы.
   Для **Individual Plan или Team Plan на qwencloud.com** выберите
   **«QwenCloud Token Plan — Сингапур»**. Alibaba Coding Plan — отдельный сервис;
   его каталог может отличаться от моделей вашей подписки QwenCloud.
3. Введите «Ключ API» и нажмите «Применить». Пустой ввод сохраняет прежний ключ;
   удаление задаётся отдельным действием окна. Если ключ уже сохранён, повторять ввод не нужно.
4. Каталог загружается из API выбранного сервиса автоматически. Ручной JSON не требуется:
   GrigDesk подготавливает настройки для CLI в его приватной среде. Установка, обновление
   и переустановка CLI используют тот же доступ; новые модели появляются после обновления
   каталога и встают выше прежних.
5. Выберите Qwen и модель в чате. При отказе каталога карточка показывает причину, например
   HTTP 401. Проверьте выбранный сервис, регион и ключ. GrigDesk не пробует отправлять ключ
   другим сервисам. Успешное получение каталога ещё не подтверждает оплаченный запрос к модели.

Если Qwen отсутствует в списке моделей, внизу этого списка нажмите
«Qwen Code · Нет моделей», если это действие предложено, либо откройте карточку через
«Настройки → ИИ-исполнители». Карточка объясняет причину
и предлагает перепроверить подключение или перейти к его настройке. При несовместимости
программы используйте обновление или переустановку на вкладке «Обзор».

Подтверждённое сохранение сервиса не отменяется, пока обновляется список моделей.
Если после сохранения пропала связь, сообщение «Доступ сохранён» предлагает
«Перепроверить»: вводить уже сохранённый ключ повторно не требуется.

Пока доступ не применён, карточка показывает «Сохраните подключение» и кнопку
«Применить». Перепроверка до сохранения использует прежнее подключение.
Каталог Qwen не сворачивает разные модели в одну: подтверждённые новые модели
и модели других разработчиков остаются в кратком списке. В чате видны только модели,
пригодные для текстового разговора, свежие — выше прежних. Видео, речь и другие
нечат-модели сервиса в выборе не показываются и для чата не выбираются; старые
версии чатовых моделей можно показать в «Настройки → ИИ-исполнители → Модели».

Если вы уже настроили `modelProviders` в Qwen CLI, GrigDesk использует эту конфигурацию
вместо автоматического подключения и не меняет её. Выбор сервиса тогда не показывается;
доступ задаётся для имён `envKey` из конфигурации. Повреждённый JSON требует исправления
источника и не заменяется автоматическими настройками.

Установка проверяет installer-хуки зависимостей до подтверждения. Если окно сообщает
«Способ установки этой версии не проверен», требуется проверка изменившегося пакета.
Проверенные версии 0.27.2 и 0.27.3 поддерживаются без отключения этой защиты. Если старый
сервер при обновлении до 0.27.3 сообщает «Подготовка операции не удалась», примените
обновление GrigDesk с проверенным профилем этой версии, вручную перезапустите сервер
и повторите обновление Qwen. Необязательный
микрофонный backend CLI использует готовый addon; для его сборки из исходников нужны
Python 3, make и C++ toolchain. Эта возможность не требуется для чата GrigDesk.

## Работа чата

В меню рабочей папки можно выбрать проект с несколькими репозиториями. Основной
репозиторий задаёт папку запуска, остальные становятся дополнительными рабочими
каталогами с доступом к чтению и записи. Для разговора по задаче используются её
рабочие копии. Доступ ко всему общему родительскому каталогу при этом не выдаётся.
При смене папки, набора корней или доступа native-память отделяется от прежней сессии,
история GrigDesk сохраняется.
Остановка прерывает текущий процесс; продолжение использует сохранённую сессию.
В живой и сохранённой ленте успешный инструмент отмечен ✓, завершившийся ошибкой — ✕.

В строке хода «запр.» означает, что модель запрошена, но CLI ещё не подтвердил
выбор сессии. После такого подтверждения отметка исчезает, а модель сохраняется
в сведениях об ответе. Если CLI не назвал текущую модель, отметка остаётся.

Размышление и ответ показываются цельными блоками. Слова, пришедшие отдельными частями
потока, не становятся самостоятельными карточками. Уже сохранённые дробные шаги также
собираются при отображении; сообщения и память разговора сохраняются.

Долгое размышление, выполнение инструментов и ожидание вашего разрешения
не обрываются через 30 секунд. Кнопка остановки прерывает ход и в этих состояниях.
Если установленная версия показывает `ACP timeout: session/prompt` примерно через
30 секунд, примените обновление сервера и вручную перезапустите его, затем повторите
сообщение. Менять сервис API или заново вводить сохранённый ключ для этой ошибки не нужно.

Уровни усилия загружаются отдельно для каждой модели из установленного CLI.
Например, проверенный CLI 0.27.2 сообщает для Qwen4 Max Preview `none`, `low`, `medium`,
`xhigh`. У моделей с переключением рассуждения доступны `none` и `default`;
у моделей без такой настройки выбор отсутствует. Выбранное усилие подтверждается CLI
до отправки запроса. Неизвестный уровень после обновления каталога требует повторного выбора.
Общий запасной список CLI для неизвестной модели не считается подтверждением её возможностей.
Поэтому у некоторых сторонних моделей сервиса выбор усилия может отсутствовать до появления
соответствующей metadata в CLI; это не утверждение, что у API модели нет рассуждения.
Каталог использует размер окна, сообщённый CLI; это рабочая настройка программы,
а не отдельная проверка предельного размера запроса у сервиса.

Ссылки `.env` и `.qwen` в каждом рабочем корне также скрываются внутри песочницы пустыми
данными; исходные ссылки и их содержимое на сервере сохраняются. Ошибка раннего запуска
показывает причину песочницы, а не случайный отказ чтения `/proc` завершившегося процесса.

Режимы «Спрашивать», «Авто», «План» и «Без подтверждений» сохраняют границы песочницы
и серверную проверку прямого SSH перед исполнением инструмента. Несовместимый защитный
протокол CLI даёт видимый отказ; перехода к запуску без защиты нет. Без bwrap или на другом
серверном ОС ход недоступен.

«Авто» использует собственный автоматический режим Qwen: обычные правки внутри
выбранных каталогов выполняются самостоятельно, другие действия оценивает CLI.
Такая оценка может делать дополнительные запросы модели и расходовать квоту.
При недоступности оценки может появиться запрос разрешения. «Спрашивать» сохраняет
ручные подтверждения, «Без подтверждений» пропускает их, сохраняя границы песочницы.
Если установленный CLI не поддерживает выбранный режим, обновите Qwen Code в настройках.

PNG, JPEG, GIF и WebP можно приложить к сообщению, в том числе без текста.
Картинка передаётся непосредственно Qwen; выбранная модель должна поддерживать
работу с изображениями. Доступно до 10 картинок, до 10 МБ каждая и до 32 МиБ суммарно.
Файлы других форматов перенесите в рабочую папку и укажите их в сообщении.
При отказе из-за отсутствующей картинки приложите файл заново; несовместимый CLI
обновите в настройках исполнителя.

Получение квот Qwen пока не поддерживается в GrigDesk; это ограничение интеграции,
а не результат запроса к сервису.

## Штатные инструменты

GrigDesk допускает поиск и чтение страниц, список дел, память, субагентов и команды
агентов, навыки, LSP, правку блокнотов, обработку изображений и медиа, native расписания,
цели и workflow. Доступность конкретного инструмента зависит также от установленного
Qwen CLI, его настроек и подключённого сервиса. Например, разрешение веб-поиска
не добавляет поисковый доступ к ключу, которым можно только обращаться к модели.

Вопрос агента появляется в обычной карточке GrigDesk. Можно выбрать несколько
вариантов, если это предусмотрено вопросом, и ввести свой текст; ответы передаются
обратно Qwen. Утверждение плана показывает его текст и варианты продолжения,
которые предложил CLI. После утверждения агент может выполнять разрешённые правки
в том же ходе. Отмена и кнопка остановки прекращают ожидание ответа.

Во время работы можно отправить уточнение с текстом или картинкой той же кнопкой отправки.
Оно поступает в текущий ход: Qwen может прервать генерацию, ответить на уточнение и
продолжить исходную задачу. Статус у сообщения подтверждает передачу исполнителю;
это ещё не отдельное подтверждение прочтения моделью. Пока агент ждёт ответа в
карточке вопроса, новое сообщение композера ожидает следующего хода.

«Стоп» завершает ход сообщением «⏹ Ход остановлен.» без красной карточки ошибки.
Уже выполненные действия и доступная память сессии сохраняются. Следующее сообщение
продолжает этот разговор; изменения файлов при остановке не откатываются.

Сообщения с картинками и без них продолжают одну сессию, в том числе после «Стоп».
Если прежняя версия показывала «Qwen: чужая или неверная identity сессии» после
сообщения с вложением, примените исправление GrigDesk и вручную перезапустите сервер,
затем повторите сообщение в том же разговоре. Сбрасывать память и создавать новый
чат не требуется: сохранённая сессия со старой привязкой поддерживается.

Файловая песочница и настройка запрета прямого SSH действуют для этих инструментов
и субагентов. В режиме плана сервер закрывает shell, правку файлов, обработку медиа
и workflow. Штатное чтение страниц CLI допускает также localhost и частные адреса.

В CLI 0.27.2 и 0.27.3 инструменты субагентов могут завершаться `Tool invocation guard failed`:
CLI теряет защитный контекст родительского хода. Допуск запуска субагента этого
ограничения не исправляет; требуется совместимое исправление внешнего CLI.
Обновление с 0.27.2 до 0.27.3 само по себе проблему не устраняет.
Снимать защиту для продолжения работы GrigDesk не будет.

Для мультимедиа нужны исполняемые `ffmpeg` и `ffprobe`; без них эта часть CLI
не включается, остальные инструменты и чат остаются доступны. LSP требует
настроенного языкового сервера, а внешние сервисы обработки — своего доступа.

Процесс Qwen в песочнице работает в течение одного хода. Native расписание или фоновая
задача не продолжают работать после завершения этого процесса. Допуск этих инструментов
не создаёт постоянного фонового исполнителя в GrigDesk. В режиме «Хост» процесс живёт
между ходами (см. ниже).

## Режим «Хост»

По умолчанию Qwen работает в песочнице. Режим «Хост» включается вручную:
«Настройки → Исполнители → Qwen Code → Параметры → Режим «Хост»». Включение требует
подтверждения в общем диалоге: Qwen получит доступ к Docker, процессам и файлам
с правами пользователя сервера. Это не новая изоляция — агент работает вне песочницы,
с теми же правами, что и сервер GrigDesk. Автоматического sudo нет; выбранные режимы
подтверждения и запрет прямого SSH сохраняются.

В «Хосте» работают инструменты обычных и фоновых субагентов, мониторы, расписания
и остальные штатные инструменты совместимого CLI. Веб-поиск, LSP, навыки и обработка
медиа используют уже настроенные в Qwen программы, конфигурацию и доступ: новые
подписки, ключи и программы автоматически не покупаются и не устанавливаются;
отсутствующая зависимость показывает причину. Документация включённых плагинов
доступна в обоих режимах.

Требования: включённый тумблер «Настройки → Запуски → Держать агента чата живым между
ходами», работающий user systemd и отдельный unit приложения GrigDesk. Если окружение
недоступно, ход получает видимую причину отказа; запуска без защиты и fallback
в песочницу нет. Без Linux user systemd режим недоступен.

Процесс живёт между сообщениями: фоновая задача или расписание завершаются и публикуют
ответ в ленте без нового сообщения. Если расписание успевает завершиться, пока готовится
ответ на ваше сообщение, его результат всё равно публикуется в ленте ровно один раз
с полным текстом и не смешивается с ответом на ваше сообщение. «Стоп» прерывает текущий
ход, а не процесс.
Закрытие живого процесса в «Настройки → Запуски → Живые процессы агентов», сброс памяти,
удаление чата и выход GrigDesk завершают процесс; после перезагрузки ОС автозапуска нет.
Живые процессы не вытесняются автоматически: при заполненных слотах новый «Хост»
получает отказ с предложением закрыть ненужный процесс.
Массовое «Погасить свободные» на этой странице показывает явное сообщение с числом
отказов, если процессы не подтвердили завершение: такие процессы остаются в списке,
пока закрытие не будет подтверждено повтором.

Включение и выключение применяется к следующему ходу; уже начатую работу немедленно
прекращает закрытие живого процесса в списке. Смена профиля отделяет native-память
Qwen, переписка GrigDesk сохраняется. История после вложений не ломается. Если
подготовка процесса оборвалась (например, отказ защитного протокола), процесс остаётся
в списке живых до явного закрытия, а повторное сообщение получает явную ошибку
«незавершённая подготовка требует подтверждённого закрытия».

## Граница проверки

В конвейере доступен раннер Qwen с тем же источником моделей. Выбор исполнителя
и модели выполняется в редакторе этапа. Он не предоставляет дополнительных прав на
файлы: проверяющий этап пишет в состояние, этап реализации — в рабочую папку.
Перед назначением реальным задачам необходима отдельная проверка узла на стенде.

Автоматически проверены настоящий CLI 0.27.2 с локальным тестовым API, подготовка
каталога и ход без исходного `settings.json`, а также запуск узла с тестовым CLI.
Отдельно проверен ответ настоящего CLI после реальной паузы API дольше 30 секунд;
тесты также проверяют длительное ожидание разрешения, остановку и ошибки потока.
Настоящий CLI с локальным API также проверяет доставку уточнения во время генерации
и отдельное сохранение ответов. Ответ живой модели на уточнение требует отдельной
приёмки после ручного перезапуска сервера.
Для картинок проверены точные байты в запросе к локальному API через настоящий CLI
как в обычном ходе, так и в уточнении. Распознавание реальной моделью проверяется отдельно.
На том же локальном API проверены дополнительные рабочие каталоги, native «Авто»,
отказ автоматической оценки и её переход к ручному подтверждению при сбое.
Установка через карточку и браузерная проверка выполняются отдельно
на стенде. Оплаченный smoke требует настоящего ключа, введённого человеком через
окно доступа, и выполняется на приёмке.

Режим «Хост» проверен автоматическими тестами без платных вызовов: один процесс
на два хода, обязательный защитный протокол, фоновые ответы и расписания, остановка,
повторное закрытие после отказа, ручное включение с подтверждением и сохранением
настройки. Приёмка с живым user systemd (доступ к процессам и сокетам хоста, субагент,
настроенные LSP/медиа/поиск, серверные MCP-инструменты, закрытие фоновой команды)
выполняется владельцем на хосте после ручного перезапуска сервера; в окружении
без user systemd эти проверки дают видимый отказ и не считаются пройденными.
