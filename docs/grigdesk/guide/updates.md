# Обновление и возврат

Release — стабильные выпуски X.Y.Z; dev — явно выбранные пробные X.Y.Z-dev.N.
Смена канала не разрешает незаметный откат на меньший номер. Ошибка сети или подписи
показывается отдельно от отсутствия обновлений.

## Перед началом

Нужен проверенный опубликованный выпуск с доверенным ключом. Публикацию запускает
владелец вручную; коммиты и теги сами её не запускают. Настоящие готовые сборки проходят
отдельную приёмку до пользовательской публикации.

## Приложение

1. Жёлтая точка у знака GrigDesk означает доступное обновление. Нажмите знак или откройте
   обновления в настройках: это один диалог с версиями, каналом, составом и описанием.
   Наведение или фокус показывает подсказку; с клавиатуры знак открывается Enter или пробелом.
2. «Проверить обновления» обращается к сайту независимо от местного сервера.
3. «Обновить» скачивает и проверяет готовые компоненты. Проценты относятся к байтам
   скачивания; проверка и подготовка показываются этапами.
4. Закрытие диалога и «Позже» сохраняют задание. Они не применяют обновление при обычном выходе.
5. «Перезапустить сейчас» показывает свежую активность. Ходы могут прерваться; конвейеры
   получают Stop с возможностью продолжения. До согласия работа не останавливается.
6. Местное приложение обновляет окно и свой сервер одним выпуском. При удалённом профиле
   обновляется только окно; выбранная машина и её доверенный сертификат сохраняются.

После подтверждённого перезапуска обновление продолжает отдельный процесс: закрытие
старого окна на этом этапе не требует повторной установки. Ошибка доступа к состоянию
процесса сохраняется как ошибка обновления; сначала устраните её и продолжите прежнее задание.

## Отдельный сервер

В терминале, в том числе по SSH, вызовите grigdesk-ctl: меню показывает версию, канал и
фоновый результат проверки. Без TTY пустой вызов выводит справку. Прямые команды:

- `grigdesk-ctl server check-updates [--json]` — проверить сайт;
- `grigdesk-ctl server update-status [--json]` — прочитать установку и journal без сервера;
- `grigdesk-ctl server update [--json]` — подготовить готовую серверную сборку;
- `grigdesk-ctl server resume-update [--json]` — продолжить прежнее задание;
- `grigdesk-ctl server resume-update --rollback` — вернуть прежний выпуск, когда новый
  не запускается на реальных данных (исход applied_not_started без другого выхода);
- `grigdesk-ctl server update-channel release|dev` — явно выбрать канал без активного задания.

TTY предлагает применение после подготовки; без TTY подготовка оставляет ready.
Явный `--restart` у update/resume-update подтверждает применение и последствия остановки.
Если сервер был остановлен, он остаётся остановленным с исходом applied_not_started;
запустите его отдельно `grigdesk-ctl server start --wait`. Скачивание не запускает сервер.
Local-пара направляет в приложение и не обновляется серверной командой наполовину.
Успешное обновление освобождает свои архивы и недостижимые поколения; журнал и данные
сохраняются, предыдущее поколение удерживается для отката.

## Проверка результата и восстановление

Running относится к живому процессу, installed — к диску. Completed подтверждает запуск
нужных компонентов; applied_not_started ещё не означает работающий новый сервер.
При сбое одна часть не выдаётся за успех пары: сохраняются journal и прежние поколения.
Кнопка продолжения в приложении либо resume-update в CLI восстанавливает прежнюю цель.
Если новое поколение не запускается на реальных данных, `resume-update --rollback`
возвращает прежний выпуск по явному согласию.

После аварийного завершения продолжение само снимает блокировку доказанно завершившегося
процесса и сразу повторяет захват. Удалять её вручную не нужно. Если каталог занят живым
процессом либо его состояние не удалось проверить, операция отказывает: дождитесь завершения
другой операции обновления и повторите попытку.

При ошибке подписи не обходите проверку и не удаляйте данные или сохранённые поколения.
Сначала прочитайте состояние и устраните указанную причину. После переключения local/remote
вернитесь к подходящему профилю для подтверждённого задания. Удалённый сервер обновляется
отдельно его CLI на той машине; обновление окна его не перезапускает.
Source-установка сохраняет прежний git-путь; Android обновляется отдельно.
