# Данные и резервные копии

Программа, данные сервера и настройки клиентского окна хранятся отдельно. Резервная копия должна учитывать все используемые места.

## Перед началом

Определите выбранную машину и её фактическую папку данных. По умолчанию это `~/.grigdesk`; явные настройки могут задавать другие пути.

## Что делать

1. Завершите ходы агентов, записи, установки и задания. Согласованно остановите использующие данные процессы штатными средствами владельца.
2. Скопируйте папку данных целиком с сохранением прав: настройки машины, историю и вложения, привязки устройств, архивы входящих, плагины и их состояние, модели и артефакты.
3. Отдельно сохраните рабочие репозитории, homes исполнителей, фабричное состояние и каталог маршрутов. Они могут находиться вне папки GrigDesk. Сохраните также настройки окна и выбранного сервера, если нужен перенос клиента.
4. Проверьте читаемость копии и храните её с ограниченным доступом: в ней есть ключи и переписка.
5. Восстанавливайте при остановленных процессах. Верните согласованные папки и права, затем запустите одну копию сервера и проверьте машину и историю.

## Результат

Получена согласованная копия рабочих данных, а не только бинарников программы.

## Уборка старых артефактов

1. Сохраните нужные артефакты в резервной копии. Уборка необратима и не проверяет ссылки
   из переписки: картинки старых ответов могут исчезнуть после удаления их файлов.
2. Выполните `grigdesk-ctl artifacts-cleanup --dry-run`. Проверьте показанный корень,
   каждый каталог, его размер и сумму. Явная `GRIGDESK_ARTIFACTS_DIR` выбирает другую папку.
   Первый просмотр большой папки может идти минуты; Ctrl+C безопасно прерывает dry-run.
   В меню Ctrl+C также останавливает ещё идущий предварительный обход.
3. Выполните `grigdesk-ctl artifacts-cleanup`, когда список подходит. Для другого возраста
   добавьте `--older-than 12h` или `--older-than 14d`: допустимы целые минуты `m`, часы `h`
   и сутки `d`, умолчание — 7 суток. `--keep-generations 3` задаёт число последних поколений
   тестового кэша. `--json` даёт машинный отчёт для скриптов.
4. Либо выберите «Разработчику → Уборка артефактов» в терминальном меню любой установки.
   Меню сначала показывает список; по умолчанию выбрана «Отмена». Только явный выбор
   «Удалить» запускает удаление с повторной проверкой.
5. Проверьте отчёт. Молодые и занятые каталоги сохраняются, как и основные части кэша Node.
   На время удаления новые операции с directory lock ждут завершения уборки; при занятом
   барьере другая уборка пропускает каталоги. После завершения команду можно повторить.
   Байты отчёта оценивают удалённые файлы и могут отличаться от прироста свободного места.
   При ошибке исправьте причину и повторите команду: остальные каталоги могли уже удалиться.
   Ctrl+C останавливает уборку с кодом 130, SIGTERM — 143. Начатое удаление одного каталога
   может завершиться; следующие не удаляются, уже удалённое не возвращается. Отчёт сохраняет
   сделанную часть работы; в JSON отмена отмечена полем `interrupted: true`.

Сервер не убирает остальные темы автоматически. Тесты DeepSeek подчищают только свои
известные старые результаты. Потерянные пользовательские файлы восстанавливаются из копии;
тестовые сборки пересоздаются штатной подготовкой.

## Ограничения и восстановление

Нельзя обещать полный backup одной папкой: фабрика и внешние исполнители имеют собственные homes. Кэши поколений сервера не заменяют историю. Не удаляйте блокировки живых процессов. Старые абсолютные ссылки на вложения могут требовать прежнего расположения.
