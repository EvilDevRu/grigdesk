# Профили доступа исполнителя

Профиль сохраняет подключение одного исполнителя. Можно сохранить несколько подключений;
активным бывает одно. Этот выбор действует на разговоры, служебные вызовы и конвейеры.

1. Откройте «Настройки → Исполнители», выберите исполнителя и вкладку «Доступ».
2. Нажмите «Добавить профиль», задайте имя и способ входа, затем «Продолжить».
3. Для API введите ключ выбранного режима. Для CLI следуйте шагам мастера:
   «Введите этот код на сайте» и «Код с сайта» означают разные направления.
4. Дождитесь проверки и состояния «Сохранён». Открытая ссылка ещё не означает успешный вход.
5. Выберите «Активировать» в строке нужного подключения. Активная строка отмечена галочкой.
   В меню исполнителя в шапке нажмите кнопку подключения внизу, под лимитами и прогнозом.
   Кнопки соединены в общий переключатель; текущее подключение выделено заливкой.
   Если места не хватает, остальные подключения находятся в «…».
   Текущую кнопку можно нажать без повторной смены доступа. Ряд кнопок появляется,
   только если сохранено больше одной учётной записи. Для управления подключениями
   нажмите шестерёнку в заголовке меню, выберите исполнителя и вкладку «Доступ».

Кнопка «Добавить профиль» находится над списком. Круговая стрелка восстанавливает вход,
карандаш меняет имя, корзина удаляет неактивное подключение после подтверждения. Переименование сохраняет
доступность исполнителя, выбранное подключение и статистику. Все эти изменения
сохраняются сразу, без общего «Применить».

Обычный API GLM и Coding Plan сохраняются как два отдельных профиля со своими ключами
и статистикой. Повторный вход DeepSeek предупреждает, что аккаунт не удалось определить.
До подтверждения прежний ключ работает; отмена ничего не меняет. Подтверждение сохраняет
профиль и историю, но начинает новую сессию исполнителя с заметкой о памяти.

«Восстановить вход» относится к выбранному профилю и не включает неактивное подключение.
Удалить активный профиль нельзя: сначала явно выберите другой. Переключение доступно,
когда у этого исполнителя нет активных диалогов и незавершённых конвейеров. Работа,
ожидание подтверждения, фон и сон считаются активностью; конвейер на паузе удерживает
доступ. Пока исполнитель занят, кнопки переключения отключены с объяснением.
После завершения работы доступность обновится автоматически.

При потере связи дождитесь восстановления: мастер узнает действительный результат
без повторной отправки ключа. После прерванного/истёкшего входа используйте «Повторить».
Если версия CLI не поддержана, мастер объяснит отказ; прежнее подключение сохраняется.
Другой аккаунт при слетевшем входе автоматически не подставляется.
Вход в GrigDesk при этом сохраняется: восстановите доступ выбранного исполнителя.
Если прежний ключ GLM уже не работает и аккаунт нельзя сравнить, мастер попросит
подтвердить замену после проверки нового ключа. До подтверждения подключение не меняется.
После отмены CLI-входа дождитесь завершения процесса: до этого новые ходы,
переключение профиля и следующий вход могут оставаться временно недоступными.
Если ответ операции потерялся, следующий шаг сначала проверяет её исход. Другой профиль
до восстановления результата не получает прежнюю попытку. Неизвестность результата
переживает перезагрузку окна; секретный ввод для этого не сохраняется.
Ошибки сети, отказ ключа, ограничение частоты, истечение кода и сбой сохранения
объясняются отдельно. Если отмену ещё нельзя подтвердить, мастер остаётся открытым.

Настоящие CLI-входы и квоты зависят от версии и аккаунта. Автоматические проверки
на синтетических данных не заменяют проверку с владельцем доступа.

Незавершённый ввод сохраняется при переходе между страницами настроек. Перед общим
«Применить» завершите мастер или отмените ввод. Закрытие настроек и потеря входа
очищают секретные поля. Режим существующего профиля закреплён: для другого режима
добавьте отдельный профиль. Обновление токена того же аккаунта сохраняет прогноз.
