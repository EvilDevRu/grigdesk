# Inbox, Telegram and GitHub

The inbox collects materials from configured sources and helps turn them into tasks.
On narrow screens, long task links and channel-setting labels wrap; selected-conversation actions stay at the bottom.

## Before you begin

Connect a source and configure project rules. Telegram and GitHub have separate authentication,
network availability and settings.

## What to do

1. Open the source or shared Inbox queue.
2. Select a card, read the original material and discussion, and use search and status filters.
3. Check the proposed task and project. Answer clarifications; split independent topics into tasks.
4. Confirm the proposed action. Track message processing separately from the resulting task.
5. Restore failed source access in settings and retry the specific failed action.

Pending / History tabs preserve filters. Channels expands connection and intake settings.
Initial loading reserves tab and search positions so the loaded queue does not shift them.

## Result

The material receives an explicit decision; created tasks are available for evaluation and launch.

## Limits and recovery

Source state, card processing and operation delivery are independent.
A connection lost after sending does not prove failure: check the destination before retrying.
Disabling a rule does not remove materials already received.
