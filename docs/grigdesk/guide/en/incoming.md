# Incoming, Telegram and GitHub

Incoming collects material from configured sources and helps turn it into tasks. On narrow screens, long task-link labels and channel settings wrap; actions for the selected conversation stay in the bottom bar.

## Before you start

Connect the required source and configure project rules. Telegram and GitHub have separate authorization, network availability and settings.

## What to do

1. Open the relevant source or the combined Incoming queue.
2. Select a card and read the original material and discussion. Use search and filters for the required state.
3. Check the proposed task and project. Answer clarifications; split independent topics into separate tasks.
4. Confirm the proposed action. Track message processing separately from the created task's state.
5. If a source fails, restore access in its settings and retry the specific failed action.

In Incoming, compact Pending / History tabs switch queues without losing filters. Channels expands connections and intake of new requests. During initial loading, the skeleton reserves tabs and search so the ready queue does not move them.

## Result

The material receives an explicit decision, and a created task is available for evaluation and execution.

## Limitations and recovery

Source state, card processing and operation delivery are independent. Disconnection after sending does not prove that nothing happened: check the destination before retrying. Disabling a rule does not delete material already received.
