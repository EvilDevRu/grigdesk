# Presentations and videos

Presentations turns finished work into a script, narration, browser recording and subtitled MP4,
using an already running environment.

## Before you begin

Enable Presentations. Check the recording browser, ffmpeg, storage, script model and at least one voice
or your own audio. Cloud narration and model requests may send text to providers and incur charges.

## What to do

1. Choose a permanent project environment, manual sandbox or attempt environment waiting for a human.
   Running attempts block recording. A ready API without a working interface is insufficient.
2. Record video starts preparation; Choose topic prepares without starting.
   Review task text, wishes, code sharing, commits and uncommitted changes.
   Sandboxes default to the branch with current changes; permanent environments do not read code by default.
3. Start analysis/build. The model proposes a brief and scenes; the server verifies actions on the live environment.
   Failure or uncovered requirements stop completion. A new analysis replaces old scenes after confirmation.
4. Inspect each scene's screen, actions, narration, caption and subtitle. Drafts survive scene changes;
   building saves them first. Continues previous preserves screen state but requires rerecording the whole chain.
5. Choose a voice and supported rate; preview samples and your line.
   Local voices install separately with size/license information and may require a GPU.
   Synthesis does not replace your uploaded audio.
6. Supported voices use `+` before a vowel for stress. Put common cases in the dictionary and special lines locally.
   Unsupported stress/rate is shown explicitly. Spell out numbers and Latin text for limited voices.
7. Build video and watch stages. Fresh clips are reused and stale ones rerecorded.
   Review scene video/audio and final output; download MP4 and separate SRT.
8. Watch the entire film and listen to questionable parts. Recognition can find omissions or silence,
   but does not verify intonation or stress.

## Result

Video and subtitles are in the card. Rebuilding clearly marks the previous file.
Restarting the interface preserves saved build progress.

## Limits and recovery

Changing target, policy or data requires rechecking. Mark external changes with Data updated;
there is no automatic detection. Demo data preparation requires a trusted recipe, an isolated manual sandbox
and confirmation. Unknown outcomes are not repeated automatically.
Voice/text changes stale audio, action changes stale recording, and caption changes stale final output.
Uploaded audio remains. Git-history changes may require refreshing an explicit selection;
an old script is not presented as the result of a new choice. Concurrent edits require reloading.
A small static-interface recording can simply compress well: verify duration and visible frames.
Empty, too short or completely flat-colour recordings still fail.
Network/key readiness is not a paid trial. If GPU memory is short, close programs using it or choose another voice.
Download important finals before retention expires, normally after 30 days without changes.
Automatic channel delivery and frame-by-frame verification of the final MP4 are not connected; download manually.
