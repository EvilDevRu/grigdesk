# Getting started

GrigDesk brings together agent conversations, projects and task execution. First choose a machine:
its server stores the data and performs actions.

## Before you begin

Install the application and prepare at least one executor in settings. There is no separate first-run
wizard. A free conversation is enough to begin; connecting a tracker or pipeline can wait.

## What to do

1. Open the physical `GrigDesk` file from the extracted package. On first launch, wait for local server preparation.
2. Check the saved machine selection. A remote machine stays selected until you change it;
   a new local server does not replace it automatically.
3. Open settings, choose a task mode and configure an executor and access.
   Resolve any readiness issue on the indicated settings page before sending a request.
4. Register a working copy in Projects if you will work with code. Create a conversation in Chats
   and check its model, permissions and working folder.
5. Send a small request. If the agent asks for permission, read the exact action before answering.

Startup shows a compact burgundy splash with layered relief and the GrigDesk name.
The lower-left status describes loading, checking, starting or preparing the server, or waiting for VPN.
The workspace then opens. Errors and long waits show a reason and let you choose a machine.

## Result

The machine is connected and an executor selected. Replies and completed actions appear in the conversation.
Reading built-in help does not call a model.

On a wide screen, section icons are on the left. Unselected icons share a muted grey-blue colour;
the numbers below them show each section's state. Menus use flat rows: hover and keyboard focus
highlight a row, dangerous actions stay red, and a thin border surrounds the whole panel.

## Limits and recovery

A missing executor or key does not mean data was lost. Correct the settings and check readiness again.
Do not start a second server using the same data folder.
