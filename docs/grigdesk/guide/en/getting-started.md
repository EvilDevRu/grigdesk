# First launch

GrigDesk brings together agent conversations, projects and task execution. First select a machine: its server stores data and performs actions.

## Before you start

Install the application. There is no separate first-run wizard; configure at least one executor in Settings. A free conversation is enough to start; you do not need a tracker or pipeline immediately.

## What to do

1. Open the physical `GrigDesk` file from the extracted bundle. On first launch, wait for the local server to be prepared.
2. If a machine selection is already saved, check its name. A remote machine stays selected until you decide otherwise; a new nearby server does not automatically replace it.
3. Open Settings, choose the task mode and configure an executor and access. If something prevents sending, fix the stated cause on the relevant settings page.
4. In Projects, register a working copy if you plan to work with code. In Chats, create a conversation and check the model, permissions and working directory.
5. Send a small request. If the agent asks for permission, read the exact action in the card before answering.

Startup displays a compact burgundy splash screen with layered relief and the GrigDesk wordmark. A line at the bottom left reports loading, checking, starting or preparing the server, or waiting for VPN. The workspace then opens; an error or a long wait shows its cause and lets you choose a machine.

## Result

A machine is connected, an executor is selected, and the reply and completed actions appear in the conversation. Built-in help can be read without contacting a model.

On a wide screen, use the icons on the left to open sections. Unselected icons share a muted blue-gray color; numbers below them show the state of each section.

Dropdowns and action menus show items without individual borders. Hover and keyboard focus highlight the row background; dangerous actions keep red text. A thin border marks the whole panel.

## Limitations and recovery

A missing executor or key does not mean data was lost. Fix the cause in Settings and check readiness again. Do not start a second server using the same data directory.
