# Код и Git

Плагин «Код» показывает файлы, Git-изменения и коммиты зарегистрированных репозиториев. Просмотр исходников и сравнений работает только для чтения.

## Перед началом

Включите инструмент и зарегистрируйте пути проекта. Для Git-действий нужен доступный репозиторий на сервере.

## Что делать

1. Откройте «Код» и выберите проект, репозиторий и рабочую копию.
2. В «Файлах» выберите документ либо найдите путь/содержимое поиском от двух символов. Клик по результату открывает строку.
3. В «Изменениях» сравните индекс с HEAD и рабочее дерево с индексом: один файл может быть в обеих группах. Выберите файл либо общий «Обзор».
4. В «Коммитах» отметьте диапазон; Shift добавляет промежуток. «+ текущие» включает рабочие изменения только для диапазона до HEAD. «Вся ветка» требует доступной базы.
5. Переключайте вид рядом/в колонку кнопкой над кодом; пробелы, контекст и перенос строк находятся под значком «Вид сравнения». F7/Shift+F7 переходят по блокам, затем к соседним файлам группы.
6. Для проверки используйте «Просмотрено», прогресс и переход к непросмотренному под шапкой. В меню «Действия с кодом» доступны выделение блока, замечание, объяснение и частичный индекс. Корзина «Замечания агенту» открывается отдельно. В узкой панели подписи действий заменяются значками с подсказками; настройки расположения остаются под значком «Вид сравнения». Действия индекса, отката и коммита выполняйте только в показанной области с учётом предупреждений и подтверждений.
7. «Спросить агента» создаёт отдельный редактируемый черновик с файлом/изменениями, не отправляя его. «Ссылка» копирует путь и доступную позицию.

Над деревом изменений можно искать по пути; воронка раскрывает фильтр статуса.
В меню «Действия с деревом» рядом с поиском можно свернуть, развернуть каталоги
или показать открытый файл. Счётчик результатов и очистка появляются при фильтрации.
Выберите несколько файлов через Ctrl/Meta, Shift или кнопку выбора строки:
появится панель действий с числом выбранных файлов и кнопкой снятия выбора.

## Подготовить и отправить коммит

1. В «Изменениях» добавьте нужные файлы в индекс кнопкой `+`. `−` возвращает staged-файл в рабочую группу. Для каталога и частичного выбора сначала проверьте состав.
2. В нижней форме напишите сообщение. Генерация названия предлагает текст по staged diff и сама коммит не делает.
3. Выполните коммит: в него входит только уже подготовленный индекс, автоматического добавления файлов нет.
4. При необходимости выполните fetch для обновления счётчиков, затем push. Fetch не делает merge/rebase; push не использует force и может опубликовать ветку без upstream. После нажатия push можно закрыть раздел «Код»: отправка продолжится, а успех или ошибка появятся общим тостом. Его можно закрыть крестиком. До завершения запроса повторный push в той же панели недоступен.
5. Для ещё не опубликованного локального HEAD доступны дополнение коммита и soft reset с подтверждением. Проверьте область и смысл действия перед применением.

«Откатить» tracked-правку возвращает файл к индексу, сохраняя staged-часть. Удаление нового файла — отдельное действие без возможности отмены. Общий откат группы новых файлов не удаляет. История файла и авторство строк доступны из действий файла; просмотр версий не разрешает конфликт автоматически.

## Результат

Изменения просмотрены с явно названными сторонами сравнения. Выбор файла и диапазона сохраняется при обновлении снимка.

## Ограничения и восстановление

Конфликт показывает нашу версию и рабочий файл; после исправления пометьте его разрешённым. Коммитный диапазон нельзя stage/unstage. При устаревшем снимке перечитайте изменения. Неизвестные файловые ссылки остаются текстом. Отсутствие upstream делает обзор всей основной ветки недоступным.
