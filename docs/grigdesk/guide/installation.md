# Установка приложения

Обычная поставка использует готовый Linux-установщик с сайта GrigDesk. Исходники,
системный Node и npm на машине установки не нужны. Новые portable-комплекты не собираются.

## Перед началом

Требуются Linux x64, glibc 2.28 или новее. Для приложения нужен FUSE 2; серверный режим
не требует GUI. CLI и авторизация внешних исполнителей настраиваются отдельно.
Перед переходом с прежнего переносимого комплекта закройте его окно и сервер.
Реальные готовые сборки проходят отдельную приёмку до пользовательской публикации.

## Что делать

1. При наличии опубликованного проверенного выпуска скачайте `grigdesk-install` с
   [сайта GrigDesk](https://grigdesk.com). Владелец выпуска должен настроить доверенный ключ.
2. Разрешите исполнение файла: `chmod +x grigdesk-install`.
3. Выберите один режим: `./grigdesk-install install local` — приложение с местным сервером;
   `install remote` — приложение для удалённых машин; `install server` — только сервер.
4. Программа размещается отдельно от данных в пользовательской папке; sudo не требуется.
   Повтор над своей регистрацией использует сохранённое задание обновления; чужой ярлык
   или регистрация вызывает отказ.
5. Сохраните прежние данные и настройки. Установщик не удаляет старую portable-папку.

## Вариант: deb-пакет

Для удобной установки через apt скачайте с сайта `grigdesk_<версия>_amd64.deb` и выполните
`sudo apt install ./grigdesk_<версия>_amd64.deb`. Пакет ставит только загрузчик
`/usr/bin/grigdesk` и подписанный установщик: при первом запуске из меню приложений
комплект разворачивается в вашей пользовательской папке (`~/.local`), как при ручной
установке в режиме local. Дальше приложение обновляет себя само — apt не участвует
в обновлениях, sudo повторно не нужен. Обновление или удаление deb не трогает
пользовательскую установку и данные; серверный режим ставьте обычным установщиком.

## Результат

Установка имеет отдельную регистрацию, проверенные поколения компонентов и общий указатель.
Remote-режим не создаёт местный серверный descriptor.

## Ограничения и восстановление

Установщик принимает абсолютные пути через --root, --data-home, --user-data, --bin-dir,
--applications-dir и --unit-dir. Свою серверную службу он регистрирует без enable/start.
При коллизии не удаляйте данные или регистрацию
ради повторного запуска. Android устанавливается отдельно; его обновление сюда не входит.
