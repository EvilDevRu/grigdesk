# Плагины: слоты, размещения и область

Как плагин встаёт в интерфейс GrigDesk и чем человек этим управляет. Реестр плагинов,
тумблер и настройки описаны в заголовке `server/src/lib/pluginsRegistry.ts`; здесь —
контракт встраивания, общий для системных и пользовательских плагинов с
собственным кодом веба.

## Каталог и установка из Git

В общем разделе плагинов вкладки «Каталог» и «Установленные». Поиск и фильтры помогают
выбрать пакет сайта; установка из карточки подставляет источник и точную версию.
«Официальный» и «Сообщество» обозначают происхождение, а не аудит безопасности кода.
Каталог подключается автоматически; если оба сайта недоступны, ручная установка остаётся доступной.

В «Настройки → Плагины» нажмите общую кнопку «Установить из Git…», затем укажите адрес репозитория и тег vX.Y.Z.
После скачивания появится карточка с источником, полным SHA и предупреждениями.
Перед подтверждением пакета вне каталога показано предупреждение о неизвестном источнике;
при сбое проверки — сообщение о невозможности проверить источник. Применение требует
отдельного явного подтверждения. Новый плагин появляется выключенным;
включите его и вручную перезапустите GrigDesk для подключения кода.

Карточка плагина показывает источник, доступное обновление, ручные правки и откат.
Закрытие окна не отменяет активное задание. Неизвестный исход сначала уточняется;
recovery показывает причину и запрещает новую замену. Подробнее —
[установка, пределы, runtime и восстановление](../plugins/user-plugin-install.md).

## Слоты

Слот — именованное место в ядре, куда плагины ставят свои компоненты. Ядро называет
слот и даёт контекст; кто в нём стоит, ядро не знает.

- **Область владеет своими слотами.** Файл `shared/plugins/slots/<область>Slots.ts` объявляет
  имя, тип контекста и подпись для настроек; пространство имён в имени называет хозяина
  (`provider.*`, дальше `board.*`, `chat.*`). Оглавление `shared/plugins/slots/index.ts` только
  объединяет типы и подписи — содержания в нём нет. Новый слот = запись в файле области,
  строка импорта в оглавлении и `<PluginSlot>` в нужном месте ядра.
- **`<PluginSlot name="…" :context="…">`** (`web/src/plugins/PluginSlot.vue`) рисует
  размещения слота по порядку; имя проверяется типом, контекст — типом слота. Каждое
  размещение стоит в своей границе ошибок: упавший компонент плагина показывает «Плагин
  «id» не отрисовался» на своём месте, соседи и хозяин слота живут дальше. Пока список
  плагинов не загружен, слот пуст.
- **Реестр размещений** (`web/src/plugins/registry.ts`): `registerPlacement({ pluginId,
  slot, component, order })`. Записи статичны, включённость плагина и размещения слот
  читает из стора плагинов при отрисовке — тумблеры действуют без перезагрузки.
- **Системные плагины веба** живут в `web/src/plugins/<id>/index.ts` и регистрируют
  размещения там; загрузчик `web/src/plugins/index.ts` собирает их через
  `import.meta.glob`, точка входа импортирует только его. Добавить плагин — добавить
  папку; ядро не правится.

Слоты сегодня:

| Слот | Контекст | Где |
|---|---|---|
| `provider.popover.after-bars` | `{ providerId }` | всплывашка исполнителя в топбаре, под полосами лимитов |

## Размещения в манифесте

Плагин объявляет, какие слоты умеет занимать: `placements: [{ slot, default? }]`.
Компонент к слоту привязывает код веба плагина, манифест только называет места — чтобы
настройки могли их включать и гасить. Незнакомый слот из чужого манифеста отбрасывается
с предупреждением: место могло появиться в версии GrigDesk, которой на машине ещё нет.

Состояние тумблеров — prefs `pluginPlacements: { <id>: { <slot>: boolean } }`, умолчание —
`default` манифеста (иначе включено). `/api/plugins` отдаёт `placements: [{ slot, label,
enabled }]`, `PUT /api/plugins/:id/settings` принимает `placements: { <slot>: boolean }`
рядом со значениями — только по заявленным слотам. В диалоге настроек это группа
«Размещение»: тумблер на каждое место, гасит место, не выключая плагин.

Поля запроса независимы: отсутствие `values` сохраняет параметры, отсутствие
`placements` сохраняет размещения. Переданный `values` заменяет набор параметров
плагина (пустой объект возвращает умолчания), а `placements` меняет только перечисленные
места. Ответ всегда содержит `values`; при изменении одних размещений это прежние
эффективные значения параметров.

Параметры и размещения редактируются в общей сессии настроек. Кнопка «Применить»
сохраняет их после успешного ответа; закрытие с неприменёнными изменениями требует выбора.
При ошибке черновик остаётся доступен для повтора, а рабочее состояние плагина не меняется.
Переключение вкладок не теряет черновик. Плагин с одними размещениями тоже считается
настраиваемым и попадает в фильтр установленных «С параметрами».

## Область по исполнителям

Тип настройки `providers` — массив id из живого реестра исполнителей, пустой — «все».
Диалог рисует галочку на каждого исполнителя и называет пустой выбор словами («Ни один
не отмечен — значит все»); сервер принимает только строки-идентификаторы без повторов.
Смысл области задаёт сам плагин: прогноз лимитов, например, не замеряет полосы
исполнителей вне области и не показывает у них блок.

## Страница пользовательского плагина

Пользовательский плагин (`plugins/<id>/`, вне репозитория) может привезти **свой
интерфейс** — папку `web/` с `index.html` и чем угодно рядом, без сборки. Границы:

- **Ядро страницу не исполняет, а показывает.** Сервер раздаёт папку под
  `/api/ext/<id>/web/` только включённому плагину (общий auth guard закрывает её вместе со
  всем `/api`), клиент показывает её общей панелью-iframe: в правой рейке при
  `nav.group: "dock"`, иначе страницей по ссылке в сайдбаре. Адрес — всегда `/ext/<id>`,
  `nav.path` такого плагина не участвует (`shared/tools/catalog.ts#pluginPageRoute`).
- **Страница ходит в API сама.** Тот же origin и та же сессия: свои роуты из `server.js`
  (`/api/ext/<id>/…`) и общие ручки GrigDesk ей доступны как любой вкладке. Vue и UI ядра
  внутрь не передаются — у плагина своя вёрстка, и ядро ей ничего не должно.
- **Снёс папку — исчез пункт.** Реестр панелей (`shared/tools/registry.ts#toolsOf`)
  собирает такие инструменты из стора плагинов на лету; владельцем панели считается сам
  плагин, поэтому его тумблер гасит и рейку, и роут теми же правилами, что у встроенных.
  Горячих клавиш у страниц плагинов нет — сочетания раздаёт каталог встроенных.

Проверка: `tests/server/plugins-web-page.test.js` (манифест и раздача),
`tests/web/plugin-web-page-tools.test.js` (стор и реестр панелей).

## Документация плагина

Документация пользовательского плагина лежит в его пакете, в постоянном месте:
оглавление `docs/README.md` и документы рядом. В `docs/` GrigDesk её нет — плагина может
не быть на другой установке. GrigDesk находит оглавления включённых плагинов на каждом
ходе чата и называет агенту их пути с именем и описанием из манифеста; агент открывает
оглавление, когда просьба касается плагина. Установка, удаление и тумблер плагина
меняют подсказку со следующего хода, без рестарта. Плагин без `docs/README.md` работает
как прежде. Формат для авторов — `plugins/README.md`, раздел «Документация»; устройство —
[документация плагина](../plugins/plugin-docs.md).

## Что плагин пока не может

Занять место, которого ядро не объявило слотом; заменить или обернуть элемент ядра;
вмешаться в ход чата. Первое решается новым слотом по запросу, второе и третье — темы
отдельных контрактов (обёртки, серверная шина действий и фильтров). Пользовательские
плагины могут объявлять `placements`, но Vue-кода в слоты они не привозят — размещения
заработают вместе с `web.js` следующей версии манифеста; своя страница (выше) этого
не требует.
