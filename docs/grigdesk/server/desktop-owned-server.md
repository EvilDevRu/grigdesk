# Дочерний сервер приложения: владение, IPC и перезапуск

Сервер поддерживает режим дочернего процесса приложения. `attachDesktopParent` включает его
только при `GRIGDESK_DESKTOP_CHILD=1` и подключённом IPC-канале. Маркер удаляется из окружения
при любой попытке подключения, поэтому исполнители агентов его не наследуют. Канал не несёт
сообщений и отпускается через `unref`: он нужен как признак жизни владельца.

Разрыв канала до подключения координатора остановки вызывает выход 0. После подключения
он начинает штатный слив с причиной «приложение GrigDesk закрылось». Обычный сервер без
маркера сохраняет прежний запуск и обработку сигналов.

`GET /api/system/server` возвращает `mode`: `desktop`, `systemd` или `manual`, а также прежнее
поле `systemd`, PID и время работы. Перезапуск в режиме `desktop` требует подключённого
родителя, отвечает сразу и через 400 мс начинает слив с кодом 75. Координатор сохраняет этот
код при успехе, превышении бюджета и ошибке закрытия. Повторный сигнал во время слива
по-прежнему даёт выход 1.

Менеджер обновления в режиме `desktop` запускает отдельный worker с origin и путём CLI-токена.
Содержимое токена отсутствует в argv. После публикации worker делает один POST
`/api/system/update-restart` с CLI-токеном и `jobId`. Маршрут проверяет способ авторизации,
режим, канал и сохранённое задание в состоянии `restarting`, затем начинает слив с кодом 75.
Ответ 202 оставляет подтверждение новому серверу. Отказ соединения также сохраняет задание
для следующего запуска; другой отказ даёт `restart_failed`. После публикации отката нет.

Независимый `createServerSupervisor` в `desktop/src/serverSupervisor.ts` проверяет HTTP и
снимок службы до запуска. Готовый GrigDesk считается внешним; чужой HTTP означает конфликт.
Отсутствие ответа и запускающаяся служба вызывают ожидание. Свой запуск проходит проверку
runtime, совпадения origin, VPN-ворота и повторный снимок. Владение снимается по `exit` или
ошибке без PID, а не по закрытию stdio: дескрипторы могут оставаться у потомков.

Код 75 запускает новое поколение через тот же конвейер с перечитыванием runtime и сроком
90 секунд. Отказ записывается в журнал главного процесса. Отмена и deadline прерывают
ожидание даже порта, который не поддерживает сигнал; поздние результаты не могут запустить
процесс или вернуть готовность. `stop` отменяет запуск и рестарт, шлёт только своему живому
процессу один SIGTERM и ждёт бюджет слива. Затем возможен SIGKILL и ещё пять секунд ожидания.
Внешний сервер не получает сигналов. Потомки после принудительного выхода отдельно не добиваются.

`loadServerRuntime` проверяет descriptor версии 1 (`root`, `node`) либо 2
(`root`, `node`, `home`), файлы установки,
Node общей проверкой совместимости. Desktop с упакованным интерфейсом не требует
рабочего web/dist; свою версию он проверяет и публикует [отдельно](../web/packaged-ui.md). В версии 2 `home` важнее `GRIGDESK_HOME` окружения окна; версия 1 сохраняет
окружение и умолчание. Файл — `GRIGDESK_ENV_FILE` либо `<папка данных>/.env`.
Остальное окружение родителя важнее текста настроек; следы AppImage, Electron и systemd удаляются, PATH повторяет префикс юнита,
`NODE_ENV` сохраняется. Журнал открывается на дозапись с правами 0600 при создании и
ротируется в `.1` при размере больше 10 МБ.

Своё окно запускает `<root>/server/src/app.ts` системным Node из `runtime.json` с
`cwd=<root>/server`, stdio в журнал и IPC-каналом, без shell и без отвязки. Журнал — тот же,
что у `deploy/restart.sh`: `GRIGDESK_LOG` или `<папка данных>/state/grigdesk-server.log`; диалог
ошибки называет только путь журнала. Тот же env получают VPN-ворота; содержимое `.env` не
попадает в argv, renderer и тексты ошибок.

## Установка, CLI и ярлык

`grigdesk-ctl desktop install` пишет `$XDG_DATA_HOME/grigdesk/desktop/runtime.json` (пустой или
относительный `XDG_DATA_HOME` даёт `~/.local/share`) — `{ "version": 1, "root", "node" }`
с физическим путём корня и Node, прошедшим проверку версии, — и только затем заменяет
окно `bin/grigdesk-app`. При явной `GRIGDESK_HOME` после замены окна descriptor атомарно
обновляется до версии 2 с полем `home`; при папке по умолчанию остаётся версия 1.
До записи проверяется допустимость папки. Пара файлов не имеет общего отката. `status` печатает третью
строку `runtime\t0|1` (наличие файла), `remove` удаляет окно и descriptor, профиль окна цел.

Переходный режим: пока установленного descriptor нет, `grigdesk-ctl open` и ярлык работают
по-прежнему — открывают окно и запрашивают запуск службы. С исправным descriptor `open`
только открывает окно, а `deploy/shortcut.sh install` ставит `Exec` прямо на AppImage (Node в
PATH не нужен). `deploy/install.sh` не стартует юнит, если на порту уже отвечает GrigDesk:
печатает «GrigDesk уже работает на порту <порт> — юнит не запускаю» и при выбранном
автозапуске делает только `enable`. Иначе юнит ушёл бы в вечный перезапуск рядом с
сервером приложения.

CLI называет сервер вне службы «работает вне службы»; `grigdesk-ctl server stop|restart` для него
отвечают «Сервер работает вне службы (приложение GrigDesk или ручной запуск); systemd им не
управляет». `deploy/restart.sh` по-прежнему гасит любого владельца порта и забирает сервер у
приложения: тот становится ручным и переживает закрытие окна. Карточка «Процесс GrigDesk» в
настройках показывает «Под управлением приложения» без совета про `deploy/install.sh`, а блок
«Автозапуск и ярлык» говорит, что сервером управляет приложение, а не ручной запуск.

## Ограничения

- Пока сервером владеет приложение, телефон, посредник и Telegram-пульт работают только при
  открытом окне; сервер без окна — служба, запущенная до открытия приложения.
- VPN-ворота своего сервера работают в фоне; окно показывает встроенный UI сразу
  ([старт окна](../web/desktop-startup.md)), ожидание видно как состояние связи.
- Своё поколение перезапускается только по коду 75. Другой выход не перезапускается: окно
  уходит в offline, сервер вернёт повторный запуск приложения или служба.
- В отличие от `KillMode=mixed` юнита, после SIGKILL осиротевшие потомки сервера не добиваются.
- Выход приложения во время слива перезапуска шлёт SIGTERM уже останавливающемуся серверу, и
  координатор выходит сразу с кодом 1 — так же, как служба при остановке во время рестарта.

## Проверки

Протокол сервера проверяют `desktop-parent`, `system-desktop-restart`, `shutdown` и тесты
обновления. Контроллер проверяют `runtime-config`, `server-process` и `server-supervisor`;
последний включает настоящий Node на отдельном порту и проверку сохранности соседнего сервера.
Сквозь приложение — [E2E старта](../testing/desktop-startup-e2e.md), включая настоящий GrigDesk
под окном (SE-10); установку и ярлык — `desktop-install-script` и `shortcut-script`, CLI —
`tests/cli/{open,server}.test.mts`.
