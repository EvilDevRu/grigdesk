# Офлайн-установка GrigDesk на Windows

Для x64 и ARM64 сборщик использует соответствующий Windows-раннер и версию Node
из `server/build/node-runtime.json`. В архив входят NSIS-установщик окна,
PowerShell bootstrap, Go-помощник, опись выпуска и `server.zip`.
Серверный архив содержит Node, production-зависимости, GrigDesk API
и нативную Go-фабрику. Статус установленного сервера читает версию
из той же подписанной поставки.

PowerShell проверяет архитектуру, запрашивает согласие, копирует помощник
в отдельный каталог пользователя и сверяет его SHA-256. Помощник проверяет
Ed25519-подпись описи и хеши каждого компонента. Он распаковывает сервер в
отдельной папке, вызывает NSIS и публикует runtime рядом с установленным окном.
При ошибке после регистрации программы помощник запускает её деинсталлятор
и очищает каталог своей попытки. Если деинсталляция прерывается, каталог
сохраняется для повторной попытки удаления.
Существующий каталог или запись установки в реестре требуют отдельного решения,
поэтому текущая команда рассчитана на чистую установку. Программа по умолчанию
лежит в `%LOCALAPPDATA%\GrigDesk`, данные в `%USERPROFILE%\.grigdesk`.

При запуске окно находит локальный runtime в своём каталоге и создаёт
локальный профиль при первом входе. Supervisor открывает Node через IPC.
После bind сервер передаёт ключ окна своему родительскому процессу, а
нативная оболочка обменивает его на обычную сессию. Закрытие IPC завершает
собственный сервер через общий shutdown-контракт. Штатный деинсталлятор
удаляет каталог программы. Данные сервера хранятся отдельно.

На Windows пользовательский `GRIGDESK_REQUIRE_VPN=1` запрещает запуск, пока
для этой платформы нет нативной проверки интерфейса. Профильным хукам,
которые используют Bash, нужен Git for Windows. Обновление и откат
установленного Windows-комплекта требуют отдельной реализации.
