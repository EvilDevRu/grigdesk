# Режим задач до создания проекта

`POST /api/onboarding/advance` принимает необязательный boolean `previewWorkspace`.
Флаг разрешён только на шаге `project`; на других шагах, в `/back`, `/dismiss`
и PATCH он отклоняется без изменения состояния. Ревизия и идентификатор прохода
проверяются тем же CAS-контрактом, что обычный переход.

При `previewWorkspace=true` и отсутствии `projectIntent` сервер сохраняет
`step=workspace` без проверки обязательных полей проекта, Git и создания паспорта.
Это позволяет заранее выбрать режим задач. PATCH сохраняет его в draft, повторное
открытие продолжает третий шаг. `/back` возвращает редактируемый проект вместе с
выбранным режимом. Если создание паспорта уже началось, прежний intent проходит
обычное восстановление; предварительный просмотр не обходит его блокировку.

Обычное `/advance` со второго шага по-прежнему проверяет и создаёт проект.
Завершение с третьего шага требует `projectSaved=true`; попытка завершить пустой
проход возвращает `invalid_project` и сохраняет активное состояние. UI вместо
завершения показывает «Добавьте проект». Уже созданные паспорта не дублируются.

Контракт проверяется `onboarding-workspace-preview.test.js` и компонентными
сценариями `onboarding-navigation.component.test.js` с настоящим HTTP-сервисом.
