# Установка и откат DeepSeek ELF

Готовый candidate устанавливается отдельно от сборки и перезапуска GrigDesk:

```sh
npm --prefix deepseek run install:binary -- \
  --binary /path/to/candidate \
  --target /installed/grigdesk/bin/deepseek \
  --host-contract /installed/grigdesk/server/deepseek-host-contract.json \
  --releases-dir /private/deepseek/releases \
  --glm-mode api
```

Опциональный `--glm-mode api|coding-plan` задаёт фактический режим GLM потребителя:
admission сверяется для него вместо режима из host-контракта. Рантайм службы всё равно
проверяет admission выбранного режима на каждом запуске, поэтому требование
неиспользуемого режима избыточно; `grigdesk-ctl build deepseek` передаёт режим сам
из настроек потребителя.

Первые три аргумента обязательны. Каталог target уже должен существовать. Если не передан
`--releases-dir`, резервные ELF лежат в `runtimes/deepseek/releases` папки данных.
`deploy/lib/deepseek-cli.sh` передаёт те же явные пути; файл требований всегда задаёт
установленный потребитель. Установщик не загружает candidate, не меняет `.env`, homes чатов
и исходники, не останавливает сервер.

Собственный directory lock сериализует установки одного target. В приватном staging на
filesystem target создаётся отдельная копия candidate, затем её запись закрывается.
Только эта копия проходит SHA256, `--runtime-info` и полный `--verify`. Пробы работают с
одноразовыми home/cache и окружением без ключей, `NODE_OPTIONS` и loader-переменных.
Проверяются host contract, settings bridges и допуск GLM API, вычисленный по фактическим
входам плагина. Отсутствующий или неподходящий admission запрещает установку.

После проб и резервирования повторно проверяются SHA и файловый отпечаток копии.
Предыдущий ELF сохраняется отдельным файлом `releases/<sha256>/deepseek` и проверяется по SHA.
Затем атомарный rename публикует тот же проверенный staging ELF. Уже работающий процесс
продолжает использовать прежний файл. Ошибка до rename оставляет установленную команду.

Рядом с target хранится private receipt `<target>.grigdesk-deepseek.json`: он содержит
проверенные SHA и разрешает замену только известных байтов установщика. Произвольные ссылки
и чужие обычные файлы не перезаписываются и не исполняются. Receipt сохраняет прежние SHA
при добавлении новой, поэтому сбой между его обновлением и rename не теряет распознавание
старого файла. Резервный ELF откатывается той же командой как новый candidate со всеми пробами.

JSON результата содержит `packageId`, `sha256`, `previous` и `memory`. Если прежний
`journal.write` входит в новый `journal.read`, память продолжается (`continues`). Если нет,
установка разрешена с `resets` и предупреждением: «чаты DeepSeek/GLM начнут память заново,
лента сохранится». При первой установке возвращается `unknown` без предупреждения.

Проверки: `tests/deepseek/install.test.mts` — отказы до публикации, конкурентные установки,
работающий A после A→B, откат, изоляция probes, подмены source/staging и настоящий ELF.
Положительная GLM fixture собирает отдельный тестовый выпуск в приватной копии;
производственный admission этим не изменяется.
Отрицательная fixture также собирает отдельный ELF, но с пустым списком admission:
успешный допуск рабочей поставки не должен превращать тест отказа в ожидание её недоступности.
