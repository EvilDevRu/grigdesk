# Лишний `__pycache__` в поколении сервера

Распакованное поколение `R` = `D/runtimes/server/packages/<packageId>` неизменяемо: кэш
payload сверяет его состав со списком архива, и любой лишний путь даёт
`server_payload_invalid` «Индекс или архив серверной поставки повреждён»
([кэш payload](server-binary-cache.md)). В отличие от проверок комплекта с `release.json`,
сторонний `__pycache__` здесь не игнорируется.

## Источник: отвязанный прогон конвейера

Попытка конвейера запускается transient-сервисом `systemd-run --user --unit=factory-t<задача>`.
Такой юнит окружение сервера не наследует: он получает только список `--setenv` из
`routeLaunchEnv` (`server/src/lib/factoryRouteCli.ts`). Движок закреплённого поколения
(`FACTORY_HOME` = `R/engine`) запускает системный Python. Без `PYTHONDONTWRITEBYTECODE=1`
первый же импорт пишет `R/engine/lib/__pycache__/route_model.cpython-<версия>.pyc` и
`bootstrap_state.cpython-<версия>.pyc`; время записи совпадает с запуском юнита в
`journalctl --user` до долей секунды.

До исправления `routeLaunchEnv` этой переменной не передавал — с перехода конвейера на
закреплённое поколение ELF. Теперь она host-owned и задаётся явно в обеих ветках запуска
(юнит и detached fallback), `extraEnv` её не снимает; проверка — SB13 в
`tests/server/server-binary-factory-env.test.js`. Действует для юнитов, запущенных сервером
с исправлением. Уже запущенный юнит сохраняет своё окружение до завершения: удалённый
`__pycache__` он создаст снова при следующем импорте.

## Симптом и последствия

`bin/grigdesk-server --prepare --json` возвращает этот отказ. Ту же подготовку выполняют
запуск сервера окном и `deploy/desktop.sh install`, поэтому `grigdesk-ctl build window`
падает после успешной сборки AppImage (`не удалось: window`). Работающий сервер продолжает
работать. Пересборка сервера даёт новое чистое поколение и скрывает дефект до первого
прогона конвейера на нём.

## Поиск и уборка

`find <R> -newer <R>/.ready.json` показывает записанное после подготовки поколения,
`systemctl --user list-units 'factory-*'` — юниты, работающие из этого поколения.
Лишний каталог удаляется после завершения этих юнитов; изменённый ctime каталога переводит
следующую подготовку в полную проверку хешей с перезаписью marker.
