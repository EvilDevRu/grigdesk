# Подписанный канал выпуска с сайта

Канал переносимой установки читается с
`https://grigdesk.com/api/releases/v1/channel.json`, затем с зеркала
`https://grigdesk.ru/api/releases/v1/channel.json`. Source-установки сохраняют git-канал.
Мобильные и прежние v1-поставки на этот механизм не переводятся.

## Формат и доверие

`shared/runtime/releaseChannelContracts.ts` задаёт строгие декодеры и адреса.
Индекс содержит только `format: 1`, `publishedAt` в ISO и `latest` (запись либо null).
Запись содержит `version`, `commit`, `archiveSha256`, `archiveSize`, `bundleSha256`,
`signature`, `archiveUrl`, `compat: { os: 'linux', arch: 'x64', glibc: '2.28' }`.
Посторонние поля отвергаются. Версия — стабильный SemVer, хеши — SHA256 hex,
подпись — 64 байта ed25519 в base64. `archiveUrl` — HTTPS-адрес
`<origin>/releases/<версия>/release.tar.gz`; в выходе сборщика он ещё null.

Подписываются точные UTF-8 байты файла `release.tar.gz.sha256`:

```text
<archiveSha256>  release.tar.gz
<bundleSha256>  release/bin/bundle.json
```

После второй строки обязателен перевод строки. Менеджер реконструирует этот текст
и проверяет подпись до скачивания. Затем проверяет размер и SHA256 архива, хеш описи
после распаковки, JSON-версию нового сервера до замены. Подпись не содержит адреса
сайта; происхождение содержимого доказывают подписанные хеши.

Публичный ключ SPKI PEM — константа `RELEASE_SIGNING_PUBLIC_KEY`. Пустой ключ даёт
`release_signing_key_missing` до скачивания, чужая подпись — `release_signature_invalid`.
`node tools/release-keygen.mts <абсолютный каталог>` создаёт приватный PKCS8 PEM
с правами 0600 и публичный SPKI PEM 0644. Повторная запись приватного ключа запрещена.
Приватный ключ в репозиторий не включается.

## Сборка и публикация

`GRIGDESK_RELEASE_SIGNING_KEY` указывает сборщику путь приватного PEM. Подписанный
`node tools/bundle.mts` публикует пять имён: `release/`, `release.tar.gz`,
`release.tar.gz.sha256`, `release.tar.gz.sha256.sig`, `channel.json`.
Без ключа сохраняются три прежних выхода. Сборщик не устанавливает зависимости.

`node tools/release-publish.mts <абсолютный каталог выпуска>` проверяет подпись,
реальный SHA256/размер архива и соответствие полей канала суммам до любых SSH-команд.
Публичный PEM можно передать через `RELEASE_SIGNING_PUBLIC_KEY_FILE`, иначе используется
константа shared. `--dry-run` проверяет выпуск и печатает план без изменения файлов.

Настройки основного сайта: `RELEASE_SITE_HOST`, `USER`, `KEY`, `DIR`, `PUBLIC_ORIGIN`
с общим префиксом `RELEASE_SITE_`; необязательный `PORT` по умолчанию 22.
`KEY` для скрипта — путь к SSH-ключу. Зеркала используют наборы
`RELEASE_SITE_MIRROR_`, `RELEASE_SITE_MIRROR2_`, `RELEASE_SITE_MIRROR3_`.
На сайте заранее нужны `<DIR>/api/releases/v1/` и `<DIR>/releases/`.
SSH использует BatchMode и запоминает новый ключ хоста; изменившийся ключ отвергается.

Публикатор проверяет подписанный archive и bundle.json, сверяет SHA извлечённого сервера
до его исполнения и готовит его ресурсное поколение в собственной временной папке.
Сайт берётся только из server/help/site этого поколения; версия/commit и байты help.json
совпадают с корпусом сервера. Исходники рабочего checkout после сборки не читаются.
Preparation освобождается при успехе и отказе. `--dry-run` не исполняет бинарник,
не создаёт сайт, не меняет channel.json и не вызывает SSH.

Пять файлов (архив, суммы, подпись, канал и подготовленный help-site.tar.gz) передаются
в собственный staging внутри site root. Одна удалённая транзакция берёт
`.grigdesk-release-publish.lock`, проверяет состав, выставляет immutable каталоги
`releases/<version>/` и `help/<version>/`, затем latest.html/latest.js и последним channel.json.
Повтор допускается с теми же суммами и корпусом. Готовые каталоги версий при частичном отказе
сохраняются и переиспользуются следующим upload; старые версии не перезаписываются.
latest не хранит второй указатель версии: он читает существующий канал.

SSH disconnect освобождает собственный lock через trap; SIGKILL может оставить каталог.
Владелец сначала проверяет отсутствие publisher, затем вручную удаляет пустой lock.
Автоматического удаления чужого lock нет. GitHub сериализует разные теги общей concurrency group.
Сайт содержит assets и полные licenses с индексом, не обращается к API приложения и моделям.

Основной хост обязателен, отказ зеркала даёт предупреждение. Коды: 2 — нет настроек,
3 — локальная проверка выпуска, 4 — отказ публикации основного сайта.
Оба канала содержат один `archiveUrl`: зеркало резервирует метаданные,
скачивание остаётся на основном origin.

## Проверка и установка

Чтение канала допускает только HTTPS, запрещает redirects, ограничено пятью секундами
на источник и 1 MiB тела. Успех кешируется на пять минут; после общего отказа —
пауза 30 секунд. Параллельные запросы разделяют одну операцию. Сам сервис чтения
подпись не проверяет: это делает менеджер перед скачиванием.

`PackagedReleaseService` хранит последний снимок и ошибку. GET статуса локален;
POST `/api/system/version/check` проверяет канал. Фоновый таймер работает раз в шесть
часов и не удерживает процесс. Версия установки берётся из `bin/bundle.json`, с fallback
на identity payload. Поля разрешения source-обновлений не меняются.

POST `/api/system/package-update` принимает подтверждённые `expectedVersion` и
`expectedArchiveSha256`. Изменившийся канал даёт 409. Без portable-описи установка
отвергается с `package_update_unsupported_layout` до создания задания.
Состояние — `<dataHome>/state/grigdesk-package-update.json`, рядом каталог `.job-lock`.
Повторная установка и кнопка перезапуска блокируются активным заданием.

Стадии: queued → verifying → downloading → unpacking → probing → applying → restarting.
Прогресс — downloadedBytes/totalBytes, записи прогресса ограничены одной в секунду.
Staging по умолчанию находится в `<I>/.grigdesk-update/`, на той же файловой системе.
I — физический родитель `bin/`, runtime-корень R не заменяется.
Меняются `bin/`, `GrigDesk`, `README.md`, с резервами `<имя>.grigdesk-backup-<job>`.
Пути резервов сохраняются до переименований.

При новом запуске recover подтверждает целевую версию и удаляет резервы. Обрыв до
applying даёт `package_update_interrupted` и удаляет staging. Обрыв applying возвращает
резервы и даёт `package_apply_interrupted`; невозможный откат сохраняет
`manual_recovery_required` с путями. Резервы для ручного восстановления сохраняются.

Desktop-перезапуск использует штатный слив с кодом 75, systemd — обычный слив и выход.
При ручном запуске или потере владельца desktop задание остаётся restarting до
ручного перезапуска. Работающее окно продолжает прежний AppImage до следующего открытия.
Закрытие модала не отменяет установку; задание видно в карточке и при повторном открытии.

Реальная сборка комплекта и открытие AppImage — ручная приёмка владельца.
Допуск GLM `api` также выполняет владелец отдельно; CI не имеет платного ключа и
не продлевает допуск. Сборщик сохраняет отказ `deepseek_glm_unadmitted` без допуска.

Продуктовая версия ELF и identity payload допускает стабильный SemVer; builder передаёт
значение корневого VERSION в manifest. Проба обновления сравнивает именно эту версию
с подтверждённой целью канала, независимо от format и hostContract бинарного протокола.
