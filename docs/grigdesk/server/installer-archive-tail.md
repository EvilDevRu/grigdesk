# Потоковые архивы автономного установщика

Installer содержит небольшой Node SEA с кодом, лицензией и подписанным release-envelope.
`postject` не получает большие desktop/server assets: его WASM-инъектор исчерпывает
память на реальных объёмах дистрибутива. Воспроизведение с SEA-блоком около 512 МиБ
даёт Aborted; перенос архивов оставляет блок размером в сотни КиБ.

После готового ELF записаны архивы в фиксированном порядке: server.tar.gz, desktop.tar.gz.
Размер каждого и SHA берутся из подписанного описания. Начало хвоста вычисляется как
размер файла минус сумма двух размеров; дробные, нулевые и небезопасные числа отвергаются.
Обрезание или добавление байтов меняет диапазоны и проваливает хеш. Отдельный внешний
файл или сеть для установки не нужны; подпись installer покрывает весь ELF вместе с хвостом.

`shared/node/installerArchiveTail.ts` дописывает и читает данные блоками до 1 МиБ.
Источники должны быть обычными файлами, symlink не следует. Копия создаётся эксклюзивно
с 0600 и сохраняется только после проверки SHA; прежний target не удаляется при отказе.
`installRelease` по-прежнему проверяет конверт до архивов, а потом выполняет штатную
проверку tar/описей и подготовку установки.

`grigdesk-install --verify --json` проверяет схему, подпись и оба встроенных архива
потоково, без установки, пользовательского состояния и запуска сервера/окна.
Обязательный verify-job запускает приватную исполняемую копию только после повторной
проверки подписи её точных байтов. Проверка GUI по-прежнему отдельная.

SEA передаёт в argv два служебных пути перед аргументами пользователя, как обычный Node.
Maintenance entry отбрасывает оба: иначе `--verify` и `install` ошибочно попадут в чтение
существующей установки вместо выполнения команды автономного установщика.
