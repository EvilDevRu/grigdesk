# Владельцы порта: служба, ручной запуск и приложение

Сервер также поддерживает [дочерний режим приложения](desktop-owned-server.md). Контроллер
этого режима проверяет HTTP и службу до собственного запуска, переиспользует готовый сервер
и останавливает только свой процесс. Запущенная служба или ручной экземпляр остаются внешними
для контроллера и переживают его закрытие. Обратно: `deploy/install.sh` не стартует юнит,
если на порту уже отвечает GrigDesk, — иначе юнит ушёл бы в тот же crashloop рядом с сервером
приложения.

`deploy/install.sh` ставит user-юнит `grigdesk-server.service` (Restart=always). Если гонять
сервер руками через `deploy/restart.sh` (setsid), юнит уходит в вечный crashloop по EADDRINUSE
(число рестартов растёт без ограничений), а в окна свободного порта успевает перехватить порт —
и тогда часть запросов обрабатывает не тот экземпляр, который ожидает оператор.
Служба и ручной запуск не должны занимать один порт одновременно. На время ручной разработки
службу останавливают из терминала, вне хода агента. Диагноз перехвата:
`journalctl --user -u grigdesk-server`.

Ручной экземпляр из терминала может держать порт часами, пока юнит безуспешно перезапускается.
Побочные эффекты, которые сбивают с толку при диагностике:

- `systemctl --user is-active` показывает `activating`, `MainPID=0` — юнит «как бы поднимается»,
  хотя запросы обслуживает совсем другой процесс. Кто на самом деле на порту, видно только через
  `ss -ltnp | grep :8140`, а его происхождение — через `cat /proc/<pid>/cgroup`
  (`app-code-*.scope` = запущен руками из VS Code, `grigdesk-server.service` = боевой юнит).
- Правки серверного кода «не применяются»: ручной экземпляр стартовал до них, а `--watch` в
  бою не используется. Прежде чем решить «фикс не работает», сверь аптайм процесса со временем правки.

**`systemctl restart` эту ситуацию НЕ расшивает:** пока ручной экземпляр жив, юнит всё равно не
займёт порт. Порядок один — погасить владельца порта, дождаться освобождения, и только потом
стартовать юнит. `deploy/restart.sh` поднимает свой процесс, а не юнит; после такого перехвата
контроллер приложения также считает сервер внешним.
