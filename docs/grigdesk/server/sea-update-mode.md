# Обновление сервера из пакета

Здесь сохранён режим обновления прежнего каталога R и перехода с исходников.
Статус и замена нового варианта описаны в [обзоре одиночного ELF](server-binary.md).

Состав system-модуля выбирается до создания source release service. Для SEA используется
`PackagedReleaseService`: identity берётся из `R/release.json` прежней поставки
или защищённого VERSION payload, без git и журнала source job. Для переносимой установки
версия читается из физического `bin/bundle.json` с fallback на identity пакета.
Конструктор не запускает асинхронный captureRunning.
В DTO объявлена capability `{ kind: 'package', message }`; source-клиенты прежнего сервера
продолжают работать без этого необязательного поля.

Packaged update manager не восстанавливает прежние source jobs. Прямые apply/update
возвращают `packaged_update_requires_package`, HTTP 409, с сообщением
«Установите новый пакет GrigDesk». Маршруты `/api/system/apply`, `/api/system/update` и
`/api/system/web-rebuild` имеют ранние ворота до менеджера, npm и записи задания.
GET статуса остаётся локальным. POST проверки и таймер раз в шесть часов читают
[подписанный канал сайта](site-release-channel.md). Отдельный POST package-update
запускает скачивание, проверку, замену установки с резервами и штатный перезапуск.
Пустой публичный ключ запрещает скачивание; прежние R без portable-описи не обновляются.

Настройки сервера показывают версию сервера и интерфейса приложения и предлагают
обновить пакет через карточку и модал с прогрессом. Source-карточка checkout и её действия
используются для source.
Штатная кнопка перезапуска отдельна от обновления; владение приложением, IPC и код 75
сохраняются. Активное package-задание блокирует отдельный перезапуск через `assertIdle`.

Сборщик подменяет `releaseServices.ts` прямой фабрикой пакета. Source release/update
services исключены из SEA-графа. Общие SemVer-функции и command runner вынесены в
`releaseCommon.ts`, поскольку нужны также плагинам и launcher. Старые imports этих
функций из `grigDeskRelease.ts` поддерживаются через re-exports.

Boot staging внутри checkout недостаточен для проверки независимости: git способен
найти родительский `.git`. Поэтому package-test распаковывает архив в `os.tmpdir()`
и запускает настоящий сервер с отдельным D. Проверки изоляции namespace дополняют этот тест.
