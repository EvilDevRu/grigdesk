# Терминальное меню и прогресс сборки

Пустой `grigdesk-ctl` показывает меню, когда stdin и stdout — терминалы и процесс не
принадлежит `grigdesk-server.service`. В остальных случаях выводится справка без открытия окна.
Явный `open` всегда использует прежнюю команду. Сторож открытия, stop и restart заново
проверяется при выборе действия; меню не добавляет `--force`.

В исходной и установленной поставках меню открывает Go-команда. Распознавание
агентов вне cgroup службы этим интерфейсом не расширяется.

Шапка показывает версию своей поставки, вид установки, сервер и окно. Чтение службы и HTTP
ограничено 700 мс; журнал systemd, Docker и связи не запрашиваются. Полный пункт «Состояние»
вызывает прежний status. Переносимый marker и release.json важнее случайных исходников рядом:
готовые поставки скрывают пункты сборки и разработки. Уборка артефактов остаётся доступна
в группе «Разработчику» во всех видах установки.
Отдельный installed ctl также вызывает общие preview, подтверждение и команду уборки;
для этого ему не требуется source-диспетчер CLI или серверный payload.

Стрелки выбирают пункт, Enter выполняет его, Esc возвращает предыдущий уровень либо выходит.
Действие и его результат видны на том же экране до Enter или Esc. Имя и id устройства
запрашиваются отдельным полем. Во время полноэкранной сборки Ctrl+C отменяет действие.
В самом меню Ctrl+C завершает CLI с кодом 130, SIGTERM завершает сеанс с кодом 143.

[Общие экраны консоли](cli-terminal-screens.md) используются для выбора, подтверждения,
ввода и прогресса. Внешний журнал передаётся в обычные потоки. JSON остаётся чистым документом.

Новые надписи используют только `shared/i18n/assets/locales/{ru,en}/cli.json` и чистое общее
ядро. Язык выбирается по непустым LC_ALL → LC_MESSAGES → LANG. Если они отсутствуют,
используется русский; неизвестная локаль и C используют английский. Настройки окна не читаются.
Меню использует [тёмное оформление](cli-menu-rendering.md): короткую шапку, строку состояний,
группы команд и подсветку выбора. Под списком показано описание выбранного пункта.
Узкий терминал переносит состояния и сокращает подсказку управления. Resize перерисовывает
экран. NO_COLOR и TERM=dumb отключают цвет, dumb также отключает позиционирование курсора.
Внешние управляющие последовательности очищаются на экране.

В «Дистрибутиве» на Linux x64 доступны Linux x64, Windows x64 и Android APK.
macOS Apple Silicon, Linux ARM64 и Windows ARM64 выделены приглушённым цветом и подписью
«недоступно». Enter на такой строке оставляет меню открытым и сохраняет выделение.
Linux запускает [релизный рецепт](lightweight-installer.md#локальная-сборка-и-официальный-кандидат),
Windows — [сборку офлайн-ZIP](windows-offline-installation.md#локальная-сборка-из-linux),
Android — [debug-сборку APK](ctl-build-apk.md).

По умолчанию все три цели сохраняют результат под `~/.grigdesk/dists/`. Linux использует
`dist-build-*/release-artifacts/`, Windows — `dist-windows-*/`, Android кладёт
`grigdesk-mobile-debug.apk` в корень `dists/`. Каталог `dists/` находится в папке данных
GrigDesk (`GRIGDESK_HOME`), а рабочие файлы и журналы CLI хранятся в папке артефактов.

## Уборка артефактов

`grigdesk-ctl artifacts-cleanup [--dry-run] [--older-than 7d] [--keep-generations 3] [--json]`
убирает выбранную локальную папку артефактов только по явному запуску. Срок — положительное
целое с `m`, `h` или `d`; умолчания: 7 суток и 3 поколения. В меню предварительный просмотр
показывает корень, порог, K, список с байтами и сумму. Под отчётом две подсвечиваемые
строки выбора, как в конце сборки. Стрелки меняют выбор, PgUp/PgDn и Home/End
прокручивают отчёт. По умолчанию выбрана «Отмена». Enter по отказу, Esc и закрытие ввода
ничего не удаляют. Enter на строке «Удалить» запускает повторную проверку кандидатов.
Каталоги со свежими данными или новой блокировкой сохраняются. Ошибка отдельной папки
видна в списке, остальных кандидатов можно подтвердить. При ошибке чтения корня
или отсутствии доступных кандидатов в отчёте
с ошибками меню показывает результат без удаления.

Первый прогон на большой папке может идти минуты: dry-run только читает диск,
Ctrl+C безопасен. В меню и на терминальном stderr прямой команды видны этап и время. При проверке и удалении
шкала показывает долю обработанных позиций и текущий каталог. Отмена работает и во время предварительного обхода: Ctrl+C/SIGINT
завершает CLI с кодом 130, SIGTERM — 143, EOF в preview — 0. Текущая файловая операция
может завершиться; новые удаления после отмены не начинаются, собственные lock-и снимаются.
При настоящем удалении накопленный отчёт сохраняется, `--json` возвращает один документ
с `interrupted: true` и байтами уже удалённых каталогов. Начатое удаление отдельного дерева
может закончиться до остановки; удалённые данные автоматически не восстанавливаются.
Размер и возраст требуют обхода вложенных записей; содержимое больших
файлов не читается. Результат остаётся в истории вывода. Перед подтверждением длинный список листается PgUp/PgDn.

Отчёт содержит удалённые каталоги, байты и причины пропуска; `--json` сохраняет один
машиночитаемый документ, включая частичные ошибки. Молодые и занятые каталоги защищены,
неизвестный владелец lock также занят. Pinned Node, payloads и runtime-deps в node-cache
сохраняются; очищаются только лишние старые generations. Старые `provider-install-probes`
и целая папка `ctl-build` могут попасть под явную возрастную уборку. Собственная ротация
последних десяти build-журналов ниже не меняется. Правила путей, lock-ов, отчёта, повторов
и барьер параллельного захвата lock-ов — в [контракте уборки](artifacts-cleanup.md).

Удаление необратимо; оно может лишить старые сообщения картинок. Перед запуском проверьте
список и [сохраните нужные данные](../guide/ru/data-and-backups.md). Для source команда
меняется следующим запуском, готовым поставкам нужен обычный выпуск обновлённого CLI-helper.
Серверной миграции, фонового таймера и отдельного перезапуска сервера нет.

## Сборка

Меню предлагает all, server, web, window, deepseek и apk. Ручная команда build в
человеческом терминале и запуск через меню используют [один индикатор](cli-build-interaction.md).
Он показывает стадию и прошедшее время. Шкала отражает долю успешных стадий, если их число
известно заранее. Точная длительность неизвестна. Вне человеческого TTY команды
печатают обычный вывод и завершаются без ожидания клавиши.

Внутренний opt-in канал fd 3 передаёт `start\t<id>`, `end\t<id>\t<code>`
и `hint\tselect-server`. Пользовательский вывод не содержит этих событий.

Полные stdout/stderr пишутся в `<D>/artifacts/ctl-build/build-<UTC>-<pid>-<unique>.log`.
Каталог создаётся с правами 0700, файл — 0600. Относительная ссылка `latest.log` заменяется
атомарно. Хранятся последние десять собственных обычных журналов; чужие файлы не удаляются.
Журналы внутри artifacts доступны агентам чатов по действующим правилам доступа к артефактам.
Невозможность открыть журнал останавливает запуск до сборочных команд.

История `<D>/state/ctl-build-timings.json` версии 1 заменяется атомарно только после общего
успеха. Ошибка, прерывание, другая цепочка или повреждение истории не становятся новыми весами.
D вычисляется общим контрактом папки данных без чтения `.env` сборкой.

Экран ошибки показывает название стадии, код, последние двадцать строк и полный путь журнала.
Результат показывает компоненты и подсказки про окно и выбор сервера. Enter или Esc после
любого исхода возвращает к выбранной цели. Прямая команда отдаёт код сборки оболочке.

Сборочные команды запускаются в отдельной группе. В интерактивной сборке
дочерняя команда не читает управляющий терминал, а её полный вывод остаётся в журнале.

Профильные проверки используют отдельные HOME/D, PTY и заглушки. Реальная служба и
рабочие артефакты пользователя для них не нужны.
