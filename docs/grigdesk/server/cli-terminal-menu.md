# Терминальное меню и прогресс сборки

Пустой `grigdesk-ctl` показывает меню, когда stdin и stdout — терминалы и процесс не
принадлежит `grigdesk-server.service`. В остальных случаях выводится справка без открытия окна.
Явный `open` всегда использует прежнюю команду. Сторож открытия, stop и restart заново
проверяется при выборе действия; меню не добавляет `--force`.

В исходниках с установленным ELF меню запускается исходным Node только после успешной
проверки его версии. Если Node отсутствует или слишком стар, сохраняется прежняя автономная
ветка ELF со справкой. Распознавание агентов вне cgroup службы этим интерфейсом не расширяется.

Шапка показывает версию своей поставки, вид установки, сервер и окно. Чтение службы и HTTP
ограничено 700 мс; журнал systemd, Docker и связи не запрашиваются. Полный пункт «Состояние»
вызывает прежний status. Переносимый marker и release.json важнее случайных исходников рядом:
готовые поставки скрывают группы сборки и разработки.

Стрелки выбирают пункт, Enter выполняет его, Esc возвращает предыдущий уровень либо выходит.
Ctrl+C даёт 130, SIGTERM — 143. Raw mode, чтение stdin и видимость курсора восстанавливаются
при выходе, исключении и закрытии ввода. Перед обычной командой или QR ввод возвращается
в обычный режим. Короткий результат остаётся до Enter/Esc; open, dev и run завершают CLI
с кодом вызванной команды. Имя устройства и id запрашиваются отдельно; Esc отменяет ввод.

[Общие экраны консоли](cli-terminal-screens.md) оформляют состояния, результаты команд,
журналы, ввод, устройства, QR и сборку. Длинные результаты меню доступны клавишами просмотра.
Рамка явных команд TTY не добавляет ожидания клавиши, `--json` сохраняет чистый документ.

Новые надписи используют только `shared/i18n/assets/locales/{ru,en}/cli.json` и чистое общее
ядро. Язык выбирается по непустым LC_ALL → LC_MESSAGES → LANG. Если они отсутствуют,
используется русский; неизвестная локаль и C используют английский. Настройки окна не читаются.
Меню использует [тёмное оформление](cli-menu-rendering.md): короткую шапку, строку состояний,
группы команд и подсветку выбора. Под списком показано описание выбранного пункта.
Узкий терминал переносит состояния и сокращает подсказку управления. Resize перерисовывает
экран. NO_COLOR и TERM=dumb отключают цвет, dumb также отключает позиционирование курсора.
Внешние управляющие последовательности очищаются на экране.

## Сборка

Меню предлагает all, server, web, window, deepseek, apk и bundle. Ручной валидный `build`
в человеческом терминале использует тот же прогресс. После сборки сервера, веба и окна
предлагается [открыть окно](cli-build-interaction.md), как и при сборке из меню.
У `deepseek`, [Android APK](ctl-build-apk.md) и `bundle` сохраняется обычный итог.
Явный bundle пока
сохраняет поток строк; из меню он наблюдается тем же механизмом. Нетерминальные и агентские
запуски сохраняют прежний вывод и коды, не создавая новых журналов или истории.

Контроллер запускает прежнюю оболочку. Внутренний opt-in канал fd 3 передаёт
`start\t<id>`, `end\t<id>\t<code>` и `hint\tselect-server`; пользовательские потоки событий
не содержат. Серверные внутренние стадии в этом режиме дополнительно передают полный поток
наружу, сохраняя собственные log/exit. Bundle наблюдает прежние фазы сборщиков, verify,
pack и publish без установки. Состав, порядок, кэш и установщики остаются прежними.

Процент использует длительности последней успешной сборки того же варианта с тем же
упорядоченным набором стадий. До первого замера используются грубые веса; вклад текущей
стадии ограничен 95% её веса, общий процент — 99 до успешного выхода и закрытия потоков.
Процент не убывает; оставшееся время оценивается по незавершённым весам. Загруженность машины
может сделать оценку неточной.

При `TERM=dumb` блок прогресса выводится при начале сборки, смене стадии и завершении.
Таймерная перерисовка отключена: во время долгого шага одинаковые блоки не дописываются.
Resize по-прежнему обновляет экран, полный вывод сборки сохраняется в журнале.
В обычном терминале таймер обновляет только изменившиеся строки без очистки всего экрана.

Полные stdout/stderr пишутся в `<D>/artifacts/ctl-build/build-<UTC>-<pid>-<unique>.log`.
Каталог создаётся с правами 0700, файл — 0600. Относительная ссылка `latest.log` заменяется
атомарно. Хранятся последние десять собственных обычных журналов; чужие файлы не удаляются.
Журналы внутри artifacts доступны агентам чатов по действующим правилам доступа к артефактам.
Невозможность открыть журнал останавливает запуск до сборочных команд.

История `<D>/state/ctl-build-timings.json` версии 1 заменяется атомарно только после общего
успеха. Ошибка, прерывание, другая цепочка или повреждение истории не становятся новыми весами.
D вычисляется общим контрактом папки данных без чтения `.env` сборкой.

Экран ошибки показывает название стадии, код, последние двадцать строк и полный путь журнала.
Успех показывает компоненты, общее время и прежние подсказки про окно и выбор сервера.
После ошибки CLI завершается ненулевым кодом вместо возврата к меню.

Ребёнок сборки имеет отдельную группу и stdin `/dev/null`: случайный читатель получает EOF,
а не SIGTTIN. Ctrl+C сначала снимает дерево собственных процессов через `/proc`, включая
вложенные setsid-группы, затем посылает INT, через две секунды TERM, ещё через две KILL.
PID/starttime/PGID перепроверяются перед сигналом; группа CLI и чужие процессы не затрагиваются.
Выход лидера не отменяет эскалацию известным потомкам. В журнале сохраняется отметка прерывания.

Проверки: `tests/cli/{menu,menu-actions,menu-packaged,screens,terminal,compatibility,
build-progress,build-log,build-session}.test.mts`,
`tests/server/ctl-{build-events,build-output,bundle-progress}.test.js`.
Они используют отдельные HOME/D, PTY и заглушки, без сборки или управления живой установкой.
