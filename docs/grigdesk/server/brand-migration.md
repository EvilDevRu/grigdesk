# Переход с Кокпита на GrigDesk

Код и сборки получают имя GrigDesk вместе. Настоящие данные переносит владелец из обычной
консоли при закрытом окне и остановленных сервере, DevLink и заданиях. Проверки на фикстурах
не означают, что установленная копия уже перенесена.

## Сначала папка данных

Шаг 0 выполняет владелец после резервной копии: переносит `~/.cockpit` в `~/.grigdesk`
и оставляет `~/.cockpit` ссылкой на новую папку. Две настоящие папки не объединяются.
Для уже выполненного переноса повторять действия не нужно. Новый код принимает прежнюю
ссылку только тогда, когда её канонический адрес совпадает с новой папкой. Ссылка нужна
старым путям вложений и оставшимся внешним потребителям.

`COCKPIT_HOME` и `COCKPIT_ENV_FILE` в окружении вызывают ранний отказ с именем новой
переменной. В `.env` запрещены обе формы этих двух ключей. Остальные известные старые
ключи диагностируются без значений и без автоматической подстановки. Если остались
внутренние старые пути, старт останавливается до записи с указанием команды переноса.

## Команда переноса

Из корня кода, от владельца:

```bash
node tools/brandMove.mts
node tools/brandMove.mts --apply
```

Без флага команда показывает план и причины отказа, ничего не записывает. Перед изменением
проверяются папки, цели, процесс и порт сервера, службы, замок профиля окна и незавершённые
установки плагинов. Занятые данные и существующая цель переноса запрещают начало.
Окружение `CLAUDECODE` запрещено. Тестовые `--code-root` и `--home` допустимы только вместе
и внутри `os.tmpdir()`, включая проверку канонических адресов ссылок.

Применение состоит из пяти групп:

1. Переименование `state/cockpit-server.log` с ротациями, `state/cockpit-update.json`
   и `plugins/.cockpit-install` в соответствующие имена `grigdesk`.
2. Переименование известных ключей хоста в `.env` из `COCKPIT_*` в `GRIGDESK_*`, замена
   префикса путей и удаление переходных значений LOG/UI_RELEASES_DIR, совпадающих с умолчанием.
   Комментарии и права сохраняются. Разные значения старой и новой формы — отказ;
   при одинаковых удаляется старая строка. Неизвестные ключи плагинов остаются.
3. Замена префикса абсолютных путей в значениях `state/prefs.json`,
   `state/showcase-browser/browser.json` и `state/sandboxes/*.json`; ключи JSON не меняются.
4. Обновление совместимых ссылок `.env` и `server/.state` в дереве кода.
5. Перенос `~/.config/cockpit` в `~/.config/grigdesk`, вместе с подписью Android и DevLink.

Профиль окна `~/.config/Кокпит` переносит отдельно установщик окна в `~/.config/GrigDesk`.
Регистр имени отличает данные окна от служебной папки.
[Контракт переноса профиля](../web/desktop-profile-rename.md).
Файлы плагинов не переписываются: команда сообщает только имена файлов со старыми путями.

## Журнал, повтор и откат

`state/brand-move.json` записывает запланированные и завершённые действия, режимы и хеши.
Копии лежат в `state/brand-move-backup/`, исходная `.env` — с правами 0600.
Содержимое настроек не выводится. Повтор `--apply` после сбоя продолжает незавершённое;
после завершения не меняет данные повторно.

```bash
node tools/brandMove.mts --back
node tools/brandMove.mts --drop-links
```

`--back` предварительно сверяет все отпечатки и копии, затем возвращает изменения в обратном
порядке. Изменённый человеком файл или повреждённая копия вызывает отказ с именем файла,
без затирания. Возврат бренда требует также прежнего кода, окна и службы: инструмент
не устанавливает программы. Начальный перенос корня и ссылку `~/.cockpit` он не отменяет.

`--drop-links` убирает только собственные совместимые ссылки дерева кода; чужие ссылки,
обычные файлы и `~/.cockpit` сохраняет. Код 0 — успех, 1 — отказ условия/операции,
2 — неверный вызов или нарушение тестовой границы. Команду не следует запускать одновременно
с другим переносом или редактором настроек.

Проверки: `tests/server/brand-move.test.mts`, `brand-env.test.mts`, `data-home.test.mts`.
[Сохранённые старые имена](../overview/legacy-names.md).

## Второй этап

Второй этап сменил оставшиеся внутренние имена: метки и протокол сборки DeepSeek/GLM
(`.grigdesk.b<hash16>`, `grigdesk.settings`, `_grigdesk/settings/*`, `grigdesk-host-web-acp-v3`),
ревизии профиля GLM, умолчания домашних папок исполнителей, протокол телефона
(`urn:grigdesk:mobile:v1`, `X-GrigDesk-Operation-Created-At`, `grigdesklink`), значение рабочей
папки `grigdesk`, имя арбитра `grigdesk-arbiter`, формат выгрузки маршрутов
`grigdesk-route-authoring`, код `grigdesk_too_old` и IndexedDB `grigdesk-studio3d-intents`.

При переходе, с закрытым окном и без активных задач конвейера:

1. Папки `~/.factory/state/cockpit-deepseek`, `cockpit-glm` и `cockpit-kimi-contained`
   переименовываются в `grigdesk-*` командой `mv`; сервер их не переносит.
2. `npm --prefix server run deepseek:prepare` пересобирает DeepSeek/GLM. До пересборки сервер
   отказывает этим исполнителям: «сборка не прошла проверку версии». После неё каждый старый чат
   один раз начинает новую сессию с заметкой «профиль исполнителя изменился».

Старые значения рабочей папки, арбитра и формата маршрутов читаются как новые (`LEGACY_VALUES`).
Записанное раньше не переписывается: чат хранит прежнюю рабочую папку как есть, старые ответы
арбитра остаются в файлах уточнений, а новые записи и выгрузки получают новые имена. Поэтому
`LEGACY_VALUES` убирается только вместе с отдельным переносом этих данных. Приложение телефона 0.1.9
с новым сервером не работает. Незавершённые намерения 3D из старой IndexedDB не переносятся: перед переходом не должно
быть идущей генерации 3D.
