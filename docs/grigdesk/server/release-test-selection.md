# Ручной выбор проверок выпуска

В Run workflow владелец выбирает `test_mode=full` либо `skip`. По умолчанию выбран full.
Версия, включая 0.1.1, и канал не переключают режим и не запрещают выбор владельца.
Stable identity разрешена для main и соответствующего VERSION тега; dev остаётся
пробной версией из dev. Checkout должен совпасть с github.sha запуска.
Для skip нужна непустая `skip_reason` длиной до 1000 символов. Это данные JSON,
а не исполняемый текст команды. Skip и validation_run несовместимы.

`tools/releaseChecks.mts` сохраняет version, commit, ref, режим, причину и номер
подтверждённого прогона в release-checks.json. Каждое чтение проверяет строгую форму
и текущую identity. В full оба тестовых job должны завершиться success; в skip
или reuse оба должны иметь skipped. Отказавший или отменённый job не становится успехом.

Причина skip добавляется к RU/EN описанию до подписи индекса. Решение также включается
в testValidation файла release-acceptance.json. Успешная упаковка не объявляет полный
набор выполненным и не объявляет ручную приёмку установленного окна.

Проверки готовых пакетов, подписи, SHA, описи и штатный verify бинарников выполняются
при любом выбранном режиме. Полная схема — в [workflow выпуска](release-workflow-validation.md).
