# Клиентский TLS-вход

Основной HTTP-сервер по-прежнему слушает loopback. Полные приложения могут использовать
отдельный TLS-вход, включённый явной настройкой машины:

- `GRIGDESK_CLIENT_LISTEN` — список `IPv4:порт` через запятую; пусто означает «выключен».
- `GRIGDESK_CLIENT_ADDRESS` — `host:порт`, адрес для строки привязки. Host — IPv4 или
  имя из `[a-z0-9.-]`, длиной до 253 символов; порт 1–65535. IPv6 не поддерживается.

Эти ключи и `GRIGDESK_SERVER_NAME` включены в общий каталог переменных хоста
`HOST_ENV_SUFFIXES`. Старый префикс не подставляется автоматически при загрузке настроек.

Неверная настройка возвращает состояние `error` с причиной. Ошибка личности, реестра или
занятый порт также закрывает только клиентский вход. Если один из нескольких bind отказал,
остальные сокеты этого входа закрываются; основной HTTP продолжает отвечать.

Вход запускается в `onListen` после `mobile.start()`. Он использует ту же личность мозга
`ensureBrainIdentity` и общий `DeviceStore`, но принимает только устройства scope `client`.
Записи прежнего формата без scope читаются как `mobile-v1`; чтение не переписывает файл.
Новые вызовы `DeviceStore.add` без scope сохраняют `mobile-v1` ради прежнего протокола.

`tls.Server` требует TLS 1.3 и запрашивает клиентский сертификат. Самоподписанные сертификаты
проверяются по реестру устройств. Действующий `client` связывается с сокетом через
[реестр субъектов](client-device-principal.md), получает фоновый `touch` со своим catch и передаётся основному
`app.server.emit('connection', socket)`. Fastify сохраняет protocol `https`.

Неизвестный сертификат или его отсутствие попадает в отдельный bootstrap с
[hello и pair](device-pairing.md); остальные пути отвечают 401 `unpaired`.
Отозванный сертификат и чужой scope получают HTTP 403 до основного API. Даже сырой отказ
содержит заголовок версии контрактов.

На входе допускается не более 256 TCP-сокетов, включая незавершённые TLS-рукопожатия, и
24 соединений на отпечаток. Лишнее TCP-соединение закрывается; лишнее TLS-соединение
сертификата получает 403 `connection_limit`. Непривязанным TLS-соединениям выделено
отдельно 16 мест; простой ограничен 3 с, полный срок 10 с, даже при поступлении отдельных байтов.
Перебор привязки ограничивается по IP в обоих входах; заполнение таблицы другого IP
не запирает действующие коды для всех устройств.

TLS-сессии не возобновляются: `SSL_OP_NO_TICKET`, `sessionTimeout: 1`, `newSession` без
сохранения и `resumeSession` с `callback(null, null)`. Это сохраняет сертификаты обеих
сторон при каждом подключении. Клиент также должен выключать кэш сессий.

`disconnect(fp)` отмечает субъект отозванным и разрывает все его TLS-сокеты, включая SSE и
WebSocket. Отзыв в DeviceStore записывается вызывающей стороной до disconnect.
`close()` закрывает все собственные соединения и слушатели, в том числе уже переданные
основному Fastify; повторное закрытие безопасно. Он зарегистрирован в shutdown и onClose.

Проверки: `client-config.test.js`, `client-listener.test.js`, `client-listener-boot.test.js`.
Тесты используют только синтетические сертификаты, временное состояние и случайные порты.

Незавершённых TLS-рукопожатий не больше 16 с одного IP при сохранённом общем пределе 256.
Срок ClientHello — 5 с: tlsClientError явно закрывает сокет. Успешный handshake освобождает
этот отдельный слот, затем применяются пределы устройства или bootstrap.
