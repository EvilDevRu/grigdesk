# Подготовка состава серверного комплекта

Здесь сохранена раскладка прежнего каталога R и перехода с исходников.
Состав payload нового варианта описан в [обзоре одиночного ELF](server-binary.md).

`server/build/resources.json` задаёт исходный и выходной путь каждого ресурса.
Копируются Python-программы, requirements, движок, запускалки,
каталог helper-ов и ESM bridge. Исходные `server/src`, `server/scripts` и `shared`
целиком в комплект не переносятся. Совместимые обёртки создаются отдельно.

`server/scripts/sea/dependencies.mts` раскрывает проверенный официальный архив
Node вместе с npm, заголовками и лицензиями. Серверные зависимости устанавливаются
`npm ci --omit=dev --prefer-offline` в отдельном staging по lockfile. HOME, cache
и конфигурация npm находятся за пределами комплекта. Для native-сборок используются
заголовки того же Node; Python bytecode отключён, чтобы node-gyp не создавал кэш в runtime.
В staging package.json разрешены lifecycle scripts точных версий cpu-features и ssh2.
После сборки из node-gyp build остаются только загружаемые Release/*.node;
Makefile/config.gypi, объекты и дубликаты удаляются. Compiler prefix maps и удаление
debug-данных исключают пути машины сборки. Аудит ищет их во всех файлах, включая npm/ELF.

Каждый непосредственно импортируемый пакет должен быть production dependency.
В частности, сервер явно объявляет `ajv` и `ws`, даже если они уже есть транзитивно.
Проба закреплённым Node импортирует production packages, разрешает package.json
Playwright и проверяет каждый поставляемый `.node` отдельным процессом.
После очистки поставляются два bindings: cpu-features и ssh2 для Node24.21.0/ABI137.
Проба загружает каждый в отдельном процессе, исключая повторную загрузку копий
NAN binding в одном процессе.

Индекс `licenses/THIRD-PARTY.json` связывает пакет и версию с текстами лицензий.
Сохраняются лицензия Node и предоставленные npm-пакетами файлы. Для шести точных
версий, у которых в исходной поставке нет такого файла, используются сохранённые
тексты [SPDX](https://github.com/spdx/license-list-data/tree/main/text): name/version/SPDX
и SHA256 закреплены в `server/build/licenses/npm-fallbacks.json`. Рядом копируется
исходный package.json с авторством и декларацией лицензии. Неизвестная версия либо
повреждённый текст останавливают сборку; сеть при сборе лицензий не нужна.

`stage.mts` учитывает файлы, режимы, размеры, SHA256 и внутренние относительные ссылки.
Отсутствующий обязательный файл, наружная ссылка, данные GrigDesk, `.env`, кэш,
лишний собственный TS или sourcemap запрещают публикацию. TS, карты и каталоги
`profiles` внутри сторонней библиотеки проверяются как её файлы, а не как данные GrigDesk.
Эти проверки не устанавливают комплект и не запускают живую службу.
