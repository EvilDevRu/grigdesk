# Предел попыток happy-eyeballs в сервере и Harness

Node по умолчанию открывает параллельные попытки соединения по IPv4 и IPv6
(`autoSelectFamily`, вторая попытка через 250 мс). На маршрутах с мёртвым IPv6
(например, VPN публикует `::/1`, но отказывает IPv6-соединения) отказ параллельной
IPv6-попытки обрывает ещё не установившееся IPv4-соединение: итог `ETIMEDOUT` за
1,3–2,5 с. Хосты, чей IPv4-handshake медленнее отказа (~1,2 с), отказывают всегда;
более быстрые выживают гонку. Проверено 2026-11-23 на `api.z.ai` и `api.telegram.org`.

Сервер и Harness применяют общий предел второй попытки 2000 мс
(`NETWORK_FAMILY_ATTEMPT_TIMEOUT_MS`, `shared/node/networkFamily.ts`): здоровое
семейство успевает соединиться до старта отказывающей попытки, а переход на резервное
семейство при действительно мёртвом первом сохраняется. Прецедент того же предела для
npm — [provider-install-npm](../chat/provider-install-npm.md). Ручки настройки нет:
предел безусловный, на здоровой сети меняется только ожидание резервной попытки.

## Точки применения

- `startServer()` вызывает `applyNetworkFamilyAttemptTimeout()` до сборки сервисов —
  нативный fetch сервера: генерация моделей, `fetchWithIsolatedDns` (host.fetch
  драйверов, медиа, файлы Tripo, архивы приложения и ретранслятора), WebSocket-клиенты.
- Bootstrap одноразового сетевого ребёнка (`isolatedNetworkWorker.ts`) применяет тот же
  предел сам: ребёнок не наследует дефолты родителя. Через него идут `isolatedFetch`
  (лимиты Claude/GLM/DeepSeek, баланс Tripo, каталог плагинов, Telegram Bot API) и
  `options.core.fetch` плагинов.

- Автономный launcher DeepSeek/GLM передаёт этот предел штатным флагом в argv
  своего worker Node до загрузки Harness. Это охватывает web и ACP. Флаг задан
  launcher, пользовательские `NODE_OPTIONS` остаются исключены.

## Границы

- Для Harness нужна отдельная сборка и установка `bin/deepseek`. Исправление находится
  в launcher, поэтому можно переупаковать проверенный payload текущей сборки через
  `--payload`, сохранив generation, версии журнала и отпечатки совместимости GLM.
  Установка совместимой сборки применяется к следующему ходу без перезапуска GrigDesk.
- Внешние CLI исполнителей и Go-фабрика живут в своих рантаймах и не наследуют предел.

## Проверка

`tests/server/network-family.test.js`: предел в текущем процессе и в сетевом ребёнке
(операция воркера возвращает его дефолт). Регрессия транспортов —
`tests/server/isolated-fetch.test.js`. `tests/deepseek/worker.test.mts` проверяет предел
в реальном дочернем процессе, запущенном launcher. На проблемном маршруте встроенный Node
с 250 мс трижды получил `ETIMEDOUT`, а с 2000 мс трижды получил HTTP 401 от шлюза Z.ai
на запрос без ключа. Этот замер проверяет соединение до шлюза.
