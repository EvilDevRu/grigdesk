# Локальный ключ окна и обычная сессия

Сервер публикует ключ окна только после успешного `listen`. Асинхронный `onListen`
сначала атомарно записывает файл, затем устанавливает ключ в памяти. До окончания
публикации обмен отвечает 503. Ошибка записи оставляет сервер доступным и ключ
недоступным; неудачный bind не меняет ключ процесса, занявшего порт. При закрытии
конечный файл не удаляется.

Общий resolver `shared/desktop/windowKeyPath.ts` получает env, uid и port явно и не зависит
от Node или браузера. Абсолютный
`GRIGDESK_WINDOW_KEY_PATH` важнее `XDG_RUNTIME_DIR`; иначе используется
`/run/user/<uid>/grigdesk/window-key-<порт>`. Неверное явное значение запрещает
публикацию без перехода к default. UID должен быть известным неотрицательным целым,
порт — 1…65535, включая 80.

Переопределения пути/runtime должны быть переданы серверу и окну одинаково через env.
`runtime-env.sh` передаёт из файла окружения только эффективный порт, без экспорта
остальных переменных; обычная установка использует default пути ключа.

Проверяется непосредственный каталог ключа: обычный собственный каталог 0700.
Отсутствующий каталог создаётся одним `mkdir`; его родитель должен уже существовать.
Предки выше этого каталога не проверяются. Существующий конечный файл допускается
только как собственный обычный файл 0600. Ссылки, каталоги и другие права отвергаются
без chmod. Ключ — 32 случайных байта base64url, 43 символа без перевода строки.
Запись идёт в уникальный файл 0600 с O_EXCL, затем rename; при отказе убирается только
собственный временный файл. Граница доверия — пользователь Linux, без защиты от
процесса того же UID, меняющего дерево во время операции.

`POST /api/auth/window-session` публичен для общего гарда, но принимает только
заголовок `x-grigdesk-window-key`. Порядок отказов:

1. Нет опубликованного ключа — 503 `window_key_unavailable`.
2. Сокет не loopback либо присутствует любой из `Forwarded`, `X-Forwarded-For`,
   `X-Forwarded-Proto`, `X-Forwarded-Host`, даже пустой — 403 `local_only`.
3. Host отличается от authority сервера, Origin присутствует и отличается от
   канонического origin либо `Sec-Fetch-Site: cross-site` — 403 `bad_window_origin`.
   Для порта 80 допустимы Host `127.0.0.1` и `127.0.0.1:80`.
4. Ключ не является одиночной строкой 43 base64url либо не равен ключу в памяти —
   401 `bad_window_key`. Сравнение одинаковых по длине Buffer использует timingSafeEqual.

Успех создаёт обычную сессию AuthStore и выдаёт host-only `grigdesk_sid`: Path=/,
HttpOnly, SameSite=Lax, Max-Age; на локальном HTTP без Secure. Срок сессии — 400 дней; парольный механизм снят. CLI, internal-токен и существующая cookie не заменяют
ключ. Старые сессии отзываются при переходе на формат 2; выхода больше нет. Все ответы POST имеют `Cache-Control: no-store`, включая ошибки
разбора тела; access logging выключен только у этого маршрута, чтобы не записывать
секрет, ошибочно переданный клиентом в query.

Проверки: `tests/server/window-key.test.js`, `auth-window-session.test.js`,
`loopback-only.test.mts`, `app-boot-smoke.test.js`. Boot-фикстуры явно задают путь
ключа под своим root; helper передаёт единый effectiveEnv в before, child и чтение
собственных файлов. Внешний или относительный override отвергается до spawn.
Проверки запуска используют только свои порты и серверы, без обращения к рабочему GrigDesk.
