# Фоновое чтение реестра исполнителей

Обычный `GET /api/providers` не держит окно до завершения внешних проб. Успешный
снимок живёт в серверном кэше 60 секунд. После истечения TTL запрос запускает одно
общее обновление и сразу получает последний успешный снимок. Отказ обновления
снимок не стирает. Без снимка ожидание ограничено 1200 мс; если сбор ещё идёт,
возвращается пустой список исполнителей с обычным `showAllModels`.
Быстрый отказ без предыдущего снимка сохраняет исходную ошибку HTTP.

Поздний успешный сбор отправляет одно событие `providers-update` всем окнам:
оболочка перечитывает уже готовый снимок. Одновременные запросы разделяют сбор
и не размножают уведомление. Инвалидация кэша сохраняет прежнюю защиту поколений:
снимок до изменения настроек или установки не возвращается как актуальный.

Явный `GET /api/providers?refresh=1` сохраняет полное ожидание проб и обновляет
каталог моделей. Внутренний декоратор `providerRegistry` также ждёт актуальный
результат: ограничение HTTP не меняет выбор исполнителя сервером. Лимиты
`/api/providers/usage` имеют отдельный кэш и собственный фоновый цикл.

Проверки: `tests/server/providers-background-read.test.js` измеряет p95 двадцати
одновременных холодных запросов при заблокированной пробе, единственный сбор/SSE,
немедленный устаревший снимок и полное ожидание явного refresh. Фикстуры реестра
подменяют оба источника — адаптеры и модели — чтобы не вызывать живой каталог.
