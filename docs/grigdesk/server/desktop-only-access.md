# Интерфейс приложения и вход по локальному ключу

Штатный интерфейс GrigDesk открывается в Electron. Труба местного профиля читает личный файл ключа
и обменивает его на сессию в памяти главного процесса. Vue загружается из встроенного пакета. Парольного входа, первичной настройки,
смены пароля и выхода больше нет. Для защиты открытого приложения блокируют экран компьютера.
Привязка телефона и её отзыв остаются отдельными действиями настроек.

Публичны только GET `/api/auth/state` и POST `/api/auth/window-session`. Состояние содержит
`method: 'window-key'`, `configured` (ключ опубликован), `authenticated`, `secure`; действующая
сессия дополнительно получает `clientScope`. Все ответы этих ручек имеют `no-store`.
Удалённые парольные пути и выход с авторизацией возвращают JSON 404, без неё — отказ гарда.

Общий гард защищает API, WebSocket, SSE, shots и страницы плагинов. Решение принимает
сопоставленный маршрут Fastify. Сервер больше не раздаёт UI и assets; навигация к корню
или неизвестному документу получает самостоятельное сообщение «GrigDesk открывается в
приложении» без входа и личных данных. Закрытые запросы получают 401; навигация к ним —
самостоятельный HTML отказа, API fetch — JSON. CLI/internal сохраняют прежние права.

`Sec-Fetch-Dest: empty` обозначает fetch, поэтому получает JSON 401. Это не навигация:
HTML здесь сломал бы разбор ответа API-клиентом и не дал бы запустить восстановление входа.

## Сессии и локальные данные

Файл `GRIGDESK_AUTH_SESSIONS` сохраняет прежний путь. Формат 2 содержит `version: 2`,
`clientScope` и карту `sessions`. Сессия живёт 400 дней, двадцать первая вытесняет старейшую.
Запись атомарна: временный файл 0600 рядом с целевым и rename. Новые сессии переживают
перезапуск сервера; плоский прежний формат, повреждённый файл и неизвестная версия их не дают.

При переходе старый строковый `login` из `GRIGDESK_AUTH_ACCOUNT` переносится без изменения
в `clientScope`, отсутствующий становится пустой строкой. Старый файл не меняется, хеш не
читается для проверки входа и не переносится. После сохранения версии 2 scope берётся из неё.
Web использует scope как прежнего владельца pending 3D, сохраняя IDs и состояние заказов.

## Восстановление и обновление

Без оболочки первый API 401 прекращает фоновые запросы и один раз перезагружает документ. Метка
`grigdesk-auth-reload-at` в sessionStorage ограничивает reload одной минутой; недоступный
storage считается уже использованной попыткой. Повторный 401 показывает «Нет входа».
Поздние ответы прежней эпохи не восстанавливают сессию, исходный запрос не повторяется.
При старте web без сессии показывает «Нет входа. GrigDesk открывается в приложении» без повторов;
подсказка предлагает закрыть и снова запустить приложение для нового входа по ключу.

В приложении 401 обрабатывает труба: она обновляет местную сессию и повторяет только GET/HEAD.
Web с обнаруженной оболочкой запрашивает её состояние и сохраняет текущий документ. Без оболочки
сохраняется прежний ограниченный reload и экран «Нет входа». Удалённое устройство входит через
TLS-сертификат; сессия браузера и токены на этом сокете не рассматриваются.

Встроенный интерфейс обновляется установкой пакета. Серверная пересборка не меняет его файлы;
service worker не используется. Секрет трубы, ключ устройства и cookie сервера недоступны JS.

## Проверка интерфейса агентом

Проверка API headless-браузером может использовать `X-GrigDesk-Token` из штатного CLI-токена
как секретный заголовок запросов своего origin. Это не возвращает серверную раздачу UI.
Для интерфейса используется изолированное приложение с собственными трубой и данными.
Токен не вставляют в URL, код страницы или отчёт; парольной формы больше нет.
Владелец пользователя ОС может прочитать локальный ключ: это граница доверия, а не проверка
User-Agent или запрет владельцу написать собственный клиент.

Контракты проверяют `auth-store`, `auth-window-session`, `desktop-only-access`, `no-access.component`,
`auto-login`, `connection-lifecycle`; настоящие окна — [Electron E2E](../testing/desktop-window-e2e.md).
