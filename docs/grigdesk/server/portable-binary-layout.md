# Ограничения плоской папки с бинарниками

Этот документ относится к прежним копиям отдельных файлов без marker переносимой поставки.
Новая команда [bundle](portable-bundle.md) сохраняет раскладку bin/, включает библиотеку ctl
и добавляет первичный выбор соседнего сервера окном. Прежние ограничения ниже сохраняются
для плоских копий без такого комплекта.

Автономные ELF сервера и DeepSeek содержат собственные ресурсы, однако существующий
запуск полного приложения рассчитан на установку с каталогом `bin/`. Перенос отдельных
ELF и перенос всей установленной копии имеют разные ограничения.

## Поиск сервера окном

`desktop/src/runtimeConfig.ts:loadServerRuntime` сначала читает описание установки
из `desktopRuntimePath`: при обычном XDG это
`~/.local/share/grigdesk/desktop/runtime.json`. Отсутствующий файл даёт
`problem: not_installed` до поиска исполняемых файлов. Наличие `grigdesk-server` рядом
с окном само по себе не меняет результат.

Descriptor v4 содержит абсолютные `binary`, `home` и `cliPaths`. Перенос такого JSON
с другой машины не привязывает его к новому расположению программы. `appDir` служит
очистке окружения AppImage; он не задаёт каталог поиска соседнего сервера.

Контракт выбора и подготовки — [серверный ELF в окне](server-binary-desktop.md).

## Корень установки и папка данных

Launcher в `server/src/binary/main.ts`, payload/helper в
`server/src/lib/runtimePaths.ts` и подготовка окружения в `server/src/lib/seaLaunch.ts`
вычисляют `installationBin = dirname(binary)` и корень установки как его родителя.
Это соответствует расположению `<установка>/bin/grigdesk-server`.

Если файл лежит плоско в `~/release/grigdesk-server`, корнем установки становится HOME.
Проверка `checkDataHome` считает обычную `~/.grigdesk` вложенной в установку и отказывает
с кодом 78 ещё до распаковки payload. При расположении
`~/release/bin/grigdesk-server` корнем становится `~/release`, и та же проверка допускает
умолчание папки данных.

Это ограничение вычисления установки, а не зависимость от текущего рабочего каталога.
Точный guard описан в [размещении payload](server-binary-placement.md).

## Единая команда

`bin/grigdesk-ctl` — Bash-скрипт. Он вычисляет корень на один уровень выше своего
каталога, читает `<корень>/deploy/lib/runtime-env.sh` и ищет сервер в
`<корень>/bin/grigdesk-server`. Собранный helper команды находится внутри payload,
но для его подготовки существующий shell-вход использует внешнюю библиотеку deploy.
Открытие окна из helper также использует `<корень>/bin/grigdesk-app`.

Копия только `grigdesk-ctl` в плоскую папку без deploy отказывает даже при `--help`.
Поэтому плоская копия команды без marker и библиотеки не является автономной поставкой.

## JSON и исполнители

| Файлы | Текущий контракт |
| --- | --- |
| Metadata, helpers, схемы и host contract сервера | Входят в payload, отдельные копии возле ELF не нужны. |
| Manifest и generation DeepSeek | Встроены в его ELF и извлекаются в собственный кэш. |
| `state/models.json` | Создаётся из встроенных адаптеров в папке данных. |
| `runtime.json` окна | Внешнее описание выбранной установки, требуется нынешнему загрузчику окна. |
| `*.grigdesk-server.json`, `*.grigdesk-deepseek.json` | Квитанции установки; отсутствие допустимо для обычного запуска candidate. Серверная полная verify проверяет присутствующую квитанцию и её абсолютный target. |
| Пользовательские файлы авторизации CLI | Принадлежат пользователю, который запускает приложение. |

Реестр исполнителей включает адаптеры через сгенерированные литеральные импорты
`server/scripts/sea/registries.mts`. Доступность CLI определяется отдельно:
`available = probe.ok && auth.available`. Поиск команды и поиск авторизации могут
давать разные отказы. Порядок PATH и поиск nvm — в
[контракте CLI](server-binary-path.md); отдельное ограничение проверки Codex — в
[описании его авторизации](../chat/codex-auth-home.md).

## Граница проверки

`tests/desktop/runtime-config.test.js`, `tests/server/server-binary-layout.test.js`,
`tests/server/server-binary-cli-path.test.js` и
`tests/server/deepseek-binary-descriptor.test.js` проверяют существующие loader,
guard, PATH и binary descriptor. Дополнительная изолированная проверка на одноразовых
HOME подтвердила отказ плоской команды без deploy, отсутствие поиска соседнего сервера,
код 78 у launcher с плоским ELF в HOME и успешный placement при сохранении `bin/`.

Эти проверки не подтверждают запуск готового переносимого AppImage на другой машине.
Linux x64, совместимые системные библиотеки и зависимости отдельных возможностей
сохраняются по [контракту сервера](server-binary.md).
