# Привязка полного приложения

Строка `GRIGDESK:PAIR:1:<base32>` переносит адрес машины, порт, SHA-256 DER-сертификата
сервера и одноразовый код. Base32 использует RFC 4648 без `=`; декодер допускает нижний
регистр и краевые пробелы. Неверные длины, порт 0, лишние байты и недопустимые имена
отклоняются. IPv6 зарезервирован и даёт `unsupported_address`.

Байты: тип адреса `04` и четыре байта IPv4 либо `48`, длина и ASCII имени
`[a-z0-9.-]` (1–253 символа); затем два байта порта big-endian, 32 байта пина и 24 байта
кода. Код наружу записывается base64url. IPv4 даёт 117 символов, QR alphanumeric уровня M
помещается в версию 5. Общие векторы находятся в `tests/fixtures/pairing-vectors.json`.

Неизвестный сертификат получает отдельное приложение с лимитом тела 4 КиБ. В нём
`GET /api/client/hello` раскрывает только продукт, общее имя GrigDesk, пин и версию API;
`device` равен null. `POST /api/client/pair` принимает код и необязательное имя, но
отпечаток всегда читает из TLS-сокета. Имя, заданное при выдаче кода, имеет приоритет.
Все остальные пути дают 401 `unpaired`.

Код живёт 10 минут, привязан к scope и одному сертификату. Повтор тем же сертификатом
возвращает прежнее устройство до истечения срока; другой сертификат и чужой scope дают
401 `pair_code_invalid`. После пяти ошибок шестой запрос получает 429 `pair_locked`.
Окно попыток — также 10 минут. Коды и результаты живут в памяти, список устройств — на диске.

После успешной привязки следующий TLS идёт в основной API. Поэтому обработчик pair
зарегистрирован также там: повтор потерянного ответа должен работать на новом соединении.
Оба пути используют один код и проверяют тот же сертификат; основной путь закрыт общим гардом.
Прежний `PairingCodes.issue()` без параметров по-прежнему выдаёт scope `mobile-v1`.

Управление на основном API доступно только `authKind: session`, включая устройства.
CLI/internal получают 403 `session_required`:

- `GET /api/client/hello` возвращает имя из `GRIGDESK_SERVER_NAME` либо hostname и устройство
  текущего TLS-сокета.
- `GET /api/devices` возвращает состояние входа и публичный список с scope и датами.
  Пины, коды и ключи в этот ответ не входят.
- `POST /api/devices/pairing` принимает имя и необязательный адрес; отдаёт строку,
  `expiresAt`, выбранный адрес, матрицу QR из строк `0/1` и SVG.
- `POST /api/devices/:id/revoke` сначала сохраняет отзыв, затем закрывает соединения
  сертификата на обоих входах. Готовность мобильного входа v1 для этого не нужна.

При выключенном входе выдача кода даёт 409 `client_listener_off`. Адрес выбирается из тела,
затем `GRIGDESK_CLIENT_ADDRESS`, затем единственного не-wildcard слушателя. Если его
невозможно определить, возвращается 409 `client_address_unknown`.

Вкладка «Доступ» показывает блок «Устройства» перед прежним мобильным разделом. Видны
имя, вид приложения, последний вход и отзыв с подтверждением. Диалог добавления показывает
QR, строку и остаток срока; при закрытии секрет очищается. Выключенный вход объясняет
настройку `GRIGDESK_CLIENT_LISTEN`. SVG отображается как изображение, строка не входит
в события журнала API. Проверка: `tests/web/settings-devices.component.test.js`.

Сертификат, существующий с другим scope, получает 409 без расходования кода. В строке привязки
unsupported_address относится только к зарезервированному типу 0x06; неизвестный тип invalid_pairing.
Выдача кода содержит expiresInMs для отсчёта на устройстве независимо от часов сервера. Список
устройств содержит currentDeviceId для предупреждения об отзыве собственного доступа.
