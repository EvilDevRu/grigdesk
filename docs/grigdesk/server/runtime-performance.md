# Диагностика HTTP и ресурсов сервера

Общий verbose включает диагностический logger и сбор ресурсов процесса сервера.
Новые события не требуют отдельной службы или внешнего watchdog.

## HTTP, SSE и WebSocket

Сервер генерирует случайный UUID `serverRequest`; входящему request-id не доверяет.
Ответы `/api` кроме самого журнала получают `X-GrigDesk-Request` и числовую метрику
`grigdesk;dur` в Server-Timing. Граница — raw.writeHead, включая hijacked SSE и raw
ответы плагинов. Прежние метрики и overload заголовков сохраняются.

`server.http` содержит method, шаблон маршрута, status/outcome и относительные этапы:
prepareMs до preHandler, handlerMs до заголовков, sendMs до завершения/закрытия ответа.
Это длительности hooks, не CPU-профиль функции. Для SSE sendMs описывает жизнь потока
и не означает фриз. Запрос без заголовков получает один `server.pending` через 3000 мс;
не более 128 unref-таймеров. Отправка заголовков снимает ожидание даже у долгого потока.

Успешный WS handshake завершается по websocketServer connection с `server.upgrade`.
Его долгая жизнь не считается HTTP pending. Отказ авторизации остаётся обычным HTTP
с прежним кодом. При смене политики reset снимает таймеры, старое поколение не получает
метаданные после повторного включения. Close освобождает подписку WS и таймеры.

## Ресурсы процесса

При verbose работает один интервал 5000 мс, histogram цикла событий с разрешением 20 мс
и один GC observer. `server.runtime` содержит фактический periodMs, loopMaxMs,
loopP95Ms, cpuPercent, rss, heapUsed, gcMs и gcCount. Histogram и GC сбрасываются
между окнами; новый enabled-период начинает собственную базу CPU. CPU измеряется
в процентах одного ядра и может превышать 100 при работе нескольких потоков.

Off/close освобождают интервал, histogram и observer. Полная остановка процесса может
оставить только начало/ожидание без итога: зависший процесс не может сам гарантированно
записать событие о своём зависании. После восстановившейся блокировки задержка попадает
в следующее окно. CPU-профили, heap snapshots и наблюдение чужих процессов не вводятся.

Автоматические события не содержат тела запросов, чаты, поля форм, реальные параметры
маршрутов или входящие заголовки. UUID служит корреляции, не авторизации. Проверки
http-diagnostics/runtime-performance проходят hooks, настоящий SSE и WS с auth guard;
синтетические часы подтверждают формулы и lifecycle, а не здоровье живой машины.
