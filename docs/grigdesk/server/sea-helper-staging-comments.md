# Стабильный вход helper без пути staging

`buildHelper` передаёт сгенерированный вход esbuild через `stdin` с постоянным
`sourcefile: <id>.mjs` и `resolveDir` корня исходников. Генератор строит относительные
импорты от виртуального файла в том же корне. Поэтому случайный workDir не влияет
на байты helper, импорт исходника и однократный вызов main сохраняются.

Прежний файловый entry `<workDir>/<id>.mjs` оставлял в ESM комментарий esbuild с именем
файла относительно текущей папки процесса. Для staging во временной папке комментарий
содержал полный путь staging как подстроку после `../`. Штатный auditStage отклонял его
на стадии prepare; в других папках такой комментарий мог пройти аудит, но менять packageId.

Аудит не ослаблен: он по-прежнему ищет пути sourceRoot, cacheDir, payload и work во всех
байтах. `tests/server/sea-helper-build.test.js` собирает один chat-permission-mcp из двух
разных workDir под `os.tmpdir()`, сравнивает байты, ищет абсолютный и относительный workDir
и запускает неизменённый auditStage с запрещёнными корнями обеих папок.

Наличие прежнего R для сравнения производительности — отдельный
[контракт baseline в E0](server-binary-smoke-baseline.md).
