# Изолированная сеть сборщиков статистики

`server/src/lib/isolatedFetch.ts` выполняет каждый запрос в одноразовом дочернем Node.
GLM usage, DeepSeek usage (включая страницы тарифов), баланс Tripo и Telegram Bot API
используют его по умолчанию. Подмены `fetchImpl` в тестах сохраняются. Генерация
моделей, загрузки 3D-ассетов и транспорт чатов не проходят через этот сборщик.

Таймаут ожидания native fetch сам по себе не гарантирует освобождение зависшего
системного DNS в долгоживущем процессе. Здесь DNS, HTTPS и чтение тела принадлежат
дочернему процессу. Родитель по отмене или по истечении срока посылает SIGKILL
только своему ребёнку, дожидается `close` и возвращает ошибку. Следующий запрос
получает новый процесс; зависший resolver сервера не используется. В ребёнке есть
резервный сторож на случай исчезновения родителя: deadline плюс одна секунда.
Резервный сторож и завершение после записи ответа используют SIGKILL самого себя,
без `process.exit`, который способен зависнуть внутри native cleanup. Родитель
принимает только полный ответ протокола и подтверждённый `close`.

Поддержаны HTTP(S), строка/URL, строковое тело запроса, метод, заголовки, redirect
и AbortSignal. Request, потоки и прочие тела не поддержаны. Ответ буферизуется
целиком: по умолчанию до 2 МиБ после распаковки и 15 секунд, входной JSON — до 256 КиБ.
`isolatedFetchWithLimits` позволяет явно задать срок до 300 секунд и ответ до 20 МиБ;
Telegram использует 8 МиБ для getUpdates и 20 МиБ для файлов. Проверяются заявленный
и распакованный размеры. Это bounded-транспорт, не универсальная замена fetch.
Вернувшийся Response хранит
статус, заголовки и тело; исходный URL и redirected не восстанавливаются.

Ключи передаются через stdin, не в argv; окружение ребёнка не наследует credentials
и NODE_OPTIONS. Сохраняются PATH и настройки CA. Текст сторонних исключений и stderr
не публикуется: возвращается только код ошибки. Перенаправления следуют режиму caller,
поэтому `redirect: 'error'` Codex Reset продолжает запрещать их.
Исполняемый Node выбирает `nodeExecutable()` для source и пакетной поставки;
дополнительного helper-файла, curl или сборки сторонних зависимостей нет.

Плагины получают этот же транспорт как `options.core.fetch`; автор плагина явно
передаёт его своему сборщику. Native fetch внутри произвольного плагина автоматически
не подменяется. Таймеры, интервалы повторов, сохранение прежнего успешного снимка
и защита поколений остаются у потребителя.

Проверка: `tests/server/isolated-fetch.test.js` проверяет реальный дочерний процесс,
отмену и жёсткий срок с закрытием TCP, следующий успешный запрос, запрет redirect,
предел тела, POST с заголовком и работу при сломанном fetch родителя. Профильные
регрессии: `glm-usage`, `deepseek-usage`, `tripo-provider`, `plugin-core`.
Применение серверного изменения требует сборки установленного пакета и ручного
перезапуска приложения; работающий сервер из хода агента не перезапускают.
