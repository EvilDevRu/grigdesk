# Версия контрактов API

Сервер ставит `X-GrigDesk-Api: <major>.<minor>` на каждый ответ основного HTTP-приложения,
включая отказы авторизации и 404. Плагин `server/src/plugins/apiVersion.ts` регистрируется
первым и добавляет заголовок в `onRequest`, в том числе через `reply.raw.setHeader`:
настоящий SSE использует `hijack` и обходит накопленные заголовки Fastify.

Источник номера — `shared/client/apiVersion.ts`. Major обозначает несовместимое изменение,
minor — совместимое расширение. До первого выпуска номер закреплён на **0.1**, и проверка
отпечатка не блокирует изменения: `--check` возвращает 0 и «до выпуска сторож выключен».
Версии сборок приложения при этом не меняются.

`API_CONTRACT_FINGERPRINT` — SHA-256 от отсортированных записей
`<относительный путь>\n<текст с LF>\n`. В него входят `shared/**/*Contracts.ts`,
`shared/lib/contractDecoders.ts` и прямые `shared/client/*.ts`, кроме `apiVersion.ts`.
Таким образом, смена имени контракта тоже меняет отпечаток, а CRLF вместо LF — нет.

```bash
node tools/api-version.mjs --check
node tools/api-version.mjs --root <каталог> --check
```

После первого выпуска несовпадение отпечатка даёт код 1 с сообщением «контракты изменились».
Для совместимого изменения выполняют `--bump minor`, для несовместимого — `--bump major`.
Инструмент переписывает только две константы версии и отпечатка. Первый выпуск переводится
с 0.1 на 1.0 командой `node tools/api-version.mjs --bump major`; до выпуска её не вызывают.

При объединении веток до первого выпуска номер остаётся 0.1, а зафиксированный
отпечаток обновляют по фактическому общему дереву. Независимый расчёт в
`tests/server/api-version.test.js` проверяет его даже при major 0. Один `--check`
до выпуска намеренно не доказывает актуальность отпечатка.
