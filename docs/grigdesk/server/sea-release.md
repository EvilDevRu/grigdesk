# Сборка серверного SEA-комплекта

Команда из дерева исходников:

```bash
npm --prefix server run build:sea -- --out-dir /path/to/releases --cache-dir /path/to/cache
npm --prefix server run test:sea -- --release-dir /path/to/releases/grigdesk-server-VERSION-linux-x64-CONTENT
```

Требуются Linux x64, поддерживаемый Node для инструментов, установленные devDependencies
с закреплёнными esbuild/postject, tar/xz, инструменты native-сборки npm и strip из binutils.
Node **24.21.0** берётся из проверенного архива в cache либо `b24/.cache`/`relay/.cache`;
сборщик сервера его не скачивает. Повреждённый cache допускает другой проверенный
локальный архив; копия хешируется и публикуется атомарным rename.
npm использует `npm_config_cache` либо cache/npm,
режим `--prefer-offline` и отдельный HOME вне комплекта. Полный состав описан в
[подготовке пакета](sea-package.md).

Серверный CJS включает собственный граф, сгенерированные таблицы исполнителей и БД,
контекст SEA и замену module URL. Внешними остаются npm и builtin. Warning esbuild и
наружный собственный import останавливают выпуск. Banner связывает require с физическим
`server/grigdesk-server`, а не с cwd. Blob и исполняемый файл используют один Node.
Helpers собираются отдельными ESM; b24 и relay — своими закреплёнными сборщиками.

`release.json` содержит schema 1, версию из VERSION, packagingVersion 1,
Node/platform/arch/ABI, файлы с mode/size/SHA256 и внутренние относительные ссылки.
ContentId хеширует остальные поля manifest; manifest исключён из списка файлов.
Окончательный бинарник не содержит своего contentId. До manifest каталоги получают0755,
файлы0644, исполняемые0755. В tar.xz записывается числовой владелец0/0, поэтому
распаковка с umask022 не меняет результат проверки.

Временная сборка создаётся внутри out-dir. До публикации выполняются аудит состава,
проверка manifest и boot с новым временным HOME/D и отдельными loopback-портами.
Smoke проверяет общий auth guard и штатный SIGTERM. Затем создаётся tar.xz,
каталог версии получает суффикс первых 16 знаков contentId, архив публикуется последним
rename. Отказ prepare, smoke или tar сохраняет предыдущий результат.
Старые версии автоматически не удаляются. `build-result.json` хранит пути, хеш и размер
архива, contentId и runtime; это отчёт сборки, он не входит в комплект.

Бинарник поддерживает `--help`, `--version`, `--version --json`, `--license` и
`--check-runtime`/`--check-startup`. Полная проверка сверяет версии, файлы, все хеши,
биты исполнения и ссылки, печатает JSON и возвращает0/1. Добавления дают предупреждения,
сторонний `__pycache__` игнорируется. Быстрая проверка запуска сохраняет проверку состава,
размеров, exec-битов, manifest/contentId и хешей SEA/вложенного Node, пропуская хеши
библиотек. Обе команды не запускают сервер и не читают D.
Неизвестные и несовместимые аргументы дают код 2 до boot.

`test:sea` запускает проверки через общий сторож памяти. Отсутствующий пакет — ошибка,
а не skip. Проверяются ELF, служебные команды без Node в PATH, отдельная распаковка
архива и настоящий boot с временными данными. Все `tests/server/sea/*.test.mts`, включая
[изоляцию без checkout](sea-isolation.md), входят в этот отдельный gate. GUI и настоящая
служба находятся в отдельных `.e2e.mts` и требуют явного внешнего запуска.

Явная команда `bash tools/server-sea-check <out-dir> <cache-dir>` собирает комплект
и запускает весь `test:sea`,
сохраняя код отказа; публикации или установки в нём нет. Явные каталоги можно передать
двумя аргументами либо через `GRIGDESK_SEA_RELEASE_DIR`/`GRIGDESK_SEA_CACHE_DIR`.
Без них создаётся отдельный временный каталог, проверенный результат сохраняется.
Кэш npm общий для build и dependency probe, пользовательский `npm_config_cache` имеет приоритет.
Обычные `tools/release`/`tools/release-check` SEA не собирают и не принимают.
Подробности и проверки обоих путей — [контракт release gate](sea-release-gate.md).

Первая SEA-поставка исключает runtime DeepSeek. Общая конфигурация не читает отсутствующий
source-контракт поставки; адаптер получает embedded-режим и сообщает о недоступной generation.
Source-проверка контракта сохраняется. Интеграция отдельного бинарника DeepSeek выполняется
после объединения соответствующей ветки.

SHA256 одного архива описывает один выпуск. Битовая воспроизводимость SEA этой проверкой
не доказана.
