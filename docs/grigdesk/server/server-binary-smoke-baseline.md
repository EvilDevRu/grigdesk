# Необязательный baseline в ранних воротах E0

Обычная сборка серверного ELF работает с новым кэшем без прежнего SEA-комплекта.
E0 всегда выполняет metadata, cold HTTP с авторизацией, prepare, IPC с подтверждением
передачи preparation и полную verify. Ограничения размера ELF ≤450 MiB и cold API ≤30 с
действуют независимо от baseline.

E0 в отдельном процессе временно задаёт umask `0077`, который наследуется тестовыми
ELF, а HOME создаёт с явным режимом `0700`. Это сохраняет приватные права и у каталогов,
создаваемых приложением перед повторным IPC boot. Иначе при umask терминала `0002`
HOME и вложенные factory-каталоги получают `0775`, и штатная защита source lock
останавливает E0 с `factory_source_lock_invalid`. После успеха или отказа маска
вызывающего процесса возвращается. Проверка прав остаётся включённой; реальная
папка данных пользователя в E0 не используется.

Сравнение тёплого старта включается существующим каталогом `cache/baseline-release`.
В нём обязателен `server/grigdesk-server`; неполный или непригодный baseline даёт отказ,
не превращается в пропуск. Сохраняются прогрев baseline и три пары его запусков с кандидатом.
Отношения median и p95 должны быть ≤2. Полные статистические ворота S27 не меняются.

Без каталога baseline E0 не вычисляет отношения. Отчёт E0 и `build-result.json` содержат:

```json
{
  "warmRatio": null,
  "warmP95Ratio": null,
  "warmRatioNote": "warm ratio не измерялся: нет baseline"
}
```

При наличии baseline оба отношения числовые, а warmRatioNote равен null. Отсутствие замера
не выдаётся за успешное сравнение производительности. Builder переносит эти поля в результат
только после успешного smoke; отказ сохраняет прежние ELF и build-result.

`tests/server/server-binary-build.test.js` проверяет это через порты smoke и публикацию
builder: новый кэш, абсолютный cold-порог, отказ каждой функциональной проверки, успешный
baseline, превышение median/p95 и неполный явно существующий baseline.
Isolation-проверка также проверяет права временного HOME, вложенные записи приложения,
настоящий source gate и возврат umask после успеха и отказа;
регрессию запускают через сторож памяти в том числе при umask `0002`.
