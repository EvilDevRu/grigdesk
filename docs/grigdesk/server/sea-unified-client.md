# SEA и единое приложение

Здесь сохранён API-контракт прежнего каталога R и перехода с исходников.
Приёмка API нового варианта описана в [обзоре одиночного ELF](server-binary.md#сборка-и-приёмка).

Готовый сервер предоставляет тот же API, что source-запуск. `apiVersionPlugin` добавляет
`X-GrigDesk-Api: 0.1` также к отказам авторизации, SSE и 404. Клиентский TLS-вход,
bootstrap и маршруты устройств включены в CJS-граф. Настройки `GRIGDESK_CLIENT_LISTEN`,
`GRIGDESK_CLIENT_ADDRESS` и `GRIGDESK_SERVER_NAME` читаются из обычного окружения сервера;
ошибка отдельного входа не запрещает основной boot.

Интерфейс принадлежит пакету приложения. Серверный R не содержит web/dist и не публикует
UI-версии в D. Прежние `/ui/<id>/` возвращают404; корневой HTML объясняет, что GrigDesk
открывается в приложении. Локальная труба читает запечатанный пакет окна и передаёт API
серверу с сессией в main. Origin трубы отличается от порта API. Подробнее —
[единое приложение](../overview/unified-client.md) и [пакет интерфейса](../web/packaged-ui.md).

Descriptor v3 выбирает SEA как местный сервер. Загрузчик проверяет R, а supervisor
сохраняет IPC и restart75; собственный интерфейс окна доступен до готовности сервера.
Удалённый профиль не запускает местный сервер. Выбор R не переносит профили машин
оболочки и не меняет их origin; [выбор и возврат](sea-desktop.md).

`grigdesk-ctl device add|list|revoke` входит в существующий `grigdesk-cli` helper.
Отдельного процесса или новой точки входа helper для команд устройств нет. Команда обменивает
локальный ключ окна на короткую сессию; токен CLI не заменяет права человека на привязку.
TLS-личности и привязки находятся в D, выпуск сертификатов требует OpenSSL хоста.
Отозванный сертификат получает403 с `device_revoked`.

В общем модале настроек `system.updates` использует `updateCapability.kind=package`:
показывает версию сервера/приложения и «Установите новый пакет GrigDesk», скрывает
source-действия и не опрашивает пересборку web. Source-режим сохраняет прежние действия.
Изменение API DTO учтено в отпечатке общих контрактов; до первого выпуска API остаётся0.1.

`sea/protocols.test.mts` проверяет настоящий SEA через startPipe/createUpstream,
авторизацию, версию API, команды устройств и прежние SSE/WS/PTY. `sea/clients.test.mts`
проверяет TLS1.3, bootstrap, привязку, device-auth и отзыв. Оба используют read-only R,
одноразовый D, закрытый checkout и заглушку host Node. Публичный OpenSSL config подключён
в namespace только для чтения; ключи выпускаются внутри D.
