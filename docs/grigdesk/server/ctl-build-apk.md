# Android APK в общей команде сборки

В исходниках `grigdesk-ctl build apk` вызывает существующий `tools/mobile build`.
В терминальном меню та же цель доступна в группе «Сборка» как «Android APK».
Она собирает общий интерфейс в Android assets и debug APK модуля `:client`.
Подготовка Java, SDK и зависимостей остаётся в штатных командах
[Android-сборщика](../mobile/android-build.md).

Цель самостоятельная: `all` по-прежнему собирает сервер, веб и окно. Установка на телефон
не выполняется. Подписанный выпуск вызывается отдельно через `grigdesk-ctl mobile release`
с существующим ключом подписи.

Результат — `<D>/state/mobile-apk/grigdesk-mobile-debug.apk`, где D определяется
`GRIGDESK_HOME`, иначе домашней папкой GrigDesk. `GRIGDESK_MOBILE_APK_DIR` переопределяет
каталог результата. Относительный путь в терминальном режиме считается от корня исходников,
где запускается дочерний сборщик.

Терминал показывает одну наблюдаемую стадию `apk.build`, общий прогресс, длительность,
полный журнал и путь к APK. Успешный итог не предлагает открывать окно GrigDesk.
Вне терминала сохраняется поток сборщика; отказ возвращает исходный ненулевой код,
сообщение `не удалось: apk` и завершает стадию тем же кодом.

Проверки: `tests/server/ctl-build.test.js`, `tests/server/ctl-build-events.test.js`,
`tests/cli/build-session.test.mts`. Изолированные заглушки проверяют делегирование,
ошибки, пути, меню и обе локали; настоящую Android-сборку они не запускают.
