# Подтверждённые проверки для stable-выпуска

Ручной workflow принимает необязательный `validation_run`. По умолчанию выполняются все
серверные, web, shared и guide-проверки; явный test_mode=skip описан отдельно в
[контракте workflow](release-workflow-validation.md). Явный номер позволяет stable-выпуску из main или тега использовать
уже успешный полный прогон тех же исходников, сохраняя отдельную свежую сборку комплекта.
В full без этого входа server/shared/guide и web выполняются параллельно на разных runner.
Упаковка зависит от обоих job. При явном входе оба проверочных job пропускаются, но
plan-job обязан подтвердить прежний полный запуск до любых ключей; сам пропуск
проверок не считается успехом.

`tools/releaseValidation.mts` проверяет по GitHub API:

- Завершение запуска с `success`, событие workflow_dispatch и тот же репозиторий, включая head.
- Точный путь workflow и его текущую либо известную прежнюю полную версию.
- Успех каждого проверочного и сборочного job и всех четырёх тестовых шагов, общего
  outcome-гейта, production web, комплекта, deb и загрузки артефактов. Для текущей
  версии workflow обязателен также успех проверки готовых пакетов. Только отдельная
  публикация может иметь skipped при проверочном выпуске без publish. Пропущенные
  тесты не подходят, поэтому цепочки reuse запрещены.
- Полные Git-деревья исходного запуска и stable-коммита: пути, blob SHA, типы и modes совпадают.
  Усечённая выдача API считается отказом.

Из сравнения исключены только семь файлов самого CI-механизма:
workflow выпуска, `tools/releaseValidation.mts`, `tests/server/release-validation.test.js`,
`tests/server/release-workflow.test.js`, эта статья, `release-workflow-validation.md` и README
серверной документации. Их symlink-варианты запрещены. Остальные тесты, runtime-исходники,
guide, manifests и lock-файлы сравниваются полностью.

Режим доступен только каналу release из main или тега, совпадающего с VERSION. Ошибка подтверждения
останавливает задание до ключей и упаковки. Обычный запуск по умолчанию выполняет
все проверки; skip выбирает владелец явно.
Новые проверки самого механизма и контракта workflow выполняются также при reuse.

После подтверждения не повторяются браузер тестов, тестовые варианты ELF и четыре больших
набора. Подготовка runtime-исходников, production-сборка UI, новая сборка бинарников,
их штатные verify/E0, подпись, deb и публикация сохраняются. Режим не означает ручную
приёмку установленного AppImage. JSON-свидетельство входит в артефакты выпуска и содержит
номер исходного запуска, оба commit SHA, отпечаток сравниваемых файлов и список проверок.

Контракты GitHub: [workflow runs](https://docs.github.com/en/rest/actions/workflow-runs),
[Git trees и ограничение recursive-выдачи](https://docs.github.com/en/rest/git/trees#get-a-tree).
