# Сессионная авторизация приложения

Вход выполняется [локальным ключом окна](window-key.md) или по проверенному
[TLS-сокету устройства](client-device-principal.md). `lib/authStore.ts` хранит
сессии формата 2 и `clientScope`; парольная учётная запись служит только источником миграции
прежнего login. Сессия живёт 400 дней, сохраняется после рестарта, лимит — 20 записей.
Подробный контракт перехода и восстановления: [доступ приложения](desktop-only-access.md).

Публичны только GET `/api/auth/state` и POST `/api/auth/window-session`. Все остальные API,
SSE, WebSocket, HTML, SPA-переходы, shots и ассеты закрыты. Навигация получает HTML 401 без
скриптов, остальные запросы — JSON 401. `needsSetup` и парольных форм больше нет.
`/api/health` также закрыт: он содержит сведения машины, проверке готовности достаточно state.

Гард решает по `request.routeOptions.url`, а не сырому `request.raw.url`: Fastify декодирует
путь до сопоставления, поэтому `/%61pi/terminal` должен иметь те же ограничения, что обычный
API. Некорректное percent-encoding cookie даёт отказ, а не 500. SPA-fallback не отвечает
HTML на API-подобный путь или неизвестную мутацию.

`GRIGDESK_TOKEN` и `VITE_GRIGDESK_TOKEN` не возвращать: секрет сборки доступен клиентскому JS.
CLI получает отдельный файловый токен 0600, а процессы чата — `GRIGDESK_INTERNAL`, случайный
in-memory токен текущего сервера. Внутренний Fastify inject также обязан передавать
`X-GrigDesk-Internal`: иначе защищённое чтение вернёт 401 вместо данных. Непредвиденный код
нельзя подменять пустым успешным списком. Проверка: `app-internal-inject.contract.test.js`.

Fastify не доверяет forwarded-заголовкам. Cookie host-only, HttpOnly, SameSite=Lax, Path=/;
на локальном HTTP без Secure. Любой forwarded-заголовок запрещает обмен ключа.
Подробности сети: [loopback](loopback-access.md).

Устройство получает `authKind: 'session'` и отдельный `authPrincipal` с идентификатором
устройства. Его субъект проверяется до cookie, токенов и публичных путей. Отзыв даёт
403 `device_revoked`, включая состояние входа. Локальный ключ окна устройству не выдаёт
дополнительную сессию: обмен возвращает 403 `local_only`.

Короткие CLI-сессии и долгие сессии окна имеют отдельные пределы по 20 записей.
Новая сессия не вытесняет себя; принадлежность короткой группе сохраняется в файле v2.
