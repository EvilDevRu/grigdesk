# Явная уборка артефактов

`grigdesk-ctl artifacts-cleanup` работает локально, без HTTP, systemd и чтения настроек
сервера. Корень выбирается через `artifactsPath`: непустая `GRIGDESK_ARTIFACTS_DIR` важнее
папки `artifacts` выбранной папки данных. Относительный путь и корень файловой системы
отвергаются. Отсутствующий корень даёт пустой отчёт без создания папки.
Команда доступна как в source/packaged CLI, так и в отдельном installed ctl. Оба меню
используют общее подтверждение из `cli/artifactsCleanupMenu.ts`; локальная команда не
загружает source-управление сервером и не проверяет receipt установки ради уборки.

```bash
grigdesk-ctl artifacts-cleanup --dry-run --older-than 7d --keep-generations 3
grigdesk-ctl artifacts-cleanup --older-than 7d --keep-generations 3 --json
```

`--dry-run` только читает: показывает кандидатов, размеры, пропуски и сумму без lock-записей
и удаления. Срок `--older-than` — положительное целое с `m`, `h` или `d` (минуты, часы,
сутки), по умолчанию `7d`. `--keep-generations` — положительное безопасное целое,
по умолчанию `3`. Повторные флаги со значением и неизвестные аргументы дают код 2 до эффектов.

Обычные непосредственные каталоги корня выбираются целиком, в том числе старые `ctl-build`
и `provider-install-probes`. Сама папка `deepseek-binary` сохраняется: `test-builds`, `gates`,
`build-input-tests` и `explicit-cache` раскрываются до дочерних каталогов. Другие каталоги
темы выбираются по возрасту. В `deepseek-binary/node-cache` убираются только лишние
`generations`; архив pinned Node, `payloads`, `runtime-deps-node24`, `node-runtime` и прочее
содержимое сохраняется. Пустые структурные контейнеры остаются.

Возраст определяется самым свежим mtime всего дерева. Ровно на пороге, в будущем либо
со свежей вложенной записью каталог сохраняется. Поколения сортируются по этому времени
от новых к старым, при равенстве — по имени. Полная свежесть соседних поколений берётся
из общего снимка, затем обновляются состав папки и mtime её непосредственных каталогов.
Каждый кандидат перед удалением измеряется заново; повторного полного обхода всех
соседних поколений для каждого кандидата нет. Последние K защищены; более старые также
сохраняются, если молоды или заняты, поэтому итоговое число может превышать K.
Служебные `<id>.lock.release-*`, `<id>.lock.stale-*` и остатки quarantine не занимают
места в K; они могут быть убраны отдельно по возрасту. Заведомо защищённый current helper-а
не обходится для подсчёта размера: его запись имеет `bytes: null`.

Сохраняются каталоги с живым либо неизвестным владельцем sibling/ancestor lock, вложенного
`*.lock`, `*.install-lock`, `*.select-lock`, `*.cutover-lock`, `lock`, записи
`.locks/<packageId>` или каталога с `owner.json`. Siblings/ancestors проверяются для
четырёх общих суффиксов `DIRECTORY_LOCK_SUFFIXES`.
Смерть устанавливается по PID и времени старта,
не по возрасту lock. Dry-run не освобождает даже мёртвые lock-и. После предварительного
обхода настоящая уборка берёт sibling-барьер `<root>.cleanup.lock`, затем directory lock
кандидата без ожидания. Общий `acquireDirectoryLock` проверяет барьеры физических предков
до и после публикации владельца: новый ancestor/nested/package lock не выдаётся до конца
уборки. Уже выданные lock-и проверяются как прежде; собственный барьер обходится только
по точному token. Конкурирующая уборка пропускает кандидатов с причиной занятости.
Мёртвый барьер восстанавливается по PID/starttime; неизвестный сохраняется.
Под барьером повторяются проверки inode, возраста, поколений и занятости, затем
освобождаются только собственные lock-и. Ссылки не обходятся; файл или
ссылка вместо кандидата пропускается. Сам корень не удаляется.

Перед удалением корень и структурные предки открываются с `O_DIRECTORY|O_NOFOLLOW`.
Этот fd открывается до захвата candidate lock и закрывается после его release: создание
owner, удаление lock и самого дерева закреплены за одним физическим родителем.
Операции выполняются через `/proc/self/fd/<parentFd>/<name>`, поэтому последующая подмена
`gates` или другого предка ссылкой не перенаправляет удаление наружу. Кандидат атомарно
переименовывается в `<name>.cleanup-<random>` рядом с собой; inode проверяется уже после
переноса. Чужая замена не удаляется. При ошибке остатки возвращаются под прежним именем,
если оно свободно. После аварии quarantine остаётся в том же семействе и подлежит
следующему возрастному прогону; сам по себе он не считается активным lock.

При активной либо неизвестной сборке в теме поколения сохраняются целиком. Состояние темы
сканируется один раз под барьером. `generations/<id>.lock` удерживается builder до конца
упаковки payload и чтения journal contract, включая повторное использование старого
поколения. Поэтому обычная сборка без candidate lock также защищает используемое дерево.
`prepare:runtime` готовит архив Node и dependencies, а не поколения; эти каталоги защищены
от удаления независимо от возраста.

## Отчёт и ошибки

Текстовый отчёт переведён на ru/en. `--json` выдаёт один документ format 1 без терминальной
рамки: `root`, `dryRun`, `olderThanMs`, `keepGenerations`, `entries`, `wouldDeleteBytes`,
`freedBytes`, `errorCount`, `interrupted`. В каждой записи относительный `path`, `bytes` (либо `null`, если
размер не прочитан), `status` и `reason`. Статусы: `would-delete`, `deleted`, `skipped`, `error`.
Причины: `young`, `locked`, `lock-unknown`, `protected-cache`, `keep-latest`, `current`,
`symlink`, `not-directory`, `disappeared`, `io-error`; успешное удаление имеет `reason: null`.

`freedBytes` суммирует размер обычных файлов только полностью удалённых деревьев, а не
точное изменение `df`: открытые файлы и hardlinks могут задержать освобождение блоков.
Ошибка одного дерева не отменяет обработку остальных; код 1 и `errorCount` сообщают отказ.
Частично удалённое дерево не засчитывается полностью. После устранения причины команду
можно повторить: уже отсутствующие данные повторно не учитываются. Удаление необратимо,
общей транзакции и восстановления без резервной копии нет.

SIGINT/Ctrl+C и SIGTERM кооперативно останавливают обход между файловыми операциями,
включая предварительный просмотр в меню. Уже начатое удаление одного каталога завершается,
следующие не начинаются; собственные lock-и освобождаются. Возвращаются накопленный отчёт
с `interrupted: true` и код 130/143. JSON остаётся одним документом; байты учитывают только
полностью удалённые деревья. EOF во время просмотра меню завершает его с кодом 0 без удаления.

Сервер не запускает уборку по таймеру. Автоматическая
[retention тестового helper](../testing/source-runtime-dependencies.md) ограничена своей темой.
Уборка не анализирует ссылки из переписки: удалённые картинки старых ответов станут
недоступны, см. [руководство по данным](../guide/data-and-backups.md).
