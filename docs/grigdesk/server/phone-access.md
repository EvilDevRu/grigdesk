# Доступ телефону к выбранному серверу

Новый Android-клиент получает отдельный конверт `GRIGDESK:PHONE:2:`: UTF-8 JSON в
каноническом base64url без padding. Он содержит имя и pin сервера, до восьми прямых
IPv4/DNS-адресов, один настроенный совместимый ретранслятор и один client-код на десять
минут. Нужен хотя бы один путь. Старый `GRIGDESK:PAIR:1:` сохраняет прежний смысл.

`GET /api/devices/access` возвращает способы связи именно обслуживающего сервера и
`source: saved | env | off`. Сохранённая настройка версии 1 в приватном `phone-access.json`
рядом с реестром устройств имеет приоритет над окружением. Чтение не создаёт файл;
повреждение не превращается в пустую настройку или открытый вход.

`PUT /api/devices/access/direct` явно включает вход на конкретных IPv4 действующих
интерфейсов. Владелец сериализует весь переход: новые bind, durable-запись, публикацию
runtime и закрытие исключённых входов. Ошибка bind или записи закрывает только staged
входы; прежний доступ и основной HTTP остаются доступны. Linux не даёт занять `ip:порт`,
пока тот же порт держит wildcard-вход: при сужении «все сети → одна» владелец освобождает
ненужный wildcard перед bind и восстанавливает его при отказе bind или записи. Основной HTTP по-прежнему
слушает loopback. Порты, firewall, роутер и внешняя публикация автоматически не настраиваются.

Кандидаты адресов берутся у сервера. Loopback, wildcard, localhost и multicast в телефонный
конверт не входят. Wildcard разворачивается в интерфейсы; несколько сетей требуют выбора.
`GRIGDESK_CLIENT_ADDRESS` описывает только вход из окружения: при сохранённой настройке
кандидаты берутся из неё.
DNS без подходящего IPv4 не публикуется. Выдача QR не проверяет достижимость с телефона.

`POST /api/devices/phone-pairing` выпускает QR без обязательной формы имени/адреса.
По умолчанию устройство называется «Телефон». Ретранслятор берётся только из собственного
реестра и согласованной capability. Произвольные токены и host из тела запроса не принимаются.
При превышении вместимости QR ответ `qr_too_large` предлагает сократить адреса.

`GET /api/devices/phone-pairing/:attemptId` показывает pending, connected или expired.
Pair оставляет pending; успех подтверждает authenticated hello именно устройства,
связанного с кодом. Cookie, чужой сертификат и выпуск QR успеха не подтверждают.
Корреляция живёт в той же ограниченной TTL-записи, что код.

Управление, переименование `PATCH /api/devices/:id` и отзыв наследуют session-only guard
и `Cache-Control: no-store`. Публичные списки и progress не содержат кодов, device pin
или токенов. Отзыв сначала сохраняется, затем закрывает прямые и private TLS-сокеты.

Для relay используется отдельный private client TLS на случайном loopback-порту,
с той же личностью, bootstrap и scope. Он работает при выключенном direct и не выдаётся
как прямой адрес. Лимиты 256 TCP, 24 на сертификат, 16 bootstrap и 16 незавершённых
handshake на IP общие для direct, staged и private групп; прежние сроки сохраняются.

Один v1 control согласует capability `client-v2`. Только новые device/data с
`v:2,target:client` направляются в private client TLS. Прежние v1-пары сохраняют ограниченный
мобильный API и не вытесняются вторым control. Несовпадающий target не расходует pending id.

Токен устройства общий для ретранслятора. Отзыв телефона действует на сервере: внешний
слой ещё может принять token, но внутренний TLS отказывает до API. Для смены общего
токена нужно пересоздать ретранслятор. Server→public relay guard сохраняется; он не
требует VPN на телефоне.
