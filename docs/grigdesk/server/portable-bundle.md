# Переносимая папка GrigDesk

`grigdesk-ctl bundle` из исходников заново собирает Linux x64 комплект в `release/`,
архив `release.tar.gz` и внешние суммы `release.tar.gz.sha256`. DeepSeek пересобирается
из закреплённого upstream-снимка вместе с сервером, b24, посредником и AppImage.
Номер версии берётся из `VERSION`; до выпуска он остаётся `0.1.0`.
`bundle --help` работает без Node и сборки, лишние аргументы дают код 2.
Вне исходников команда сборки отказывает. `build` и `release` сохраняют свои прежние роли.

## Состав и сборка

В корне находятся `GrigDesk`, `README.md` и служебный каталог `bin/`:

- `grigdesk-server`, `b24`, `grigdesk-relay`, `deepseek`, `grigdesk-ctl`;
- `lib/runtime-env.sh` для автономного ctl;
- `bundle.json`: format 1, kind portable, версия, commit, dirty и список файлов
  с относительным path, size, mode и SHA256.

Опись не включает саму себя. Внешний checksum содержит SHA256 архива и
`release/bin/bundle.json`; из родительского каталога его проверяют командой
`sha256sum -c release.tar.gz.sha256`. Затем хеши файлов сверяют с описью.
Архив имеет корень `release/` и сохраняет права: программы 0755, тексты 0644,
каталоги 0755. Перед публикацией архив распаковывается, байты и права сверяются.

Сборщик использует build-only входы с отдельными out/cache. AppImage включает свежий UI;
готовые установленные бинарники входами не являются. HOME, D, XDG и временные каталоги
принадлежат сборке, личные token/loader/VITE overrides не передаются. DeepSeek проходит
полный verify и проверку host/GLM compatibility текущего сервера.

Payload копируется по закрытому списку. В него не включаются папка данных, чаты, `.env`,
ключи, токены, фабричные профили, пользовательские плагины и квитанции установщиков.
Установленные `bin/`, descriptor окна и работающий сервер сборкой не меняются.

Собственный owner-lock и sibling staging сериализуют сборку. HEAD/dirty снимаются до её
выходов, включая новые неигнорируемые исходники. Старые папка, архив и checksum заменяются
только после всех проверок; отказ публикации возвращает прежние выходы. При отказе
восстановления резерв сохраняется с указанием пути в ошибке. Атомарность трёх имён
при SIGKILL не гарантируется. Чужие staging и locks не очищаются.

## Запуск и выбор сервера

Нужны Linux x64 с glibc 2.28+, libfuse2 для AppImage (libfuse2t64 на новых Ubuntu),
свои CLI исполнителей и авторизация. Системный Node не нужен; для ctl нужны Bash и Python3.
Прочие зависимости возможностей перечислены в [требованиях хоста](sea-host-requirements.md).
Окно не устанавливает пакеты и не просит sudo. Обход отсутствующего FUSE не предусмотрен.

Закройте прежнее окно и откройте `GrigDesk`: действующий singleton второй копии только
фокусирует прежнее окно. На пустом профиле сервер находится по marker рядом с физическим
APPIMAGE; без APPIMAGE у packaged-окна используется физический execPath. Source Electron
соседей не ищет. Временные mount/APPDIR и HOME/PATH не являются корнями discovery.

Адрес и доступность local вычисляются без тяжёлой проверки и записи descriptor.
Документ открывается сразу, подготовка сервера идёт в фоне с видимым статусом.
Первый выбор публикует descriptor v4 общей транзакцией lock/CAS/recovery, без фиктивного
runtime-version. Предыдущий primary может отсутствовать; лишний previous не создаётся.
Отмена или смена профиля до commit запрещает поздний выбор и запуск.
Только supervisor владеет start, preparation ACK и остановкой своего процесса.

Исправный сохранённый выбор приоритетен, в том числе remote и явный URL запуска.
Другой соседний сервер появляется отдельной строкой машин без автоматического verify.
Выбор ELF, R или source, сделанный через ctl вне окна, также сохраняется: при фоновом
запуске источником выбора остаётся `runtime.json`, а не привязка профиля к прежнему ELF.
Автоматическая запись descriptor допускается только при его отсутствии либо доказанном
исчезновении серверного входа с доступным соседом. Иное расхождение не вызывает verify
прежней привязки, запись выбора или остановку чужого сервера.
При ENOENT/ENOTDIR именно серверного входа сосед может заменить пропавший путь,
сохранив D, CLI paths, id и порт трубы. О переносе сообщается после показа окна.
Сообщение не задерживает подключение: подготовка завершается после запуска сервера,
а закрытие диалога и ошибка его показа на неё не влияют. Сообщение остаётся одно на запуск.
Повреждённый JSON, EACCES, отсутствие Node и ошибка проверки не разрешают fallback.

Привязка local к ELF хранится в приватном `serverBinary` настроек Electron; публичный
shell API её не отдаёт и PATCH её не принимает. Разные ELF имеют разные стабильные
порты труб. Прежний local сохраняет идентичность до перехода и допускает возврат.
Явный URL запуска и добавление «Этот компьютер» обновляют основной local с прежними id
и портом, даже если он уже привязан к ELF. Отдельный portable-профиль при этом не меняется.
При ручной активации ELF проверяется до остановки своего supervisor; внешний владелец D
даёт отказ. Production-адаптер передаёт `ownsServer` из текущего supervisor, чтобы
координатор отличал свой процесс от внешнего. После stop создаётся новый контроллер.

Перед сменой локальной установки завершите ходы в чатах: штатный слив собственного
сервера может прервать незавершённые ходы и временно отключить телефон. Чужой процесс
сигналов не получает. Переход к удалённой машине не останавливает местный сервер.

Автономный `bin/grigdesk-ctl` использует Node/helpers серверного payload.
Без аргументов в человеческом терминале он показывает [меню команд](cli-terminal-menu.md),
скрывая сборку и разработку. Вне терминала выводится справка без открытия окна.
`open` находит корневой `GrigDesk`, не навязывает URL и не запускает systemd даже
без descriptor. `desktop use-server <ELF>` использует тот же portable-selector;
установка окна без исходников недоступна.

## Меню, перенос и удаление

После показа окна native-вопрос один раз предлагает добавить GrigDesk в меню приложений.
Согласие и отказ сохраняются отдельным private marker в userData, вне settings.json.
Согласие создаёт только пользовательский `grigdesk-portable.desktop` в абсолютном
XDG_DATA_HOME/applications либо `~/.local/share/applications`. Чужой файл не заменяется,
ошибка видна и не мешает серверу. Exec указывает на физический AppImage, с экранированием
desktop entry, без shell и установки служб.

Переносите папку после закрытия окна и остановки собственного сервера. Прямой запуск
восстановит исчезнувший путь. Одноразовый ярлык хранит старый абсолютный Exec: после
переноса поправьте путь в своём ярлыке или запускайте файл напрямую. Повторного вопроса
не будет; удалять весь userData, личность и настройки окна ради ярлыка не нужно.

Для удаления закройте окно, дождитесь слива, удалите переданную папку, архив/checksum и
свой portable-ярлык. Общие данные и профиль окна сохраняются; прежняя установка остаётся.

## Проверки

Состав, свежие выходы, приватность, настоящий tar и откат проверяют
`tests/server/{ctl-bundle,portable-bundle}.test.js`. Первичный выбор, перенос, отмену,
список машин и меню проверяют `tests/desktop/{binary-selection,portable-runtime,
portable-integration,profiles,shell-api,server-supervisor}.test.js`.

После публикации настоящий комплект передают через GRIGDESK_TEST_BUNDLE_DIR тесту
`tests/server/portable-bundle-acceptance.test.mts`: изоляция HOME/checkout/host Node,
реальный ELF, API, ручной выбор и перенос. Без пакета эта проверка не считается пройденной.
Открытие AppImage, меню, FUSE и работу на другой машине проверяет человек.
