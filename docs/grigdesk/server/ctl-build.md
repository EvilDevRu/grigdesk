# Сборка и установка из исходников

В папке исходников `grigdesk-ctl build` собирает и ставит сервер, веб и окно по порядку.
Команда использует Node разработчика из PATH, в том числе когда рядом уже установлен
`bin/grigdesk-server`. Исходники распознаются по одновременному наличию `server/src/app.ts`,
`web/package.json` и `desktop/package.json`. Готовая поставка с `release.json` сохраняет
приоритет; в ней и в установке ELF без исходников команды разработки дают прежний отказ.

```sh
grigdesk-ctl build
grigdesk-ctl build all
grigdesk-ctl build server
grigdesk-ctl build web
grigdesk-ctl build window
```

Без цели выбирается `all`: сервер → веб → окно. `server` вызывает `build:binary` и
`install:binary`; `web` сохраняет подготовку зависимостей и `npm run build` в web;
`window` сначала готовит и собирает веб, затем выполняет `npm --prefix desktop run dist`
и `deploy/desktop.sh install`. В `all` веб собирается один раз до упаковки окна.
Неизвестная цель или лишний аргумент дают код 2 и подсказку до любых эффектов.
`--help` и `-h` в любом месте печатают общую справку без сборки и установки.

## Сервер и кэш

Сборка использует `${XDG_CACHE_HOME:-$HOME/.cache}/grigdesk/server-binary/out`,
кэш — соседний `cache`. `server/scripts/ctlBuild.mts` подготавливает архив Node штатным
`ensureNodeArchive`: версия и SHA256 читаются из `server/build/node-runtime.json`.
Проверенный локальный архив используется без сети; отсутствующий или испорченный
загружается с проверкой SHA, не более трёх попыток с паузой 30 секунд.
Далее действуют штатные [ворота сборщика серверного ELF](server-binary.md#сборка-и-приёмка).
Входы helpers теперь имеют постоянные имена и не включают случайный путь staging:
[исправление детерминированности](sea-helper-staging-comments.md).
Прежний комплект в кэше для обычной сборки не требуется: без baseline E0 выполняет
все функциональные проверки и cold-порог, а в E0/build-result явно пишет
«warm ratio не измерялся: нет baseline». При существующем baseline остаются прежние
пороги warm median/p95 — [контракт сравнения](server-binary-smoke-baseline.md).

Установщик получает `<корень>/bin/grigdesk-server` и releases в
`<папка данных>/runtimes/server/releases`. Папка данных вычисляется через
`grigdesk_data_home`: `GRIGDESK_HOME`, иначе `$HOME/.grigdesk`; сборка не читает `.env`.
[Установщик](server-binary-install.md) проверяет кандидата и атомарно заменяет ELF,
сохраняя резерв прежнего файла.

После установки только читается descriptor окна по общему пути XDG. Для корректного
v4 на этот ELF выбор уже сохранён; при ином descriptor печатается подсказка
`grigdesk-ctl desktop use-server <ELF>`. Команда выбора автоматически не выполняется.
[Descriptor v4](server-binary-desktop.md) хранит путь ELF и при следующем запуске окна
получает новый packageId, поэтому повторный выбор того же пути после обновления не нужен.

## Результат и отказы

В человеческом терминале ручной `build` и варианты из меню показывают
[экран прогресса](cli-terminal-menu.md): стадии, оценку времени, последнюю строку и путь
полного журнала в папке данных. Явный build выходит сам; успешный результат из меню ждёт
Enter/Esc. Вне терминала и внутри cgroup серверной службы остаётся прежний поток строк.
Наблюдение включается внутренним маркером и fd 3, не меняя сборочные команды.

После успеха печатаются установленные компоненты. Для `all`, `server` и `window`:
«Закройте окно и откройте снова — запустится новый код».
После одного `web`: «Окно покажет новый веб после grigdesk-ctl build window».
Веб вшивается в пакет окна при его сборке, поэтому одного открытия прежнего окна недостаточно.
Открытое окно и работающий сервер продолжают работу; команда не посылает им сигналов,
не обращается к systemctl и не перезапускает компоненты. Установка окна сохраняет
выбранный descriptor v3/v4.

Первая обязательная ошибка останавливает цепочку с её ненулевым кодом и строкой
`не удалось: server`, `не удалось: web` либо `не удалось: window`.
Установщики сохраняют прежние файлы при отказе своей стадии; уже успешные стадии
всей цепочки автоматически не откатываются. Отказ optional подготовки DeepSeek
сохраняет прежнее предупреждение и не прерывает веб.

Проверки: `tests/server/ctl-build.test.js`, `ctl-build-runtime.test.js`,
`tests/cli/entry.test.mts` через сторож памяти. Они используют временные HOME/XDG/D,
заглушки npm/установщиков и отдельный тестовый ELF; настоящие окно и служба проверяются вручную.
