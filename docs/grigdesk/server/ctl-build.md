# Сборка и установка из исходников

В папке исходников `grigdesk-ctl build` собирает и ставит сервер, веб, окно и задачи Б24
(`bin/tracker`). Команда использует Node разработчика из PATH, в том числе когда рядом уже
установлен `bin/grigdesk-server`. Исходники распознаются по одновременному наличию
`server/src/app.ts`, `web/package.json` и `desktop/package.json`. Готовая поставка
с `release.json` сохраняет приоритет; в ней и в установке ELF без исходников команды
разработки дают прежний отказ.

```sh
grigdesk-ctl build
grigdesk-ctl build all
grigdesk-ctl build server
grigdesk-ctl build web
grigdesk-ctl build window
grigdesk-ctl build deepseek
grigdesk-ctl build apk
```

Без цели выбирается `all` — «Всё (server, desktop, tasks)». Сначала общей фазой готовятся
зависимости (`ensure_deps`: сверка серверных пакетов через `npm install`, веб при отсутствии
`node_modules`, проба DeepSeek),
затем три цепочки собираются **параллельно**: сервер (`prepare-runtime`, `build:binary`,
`install:binary`), окно (`npm run build` в web и `npm --prefix desktop run dist`) и задачи
Б24 (`npm --prefix tracker run build`). Установка окна идёт строго после всех цепочек:
`deploy/desktop.sh install` проверяет метаданные и совместимость `bin/grigdesk-server`
([декодер runtime-env](runtime-env-version-sync.md)), поэтому не может конкурировать
с `install:binary`. Отдельные цели остаются последовательными: `server` вызывает
`npm install --no-audit --no-fund` в сервере, затем `build:binary` и `install:binary`;
`web` сохраняет подготовку зависимостей и
`npm run build` в web; `window` сначала готовит и собирает веб, затем выполняет
`npm --prefix desktop run dist` и `deploy/desktop.sh install`.
`apk` — отдельная цель [сборки Android-приложения](ctl-build-apk.md) через `tools/mobile build`.
Она включает общий интерфейс внутрь APK и не входит в `all`.
`deepseek` — отдельная цель, не входящая в `all`: она не собирает веб и окно и не меняет
привязку сервера окна. Стадии: зависимости (ставятся только при отсутствии
`deepseek/node_modules`), подготовка среды (`prepare:runtime` с общим кэшем), сборка,
`verify`, проверка допуска GLM, установка штатным `install:binary` с host-контрактом,
releases папки данных и `--glm-mode` фактического режима потребителя, затем чистка.
Кэш и кандидат — `${XDG_CACHE_HOME:-$HOME/.cache}/grigdesk/deepseek-binary/{cache,out}`.

Задачи Б24 собираются внутри `all` своим сборщиком tracker: зависимости ставятся только при
отсутствии `tracker/node_modules`, затем `npm --prefix tracker run build` публикует ELF
атомарной заменой прямо в `bin/tracker` (тот же закреплённый Node, что и у релизного
комплекта). Кэш — `${XDG_CACHE_HOME:-$HOME/.cache}/grigdesk/tracker-binary/cache`.
Отдельной цели `tasks` нет: свежий ELF для команды `grigdesk-ctl tracker` даёт `all`.

Перед запуском в терминале preflight считает identity входов дерева без сборки и
проверяет допуск режима потребителя. Если он покрыт, сборка идёт без вопроса. Если
допуска нет, вопрос называет режим и по Enter выбирает его живой smoke; доступны также
«Оба режима» и «Отложить — установка не будет выполнена». Ошибка или таймаут preflight
возвращают прежний вопрос с пропуском по умолчанию. Выбор передаётся окружением
`GRIGDESK_DEEPSEEK_SMOKE=none|consumer|both`; семантика переменной прежняя, без терминала
по умолчанию — `none`. Smoke запускается
только для режимов, чей допуск не совпал со входами кандидата (`admission:check`):
пройденная проверка дописывает допуск в `compatibility/glm.json` (`--admit`), metadata
кандидата пересобирается и снова проходит `verify`. Живой smoke требует ключ и баланс
соответствующего маршрута Z.ai; его отказ — ненулевой код сборки, отчёт лежит в
артефактах `glm/G12`. Без нужного допуска и без smoke сборка завершается зелёным
итогом и путём кандидата в журнале. Событие наблюдателя `hint deepseek-deferred <mode>`
заменяет строку «Поставлен DeepSeek» заметным предупреждением «Установка не выполнена:
нет живого допуска GLM (режим)» и подсказкой о повторной сборке. Код остаётся 0;
отказ самой установки — код отказавшей стадии. Успех не требует
перезапуска: следующий ход DeepSeek получает новый ELF
([обновление поставки](../chat/deepseek-auto-runtime-update.md)).
После успешной установки цель подчищает за собой: кандидат в кэше удаляется, а стадия
`prune:cache` оставляет в папке кэша поставки только две свежие группы поколений по
buildId (новая и предыдущая — для идущих ходов) и два свежих резервных ELF для отката.
Нечитаемое поколение чистка не трогает; отказ чистки — предупреждение, не отменяющее
установку.
Неизвестная цель или лишний аргумент дают код 2 и подсказку до любых эффектов.
`--help` и `-h` в любом месте печатают общую справку без сборки и установки.

## Сервер и кэш

Существующий `server/node_modules` не отменяет подготовку: после изменения lock в нём
могут отсутствовать новые пакеты. `npm install --no-audit --no-fund` согласует дерево
с зависимостями перед офлайн-копированием production npm. В `all` это происходит один
раз до параллельных цепочек; отдельный `server` выполняет ту же подготовку без веба.
Отказ npm останавливает сборку до подготовки Node, упаковки и установки ELF.

Сборка использует `${XDG_CACHE_HOME:-$HOME/.cache}/grigdesk/server-binary/out`,
кэш — соседний `cache`. `server/scripts/ctlBuild.mts` подготавливает архив Node штатным
`ensureNodeArchive`: версия и SHA256 читаются из `server/build/node-runtime.json`.
Проверенный локальный архив используется без сети; отсутствующий или испорченный
загружается с проверкой SHA, не более трёх попыток с паузой 30 секунд.
Далее действуют штатные [ворота сборщика серверного ELF](server-binary.md#сборка-и-приёмка).
Входы helpers теперь имеют постоянные имена и не включают случайный путь staging:
[исправление детерминированности](sea-helper-staging-comments.md).
Прежний комплект в кэше для обычной сборки не требуется: без baseline E0 выполняет
все функциональные проверки и cold-порог, а в E0/build-result явно пишет
«warm ratio не измерялся: нет baseline». При существующем baseline остаются прежние
пороги warm median/p95 — [контракт сравнения](server-binary-smoke-baseline.md).

Установщик получает `<корень>/bin/grigdesk-server` и releases в
`<папка данных>/runtimes/server/releases`. Папка данных вычисляется через
`grigdesk_data_home`: `GRIGDESK_HOME`, иначе `$HOME/.grigdesk`. Из `.env` читается только
`GRIGDESK_GLM_API_MODE` для проверки пары; экспортированное значение имеет приоритет.
Другие настройки и ключи сборка из файла не загружает:
[единый режим проверки](server-install-glm-mode.md).
[Установщик](server-binary-install.md) проверяет кандидата и атомарно заменяет ELF,
сохраняя резерв прежнего файла.

Перед заменой серверный установщик проверяет совместимость кандидата с установленными
DeepSeek/GLM. Несовместимая пара останавливает стадию `server.install`, сохраняя старый
сервер. Уже установленный optional исполнитель не пропускается как предупреждение:
[проверка пары](server-executor-install-guard.md). Нестандартный путь можно передать
через `GRIGDESK_DEEPSEEK_BIN`; новая сборка исполнителя не получает допуск GLM автоматически.

Для отдельной цели `server` после установки только читается descriptor окна по общему
пути XDG. Для корректного v4 на этот ELF выбор уже сохранён; при ином descriptor
печатается подсказка `grigdesk-ctl desktop use-server <ELF>`.
Полная сборка после успешной установки окна сохраняет
[привязку для следующего запуска](build-server-selection.md), если прежний сервер
принадлежит этой копии или её `release/` и использует ту же папку данных.
[Descriptor v4](server-binary-desktop.md) хранит путь ELF и при следующем запуске окна
получает новый packageId, поэтому повторный выбор того же пути после обновления не нужен.

## Результат и отказы

В человеческом терминале ручной `build` и варианты из меню показывают
[экран прогресса](cli-terminal-menu.md): стадии, оценку времени, последнюю строку и путь
полного журнала в папке данных. После успеха явный build и сборка из меню предлагают
[открыть окно или отказаться](cli-build-interaction.md); по умолчанию выбран отказ.
Вне терминала и внутри cgroup серверной службы остаётся прежний поток строк без вопроса.
Наблюдение включается внутренним маркером и fd 3, не меняя сборочные команды.

После успеха печатаются установленные компоненты. При согласованном выборе сервера:
«Закройте окно и откройте снова — запустится новый код».
При сохранённом выборе другой установки явно говорится, что новый сервер ещё не выбран,
и остаётся подсказка `use-server`; обещание запуска нового сервера не печатается.
После одного `web`: «Окно покажет новый веб после grigdesk-ctl build window».
Веб вшивается в пакет окна при его сборке, поэтому одного открытия прежнего окна недостаточно.
Открытое окно и работающий сервер продолжают работу; команда не посылает им сигналов,
не обращается к systemctl и не перезапускает компоненты. Обычная установка окна сохраняет
выбранный descriptor v3/v4; полная сборка сохраняет корректный descriptor любой версии
до применения отложенной привязки новым окном.

В отдельной цели первая обязательная ошибка останавливает цепочку с её ненулевым кодом
и строкой `не удалось: server`, `не удалось: web`, `не удалось: window`,
`не удалось: deepseek` либо `не удалось: apk`. В параллельном `all` отказ останавливает
только свою цепочку: остальные доходят до конца, установка окна и отложенная привязка
не выполняются, итоговый код и причина — первой отказавшей цепочки в порядке
сервер → окно → tasks (`не удалось: tasks`). Вывод параллельных цепочек чередуется
в общем журнале; экран прогресса показывает каждую стадию отдельно.
Установщики сохраняют прежние файлы при отказе своей стадии; уже успешные стадии
всей цепочки автоматически не откатываются. Отказ optional подготовки DeepSeek
сохраняет прежнее предупреждение и не прерывает веб.

Проверки: `tests/server/ctl-build.test.js`, `ctl-build-runtime.test.js`,
`tests/server/deepseek-prune-cache.test.js`,
`tests/cli/entry.test.mts`, `tests/cli/build-session.test.mts` через сторож памяти. Они используют
временные HOME/XDG/D, заглушки npm/установщиков и отдельный тестовый ELF; настоящие окно
и служба проверяются вручную.
