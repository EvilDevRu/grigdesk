# Минимум системы для собранных файлов и окна

Собранные `grigdesk-server`, `b24`, `grigdesk-relay` и `deepseek` динамически связаны
с glibc. По таблице символов (`objdump -T`) старшая требуемая версия — `GLIBC_2.28`,
для libstdc++ — `GLIBCXX_3.4.21`. Значит, на системе со старшей glibc ниже 2.28 они
не загрузятся; это нижняя граница, а не проверенный запуск на такой системе.

Окно `grigdesk-app` собрано как AppImage. Его runtime не связан с libfuse статически,
а загружает `libfuse.so.2` через `dlopen` при старте. Без этой библиотеки AppImage
падает до запуска Electron, и при двойном щелчке человек не видит никакого сообщения.
На Ubuntu 22.04 и новее `libfuse2` (на 24.04 — `libfuse2t64`) по умолчанию не стоит.
Обход без установки пакета — флаг `--appimage-extract-and-run`: runtime распаковывает
образ во временный каталог и запускает его без FUSE.

Это поведение прежнего runtime: electron-builder 26.15.3 по умолчанию берёт набор
`toolsets.appimage: "0.0.0"` (legacy fuse2). Бета-наборы `1.0.2` и `1.0.3` ставят runtime
type2 от 20251108. Он ищет в PATH setuid-root `fusermount` или `fusermount3` и `libfuse.so.2`
не требует, но сам на распаковку при отказе FUSE не переходит: печатает «Cannot mount
AppImage» и завершается. Для небазовых наборов electron-builder также перестаёт по умолчанию
добавлять `--no-sandbox` в desktop entry, поэтому запуск окна с ними проверяется отдельно.

Остальные зависимости возможностей (Python, OpenSSL, ffmpeg, браузер, CLI исполнителей)
перечислены в [зависимостях от хоста](sea-host-requirements.md).
