# Синхронность ожидания версии серверного ELF

Хост-скрипт `deploy/lib/runtime-env.sh` при выборе серверного ELF проверяет его
`--runtime-info --json` строгим декодером: контракт (`format`, `hostContract`,
`packagingVersion`), Node/ABI, capabilities, protocol движка и **product-версию**.
Продуктовая версия — единственное поле, которое меняется каждый релиз.

## Грабля

Релиз `0.1.1` поднял `VERSION`, а литерал `"0.1.0"` в декодере остался. Сборка
«Всё» пересобирает `bin/grigdesk-server` с новой версией, и следующий же шаг
«Окно: установка» падал сообщением «Некорректное описание серверного ELF.» уже
после успешной упаковки AppImage — установка проверяет ELF через этот декодер.
Поэтому в параллельном «Всё» установка окна намеренно идёт после всех цепочек
и никогда не конкурирует с `install:binary` сервера.

## Контракт

- Ожидание объявлено одной переменной шапки: `GRIGDESK_EXPECTED_SERVER_VERSION`.
- Декодер принимает значение аргументом и сравнивает с `version` манифеста ELF;
  литеральной версии внутри python-блока нет.
- Ожидание обязано совпадать с `VERSION` репозитория. Соответствие держит
  `tests/server/runtime-env-version.test.mts`: он читает оба файла и падает при
  рассинхроне, поэтому подъём версии без правки хост-скрипта ловится тестом,
  а не сломанной установкой окна.

## Проверка

- Смоук: `source deploy/lib/runtime-env.sh && grigdesk_select_server_binary <root>`
  на собранном ELF возвращает packageId без ошибки.
- Тест: `bash tests/run-node-tests-safe.sh --test tests/server/runtime-env-version.test.mts`.
