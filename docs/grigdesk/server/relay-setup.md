# Серверное задание настройки ретранслятора

`MobileService` владеет `RelayDeploymentService`; административные действия находятся
в `/api/mobile/deployments`. Все чтения и мутации требуют сессию человека и возвращают
`Cache-Control: no-store`. CLI/internal bearer не дают права запускать мастер.
Выбранный домашний сервер закрепляется `expectedServerFp` до первого SSH-подключения.
Обе оболочки получают этот отпечаток из `server.fp` ответа `GET /api/mobile/status`:
это pin домашнего сертификата, загруженного `ensureBrainIdentity`, а не SSH-ключ VPS.
До загрузки личности поле равно `null`; чтение статуса не создаёт и не меняет ключи.

## Журнал и запросы

`GET /api/mobile/deployments` возвращает `{jobs: [...]}`, включая `{jobs: []}` для пустого
списка. Query `requestId` отбирает повтор запроса в той же оболочке; неизвестный requestId
возвращает `{jobs: []}`. Этот формат одинаков для ctl и desktop.
`GET /api/mobile/deployments/:id` восстанавливает полный снимок. Создание принимает только
публичные параметры SSH/public/candidateHost, режим setup/restore и идентификатор запроса.
Одинаковые параметры того же requestId возвращают квитанцию; изменение параметров даёт 409.
Активное задание выбранного relay или публичного endpoint исключает конкурирующее создание.

Журнал `relay-deployments.json` в мобильной папке данных записывается через общий
`writeDurableFile`: fsync содержимого, rename, fsync каталога. Он содержит безопасный
снимок, шаги и квитанции действий, без SSH-пароля, приватного ключа и passphrase.
Повреждение этого журнала закрывает мастер, сохраняя прежний мобильный/direct-вход.

## SSH и подтверждение

`POST /:id/probe` получает host key без учётных данных. `/:id/host-key` принимает явное
trust/replace либо reject по одноразовому challenge текущей revision.
Соединение ssh2 повторно проверяет отпечаток до аутентификации.

`/:id/credentials` принимает binary JSON не больше 64 KiB только по HTTPS либо loopback
без forwarded-заголовков. Password и privateKey/passphrase взаимоисключающие. В журнал
попадает только несекретная квитанция attemptId; тело Buffer очищается после обработки.
Пароль и ключ не передаются локальному процессу, argv, env, SSE или журналу ошибок.

Предпроверка читает ОС, архитектуру, glibc, библиотеки, systemd, права и порт. Файл relay
берётся из проверенного подписанного server archive, digest закрепляется в preview.
До отдельного `/:id/start` системные объекты и файлы VPS не устанавливаются.
Preview ограничен пятью минутами; после истечения нужен повторный ввод доступа.

Передача SFTP считается завершённой после подтверждения записи и закрытия файла.
Преждевременное закрытие или отказ записи прерывают установку. Удалённая проверка
контрольной суммы останавливается на первой ошибке до создания пользователя и службы;
успешный запуск `--version` не подменяет целостность файла.

## Прерывание и сохранение доверия

После принятия start заданием владеет сервер, независимо от закрытия HTTP-клиента.
При старте нового владельца незавершённые стадии становятся interrupted; автоматического
SSH без нового секрета нет. Retry снова требует probe и credentials. Check предназначен
для повторной сетевой проверки после ожидания DNS/VPN.

Новый setup резервирует relay id и выключенную запись до удалённой установки. Restore
использует сохранённые дома сертификат и токены выбранного relay. Маршрут меняется CAS;
конкурирующее значение не затирается. Временная недоступность не удаляет записи и ключи.
Удаление relay с активным заданием возвращает `deployment_busy` (409).

Проверка TLS/control/data и готовность relay не подтверждают телефон: это делает только
аутентифицированный hello устройства. Прежние ручные env/QR, direct и локальный Docker
сохраняют собственные контракты.

Платформа и ограничения: [принятое правило](../mobile/remote-access-platform.md).
Пределы проверки установки, rollback и реального systemd фиксируются отдельно в результатах
приёмки; наличие серверных модулей само по себе их не доказывает.

## Клиенты одного задания

`cli/relaySetup.ts` используется исходной и установленной консолью; короткая cookie
выдаётся общим `cli/serverSession.ts`. Installed использует `.env` из receipt.dataHome,
не source runtimePaths. Desktop читает тот же журнал на существующей странице доступа.
Клиенты не разбирают stdout установщика и не управляют жизнью принятого worker.

Общий телефонный диалог принимает выбранный relay уже при открытии, чтобы не выпускать
промежуточный QR для другого пути. Route-only PATCH Android сохраняет прежний ключ;
обычный add QR продолжает миграцию на key2. [Контракт телефона](../mobile/phone-access.md).

Предпроверка публикует только фиксированные коды: неподдерживаемая платформа, занятый
порт, отказ SSH и общий отказ проверки systemd/прав. Сырые SSH-ошибки не показываются.

Публичный снимок отдельно хранит результат запуска службы и проверку канала. Прерванная
установка не утверждает состояние службы; исторический запуск не заменяет текущую связь
с relay. Клиентский decoder собирает вложенные поля по схеме, не сохраняя неизвестные данные.
