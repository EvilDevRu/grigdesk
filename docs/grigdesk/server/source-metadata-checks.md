# Служебные данные после объединения исходников

Проверка `tests/server/api-version.test.js` считает отпечаток контрактов независимо
от `tools/api-version.mjs`. При изменениях `shared/**/*Contracts.ts` обновляется
`API_CONTRACT_FINGERPRINT` в `shared/client/apiVersion.ts`; до первого выпуска
номер остаётся 0.1. Изменение типов, комментариев или форматирования тоже меняет
отпечаток, поскольку он учитывает текст файлов, а не только исполняемый код.
Полный контракт — [версия API](api-version.md).

`server/src/modules/routes/api.ts` передаёт путь к модулю публикации через
`GRIGDESK_ROUTES_KIT`. Поэтому `ROUTES_KIT` входит в `HOST_ENV_SUFFIXES` общего
`shared/runtime/legacyBrand.ts`. Этот список обслуживает диагностику старого
префикса и не подставляет старые значения в новые переменные. Его полноту
относительно исходников проверяет `tests/server/brand-env.test.mts`.

В том же списке учитываются `APPIMAGE_TOOLS_PATH` проверенного упаковщика окна
и `BRANCH`/`COMMIT` команд переключения ветки стенда. Новый helper с `import.meta.url`
регистрируется также в `server/build/sea-inventory.json`, даже если URL используется
только guard прямого запуска. Это независимые проверки: актуальный отпечаток API
не доказывает полноту переменных или описи упаковки.

Проверка версии source-entry сравнивает ответ с корневым `VERSION`, а не с номером
первоначального выпуска. Подготовка нового номера приложения не меняет `API_VERSION`
автоматически.

Перед первым выпуском снимки пересчитываются по всему объединённому дереву, включая
публичный ключ подписи в `releaseChannelContracts.ts`. Отключённые исходники с суффиксом
`.disabled` не считаются активными потребителями переменных окружения; номер API остаётся 0.1.
