# ACK продлевал long-poll и снимал исправный хост

Живая трасса показала: после отказа screenshot native-команда вернула результат,
heartbeat продолжался раз в пять секунд с успешными ответами. Ожидающий poll
прервался ровно через клиентские 25 секунд; клиент снял native host и начал
перерегистрацию. Последующие команды прежних вкладок получили отказ доступа.

Причина воспроизведена в `BR13-poll-deadline`. `browserBroker.poll()` заново ставил
таймер на 20 секунд после каждого пробуждения очереди. Завершение уже выданной
команды тоже будит очередь. ACK через шесть секунд продлевал общий poll до 26
секунд, хотя HTTP-клиент прекращает его через 25. Теперь один абсолютный deadline
задаётся при входе в poll; пробуждения используют только остаток бюджета.
Проверка сохраняет живые heartbeat и неизменное поколение хоста.

Отдельно очистка host получала HTTP 400: клиент посылал `Content-Type:
application/json` у DELETE без тела. Fastify отклонял запрос кодом
`FST_ERR_CTP_EMPTY_JSON_BODY` до обработчика. Прежний серверный lease оставался жив,
поэтому немедленная новая регистрация получала 409. HTTP-адаптер теперь задаёт
JSON content type только при наличии тела. Интеграционный `API-host-delete`
проверяет настоящий адаптер клиента с Fastify, снятие host и новую регистрацию.

После ручной загрузки исправления повторён прежний живой триггер: скрытый screenshot
исчерпал пять секунд, затем прошло больше минуты до следующих действий. Snapshot,
list и последующая серия команд сохранили grants. В журнале за этот интервал нет
DELETE или повторной регистрации; максимальный промежуток heartbeat — около пяти
секунд. Это проверка устойчивости host при отказе захвата, а не успех самого JPEG.

Границы authority не меняются: истечение lease, явный revoke и смена host по-прежнему
отзывают grants. Автоматического восстановления прав нет. Это доказанная причина
конкретного свежего отказа; исторические отказы без такой последовательности и
[длительные паузы UI](browser-host-ui-stall.md) требуют отдельного сопоставления.
