# Библиотека агентов

Раздел `/agents` использует `layout: workspace` и `data-ui-workspace`. Каталог 240 px
примыкает к каркасу; редактор занимает остальную ширину. Обе шапки — общий
[UiPaneHeader](pane-header.md), 36/52 px до переноса строк. Поля и действия формы
имеют высоту 32/44 px, действия шапки — 28/44 px. Палитра, шрифт и радиусы берутся
из общих токенов GrigDesk.

Каталог ищет по названию и ID без учёта регистра. Роли сгруппированы по типам:
«Агент ИИ», «Решение человека», «Команда проекта»; неизвестный тип из файла
остаётся отдельной группой. В строке видны название, ID и рекомендации класса/усилия.
Установка стандартного набора закреплена внизу каталога и добавляет только отсутствующие
роли; повторная установка не перезаписывает правки.

Редактор начинается с объяснения назначения библиотеки. Первые поля — «Название
агента», «Тип роли» и «Инструкция роли». Затем идут рекомендации класса модели и
глубины рассуждений; у команды и решения человека они скрыты, но значения сохраняются
при обратном переключении типа. ID существующей роли, примечание, ключ запуска, время, бюджет
и флаги находятся в раскрываемых «Технических параметрах». Их открытость сохраняется
под прежним ключом `grigdesk-agents-pro`. Справка через `UiField help` поясняет назначение
полей и примеры. Многострочная инструкция использует общий контекст
`workspace-instruction` в UI-kit: моноширинный текст и минимум 240 px. Числовые поля используют `UiNumberInput`;
площадка каждой подписи checkbox — 32/44 px через `workspace-form` в UI-kit.

Изменения применяются явной кнопкой в закреплённом footer. «Отменить» возвращает
загруженную карточку без сетевой записи; при создании закрывает новую форму.
Переход к другой роли с несохранёнными изменениями и удаление требуют общего диалога.
Ответ записи нормализует форму и локальный список: отказ последующего перечитывания
не возвращает старые значения. Ошибки загрузки видны и при непустом каталоге.
Во время записи, удаления или установки набора конкурирующие действия отключены.

Новая роль требует уникальный ID: 1–41 символ, строчные латинские буквы, цифры,
дефис и подчёркивание; первый символ — буква или цифра. После создания ID доступен
только для чтения. Неизвестные тип, класс и effort показываются как сохранены.
Значения усилия загружаются из реестра исполнителей, без собственного списка в форме.

При ширине рабочей области до 900 px каталог и редактор занимают одну панель.
Первым показывается каталог; кнопки возврата сохраняют локальный ввод и поиск,
поскольку скрытие CSS не размонтирует компоненты. При ширине самого редактора
до 600 px поля переходят в одну колонку, до 480 px отступы формы и footer равны 12 px.

`agents-responsive.test.mts` проверяет настоящий frontend с синтетическим API:
геометрию на 320–1440 px, узкую рабочую область, создание и сохранение всех полей,
отмену и подтверждения, установку набора, справку, длинные и неизвестные значения,
ошибки записи и перечитывания. Это проверка интерфейса; контракт библиотеки и API
описан в [каталоге стадий](../pipeline/agent-stage-catalog.md).
