# Связь главного окна и карточек

В desktop главный документ — единственный владелец `/api/events`, long-poll `/__shell/state?rev`
и периодического dashboard. Роль `main`/`surface` фиксируется из полного UA до первой загрузки.
Браузер и Android имеют роль `page` и сохраняют прежний поток своей вкладки без новых каналов.
Настройка роли SSE выполняется до создания журнала окна и первого подписчика.

Закрытые запросы открытия из разных документов одного origin разделяют Web Lock.
Это оставляет HTTP-соединения для первой загрузки карточки при нескольких быстрых кликах:
POST ожидает native loadURL, поэтому одновременные POST не должны занять весь пул.
Срок каждого запроса начинается после получения блокировки; автоматического повтора нет.

Межоконные сообщения идут через same-origin BroadcastChannel с точной проверкой версии,
набора полей и вида сообщения. Произвольные команды каналы не выполняют:

| Канал | Контракт |
|---|---|
| `grigdesk-sse-v1` | `{version:1,name,data}`; только hello, diagnostic-logging, task-shelf-changed, speech-settings, chat-done, ssh-sessions, ssh-audit, db-sessions, db-queries, db-audit |
| `grigdesk-shell-v1` | `{version:1,type:'shell-changed'}`; карточка делает короткий refresh без rev |
| `grigdesk-board-v1` | board-request или board-snapshot с object data и конечным числом readAt |
| `grigdesk-task-data-v1` | task-data-changed после успешных setFavorite/markSeen; shelf-acknowledge с каноническим taskId |

Главное окно отвечает на запрос доски своим кешем. После собственного завершённого чтения
любой документ делится снимком; чужой снимок не запускает GET dashboard и не отправляется
обратно. Обычный `board.load()` карточки только запрашивает снимок, `load(true)` после её действия
сохраняет одно прежнее чтение портала. Ожидание снимка не занимает loading: таймер может сразу
выполнить своё действие. Более старый readAt отвергается, включая ответ собственного GET,
начатого до свежего снимка. Время завершения запроса не делает его данные новее;
подробнее — [порядок снимков доски](board-snapshot-order.md).

Избранное и просмотренное перечитываются быстрыми локальными API. Сигнал во время старого GET
оставляет один последующий запрос, dispose отменяет отложенный запуск. Полка карточки принимает
полные серверные entries в passive-режиме без построения rows, гидратации деталей и оповещений.
Отметку полки исполняет main с полным наблюдением конвейера и оценки. Основная полка сохраняет
прежние гидратацию и оповещения. Речь карточка сверяет отдельным `chat.syncSpeech()` без ensure
чата при входе и hello, а speech-settings принимает как снимок с прежней защитой от гонок.

Подписки задач и доски ставятся после входа до первого монтирования карточки и её markSeen.
Достигнутый ready не сбрасывается при offline/locked/потере входа: документ и текст сохраняются.
Потеря входа снимает авторизованные связи, новый вход создаёт их заново. Shell-канал живёт через
offline до unmount; старый Promise загрузки плагинов проверяет поколение. Отзыв доступа закрывает
SSE или зеркало; unmount и HMR освобождают принадлежащие им каналы и обработчики.

Проверки: SR, WR, TS, BM, SP, TWP и TWS в целевых тестах окон.

Окна инструментов используют тот же SSE mirror. Их отдельный протокол владения и проекция
Полки описаны в [контракте окон инструментов](tool-windows.md); поток chat-step не пересылается.
