# Alt+Shift+клавиша не доходит до страницы: пару забирает переключатель раскладки

Пара `Alt+Shift` — это системный переключатель раскладки XKB (`grp:alt_shift_toggle`, типовая
настройка машины с `us,ru`). Вторая нажатая клавиша пары отдаётся переключателю: она приезжает
в браузер как `GroupNext` и СВОЙ модификатор не выставляет.

Замер (отдельный Xvfb с `us,ru` + `grp:alt_shift_toggle`, Chrome, настоящие события XTEST):
- Alt→Shift→1 → `Digit1`, `altKey=true`, `shiftKey=FALSE`;
- Shift→Alt→1 → `Digit1`, `shiftKey=true`, `altKey=FALSE`;
- правые Alt/Shift ведут себя так же (`ralt_rshift_toggle`);
- `Ctrl+Shift+1` доезжает целиком.

Значит `Alt+Shift+<клавиша>` на такой машине не «конфликтует с системой», а не существует:
страница не увидит эту пару ни в каком порядке нажатия, и назначить её через запись сочетания
тоже нельзя — в окно записи приедет `Alt+цифра` либо `Shift+цифра`.

Отсюда два следствия в коде: заводские клавиши инструментов — `Ctrl+Shift+цифра`
(`web/src/shared/tools/catalog.ts`), а окно записи отдельно ловит `GroupNext`/`ModeChange`
(`isLayoutSwitch` в `web/src/shared/hotkeys/combo.ts`) и объясняет человеку, что клавишу забрал
переключатель раскладки. Список RESERVED в том же файле этот случай не покрывает: он про
комбинации, которые перехватывает браузер, а здесь клавиша до браузера не доходит вовсе.
