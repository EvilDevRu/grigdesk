# Повторное подключение окна инструмента

Задача 93020. Перезагрузка документа не меняет native instance окна инструмента.
Новый документ отправляет `ready` без эпохи координатора: прежний `init-ack` не означает,
что панель нового документа готова. Главное окно снова отправляет `init` и ждёт подтверждения.
Обычный повтор `ready` уже готового документа с той же эпохой не передаёт полный снимок заново.

После перезагрузки главного окна координатор принимает существующие native окна через status.
Живой дочерний документ подтверждает новую эпоху без повторного импорта снимка поверх панели.
Номера команд и подтверждения принадлежат эпохе: меньший номер новой эпохи исполняется,
повтор в той же эпохе не создаёт второй intent, сообщения прежней эпохи отбрасываются.
Локальный id intent не переиспользуется при смене эпохи; поздний consume старой команды
не подтверждает новую команду с таким же номером. Уже отправленные команды с неизвестным
результатом автоматически не повторяются.

Контекст Кода публикуется после установки файловой модели и перехода на нужную строку.
Monaco может не сообщить о переходе на первую строку новой модели, если курсор уже стоит там:
отсутствие события не должно оставлять в контексте чата строку прежней модели.

Снимок Docker хранит вид просмотрщика `logs` или `exec` и id контейнера. Импорт восстанавливает
тот же вид после загрузки списка контейнеров; при возврате в скрытую панель просмотрщик
монтируется после показа колонки. Клиентский поток прежней панели снимается до создания
нового. Терминальный вывод и сокеты в снимок не входят.

Проверяются prepared `tool-window-relay`, `tool-window-host`, `code-view.component`,
`tool-window-panels.component` и Electron: перезагрузка main и child, переход 5 → 1 того же
файла, перенос и возврат Docker с открытым терминалом контейнера.
