# Композиция каркасов загрузки

Каркасы используют общий набор и повторяют будущую раскладку.
Прямых ответов владельца на видимость подписи и вид мерцания не поступало: применены
рекомендованные варианты утверждённого плана — скрытая подпись и плавная пульсация.
Эти варианты не обозначаются прямыми решениями владельца.

`UiSkeleton` принимает `shape: line | block | circle`, `width?` и `height?` как CSS-размеры.
По умолчанию line занимает 100%×8px, block — 100%×64px, circle — 32×32px.
Каждый кирпичик имеет `data-ui-skeleton` и `aria-hidden=true`, без role и действий.
Цвет, радиус и движение задаёт общий feedback.css; локальная композиция задаёт размеры.

`UiSkeletonLayout` принимает `layout: list | form | text`, `header=true`, `rows=4`.
Он компонует кирпичики и не объявляет отдельный статус. При готовой внешней шапке
передаётся `header=false`. Экран оборачивает композицию одним `UiLoadingState`.
Многозонные экраны имеют отдельный лёгкий компонент рядом с экраном.

Каркас содержит только заменяемую область. Он не дублирует шапку, ввод и существующие поля.
Сохранённые настройки передаются из уже доступных refs или общего лёгкого read-helper.
Каркас не читает дополнительные данные и не создаёт новых настроек.

Геометрия проверяется в Chromium относительно настоящего готового компонента в том же
хосте: x/width колонок, y/height шапки и ввода, ритм строк, отсутствие горизонтального
переполнения. Допуск крупных областей — 4 CSS px. Не предсказываются длины текста,
число неизвестных записей и условные области, зависящие от ещё не полученного ответа.

Ленивый каркас остаётся в основном пакете и не импортирует готовую панель или её runtime.
Ошибки и повторы сохраняют прежнего владельца; `failed` подавляет только декорацию.
Полный API статуса и исключения — в [состояниях загрузки](loading-states.md).
