# Вход с доски в настройки драйверов

Шестерёнка доски и действие баннера подключения сразу открывают каталог
`TrackerSettingsDialog`, по образцу исполнителей. По умолчанию видны параметры
текущего подключения. Если внешнего трекера нет, выбран первый установленный драйвер.
Открытие читает текущий выбор и реквизиты через tracker API, версии — через локальный
GET `/api/driver-installs/installed`. Запросов к репозиториям и записей настроек нет.
До ответа tracker API виден общий каркас формы, сохранение недоступно.

`connectionOpen` принадлежит экземпляру каталога и начинается с `true`. Доска создаёт
новый экземпляр при каждом открытии, поэтому закрытый ранее мастер, подтверждение
либо результат обновления не меняют следующий вход в настройки драйверов.

«Добавить трекер» сразу открывает источники, «Обновить» — подготовку выбранного
пакета в той же модальной оболочке. Выбор версии, откат и восстановление запускаются
из параметров драйвера. Отдельного списка пакетов и «Других действий» нет. Только после явного перехода восстанавливается серверный job.
Открытие каталога не подтверждает, не отменяет и не стирает сохранённую операцию.
«К настройкам», «Готово» и настройка подключения из результата возвращают в этот
каталог с черновиками драйверов в памяти текущего экземпляра. Прежние завершённые
попытки не подменяют новое добавление, текущая активная операция восстанавливается.

Проверки `TRACKER-SETTINGS-03/04/05/06` в
`tests/web/tracker-settings.component.test.js` проходят вход без job, с завершённым
и подготовленным обновлением, повторный вход после установки, медленное чтение
и просмотр другого драйвера без изменения подключения доски.
