# Ресурсы компьютера

Панель открывается индикатором CPU/RAM в топбаре и использует общую плитку топбара.
В шапке остаются загрузка CPU и суммарная занятая память ОЗУ + swap. На экранах уже
900 px индикатор по-прежнему скрыт. Большой список устройств прокручивается внутри плитки.

## Строки и тревога

- Процессор: загрузка, полоса, средняя загрузка за минуту и доступная температура CPU.
- ОЗУ и подкачка: прежняя разбивка памяти; при нулевой подкачке — подпись о её отключении.
- Каждая видеокарта: исходное название, загрузка и полоса, видеопамять и её температура.
  Неизвестная загрузка обозначается прочерком с пустой полосой; неизвестная видеопамять
  не подменяется нулём.
- Каждый настоящий раздел: полная точка монтирования, свободные ГБ в заголовке,
  полоса занятого места, подпись занятого и общего объёма. Раздел папки данных получает
  подпись «диск данных GrigDesk». Температура NVMe находится в строке своего раздела.

Красный диск или температура любого показанного устройства включает метку тревоги в
индикаторе ресурсов. Метка расположена абсолютно и не меняет ширину индикатора. Причина
также входит в его доступное имя. Высокая загрузка CPU, RAM или GPU сама метку не включает.
При потере связи остаются последний снимок, отметка устаревания и время получения данных.

Оформление метки находится в `web/src/styles/components/actions.css`, рядом со стилями
кнопки `topbar-metrics`. При устаревшем снимке цифры приглушаются, а метка сохраняет яркость.

Цвет нагрузки CPU/RAM/GPU: жёлтый от 60%, красный от 85%. Цвет диска определяется
доступным местом до округления: меньше 30 ГБ — жёлтый, меньше 10 ГБ — красный.
Поэтому небольшой настоящий раздел тоже может включать тревогу.

Температурные пределы `max` и `crit` своего канала имеют приоритет. Если они отсутствуют,
запасные границы жёлтого/красного — 80/90 °C для CPU и GPU, 60/70 °C для NVMe.
Пределы вне диапазона (0, 150] °C считаются несообщёнными, включая заглушки NVMe.
При единственном `max` красная граница равна большей из него и запасной красной;
при единственном `crit` жёлтая — меньшей из него и запасной жёлтой. Красный проверяется
первым, включая совпадение или инверсию сообщённых пределов. Это правила индикации,
а не гарантированные рабочие температуры любого оборудования.

Числа используют текущую локаль интерфейса, именованные параметры переводов ru/en и
основание 1024. Новые объёмы и температуры округляются только при показе, до десятых.
Названия устройств и точки монтирования остаются данными и не переводятся.

## Снимок API

`GET /api/system` синхронно возвращает последние завершённые снимки из памяти. Он не
читает файлы, не запускает процессы и не ждёт опроса оборудования. Авторизация и адрес
маршрута сохраняются. Общий тип — `shared/runtime/systemMetrics.ts`.

Прежние `cpu`, `mem`, `net` сохраняют форму и формулы. Новые поля необязательны:

| Поле | Данные |
|---|---|
| `cpu.temperature` | Температура процессора |
| `gpus[]` | `id`, `name`, необязательные `percent`, `memoryUsedGb`, `memoryTotalGb`, `temperature` |
| `disks[]` | `id`, `device`, `mountpoint`, `totalGb`, `usedGb`, `freeGb`, `percent`, `dataHome`, необязательная `temperature` |
| `temperature` | `celsius`, необязательные `maxCelsius`, `critCelsius` |

Все новые опубликованные числа конечные. Объёмы передаются в ГБ без округления,
температура — в °C. Отсутствие метрики не означает ноль. До первого завершённого опроса
списки могут быть пустыми. Успешный опрос без устройства удаляет его прежнюю строку.
Новый интерфейс со старым сервером показывает прежние строки и запасную разбивку памяти;
старый интерфейс игнорирует новые поля. Опрос store, stale и единственный SSE не меняются.

## Источники и принадлежность

CPU и прежний снимок памяти обновляются каждые 2 секунды. GPU и hwmon — независимыми
проходами раз в 5 секунд, ёмкость разделов — раз в 45 секунд. Каждый файловый проход
защищён от перекрытия. Идентичность NVMe хранится вместе с диском; свежая температура
присоединяется в памяти, не ожидая следующего измерения ёмкости.

CPU распознаётся по `k10temp/Tctl` или `coretemp/Package id`. Из нескольких пакетов
выбирается самый горячий вместе с пределами его канала. Для NVMe используется Composite,
для AMD — edge. Неподписанные датчики платы, acpitz, Wi-Fi и вторичные каналы NVMe не
показываются. Номер hwmon не определяет владельца: связь устанавливается по каноническому
пути устройства. Для mapper/slaves и NVMe multipath температура присоединяется только
при единственном определённом контроллере; неоднозначный раздел остаётся без температуры.

NVIDIA опрашивается отдельным `nvidia-smi` без shell: UUID, PCI, имя, загрузка, VRAM,
температура. Пределы hwmon связываются по PCI. Срок — 2 секунды, вывод ограничен 128 КиБ;
при превышении посылается SIGKILL только своему child. До `close` новая команда не
запускается. ENOENT отключает NVIDIA до создания нового сборщика. Другой сбой сохраняет
последний удачный снимок; успешный пустой ответ удаляет карты.

AMD читается из `cardN/device` sysfs: vendor, product_name, gpu_busy_percent,
mem_info_vram_used/total. Канонический device устраняет дубли DRM. Команды не запускаются.
Отсутствие оборудования, файлов или доступа не создаёт пользовательскую ошибку.
Остановка адаптера очищает его таймеры, завершает свой child и запрещает позднюю публикацию.

## Разделы

Список берётся из mounts: локальные ext2/3/4, xfs, btrfs, f2fs, jfs, reiserfs, bcachefs,
vfat, exfat, ntfs/ntfs3/fuseblk с подтверждённым блочным устройством в dev и sysfs.
До statfs исключаются сетевые и служебные ФС, loop/ram/zram и `/boot/efi`.
Octal escapes точек монтирования декодируются. Bind-маунты, алиасы и подтома одного
раздела сводятся к самой короткой точке монтирования; разные разделы остаются разными.

Путь папки данных приходит из `config.dataHome`. Его канонический путь сопоставляется
с самым длинным маунтом по границе сегмента до дедупликации. Флаг данных переносится
представителю раздела. Содержимое папки данных для этого не читается.

Асинхронный statfs даёт всего `blocks × bsize`, занято `(blocks − bfree) × bsize`,
свободно `bavail × bsize`; полоса — занято/всего. Резерв ФС не входит в доступное место,
поэтому свободное и занятое могут не складываться в общий объём. Ошибка отдельного раздела
не отменяет остальные. Незавершённый проход не блокирует API и не создаёт новых проходов.
