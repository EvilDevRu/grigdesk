# Обновление и удаление в шапке плагина

В «Установленных» шапка пользовательского плагина содержит кнопки включения,
обновления и удаления в виде иконок справа с подсказками и доступными именами.
Они видны и на вкладке «Параметры». Системные плагины
этих действий не получают.

«Обновить» открывает существующий `PluginInstallDialog`: управляемый пакет
получает свой сохранённый Git-источник, ручной — ввод репозитория с ожидаемым ID
текущего плагина. Подготовка и применение новой версии остаются отдельными шагами.

«Удалить» вызывает общий подтверждающий диалог. Выбор плагина, сессия настроек,
занятость и recovery проверяются повторно после подтверждения. Активное или готовое
задание установки блокирует удаление. Повторный клик не создаёт второй POST.

После подтверждённого сервером удаления карточка исчезает, выбирается следующий
пользовательский пакет и показывается необходимость ручного перезапуска.
Неприменённые поля удалённого плагина отбрасываются, если Apply не выполняется;
черновики других плагинов сохраняются. Во время уже запущенного Apply действует
обычный контракт недоступных полей: их можно отбросить после завершения применения.
Отказ сервера сохраняет ввод и показывает причину в менеджере.

Общий installer store проверяет ID и `restartRequired` в ответе удаления.
После потери ответа он перечитывает каталог без автоматического повтора POST
и без объявления успеха. Поздний ответ после dispose не обновляет каталог.

Проверки: `settings-plugin-actions.component.test.js`, `plugin-remove-store.test.js`.
Серверный контракт — [удаление пользовательского пакета](../plugins/user-plugin-removal.md).
