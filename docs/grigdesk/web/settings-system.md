# Система в общем модале настроек

`system.startup` разделяет приложение на текущем компьютере и сервер выбранной машины.
У приложения отдельный staged-автозапуск при входе и немедленная операция ярлыка через
локальную оболочку. У сервера staged-переключатель сохраняет только enabled юнита,
не перезапускает процесс. Состояние missing запрещает серверную запись, не блокируя ярлык окна;
linger и режим desktop/systemd/manual остаются объяснением. Контракт —
[разделение запуска приложения и сервера](application-server-startup.md).
Общая форма серверного LauncherState находится в `shared/runtime/launcherContracts.ts`;
прежние server exports и API ярлыка сохранены для совместимости.

`system.updates` использует существующий общий store обновления и его capability/reason guards.
Checkout и release подтверждаются с актуальным числом ходов. Перезапуск и пересборка не делают
reload документа: процесс перечитывается после связи или завершения job. Опрос пересборки
возобновляется при посещении страницы; закрытие не отменяет серверное задание.

`system.diagnostics` объединяет staged-уровень и прежний WebLogPanel. Комментарий отметки,
её ACK и скачивание являются операциями, а не частью Apply.

`system.processes` читает список при посещении и через общую SSE-подписку chat-sessions.
Собственный ticker меняет только подписи времени и снимается при уходе вместе с GET и подпиской.
Погашение одного или свободных процессов подтверждается; идущий ход посылается с force=1.
Отказ подтверждения не вызывает DELETE. Переход к чату проходит общий выбор судьбы dirty-черновика.
