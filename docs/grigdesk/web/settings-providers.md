# Параметры исполнителей в общей сессии

Страница `agents.providers` хранит обычные параметры, доступ и нативные set/unset в общей
сессии. До «Применить» доменные stores ничего не записывают. Ключи находятся в приватной
памяти сессии; поиск содержит только подписи, описания и сегменты публичного адреса.
Удаление ключа подтверждается при создании намерения null и выполняется по «Применить».
Подтверждение capability относится к конкретному значению черновика, без второго вопроса при записи.

Ресурсы сортируются по ID исполнителя: credentials → обычные настройки → нативные настройки.
После credentials адаптер ждёт обновления реестра; исчезнувшее поле остаётся неприменённым
с причиной. После неизвестного исхода ключа прежняя маска не доказывает запись: требуется
изменение set/preview в сторону намерения. Автоматической повторной отправки ключа нет.

Нативная очередь и CAS принадлежат `stores/providerSettings.ts`. Метод `commit` возвращает
явный WriteOutcome и не заполняет глобальные drafts/errors. Каждый следующий запрос получает
revision/schemaRevision из последнего каталога. Конфликт 409 перечитывает каталог и останавливает
оставшиеся поля этой цепочки; другие исполнители продолжают применение.

Baseline нативных полей содержит только известные overrides. Для скрытого сохранённого выбора
`SessionField.hasStoredValue` разрешает отложенный unset без выдуманного null в baseline.
Недоступный источник не превращает старую схему в доступные для записи controls.

Исполнители сгруппированы по общему executorTypes. Страница показывает подробности только
выбранного: «Обзор», «Доступ», «Параметры», «Модели», «MCP». Переключение не сбрасывает ввод.
MCP читается только при открытии своей вкладки либо ручном обновлении; собственный таймер
не создаётся, изменение снимка MCP не вызывает discovery повторно. Дополнительные параметры
загружаются при раскрытии или адресном поиске. До загрузки индекс предлагает явно её выполнить.

Ресурсы аккаунта на «Обзоре» используют прежний ProviderUsageResources с inline-подтверждением
и requestId; эти операции не попадают в Apply. Установка, вход и исправление runtime берут
команду из декларации исполнителя; переход в терминал проходит политику dirty-закрытия.
Команды проверяются общим validTerminalInsert и передаются как вставка без Enter.
