# Раздельный запуск приложения и сервера

Страница «Система → Запуск системы» содержит два блока:

- «Приложение» относится к компьютеру с открытым desktop-окном. Автозапуск открывает
  окно после входа пользователя; ярлык запускает текущий физический файл приложения.
- «Сервер» относится к выбранной машине, в том числе удалённой. Имя профиля видно в
  пояснении. Автозапуск службы, сведения процесса и перезапуск идут через API этой машины.

Оба переключателя входят в общий Apply, но имеют разные ресурсы: `applicationAutostart`
пишет в `/__shell/launcher`, `autostart` — в `/api/system/launcher/autostart`.
Операция ярлыка применяется сразу, не затрагивая черновики обоих переключателей.
Отсутствие серверного systemd-юнита не блокирует настройку приложения.

Linux main объявляет capability `applicationLauncher`. Локальный GET `/__shell/launcher`
возвращает `ApplicationLauncherState` из `shared/desktop/applicationLauncher.ts`; POST
принимает ровно `{autostart:boolean}` или `{shortcut:boolean}`. Пути и команды из renderer
не принимаются. Защиту origin и cookie сохраняет общая труба оболочки. Другие платформы
и прежние окна без capability показывают пояснение об отсутствии поддержки.

Main выбирает физический `APPIMAGE`, если он задан, иначе `process.execPath`.
При запуске из исходников к Electron добавляется только `app.getAppPath()`.
Путь виден в строке «Файл приложения». Серверный checkout, `runtime.json` и наличие
локального сервера не требуются для создания ярлыка.

Автозапуск окна хранится в `$XDG_CONFIG_HOME/autostart/grigdesk-app.desktop`, ярлык меню —
в `$XDG_DATA_HOME/applications/grigdesk.desktop`. При пустом или относительном XDG
используются `~/.config` и `~/.local/share`. Ярлык рабочего стола создаётся, если
каталог из `user-dirs.dirs` либо стандартный `~/Desktop` существует; отсутствие каталога
не мешает меню. Явный `$HOME` в `XDG_DESKTOP_DIR` означает отключённый рабочий стол.
Конфиг читается как данные, shell не вызывается. GNOME получает best-effort отметку
доверенного ярлыка через `gio`, без зависимости успешной записи от наличия этой команды.

Файлы публикуются через temporary и rename. Native-мутации сериализованы; ошибки чтения
и записи доходят до формы. Общий `desktop/src/desktopEntry.ts` экранирует Exec и для этой
настройки, и для прежнего предложения portable-меню. Правила:
[Desktop Entry Exec](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html),
[автозапуск после входа](https://specifications.freedesktop.org/autostart/latest/).

При буквальном `%` в пути Exec использует `/usr/bin/env --` перед файлом приложения:
GIO проверяет существование первого executable раньше раскрытия `%%`. Передача пути
аргументом env сохраняет корректный запуск без shell. Отдельный файловый тест действительно
запускает безопасную фикстуру через GIO и сравнивает полученный путь и аргументы.

Проверки: `tests/desktop/application-launcher.test.js`, `portable-integration.test.js`,
`shell-api.test.js`; `tests/web/settings-server-launcher.component.test.js` доказывает
раздельные назначения записей при удалённом сервере и отсутствующем юните.
Новый native-порт требует пересборки и повторного открытия desktop-приложения.
