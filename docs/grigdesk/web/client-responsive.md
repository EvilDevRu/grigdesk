# Сенсорная раскладка полного приложения

Общая точка входа включает data-ui-touch на корне при pointer: coarse. Кнопки и действия
имеют площадку не меньше 44 px, рейка и шапка используют общие токены. Ширина окна сама по
себе сенсорный режим не включает. Значок связи остаётся в шапке при скрытой текстовой подписи.

До 600 px боковую рейку заменяет нижняя навигация, а содержимое использует всю ширину.
Настройки чата раскрываются отдельно; список доски прокручивается страницей.
[Телефонные рабочие экраны](phone-workspaces.md) описывают геометрию и проверки.

Высота #app следует visualViewport через installAppViewport. При экранной клавиатуре
пересчитывается рабочая область, сохраняя поле чата в видимой части. Padding учитывает
четыре safe-area-inset. Обработчики изменения размера удаляются при завершении приложения.
Длинный код прокручивается внутри Markdown, а не расширяет документ.

Проверка Chromium client-responsive.test.js использует настоящие экраны с синтетическими
API на случайном порту. Матрица: 390×844, 800×1280, 1280×800, 1280×860, текст 100% и 130%.
Размеры букв и строк увеличиваются без увеличения площадок кнопок. Проверяются отсутствие
прокрутки документа, размеры видимых кнопок, значок связи, длинный код и положение поля
при уменьшенном visualViewport. Системная клавиатура и вырезы проверяются также на устройстве.

Телефонная проверка client-phone.test.js на 390×844 и 360×740 с текстом 130% подтверждает:
список и чат сменяют друг друга, черновик и вложения доступны, длинный вопрос и команда
разрешения читаются с переносами, доска открывает полную карточку задачи. Длинный вопрос
переносится также внутри flex-строки заголовка; панель сохраняет собственную прокрутку.
