# Применение черновика настроек

Координатор в `features/settings/session.ts` сначала проверяет весь dirty-набор
внедрёнными валидаторами, затем последовательно вызывает изменённые адаптеры в их
`order` (при равенстве — по ID). Повторные Apply/OK получают тот же Promise.
Редактирование и отмена черновика во время записи запрещены; владелец сессии может
всегда вызвать `dispose` при потере авторизации или размонтировании.

Адаптер объявляет цепочку и форму записи: `patch`, `full-record` или `per-field`.
При отказе или конфликте остаток его цепочки пропускается; независимые цепочки
продолжаются. Неизвестный исход и HTTP 401 останавливают всю очередь.
Необязательный `ResourceWriteResult.httpStatus` передаёт 401 и при явном результате
доменных stores. Автоматического rollback и повторной записи нет.

Подтверждение имеет проверяемую форму `ResourceWriteResult`. Классификация в
`contracts.ts`: `ApiError(409)` — конфликт, остальные HTTP-отказы — failed, сетевой
обрыв, abort, повреждённый ответ и неожиданный успешный ответ — unknown.
`resourceWriteFailure` сохраняет эту классификацию для адаптеров.

При успехе запроса принятые поля получают серверный baseline; пропущенное поле
остаётся dirty с «Сервер не принял значение». Порядок перечисления полей не влияет
на подтверждение остальных. Для `per-field` подтверждаются успешные отдельные
записи даже при отказе следующей. Нормализация сервера доступна в `saved.normalized`
и публичном `serverValue`; поле после применения показывает подтверждённое значение.
Секретное подтверждение очищает ввод, не возвращая секрет в baseline или результат.
Известные секретные строки маскируются и в сообщениях адаптера до публичного state.

Результат содержит `saved`, `remaining`, `errors`, `validation` и отдельный статус
success/partial/failed/conflict/unknown. `shouldClose` истинно только для исходного
OK при полном успехе, включая чистую форму. Частичный результат сохраняет успешные
baseline; повтор отправляет только оставшиеся намерения. «Отмена» их не откатывает.

Через 20 секунд ожидания записи показывается «Ответ задерживается» и разрешается
`stopWaiting`. Эта кнопка даёт unknown, прекращает остаток очереди и разрешает
закрытие. Поздний ответ не меняет сессию; подтверждённое обновление доменного store
не подавляется. Таймеры и часы находятся вне публичного состояния; часы внедряются
для теста. Ветка unknown начинает одно перечитывание доступного состояния без
удержания закрытия. Оно не может изменить новое открытие или следующий Apply.

Номер открытия проверяется до валидации и после каждого ожидания. Старое применение
не очищает ошибки нового открытия и не отправляет его изменения.

Проверки: `tests/web/settings-apply.test.js` (AP01–AP11 и граничные случаи),
`tests/web/settings-session.test.js`.
