# Модальное окно настроек

В локальном приложении настройки открываются в отдельном модальном окне поверх главного.
Родитель отключён для кликов и клавиатуры, но продолжает принимать SSE, сообщения и обновлять
stores. Закрытие настроек возвращает фокус главному окну без перезагрузки разговора, потери
прокрутки или набранного текста. Закрытие главного окна закрывает и настройки.

## Открытие и роль документа

Окно одно на приложение. Повторный запрос восстанавливает и фокусирует его без новой загрузки;
до `ready-to-show` оно скрыто. Размер — 1120×820, минимум — 800×600, оба ограничены рабочей
областью дисплея родителя. Геометрия настроек не сохраняется. Сворачивание и полный экран
выключены; своего меню нет. Заголовок «Настройки — GrigDesk» не заменяется заголовком страницы.

Адрес настроек сохраняет версию главного окна: `${origin}/ui/<id>/?window=settings#/settings`.
Для dev-фикстур допустим также корень `/`. Главный процесс узнаёт только свой HTTP-origin
без credentials, один из этих путей, query `?window=settings` и hash `#/settings`.
`guardContents` вызывает контроллер и отвечает `deny`, поэтому `window.open()` возвращает
`null` штатно. Похожие адреса сохраняют обычную политику защищённых дочерних окон.

До создания контроллер проверяет одну действующую cookie GET-запросом `/api/auth/state`
с таймаутом 2 с и запретом redirect. Без cookie, при отказе сети или `authenticated !== true`
окна нет. Ключ окна при этом не обменивается и вход автоматически не восстанавливается.

До первого `loadURL` главное окно получает UA-токены `GrigDeskSettings/1 GrigDeskWindow/main`,
настройки — `GrigDeskSettings/1 GrigDeskWindow/settings`. Повторная установка удаляет прежние
комплекты. Полная роль требует ровно по одному токену версии и роли; конфликтующие или
неполные комплекты роли не дают. Для оболочки настроек дополнительно требуется точный query
`?window=settings`. UA выбирает интерфейс и не даёт полномочий. Обычные окна `window.open`
получают UA сессии без маркеров и работают как страницы браузера.

В режиме main переходы RouterLink, router.push и hash на `/settings` открывают окно и
отменяют навигацию, сохраняя смонтированную страницу. Первая навигация документа на настройки
идёт на `/board` без открытия окна. В обычном браузере настройки остаются страницей.
Шестерёнка топбара и физическая клавиша Ctrl+Alt+S открывают или фокусируют настройки,
в том числе поверх терминала. Строка меню окна скрыта, одиночный Alt её не показывает.
Второй экземпляр приложения тоже фокусирует настройки,
если они открыты. [Нативные клавиши](../testing/electron-synthetic-keys.md).

## Оболочка и закрытие

`SettingsWindowShell.vue` рисует SettingsView напрямую, без router-view, AppShell, ToolHost
и SpeechProvider. Использует общие хосты диалогов, подсказок, документов и тостов. Поллинги
основного окна не запускаются. В узком окне разделы идут прокручиваемой полосой сверху.
Существующие кнопки сохранения и переключатели работают без общей кнопки «Применить».

Escape проходит общий стек слоёв: сначала закрывает верхний диалог, всплывашку или подсказку.
Запись сочетания забирает Escape для отмены записи. В текстовом input, textarea, select или
contenteditable первый Escape снимает фокус; следующее нажатие при свободном фокусе закрывает
окно. Крестик закрывает настройки сразу. Несохранённые поля теряются, как при уходе со страницы.

Формы входа в окне настроек нет. Если первая проверка входа отрицательна или пришёл 401,
окно ждёт завершения своих начатых мутаций (`pendingMutations() === 0`, проверка каждые
50 мс, не дольше 5 с) и закрывается. Главное окно восстанавливает общую сессию по ключу
после 401 своего документа.
Кнопок выхода нет; для защиты компьютера блокируют экран.

## Плотность интерфейса

Настройки используют общую [desktop-геометрию](desktop-ui-density.md). Отдельного
переключателя плотности нет; диалоги и подсказки в body наследуют общие токены.

## Связь и синхронизация

Окна общей сессии используют ленивый BroadcastChannel `grigdesk-desktop-settings-v1`.
В режиме страницы канал не создаётся. Сообщения имеют `version: 1` и точный набор полей;
неизвестная версия, тип, лишнее поле или неверное значение отбрасываются декодером.

| Тип | Дополнительные поля | Эффект |
|---|---|---|
| `settings-changed` | нет | Главное окно перечитывает фиксированный набор настроек |
| `terminal-request` | `requestId`, `insert` | Главное окно открывает терминал с введённой командой |
| `open-chat-request` | `requestId`, `chatKey` | Главное окно выбирает чат и переходит на `/chats` |
| `intent-result` | `requestId`, `ok` | Ответ основного окна на намерение |

`requestId` — 1–64 символа `[A-Za-z0-9_-]`; `chatKey` — непустая строка до 128 символов без
управляющих. `insert` — непустая строка до 16384 байт UTF-8 без U+0000–U+001F и U+007F.
Enter не добавляется: команду запускает человек. Команды не записываются в localStorage
или журналы. Значения форм, ответы API и cookie в канал не идут.

«Установить», «Войти» и исправление сборки исполнителя отправляют terminal-request;
«Открыть чат» в живых процессах — open-chat-request. Подписка ставится до отправки.
При ответе `ok: true` настройки закрываются; `false` или тишина 5 с дают тост ошибки,
окно остаётся открытым, автоматического повтора нет. Намерения принимаются только главным
вошедшим AppShell. Его размонтирование снимает мост и закрывает канал.

Каждый успешный не-GET запрос окна настроек объявляет settings-changed. Счётчик учитывает
JSON-запросы, двоичные запросы и upload до завершения результата; чтения и отказы молчат.
Главное перечитывает `plugins.load()`, `providers.load()` и `/api/settings/prefs` для
`chat.compactWindow`; `board.load(true)` — только при текущей ошибке доски. Сообщения во время
чтения склеиваются в одно следующее. Отказ одной области не блокирует остальные; поздний prefs
после размонтирования не меняет chat. Отдельного перечитывания входа и таблицы адресов нет.
Речь, диагностика и мобильные устройства продолжают обновляться через SSE.

Сочетания `grigdesk-tool-hotkeys` и удержание экрана `grigdesk-screen-wake-lock` применяются
главным окном по storage: reload стора без обратной записи. `key: null` перечитывает оба.
`grigdesk-settings-tab` читается при открытии. После возвращения сервера при рестарте
настройки перечитывают состояние сервера без перезагрузки документов. Пересборка рабочего web
не обновляет установленный интерфейс: для него требуется новый пакет приложения.

Проверки поведения: [dev Electron](../testing/desktop-window-e2e.md) и
[готовый пакет](../testing/desktop-window-package.md). Настоящий рабочий стол и установка
проверяются отдельно от изолированных запусков.
