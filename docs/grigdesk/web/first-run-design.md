# Оформление мастера настройки

`OnboardingView` использует рабочий режим `data-ui-workspace`, общие controls через
`ui.ts` и палитру GrigDesk. Ширина страницы ограничена 1160 px. Шапка содержит назначение
мастера и живой статус сохранения; ошибка записи скрывает успешный статус.

Слева расположена шкала из шести шагов, справа — текущий экран на поверхности `--sidebar`.
Текущий шаг выделен акцентом, завершённый — галочкой, пропущенный ИИ — отдельной подписью.
Три будущих шага остаются серыми и недоступными. После завершения базовой настройки
четвёртый шаг не получает `aria-current`: его по-прежнему выполняют вручную.

Карточки исполнителей показывают общий `ProviderIcon`, готовность к чатам, установку
и способ авторизации. Готовность вычисляется одинаково для статуса и перехода:
`available && chatEnabled !== false`. Одного такого исполнителя достаточно для продолжения.
Установка и вход используют прежние общие installer и терминал. Обновление показывает
занятость общей кнопки; первое чтение реестра использует `UiLoadingState`.

Папки проекта собраны в пронумерованные блоки с отдельной веткой для каждой папки.
Варианты места работы имеют описание, видимое выбранное состояние и клавиатурную
навигацию. Итог показывает сохранённые папки и ветки, режим и ссылку на следующие действия.

Подвал отделён линией: «Настрою сам» слева, пропуск и акцентное продолжение справа.
Он расположен после содержимого, чтобы не перекрывать поля на низком экране.
При смене шага фокус и прокрутка переходят к началу нового содержимого; первое открытие
не перехватывает фокус. Заголовки принимают программный фокус без дополнительной остановки Tab.

Адаптив зависит от ширины самой страницы через container queries: при ширине до 800 px
шкала располагается над формой в три колонки, до 460 px — в две. Подробности шагов
скрываются в компактной шкале, названия остаются видимыми. Карточки и действия переносятся;
сенсорную высоту controls задаёт общий `data-ui-touch`.
