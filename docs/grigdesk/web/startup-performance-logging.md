# Разделение стоимости ответа и применения доски

Для локализации стартовых пауз штатный журнал при уровне «Подробно» дополнен
операциями из закрытого каталога:

- `providers.parse` — синхронный разбор JSON реестра `/api/providers`;
- `chat.load.parse` — разбор обычных и потоковых ответов `/api/chat/store/*`;
- `api.parse` — разбор остальных JSON-ответов общего API-клиента;
- `board.apply` — проверка полученного dashboard и синхронное принятие его в store.

Для разбора передаётся только число символов. Реальный путь с id/query и тело
ответа не сохраняются. Обе ветки транспорта используют одну классификацию;
разбор неуспешного HTTP-ответа сохраняет прежний статус ошибки. Инструментирование
не меняет результаты, retry, отмену и порядок принятия снимков доски.

Это времена синхронных участков, без сетевого ожидания. `board.apply` также
не включает асинхронную загрузку отметок просмотра и последующий рендер Vue.
Их стоимость остаётся видна по браузерным longtask и Long Animation Frame.
Пересечение с короткой операцией внутри длинной задачи не доказывает причину
всей задачи.

Нужна новая сборка окна и сервера: закрытые имена проверяются с обеих сторон.
Уровень, объём, очистка при скрытии/dispose и приватность следуют
[общему контракту диагностики фризов](chat-performance-logging.md).
Проверки обычного/потокового JSON и применения доски с проверкой отсутствия
приватных данных находятся в `tests/web/chat-performance-logging.test.js`.
