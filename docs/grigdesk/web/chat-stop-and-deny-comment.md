# Кнопка остановки и пояснение отказа: очередь ходов и ввод в активный ход

Оба дефекта нашлись в одном разговоре GLM 31.10.2026: пользователь запретил
эскалацию коммита с пояснением, остановил ход — и остаток часа не мог остановить
агент, потому что кнопка «Остановить агента» висела в «Останавливаю…», а пояснение
отказа агент не увидел.

## Кнопка остановки: старт хода из очереди освобождает `stopping`

`stopping=true` ставит `stop()` (POST `/api/chat/stop`). Фронтовой стоп не трогает
очередь ходов: `expected` с составом очереди шлют только мобильные клиенты, окно
останавливает один текущий ход. Дальше события SSE:

- `chat-done` завершённого хода не сбрасывает `stopping` при непустой очереди
  (`queued > 0` в гвардии `finish()`) — индикатор «думает…» честно остаётся, работа
  продолжается, но и кнопка остаётся заблокированной;
- старт следующего хода из очереди (`chat-turn-start` без `source=background`)
  раньше вообще не трогал `stopping`: сброс был только в ветке фоновых запусков.

Итог старого поведения: кнопка «Останавливаю…» на весь следующий ход. Гонка
реальная, не теоретическая: сервер пускает ход из очереди через миллисекунды
после `chat-done`, а `finish()` ещё ждёт свой `_collectPending()` — ревизия уже
сменена, и его гвардия выходит раньше сброса.

Контракт после фикса: **старт любого не-компакт хода сбрасывает `stopping`** —
стоп относился к прошлому ходу, новый ход начинается со свободной кнопкой
(`web/src/stores/chat.ts`, ветка `chat-turn-start`). Компакт-ход кнопку не
освобождает: у него своя семантика прерывания сжатия.

## Пояснение отказа: канал эскалации текста не несёт, догоняем в активном ходе

Канал подтверждений GLM отдаёт исполнителю только `{allow}`:
`server/src/lib/glm/permissions.ts` объявляет `acceptsComment: false`, `settle`
берёт одно поле. Сервер честно отвечает окну `commentDelivered:false`
(`server/src/modules/chat/index.ts`, `/api/chat/permission/:pid`).

Прежняя компенсация — `send()` пояснения обычным сообщением — теряла главное:
во время отказа ход ещё работает, сообщение попадает в очередь и становится
отдельным ходом после конца текущего. Агент в момент отказа действует вслепую
(«Коммит отклонён — принимаю… Значит, почта — про другое»), а пояснение человека
превращается в ход без контекста.

Контракт после фикса: при `commentDelivered:false` окно сначала отправляет
пояснение **в активный ход** через in-turn канал с префиксом-связкой
`Пояснение к отказу (<tool>): <текст>`; фолбэк — прежняя очередь, если канал
не готов (Kimi/ACP, ход уже закончился). In-turn доступен у GLM и DeepSeek
(`inTurnInput.text: true` в адаптере исполнителя).

Проверка: `tests/web/chat-stop-and-deny-comment.test.js` — старт из очереди
освобождает кнопку; пояснение уходит in-turn с префиксом; неготовый канал
оставляет фолбэк в очередь.
