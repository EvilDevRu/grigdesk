# Действия кнопок мастера

Подписи различают переход по шагам, отказ от настройки и завершение.

| Кнопка | Действие |
|---|---|
| «Далее» на ИИ | Перейти к проекту с `aiSkipped=false` |
| «Пропустить шаг» на ИИ | Перейти к проекту с `aiSkipped=true`, не закрывая мастер |
| «Далее» на проекте | Сохранить паспорт и перейти к месту работы задач |
| «Далее» на месте работы | Сохранить режим и завершить проход на итоговом экране |
| Пункт «Где работают задачи» при пустом проекте | Открыть выбор режима без создания паспорта |
| «Добавьте проект» на месте работы | Вернуться ко второму шагу, сохранив выбранный режим |
| «Назад» | Вернуться ровно на предыдущий шаг того же прохода |
| «Пропустить настройку» | Подтвердить отказ, закрыть мастер, оставить текущий раздел |
| «Готово» на итоге | Закрыть мастер и открыть созданный проект, сохранив `completed` |
| «Настроить ещё проект» | Начать новый проход с ИИ, сохранив готовый проект |
| Крестик или Escape | Сохранить ввод и закрыть окно без отказа, сохранив текущий раздел |

На итоге нет кнопки пропуска: завершённый проход не превращается в `dismissed`
обычным закрытием. Общий пропуск не открывает другую форму, список проектов или
настройки исполнителей. Ошибка записи оставляет мастер и исходный раздел открытыми;
недоступные действия блокируются до явного перечитывания.

Переход ставит `busy` до ожидания очереди autosave. Пока последний PATCH и сам переход
не подтверждены, второй переход не отправляется даже при прямом вызове store.
Смена владельца или машины во время ожидания отменяет прежнее действие.

Компонентная проверка использует настоящий `OnboardingHost`, memory-router,
Pinia store, UI-controls и HTTP-сервис мастера с временными данными. Она проверяет
адрес, состояние окна, статус прохода, содержимое паспорта и внешние действия;
подмена `router.push` пустой функцией не может подтвердить назначение кнопки.
