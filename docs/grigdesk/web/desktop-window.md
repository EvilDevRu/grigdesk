# Локальное окно GrigDesk

Главный процесс `desktop/src/main.ts` загружает локальный веб GrigDesk через модули
подключения, настроек, защиты и входа. Модульные проверки, TypeScript и сборка прошли.
Сквозная проверка настоящего dev Electron подтверждает окно, вход и SSE:
[устройство проверок](../testing/desktop-window-e2e.md).

## Подключение и настройки

`connection.ts` принимает только явный `http://127.0.0.1:<порт>` с необязательным `/`.
Порт — десятичный, без ведущих нулей, от 1 до 65535. Credentials, пробелы, query, hash,
другие пути, схемы и формы IPv4 запрещены до разбора URL. Канонический origin порта 80
не содержит `:80`; такой origin допустим в сохранённых настройках.

Порядок адреса: один `--grigdesk-url=<адрес>`, затем канонический origin установленного
сервера из `runtime.json`, затем настройка, затем default `http://127.0.0.1:8140`
([старт окна](desktop-startup.md)). Пустой, неверный, повторённый или голый ключ возвращает
ошибку; остальные аргументы игнорируются. Подключение имеет только вид
`{ kind: 'local', origin }`.

Настройки лежат в `<userData>/settings.json`; тесты задают абсолютный
`GRIGDESK_DESKTOP_DATA_DIR`, обычный профиль выбирает Electron для имени GrigDesk.
`settings.ts` читает версию 1. Неподдерживаемая версия и ошибка чтения дают defaults;
в версии 1 connection и window нормализуются независимо. Неверная connection становится
null. Конечные числовые размеры округляются и ограничиваются 600…10000; default —
1280×860, maximized — false.

Сохранения одного пути идут последовательно: последний вызов становится последним на
диске. Writer создаёт личный каталог 0700, проверяет существующий каталог через lstat,
его владельца и права. Общий родитель не chmod; ссылки каталога и файла отклоняются.
Уникальный temporary открывается через wx с правами 0600, закрывается и атомарно
переименовывается. Отказ rename сохраняет прежний файл и очищает свой temporary;
следующее сохранение продолжает работать. Ошибка возвращается caller для сообщения
пользователю без содержимого настроек.

## Политики и адаптеры Electron

`windowSecurity.ts` использует реальные типы Electron через import type; его unit не
запускают Electron. Опции окна задают `persist:grigdesk-local`, sandbox, contextIsolation
и webSecurity. Node, preload, webview и spellcheck выключены; devTools разрешены только
вне упаковки. Главное окно изначально скрыто.

Свои HTTP-навигации проходят. Внешние HTTP(S) отменяются и получают канонический адрес
для системного браузера; credentials и прочие схемы, включая blob своего origin,
отклоняются. Redirect ограничивается главным фреймом, подфреймы сохраняют браузерное
поведение. Собственная ссылка в новое окно получает безопасные preferences, общую
session и show:true; её features не меняют эти опции. Потомки синхронно получают защиту
и onChild, повторное подключение обработчиков исключено.

Своему origin разрешены notifications, clipboard-sanitized-write и fullscreen.
Media требует явного непустого набора только audio. Адаптер check использует отдельный
requestingOrigin, request — requestingUrl и mediaTypes; противоречащий securityOrigin
отклоняется. Video, неизвестные permissions и media без типа запрещены.

`configureSession` сначала устанавливает единственный фильтр запросов, затем ждёт
очистку serviceworkers и cachestorage выбранной сессии. Cookie и localStorage не
очищаются. Блокируется только свой `/sw.js`, также с query; другие имена SW этот фильтр
не блокирует. Ошибка очистки передаётся caller. Сквозной тест подтверждает отказ
настоящей регистрации `/sw.js`, также с query, при работающей обычной HTTP-сети.

## Ожидание и меню

`autoLogin.ts` исполняется только в главном процессе. Ключ из
[общего серверного пути](../server/window-key.md) читается через O_NOFOLLOW и
O_NONBLOCK после проверки личного каталога и fstat того же дескриптора. Только
собственный обычный файл без прав группы/остальных и с nlink=1 допускается к чтению;
буфер ограничен 129 байтами, после trim требуется 43 base64url. FIFO не блокирует open.

При подключении одна существующая `grigdesk_sid` проверяется GET auth/state;
действующая сессия сохраняется. Иначе окно обменивает ключ через POST window-session
без тела. Redirect запрещён у обоих запросов, таймауты — 2 и 5 секунд, внешняя отмена
проверяется после await перед следующим эффектом. На отсутствие файла, 401 или 503
разрешён только один повтор чтения через 100 мс. Отказы возвращают unavailable: локальное сообщение о недоступном ключе и повтор через 10 с.

Set-Cookie берётся из getSetCookie() отдельными заголовками, без разрезания Expires
по запятой. Принимается одна host-only cookie с Path=/, HttpOnly, SameSite=Lax,
положительным безопасным целым Max-Age и без Secure/Domain. Cookies.set получает
expirationDate в секундах, вычисленный от текущего времени. Cookie API и ошибка
разбора не дают необработанного исключения, а ключ не возвращается caller.

`offline.ts` создаёт русскую страницу «Ждём сервер GrigDesk» с экранированным адресом,
тёмным фоном, CSP без скриптов и внешних ресурсов. Документ кодируется в data URL.
Проверка готовности делает GET `/api/auth/state` через fetch главного процесса с
redirect:error, таймаутом 2 с и внешним AbortSignal. Требуются статус 200 и boolean
configured/authenticated; форма HTML или поздний ответ после abort не дают готовность.
Общую проверку `shared/runtime/grigDeskReadiness.ts` также использует CLI. Текст заставки:
«Окно подключится само, как только сервер ответит. Если ожидание затянулось, выполните
в терминале grigdesk-ctl status» (команда оформлена элементом code).
Цикл ждёт 2 с между отказами и завершается при успехе либо отмене запроса или сна.

`menu.ts` возвращает шаблоны «Файл», «Правка» и «Вид» с русскими подписями ролей,
масштабом и полным экраном, без DevTools. Строка меню в окне постоянно скрыта,
одиночный Alt заблокирован; [кнопки окна встроены в топбар](desktop-titlebar.md).
Действие «Файл → Настройки…» передаёт `grigdesk:open-settings` в главный документ
и открывает [общий модал настроек](desktop-settings-window.md). Accelerator Ctrl+Alt+S объявлен
с `registerAccelerator: false`; действие обрабатывает `before-input-event` по физическому
KeyS в главном окне, до обработчика страницы и xterm.
Контекстное меню следует editFlags и может
добавить копирование адреса ссылки. Разделитель появляется только между непустыми
группами. Пустой шаблон проверяется перед popup; Menu и clipboard подключает main.

## Главный процесс и сборка

Старт идёт через заставку, supervisor сервера и ворота показа — [старт окна](desktop-startup.md).
Сразу после single-instance lock установлен обработчик второго экземпляра: до показа он
фокусирует заставку, после — главное окно с его текущим модалом, во время выхода ничего не
делает. Аргументы второго экземпляра не меняют подключение и настройки.

До первого loadURL главное окно получает UA `GrigDeskSettings/1 GrigDeskWindow/main`.
Единственная роль документа — `main`; настройки открываются внутри него по событию
`grigdesk:open-settings`. Обычные дочерние окна получают UA сессии без маркеров.
Защиту обеспечивает общий guard.

После ready `storageProtection.ts` требует доступного gnome_libsecret или
kwallet/kwallet5/kwallet6 до создания persistent session. Basic_text, unknown,
отсутствующий API и исключения завершают запуск русским сообщением и кодом 1;
открытого запасного хранения нет. Device identity и сертификат сохранены как
отдельные модули, но локальное окно их не использует.

`connectionLifecycle.ts` не импортирует Electron. Один цикл обеспечивает сессию
до загрузки, переходит к offline/wait при отказе и объединяет событие did-fail-load
с reject того же loadURL в одну попытку восстановления. Stop отменяет общий signal
и запрещает следующие эффекты после await; adapter loadDocument останавливает
текущую загрузку WebContents. Ошибка data-страницы выходит как ошибка приложения.
Сбой загрузки чужого URL, подфрейма и −3 игнорируется. Успешная загрузка завершает
цикл. HTTP 401 главного документа запускает восстановление по ключу на тот же адрес с hash,
не чаще одного раза в минуту; повторный отказ показывает локальный экран с повтором через 10 с.

Сохраняются только getNormalBounds/isMaximized главного окна и только после его показа.
Выход — единый контроллер: отменить старт и подключение, убрать заставку, остановить свой
сервер, сохранить окно, `cookies.flushStore()`, затем `app.exit(code)`. Отказ старта или
рабочей фазы — диалог без родителя, строка `GrigDesk: …` в stderr и код 1.
Дочерние окна используют общий Session и guards, отдельный вход не запускают.

Версия desktop — 0.1.0. Build готовит новый комплект в staging и собирает main.cjs через
esbuild для Node 24; Electron остаётся external, icon.png и ресурсы заставки
(`dist/splash/`) копируются после bundle.
В комплект включён [неизменяемый web-интерфейс](packaged-ui.md) в resources/ui.
Mobile renderer и preload не собираются. Dist-рецепт выпускает только Linux x64
AppImage, без обновления зависимостей. Конфигурация упаковки включает шифрование
cookie и выключает runAsNode, NODE_OPTIONS и CLI inspector. Эти четыре fuses
подтверждены в linux-unpacked и ELF, извлечённом из готового AppImage.
[Проверка пакета](../testing/desktop-window-package.md) подтверждает штатное закрытие,
шифрование постоянной cookie и восстановление после перезапуска linux-unpacked.
База в проверенном пакете — `Partitions/grigdesk-local/Cookies` внутри его userData.
Прямой запуск AppImage требует FUSE и при отсутствии `/dev/fuse` остаётся NOT RUN.

## Установка и ярлык

`grigdesk-ctl desktop install` требует уже собранного
`desktop/release/grigdesk-desktop-<версия>-x86_64.AppImage` текущей версии manifest.
Node берётся из явного GRIGDESK_NODE_DIR либо PATH; установка не читает .env и не
запускает сборку. При отсутствии файла команда возвращает 1 с подсказкой
`npm --prefix desktop run dist`, сохраняя прежнюю установку.

Окно ставится как программа копии: общий путь `deploy/lib/desktop-app.sh` —
`<физический корень копии>/bin/grigdesk-app`, тот же AppImage без расширения в имени. Так все
исполняемые файлы, как и в готовом архиве выпуска, лежат в `bin/`. `runtime.json` и метка
`data-home` остаются в `$XDG_DATA_HOME/grigdesk/desktop` (пустой XDG_DATA_HOME — HOME/.local/share).
Перед заменой файла install пишет `runtime.json` версии 1 установленного сервера; после замены
явная `GRIGDESK_HOME` сохраняется в `home` descriptor версии 2
([описание установки](../server/desktop-owned-server.md)). Копирование
идёт в скрытый `bin/.grigdesk-app.XXXXXX`, chmod 755, затем атомарный mv. При отказе удаляется
только собственный temporary, прежний файл сохраняется. После успешной замены install удаляет
окно с прежнего места `$XDG_DATA_HOME/grigdesk/desktop/grigdesk-desktop.AppImage` (открытое
старое окно продолжает работать) и вызывает `deploy/shortcut.sh refresh`: существующие файлы
ярлыка получают новый Exec, отсутствующие не создаются; отказ ярлыка только печатает
предупреждение. `remove` удаляет окно в `bin/`, прежний файл, `runtime.json` и метку,
сохраняя профиль и настройки. `status` печатает `installed`, `path` и `runtime` через TAB;
status, remove и неизвестная команда не требуют Node, неверная команда возвращает 2.

С установленным окном и его `runtime.json` ярлык ведёт прямо в `bin/grigdesk-app`: окно само
поднимает сервер. До установки (переходный режим) ярлык ведёт в `deploy/shortcut.sh open`:
скрипт вызывает `bin/grigdesk-ctl open` с каталогом Node первым в PATH. Команда запускает
установленный файл отвязанным процессом с единственным
`--grigdesk-url=http://127.0.0.1:<порт>/` до обращений к systemd или сети, затем при необходимости
запрашивает запуск службы. Окно показывает заставку и подключается само. Если окна нет,
CLI предлагает `grigdesk-ctl desktop install`, но всё равно запрашивает запуск сервера. Отсутствие
графического сеанса также не отменяет этот запрос. Отказ показывается уведомлением с причиной
из stderr. Файл `.env` находится в папке данных (или задан `GRIGDESK_ENV_FILE`).
Ключ окна из `.env` передаётся отдельно, остальное содержимое файла не экспортируется.
При вызове из cgroup службы сторож требует `--force` ещё до внешних эффектов.

Проверки установки и лаунчера используют копии CLI и фальшивые файлы/команды в
собственных HOME/XDG, включая пробелы и кириллицу; настоящая установка не проверялась.

Проверки: `tests/desktop/{connection,settings,window-security,offline,menu,auto-login}.test.js`,
`connection-lifecycle.test.js`, `storage-protection.test.js`, `build-contract.test.js`
через memory guard. Отдельная проверка `tests/desktop/e2e/isolation.test.mjs` подтверждает
одноразовые HOME/XDG, D-Bus, GNOME Keyring, Xvfb и уборку собственных процессов.

CLI и ярлык: `tests/server/{desktop-install-script,launch-script,shortcut-script}.test.js`,
`tests/cli/{entry,server,open,relay-status,cli-link,readiness}.test.mts`.
Новый текст заставки появляется после пересборки и установки окна человеком.

`tests/desktop/e2e/window.e2e.mjs` подтверждает sandbox и отсутствие Node/preload,
видимые защищённые дочерние окна с общей сессией, внешние ссылки/redirect,
разрешения notifications и отказ geolocation, offline/reload recovery и single-instance.
Настоящий изолированный GrigDesk входит по ключу без пароля, открывает оболочку и SSE;
без ключа появляется локальный отказ и автоматический повтор. Потеря сессии запускает
новый вход по ключу; действующая cookie не создаёт новую сессию после перезапуска.
Нормальные размеры переживают закрытие, дочернее окно их не перезаписывает.
Maximized в Xvfb без оконного менеджера не проверен. Показ уведомлений Linux и
настоящий микрофон требуют ручной проверки.

## Сохранённые модули прежнего клиента

`desktop/src/identity.ts` и `selfSignedCert.ts` сохраняют ключ EC P-256,
самоподписанный сертификат и electronSealer для системной связки ключей.
Сохранены тесты `identity-store`, `self-signed-cert`, `node-link`; PhoneEmulator
остаётся инструментом мобильных проверок. Локальное окно использует серверный
ключ и обычную сессию вместо прежней привязки телефона. Mobile renderer,
preload, старые IPC/media entrypoints и grigdesk-media сняты после архива.
