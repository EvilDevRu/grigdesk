# Проверка чата с полным сервером

Читай при проверке доставки ответов, сохранения истории и восстановления клиента.
Используется отдельный сервер с искусственными данными и изолированными настройками,
журналами и авторизацией. Рабочие переписки и личные конфиги не входят в fixture.

## Настоящие границы

Маршруты, auth guard, SSE, хранилище, pending и ACK должны быть настоящими.
Внешний исполнитель может заменяться управляемой fixture без запросов модели;
отчёт явно перечисляет подменённые части. Тест с такой подменой не подтверждает
поведение живого провайдера.

Текущий клиент использует [приложение и сессию окна](../server/desktop-only-access.md).
Для dev-проверки действует [авторизованный транспорт Vite](browser-grigdesk-auth.md).
Старые сценарии первичной установки пароля и reload через Service Worker сняты вместе
с браузерной установкой; они не являются инструкцией проверки текущего клиента.

## Сценарии

1. Закрытый API до авторизации и успешный обмен штатного клиента.
2. Лёгкий список, адресная загрузка большой modern/legacy-истории, Markdown и тела шагов.
3. Сохранение черновика по refs без повторной передачи подтверждённых тел.
4. Новый ход, переключение чатов и уточнение во время работы исполнителя.
5. Durable финал, отсутствие повторного ответа и снятие pending после записи.
6. Reload и reconnect: сохранение финала, старых шагов и настроек.
7. Архивирование, возврат и поиск текста за пределами превью.
8. Конфликт refs: сохранность канонических серверных шагов и ограниченный полный повтор.

Содержимое сохранённых сообщений сравнивается с seed целиком. Каждый ожидаемый HTTP-отказ
связывается со своим URI, кодом и сценарием; общий список ошибок не подавляется.
Окружение fixture включает runtime её CLI: отсутствие Node в PATH не является отказом модели.
Связанная ловушка — [ошибка stdin при запуске Claude](../chat/claude-startup-pipe-error.md).

Проверки оболочки перечислены в [проверках единого приложения](../testing/unified-client-checks.md).
Задержки измеряются [отдельным стендом](chat-performance-checks.md); успешный smoke
не подтверждает производительность и не означает обновление рабочего сервера.
