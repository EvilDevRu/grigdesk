# Проверка чатов на отдельном полном сервере

Проверено 01.10.2026 после [исправления фризов](chat-freeze-fix-results.md).
Отдельный экземпляр полного `server/src/app.ts` слушал выделенный системой порт
на loopback. В видимом Chromium открыта обычная production-страница `/chats`.
Итог: десять групп функциональных проверок прошли, код выхода 0; экземпляр
штатно завершился с кодом 0, его порт закрылся.

## Изоляция и настоящие части

Стенд получил отдельные каталоги истории, настроек, авторизации, журналов,
factory state/control/config, профилей, медиа, TLS, showcase и интеграций.
Окружение создано заново; рабочий `.env` и домашние конфиги не использовались.
Копия исходников меняет `rootDir`, чтобы проектные сканеры читали только стенд.
Служба релизов получила собственный пустой тестовый Git-репозиторий без remote.

Сервер собран обычным entrypoint: auth guard, маршруты, Fastify, SSE, хранилище,
canonical pipeline, pending ACK и статическая production-сборка настоящие.
После входа через UI браузер получил `historyStepReuseProtocol: 1`.
Ответы HTTP API не подменялись. После reload страницу контролировал настоящий
Service Worker. Сравнение всех 669 файлов `server/src`, `shared` и `web/dist`
подтвердило совпадение копии с рабочими файлами.

Внешний CLI Claude заменён управляемым исполняемым файлом: он отдаёт события
инициализации, текста, вызовов инструментов, результатов и финала через stream-json.
CLI имеет синтетический каталог, который проверяет настоящий адаптер. Команды
инструментов не выполнялись, запросов к модели не было. Учётка GrigDesk временная;
рабочая переписка не использовалась. Chromium запущен с новым профилем.

## Проверенные сценарии

В истории 80 искусственных чатов. У modern-чата и legacy-чата по 50 старых
лент из 150 шагов: по 7500 шагов, включая одинаковые legacy-тексты с разными лентами.

1. Первичная настройка пароля через UI, закрытый API до входа, получение capability.
2. Modern-история: Markdown, старые ленты и раскрытие тела результата инструмента.
3. Запись черновика через sparse PUT с 50 refs без повторной передачи старых тел.
4. Новый ход: ввод, переключение туда/обратно и автоматическая перестановка списка.
5. Уточнение в активный CLI и отдельный ответ до финала исходного хода.
6. Durable финал с 16 новыми шагами, один финальный ответ, снятый pending.
7. Reload через Service Worker: восстановлены финал, старые и новые шаги.
8. Три последующих сохранения modern-чата снова используют refs без старых тел.
9. Legacy: запись черновика, перенос в архив и возврат; сообщения и шаги совпадают.
10. Поиск уникального текста в конце длинной реплики, за пределами превью.

Старые сообщения обоих больших чатов сравнивались целиком через `deepEqual` с
исходной durable-историей, включая каждое тело шага. Это проверка содержимого JSON,
а не сравнение физических байтов файлов.

За сценарий было 13 PUT отдельных чатов: 11 sparse и 2 full. Один named409
`chat_steps_changed` восстановлен полным PUT того же снимка с прежней revision.
Проверка сопоставляет отказ и успешный повтор по чату и revision. Все три записи
после нового хода и reload были sparse; полного повтора на каждый успешный ACK нет.

Итоговые `errors` и `failures` пусты. Семь ответов 400/503 фоновых B24-ручек
учтены отдельно как ожидаемые для пустой интеграции: URI, статус и код ошибки
проверяются явно. Общие сетевые ошибки, ошибки чатов, JavaScript и остальные
ошибки консоли проверяются. Все восемь сообщений `Failed to load resource` дополнительно
сопоставлены с семью ожидаемыми B24-ответами и одним восстановленным 409; неизвестных
ошибок ресурсов нет. Самостоятельные замеры задержек этот прогон не делает;
таблица производительности остаётся результатом отдельного браузерного стенда.

## Обнаруженная граница запуска CLI

При подготовке окружения тестового CLI в `PATH` не был включён каталог Node.
Исполняемый файл с `#!/usr/bin/env node` не запускался, а запись в закрытый stdin
привела к необработанному `EPIPE` и завершению отдельного сервера. Для итоговой
проверки исправлено окружение стенда. Участок `_claudeStream.ts` совпадает с HEAD
и не менялся в исправлении фризов; это отдельный подтверждённый дефект, а не
основание обещать отсутствие любых ошибок. Подробности и статус — в
[ошибке канала запуска Claude](../chat/claude-startup-pipe-error.md).

Перед успешным прогоном исправлялись также комплект копии (`VERSION` и собственная
Git-ревизия), переход из страницы входа в чаты и локаторы сценария. Превью слева
не считается вторым финальным сообщением; действия строки открываются наведением,
переключатель архива нажимается через свою видимую label. Продуктовые файлы при
этой проверке не изменялись. Диагностический preload запуска CLI в итоговом прогоне
не использовался.

Артефакты находятся в `~/.grigdesk/artifacts/chat-runtime-smoke/` вне git:
`run.mjs`, `browser-check.mjs`, `fake-claude.mjs`, `run.log`, `run.exit`,
`results.json`, `browser-network.json`, `source-check.json`, `final-check.json`
и локальные снимки экрана.
Неуспешные подготовительные попытки сохранены отдельно. Снимки содержат сведения
локального интерфейса и не помещаются в общую документацию.

Рабочий экземпляр сервера не перезапускался. Проверка отдельного экземпляра
не включает новую серверную часть в рабочем окне и не заменяет его штатное обновление.
