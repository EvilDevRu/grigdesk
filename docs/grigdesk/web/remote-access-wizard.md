# Мастер удалённого доступа

На странице `connections.devices` компонент `RemoteAccessPanel` расположен рядом с
прежними способами связи и устройствами. Создание и восстановление — немедленные операции,
они не входят в Apply. Ручной env/legacy QR и управление устройствами сохраняются отдельно.

Форма показывает выбранный домашний сервер. Дополнительные параметры разделяют SSH,
публичный маршрут и проверочный адрес нового VPS. Host key проверяется до ввода пароля
либо выбора файла ключа. После предпроверки показан список изменений; установка требует
отдельного подтверждения. Используются общие UiDialog/UiField/UiPasswordInput/UiFilePicker.
Кнопки открытия мастера остаются смонтированными под модальным слоем: после Escape
общий диалог возвращает фокус кнопке в настройках, а само окно настроек остаётся открытым.

Секреты остаются в компоненте и уходят binary body без автоматического повтора. Pinia
хранит только публичные DTO задания. Закрытие формы, смена profile/auth scope и unmount
очищают секреты и отсекают поздние ответы. Принятое задание живёт на сервере.

Общий SSE `mobile-changed`/hello/reconnect вызывает чтение снимка; собственный EventSource
не создаётся. Исторический ready не заменяет текущую связь: offline запись остаётся
доступной для восстановления. Удаление маршрута и личности требует отдельного подтверждения
и не отзывает устройства. Готовность relay не подтверждает подключение телефона.

QR открывается общим телефонным диалогом для выбранного relay. При новом адресе мастер
направляет в обновление маршрута прежнего профиля. Оболочка без routeUpdate сохраняет
прямое изменение адреса; Android следует обновить поверх прежней установки.

Серверный контракт: [журнал и SSH](../server/relay-setup.md).
Телефон: [сохранение ключа при обновлении](../mobile/phone-access.md).
Реальный VPS, камера и внешняя сеть телефона требуют отдельной эксплуатационной проверки.
