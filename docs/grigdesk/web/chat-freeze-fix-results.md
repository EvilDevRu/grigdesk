повторная передача подтверждённых шагов и регулярная пауза отложенной записи устранены.

групп проверок [полной production-страницы на отдельном сервере](chat-runtime-smoke-check.md).
Остаются ручное включение серверной части и проверка рабочего окна после обновления.
Первичная загрузка, первая передача новых больших данных
и полный fallback после конфликта сохраняют отдельную стоимость, описанную ниже.

Дополнительно устранены источники поздней паузы, обнаруженные при проверке:

- `ChatList.vue` переиспользует один `Intl.DateTimeFormat`.
- [Кэш служебных проекций](../chat/chat-save-projection-cache.md) повторно использует
  JSON страховки и отпечаток неизменённых чатов. Vue отслеживает вложенные правки,
  замену источника, добавление и удаление полей сообщения.
- Обычное автосохранение пишет страховку, затем начинает PUT в отдельной задаче
  браузера. Очередь берёт свежие данные; принудительный flush остаётся немедленным.
- [Blob для PUT истории](chat-history-request-body.md) уменьшает синхронную стоимость
  передачи готового JSON в `fetch`, сохраняя тело, заголовки и правила повторов.

CAS, canonical protection, проверки модели/workspace, snapshot, сортировка,
поиск и durable pending ACK сохранены. Контракт протокола описан в
[повторном использовании шагов](../chat/history-step-reuse.md).

с разными лентами. Для каждого из восьми событий выполнены пять свежих context
по двадцать измерений после прогрева: всего 1600 событий в каждой сравниваемой версии.

используемый `web/dist`; CPU throttling отключён.

Прежние `~/.grigdesk/artifacts/chat-freeze-fix/` не перезаписаны. Их промежуточный общий
прогон был красным из-за учёта ожидаемого 409; отдельная проверка boundaries не
делала его зелёным. Актуальный driver записывает частичные режимы в отдельные
файлы и исключает только ожидаемый конфликт заданного сценария и URI. Итоговая
серия содержит десять отдельно учтённых ожидаемых 409, других ошибок нет.

## Отложенная запись и взаимодействие

До дополнительных правок быстрый рендер скрывал отдельную повторяющуюся паузу
`_persist.write`: snapshot, отпечатки и строковый `fetch` складывались в один callback.
Профили сохранены отдельно; кэш проекций и разделение задач убрали повторную
обработку остальных чатов, Blob сократил передачу готовых байтов. Пауза не скрывается
увеличением debounce или отключением страховки.

В каждой итоговой истории 100 блоков и 100 правок draft дали ровно 200 sparse PUT.
Всего — 400 сокращённых сохранений, каждое с 50 refs, без полных PUT и без тел
подтверждённых старых шагов. Полных GET на успешную запись нет. Приёмник сравнил
сохранённые тексты, порядок и тела с исходной искусственной историей.

| История | Запись | JSON после: медиана / p95, мс | JSON + Blob: медиана / p95, мс |
| --- | --- | ---: | ---: |
| Modern | Блок | 3,4 / 7,5 | 6,1 / 10,9 |
| Modern | Draft | 3,5 / 6,0 | 6,5 / 9,8 |
| Legacy | Блок | 5,9 / 9,4 | 11,7 / 16,9 |
| Legacy | Draft | 6,1 / 9,6 | 12,2 / 17,1 |

Прежняя сериализация полного PUT занимала медианно 68–84 мс. Legacy сохраняет
более крупные refs: fallback-ключ сообщения содержит текст. Его идентичность
не сокращалась эвристикой; позиции и проверки базы сохранены.

Блок от события до ACK занимает медианно 593 мс modern и 608 мс legacy вместо
3098 и 3039 мс. Это включает debounce и сервер; длительность ACK не является
непрерывной блокировкой страницы. Медиана обработки успешного PUT приёмником —
200 и 172 мс: чтение, слияние, durable запись и подтверждение остаются работой сервера.

Ввод проверялся через Playwright во время SSE: медиана / p95 modern
305,4 / 332,6 → 18,7 / 32,3 мс; legacy 303,9 / 375,0 → 19,5 / 32,7 мс.
Переключение и повторный монтаж: modern 266,9 / 281,9 → 173,4 / 178,6 мс,
legacy 272,9 / 282,1 → 174,1 / 184,9 мс. Это время действия Playwright с ожиданием
DOM, не самостоятельная синхронная задача на 174 мс.

## Граничные сценарии

По пять отдельных свежих страниц на вариант истории. Медиана / p95, мс:

| Работа | Modern до → после | Legacy до → после |
| --- | ---: | ---: |
| Разбор cold JSON | 24,6 / 27,0 → 21,3 / 22,1 | 23,0 / 29,6 → 21,5 / 22,0 |
| Монтаж после разбора | 534,9 / 588,4 → 412,3 / 415,0 | 295,6 / 326,7 → 214,8 / 226,3 |
| Cold до paint, включая fetch | 1037,5 / 1101,4 → 849,8 / 870,7 | 984,2 / 1110,6 → 818,8 / 827,9 |
| Владение новой лентой из 150 шагов | 0,6 / 0,9 → 0,7 / 1,0 | 0,7 / 1,0 → 0,9 / 1,0 |
| JSON записи новой ленты | 81,1 / 88,1 → 4,7 / 5,8 | 78,1 / 82,2 → 6,2 / 8,4 |
| JSON полного conflict fallback | 80,5 / 87,0 → 79,9 / 89,5 | 85,3 / 92,2 → 84,7 / 115,4 |

В cold-замерах parse, mount и paint ненулевые и действительно измерены;
чтение тела и parse разделены. `parseMs: null` означает неизмеренную работу,
а `jsonReadMs` — совместное чтение/разбор альтернативного `Response.json`.
В этой серии применился путь `.text()` с отдельным `JSON.parse`.

Новая лента впервые отправлена целиком, старые 50 лент — по refs. После изменения
серверной revision получен один 409, затем один полный PUT того же снимка;
сохранённая история после обоих сценариев проверена целиком.

**Полный fallback всё ещё блокирует поток:** JSON вместе с Blob занимает
медианно 138 мс modern и 145 мс legacy, p95 — 156 и 202 мс. Это редкая граница
восстановления, а не постоянный путь после каждого ACK. Очень большая новая лента
тоже потребует первой полной сериализации. Worker и дельты сообщений не реализованы.

Построение `historyStepReuseAck` отдельно измерено на тех же 50 лентах после прогрева:
при общих ссылках медиана 0,04 мс modern и 0,11 мс legacy; при равных, но отдельно
скопированных массивах — 43,5 и 46,8 мс, максимум около 48 мс. Второй вариант
действительно сравнивает JSON тел на сервере. Это микрозамер builder, не измерение
всего запроса или доказательство, что canonical pipeline всегда сохраняет ссылки.

## Функциональные проверки и включение

Связанная группа проверяет materialize, draft, Markdown, timeline, сохранение,
coalescing, reload, archive, workdir, CAS, pending, строгие refs, canonical pipeline,
старый сервер и rollback, поздние ACK, неизменяемое владение шагами и вложенными
метаданными. Дополнительные тесты проверяют кэш служебного JSON, квоту, порядок
страховки/PUT, немедленный flush и прежние JSON-байты в Blob.

Общий `TEST_JOBS=4 bash tests/run-all.sh` завершился с кодом 0: прошли layout,
49 проверок документации, офлайн-проверки движка, 3309 серверных и 1667 веб-тестов,
проверки типов, UI, стилей, SFC и читаемости. Lock исключил параллельный общий запуск.
После зелёного прогона выполнен `npm --prefix web run build`, код выхода 0.
Хэши 15 основных продуктовых файлов и driver совпадают с итоговым браузерным manifest.

После этого поднят отдельный полный сервер с копией той же production-сборки.
Через видимый Chromium проверены вход, новый ход, уточнение, durable ACK, reload
через Service Worker, повторные sparse записи, legacy-архив и полнотекстовый поиск.
Старые сообщения и по 7500 шагов каждого большого чата совпали с исходной историей;
сохранились все 16 новых шагов, финал один. Подготовка стенда выявила отдельный
[необработанный EPIPE при неудачном запуске CLI](../chat/claude-startup-pipe-error.md),
который не менялся этим исправлением и остаётся открытым. Это ограничение уверенности
в общем запуске агента; итоговая проверка здорового CLI прошла.

До этого общий прогон выявил неактуальный снимок миграции и отдельный data-URL
загрузчик тестов слэш-команд, не разрешавший новые импорты. Снимок дополнен только
файлами этого исправления, загрузчик использует настоящие новые helpers; все пять
тестов слэш-команд прошли. При большем параллелизме движок дважды достигал таймаута
`bootstrap-sandbox`; отдельно его 32 проверки и итоговый общий прогон прошли.
Код движка, таймауты и assertions не менялись.

Сервер самостоятельно не перезапускается: согласно [CLAUDE.md](../../../CLAUDE.md)
«перезапуск изнутри такого хода убивает исполнителя и ответ». Агент чата является
дочерним процессом сервера. Человек вручную перезапускает сервер и обновляет окно
штатной кнопкой «Обновить». До получения новой capability окно совместимо со старым
сервером и отправляет полный PUT, поэтому ускорение повторной передачи steps ещё
не включено. Живое пользовательское окно в этом исследовании не профилировалось.
