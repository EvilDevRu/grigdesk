# Порядок снимков доски

Главное окно может читать dashboard, пока человек меняет задачу в отдельной карточке.
Если снимок после действия уже принят, поздний ответ прежнего чтения не должен откатывать
таймер или другие поля доски ни в главном окне, ни в карточках.

`board.load` фиксирует `readAt` перед GET. Метка строго больше метки уже показанных данных,
даже при двух чтениях в одну миллисекунду. Ответ применяется только при `readAt` больше
текущего. Ошибка старого запроса также не заменяет состояние более нового снимка.
`loadedAt` означает время применения данных для обычного кеша; ожидание базовых отметок
просмотра не меняет `readAt` и не повышает свежесть снимка.

Успешный `load` возвращает метку принятого ответа. Связь окон публикует снимок только
при совпадении этой метки с текущей меткой доски. Отброшенный ответ не публикуется;
снимок другого окна, принятый во время GET или ожидания отметок просмотра, не получает эхо.
Дополнительного чтения dashboard при отбрасывании нет: обычный опрос остаётся в главном
окне, карточка читает доску после своего действия.

Реализация: `web/src/stores/board.ts`, `web/src/App.vue`; сообщения описаны в
[контракте связи окон](window-relay.md). Проверки зеркала и собственного действия —
`tests/web/board-mirror.test.js`, формы relay — `tests/web/window-relay.test.js`.


## Подтверждённый источник и ошибка обновления

Снимок принадлежит выбранной машине, auth clientScope и выбору внешнего трекера:
`externalId` и `revision` из локального каталога `/api/trackers`. В ключе нет пароля или cookie. Он живёт
в памяти и доверенном same-origin relay вместе с данными, в диагностику не попадает.
Перед чтением и принятием GET владелец подтверждается локальным `/api/trackers`.
Перед сохранением данных после ошибки проверка повторяется. Непроверяемый или
сменившийся источник не получает прежний снимок как fallback.

Смена машины, clientScope, потеря входа и начало записи credentials очищают снимок
и увеличивают эпоху HTTP. Во время записи load и relay не применяют данные;
исход записи снимает только собственную паузу и заново проверяет настройки.
Неизвестный исход POST не вызывает повтор мутации. Force refresh во время чтения
откладывается и объединяется до начала следующего чтения, сохраняя обновление после действия.

Relay передаёт sourceKey и отдельное сообщение board-source-invalidated с suspended.
Ключ из сообщения не назначает владельца зеркала: несовпадение запускает локальную
проверку и запрос снимка, без своего dashboard GET. Старый формат снимка без sourceKey
отвергается. Все окна после обновления приложения следует открыть с новым интерфейсом.

При ошибке обновления того же подтверждённого источника задачи остаются видимыми.
Над ними показаны причина ошибки, предупреждение о последних полученных данных и время
readAt в элементе time. Успешное обновление снимает предупреждение. Первая ошибка без
снимка показывает причину, не выдавая пустую доску за загруженные данные.
Кэш Pinia относится только к текущей сессии; сохранения на диск и серверного cache API нет.

Проверки: `board-source.test.js`, SOURCE-APP в `app-settings-window.component.test.js`
и `board-stale-snapshot.component.test.js` в `tests/web/`.
