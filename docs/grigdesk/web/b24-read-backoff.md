# Паузы чтения Б24 при отказах

Общий API-клиент сериализует `GET /api/tracker/*` по шаблону маршрута. Все потребители
`/api/tracker/task/:id`, включая карточку и полку с разными номерами задач, разделяют
одну очередь и паузу; query не создаёт новую очередь. Dashboard и комментарии
имеют независимые очереди. Область состояния — один документ окна.

После сетевого обрыва, таймаута либо HTTP 502/503/504 следующая попытка маршрута
ждёт 2, 4, 8, 16, 32 и затем 60 секунд. Пауза относится и к встроенному повтору,
и к новым вызовам из других компонентов. Успешный ответ сбрасывает паузу.
Обычный GET допускает один встроенный повтор; опрос доски и гидратация полки
выключают его, поскольку обновляются своим циклом. Мутации не повторяются.
Неуспешный ответ с HTML сохраняет HTTP-статус, поэтому 502 прокси подчиняется
той же политике, что JSON-ответ сервера.

`AbortSignal` отменяет ожидание очереди, паузу и текущий fetch. Смена или закрытие
карточки, а также её unmount отменяют загрузку деталей и комментариев. Остановка
опроса доски отменяет текущее чтение; смена области, выключение и остановка полки
отменяют гидратацию. Поздние ответы не заменяют сохранённые данные. Опрос доски
принадлежит оболочке и остаётся активным на других страницах для счётчиков задач.

Для отказов чтения Б24 общий клиент пропускает в журнал окна не более одной
`api.fail` на шаблон маршрута за скользящие 60 секунд. Длительность, номер попытки,
query и task id этого ограничения не меняют. Подавленная ошибка по-прежнему
возвращается потребителю и помечается обработанной, чтобы `store.error` её
не дублировал. Отмена активного запроса человеком не записывается как сбой API.

Проверки: `tests/web/b24-read-backoff.test.js` использует управляемые часы и реальный
API-клиент: экспоненциальные паузы, общий маршрут разных задач, HTML 502, предел
журнала, сетевой отказ, отмена очереди/повтора, сброс после успеха и остановка доски.


## Два разрешения для GET Б24

Помимо очереди шаблона маршрута документ имеет две полосы: одну для портала и одну
для локальных `task-favorites`, `task-seen`, `task-shelf`. Query не создаёт новую полосу,
прочие GET Б24 считаются портальными. Разрешение удерживается до чтения и разбора тела,
освобождается при успехе, ошибке и отмене. Отменённое ожидание не начинает поздний fetch.

Backoff ожидается до получения разрешения. Поэтому пауза одного маршрута не блокирует
другой. Обычный API и POST/PUT/DELETE не проходят эти полосы; новые повторы мутаций
не добавлены. Правило одинаково для браузера, desktop и Android, без проверки UA.
Две полосы вместе с SSE и shell оставляют место обычному API в HTTP/1.1.

Проверки: `tests/web/b24-read-capacity.test.js` и `b24-capacity.browser.test.js`.
Первая удерживает тело и проверяет отмену, вторая запускает настоящий apiClient
в Chromium при удержанных ответах портала и оболочки.
