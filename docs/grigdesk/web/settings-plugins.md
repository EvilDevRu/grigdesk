# Параметры плагинов в общей сессии

Страница `plugins.installed` сохраняет параметры, размещения и enabled через общий Apply.
Черновик не меняет работающий плагин. Ресурсы сортируются по ID плагина, затем settings → enabled.
В PUT передаётся полный набор ключей текущей схемы: baseline с изменёнными значениями и
placements. Сервер заменяет values целиком. Подтверждением служат только поля ответа сервера.
Store возвращает явные failed/conflict/unknown и не выдаёт исчезнувший плагин за успех.

После успешного переключения needsRestart показывается «Ждёт перезапуска».
Установка и подготовка остаются отдельными немедленными операциями. Смена схемы, несовместимая
с неприменённым полем, блокирует его с причиной; исчезнувшее поле остаётся dirty до отмены.

Модель хранится целой парой {provider,model,effort?}; option адресуется без разбора двоеточий.
Пропавший выбор остаётся видимым. Перенос effort на новую модель допускается только для
объявленного уровня; пустой выбор удаляет ключ effort. Пустой список providers означает всех.
Число валидируется до записи, пустая строка не становится нулём. Secret/password помечаются
секретными полями сессии; значения не попадают в поисковый индекс или public snapshot.

Список сохраняет поиск и пересечение фильтров состояния, наличия параметров и пользовательских
плагинов в памяти сессии. Выбор другого элемента и повторное посещение не теряют черновик.
Обычные параметры отображаются в странице без дополнительного диалога.

Установка использует прежний PluginInstallDialog и общий durable installer store. Переход
на другую страницу или закрытие настроек не отменяет job. Источник, сверка и откат используют
прежний PluginSourcePanel с revision/digest, request UUID и recovery guards. Health показывается
над списком, recovery блокирует новые переключения и установку. Страница `plugins.install`
открывает существующий сценарий установки через общий вложенный стек.

PluginSetupPanel получает baseline enabled сессии, включая время ожидания ACK тумблера.
Черновой enabled не запускает setup. Серверное задание отменяется только отдельной кнопкой.
Уход abort-ит своё чтение и снимает timeout, поздний GET после отмены блокирует epoch.
Возвращение перечитывает серверный результат; закрытие UI не отменяет подготовку.
