# Откуда берётся тёмное поле переименования чата

В списке слева `ChatList.vue` заменяет строку на публичный `UiInput` при нажатии
карандаша или двойном нажатии на строку. Native input принадлежит общему primitive;
локальный класс `.edit` задаёт только ширину. Этот переход выполнен в коммите
`9b5659923`: прежний native input и его локальный skin удалены.

Почти чёрный фон сохраняет действующая цепочка общих стилей:

1. `styles/components/fields.css`: `.ui-input` получает
   `background: var(--control-background)`.
2. `styles/tokens.css`: обычный `--control-background` ссылается на `--ground`.
3. `--ground` равен `#0a0c10`.

Список и его родитель `ChatsView.vue` не включают `data-ui-workspace`, поэтому
рабочий фон `--surface-2` здесь не наследуется. У поиска сверху есть отдельный
контекст `chat-list-search`, который уже задаёт `--surface-2` (`#1c222c`).
Одинаковый раздел поэтому содержит поля с разной поверхностью. Это сохранённый
базовый дизайн UI-kit после миграции компонента, а не оставшийся legacy control.

Переименование в шапке открытого разговора — другой экземпляр `UiInput` в
`ChatSession.vue`. Его `data-role="chat-title"` явно задаёт `background: var(--ground)`
в `fields.css`. Правило этой роли не охватывает редактор списка. Изменение только
базового токена не уберёт явный тёмный фон поля в шапке; изменение только роли
`chat-title` не затронет список. Skin обоих мест принадлежит общим стилям UI.

Синтетическая компонентная фикстура с настоящими `ChatList`, `UiInput` и текущими CSS
подтверждает фон редактора `#0a0c10`, фон поиска `#1c222c`, фокус и выделение названия.
Computed CSS в Happy DOM не заменяет проверку отображения в Chromium/WebView.
Общие режимы описаны в [режимах controls](control-regimes.md).
