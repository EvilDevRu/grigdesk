# Правильный снимок не доказывает показ native-вида

При живой проверке пользователь видел пустую область страницы при сохранённых
вкладке и адресной строке. В это же время snapshot отдавал DOM, native-клик менял
URL, а screenshot возвращал соответствующую страницу. Поэтому проверка JPEG
не заменяет проверку показа WebContentsView в главном окне.

Трасса также показала повторные hide/show при неизменных размерах, видимом
документе, отсутствии тостов и блокирующих слоёв. Подписка UI layer stack получает
события tooltip, хотя `getUiLayerDiagnostics()` исключает его из блокеров.
`BrowserViewport` теперь скрывает вид при событии слоя только при действительном
блокере, а одинаковую геометрию повторно не публикует. Смена размеров, тосты и
модальные слои по-прежнему сначала скрывают native-содержимое.

Регрессия `VP01` проверяет отсутствие hide/layout при открытии и закрытии tooltip;
`VP02/VP03` сохраняют границы mount и синхронное скрытие при оповещении.
Связь лишних hide/show с исчезновением содержимого пока не доказана. Изменение
размера окна при живой проверке дало лишь одиночное мерцание; содержимое не
восстановилось.

Следующая живая проверка подтвердила фактическое прикрепление: после `show` и в
следующей очереди main вид является единственным ребёнком `contentView`, видим,
имеет правильные размеры, окно видно. Последующего hide нет, но человек видит
пустоту. Новая вкладка, которой ещё не делали screenshot, также пустая. Захват
не является необходимым условием этого симптома; лишние tooltip hide его не
объясняют. Следующая проверка подтвердила правильную геометрию родителя и показ
после [синхронного перехода видимости при прикреплении](browser-visibility-reset.md).
Пользователь подтвердил содержимое до первого снимка и после серии переключений.
Скрытый захват позднее проверен отдельно после
[смены механизма перерисовки CDP](browser-surface-redraw.md), включая чистый пакет
и подтверждение пользователя при открытой панели.
