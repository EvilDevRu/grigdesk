# Старт приложения и готовность местной машины

При обнаруженной оболочке GrigDesk загружает обычный `AppShell`: верхнюю панель,
кнопку машин. Настройки доступны после подключения и подтверждения входа.
Боковая навигация скрыта, пока профиль не выбран;
выбранная машина возвращает её, в том числе при offline. Отсутствие профиля, подключение, потеря
связи, отзыв устройства и несовместимость версий не переключают окно на список машин.
`ConnectionsView` открывается только при явном `shell.showConnections`; возврат к приложению
доступен даже до первого подключения.

При запуске desktop сохранённый выбор машины имеет приоритет. Если выбора нет и доступна
локальная установка, `clientRuntime.start()` выбирает существующий локальный профиль или
создаёт «Этот компьютер» с адресом установки. Выбор сохраняется до открытия трубы. Supervisor
и подключение работают в фоне. Для выбранного local заставка ждёт соединение online,
завершение входа страницы и два кадра готовой рабочей области. Общий предел — 30 секунд
от показа заставки, включая VPN и подготовку переносимой папки. При ошибке или сроке
главное окно открывается с причиной и кнопкой машин; фон продолжает запуск.
Явный местный URL и сохранённый local без установки подчиняются тому же правилу.
Удалённый профиль сохраняет показ после кадра и обычного минимума около двух секунд.
Без локальной установки и сохранённого выбора приложение не придумывает профиль и
открывает пустой каркас после обычного минимума. Поиск установки читает файлы,
проверка произвольного живого порта не добавляет машину.

До первого подтверждённого входа выбранная машина показывает внутри рабочей области
небольшую строку состояния. Без выбранного профиля виден
[начальный экран выбора компьютера](machine-welcome.md) с добавлением и инструкцией;
отдельного полноэкранного экрана запуска нет. Страница маршрута и панели с API монтируются
после авторизации. `AppShell.active` откладывает загрузку плагинов, исполнителей, обновлений
и наблюдателя конвейеров. При последующей потере связи смонтированные страницы и инструменты
сохраняются; обычный цикл восстановления сессии включает опросы после нового входа.
После показа управление машинами доступно во время ожидания сервера. Внутренний offline-каркас
и поведение телефона сохраняются. Повреждённый встроенный UI использует прежний fatal-путь;
ошибки местного сервера открывают каркас без диалога ошибки.

Locked сохраняет постоянный диалог разблокировки и `inert` рабочего дерева. Ошибки привязки,
отзыва и версии по-прежнему принадлежат оболочке, не разрешают API и не получают
автоматических повторов, запрещённых транспортным контрактом. Подробности версии доступны
в списке машин, открытом человеком.

Проверки: `client-startup.test.js`, `app-shell-gate.component.test.js`, `client.e2e.mjs`
и SE-13/SE-16/SE-17 в `startup.e2e.mjs`. SE-17 запускает свежую локальную установку без
`--grigdesk-url`, задерживает сервер и вход, проверяет скрытое main до готовности и рабочую
область при первом показе без ранних запросов API. SE-16 проверяет мягкий срок при закрытом
VPN и восстановление в том же документе. UC-E01 проверяет мягкий показ недоступного явного
local через 30 секунд, UC-E03 — готовность и сохранение DOM/сессии при доступном явном local;
UC-E02 и SE-13 сохраняют быстрый пустой старт.
