# Внешний выбор сервера и местный профиль окна

Сохранённый `runtime.json` остаётся источником выбора сервера при фоновом запуске окна.
Открытие переносимой копии может запомнить прежний ELF в `serverBinary` местного профиля,
но последующий `desktop use-server` для ELF/R или `use-source` имеет приоритет при новом
открытии как установленного, так и переносимого окна. Подготовка запускает текущий
descriptor без проверки прежней привязки, записи выбора и остановки чужого процесса.

Без ручной активации запись descriptor допускается только в двух случаях:

- Описание ещё отсутствует, а рядом с окном найден сервер для первого запуска.
- Серверный вход сохранённого выбора отсутствует с ENOENT/ENOTDIR, а рядом есть замена.

Повреждённый descriptor и ошибки доступа не разрешают автоматическую замену.
`serverBinary` нужен для ручной активации машины через private `beforeSelect`;
возврат A→B→A сохраняет прежние id, порт трубы и настройки origin.

Отдельный профиль соседа сохраняет приватный признак `portable: true` при нормализации
настроек. Он не попадает в публичный shell API и не задаётся renderer. Добавление local
без `serverBinary` через явный URL запуска или POST `/__shell/profiles` с `local: true`
обновляет основной профиль независимо от его ELF-привязки. Id и порт остаются прежними,
а portable-сосед не переименовывается и не получает этот адрес. Если основного профиля
ещё нет, он создаётся отдельно от переносимого.

Сообщение о переносе запускается один раз после успешного старта сервера. Его показ
ждёт появления главного окна, но подготовка транспорта не ждёт закрытия сообщения.
Синхронный отказ или отклонённый Promise показа не переводят готовый сервер в ошибку.

Контракты: [старт окна](desktop-startup.md),
[переносимая поставка](../server/portable-bundle.md).
Проверки: `PB-RETURN-01/02/03` и прежний `PB-SKEP-01` в
`tests/desktop/portable-runtime.test.js`.
