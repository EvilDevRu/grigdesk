# Открепление инструментов

Отдельные окна доступны для Кода, Полки, SSH, БД, Докера и
iframe-страниц плагинов. Кнопка «Открепить» принадлежит шапке дока и доступна главному desktop
документу с возможностью `windows`. Браузер, Android и старые пакеты сохраняют прежний док.
Терминал и внешние module-панели остаются в главном документе; их registry запрещает открепление.

У инструмента один владелец: передача экспортирует явный снимок, снимает старую панель
и только затем открывает окно. До подтверждения init новая панель не монтируется.
Снимок содержит выбор и черновики, но не пароли, вывод терминала, соединения или Pinia state.
Незавершённый commit, подключение или запрос не запускается повторно при переносе.

Native создаёт непрозрачную instance. Повторное открытие поднимает ту же instance без
перезагрузки. Рейка, горячая клавиша, ссылки из чата и маршрут инструмента обращаются к
координатору до локальной очереди. В окне команды идут последовательно, следующая ждёт
consume предыдущей; повтор сообщения не превращается в новый intent. Потерянный ответ
создания сверяется через status, без повторения POST и создания локального дубля.

«Вернуть в колонку» сначала снимает панель окна и передаёт снимок главному документу.
Окно закрывается после подтверждения восстановления. При узком главном окне возврат
видимо отказывается и восстанавливает панель в окне: снимок не теряется. Escape остаётся
инструменту и его вложенным диалогам; за шапку окно можно двигать.

При возврате Кода главный документ сначала загружает каталог проектов и импортирует снимок
в скрытую панель. Показ колонки и подтверждение возврата следуют после импорта: загрузка
не зависит от того, какой инструмент человек открыл в колонке, пока Код был откреплён.

Применены рекомендации утверждённого плана: обычное закрытие снимает открепление и не
открывает колонку автоматически; следующее явное открытие локально. Геометрия сохраняется
отдельно для каждого инструмента и не перезаписывает геометрию карточек. Список открытых
окон и снимки на диск не записываются; при запуске окна сами не появляются. Смена машины,
выход и закрытие главного окна уничтожают окна через общий native lifecycle.

При `window.close()` Electron может прислать `closed` без события `close`. Последняя
геометрия уже снята на move/resize; обработчик `closed` запускает асинхронную атомарную
запись настроек. Проверка сохранения ждёт нужного содержимого файла: само закрытие окна
ещё не подтверждает завершение записи.

Главное окно остаётся источником SSE, оповещений и готовых строк Полки. Окно Полки принимает
полные rows с отдельным номером проекции, а remove и acknowledge исполняет источник.
Контекст окон имеет отдельный owner-token `toolWindow`: локальный источник `tool`
Терминала или внешней module-панели не вытесняет открытый файл Кода. В контекст попадают только подписи,
относительный путь и строка; полный снимок панели хранится отдельно в памяти.

Межоконный канал `grigdesk-tool-windows-v1` адресует сообщения по scope, instance и эпохе
координатора. Плагин выбирается через установленный registry; URL iframe не берётся из relay.
Прежний `/__shell/surfaces/open` остаётся входом только для карточек Б24, а инструменты
используют закрытый control `/__shell/surfaces/tool`.

Проверки: подготовленные `tool-window-*`, `surface-*`, `shell-api` и Electron сценарии
`tool-window.e2e.mjs`; результаты конкретного запуска находятся в отчёте этапа сборки.

Локальный вход без пароля может иметь пустой `clientScope`: готовность определяет
подтверждённая авторизация, а не непустая строка. Пустая область проверяется так же точно,
как именованная. Lazy-заглушка не получает снимок: init ждёт публичный handle самой панели.
Ключ клиентского Docker WS снимает devtools Proxy через `toRaw`, поэтому смена вкладки
и unmount находят тот же сокет, который создал предыдущий action.
