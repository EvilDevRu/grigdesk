# Code/Shelf/Terminal нельзя монтировать отдельно в route и в правом доке

Инструменты stateful: Code держит Monaco, Shelf — реактивные строки и latch событий,
Terminal — xterm, WebSocket и настоящий PTY. Два экземпляра означают расходящееся
состояние, повторные id, двойные события или лишнюю shell-сессию; общий флаг «док когда-либо
открывали» тоже плох — открытие Code тогда поднимает невидимый Terminal.

Владелец один: постоянный `web/src/shared/layout/ToolHost.vue` в `AppShell`. Route-компоненты
`CodeView.vue`/`ShelfView.vue`/`TerminalView.vue` — только пустые адаптеры, а `page`, `dock`, `hidden`
переключают CSS стабильного render-site. Lazy mounted-флаг отдельный у каждого registry id.
Док разрешён с 900 px; при переходе на 899 px он закрывается, непоказанные панели
размонтируются, но queued intent сохраняется. Возврат на широкий экран сам PTY не создаёт.
Разворачивание дока не является route-переходом: runtime-флаг `isExpanded` меняет только
ширину того же dock render-site до ширины content-колонки, не трогая
`dock.width`, URL/history, Monaco/xterm и WebSocket. Повторный клик возвращает обычную
ширину; первый Escape из expanded-состояния делает то же, следующий уже скрывает док.
Выбор хранится по registry id в `expandedPreferences`/`grigdesk-dock-expanded-tools`:
полноэкранный Code не разворачивает Shelf или Terminal. Старый общий
`grigdesk-dock-expanded` при миграции относится только к последнему открытому инструменту.
`close()` снимает активный `isExpanded`, чтобы скрытая панель не оставляла `<main>` inert,
но следующее открытие и первое явное открытие после reload восстанавливают геометрию
именно этого инструмента; сам док после загрузки не показывается. `resetAllRuntime()`
очищает mounted/runtime/intents и закрывает живые панели обычным unmount, но device-local
layout preferences не стирает.
Техническое сворачивание при смене route вызывается с `persist: false` и не переписывает
пользовательскую настройку.
Пока content целиком перекрыт, `<main>` исключён из tab-order через `inert`; смена route
сворачивает expanded, но не закрывает живую панель.
У compact Code навигатор остаётся слева от Monaco; его отдельная сохранённая ширина не
должна переиспользовать full-layout или прежний вертикальный split. Ограничение 42%
считается в JS по фактической ширине `.lay` и тем же значением заполняет CSS и
`aria-valuemax`: один CSS-only clamp оставлял невидимый dead range разделителя.

Hide/show Code обязан обновлять данные без промежуточного пустого состояния. Нельзя перед
activation revalidation вызывать `resetState()`, очищать `dirs` или отвязывать Monaco-модель:
projects/repos/root/раскрытые каталоги/file/git перечитываются поверх последнего валидного
снимка, а свежая модель подставляется до освобождения старой. Очищение допустимо только
после ответа, который подтвердил исчезновение project/context/file. Фоновая проверка также
не показывает индикаторы загрузки, меняющие геометрию header или дерева.
На первом открытии async-компонент тоже не должен оставлять пустой slot: его синхронный
loading-компонент повторяет rail/tree/editor-сетку, но остаётся чистым каркасом без импорта
Monaco. Отдельная маленькая плашка «Загрузка…» снова создаст заметный скачок геометрии.

Terminal intent заменяет прежний `sessionStorage`: очередь exact-once принимает команды и
в уже живой socket, и до lazy mount. В состоянии `closed` все ожидающие команды должны
делить один reconnect и отправляться после первого вывода shell без `\n`. Resize xterm —
не косметика: клиент посылает `{t:'resize', cols, rows}`, сервер применяет `TIOCSWINSZ` и
`SIGWINCH`; helper при закрытии WebSocket обязан убрать всю process group.
