# Обновления драйверов из каталога

Каталог драйверов показывает установленную версию и сохранённые результаты проверки
из `useDriverInstallStore.installed`. Вход читает только GET
`/api/driver-installs/installed`; автоматического сетевого поиска версий нет.
Ошибка этих сведений не блокирует редактирование подключения.

Окно настроек имеет постоянную высоту до 780 CSS px с ограничением по высоте экрана.
Переключение драйвера, режима входа, загрузка и сообщения проверки не сдвигают шапку
и нижние действия: длинное содержимое прокручивается внутри тела. На телефоне остаётся
общая полноэкранная компоновка.

Под каталогом всегда видна кнопка «Проверить обновления». Она использует существующий
POST `/api/driver-installs/check` для установленных пакетов, обновляет их записи
и оставляет редактор с черновиками открытым. Ошибка показана в редакторе.
`TrackerUpdateStatus.vue` одинаково отображает доступную версию, время проверки
и ошибку источника в каталоге драйверов.

В редакторе всегда видна кнопка «Обновить». Она доступна для управляемого пакета
с известным обновлением и без ручных правок. Недоступность общей операции установщика
также блокирует новое обновление. Пакет определяется выбранной строкой каталога,
а не подключением доски: обновление другого драйвера не переключает подключение.

Кнопка передаёт id выбранного драйвера в `TrackerInstallDialog.request` с `kind=update`.
Мастер сначала восстанавливает server-owned job и читает установленные пакеты.
Активная либо неопределённая операция имеет приоритет. Если препятствий нет,
`store.update(id)` подготавливает кандидат и открывает подтверждение; apply требует
отдельного клика. Закрытие и повторный вход не повторяют применение.

Сценарии `TRACKER-SETTINGS-07/08` в
`tests/web/tracker-settings.component.test.js` проверяют видимые действия,
отсутствие автопроверки при входе, выбранный id в update, отдельное подтверждение
и сохранение черновиков при успехе и ошибке поиска обновлений.
