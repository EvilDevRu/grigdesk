# Чтение реестра исполнителей окном

Оболочка читает реестр при запуске и раз в минуту. Список чатов и открытый
разговор также нуждаются в нём для значков и выбора модели. Раньше каждый
`providers.load()` создавал собственный `GET /api/providers`, включая
одновременное монтирование и открытие уже известного разговора.

Теперь читатели одной версии реестра разделяют один запрос. Карта летящих
чтений и статусы используют `toRaw(store)`, чтобы обёртки actions Pinia имели
одного владельца. Завершение запроса освобождает только свою запись.

Компоненты чата вызывают `load(false, { cached: true })`: присоединяются к
текущему чтению либо используют готовый снимок. Обычный `load()` по-прежнему
читает сервер после завершения прошлого запроса, поэтому минутное обновление
не выключается. Явный `load(true)` выполняет `?refresh=1`, имеет приоритет над
обычным GET и объединяет собственных читателей.

`providers-update` вызывает `load(false, { invalidate: true })`. Новая версия
не присоединяется к чтению, начавшемуся до события, и отсекает его поздний ответ.
Смена credentials и reconnect сохраняют прежнюю инвалидацию версии. Координатор
настроек ждёт последнее актуальное чтение и получает его статус ошибки.

Не всякий второй запрос после старта лишний: сервер может сначала вернуть
устаревший или пустой снимок в пределах бюджета, а затем сообщить о готовом
реестре через SSE. Это [штатное фоновое чтение](../server/providers-background-read.md).
Запрос лимитов `/api/providers/usage` также остаётся отдельным от каталога.

Проверки в `tests/web/providers-model-ref.test.js`: объединение трёх читателей,
готовый снимок для монтирования, следующее фоновое чтение, приоритет refresh,
SSE во время GET, ошибка и последующее восстановление, смена credentials и
reconnect. Компонентные проверки настроек сохраняют ожидание после записи ключа.
