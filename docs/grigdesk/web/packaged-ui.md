# Интерфейс внутри пакета приложения

Desktop build собирает web в отдельный staging `desktop/.dist-staging-*`, не трогая
рабочий `web/dist`. Staging лежит рядом с `desktop/dist`, потому что замена идёт через
`rename` в пределах одной файловой системы, а папка данных может быть на другом диске.
После успешной сборки комплект заменяет `desktop/dist`; ошибка
сохраняет предыдущую сборку. Electron-builder включает `dist/ui` как `resources/ui`
рядом с `app.asar`, вместе с AppImage. Сервер и системный Node пока остаются внешними.

`release.json` содержит версию схемы, SHA-256 идентификатор и список файлов с размерами
и SHA-256. Идентификатор вычисляется из содержимого, а не Git SHA: незакоммиченные
изменения также создают другую версию. Перед запуском проверяются все файлы, отсутствие
добавленных файлов и символических ссылок. Manifest не хеширует сам себя.

Приложение атомарно публикует проверенную копию в
`GRIGDESK_UI_RELEASES_DIR/<id>`; по умолчанию каталог — `<папка данных>/state/ui-releases`.
Промежуточные `.pending-*` не обслуживаются сервером. Параллельные запуски принимают
только идентичный проверенный результат. Повреждённый опубликованный релиз не заменяется
поверх открытого окна. Старые версии автоматически не удаляются.

Сервер обслуживает `/ui/<id>/` с private immutable cache, включая относительные JS/CSS
и lazy chunks. Общий модал использует id главного документа; рабочая сборка,
перезапуск сервера и публикация другой версии не меняют их файлы. Новый AppImage выбирает
свою версию при следующем запуске. Адреса релизов защищены общей сессией, включая запросы
с закодированным префиксом. API сохраняет прежний origin и абсолютный префикс `/api`.

До загрузки окна приложение проверяет manifest через свою авторизованную Session.
Несовместимый сервер даёт явный отказ запуска с предложением обновить сервер. Запасного
перехода на рабочий `web/dist` у установленного приложения нет. Dev Electron без runtime
и каталога релизов допускает прежний корневой адрес для HTTP-фикстур.

Ctrl+R, Ctrl+Shift+R и F5 перехватываются в главном процессе для главного окна
и обычных дочерних окон. Команда reload отсутствует в меню. Одиночный Alt
также заблокирован. Редактирование, масштаб и Ctrl+Alt+S сохраняются. Восстановление
сессии после 401 может программно перезагрузить тот же закреплённый документ.

Отсутствующие ресурсы возвращают 404, а не SPA HTML со статусом 200. Ошибка lazy-панели
показывает сообщение; ожидание ограничено 30 секундами. Ошибка навигации выводится общим
toast. PWA, service worker и кнопки обновления документа отсутствуют; Notification и
Screen Wake Lock находятся в `stores/device.js`. Исторические SW-события остаются только
в схеме старых диагностических журналов.

Проверки: `ui-release.test.js`, `ui-releases.test.js`, `menu.test.js`,
`settings-contract.test.js`, `runtime-config.test.js`; сквозной UI-E01 в
`tests/desktop/e2e/window.e2e.mjs` заменяет рабочий dist после открытия окна, загружает
разделы и встроенные панели, проверяет настройки и нативные клавиши.
