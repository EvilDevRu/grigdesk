# Интерфейс внутри пакета приложения

Desktop build собирает web в отдельный staging `desktop/.dist-staging-*`, не трогая
рабочий `web/dist`. Staging лежит рядом с `desktop/dist`: замена через `rename` остаётся
на одной файловой системе. Успешная сборка заменяет `desktop/dist`, ошибка сохраняет
прежнюю сборку. Electron-builder включает `dist/ui` как `resources/ui` рядом с `app.asar`.
Сервер устанавливается отдельно: source с Node либо
[SEA-комплект с descriptor v3](../server/sea-desktop.md).

В пакет входят `release.json`, `api-version.json` и все файлы интерфейса. Manifest
содержит размеры и SHA-256 файлов; идентификатор вычисляется из содержимого, включая
незакоммиченные изменения. Manifest не хеширует сам себя. До первой загрузки проверяются
целостность, отсутствие посторонних файлов и символических ссылок. Повреждение вызывает
фатальный диалог «Установка повреждена» и выход.

Труба читает пакет напрямую, публикация интерфейса в папку сервера не нужна. Каждая машина
получает свой loopback-origin. Статика не меняется от перезапуска/пересборки сервера;
API и shots передаются машине. Маршруты приложения находятся в hash. Настройки используют
тот же origin, cookie и пакет, что главное окно. Android build использует тот же helper
и manifest в `client/src/main/assets/ui`.

Сервер не обслуживает `/ui/<id>/`, `web/dist` или их assets даже с сессией. Корневой HTML
объясняет «GrigDesk открывается в приложении». API, закрытые shots и страницы включённых
плагинов сохраняются; встроенный UI обращается к ним через собственную трубу.

Обновление интерфейса происходит установкой следующей сборки приложения. Ctrl+R,
Ctrl+Shift+R и F5 перехватываются главным процессом в главном и обычных дочерних окнах;
reload отсутствует в меню. Одиночный Alt заблокирован. Редактирование, масштаб и
Ctrl+Alt+S сохранены. PWA и service worker отсутствуют; Notification и Screen Wake Lock
находятся в `stores/device.ts`.

Отсутствующие ресурсы возвращают 404. Ошибка lazy-панели показывает сообщение, ожидание
ограничено 30 секундами; ошибка навигации выводится общим toast. Исторические SW-события
сохраняются только в схеме старых диагностических журналов.

Проверки: `ui-release`, `pipe-server`, `menu`, `runtime-config`, `client.e2e` и
`packaged-smoke` в тестах приложения. GUI-проверки требуют настоящего Electron-окна.
