# Модальное открытие мастера

`OnboardingHost` монтирует один ленивый `OnboardingModal` через общий `UiDialog`.
Кнопка топбара запрашивает открытие через `useOnboardingStore`, сохраняя текущий
маршрут, страницу, её ввод и прокрутку. Повторное нажатие не перезапускает открытый мастер.
Начальный автоматический допуск по-прежнему проверяется только при входе с `/`;
вместо перехода в другой раздел он открывает модал поверх начальной страницы.

`installOnboardingRouteGuard` поддерживает старые ссылки `/onboarding` и
`/onboarding?new=1`: открывает окно над текущей страницей, а начальную ссылку заменяет
доской. Запрос ждёт готового подключения; смена владельца или машины закрывает окно
и очищает отложенное открытие. `/onboarding` читает сохранённый проход, `new=1`
использует прежний серверный ручной start.

Крестик и Escape ждут последнего PATCH и закрывают только окно, не отправляя dismiss.
При отказе записи пользователь может подтвердить уход через общий диалог.
Нажатие затемнения не закрывает мастер. Во время начального открытия, перехода
или ожидания закрытия действия блокируются. Общая оболочка удерживает фокус,
делает фон inert и возвращает фокус к кнопке вызова после закрытия.

Перезагрузка сохраняет текущий раздел и закрывает модал. Повторное открытие из топбара
продолжает тот же серверный проход и не дублирует проект. «Пропустить настройку» остаётся отдельным
подтверждённым сервером отказом; «Готово» ведёт к проекту. Навигация из окна к инструкции
ждёт сохранения и закрывает мастер. Авторизация через CLI также сначала сохраняет ответы,
затем закрывает окно и показывает терминал.

Проверки поведения находятся в `onboarding-modal.browser.test.js`, а прохождение шагов,
продолжение и серверные барьеры — в остальных `onboarding*.test.js`.
