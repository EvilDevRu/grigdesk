# Тематические настройки системных плагинов

В каталоге настроек 35 страниц восьми групп. «Плагины → Установленные» содержит только
пользовательские пакеты: поиск, состояние, наличие параметров, источник, обновления и откат.
Первым выбирается пользовательский пакет; без пакетов видна подсказка установки из Git.

`features/settings/pluginPages.ts` задаёт карту системных страниц. Подписи и описания
страниц берутся из общих переводов встроенных плагинов; группа «Инструменты» имеет свою
подпись и значок.

| Группа | Плагин → ID страницы |
| --- | --- |
| Подключения | `ssh` → `connections.ssh`; `db` → `connections.db` |
| Подключения | `telegram` → `connections.telegram`; `github` → `connections.github` |
| Чаты и конвейер | `analysis` → `automation.analysis`; `shelf` → `automation.shelf` |
| Чаты и конвейер | `inbox` → `automation.inbox` |
| Речь и расшифровка | `video` → `speech.videoTasks` |
| Интерфейс | `usage-forecast` → `interface.usageForecast` |
| Инструменты | `code` → `tools.code`; `docker` → `tools.docker` |
| Инструменты | `studio3d` → `tools.studio3d`; `showcase` → `tools.showcase` |

«Инструменты» стоят между подключениями и плагинами. `speech.video` сохраняет настройки
Whisper-расшифровки; `speech.videoTasks` управляет плагином «Видео → задачи».

Обе формы рисует `PluginPage.vue`: системная страница показывает одну форму без списка
и фильтров. Она принимает только запись с `system === true`: пользовательский пакет с
одноимённым ID остаётся в магазине. Неизвестный системный ID скрыт из списка, но доступен
по явному `plugins.installed` с entity и через зарегистрированные поля поиска.
Проверка карты использует собственные ключи, включая защиту имён прототипа объекта.

Адрес системного поля содержит pageId и fieldPath; пользовательского — дополнительно
entityId. Старый адрес `plugins.installed` с entity известного системного плагина переходит
на его страницу. Reveal копирует fieldPath, удаляет entityId и tabId: канонический адрес
фокусирует поле и очищает цель показа. Входящие, Презентации и кнопка каталога открывают
тематические страницы через те же правила перехода.

Поиск сразу индексирует новые страницы. Метаданные полей всех объявленных плагинов
регистрируются после посещения любой страницы плагина или вкладки «Установленные».
До этого значения и параметры не загружаются ради поиска. Переходы и размонтирование
страницы сохраняют черновики в общей сессии; «Применить» и ожидание перезапуска работают
одинаково в обоих режимах. Значения и секреты не входят в поисковый индекс.

Загрузка каталога, ошибка чтения с повтором и подтверждённое отсутствие плагина показаны
отдельными состояниями. Ошибка не выдаётся за удаление. Причина recovery установки
видна над формой и объясняет заблокированный тумблер. Загрузка привязана к странице,
entity и открытию до первого await; уход, закрытие и новое открытие обесценивают поздний
результат для UI и регистрации редакторов.

Серверный DTO `/api/plugins` и категории магазина сохраняются. Проверки:
`settings-catalog.test.js`, `settings-plugin-session.test.js`,
`system-plugin-page.component.test.js`, `settings-plugins-catalog.component.test.js`,
`settings-language.component.test.js`, `loading-lazy.contract.test.js` и переходы
в `inbox-view`, `showcase-view`, `plugin-marketplace.component.test.js`.
