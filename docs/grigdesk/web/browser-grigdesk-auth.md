# Авторизованная dev-проверка GrigDesk во вкладке агента

`npm --prefix web run dev` поднимает Vite с локальным авторизованным API.
Агент открывает опубликованный Vite адрес через `grigdesk_browser`; для dev-проверки
не нужны ручной вход, cookie главного окна или повторная передача вкладки.

## Исправленный транспорт

- `web/scripts/localApiPlugin.ts` передаёт `/api`, `/shots` и `/vscode` через
  существующий `createUpstream` приложения. Он обменивает локальный ключ на настоящую
  сессию сервера; ответ `/api/auth/state` не подменяется.
- Эффективные порт и путь ключа берутся из файла окружения GrigDesk с приоритетом
  переменных процесса. Чтение ключа использует существующие проверки владельца,
  прав и обычного файла. Неверный или недоступный ключ закрывает API отказом.
- Сессия остаётся в Node-процессе Vite. Cookie и привилегированные заголовки
  браузера снимаются, `Set-Cookie` сервера не попадает в страницу. Секреты не
  включаются в URL, клиентские модули или build defines.
- Слушатель ограничен loopback HTTP. Проксируемые запросы и WebSocket проверяют
  локальный сокет, Host с фактическим портом, Origin и Sec-Fetch-Site. Настройка
  Vite с публичным host или HTTPS отвергается. Страницы запрещают встраивание во frame.
- Общий upstream сохраняет SSE, бинарные WebSocket и обновление сессии после 401.
  Повторяются только GET/HEAD; уже отправленная мутация не повторяется.

Dev-стенд не изображает native-оболочку и не получает её capabilities. Проверки
системных окон, устройств и других native-возможностей остаются в
[изолированном приложении](../testing/desktop-window-e2e.md). Production-сборка
не включает этот dev-плагин в клиентский код.

## Исходная причина

- Прежний Vite раздавал интерфейс и проксировал `/api` без входа по ключу.
  Запрос `/__shell/state` получает HTML SPA вместо JSON оболочки. Детектор
  `web/src/shared/shellClient.ts` отвергает этот ответ и не обнаруживает оболочку.
- Публичный `/api/auth/state` отвечал `200`, `method: 'window-key'`,
  `configured: true`, `authenticated: false`. HTTP 200 здесь не подтверждает вход.
  Стор `web/src/stores/auth.ts` сохраняет отсутствие сессии, затем показывается
  `NoAccessView`.
- `desktop/src/pipe/upstream.ts` обменивает локальный ключ на сессию и держит
  cookie в памяти main. `Set-Cookie` не передаётся документу интерфейса.
- `desktop/src/browser/browserView.ts` создаёт отдельную session для машины и
  владельца вкладки, без privileged preload. Native guest также запрещает запросы
  к origin локальной трубы. Передача вкладки агенту разрешает действия со страницей,
  но сама по себе не создаёт вход на сайт.

Живое воспроизведение: `open`, `snapshot` и `console` прошли успешно; документ
показал «Нет входа». Нажатие «Подключиться сейчас» сохранило тот же экран.
Отдельные HTTP-чтения подтвердили `authenticated: false` и HTML вместо shell state.
История исходного разговора не использовалась; вывод относится к повторному
открытию адреса со скриншота. Причина выбора адреса исходным агентом не установлена.

## Отличие от потери доступа к вкладке

[Восстановление после reconnect](browser-host-reregister.md) меняет grantEpoch и
возвращает агенту право работать с собственной страницей. Оно не обменивает ключ
окна, не переносит cookies и не меняет результат `/api/auth/state` сайта.
Пустой `list`, `access_revoked` и экран «Нет входа» требуют разной диагностики.

При отсутствии сессии повторная выдача вкладки не заменяет исправление dev-входа.
Парольная форма GrigDesk снята. Сначала проверяют запуск местного сервера,
эффективный порт и безопасное чтение ключа; ручной вход здесь не предусмотрен.

Регрессии: `tests/web/local-api.test.js` проверяет настоящий auth-модуль через Vite,
параллельный вход, отсутствие cookie в странице, отказы Host/Origin/cross-site,
небезопасный ключ, SSE, WebSocket и запрет повтора POST. Wiring штатного конфига —
`tests/web/api-same-origin.test.mts`.

После исправления живой `/api/auth/state` подтвердил вход без `Set-Cookie` для
страницы. Доска открылась через `grigdesk_browser`; snapshot содержит её интерфейс,
экран «Нет входа» отсутствует, console не содержит ошибок. Native-возможности и
полный маршрут конвейера в этой проверке не запускались.
