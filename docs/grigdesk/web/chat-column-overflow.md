# Колонка чата без min-width: 0 — длинная команда выталкивает кнопки за экран

**Где:** `web/src/views/chat/ChatSession.vue` (`.cs`), проявляется на странице «Чаты»
(`ChatsView`: `.stage :deep(.cs) { flex: 1 }`).

Флекс-элемент по умолчанию имеет `min-width: auto` — он НЕ сжимается ниже min-content своего
содержимого. Одна длинная неразрывная строка (команда `python3 -c "…"` во всплывашке разрешения
или в ленте шагов) раздувала всю колонку чата: при окне 1400 её ширина становилась 1540, и кнопки
«Разрешить/Отклонить» уезжали за правый край. Коварство в том, что `document.scrollWidth`
переполнения НЕ показывает — страница не скроллится, содержимое просто обрезано, и со стороны
выглядит как «кнопок нет».

Лечится `min-width: 0` на `.cs` (плюс `overflow: hidden` на самой плашке). Проверять замером
`getBoundingClientRect().right` кнопки против ширины окна, а не глазами по скриншоту.

Там же: длинные команды показываем блоком с `white-space: pre-wrap` + `overflow-wrap: anywhere`
и `max-height` со скроллом, а не одной строкой с многоточием — решение о разрешении принимают
по тому, что видно целиком.

**Тот же обрез повторился с другой стороны — кнопками варианта.** У ACP-плана Kimi
подписи вариантов не слова, а фразы («Approve plan and continue…»), и ряд кнопок в шапке плашки
стоял `flex: none` с `flex-wrap: wrap`. Обёртка при этом не срабатывает НИКОГДА: не сжимаясь,
контейнер получает ширину `max-content`, переносить внутри себя ему нечего. Замер в плавающей
панели (колонка 360 px): `perm.scrollWidth` 475 против `clientWidth` 345, правый край кнопки
«Revise plan» — 475, то есть она целиком за краем и обрезана `overflow: hidden` плашки. Страница
опять не скроллится, поэтому со стороны это «у плана всего одна кнопка».

Лечится тремя правками разом: перенос разрешён самому ряду (`.p-row { flex-wrap: wrap }` —
не влезли, значит кнопки уезжают на вторую строку, оставаясь наверху), ряд кнопок получает право
сжиматься (`flex: 0 1 auto; min-width: 0`), а сама кнопка — `max-width: 100%` с переносом текста.
Проверено замером на 360 / 420 / 1400: `scrollWidth == clientWidth`, правый край каждой кнопки
внутри колонки. Happy-dom это не ловит (в нём нет раскладки) — только настоящий headless Chrome.

Воспроизводимый baseline теперь запускается командой
`npm --prefix web run test:ui-browser`. Она не трогает пользовательский Chrome: создаёт
временный profile, открывает auth-free `ui-gallery.html` и проходит ширины
340/360/600/759/760/899/900/1200/1500. Там же закреплена полноширинная disclosure-строка,
из-за которой tool/think rows раньше превращались в центрированные «островки». Если Chrome
лежит не в системном fallback-пути, задаётся `CHROME_BIN`.
