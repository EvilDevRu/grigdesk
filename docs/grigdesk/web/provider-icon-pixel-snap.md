# Горизонтальная привязка логотипов к физическим пикселям

Ряд `.provbox` в `AppShell.vue` использует `v-svg-pixel-snap` из
`web/src/shared/svgPixelSnap.ts`. После раскладки директива измеряет видимую левую
границу каждого SVG через `getBBox()` и `getScreenCTM()`. Штрих Claude учитывается
в границах. Координата округляется по `window.devicePixelRatio`, а поправка
применяется только через `translateX()`.

Размер кадра Codex и Claude — 14 CSS px по высоте, размер рисунка — примерно 13 CSS px.
У остальных исполнителей кадр — 13 CSS px, рисунок — примерно 12 CSS px;
пропорции и исходные контуры не меняются. Сдвиг относительно исходной раскладки
ограничен половиной физического пикселя по горизонтали. Вертикальное положение
сохраняет [общую ось топбара](topbar-vertical-axis.md): округление верхних границ
знаков разной высоты нарушало центровку. Диагонали, кривые и мелкие внутренние
детали по-прежнему используют обычное сглаживание.

Один `ResizeObserver` обслуживает весь ряд и его родителя. Обновление Vue,
изменение размеров окна и смена плотности дисплея планируют общий animation frame.
Прежний сдвиг исключается из расчёта исходной позиции: повторный пересчёт не
накапливает поправку и не вызывает дрожания. При удалении ряда наблюдатель,
события и запланированный кадр освобождаются. Директива предназначена для SVG,
которые не задают собственный CSS `transform`.

Браузерная проверка полного `AppShell.vue` использует синтетические хранилища:
ширины окна 600, 834, 1024 и 1920 CSS px при DPR 1, 1.25, 1.5, 2 и 3. Проверены целые
физические координаты левых границ, прежние размеры и пропорции, общая ось знаков,
стабильность повторных пересчётов, удаление и повторное создание ряда. Смена DPR
дополнительно проверяется вместе с событием `resize`, как при изменении масштаба
браузера; CDP-подмена DPR сама по себе не посылает событие media query в стенде.
