# Heartbeat браузера зависит от цикла событий интерфейса

`browserHost.ts` запускает heartbeat из главного SPA: ожидание 5 секунд, native
снимок grants, HTTP heartbeat, продление native lease. Ответ сервера даёт lease
до 15 секунд. Долгий JavaScript или задержка event loop мешают всей этой цепочке;
независимость heartbeat от Promise команды не делает его независимым от UI.

В живом интервале перед DELETE/POST хоста журнал интерфейса зафиксировал
`event-loop` 13 279 ms, затем 2 655 ms. `longtask` в соответствующих выборках —
максимум 8 935 ms и 3 554 ms; документ отмечен visible. Разрыв между heartbeat
составил 24 299 ms. После перерегистрации прежний агент получил `access_revoked`.
Скриншоты в проверенной последовательности этого агента отсутствовали.

Это подтверждённое совпадение задержки UI с потерей lease, а не установленная
причина самой длительной операции. Поле `operation` в performance-журнале означает
близкую измеренную операцию и не доказывает, что она заняла всё время блока.
Нельзя автоматически приписывать паузу отрисовке чата либо скрытому браузеру.

Диагностика heartbeat должна различать ожидание таймера, native state, HTTP и
продление lease. Исправление не должно продлевать истёкшие права по старому proof
или автоматически выдавать grants после смены host. Контракт отзыва сохраняется
в [описании перерегистрации](browser-host-reregister.md).
