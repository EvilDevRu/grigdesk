# Таймер в state стора + $subscribe = бесконечный круг

Стор, который сам сохраняет своё состояние (`$subscribe` → запись снимка), не имеет
права держать в `state` id таймера. Дебаунс записи присваивает его — это мутация
состояния, — подписка будится снова, ставит новый таймер, и цикл замыкается сам на
себя. Проявляется не ошибкой, а зависанием: тест раздела «Видео» встал намертво и
ушёл в фон по таймауту, хотя в логике поллинга ничего рекурсивного нет.

Таймеры сеанса разбора поэтому лежат в `WeakMap` рядом со стором
(`web/src/stores/videoSession.ts`), а не в его `state`. `WeakMap`, а не модульная
переменная: в одном процессе (компонентные тесты) живёт несколько pinia, и чужой
интервал гасить было бы нечем.

Соседняя мина того же теста: заглушка `'../shared/api-client.js'` вида
`export const api = globalThis.__api` снимает ЗНАЧЕНИЕ в момент импорта модуля. Если
тест подставляет свой api после `compileModule`, стор получает `undefined`, а его
`try/catch` вокруг сети превращает `TypeError` в «сервер не отвечает» — то есть беда
выглядит логической, а не тестовой. Стаб должен быть ленивым прокси
(`get: (...args) => globalThis.__api.get(...args)`).
