# «Нет входа» на собственном стенде: web-процесс запущен без пути ключа окна

Вход интерфейса держится на секретном ключе: процесс обменивает файл ключа на сессию
(`shared/desktop/windowKeyPath.ts`, обмен в `desktop/src/pipe/upstream.ts`). Путь берётся
из `GRIGDESK_WINDOW_KEY_PATH`; без переменной — умолчание
`<XDG_RUNTIME_DIR>/grigdesk/window-key-<порт API>`. У стенда со своей папкой данных файла
на умолчательном месте нет, поэтому обмен не может пройти никогда.

## Симптом и точная диагностика

- Страница открывается, но показывает «Нет входа» и не оживает.
- `GET /api/auth/state` через фронт отвечает HTTP 503 `{"error":"connecting"}`;
  тот же запрос напрямую к API стенда — HTTP 200. «Connecting» отдаёт не сервер,
  а Vite-плагин (`web/scripts/localApiPlugin.ts`): обмен не состоялся, и плагин
  отвечает начальным состоянием на каждый запрос страницы.
- Сервер при этом здоров: прямой обмен его ключом (`stand.sh cookie`) выдаёт сессию.
- Проверка причины: у процесса web должна быть `GRIGDESK_WINDOW_KEY_PATH` на файл
  ключа стенда; на умолчательном пути файла стенда нет либо там ключ чужого сервера.

## Исправление

- Правильное: запускатор web-процесса стенда передаёт
  `GRIGDESK_WINDOW_KEY_PATH=<папка стенда>/window-auth/window-key` — тем же значением,
  что получает сервер (у серверного окружения стенда путь уже есть в `isolatedEnv`).
- Быстрый разблок до правки запускатора: скопировать файл ключа на умолчательное
  место и дать права 0600. Мера временная: `/run` — tmpfs, а после рестарта сервера
  содержимое может смениться; копия не заменяет передачу переменной.

Плагин перечитывает ключ при каждом обмене — переменная применяется без рестарта Vite.
Копия ключа в чужой каталог не создаёт второй вход: файл читает только владелец.
