# Каркасы при смене состояния оболочки и загрузке панели

Ширина окна и доступная ширина панели различаются из-за реек оболочки.

- При подключении Чатов сохранённая ширина списка ограничивается контейнером рабочей
  области. Минимум списка — 220 px, чату остаётся 420 px; верхний предел совпадает
  с `ChatsView`: меньшая из доступной ширины за вычетом чата и большей из 560 px
  и 40% ширины хоста. Без сохранения сохраняются обычные ширины 300/260 px,
  на телефоне — одна колонка. Изменение размера контейнера не записывает настройку.
- Каркас подключения Конвейера читает существующие `grigdesk-compact` и `grigdesk-loops`
  без записи и передаёт их `PipelineLoading`. Перед карточками зарезервирована панель
  инструментов с теми же высотой, отступами оболочки и промежутком до списка.
- При подключении Доски `BoardLoading` резервирует раздел собственных задач перед
  показателями. В самой Доске раздел уже виден и повторно в каркас не добавляется.
- Ленивый каркас SSH использует общую `UiPaneHeader` и каталог шириной 240–300 px.
  При контейнерном пороге 880 px показывается навигация, список занимает всю ширину,
  консоль и журнал скрыты. При 560 px сводка скрывается, как в готовой панели;
  `compact` и `dock` сами по себе не заменяют измерение контейнера.
- Ленивый каркас Терминала располагает панель действий и консоль одной flex-колонкой.
  Высота действий определяется общим размером controls и их отступами, консоль занимает
  остаток высоты без промежутка от grid-обёртки статуса.

Запросы, условия ожидания, ошибки и сохранения остаются у готовых экранов.
Допуск сравнения крупных областей — 4 CSS px, см. [контракт композиции](skeleton-layouts.md).
