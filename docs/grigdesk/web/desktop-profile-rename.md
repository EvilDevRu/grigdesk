# Перенос профиля окна GrigDesk

При установке нового окна `deploy/lib/desktop-app.sh` копирует прежний профиль в
`$XDG_CONFIG_HOME/GrigDesk` (по умолчанию `~/.config/GrigDesk`). Имя источника и прежняя
partition заданы в `LEGACY.profileDir` и `LEGACY.partition`; Bash-константы сверяются тестом.
[Точные прежние пути и порядок перехода](../server/brand-migration.md).

Копирование выполняется только при отсутствии нового профиля и без явно заданной
`GRIGDESK_DESKTOP_DATA_DIR`. Существующий новый профиль сильнее старого, даже пустой.
Живой SingletonLock запрещает перенос. Исходный профиль сохраняется без изменений;
копия готовится в соседней временной папке с правами 0700 и публикуется переименованием.
При ошибке временная папка удаляется, незавершённый профиль не становится рабочим.

Local Storage и IndexedDB сохраняются. Partition переименовывается в `grigdesk-local`.
Ссылки, Singleton-файлы, кэши и Cookies, включая Cookies в Network, не копируются.
Cookie связана с прежним приложением и хранилищем ключей: новый клиент получает свою сессию
при первом входе, последующие открытия используют её. Перенос внутри Electron не выполняется.

При первом старте веба `legacyStorage.ts` переносит прежний префикс localStorage до загрузки
сторов. Новый ключ сильнее старого, старый удаляется; запрет доступа к storage не мешает
загрузке. База намерений оплаты 3D сохраняет своё имя.

`desktop-install-script.test.js` проверяет копию, отказ занятого профиля и обход переноса.
`tests/desktop/e2e/profile-rename.e2e.mts` в одноразовой D-Bus/Keyring-сессии пишет маркеры
старым пакетом, читает новым и проверяет один новый вход и его сохранение. Это проверка
пакетов с временным HOME, а не запуск против настоящего профиля.
