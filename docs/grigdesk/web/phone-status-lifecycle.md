# Постоянные цели второй полосы телефона

`PhoneStatusBar` монтируется на всё время жизни `AppShell`. Условие `hasMachine`
управляет его видимостью через `v-show`; host-узлы метрик и исполнителей остаются
в документе даже до выбора машины. Сами действия по-прежнему доступны только
при наличии машины. Скрытая полоса не занимает место и не добавляет источников данных.

Условный монтаж через `v-if` нарушает два сценария Teleport:

- При первом запуске без машины Teleport метрик уже существует, а цели ещё нет.
  После появления профиля обновление может завершиться ошибкой вставки в `null`;
  обе области полосы остаются пустыми, хотя каталог исполнителей уже загружен.
- После удаления и восстановления профиля Teleport может сохранить ссылку на прежний,
  отсоединённый host. Кнопка CPU/RAM обновляется вне документа при сохранённом снимке.

`defer` откладывает первый монтаж Teleport, но не отслеживает замену DOM-узла
по прежнему селектору. Постоянные host-узлы исключают эту замену.

`phone-topbar.component.test.js` проверяет старт без профиля, восстановление машины,
идентичность host-узлов, единственные controls, unknown/stale, смену ширины и открытие
ресурсов после восстановления. Переходы offline/connecting/locked/online с выбранным
профилем сохраняют те же кнопки и их подключение к документу.
