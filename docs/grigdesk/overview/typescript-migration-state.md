# Учёт миграции на TypeScript

Читай при переносе JS/Vue, изменении точек входа и расхождении снимка миграции.
Текущий остаток вычисляет `tools/migrationInventory.mts`; числа из отдельного прогона
не являются постоянным контрактом проекта.

```bash
node tools/migrationInventory.mts --json
```

Команда читает рабочее дерево, включая неигнорируемые новые файлы. Поля `legacy` и `vue`
содержат пути, `typecheckDebt` — диагностики проверки типов web. Снятие JS-файла с учёта
не доказывает, что его поведение перенесено: нужно проверить вызывающий код.

## Снимок и совместимость

`tests/fixtures/migration-inventory-baseline.json` — проверяемый снимок, а не независимый
источник текущего состояния. При расхождении сначала устанавливают причину добавленных
и удалённых путей. Обновлять снимок только ради зелёной проверки нельзя.
[Порядок обновления снимка](../testing/migration-inventory-snapshot.md).

`COMPATIBILITY` перечисляет именованные исключения. `remainingBeyondCompatibility()`
вычитает их из остатка; исключение не означает завершённый перенос реализации.
Старый launcher может требоваться установленному MCP, hook или механизму обновления.
Его удаление требует проверки фактического потребителя.

`COVERAGE_EXCEPTIONS` отделяет намеренные тестовые образцы от кода продукта.
Зависимости, результаты сборки и приватное состояние не являются предметом миграции.

## Проверки разных границ

- `tests/docs/migration-inventory.test.mts` сверяет остаток, исключения и охват TS/MTS.
- `tests/docs/compatibility-list.test.mts` проверяет смысл списка совместимости.
- `tests/docs/entrypoint-graph.test.mts` проверяет разрешение зависимостей точек входа.
- Проверки типов пакетов, запуск тестов и сборка выполняются отдельно; успешная опись
  не заменяет ни один из этих результатов.

Новый `.mts`, переименованный тест или Vue-компонент должен попасть и в свою программу
типов, и в нужный запуск. Шаблоны package scripts и `tsconfig` проверяются по месту,
а не предполагаются одинаковыми для server, web, mobile, desktop и relay.
Правила [трёх описей browser-тестов](../testing/browser-test-inventory.md) описаны отдельно.

Отдельные среды сохраняют собственные ограничения: [AudioWorklet](typed-audio-worklet.md),
[общий Node-код](../testing/shared-node-typecheck.md) и
[типизированные загрузчики Vite](../testing/typed-vite-unit-loaders.md).
