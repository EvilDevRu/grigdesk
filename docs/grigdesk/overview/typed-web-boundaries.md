# Типизированные границы web

Готовый Vue-компонент объявляет `script setup lang="ts"` и выходит из переходного
`web/tsconfig.json.exclude`. Типы props уточняют прежние runtime-объявления: `Array`,
`Object`, `required` и значения по умолчанию сохраняются. Типизация сама по себе
не меняет события, модель компонента, шаблон и порядок lifecycle.

Файл документа приходит через `apiClient` как `unknown`. Клиентский
`web/src/features/documents/contracts.ts` проверяет ссылку и описание через общий
`parseResolvedDocument`, затем проверяет содержимое, размер, время и отображаемый путь.
Проверка выполняется перед публикацией в `DocumentPanel`; неверный ответ оставляет
документ сброшенным и использует прежнее сообщение ошибки. Поколение запроса
по-прежнему отсеивает ответ предыдущего документа.

Переход по абсолютному пути в `DocumentsView` также проверяет `ResolvedDocument`
перед `router.replace`. Ошибка формы ответа не превращается в успешную навигацию.
Текст ошибки получается через общий `failureText` из `apiClient.ts`.

`TerminalPanel` принимает WebSocket-сообщение как `MessageEvent<unknown>`. Только строка
или `ArrayBuffer` попадает в xterm и подтверждает готовность shell. Объект другого типа
не запускает обработку очереди намерений. Поколение сокета, пауза перед вставкой команды,
один экземпляр терминала и его cleanup сохраняются.

`DiffPanel` проверяет контейнер репозиториев, списки файлов и читаемые поля файла перед
назначением состояния. Поля содержимого должны быть строками, счётчики — числами,
флаги — boolean; переданный список hunks должен быть массивом. Отсутствующие старые
optional-поля допустимы, неизвестные расширения сохраняются. Неверный ответ использует
прежнюю ветку ошибки с очисткой списка репозиториев. Модели Monaco снимаются после
установки новых моделей, а хост редактора сохраняется при обновлении.

`BootstrapDecision` проверяет объект подтверждения перед сравнением visitId/stopHash.
Успешный CAS и повтор resume остаются разными действиями: отказ продолжения не вызывает
повторную запись ответа. `DeferredFindings` проверяет identity попытки и отображаемые
поля находок перед `ready=true`; ответ старого поколения не публикуется.

`ArbiterDecision` типизирует только отображаемую проекцию решения и ответы формы.
`ChatsView` сохраняет устройство хранения ширины списка, измерение доступного места,
захват указателя и регистрацию видимой поверхности чата.

Все продуктовые модули и компоненты `web/src` проверяются общим строгим TS-проектом:
переходный `allowJs` и исключения продуктовых SFC сняты. Тесты и scripts сохраняют
отдельные настройки сред. Остаток других областей указан в
[состоянии миграции](typescript-migration-state.md).
