# Типы и язык после объединения интерфейса

Перенос чистых модулей в TypeScript сохраняет согласованную редакцию языка интерфейса.
`LocaleSource` из `shared/i18n/catalogs.ts` принимает строку или
readonly-порт текущего языка; пропущенная локаль сохраняет русский контракт прямого вызова.
Справочники диагностики и стадий обновления используют `messageLabels` с `uiLocalePort`:
чтение подписи после переключения языка не требует пересоздания объекта.

Стор `device` сохраняет причины в `$state.wakeLockIssue` и `$state.notificationIssue`.
`wakeLockError` и `notificationError` являются переводящими getters. Это форма входной
редакции с поддержкой языка; перенос типов не возвращает сообщения в state и не меняет
ключи localStorage, порядок запросов системного разрешения или lifecycle блокировки экрана.

`providerUsage.ts` также экспортирует `localizeUsageBar` и `localizeUsageResource`.
Проекции переводят собственные подписи и подтверждения по стабильным ID. Неизвестные поля,
команды, payload и внешние сообщения сохраняются; русская проекция возвращает исходный объект.
Формы представления принадлежат web и не создают нового серверного DTO.

При переименовании переведённого модуля обновляются его пути в `include`, `dynamicKeyTables`
и `dynamicExpressions` файла `web/scripts/i18n-scope.json`. Вычисляемые выражения сохраняются
дословно либо меняются одновременно с правилом. Проверка `npm --prefix web run check:i18n`
сверяет новый TS-путь с прежней областью ключей.
