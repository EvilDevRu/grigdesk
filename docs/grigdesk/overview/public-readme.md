# Публичный README

Корневой [README](../../../README.md) — английская страница знакомства с GrigDesk.
Она описывает возможности, установку, плагины и точки входа в документацию.
Пользовательские ссылки ведут в полный английский корпус `docs/grigdesk/guide/en/`;
отдельная точка входа сохраняет русское руководство. README описывает немедленную
смену встроенной справки по языку устройства и обе офлайн-локали своего выпуска. Изменение README само по себе не меняет поведение приложения.

## Шапка и интеграции

Шапка использует SVG `docs/images/readme/hero.svg`: холст 1280×248, высота при
ширине изображения 900 px — около 174 px. В него встроены существующие знак
`docs/images/brand/grigdesk-app-icon.svg` и
wordmark `docs/images/brand/grigdesk-wordmark-light.svg`, без изменения геометрии.
Композиция центрирована. Фирменная надпись служит единственным крупным акцентом,
под ней стоит слоган «Your agents. One workspace.». Ниже — простая линия с четырьмя
узлами и подписями Plan → Build → Review → Test. Это схема последовательности,
без обозначения состояния живого прогона. Вложенных карточек, номерации этапов,
мелких заглавных подписей и декоративной сетки нет.
Отдельный скриншот интерфейса в README не встроен.
Версия и лицензия собраны в один абзац, навигация — в следующий.
Обложка имеет собственный тёмный фон и сохраняет контраст в светлой и тёмной
темах GitHub. `picture` выбирает `hero-mobile.svg` при ширине окна до 640 px.
Мобильный холст 640×330 сохраняет ту же композицию с увеличенными относительно
ширины холста подписями; при ширине картинки 358 px его высота — около 185 px.
Остальные размеры используют основную обложку через `img`.
Поддержка `picture` описана в [руководстве GitHub](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github#adding-an-image-to-suit-your-visitors).
Это оформление содержимого README;
значок рядом с именем репозитория в интерфейсе GitHub принадлежит владельцу
репозитория и не задаётся Markdown.

Палитра нейтральная: однотонный фон `#191C20`, фирменная надпись `#F2F3F5`,
слоган и подписи `#D6DAE0`, линия конвейера `#59616C`.
Фиолетовый `#9A7DF5` сохранён в фирменном знаке; заливки и бейджи его не повторяют.
Изображения интеграций имеют прозрачный фон; бейджи версии и лицензии — `#30363D`.

Слоган, подписи этапов и подписи интеграций используют Noto Sans Regular.
Гарнитура входит в стек обычного текста GitHub; размер и насыщенность не конкурируют
с фирменной надписью. В SVG буквы сохранены контурами, поэтому отсутствие шрифта
на устройстве читателя не вызывает подмену. Шрифтовые файлы не встроены.
Названия остаются в `title`, `desc`, `data-label` и альтернативном тексте README.
Текст Markdown использует штатную типографику GitHub, без собственных стилей.
Вводный абзац оставлен обычной насыщенности. Заголовки групп интеграций используют
обычный текст Markdown/HTML, без уменьшенного кегля и прописных декоративных подписей.

Раздел Works with содержит две явно подписанные группы: AI agents и Task boards.
Группа исполнителей перечисляет Claude Code, OpenAI Codex, Kimi Code, DeepSeek и Z.ai (GLM).
Их SVG в `docs/images/integrations/` переносят геометрию из
`web/src/shared/ProviderIcon.vue`. Знак и название объединены в одно изображение
на прозрачном фоне, без подложки или рамки. Одинаковые площадки 164×48 px
выравнивают элементы по колонкам; блок выровнен по левому краю основного текста.
На широком экране пять исполнителей помещаются в ряд, на ширине окна 390 px —
по два в ряд. Каждое название переносится вместе со своим знаком.

Светлая тема использует варианты `*-light.svg` с текстом `#24292F` и тёмными
монохромными значками исполнителей. Основные файлы используют текст и монохромные
знаки `#D6DAE0`. `picture` выбирает вариант через `prefers-color-scheme`;
цветные знаки досок в обеих темах сохраняются. При подготовке локального светлого
превью выбор источника явно выставляется в светлую тему, как при выборе темы GitHub,
независимо от темы операционной системы.

Исполнители и доски используют центр значка на y=24, видимую высоту знака 24 px,
кегль названия 16 px и базовую линию y=29. Ширина знака следует
его пропорциям. У исполнителей viewBox учитывает реальные границы рисунка из
`ProviderIcon.vue`, чтобы широкий DeepSeek не выглядел ниже соседних знаков.
При изменении исходного знака нужно сверять обе копии. Знак Z.ai взят из Lobe Icons;
его MIT-уведомление сохранено в `web/public/third-party-notices.txt`.

В группе досок представлены GrigDesk, Bitrix24 и Jira Cloud. Под группой явно указано:
задачи GrigDesk встроены, Bitrix24 и Jira Cloud подключаются устанавливаемыми драйверами.
Ссылки драйверов ведут в их публичные репозитории из
`shared/trackers/driverSources.ts`. Значок Bitrix24 — неизменённый PNG с
[официального сайта](https://www.bitrix24.com/favicon-32x32.png); Jira — SVG из
[Simple Icons](https://github.com/simple-icons/simple-icons/blob/develop/icons/jira.svg),
распространяемого под CC0. Знаки обозначают интеграции с соответствующими продуктами.
Файлы `board-grigdesk.svg`, `board-bitrix24.svg` и `board-jira.svg`, а также их светлые
варианты объединяют знак и подпись в одно изображение. PNG Bitrix24 встроен в SVG как data URL; внешних ссылок
внутри картинок нет. Разные baseline изображений и обычного текста больше не
влияют на ряд досок.

## Версия, установка и вкладки

Бейдж Shields.io читает последний опубликованный стабильный GitHub Release.
Он показывает версию доступной поставки, а не незавершённые изменения текущей ветки,
и не требует ручного обновления строки README при каждом выпуске.

Install ведёт к `releases/latest/download/grigdesk-install` и повторяет режимы
`local`, `remote`, `server` из [руководства установки](../guide/installation.md).
Бейдж лицензии и секция License ссылаются на корневой MIT [LICENSE](../../../LICENSE).
Вкладки README и MIT license формирует GitHub из стандартных файлов репозитория;
дополнительная реализация вкладок внутри README не нужна. Распознавание лицензии
описано в [документации GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository#detecting-a-license).

## Плагины и документация

Секция Plugins направляет в каталог через Settings → Plugins, описывает установку из Git
и даёт ссылки на английскую пользовательскую статью, контракт автора и пример пакета. Карточек, названий
и ссылок Studio3D и Codex Reset в публичном README нет. Их существующие картинки
не удаляются.
README не копирует инструкции внешних плагинов: их документация остаётся в собственных
репозиториях.

Секция Documentation группирует ссылки по первому запуску и работе с агентами.
Она предлагает открыть руководство своего серверного выпуска через Help или F1,
затем ведёт к исходному руководству, основным пользовательским статьям и техническому оглавлению.
Возможности описаны четырьмя короткими абзацами: работа в чате, конвейер,
проверка результата и подключение досок. Основная установка начинается прямой
ссылкой на установщик и отдельным блоком команд. Требования и настройка CLI исполнителей
указаны рядом. Дополнительные режимы `remote` и `server` представлены таблицей
с назначением команд внутри раскрываемого `details`; там же ссылка на `.deb`.
Навигация в начале README использует обычные якоря разделов.
Ссылки и охват оглавлений проверяются существующими тестами
`tests/docs/markdown-links.test.mjs` и `tests/docs/documentation-structure.test.mts`.
Для превью через GitHub Markdown API используется режим `gfm` с контекстом репозитория.
Проверяется, что `source` и резервный `img` остаются внутри одного `picture`:
обычный режим `markdown` может вынести изображение в отдельную ссылку и лишить его
адаптивного источника. Превью проверяется в обеих темах и при ширине окна 390 px.
