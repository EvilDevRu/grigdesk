# Поддержка документации

Читай при ревизии документов, появлении противоречий и изменении оглавлений.
Небольшие тематические файлы нужны для выборочной загрузки знаний в контекст агента.
Короткий документ сам по себе не является дублем или кандидатом на объединение.

## Чтение и принадлежность

Сначала README области, затем только документы нужной темы. Строка оглавления называет
контракт, симптом или действие, ради которого нужно открыть файл. Оглавление не копирует
его содержание и не требует прочитать соседние статьи заранее. `@`-импорт областей запрещён.

- `guide/` описывает действия пользователя; статьи входят в `guide/catalog.json`.
- Папки областей описывают реализацию, ограничения и воспроизводимую диагностику.
- `docs/engine/` содержит контракты движка.
- Локальные обстоятельства машины находятся в `docs/local/` вне Git.
- Инструкции внешнего плагина принадлежат его собственному `docs/README.md`.

## Актуальность

Действующее правило проверяется по реализации и профильным тестам. Для неочевидного
утверждения указываются путь исходника, имя теста или ссылка на основной контракт.
Пути исходников пишутся от корня репозитория; путь внутри внешнего пакета, установленного
комплекта или синтетического примера явно обозначается как такой путь.

Прежнее поведение, которое всё ещё поддерживается, остаётся частью документации с точной
границей совместимости. Снятое решение помечается **«История»** в начале файла и в README;
рядом даётся ссылка на текущий контракт. Старые команды не предлагаются к исполнению.
Возраст файла не является основанием для удаления. Дата проверки внешней документации
или версия протокола сохраняется, если она ограничивает достоверность сведений.

Если факт не удалось подтвердить, документ обозначает конкретный предел проверки.
Успех теста, просмотр исходника и ручная проверка интерфейса не подменяют друг друга.

## Обезличивание и разовые работы

Общий текст не содержит номеров задач, идентификаторов запусков, частных аккаунтов,
реальных профилей, адресов стендов и личных абсолютных путей. Примеры используют
`<TASK>`, `<PROFILE>`, `<USER>`, переменные окружения и зарезервированные домены `example.org`.
Числовые границы протокола, версии и адреса публичных первоисточников сохраняются.
В исполняемом примере переменная должна быть определена; placeholder сам по себе не команда.

Из разового разбора сохраняются симптом, причина, действующее правило и способ проверки.
Журналы попыток, результаты одной сборки, счета личной сессии и снимки интерфейса остаются
в локальной папке артефактов. Общий документ не зависит от файла на машине автора и не
ссылается на конкретный локальный план. Обсуждение согласования плана не заменяет описание
реализованного поведения. Происхождение редакций сохраняет Git, без строк со старыми путями.

## Дубли, удаление и проверки

У каждого правила один основной документ. Другие статьи ссылаются на него и описывают
только собственную границу. Историческая заметка сохраняет причину решения, если она ещё
помогает избежать регрессии. Повторный отчёт без новых знаний удаляется после проверки
входящих ссылок; уникальные сведения предварительно переносятся в документ своей темы.

При изменении факта обновляются его документ и README области. Пользовательская инструкция
сверяется с `guide/`; удаление или переименование статьи требует обновить каталог справки.
После правок проверяются ссылки, якоря, охват оглавлений, обезличивание и бюджет корневых
инструкций через профильный набор из [правил тестирования](../../../tests/README.md).
Проверка ссылок не доказывает семантическую актуальность текста.
