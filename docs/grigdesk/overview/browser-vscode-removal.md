# Браузерный VS Code был и ВЫПИЛЕН: serve-web не видит git в worktree

Встроенный редактор (`code serve-web` на `127.0.0.1:8141` + реверс-прокси `/vscode`, iframe
на том же origin) был удалён. Причина одна и
она неустранима настройкой: **расширение git внутри serve-web видело в открытой через
`?folder=` папке 0 репозиториев**, то есть ровно то, ради чего редактор и ставили — диф
и история правок агента — не работало. Вместо него: диф на Monaco (`DiffView`, движок того
же VS Code) и нативный раздел «Код» (`/api/code/:project/*` — дерево, staged/unstaged diff,
явные `+/-`, commit, push и генерация редактируемого названия коммита).

Что осталось в дереве от той сборки: мёртвый прокси `/vscode` в `web/vite.config.js` и
живой, но никем не вызываемый `GET /api/tasks/:id/workspace` (`{repos, beWt, feWt}` из
`tNNNN.env`; `repos` — канонический список worktree, `beWt`/`feWt` — совместимые aliases
первых двух). Наличие `serve-web` в установленном CLI само по себе эту проблему не решает.

Если редактор будут возвращать (например панелью-доком), сначала проверяется ИМЕННО git,
а не то, что страница открылась: поднять `serve-web`, открыть worktree задачи, посмотреть
вкладку «Source Control». Остальные грабли той сборки, которые понадобятся снова:
`--server-base-path /vscode` обязателен (иначе ассеты уезжают по `/static/…` мимо прокси),
`rewritePrefix` тоже `/vscode` (не срезать), `frame-ancestors`/`X-Frame-Options` serve-web
не шлёт (iframe на своём origin работает), первый запуск тянет ~50 МБ веб-сборки в
`.state/vscode`, а iframe не отправляет заголовки авторизации — прежняя сборка просто
исключала `/vscode` из гарда, что сегодня противоречит правилу «весь `/api` за сессией».
