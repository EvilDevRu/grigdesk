# Python есть, но создание окружения требует ensurepip

На Debian/Ubuntu наличие `python3` и даже успешный `python3 -m venv --help`
не доказывает готовность создания окружения с pip. Без отдельного системного
пакета venv команда может создать `pyvenv.cfg` и `bin/python`, а затем завершиться
с ошибкой `ensurepip is not available`. Повторное обновление встречает ту же ошибку;
наличие pip в прежнем окружении не заменяет отсутствующий системный ensurepip.

Установщик распознаёт эту диагностику в stdout и stderr, включая перенос строки
между `not` и `available`, и отсутствие модулей `venv` или `ensurepip`.
Основная строка ошибки предлагает установить системный пакет `python3-venv`
для Debian/Ubuntu и повторить операцию. Подробный вывод остаётся в «Деталях».
Другие ошибки окружения сохраняют общее сообщение, без ложного диагноза.

Системный пакет устанавливает администратор компьютера с сервером GrigDesk;
сам установщик не вызывает sudo или пакетный менеджер. После установки пакета
«Обновить» восстанавливает частичное окружение. Перезапуск сервера для появления
системного компонента не требуется.

Регрессия: `tests/server/speech-install.test.js` проверяет оба потока диагностики,
сохранение failed, остановку до установки пакетов и успешный повтор после
устранения причины.
