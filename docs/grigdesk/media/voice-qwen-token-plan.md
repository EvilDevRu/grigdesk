# Qwen Token Plan: API озвучки и эксперимент с ударениями

## Подключение в штатной команде

Профиль подключён в `voice/src/engines/qwenToken.ts` через явный выбор:

```sh
voice generate --service qwencloud-token --engine qwen \
  --text "Я плач+у за билет в старинный з+амок" \
  --instruction "В слове плачу ударение на У" --out speech.wav
```

Для повторных вызовов можно задать `GRIGDESK_VOICE_QWEN_SERVICE=qwencloud-token`.
Команда принимает унаследованный `DASHSCOPE_API_KEY` или отдельный `TOKEN_PLAN_API_KEY`;
общий явный ключ имеет приоритет. Адрес исполнителя чата автоматически не наследуется.

`model-studio` по умолчанию использует `qwen3-tts-flash` с обычным API и отвергает
подписочный ключ до HTTP. Во время исходного эксперимента отправка такого ключа
к обычному API дала HTTP 401; это устранено явным выбором профиля и проверкой готовности.
`ready` подписочного профиля означает наличие ключа нужной формы, а не живую проверку доступа.

TTS входит в QwenCloud Token Plan. Нельзя определять
конкретный тариф только по префиксу `sk-sp-`: подписочные ключи и адреса различаются.
Проверка не разрешает перебирать сервисы с ключом без знания выдавшего его сервиса.

## Отдельный подписочный контракт

Для QwenCloud Token Plan документация указывает:

- модель `qwen-audio-3.0-tts-plus`;
- `POST https://token-plan.maas.qwencloudapi.com/api/v1/services/audio/tts/SpeechSynthesizer`;
- заголовок `Authorization: Bearer <ключ подписки>`;
- тело `{model, input:{text, voice, format, sample_rate}}`;
- результат `output.audio.url`, скачиваемый отдельным запросом без ключа.

Это другой контракт, чем у `qwen3-tts-flash`. Его нельзя подключить только сменой
базового адреса старого адаптера. Каталог из 48 голосов старого адаптера не является
каталогом голосов подписочной модели.

Живая проверка подписочного API 2026-11-15 получила HTTP 200 и непустые PCM WAV
для русского текста с `longanhuan_v3.6`, `sample_rate=24000`,
`language_hints=["ru"]` и `input.instruction`. Это подтверждает получение звука,
но не правильность произношения русского текста.

После интеграции отдельно проверен собранный SEA `bin/voice`: `generate` с
`--service qwencloud-token`, общими метками `+` и `--instruction` получил WAV mono
PCM16 24 кГц. Файл прошёл строгую проверку и был опубликован штатной командой без
Python или ffmpeg; отчёт содержит выбранные service/model и предупреждение об ударениях.

## Каталог голосов и языков

`voice voices --engine qwen --service qwencloud-token --json` перечисляет 600 голосов:
Long An Huan из примера Token Plan, два системных голоса `qwen-audio-3.0-tts-plus`
и 597 базовых голосов модели (589 китайских и 8 английских). Имена, суффиксы
ID и языки базовых голосов взяты из таблицы Plus, на которую ссылается
[каталог QwenCloud](https://docs.qwencloud.com/developer-guides/speech/voice-list/qwen-audio-tts).
В `qwenTokenBaseVoices.json` записи сгруппированы по коду языка. Код добавляет префикс
`qwen-audio-3.0-tts-plus-`, поэтому изменение каталога не меняет уже сохранённые ID.

Два системных голоса поддерживают китайский и английский. Long An Huan сохраняет
русский как экспериментально проверенный язык вместе с китайским и английским
из каталога QwenCloud. Без `--language` адаптер проверяет наличие в тексте русских букв,
иероглифов и латиницы в таком порядке. При отсутствии подходящей подсказки выбирается
первый язык голоса. Явный код проверяется по списку выбранного голоса до запроса.

Живой запрос Token Plan получил WAV от обоих новых системных голосов
и от одного английского и одного китайского базового голоса. Синтез и
произношение всего каталога не проверялись.

## Проверка ударений

Последовательность для сравнения: «замок, замок; мука, мука; плачу, плачу; стоит, стоит».
В размеченных вариантах первое слово пары получает ударение на первый слог, второе —
на второй. Проверяются отсутствие разметки, U+0301 после гласной, `+` перед гласной,
заглавная ударная гласная, отдельная инструкция и перестановка ударений внутри пары.
Фиксируется `seed=42`; точный повтор варианта с U+0301 дал одинаковый PCM.

Профиль и эксперимент отправляют текст в подписочный API. Общий `parseVoiceText`
снимает `+` и возвращает структурированные позиции, а U+0301 сохраняет в тексте,
не распознавая его как структурированное ударение. Поэтому пустой `ignoredDirections`
для U+0301 не подтверждает поддержку ударений движком.

Спектральное сравнение вариантов с противоположным порядком U+0301 не дало
однозначного результата для всех четырёх пар. Акустическое сходство не является
распознаванием ударений. Агентом прослушивание не выполнено: его инструмент не принимает
аудиовход. Ни принятие текста API, ни различие звуковых файлов не доказывает,
что модель ставит ударение в заданное место. Стабильное управление русскими ударениями
для произвольных слов остаётся неподтверждённым.

В проверке связного текста человеком вариант с одной русской инструкцией не обеспечил
нужное ударение в «я плачу́ за билет»: получена обратная связь об отсутствии нужного
ударения. Это отрицательный результат для конкретной реплики, а не проверка всех слов
или голосов. Следующая попытка совмещает U+0301 в тексте и инструкцию; HTTP 200 и WAV
подтверждают получение нового образца, но не исправление произношения.

Комбинированный вариант затем получил ручную оценку «в целом работает», однако
нужное ударение в «стоит» не получилось. В реплике есть «на холме стоит» и «того стоит»;
обратная связь не уточняет, какое вхождение прочитано неверно. Это частичный успех
на одной фразе, голосе и фиксированном seed, а не гарантия выполнения всех указаний.

Проверяемый приём: U+0301 после нужной гласной (`плачу́`, `стои́т`, `сто́ит`) вместе
с `input.instruction`, явно объясняющей ударный слог и значение слова. Например:
«В “я плачу́ за билет” ударение на последний слог ЧУ, гласная У ударная».
Применение приёма требует прослушивания каждой важной реплики. Это экспериментальный
способ управления произношением. `voice --service qwencloud-token` передаёт инструкцию,
переводит общий `+` в U+0301 и добавляет подсказку. При метках возвращается `warnings`;
capabilities явно содержат `stressMode=experimental`. В профиле `model-studio`
инструкция по-прежнему игнорируется.

Документированный SSML `<phoneme>` описывает китайский pinyin и английский CMU,
а не русскую фонемную разметку. Эксперимент с CMU может дать приближённое чтение,
но не объявляется поддержкой точных русских фонем.

## Особенность WAV

Полученный WAV содержал размеры RIFF/data как потоковые значения около `0x7fffffff`,
не соответствующие длине файла. `ffprobe` прочитал PCM, но строгий `checkWaveFile`
отклонил исходный контейнер. Эксперимент сохранил исходник и нормализовал заголовок
через ffmpeg без изменения PCM. Штатный `qwenTokenWav.ts` обрабатывает эту конкретную
пару размеров напрямую, без внешнего процесса, затем строго проверяет WAV перед
публикацией. Другой повреждённый заголовок не считается потоковым и не исправляется.
