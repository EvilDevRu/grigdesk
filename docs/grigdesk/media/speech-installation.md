# Установка Whisper из настроек

На странице «Речь» карточка «Распознавание речи» показывает одну строку состояния:
«Не установлено», текущий этап установки, последнюю ошибку или «Готово».
«Готово» требует исправного окружения и проверенного кэша выбранной модели.
Наличие каталога venv само по себе этого не доказывает. Для отсутствующего окружения
доступна кнопка «Установить», для существующего — «Обновить» и «Удалить».
Обновление восстанавливает и частично установленное окружение.

## Одна операция до готовой модели

После подтверждения общего UI установщик под одним maintenance и файловым замком:

1. Создаёт или восстанавливает штатный venv через системный Python 3.
2. Ставит закреплённые `requirements-media.txt` текущего выпуска GrigDesk.
3. Запускает `cuda-probe.py` в новом окружении. При обнаруженном NVIDIA GPU
   (`ready` или `missing_library`) ставит `requirements-media-cuda.txt`.
4. Проверяет импорты и доступность ffmpeg/ffprobe.
5. Скачивает pinned snapshot выбранной модели из серверного allowlist в runtime-кэш.
6. Проверяет кэш через общий `model-cache-probe.py` и загружает веса через
   `WhisperModel` на CPU без сети. Только после этого сохраняет успешный исход.

Модель передаётся из текущего пресета/явного выбора, без применения черновика.
Весь цикл показывает один прогресс по этапам, без выдуманного процента.
Ошибка скачивания или проверки модели остаётся failed; повторное «Обновить»
позволяет восстановить установку. Закрытие настроек не отменяет серверную операцию.

CUDA выбирается автоматически, решение видно в свёрнутых «Деталях» установки.
В «Расширенном» доступны авто, явная установка библиотек и пропуск их установки.
Пропуск сохраняет ранее установленные библиотеки. Ошибка автоматической пробы
показывается явно; ручной выбор позволяет продолжить после диагностики.
Python 3 с venv, ffmpeg и ffprobe остаются системными зависимостями; sudo не вызывается.

## API и владение

`GET /api/settings/speech/installation` возвращает наличие окружения и последнюю
операцию. `POST /api/settings/speech/installation/:operation` принимает операции
`install`, `update`, `uninstall` и объект с необязательными полями:

- `modelId`: модель серверного allowlist, по умолчанию medium;
- `cuda`: boolean; отсутствие означает автоматическое определение GPU.

Пути, команды и переменные окружения клиент передать не может. Общая авторизация
`/api` обязательна. UI не повторяет POST при потере ответа, а уточняет исход GET.
Отказ нового действия не показывает старую успешную операцию как его результат.

Сервис обслуживает настоящий каталог `<dataHome>/state/media-venv`. Допустимы
имена Python внутри его `bin` и alias родительских каталогов; сравнение не раскрывает
ссылку самого Python на системный бинарник. Ссылка вместо корня venv и внешний
`GRIGDESK_MEDIA_PYTHON` не обслуживаются. Подробность — [проверка путей](speech-managed-paths.md).
Штатный Python используется по умолчанию: после установки не нужны правка `.env`
и очередной перезапуск сервера.

`SpeechRuntime.prepareMaintenance()` запрещает обслуживание во время диктовки,
прогрева, расшифровки видео и model jobs. После допуска новые старты заблокированы
до окончания всего цикла, включая модель. Текущие распознавания не прерываются.
Межпроцессный directory lock дополняет серверную очередь.

Общий supervisor установщиков запускает каждую команду с таймаутом, явным владением
процессом и ограниченным хвостом вывода. Python получает тот же HF_HOME и пути библиотек,
что и runtime речи; личный кэш HuggingFace не используется.
Running и итог атомарно сохраняются в `state/speech-install/current.json` папки данных.
После рестарта running становится interrupted без повторения команды; живая прежняя
группа процессов блокирует новый старт. Чужие PID не завершаются.

Удаление проверяет `pyvenv.cfg` и удаляет только штатный venv. Кэш моделей, словарь,
язык и остальные настройки сохраняются. Любой исход инвалидирует диагностику;
UI перечитывает capabilities до показа готовности, без записи настроек.
Опрос работает только на активной странице и восстанавливается после возвращения.

Проверки: `speech-install.test.js`, `settings-speech.component.test.js`,
`settings-speech-session.test.js`. Fixtures используют временные каталоги,
fake runner и настоящий supervisor с поддельными командами; реальный pip не запускают.
