# Файловая диктовка: несовместимость faster-whisper и PyAV

`faster-whisper==1.2.1` вызывает `av.open(..., metadata_errors="ignore")`.
PyAV 19 удалил этот аргумент: импорт библиотек проходит, но чтение любого аудиофайла
падает с `TypeError: open() got an unexpected keyword argument 'metadata_errors'`.
Зависимость upstream `av>=11` допускает эту несовместимую версию.
В `requirements-media.txt` закреплён совместимый `av==18.1.0`.

Сбой выглядит плавающим, потому что live-worker передаёт в `model.transcribe` готовый
массив PCM и не вызывает файловый декодер. Резервный batch-путь после остановки читает
полную запись через `decode_audio`; он же используется при расшифровке встреч.

`audio-probe.py` декодирует короткий WAV из памяти через `faster_whisper.audio.decode_audio`
и проверяет число сэмплов. Модель, сеть и временные файлы ему не нужны. Общие sync/async
preflight и проверка установщика используют эту пробу, поэтому успешного импорта
недостаточно для готовности окружения. Установщик не переходит к скачиванию модели,
если файловый декодер неисправен.
Проба включена в оба allowlist серверных ресурсов и опись SEA: проверка не зависит
от наличия исходников рядом с собранным сервером.

Уже установленное окружение восстанавливается через «Настройки → Речь → Обновить»
в выпуске с исправленным requirements. Новая диктовка запускает новый Python-процесс
и подхватывает заменённый пакет без перезапуска сервера.
Обе операции установщика, `install` и `update`, используют один закреплённый requirements.
Для упакованного сервера сначала требуется установить и запустить исправленную сборку:
уже работающий процесс продолжает читать requirements из прежнего payload.

Источники: [ошибка upstream](https://github.com/SYSTRAN/faster-whisper/issues/1589),
[изменение API PyAV 19](https://pyav.basswood.io/docs/stable/development/changelog.html#v19-0-0).
