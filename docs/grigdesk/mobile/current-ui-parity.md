# Актуальный интерфейс полного Android-клиента

Полный `:client` получает тот же `web/src`, что и desktop. Оформление проектов, маршрутов,
конвейера, чатов, мастера настройки, инструментов и общих диалогов переносится сборкой
`tools/client-ui.mts`, а затем APK. Изменение `web/dist` на сервере не обновляет встроенные
ресурсы установленного приложения. Прежний `mobile/src` не определяет эти экраны.

Пакет `assets/ui` содержит `release.json`, номер API и все ресурсы, включая ленивые страницы.
Content id зависит от содержимого, поэтому учитывает незакоммиченные изменения общего UI.
Проверка готового APK сверяет manifest с собранным каталогом, каждый размер и SHA-256,
полноту файлов, пакет, версию и подпись. Для установки поверх прежней сборки требуется
тот же сертификат; повторная сборка сама по себе не требует нового ключа или привязки.

## Что входит в визуальную сверку

Карта точек входа — [экраны общего интерфейса](../web/ui-screen-inventory.md). Самостоятельных
страниц настроек сейчас 22; старый `connections.mobile` — адрес совместимости для
`connections.devices`. Вложенные окна, формы, выбранные объекты, меню топбара, отсутствие
машины и блокировка проверяются отдельно от маршрутов. Белый кадр, сообщение о неверном DTO
или незавершённое подключение терминала не подтверждают готовность рабочего экрана.

Основная матрица общего UI: телефон 390×844 и 844×390, планшет 768×1024 и 1024×768,
desktop 1440×1000. Дополнительные поверхности проверяются также при 320×568 с текстом130%,
после прокрутки до конца и при уменьшении высоты до 430 px. Площадки общих действий в touch
получают 44 px через общий режим, а переполнение кода остаётся внутри редактора.

Настоящие Vue-компоненты и CSS проверяются в Chromium с синтетическими API. Выбранный файл
Кода, загруженный документ, вывод локального тестового WebSocket и содержимое тестового iframe
должны быть видны до снимка. Внешний плагин проверяется по оболочке; дизайн его содержимого
принадлежит самому плагину.

Постоянные проверки: `client-phone.test.js`, `client-responsive.test.js`,
`machines-responsive.test.js`, `machine-welcome.test.js`, `projects-responsive.test.js`,
`routes-responsive.test.js`, `inbox-responsive.test.js`, `onboarding.browser.test.js`,
`arbiter-conversation.browser.test.js`, `video-responsive.test.js` и `e2e/settings-modal.e2e.mjs`.
Проверка видео сохраняет полную подпись добавления задачи и уже заполненный черновик.
Последний тест настроек проверяет
также старый адрес доступа, раскрытие ретрансляторов и закрытие вложенного окна.
Стенд настроек принимает `CHROME_BIN` для явного выбора полного Chromium.

## Предел проверки

Браузерная матрица подтверждает общий интерфейс, а Gradle unit/lint — нативные контракты
и сборку. Системная клавиатура, реальные вырезы, биометрия, QR-камера, микрофон, поворот
WebView и уход приложения в фон требуют отдельной проверки на физическом Android.
