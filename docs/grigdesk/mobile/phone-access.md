# Один профиль телефона с прямым и relay-подключением

Актуальный Android-модуль `:client` принимает `GRIGDESK:PHONE:2:` с прямыми адресами,
совместимым ретранслятором либо обоими путями. Старые `GRIGDESK:PAIR:1:` и direct-профили
продолжают читаться. Настольный транспорт остаётся прямым.

Один ключ установки используется для pair и следующего authenticated hello. Приватный
профиль сохраняется по server pin с прежними id и портом локального origin. В нём хранятся
direct-маршруты, optional relay и deviceId. Проекция address — первый direct либо пустая
строка для relay-only. Формат файла остаётся версии 1; старая сборка приложения не сможет
прочитать relay-only запись, поскольку требовала непустой HTTPS address.

Внешний TLS проверяет pin ретранслятора до отправки его token. Внутренний TLS проверяет
pin сервера до кода и HTTP. Нативный forwarder слушает случайный loopback-порт и переносит
зашифрованные байты с ограниченным буфером; WebView получает прежний локальный origin,
без token, code, pin или private routes в ShellState.

Единственный routing owner предпочитает прямой pinned hello. Сетевая недоступность
допускает следующий прямой адрес и настроенный relay. При работающем relay штатный health
цикл ищет direct, не публикуя пробные отказы как общую недоступность профиля.
Восстановленный direct выбирается новым запросам; начатые POST, файлы и upgrade остаются
на прежнем пути. Тело запроса не буферизуется и не повторяется при потере ответа.

Pin mismatch сервера, отзыв, чужой scope, блокировка ключа и несовместимая версия API сервера
защёлкивают весь профиль. Запасной путь не обходит отказ. Обычная бизнес-ошибка API не отзывает
устройство. Отказы самого ретранслятора — несовместимость, чужой сертификат внешнего TLS,
отвергнутый token — отключают только relay-путь с явной причиной; прямой путь остаётся доступен. Перезапуск relay без control считается временным offline.
Закрытие, фон и ручное отключение отменяют собственные соединения;
возврат сохраняет профиль и маршруты без нового QR.

Матрица совместимости:

| Сервер и ретранслятор | Прежний телефон | Новый client через relay |
|---|---|---|
| Новый сервер, старый relay | v1 сохраняется | Нужно обновить relay |
| Старый сервер, новый relay | v1 сохраняется | Capability не согласована |
| Оба обновлены | v1 сохраняется | client-v2, direct необязателен |

VPN на телефоне не нужен. Состояние waiting_vpn относится к маршруту сервера до публичного
ретранслятора. Общий token ретранслятора меняется его пересозданием; отзыв сертификата
телефона проверяется сервером независимо от выбранного пути.

Физические QR-сканер, Keystore, Wi-Fi/мобильная сеть и возврат из фона проверяются на
устройстве. Результаты такой проверки отражаются в отчёте задачи, без отдельных
инструкций установки на личный телефон и документов о разовой проверке.
