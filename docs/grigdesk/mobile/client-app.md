# Полное приложение Android

Модуль :client имеет applicationId local.grigdesk.mobile, namespace local.grigdesk.client и
общую версию mobile/package.json — 0.1.0. Он использует WebView без Capacitor; прежние :app,
mobile/src и мобильный протокол v1 сохранены отдельно.

Язык установки и собственных сообщений описан в [контракте локали](interface-language.md).
Он не меняет документ WebView при выборе языка.

WebView включает JS/DOM storage, запрещает file/content access и mixed content. Навигация
доверяет только зарегистрированным origin труб. Внешний HTTP(S) открывается системным
браузером после жеста в главном фрейме. Микрофон выдаётся только origin трубы после
RECORD_AUDIO. Файлы выбирает системный ACTION_OPEN_DOCUMENT. Cookie grigdesk_pipe ставится
HttpOnly/SameSite=Strict до загрузки. Системный Назад вызывает grigdeskBack; на корне сворачивает
приложение. Cleartext разрешён только 127.0.0.1, резервное копирование выключено.

WebPolicy проверяется JVM-тестами без устройства. Работа микрофона, выбора файла, поворота
и биометрии принимается отдельно на физическом Android.

Локальная труба использует HTTP/1.1 на loopback, пул 32 работника и ограничение заголовка
64 КиБ. Content-Length и chunked читаются потоками; неизвестная длина ответа передаётся
chunked с flush каждой части. Мутация без объявленного тела — DELETE без Content-Length и
transfer-encoding — уходит на машину без тела: произвольный RequestBody OkHttp пометил бы
chunked без Content-Type, и Fastify ответил 415 до обработчика. POST, PUT и PATCH требуют
тело в OkHttp и пересылаются как прежде. Cookie и привилегированные заголовки WebView не
идут наверх.
OkHttp использует TLS 1.3 и точный SHA-256 pin; каждый новый сокет получает отдельный
SSLContext. Upgrade использует ту же фабрику SSLSocket и передаёт бинарные байты напрямую.
Несовместимая версия прекращает начатые потоки и возвращает 426 до явного переподключения.

JVM-стенд с синтетическими клиентским и серверным сертификатами проверяет pin до HTTP,
POST 5 МиБ, SSE с задержкой второго события, бинарный upgrade, cookie и keep-alive.

Машины хранятся в приватном client-profiles.json с атомарной заменой. Один pin сохраняет
один профиль и его порт; новые машины получают отдельные порты 47101–47199. Порт 47100 —
экран без машины. Оболочка не отдаёт в WebView pin и внутренний номер порта.
Формат GRIGDESK:PAIR:1 на Java проверяется общими тестовыми векторами репозитория.

Shell API поддерживает long-poll до 25 секунд, выбор, привязку, переименование, смену адреса
после pin-проверенного hello и удаление. Только offline повторяется с паузами 1–30 секунд
и jitter ±20%; отключение и терминальные состояния гасят повторы. Сканер — своя Activity
zxing, сохранение — поток в MediaStore Downloads, разблокировка — BiometricPrompt с сильной
биометрией или кодом устройства. Имя файла с путём или `..` отвергается.

Жизненный цикл считает запущенные Activity всего приложения. Уход в фон закрывает
HTTP/SSE и upgrade наверх на рабочем потоке: TLS не закрывается в UI-потоке.
[Управляемая блокировка](app-lock.md) выключена по умолчанию и считает только непрерывный
фон по выбранному сроку 0/60/300 секунд, включая сон устройства. Холодный запуск с
включённой политикой требует подтверждения. Нативная карточка скрывает закрытый WebView
до доставки снимка; возврат до срока продолжает работу без нового prompt.
Системные диалоги учитываются отдельно: без видимости диалог получает не более 60 секунд
до ухода в фон. Поворот переносит тот же WebView через MutableContextWrapper и сохраняет
один runtime: документ и начатые POST не загружаются заново. Решения проверены JVM;
фактическая биометрия, первый кадр и поворот требуют устройства.

Прежняя личность Keystore сохраняется без пересоздания; утрата старого ключа переводит
подключение в unpaired. Современные привязки используют отдельный alias без аппаратного
срока, а доступ закрывает gate установки. Старые привязки до нового QR сохраняют
600-секундное аппаратное требование и могут показывать locked независимо от настройки.
В probe и перед новым TLS-соединением выполняется Signature NONEwithECDSA.initSign: Conscrypt может
поглотить причину при TLS-подписи, поэтому одной цепочки TLS-исключений недостаточно.
Срок прежней аппаратной авторизации проверяет Keystore, независимо от фоновой политики.
Системный выбор файла учитывается и при проверке видимости процесса, без ложного ухода в фон.
Пул OkHttp хранит незанятый сокет до 60 с; ошибки отдельного запроса и 5xx не меняют связь
и не закрывают соседние потоки. Состояние online/offline сообщает probe: первая попытка ограничена 3 с, после online
offline наступает только после трёх неудач подряд. Одна успешная проверка сбрасывает счётчик.

Отказы нативных Future разворачиваются из ExecutionException, чтобы отмена сканирования или
биометрии не выглядела сетевой ошибкой. Origin передаётся без пути, API без выбранной машины
возвращает no_machine. Неприменённая навигация хранится до появления новой Activity и применяется
один раз: поворот в момент старта не теряет URL и не перегружает уже открытый WebView.

Текущая Activity хранится слабой ссылкой и очищается в onDestroy. Удерживаемые WebView и
MutableContextWrapper имеют обоснованное подавление StaticFieldLeak: документ живёт весь процесс,
а уничтоженная Activity заменяется applicationContext. Data extraction исключает все домены
cloud-backup/device-transfer вместе с allowBackup=false. Два lint-предупреждения по JS и своему
TrustManager ожидаемы: UI требует JS, а mTLS доверяет только точному pin, не любому сертификату.

Новый [единый доступ](phone-access.md) переносит в PHONE:2 прямые и relay-маршруты
одного сервера. Старые строки PAIR:1 сохраняются; shell не публикует приватные маршруты.

Обновление адресов существующего профиля с прежними ключом и доверенными сертификатами
описано в [контракте маршрутов](phone-access.md#обновление-маршрута-существующего-профиля).
