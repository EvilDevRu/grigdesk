# Управляемая блокировка Android

Полный клиент `:client` хранит одну политику установки в приватном `app-lock.json`:
`enabled` и `delaySeconds` (0, 60 или 300). При отсутствии файла блокировка выключена,
начальный срок — минута. Телефон и планшет независимы; все машины одной установки
используют одну политику. Сервер и localStorage её не хранят.

Настройка «Блокировать приложение» находится в поведении интерфейса и сохраняется
сразу, без общего «Применить». Диалог наследует доступность настроек: online и
подтверждённый вход. На старых оболочках и desktop без блока `appLock` настройка скрыта.
Отдельного входа в настройки без машины нет.

## Фон и системное подтверждение

Считается только непрерывный фон. Активная работа не расходует срок, короткие выходы
не суммируются. Выбор «Сразу» оставляет передний план открытым и закрывает уход в фон.
Монотонные часы `elapsedRealtime` включают сон устройства: возврат сверяет срок,
даже если Handler ещё не доставил таймер. Отмена и смена политики инвалидируют старые
callback поколением. Выключение не позволяет прежнему таймеру снова закрыть приложение.
Потеря сети сама по себе gate не меняет.

Холодный запуск с включённой политикой закрыт. Пустой или повреждённый существующий
файл означает включённую защиту с минутным сроком; чтение не переписывает повреждение.
Неудачная атомарная запись сохраняет прежнюю политику, таймер и состояние в памяти.

Нативная непрозрачная карточка скрывает retained WebView до любого HTTP-снимка.
Документ и начатые POST не перегружаются. Кнопка и HTTP-разблокировка используют общий
`UnlockSession`: один системный prompt, перенос при повороте, отмена с возможностью
повтора. Успех открывает gate, сохраняя ручное отключение машины и приостановку сети
до настоящего возврата приложения. Выключить политику можно после входа.

## API и согласованный снимок

`POST /__shell/app-lock` принимает только полную пару `enabled`/`delaySeconds` и
возвращает полный снимок. Необязательный публичный блок:

```json
{ "appLock": { "enabled": true, "delaySeconds": 60, "locked": false } }
```

Gate закрывает выдачу транспорта и действия оболочки; новые API-запросы получают
423 `locked`. Доступными остаются чтение состояния и системная разблокировка.
Статус машины и блокировка приложения независимы: web учитывает `appLock.locked`
для `inert` и общего LockOverlay даже при статусе online.

`ShellState` читает gate и ревизию под своим монитором. AppLock уведомляет слушателя
после освобождения собственного монитора, поэтому нет обратного порядка блокировок.
Разблокировка тоже публикует ревизию, включая установку без выбранной машины.
Старый long-poll не может откатить принятый ответ настройки или разблокировки.

## Ключ и переход привязок

Новая привязка использует отдельный Keystore alias `grigdesk-client-v2` без аппаратного
600-секундного требования и сохраняет `clientKey: 2` в приватном профиле.
Отсутствие поля означает прежнюю личность `grigdesk-client`; транспорт выбирает ключ
по профилю. Прежний ключ не пересоздаётся и не удаляется. Непереведённые машины
продолжают работать, включая прежнее аппаратное требование подтверждения.

Для перехода нужен новый QR каждой машины. Совпадение pin обновляет тот же профиль:
пользовательское имя, id, локальный порт/origin и дата создания сохраняются, маршруты
обновляются из QR. Данные документа и черновики остаются в прежнем origin. Повтор QR
не создаёт дубль; последующее явное переименование не сбрасывает версию ключа.
Старую запись устройства на сервере человек отзывает отдельно после проверки новой.

JVM-тесты проверяют политику, срок, поколения, снимки, доступ и сохранение профилей;
web-тесты — настройку, ошибку сохранения и совместимость старых оболочек.
Настоящий Keystore, биометрия, поворот prompt, первый физический кадр, QR и две
установки требуют отдельной приёмки на Android и не доказываются JVM-проверками.
