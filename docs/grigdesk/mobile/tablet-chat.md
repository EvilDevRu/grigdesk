# Планшет и представление разговоров

Планшет показывает список и карточку рядом начиная с ширины окна 760 px, в портретной
и альбомной ориентациях. Рейка остаётся узкой, без подписей; названия доступны по ARIA.
Класс устройства определяется короткой стороной `screen`, поэтому уменьшение высоты
окна клавиатурой не переключает планшет в телефонную раскладку. Более узкое окно,
например разделённый экран Android, оставляет одну колонку с возвратом к списку.

## Список

Аватар содержит знак исполнителя. Цвет и имя приходят из адаптера сервера, а локальная
таблица векторных знаков независима от веб-пакета. Неизвестный исполнитель получает
первую букву имени. Кольцо работающего чата вращается отдельно от знака; при
`prefers-reduced-motion` остаётся статичным. SVG целиком помещается в коробку аватара:
вращение его окружности не увеличивает `scrollWidth` строки.

Строка показывает название, компактное время и превью последней непустой реплики.
В узкой колонке чип модели уступает место названию. Тумблер «Показывать архив»
переключает активные и архивные чаты. Поиск ограничен загруженными строками.
Черновик имеет приоритет над превью, хранится в памяти текущей разблокированной сессии
и переживает смену чата/раздела. Блокировка очищает его. Отправка очищает только исходный
черновик исходного чата; новый текст, набранный до завершения отправки, не стирается.

## Содержимое чата

Ответы понимают заголовки, выделение, списки, цитаты, inline code, таблицы и ссылки.
`marked` используется только как tokenizer; Vue создаёт узлы из разрешённого набора.
HTML остаётся текстом, изображения по-прежнему получает отдельный авторизованный
компонент. HTTP(S)-ссылка по нажатию открывается системным браузером: внешний документ
не загружается в WebView с нативным мостом. Файловые пути остаются текстом.

Шаги сохранённого ответа доступны по строке счётчиков. Живой ход сразу показывает
действия, опубликованные резюме размышлений и текстовые шаги. Нажатие раскрывает команду,
путь или результат. Обновление результата не закрывает раскрытый шаг. Кнопка
«К последним сообщениям» возвращает к концу; автоматическая прокрутка не мешает чтению
выше. Повторный progress не начинает новое чтение до завершения предыдущего.

Это ограниченная проекция ленты: сохранённые шаги сгруппированы при ответе, сложные
диффы и вложенные субагенты не получают отдельную визуализацию веба. Не следует считать
отсутствие переполнений доказательством полного соответствия веб-разговору.

В 0.1.8 добавлены общая линия сообщений одного хода, настройка вида разговора,
перенос остановки к отправке и компактный верх списка. Подробности —
[поиск, архив и вид разговора](chat-layout-controls.md).

## Совместимое расширение API

Все новые поля необязательны в v1; замороженный decoder старого выпуска принимает их.

- `chat.provider`: `id`, `name`, шестизначный hex `color` из адаптера, без probe/auth.
- `chat.preview`: до 300 символов. Вычисляется вместе с кэшированной шапкой истории;
  повторное чтение списка не перечитывает сообщения неизменённых файлов.
- `messages[].activity` и `activity` живого чата: `items` и счётчик `omitted`.
  Вызов инструмента и результат соединяются по id; незнакомое событие остаётся строкой.
  На проекцию — до 400 элементов и 128 KiB JSON, на текст/результат — 6000 символов;
  усечение помечено. Бюджет ответа остаётся 2 MiB.

Новые данные требуют обновлённого процесса GrigDesk. На прежнем сервере приложение
продолжает работать с буквенными аватарами и прежней историей без шагов.

Проверки: `mobile-chat-presentation.test.js` проверяет преобразование и совместимость,
`chat-presentation.test.js` — безопасное представление и обновление раскрытого шага,
`ui.test.js` — сохранение черновика. Визуальные сценарии `chat-tablet`, `chat-tablet-live`
и `chat-tablet-actions` добавлены к общей матрице, включая портрет и шрифт 130%.
