# Авторизация существующего Android-ключа

В полном клиенте `:client` ключ `DeviceKey` создаётся в Android Keystore с обязательной
аутентификацией и разрешением использования на 600 секунд. `ensure()` возвращает управление,
если alias уже существует: обновление APK не применяет к нему новые параметры генератора.

Согласно [контракту Android Keystore](https://developer.android.com/privacy-and-security/keystore#key-use-authorizations),
авторизации ключа задаются при генерации или импорте и впоследствии не меняются.
Изменение настройки интерфейса само по себе не снимает требование аутентификации старого ключа.
Срок разрешения Android также не зависит от того, сколько времени приложение было в фоне:
[параметры аутентификации](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder#setUserAuthenticationParameters(int,int)).

`DeviceKeyManager` предъявляет сертификат этого ключа во внутреннем TLS. Серверный реестр
устройств авторизует его по отпечатку сертификата. Создание другой личности без согласованного
перехода привязки не сохраняет доступ под прежней записью устройства.

Это ограничение существующего устройства ключа, а не требование нового QR для обычной
[разблокировки](unlock-recovery.md). Способ перехода на другую политику ключа здесь не задаётся.
