# Развёртывание посредника

Посредник запускается [готовым Go-бинарником](relay-binary.md).

В настройках GrigDesk откройте «Подключения → Доступ к серверу». Ручная настройка
ретрансляторов раскрывается отдельно: добавьте имя, адрес и порт посредника.
Скачайте `relay.env`; храните его вне checkout с правами 0600 и передайте на машину посредника
без публикации в переписке или репозитории. Для VDS сначала настройте и проверьте системный
запрет прямого выхода мозга при отказе VPN. [Граница сети](#граница-vpn).

Скопируйте готовый бинарник и свой `relay.env` на выбранную машину. При ручном
запуске загрузите переменные из защищённого файла и запустите бинарник по
[инструкции](relay-binary.md). Адрес и порт должны совпадать с настройкой посредника.

`grigdesk-ctl relay status` показывает связи, зарегистрированные на домашнем сервере.
Общий `grigdesk-ctl status` из рабочей копии также выводит эти связи. Запуск и журнал
службы на VPS обслуживает systemd. [Контракт CLI](../server/grigdesk-cli.md).

## Мастер для отдельного VPS

«Удалённый доступ» на той же странице и команды `grigdesk-ctl relay setup` / `relay restore`
используют одно серверное задание. Первая платформа — Ubuntu/Debian x64 с systemd,
без Docker, Node и исходников на VPS. Сначала проверяются host key, платформа, библиотеки,
права и порт; установка начинается только после отдельного подтверждения изменений.
Пароль либо выбранный приватный ключ и его фраза живут только в памяти операции.

Закрытие окна или консоли не отменяет принятое задание. Откройте настройку снова для
просмотра результата; после прерывания нужен повторный SSH-ввод. Системная служба работает
от отдельного пользователя, env имеет режим 0600. Готовность доказывает канал с домашним
сервером, подключение телефона отдельно подтверждается authenticated hello.
При обрыве после замены файла откройте то же задание и нажмите «Продолжить установку
по SSH». Мастер проверит прежний ключ VPS и продолжит установку выбранного выпуска.
При ожидании DNS или VPN исправьте настройку и нажмите «Проверить»: новый ввод
SSH-доступа для готового выпуска не требуется.

Для восстановления выберите сохранённое подключение и SSH нового VPS. Старые сертификат,
pin и секреты берутся из домашнего GrigDesk. При прежнем DNS и порте обновите DNS;
состояние ожидания не выдаётся за успешное переключение. При новом публичном адресе
обновите маршрут существующего профиля телефона без удаления ключа и доверия.
Адрес проверки нового VPS задаётся отдельно, если отличается от SSH-входа.
Список заданий позволяет открыть нужную попытку. Для смены VPS до установки завершите
ожидание отдельным действием; в ctl выберите 0 и подтвердите завершение старого ожидания.
Подробности журнала и API — [серверное задание](../server/relay-setup.md).

## Домашний посредник и перенос

Для домашнего посредника нужен доступный телефону адрес и проброс опубликованного порта,
если он требуется вашей сетью. Мозг устанавливает исходящие соединения. Основной HTTP слушает loopback.
прямой вход приложений включается отдельной настройкой.

На новый VDS переносите прежний `relay.env`: он сохраняет сертификат/pin и секреты ролей.
Сохранение адреса через DNS позволяет телефонам пользоваться прежней записью без повторной
привязки мозга. Если адрес или порт меняется, восстановите подключение с новым адресом и используйте
«Обновить маршрут» на уже привязанном телефоне с новым PHONE:2 QR. Произвольная смена pin существующей записи требует её явного удаления.

QR PHONE:2 содержит краткоживущий pair-код. Повтор с прежним сертификатом сохраняет
запись устройства.

## Wire-протокол посредника

Внешний TLS начинает обмен одной строкой UTF-8 JSON, ограниченной 2048 байтами.
Управляющий канал открывает домашний сервер с `v:1` и ролью `brain-control`.
Стороны согласуют capability `client-v2`. Служебный запрос `health` также использует `v:1`.
Секреты ролей различаются, подтверждение успешного hello содержит `{"ok":true}`.

Полное приложение посылает `v:2,target:client,role:device`. Посредник сообщает
`incoming` с идентификатором и целью по управляющему каналу. Домашний сервер
открывает отдельный `brain-data` с той же целью и идентификатором, затем передаёт
байты в клиентский TLS-вход. Несовпадающая цель не расходует ожидающую пару.
Посредник принимает прежние запросы пар версии 1, однако домашний сервер
открывает локальный вход только для согласованной цели `client`.

Байты после hello сохраняются для туннеля. Посредник передаёт поток с backpressure
и не разбирает внутренний TLS или HTTP. Закрытие любой стороны закрывает всю пару.
Лимиты соединений, IP ban и жизненный цикл Go-процесса принадлежат `utilities/relay/`.
[Сборка и проверки посредника](relay-binary.md).

## Граница VPN

Для публичного посредника домашний сервер проверяет VPN-маршрут к каждому
разрешённому числовому IP перед подключением и во время связи. Потеря маршрута
закрывает пары и переводит связь в `waiting_vpn`. Домашний посредник допускается
по локальному маршруту.

Для публичного подключения настройте системный kill switch и проверьте, что при
отказе VPN отсутствует прямой исходящий трафик по IPv4 и IPv6, включая уже открытые
соединения. Проверку выполняют на реальной сети. GrigDesk самостоятельно не меняет
firewall и не отключает VPN.
