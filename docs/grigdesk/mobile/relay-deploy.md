# Развёртывание посредника

Вариант без Docker — [посредник одним готовым файлом](relay-binary.md).

В настройках GrigDesk откройте «Подключения → Доступ к серверу». Ручная настройка
ретрансляторов раскрывается отдельно: добавьте имя, адрес и порт посредника.
Скачайте `relay.env`; храните его вне checkout с правами 0600 и передайте на машину посредника
без публикации в переписке или репозитории. Для VDS сначала настройте и проверьте системный
запрет прямого выхода мозга при отказе VPN: [граница сети](native-security.md).

Контейнер собирается из каталога `relay/`. Пример использует placeholders; путь к env
должен быть абсолютным и принадлежать владельцу развёртывания.

```bash
RELAY_ENV_FILE=/secure/location/relay.env RELAY_PUBLISH_PORT=443 \
  docker compose -f relay/compose.yaml up -d --build
docker compose -f relay/compose.yaml ps
docker compose -f relay/compose.yaml logs --tail 50
```

При каждой compose-команде используйте те же `RELAY_ENV_FILE`/`RELAY_PUBLISH_PORT`
либо собственный приватный env-файл Compose, а также постоянное имя проекта `-p`:
сквозная проверка поднимает свой проект `grigdesk-relay-check` и рабочий не трогает.
Контейнер слушает 7443 внутри; опубликованный порт должен совпадать с адресом,
записанным в настройках мозга и QR. Рабочий GrigDesk не помещается в этот контейнер.

Compose задаёт read-only filesystem, непривилегированного пользователя, снятые capabilities,
`no-new-privileges`, 256 MiB, 128 PID и ограниченный local log. Supervisor завершает
контейнер при сбое или зависании дочернего relay; `restart:unless-stopped` восстанавливает его.
Обычный `docker stop` является явной остановкой и не должен немедленно отменяться рестартом.
Healthcheck проходит через настоящий TLS `health` протокол.

## Повседневное управление локальным контейнером

После развёртывания `grigdesk-ctl relay status`, `start`, `stop`, `restart` и `logs -n 50 -f`
управляют существующим контейнером. `grigdesk-ctl status` показывает также связь посредников
с сервером. CLI не выполняет compose up и не запускает посредник автоматически.
Контейнер выбирается по метке compose service=relay и точному compose-файлу текущей копии;
при нескольких контейнерах или нескольких compose-файлах задайте `GRIGDESK_RELAY_PROJECT`
в `.env` папки данных. [Контракт команды](../server/grigdesk-cli.md).
Для посредника готовым файлом используются команды из [его инструкции](relay-binary.md).

## Мастер для отдельного VPS

«Удалённый доступ» на той же странице и команды `grigdesk-ctl relay setup` / `relay restore`
используют одно серверное задание. Первая платформа — Ubuntu/Debian x64 с systemd,
без Docker, Node и исходников на VPS. Сначала проверяются host key, платформа, библиотеки,
права и порт; установка начинается только после отдельного подтверждения изменений.
Пароль либо выбранный приватный ключ и его фраза живут только в памяти операции.

Закрытие окна или консоли не отменяет принятое задание. Откройте настройку снова для
просмотра результата; после прерывания нужен повторный SSH-ввод. Системная служба работает
от отдельного пользователя, env имеет режим 0600. Готовность доказывает канал с домашним
сервером, подключение телефона отдельно подтверждается authenticated hello.
При повторной установке изменённая служба перезапускается, одинаковая рабочая конфигурация
остаётся активной. Отказ новой сетевой проверки откатывает прежнюю установку на том же VPS;
потеря SSH может оставить результат отката неизвестным и требует повторного ввода доступа.

Для восстановления выберите сохранённое подключение и SSH нового VPS. Старые сертификат,
pin и секреты берутся из домашнего GrigDesk. При прежнем DNS и порте обновите DNS;
состояние ожидания не выдаётся за успешное переключение. При новом публичном адресе
обновите маршрут существующего профиля телефона без удаления ключа и доверия.
Адрес проверки нового VPS задаётся отдельно, если отличается от SSH-входа.
Список заданий позволяет открыть нужную попытку. Для смены VPS до установки завершите
ожидание отдельным действием; в ctl выберите 0 и подтвердите завершение старого ожидания.
Подробности журнала и API — [серверное задание](../server/relay-setup.md).

## Домашний посредник и перенос

Для домашнего посредника нужен доступный телефону адрес и проброс опубликованного порта,
если он требуется вашей сетью. Мозг устанавливает исходящие соединения; основной сервер
GrigDesk и мобильный TLS-вход не публикуются. Docker-сеть не должна перекрывать маршруты VPN:
[конфликт подсети](../server/docker-vpn-subnet-conflict.md).

На новый VDS переносите прежний `relay.env`: он сохраняет сертификат/pin и секреты ролей.
Сохранение адреса через DNS позволяет телефонам пользоваться прежней записью без повторной
привязки мозга. Если адрес или порт меняется, восстановите подключение с новым адресом и используйте
«Обновить маршрут» на уже привязанном телефоне с новым PHONE:2 QR. Произвольная смена pin существующей записи требует её явного удаления.

QR с первой привязкой ограничен по времени. Современный PHONE:2 содержит краткоживущий pair-код; повтор прежним сертификатом
сохраняет устройство. Прежний QR старого приложения имеет отдельный контракт.
