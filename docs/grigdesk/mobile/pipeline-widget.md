# Виджет «Конвейер»

Виджет главного экрана показывает три счётчика живого конвейера выбранной машины:
«В работе», «Ждут вас», «Остановлены». Текст задач и причины остановок не покидают сервер.

## Данные

`GET /api/factory/widget-summary` за общим auth guard отдаёт `{running, waiting, stalled, at}`.
Счётчики считает `server/src/lib/factoryWidget.ts` по сводкам `listTasks`: завершённые
(`completed`/`abandoned`) и read-only проекции пропускаются; «ждут вас» — `stalledHuman`,
`bootstrapStop.state ∈ {waiting, answered}`, остановка `kind: human` или ворота `GATE_*`
со статусом `wait|waiting|premature` в `stageMap` (ключи реестра route-v2 заглавные,
сравнение без регистра); «остановлены» — крах демона (`stall`); «в работе» — живой демон.
Одна задача попадает ровно в один счётчик, ожидание человека важнее краха и демона.
Правила осознанно отличаются от прежнего фасада attention (read-only не считается,
приоритет ожидания, терминальный набор ledger).

## Обновление

- Периодика: WorkManager, 15 минут, без сетевого constraint, уникальная работа KEEP;
  назначается в `ClientApplication.onCreate` и переживает смерть процесса.
- События: веб на SSE `state-change` шлёт `POST /__shell/widget-refresh` (пустой объект)
  с leading+trailing окном 10 секунд; труба увеличивает requestId и ставит работу
  APPEND_OR_REPLACE. Capability снимка — `widget`. Последний сигнал внутри окна не теряется.
- Воркер `PipelineWidgetWorker` читает `client-profiles.json`, создаёт собственный
  `RoutedUpstream` с ключом профиля (v2 подписывает в фоне без биометрии) и сохраняет
  ответ в кэш `pipeline-widget.json` (атомарная запись, profileId/requestId, битый файл = «данных нет»).
- Все попытки одной машины разделяет окно 10 секунд: новый запрос ждёт, а не теряется.
  Один процессный lock сериализует periodic/one-shot; обработанные requestId не повторяют HTTP.
  Deadline 90 секунд закрывает transport. onStopped прерывает ожидание и запрещает commit.
- Отсутствие сети определяется при выполнении работы и даёт offline без HTTP.
  Android может откладывать выполнение; периодика не обещает точного времени.
- ClientRuntime.show перерисовывает виджет до навигации; смена/удаление выбора немедленно
  скрывает числа старой машины. Все renderAll используют PipelineWidgetPublication:
  выбор/кэш читаются внутри общей операции вместе с updateAppWidget. Commit проверяет источник.

## Состояния и блокировка

Кэш хранит последние счётчики и состояние: `ok`, `offline`, `locked`, `no_machine`,
`unpaired`, `identityMismatch`, `client_upgrade_required`, `server_upgrade_required`.
Отказ связи сохраняет только успешные данные той же машины. До первого успеха — прочерки;
пустой успешный конвейер — нули. device_revoked/device_unknown/device_scope_forbidden/pair_locked
нормализуются в unpaired; коды версии получают отдельные подписи. Закрытый gate пропускает
`widget-refresh` как данные (решение владельца): счётчики — не переписка, интерфейс остаётся
заблокированным. Прежний ключ с аппаратной авторизацией: транспорт возвращает терминальный
код `locked` в теле ответа, обновление сохраняет его в кэше без успешного запроса.
Тап по виджету открывает `/#/pipeline` через extra `grigdesk_notify_url` и существующий
механизм `applyNotifyUrl`: адрес переживает холодный старт и блокировку. Intent задаёт
NEW_TASK|CLEAR_TOP|SINGLE_TOP; retained-ветка onCreate тоже применяет pending URL через прежний guard.
После потребления applyNotifyUrl удаляет extra текущего Intent. Поворот сохраняет выбранный
пользователем раздел после уже исполненного тапа; пока gate/pageLoaded закрыты, цель остаётся ожидающей.

## Границы проверки

Классификация, кэш, обновление и труба проверяются JVM/Node-тестами. Фактический показ
виджета, тап, кнопка обновления, периодика после смерти процесса и поведение прежнего ключа
принимаются на физическом Android. Конфигурационной Activity нет: машина — выбранная
в приложении; без машины виджет показывает «Нет машины».
