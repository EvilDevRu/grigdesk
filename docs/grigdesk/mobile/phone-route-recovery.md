# Восстановление телефонного транспорта

PHONE:2 использует один ключ установки для pair и подтверждения. После pair приложение
закрывает транспорт bootstrap и открывает новый для authenticated hello. Это работает
также с сервером, сохраняющим keep-alive bootstrap до закрытия сокета. Профиль появляется
только после подтверждения pin и устройства. Имя и маршруты проверяются до вставки новой
записи в список профилей: неудачная проверка не повреждает следующее сохранение.

Один routing owner выполняет один probe одновременно. Запросы, пришедшие до выбора пути,
ждут его результат; закрытие поколения отменяет также ожидающих. Рабочий relay не становится
offline из-за пробного отказа direct. Поиск пути, запущенный прикладным запросом WebView,
публикует только успех: его offline отменял бы плановый повтор ShellApi, который создаёт
новый транспорт. Сам запрос получает 503 с причиной пути, например `relay_upgrade_required`.
Health-проба ShellApi, дождавшаяся чужого поиска, сообщает его итог. Начатые HTTP, POST, SSE и upgrade продолжают использовать
свой child и не повторяются при смене пути или потере ответа.

`brain_offline` после перезапуска relay — временный сетевой отказ. После восстановления
control штатный следующий probe снова использует relay без нового QR. Отказы самого
ретранслятора отключают только relay-путь до нового транспорта профиля и сообщаются через
offline с причиной: несовместимый протокол — `relay_upgrade_required`, чужой сертификат
внешнего TLS — `relay_pin_mismatch`, отвергнутый token — `relay_unauthorized`. Поиск direct
продолжается: у него собственный pin сервера, поэтому подмена или пересоздание relay не
открывает доступ к серверу. Несовместимость API сервера, pin/identity сервера на любом пути,
отзыв, scope, блокировка ключа и `pair_locked` остаются терминальными для всего профиля. Код блокировки привязки распознаётся также в настоящем ответе HTTP 429.

Нативный relay forwarder допускает 16 пар: шесть запросов WebView, SSE, WS и пять idle
соединений OkHttp укладываются с запасом. Это меньше серверного лимита 24 на сертификат;
общий бюджет ссылки relay остаётся прежним. Пул forwarder содержит один accept и два
работника на каждую пару, чтобы idle-соединения не блокировали новые направления.

Для direct сохранены трёхсекундные connect/hello. Для relay внутренний handshake и
ограниченный probe получают 75 секунд с учётом внешнего TLS и дозвона сервера. Ответ hello
после рукопожатия ждётся не дольше 10 секунд, в том числе по соединению из пула: мёртвый
сервер за relay обнаруживается за секунды, а не за минуты. Внешний ACK
ожидается до 65 секунд, внешний handshake — до пяти. Потоковые HTTP-ответы не получают
общий callTimeout. Pin ретранслятора по-прежнему проверяется до token, pin сервера — до HTTP.

JSON-поля PHONE:2 проверяют исходные типы: числовой id, строковый protocol, дробный port
и pin в виде массива отвергаются до сети; общие векторы TS и Java лежат в
`tests/fixtures/phone-pairing-vectors.json`. Нативный `org.json` не должен молча преобразовывать такие значения.
