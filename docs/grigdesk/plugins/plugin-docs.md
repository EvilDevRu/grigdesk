# Документация пользовательского плагина

Документация плагина приезжает и уходит вместе с его пакетом: у GrigDesk нет копии чужих
инструкций. Плагин не установлен — его документации нет; выключен — агент о ней не узнает.

## Постоянное место

Оглавление — `docs/README.md` в корне пакета, документы — рядом с ним в `docs/`. Манифест
это место не настраивает: GrigDesk знает его заранее (`server/src/lib/pluginDocs.ts`,
`PLUGIN_DOCS_DIR` и `PLUGIN_DOCS_INDEX`). Содержимое документов GrigDesk не читает и не
проверяет — путь к оглавлению получает агент и дальше идёт по ссылкам сам.

Документация есть, когда `docs/` — обычный каталог, а `README.md` в нём — обычный файл.
Ссылка на месте любого из них не принимается: каталог агент читает без вопроса человеку, и
это право не должно уводить за пределы пакета. Ссылки глубже, внутри `docs/`, GrigDesk не
проверяет; пакет из git их не допускает вовсе ([проверка пакета](user-plugin-package-validation.md)).
Плагин без `docs/README.md` работает как прежде, только агент не получает его оглавления.

Формат оглавления для авторов — в `author-contract.md`, раздел «Документация».

## Какие плагины доступны

`fastify.pluginDocs()` (модуль `server/src/modules/plugins`) берёт из каталога только
включённые пользовательские плагины, чей `api` GrigDesk поднимает. Плагин, заблокированный
recovery установщика, в каталог не попадает — и сюда тоже. Системные плагины
документируются в `docs/grigdesk/` и в подсказке не участвуют.

Оглавление ищется на каждом вызове, а не только при скане каталога: появление и удаление
`docs/README.md`, установка, удаление и тумблер плагина видны следующему ходу без
рестарта. Рестарта после включения ждёт только код плагина — его документация в подсказке
появляется сразу.

## Подсказка хода

Обычный ход чата получает после текста человека блок (`server/src/lib/chat/pluginDocsHint.ts`):

```text
[Подсказка GrigDesk: документация плагинов]
Включённые плагины держат документацию у себя, оглавление — docs/README.md в папке плагина.
Открывай его, только если просьба касается плагина, и читай документы по ссылкам из него.
- «<имя>» (<id>) — <описание>: <абсолютный путь плагина>/docs/README.md
[/Подсказка]
```

- Плагины идут по id. Имя и описание из манифеста сводятся к одной строке до 200 символов,
  квадратные скобки становятся круглыми: подпись не может закрыть рамку блока.
- В блоке не больше 20 плагинов; об остальных — одна строка с шаблоном пути.
- Путь абсолютный: рабочая папка разговора может лежать далеко от каталога плагинов.
- Без плагинов с документацией текст хода не меняется — контекст не тратится.
- Блок стоит перед подсказкой о картинках и хуком названия. В историю уходит исходный
  текст человека. Сжатие контекста и слэш-команда блока не получают.
- Сбой поиска пишет предупреждение в журнал сервера; ход идёт без подсказки.

## Право чтения

Запуск исполнителя получает `pluginDocsDirs` — каталоги `docs/` из подсказки. Поле одно и
то же у всех ходов, включая служебные: иначе сжатие переоткрывало бы живую сессию.

- **Claude** без правила отклоняет Read вне рабочих каталогов. Адаптер дописывает
  `Read(//<каталог>/**)` к `permissions.allow` настроек `--settings`, как для каталога
  вложений ([картинки в уточнении](../chat/in-turn-images.md)). Набор каталогов входит в
  `restartOn`: изменился список плагинов — живая сессия переоткрывается с тем же sessionId.
- **Codex** без строгих readable roots читает файлы вне рабочих корней сам.
- **DeepSeek и GLM** (DSH) в `workspace-write` не спрашивают approval на read; чтение вне
  cwd песочница оставляет доступным ([DeepSeek Harness](../guide/deepseek.md)).
- **Kimi** живёт в своём mount namespace только с рабочей папкой и вложениями: оглавление
  плагина вне рабочей папки ему не видно.
