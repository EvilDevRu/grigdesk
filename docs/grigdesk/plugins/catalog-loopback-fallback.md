# Локальный резерв каталога

Третий хост каталога — `http://127.0.0.1:4174`. Сервер обращается к нему после отказа
обоих публичных источников. Все три хоста используют `/api/plugins/v1/` и единый
каталог с историей API 1 и API 2. Порядок полных адресов приведён
в [выборе источника](catalog-failover.md).

HTTP разрешён только этому origin. Другой порт, `localhost`, другой loopback-адрес
или публичный HTTP-хост не допускаются. Credentials, query, hash и посторонний путь
также запрещены; redirects не выполняются. Адреса поступают из серверного списка,
окно не может передать свой URL.

Локальный ответ проходит те же проверки размера, типа JSON, схемы и согласования
снимка с карточкой. HTML вместо JSON считается отказом источника.
Корректный пустой JSON-каталог считается успешным, поэтому доступный пустой публичный
каталог не переключает чтение на локальный сайт.

Сервис обращается к loopback компьютера, на котором работает сервер GrigDesk.
Кеш не делает локальный источник приоритетным: каждое обновление снова начинается
с публичного основного сайта. Сеть по-прежнему не вызывается при запуске приложения.

Три попытки ограничивают ожидание индекса 15 секундами. Браузер оставляет запас
и ждёт 20 секунд. Общий срок чтения карточки остаётся 12 секунд.

Проверки `tests/server/plugin-catalog-local.test.js` подтверждают последний приоритет
локального хоста, оба API в едином v1, чтение карточки, возврат на публичный сайт
и ограничения URL. Сеть в тестах синтетическая.
