# Хост профиля в ссылках на стенд

Профиль может требовать конкретный hostname для локального входа приложения.
`PROFILE_SERVICE_HOST` передаётся сервером в поле `serviceHost` обзора песочниц,
графа конвейера и каталога целей презентаций. Значение читается без исполнения
`profile.sh`; схема, порт, путь и учётные данные не допускаются.

Общий клиентский генератор `sandboxUrl(port, serviceHost)` предпочитает этот хост
hostname окна GrigDesk. Старый сервер может не передать поле: тогда локальные
`127.0.0.1` и `[::1]` заменяются на `localhost`, а удалённый hostname сохраняется.
Тот же fallback применяется к портам Docker, у которых нет профиля.

Это устраняет цикл авторизации приложений, которые принимают числовой loopback за
внешнюю среду и отправляют браузер на отсутствующий серверный login-путь. Маршруты
самого приложения и конфигурация его dev-сервера не изменяются.
