# Декларации пакета и подсказки редактора

Сборщик `web/scripts/buildPluginTypes.mjs` сначала выпускает декларации серверного
и оконного контрактов, затем подготавливает переносимую папку. Относительные импорты
исходников сервера и достижимых публичных типов указывают на существующие `.ts`-файлы:
их проверяет граф точек входа. В готовых декларациях эти ссылки преобразуются в `.js`,
которые TypeScript разрешает в соседние `.d.ts` без исходников GrigDesk.

Пометка `@internal` у служебного UI-экспорта должна стоять на его исходном объявлении
в готовом пакете. Комментарий только у строки `export { ... } from ...` не появляется
в подсказке TypeScript. После подготовки файлов сборщик разрешает псевдонимы экспортов
через TypeScript checker и помечает объявления функций и переменных, включая default
компоненты Vue. Исходные SFC, публичный фасад и состав runtime-экспортов не меняются.
Если служебный экспорт или его объявление не найдены, сборка завершается ошибкой.

`TSDK-PACKAGE` проверяет QuickInfo во внешнем проекте автора: все служебные экспорты
имеют тег `internal`, а обычные `UiButton` и `confirmDialog` его не получают.
Переносимость ссылок и реальные props, события и слоты проверяются тем же набором
`tests/web/plugin-types.test.js`; соответствие значений runtime-фасаду — отдельным
`tests/web/plugin-types-facade.test.js`.
