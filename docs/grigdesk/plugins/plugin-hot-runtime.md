# Включение и обновление без перезапуска

Пользовательские плагины API 1/2 загружаются при первом включении, а после обновления
или отката включённый пакет сразу получает новый сервер и панель. Выключенный пакет
сохраняет своё состояние; следующее включение подключает новую версию. Здоровый runtime
возвращает `needsRestart: false`, installer — `restartRequired: false`.

## Владение сервером

`modules/plugins/runtime.ts` создаёт отдельный Fastify для каждого плагина без нового
слушающего порта. Постоянные `/api/ext/:id` и `/api/ext/:id/*` проходят общий auth guard,
затем admission и передают исходные HTTP request/response собственному router. Тело
ещё не разобрано: сохраняются JSON, multipart, потоки и WebSocket. `authKind` и
`authPrincipal` переносятся из доверенного request через WeakMap, не через заголовки.
Общие серверные декораторы доступны по живым ссылкам; hooks и маршруты принадлежат
отдельному серверу. Префикс ограничивает доступные снаружи пути плагина.

Выключенный при boot плагин не импортируется. Первое включение ждёт готовности сервера
до записи enabled и открытия admission. Конкурентные изменения во время загрузки
отклоняются. Отказ загрузки не записывает новое enabled; неудачная попытка выполнения
остаётся potentially loaded, поскольку top-level код мог создать timer или child.
Неподдерживаемый API и конфликт серверных входов по-прежнему требуют исправления пакета.

Обычный off сразу закрывает новые запросы, on открывает тот же сервер. Принятые
потоки/WS продолжаются. За остановку собственных фоновых задач при off отвечают
`onDisable`/`prepareChange` плагина, за окончательную очистку — его Fastify `onClose`.

## Замена файлов и ESM

Admission сначала закрывает новые запросы, ждёт drain и проверяет `busyReason`.
Если автор объявил `prepareReplace`, сохраняется его lease. Иначе управляемый runtime
закрывает свой Fastify, дожидаясь `onClose`, и предоставляет lease ядра. Это не обход
проверки занятости. Автор обязан освобождать свои ресурсы в `onClose`; ядро не убивает
процессы или таймеры плагина произвольно. Зависшее закрытие не разрешает замену файлов.

При installed прежний сервер закрывается и удаляется; refresh сканирует новый пакет
и подключает включённую версию. При reverted после закрытия создаётся прежний сервер,
сохраняющий off/on. При blocked старый gate остаётся закрыт. Failed import/register
не получает fallback lease; для такого исхода сохраняется очередь следующего запуска.

Каждая загрузка серверного кода использует отдельную временную копию пакета без `.git`.
Новый путь обновляет весь ESM graph, включая относительные зависимости; один query
у `server.js` этого не обеспечивает. `options.plugin.dir` по-прежнему указывает на
установленный пакет, `dataDir` остаётся постоянным вне заменяемого дерева. Копия
удаляется после `onClose`. Сам Node не выгружает уже импортированные ESM из памяти.

Оконные JS/CSS/переводы получают адреса `/api/ext/<id>/module/<generation>/…`.
У iframe API 1 меняется src `/api/ext/<id>/web/<generation>/`, обновляя страницу и её imports.
Новый адрес меняет базу относительных imports и сбрасывает закэшированные ошибки
браузерного ESM. Поколение обновляется также при повторном включении. Прежний адрес
поколения после обновления не раздаёт файлы новой версии. Общий `state-change` сообщает
окнам о свежем каталоге; существующий runtime окна отзывает старый контекст и панель.
Обновление окна или отдельный SSE плагину не требуются.

Удаление закрывает тот же собственный сервер, убирает маршруты и возвращает
`restartRequired: false`. Настройки и dataDir сохраняются.

## Проверка

`plugin-hot-runtime.test.js` использует реальные Git-релизы, общий installer,
auth и один экземпляр сервера. Он проверяет update → off/on → rollback, новые
относительные зависимости, ресурсы панели, обновление выключенного пакета,
busy и восстановление прежнего router при испорченном кандидате. Дополнительно
`plugin-runtime`, `plugin-changes`, `plugin-install-lifecycle`, `plugin-install-routes`,
`plugin-server-entry`, `plugin-web-module` и `plugin-remove` проверяют admission,
авторизацию, TypeScript, streams/WS и отказы lifecycle.
