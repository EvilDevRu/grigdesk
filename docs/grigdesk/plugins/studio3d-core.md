# Ядро обработки 3D

Общие формы раздела объявлены в `shared/studio3d/studio3dContracts.ts`. Декодеры отклоняют
неизвестные поля, нечисловые расходы и прогресс вне 0–100. Неизвестное принятие заказа
представлено `unknown`; явное прекращение ожидания — `unresolved`. Второе состояние
не активно, но не означает нулевое списание или возврат. Проверка скелета имеет
собственные job и child, состояния pending/ready/failed/unknown/unresolved.

Облачный исполнитель разделяет чистое разбиение `plan`, бесплатную подготовку
`prepare` и однократный `send`. Каждая позиция хранит собственные параметры.
Snapshot доступа связывает загрузку и отправку с одним аккаунтом; кеш загрузок
учитывает аккаунт и SHA-256. Credentials не являются частью сетевых DTO.

HTTP deadline клиента охватывает заголовки и чтение JSON, ограниченное 4 МиБ.
Повреждённый успешный ответ, неизвестный отказ и 5xx после создания не доказывают
непринятие заказа. Клиент не повторяет POST автоматически.

Скачивание идёт потоком. Продолжение partial требует сильного ETag и согласованного
Content-Range; смена URL или валидатора запускает скачивание заново. Chunked 200
может завершиться без Content-Length. Файл публикуется после полного EOF, проверки
размера, локального SHA-256 и fsync. SHA-256 подтверждает локальное содержимое,
а целостность продолжения обеспечивают валидатор и диапазон.

CDN не получает Authorization/Cookie. Разрешены публичные HTTPS адреса, каждый из
не более трёх переходов проходит проверку DNS/IP. Соединение использует выбранный
проверенный адрес без повторного DNS. Тестовая подмена транспорта доступна только
в dependency injection, не в параметрах API.

GLB анализ и локальный rewrite выполняются общей очередью в отдельном процессе:
файл до 150 МиБ, JSON до 16 МиБ, 100 000 узлов и глубина до 256. Heap ограничен
256 МиБ, watchdog завершает собственного ребёнка при RSS свыше 512 МиБ или сроке
60 секунд. Это эксплуатационный предел, а не обещание защиты хоста от OOM.
Вход читается через проверенный дескриптор, размер подтверждается до аллокации.
Граф обходится линейно; instancing сохраняется. Bounds без min/max, с анимацией
или skinned mesh считаются неизвестными: масштаб по ним недоступен.

Основной файл выбирается по объявлению task type, а не порядку URL. Именованные
виды сохраняют маску наличия; export имеет роль file, изображения — image.
Неизвестный ассет остаётся дополнительным скачиваемым файлом. Fake Tripo использует
самостоятельную таблицу типов, чтобы parser не подтверждал собственную ошибку.

## Общая проверка результатов и восстановление

Asset validators находятся в `lib/studio3d/assetFormats.ts`, `gltfResources.ts`,
`fbxContainer.ts`, `modelContainers.ts`; HTTP-модуль реэкспортирует прежние имена.
Upload, worker и importer применяют одинаковые container/decode/file границы.
Готовность требует проверенных обязательных ролей и основного файла; недоступное
или повреждённое необязательное preview не блокирует оплаченный основной результат.
Его может заменить первый снимок viewer. Ошибка обязательного файла сохраняет расход
и разрешает только бесплатную докачку, не новый платный retry.

Поздний parent переносит импорт из проверенной библиотечной копии, даже если исходный
проектный файл исчез. Прежняя проекция удерживается до проверки новой копии; lease
закрывает удаление источника во время копирования. Некорректный FBX или другой контейнер
не становится ready только по расширению.

Повтор intent после удаления его версии возвращает closed tombstone без модели/версий,
даже если папка модели ещё есть; childId и платёжный журнал остаются. Исчезновение
активной папки отражается library.ok=false и закрывает новый admission вместо скрытого
HTTP failure. Сохранение файла не меняет формат по расширению: несовпадение требует
отдельного шага экспорта, без создания неверно названной копии.

Картинки результатов проверяются по фактической сигнатуре и полному decode, включая
preview, mask и виды. PNG под ссылкой .webp публикуется с расширением .png. Для uploads
MIME и расширение дополнительно должны совпасть с байтами. Обязательная битая картинка
не становится ready; необязательное preview не блокирует готовый основной файл.
Экспорт file с известным модельным расширением проверяется как контейнер без сводки.
