# Панель модуля при восстановлении связи

Оболочка при `connecting`, `offline` и `locked` сохраняет уже открытые инструменты.
При этом она сбрасывает подтверждение входа и увеличивает `auth.logEpoch`.
Эпоха runtime отзывается: старый `context.signal` прерывается, доставка событий и
уведомления снимаются, cleanup фонового hook вызывается один раз.

Отзыв прав и удаление интерфейса имеют разные сроки. `bootstrap.ts` передаёт реестру
реактивный допуск панели с состояниями ожидания, готовности, временного обрыва и отзыва.
Для сохранения интерфейса сравниваются `clientScope` и `profile.id`; `logEpoch` по-прежнему
участвует в отзыве прав. Смена владельца или профиля, выход без оболочки, выключение
плагина и смена дескриптора освобождают компонент и CSS как раньше.

## Открытая панель

При временном обрыве того же владельца `PluginModulePanel.vue` снимает lease и отменяет
незавершённую подготовку, сохраняя готовый компонент, локальный ввод и его CSS.
Готовые стили принадлежат видимой панели; фоновый запуск их не подключает.
Ошибка загрузки модуля или CSS остаётся локальной ошибкой, а не поводом для сетевого цикла.

После возврата online панель ждёт подтверждения входа и свежего принятого каталога.
Она получает новый lease из общего с фоном реестра и заменяет prop `context` без
повторного setup компонента. До этого прежний context остаётся отозванным.
Старый объект context и после восстановления не получает прав; обработчики действий
авторского компонента должны читать актуальный `props.context`.

Панельная `events.on`, зарегистрированная в setup с текущим Vue scope и переданным
prop context, следует за заменой этого prop. Старый транспорт снимается при abort,
новый использует новый context; повторный setup или второй EventSource не нужны.
Ручной off и unmount прекращают также слежение за prop. Фоновые регистрации и
регистрации вне Vue-компонента этим переносом не охвачены: фон создаёт их в новом start.

Применяется и к модулю без `startOnLogin`, и к панели с работающим фоном.
Повторные обрывы не перемонтируют компонент; каждый новый фоновый start остаётся
отдельной эпохой с собственным signal и однократным cleanup.
