# Удаление пользовательского пакета

`POST /api/plugin-installs/plugins/:id/remove` с пустым JSON-телом вызывает
существующий `PluginInstallService.remove`. Требуются браузерная session и допустимый
Origin; CLI и internal transport не разрешают мутацию. Локальный AJV отвергает
лишние поля, ID проверяется общими правилами. Системные ID запрещены сервисом.

Сервис использует общий допуск установки и runtime lease: дожидается принятых
вызовов, сохраняет durable намерение и переносит current/previous в служебные
транзакции до удаления записей managed-установки. Удаление доступно также для
ручного пакета без managed metadata. Сохранённые prefs и отдельный dataDir
не входят в удаляемое дерево.

Загруженный server без `prepareReplace` закрывает собственный Fastify и ожидает onClose.
При успешной очистке удаление не требует перезапуска. Неудачный import/register
сохраняет `plugin_stop_required`; обычное выключение само по себе не выдаёт lease.

Успешный ответ содержит только `{ id, restartRequired }`. Каталог обновляется
без импорта новых модулей, затем общий SSE передаёт `state-change` с `plugins: true`.
Работающие окна перечитывают список штатным механизмом. Сам сервер из хода агента
не перезапускается.

Проверки: `plugin-remove.test.js` использует настоящий модуль, installer, auth guard
и временные каталоги; проверяет удаление ручного пакета, сохранность данных/prefs,
исчезновение из каталога, запрет системного ID и удаление загруженного legacy server.
