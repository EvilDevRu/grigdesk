# Пользовательские плагины

Плагин — пакет с plugin.json по [единому манифесту v1](manifest-v1.md).
Api всегда равен 1; обязательны id, description, файловая icon, entrypoints и contributes.
Версия для установки равна тегу vX.Y.Z, минимум приложения — engines.grigdesk.

```json
{
  "id": "my-panel",
  "api": 1,
  "name": "Моя панель",
  "version": "1.0.0",
  "description": "Сервер, панель и ресурсы исполнителя",
  "icon": "assets/icon.png",
  "entrypoints": {
    "server": "runtime/main.ts",
    "web": { "dir": "ui", "entry": "panel.js", "css": ["panel.css"] }
  },
  "contributes": {
    "panels": [{ "title": "Моя панель", "group": "dock", "order": 10 }],
    "slots": [{ "slot": "provider.popover.after-bars", "kind": "provider-usage", "default": true }],
    "settings": [], "commands": [], "themes": []
  },
  "gallery": { "screenshots": [] },
  "install": { "npm": [] }
}
```

Сервер и модуль интерфейса независимы. Серверный путь js/mjs/ts выбирается только
объявлением. Entry модуля — готовый js/mjs-компонент Vue; CSS и переводы ru/en
относительны web.dir. Пути принадлежат пакету, без ссылок, скрытых компонентов,
выхода из каталога и node_modules. Один PNG/JPEG/WebP до 256 КиБ используется во всей
навигации и карточках. Скриншотов до шести по 4 МиБ, SVG не принимается.

Contributes.panels объявляет одну панель на /ext/идентификатор. Group выбирает rail,
tools или dock, order задаёт сортировку; без panels ссылки нет. Панель монтирует один
ToolHost и на узком экране, и в доке от 900 px. Открепление недоступно.
Contributes.slots явно объявляет readonly JSON provider-usage; панель и слот совместимы.
Commands/themes пока только декларации без исполнения. Настройки берутся из contributes.settings.

Пользовательский пакет по умолчанию выключен; выбор человека хранится в prefs.
Первое включение и обновление подключают код без перезапуска. Старые пакеты остаются
видны как несовместимые с причиной, не исполняются и переустанавливаются новым форматом.
Docs/README.md внутри пакета содержит документацию автора для агентов.

## Модульная панель

Готовый default-экспорт — компонент Vue с setup/render или функция. Шаблон компилируется
автором, runtime compiler не предоставляется. DTO содержит публичные entrypoints.web
и contributes, проекции nav/settings/placements, compatibility и URL файловой icon.
Серверные пути в HTTP-каталог не передаются.

Импортируйте Vue из `vue`, а UI только из `@grigdesk/ui`: оба имени карта модулей
разрешает в экземпляры текущего окна. Фасад UI открывает все runtime-экспорты
[web/src/ui.ts](../../../web/src/ui.ts): кнопки и поля, выбор и вкладки, составные контролы,
диалоги, подтверждения, подсказки, сообщения, тосты, язык и диагностику слоёв.
Не включайте свою Vue/UI в bundle, не создавайте app, DialogHost, TooltipHost или
EventSource. Общие hosts дают диалоги поверх окна и единый порядок Escape.

Панель получает props `context`, `active`, `compact`, `presentation`.
`context` содержит:

- `pluginId` — id пакета;
- `api.get/post/put/patch/del` — общий клиент с сессией и обработкой 401, только `/api/…`;
- `locale.value` — readonly текущий язык;
- `settings.value` — глубоко readonly актуальные эффективные настройки;
- `t(key, params?, fallback?)` — перевод из своих JSON-словарей ru/en с именованными
  параметрами; запасной язык ru, затем явный fallback или сам ключ.

Дополнительные сервисы того же контекста:

| Возможность | Контракт |
| --- | --- |
| `signal` | AbortSignal экземпляра; отзывается при выключении, выходе и смене владельца. |
| `events.on(event, listener, {lifetime?} = {})` | Получает только `data` своего события через общий SSE, возвращает `off()`. По умолчанию lifetime — `panel`, для фона явно укажите `background`. |
| `alerts.show({id, title, body?, detail?, tone?, sticky?, openPanel?})` | Показывает уведомление от имени своего плагина, возвращает boolean. Кнопка «Открыть панель» включена по умолчанию; `openPanel: false` убирает её. |
| `alerts.dismiss(id)` / `alerts.clear()` | Снимает своё уведомление или всю свою область, включая системный канал. |
| `askAgent({workdir, title, draft})` | Возвращает Promise id нового открытого чата. Сервер проверяет папку; черновик не отправляется. |
| `panel.open()` / `panel.close()` | Promise boolean: открыть или закрыть свою панель; на узком экране используется обычная страница инструмента. |
| `panel.setExpanded(value)` | Boolean: разворачивает свой видимый док, сохраняя ширину. На странице и при чужом доке возвращает false. |

`workdir` имеет вид `{kind: 'grigdesk'}`, `{kind: 'project', projectId, repoKey: null}`
или `{kind: 'path', path: '/абсолютный/путь'}`. Можно выбрать существующую папку вне
зарегистрированных проектов: запреты корня/home и проверку исполнителя применяет сервер
так же, как в чате. До создания загружается store чатов; нужна выбранная модель, непустой
заголовок и строка черновика. Ошибки проверки возвращаются автору через rejected Promise.

Подписка `panel` при `active=false` отключает доставку, сохраняя регистрацию и ввод;
при повторном показе доставка восстанавливается. Unmount снимает регистрацию, а при
регистрации в Vue scope работает и его dispose. Фоновая подписка разрешена во время
start по первому спросу и живёт до остановки экземпляра. Обработчик получает только события
своего pluginId и выбранного имени, без отдельного EventSource.

Для инициализации экспортируйте необязательный start(context). Он вызывается по
первому спросу объявленной панели или слота. Без спроса импортов нет; панель и слот
делят один start и context. Последний release вызывает cleanup. Start возвращает
void, cleanup-функцию или Promise одного из этих результатов:

```js
export function start(context) {
  const off = context.events.on('progress', (data) => {
    context.alerts.show({ id: 'progress', title: context.t('progress'), body: String(data) });
  }, { lifetime: 'background' });

  return () => off();
}
```

Панель и слот делят один модуль и один объект context после первого спроса. Фон не подключает CSS;
стили принадлежат панели. Start выполняется отдельно в каждой вкладке браузера и на
телефоне, а также в основном desktop-окне; в surface-окнах фон не запускается. Каждая
вкладка получает события общего потока, поэтому побочные эффекты start нужно учитывать
при нескольких открытых окнах. При offline оболочки, выходе, смене профиля и выключении
плагина signal отзывается, свои уведомления снимаются, cleanup вызывается один раз.
После online и свежего каталога создаётся новый экземпляр. Поздний async cleanup также
будет вызван. Учитывайте signal и освобождайте свои ресурсы: принудительной остановки JS нет.
При временном обрыве того же владельца открытая панель сохраняет компонент, ввод и CSS.
После восстановления входа и свежего каталога её prop `context` заменяется общим с фоном
новым объектом без повторного setup. Читайте актуальный `props.context` в действиях:
старый объект остаётся отозванным. Панельные подписки, созданные в setup через этот prop,
автоматически следуют за его заменой до ручного off или unmount.
Подробности — [восстановление панели](plugin-panel-reconnect.md).
Выключение в другом окне автоматически обновляет каталог и останавливает модуль здесь.
После восстановления общего SSE каталог перечитывается, чтобы учесть пропущенное выключение.

Смена языка и настроек обновляет панель без пересоздания и потери ввода.
Настройки сохраняются через общий раздел настроек плагина. CSS выпускается отдельно и
перечисляется в `css`: обычный CSS-import внутри готового ESM не поддержан. Ограничивайте
селекторы своим корнем панели; CSS не изолирован. Стили самой UI-библиотеки уже есть в окне.

Пример исходника с render-функцией:

```js
import { h } from 'vue';
import { UiButton, confirmDialog } from '@grigdesk/ui';

export default {
  props: ['context'],
  setup(props) {
    return () => h(UiButton, {
      onClick: () => confirmDialog(props.context.t('question')),
    }, () => props.context.t('open'));
  },
};
```

Сборка (esbuild — зависимость проекта автора):

```sh
npx esbuild src/panel.js --bundle --format=esm --outfile=ui/panel.js --external:vue --external:@grigdesk/ui
```

Положите CSS и ru/en JSON рядом в `ui`. Для SFC сначала скомпилируйте компонент обычной
сборкой автора, сохранив эти же external. Общие компоненты не нужно копировать в пакет.

Ядро запускается независимо от карты модулей. Если карта недоступна или указывает на
другие экземпляры Vue/UI, панель объясняет несовместимость на языке окна. Загрузка
ограничена 30 секундами; ошибки JS/CSS/переводов и отрисовки остаются внутри панели.
Это граница ошибок доверенного кода, а не sandbox. В dev правка загруженного графа UI
вызывает полную перезагрузку, чтобы внешние импорты сохранили общую identity.
После обновления или отката сервер и модуль заменяются автоматически: адреса нового
поколения обновляют также относительные ESM imports и CSS. Повторное включение меняет
поколение адресов, позволяя повторить загрузку после ошибки без перезагрузки окна.

Перед установкой v1 обновите сервер и пакеты окон desktop/Android. Обнаружение и
первое включение и обновление работают без перезапуска. Произвольные Vue-слоты и отдельное окно сюда не входят.
Для TypeScript и Vue SFC доступен пакет `@grigdesk/plugin-types`: готовую папку подключают
только в dev-проекте автора. Команда сборки, `import type`, mapping `@grigdesk/ui`,
совместимость и пример описаны в [контракте пакета типов](plugin-types.md).
Полный UI-фасад, включая прежние raw toast API, сохранён для доверенного
кода; сервис alerts предоставляет удобную область плагина, а не sandbox. Устройство ядра —
[модульные панели](plugin-ui-modules.md), подробный контракт —
[сервисы модуля](plugin-module-services.md).

## Серверный набор ядра

Default-export получает прежние `config`, `prefs`, `plugin`, `prefix`, `dataDir`, mutable
`lifecycle` и новое поле `core`. Поддержаны async-функция `(fastify, options)` и callback
`(fastify, options, done)`. Используйте обычную encapsulation Fastify без `fastify-plugin`:
scope наследует декораторы приложения и общий auth guard. Для действий только человека
проверяйте `request.authKind === 'session'` в своём handler.

| Метод `options.core` | Контракт |
|---|---|
| `await getProviders(type)` | Только возможности исполнителей этого типа. Сейчас поддержан `3d`; остальные типы дают `[]`. |
| `emit(event, data?)` | Общий SSE `plugin-event`, тело `{pluginId, event, data}`. Ядро подставляет id; отсутствующие данные становятся `null`. |
| `withPathLock(key, asyncTask)` | Та же очередь по ключу, что у ядра; освобождается после завершения задачи. |
| `await acquireKernelFileLock(options)` | Штатный kernel flock; ручка содержит `release()`, `assertHeld()`, `assertPathIdentity()`, `inheritedFd()`. |
| `documents.roots(scope?)` | Актуальные корни экземпляра DocumentReader приложения. |
| `documents.resolveAbsolute(path, scope?)` | Безопасный перевод абсолютного пути в DocumentRef. |
| `documents.read({source, path})` | Чтение текста внутри разрешённого корня; `path` относительный. |
| `documents.readAsset({source, path})` | Чтение изображения с теми же файловыми границами. |
| `project(id)`, `sandboxes()`, `holdSandbox(task)` | Сервисы проекта и песочниц приложения для объявленного сервера. |
| `readSourceText(root, relative, limit)`, `lock(directory)`, `digest(value)` | Ограниченное чтение кода, mkdir-lock и SHA256 канонического JSON. |
| `validateModel(ref)`, `modelText(input)` | Проверка и вызов model-only транспорта без coding tools или cwd. |
| `parseByteRange(header, size)` | Один диапазон `{start, end}`, `'invalid'` для невыполнимого или `null` для неизвестной формы. |

Новые серверные сервисы входят в `options.core`. Перед использованием проверяйте
наличие нужных методов: в старой сборке расширение может отсутствовать. Отдельного
`hostServices` не требуется. Контракт вызовов, квитанций и файловых границ —
[серверные сервисы](plugin-core-runtime.md).

`getProviders('3d')` возвращает фасады `studio3d`, без полей адаптера, входа и ключей.
Публичные данные фасада заморожены; методы сохраняют `this` исходного исполнителя.
`snapshot()` возвращает замороженный `{accountKey, billingUrl}` без credentials. Передавайте
именно этот объект в `isCurrent`, `balance`, `history`, `prepare`, `send`, `poll`: копия,
JSON или снимок другого плагина/исполнителя дают TypeError. Повторный `getProviders` того же
core сохраняет пригодность снимка. Необязательные методы могут отсутствовать.

Имя `emit` — непустая строка до 128 символов без управляющих знаков. Перевод строки
отклоняется; данные не могут заменить имя SSE или id плагина. Например:

```js
export default async function plugin(fastify, { core }) {
  fastify.get('/readme', async () => {
    const document = await core.withPathLock('example:readme', async () => {
      return core.documents.read({ source: 'grigdesk', path: 'README.md' });
    });

    core.emit('document-read', { size: document.size });

    return document;
  });
}
```

Читатель использует живые корни приложения; добавлять их через core нельзя. При отсутствии
reader или общего SSE вызов явно отказывает. Файловый замок принимает `{lockPath, mode?,
timeoutMs?, ...}`; `mode` — `exclusive` или `shared`. Освобождайте ручку в `finally`,
не удаляйте lock-файл. Очередь `withPathLock` действует внутри процесса, flock — между
участниками файлового протокола. Плагин не импортирует исходники ядра самостоятельно.

## Выключение и проверка настроек

У загруженного плагина тумблер сразу закрывает новые API/static/WebSocket-запросы:
404 `{error: 'plugin_disabled', message: 'Плагин выключен.'}`. Уже принятые streams/WS
не обрываются. Повторное включение открывает тот же runtime; выгрузки кода нет.
Необязательные `lifecycle.onDisable()` и `lifecycle.onEnable()` вызываются после принятой
смены состояния, по одному разу; при boot и повторе того же значения уведомления нет.
Их Promise не удерживает HTTP, ошибки журналируются. Остановка фона принадлежит плагину;
`core.emit` остаётся доступным и после выключения.

Выключенный при boot плагин не импортируется заранее. Первое включение готовит сервер
до записи enabled и открывает его сразу после успешного сохранения. `needsRestart` в GET каталога
и ответе toggle отражает состояние текущего процесса. Здоровый загруженный плагин не требует
рестарта, а несовместимый API или конфликт серверных входов требуют исправления пакета.
Ручная правка prefs не переключает admission: используйте API настроек или перезапуск.

`lifecycle.prepareChange(change, signal)` необязателен. Он получает копию `{enabled?;
values?}`; `values` уже отфильтрованы по схеме, числа нормализованы, defaults добавлены.
Запрос только с placements не вызывает проверку. Для отказа можно бросить понятную 4xx-ошибку
с `statusCode`, строковым `code` из строчных латинских букв/подчёркиваний и `message`:

```js
options.lifecycle.prepareChange = async (change, signal) => {
  if (signal.aborted || Number(change.values?.limit) > 10) {
    throw Object.assign(new Error('Выберите лимит не больше десяти.'), {
      statusCode: 409,
      code: 'limit_too_large',
    });
  }
};
```

Отказ с HTTP 409 и собственным кодом, как в примере, окно показывает с причиной сервера
как «Не удалось применить изменения». Код `revision_conflict` обозначает конфликт версий
настроек; для обычного отказа проверки используйте свой код.

Без ресурсной подготовки допустим `undefined`. Иначе верните весь transition:
`{commit(), async rollback(), async afterCommit()}`. Порядок: prepare → запись свежих prefs
→ синхронный не бросающий commit → смена допуска/уведомление → afterCommit. До commit
подготовка не меняет действующий runtime; ошибка записи вызывает один rollback.
Неверная форма transition отвергается до записи. Неизвестное исключение даёт безопасный
409 `plugin_change_rejected` без текста исключения; настройки и допуск прежние.

Prepare ограничен 5000 мс: 409 `plugin_change_timeout`, signal прерывается. Поздний transition
получает только rollback; поздняя ошибка обработана. До завершения подготовки и подтверждённого
cleanup другая смена настроек, тумблер или замена файлов получают busy. При вечной подготовке
или неудачном rollback нужен ручной перезапуск — это написано в `plugin_change_busy`.
AfterCommit ждут до 5000 мс: затем HTTP отвечает успехом, prefs уже сохранены, а reservation
удерживается до завершения Promise. Его ошибка журналируется и не отменяет commit.

Общий Apply сохраняет settings перед enabled отдельными запросами. Отказ тумблера не
откатывает предыдущий успешный запрос settings. После замены пакета installed/blocked
можно записать настройки и enabled, но старый validator и hooks не вызываются, gate не открывается.
Выключение не выдаёт lease автоматически. При отсутствии prepareReplace ядро отдельно
закрывает собственный Fastify плагина и дожидается его onClose перед заменой файлов.

## Сервер на TypeScript

Объявите путь в entrypoints.server. Для TypeScript используется native стирание типов
Node: явные расширения относительных imports, стираемый синтаксис без enum, namespace
с кодом и parameter properties. Relative imports и top-level await поддержаны. Соседние
необъявленные серверные файлы не исполняются и не создают конфликт имён.

## Документация

Документация плагина живёт в нём самом, а не в GrigDesk: она приезжает с пакетом и
уходит вместе с ним. Структура всегда одна:

```text
docs/
  README.md        — оглавление
  <тема>.md        — документы
```

GrigDesk сам находит `docs/README.md` у включённых плагинов и в каждом ходе чата
называет агенту путь к оглавлению вместе с именем и описанием из манифеста. Выключил
или удалил плагин — его документация из подсказки исчезла. Агент Claude получает
право читать `docs/` без вопроса человеку, даже если разговор идёт в другой папке.

Оглавление устроено как README областей `docs/grigdesk/`: заголовок, строка о том, что
делает плагин, затем разделы «Контракты», «Устройство», «Грабли» — по строке-ссылке
на документ. Документ — один факт или контракт, имя — короткое английское
`kebab-case.md`, текст — русский. Ссылки только относительные: установленная копия
лежит не там, где репозиторий. Документация едет на любую установку, поэтому в ней
нет секретов, путей и имён конкретной машины. `docs/` — обычная папка, `README.md` —
обычный файл: ссылка на их месте не принимается. Устройство —
[документация плагина](plugin-docs.md).

## Версия для установки из git

Установщик принимает манифест v1 с независимо объявленными сервером и модулем. Неверный модуль отвергается
с понятным `manifest_invalid`; любые ресурсы модуля внутри `node_modules` запрещены.
JS, CSS и переводы считаются кодом, исполняемым GrigDesk. Предпросмотр предупреждает
о выполнении модуля в главном окне с сессией человека и доступом к любому API.

Манифест может указать `engines: { "grigdesk": ">=X.Y.Z" }` и
`install: { "npm": [".", "server"] }`. Каждый выбранный каталог содержит
`package.json` и `package-lock.json` v2/v3. Без `install.npm` корневой lockfile
выбирает корень автоматически. Runtime dependencies требуют lockfile; Git/file/URL
зависимости и workspaces не поддержаны. Npm scripts при подготовке не исполняются.
Пакет повторно проверяется после npm; подробности и пределы —
[контракт установки](user-plugin-install.md).

Публикуйте тег `vX.Y.Z`, совпадающий с `version` в `plugin.json`; предпочтителен
аннотированный тег. Установленную копию не правят: разработка и выпуск версии
происходят в репозитории плагина. Рекомендуемый `.gitignore`:

```gitignore
node_modules/
__pycache__/
.runtime/
.env
.env.*
```

## Данные и остановка для замены

`options.dataDir` — отдельный каталог для долговечных данных, браузеров и cache.
Он остаётся на месте при update/rollback. `options.lifecycle` — mutable объект:
`busyReason` служит диагностикой, `prepareReplace(signal)` возвращает удерживаемый
lease. Плагин с фоновой работой обязан закрыть новый допуск, остановить своих
workers/внешних CLI и дождаться завершения до возврата lease. Один busyReason
этого не делает. Без prepareReplace ядро получает lease через закрытие собственного
Fastify; автор обязан освобождать все свои ресурсы в onClose. При ошибке import/register
живой замены нет. Подробности — [управляемый runtime](plugin-hot-runtime.md).

Пример для плагина **без фоновых работ**; `replacing` также проверяют его изменяющие
handlers перед новым действием:

```js
let replacing = false;

options.lifecycle.busyReason = () => null;
options.lifecycle.prepareReplace = async (signal) => {
  if (signal.aborted || replacing) {
    throw new Error('Замена сейчас недоступна.');
  }

  replacing = true;

  return {
    async finish(outcome) {
      if (outcome === 'reverted') {
        replacing = false;
      }
    },
  };
};
```

`installed` и `blocked` сохраняют остановку до перезапуска. Не переносите этот
пример на измеритель с процессами: его атомарная остановка и восстановление —
отдельный контракт. Подробнее — [runtime lease](plugin-install-runtime.md).
