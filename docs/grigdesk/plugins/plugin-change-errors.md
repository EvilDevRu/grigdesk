# Ошибки проверки настроек и серверного входа

Store плагинов различает причину HTTP 409 при сохранении параметров и тумблера.
Отказ со строковым кодом `error` даёт результат `failed`: общий Apply показывает
«Не удалось применить изменения» и текст причины сервера. Это относится и к собственному
коду автора, например `limit_too_large`, и к кодам ядра `plugin_change_rejected`,
`plugin_change_timeout`, `plugin_change_busy`, `plugin_server_conflict`.
Исключение — `revision_conflict`: он сохраняет результат `conflict` и подпись
«Настройки изменились снаружи». Ответы без строкового кода и другие HTTP-статусы сохраняют
общую классификацию настроек. Сам HTTP-код отказа остаётся 409.

После отказа подтверждённые параметры и enabled не меняются; черновик остаётся неприменённым.
Это правило одинаково для обычной страницы и узкой touch-панели. Текст ошибки — данные,
его не переводят как ключ и не исполняют как разметку. Контракт подготовки и таймаутов —
[серверный набор ядра](server-core-api.md).

Пакет с обоими входами `server.js` и `server.ts` установщик отклоняет с HTTP 422 и прежним
кодом `manifest_invalid`. Сообщение содержит только причину:
«У плагина есть server.js и server.ts. Оставьте один серверный файл.»
Префикс о нечитаемом `plugin.json` к этому случаю не добавляется: JSON мог быть корректным.
Сканер каталога показывает ту же причину в `serverError`.
Попытка включить такой пакет возвращает HTTP 409 `plugin_server_conflict`; окно показывает
отказ включения с этой причиной, сохранённый тумблер остаётся выключенным.
