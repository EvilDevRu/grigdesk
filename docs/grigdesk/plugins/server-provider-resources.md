# Ресурсы фонового плагина во всплывашке исполнителя

Серверный пользовательский плагин без `web` и `webModule` может объявить
`placements: [{slot: "provider.popover.after-bars", default: true}]`.
Веб GrigDesk показывает его данные в существующей всплывашке исполнителя:
собственной страницы, навигации и исполняемого браузерного кода плагину не требуется.

Нативный `ProviderUsagePlugins.vue` выбирает только включённые пользовательские
фоновые плагины с включённым размещением. Пока popup открыт, он читает
`GET /api/ext/<id>/provider-usage?providerId=<providerId>` через общий `apiClient`.
Плагин возвращает `{resources: []}` для исполнителей вне своей области.
Повторное чтение — раз в минуту после завершения предыдущего. Закрытие popup,
смена исполнителя, версии, тумблера или размещения отменяют запрос и таймер;
поздние ответы прежнего поколения не публикуются. При отказе прежние цифры
помечаются устаревшими; внутренний текст ошибки API не отображается.

Ответ содержит не более четырёх строк. У строки обязательны `key`, `label`,
`summary`; необязательны `note`, `tone` (`ok`, `muted`, `warn`, `bad`),
`translations: {ru?, en?}` с текстовыми `label`, `summary`, `note` и до трёх
`controls` вида `{id, kind: "link", label, href}`. Ссылки — только HTTPS без
credentials. Команды, поля ввода, денежные значения и произвольные компоненты
этот контракт не принимает. Текст не вставляется как HTML.

`shared/plugins/providerUsageResources.ts` проверяет форму и ограничения, задаёт
ключи в области плагина и выбирает проверенные переводы. Нативный
`ProviderUsageResources` рисует строки и ссылки. Оговорка источника и давность
остаются видимыми также в readonly-всплывашке; ресурсы аккаунта сохраняют прежние
правила. Ядро не знает имён конкретных фоновых плагинов, провайдеров и их источников.

Этот контракт дополняет JSON-размещения серверных плагинов. Загрузка произвольного
Vue-кода пользовательских модулей в слоты по-прежнему не поддерживается.
