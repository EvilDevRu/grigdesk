# Git в фоне и сообщения о результате

CodePanel запускает HTTP-мутацию для снимка проекта, репозитория и рабочей копии.
Скрытие дока и уход с полноразмерной страницы отменяют только право старой активации
загружать интерфейс. Уже запущенная Git-команда сохраняет busy до ответа: повторное
открытие той же панели не разрешает второй push поверх первого.

Успех генерации сообщения, коммита, fetch, pull, push и отмены коммита показывается через общий
`showToast` из публичной границы UI. Ошибки Git-действий используют тот же центр с тоном
ошибки. Тосты закрываются стандартным крестиком, свайпом или общим таймером. Закрытие
тоста не повторяет и не отменяет Git-команду. Footer больше не хранит сообщение о
результате; он показывает только текущие расхождения и состояние отслеживания ветки.

Оповещение публикуется до проверки актуальности панели, поэтому результат push виден
и после её уничтожения или выбора другого worktree. Заголовок называет исходный проект.
Проверка контекста и номера операции по-прежнему защищает модели, черновик коммита и
tracking новой рабочей копии от запоздалого ответа старой.

Push применяет tracking из собственного ответа и не перечитывает тяжёлый список файлов.
Одновременно он инвалидирует более ранние GET Git-снимка: чтение, начатое при повторном
открытии до завершения push, не вправе вернуть прежний ahead после успешной отправки.
Остальные Git-мутации при скрытой панели обновляют метаданные без загрузки сторон diff.

В нижнем ряду три отдельные команды: круговая стрелка проверяет remote через fetch,
стрелка вниз получает изменения в рабочую ветку, стрелка вверх отправляет их.
`POST /api/code/:project/pull` работает в общей очереди мутаций worktree: требует
чистого индекса и рабочего дерева, включая отсутствие новых файлов, и удалённого upstream.
После fetch сервер выполняет `merge --ff-only --no-autostash --no-squash` на полученный upstream-коммит.
Настройки pull.rebase, merge.autoStash и branch.mergeOptions не разрешают rebase,
скрытый stash, squash в индекс или merge-коммит.
Расхождение истории, detached HEAD, отсутствие upstream и локальные правки дают понятный
отказ, сохраняя локальную ветку и файлы. Ошибка сети не раскрывает URL remote.
Успех pull обновляет tracking и перечитывает Git-снимок с историей и diff; повтор без
новых коммитов явно сообщает об этом. Fetch обновляет только tracking и подтверждает
проверку отдельным тостом. Оба действия инвалидируют более ранние GET Git-снимка.

HTTP POST push не получает signal от видимости панели и не повторяется автоматически.
Сервер сериализует мутации worktree и исполняет `pushCurrentBranch` до ответа; изменений
этого серверного контракта для фонового завершения не требуется.

Проверки: `CODE-PUSH-BACKGROUND`, `CODE-PUSH-BUSY`, `CODE-PUSH-ERROR`,
`CODE-PUSH-UNMOUNT`, `CODE-PUSH-FRESH` и `CODE-PUSH-CONTEXT` в компонентных тестах
проверяют отложенные ответы, общий центр тостов, закрытие уведомления и границы контекста.
Серверный `code-git-actions.test.js` проверяет push в изолированный локальный bare remote.
`code-pull.test.js` проверяет fast-forward с настоящим remote, повтор, расхождение,
сохранность staged/work/untracked, ограничения контекста, доступ и безопасную ошибку сети.
Компонентные `CODE-PULL-UI`, `CODE-PULL-ERROR`, `CODE-PULL-UNAVAILABLE` проверяют кнопку,
запрет повтора, обновление истории, тост и доступность.
