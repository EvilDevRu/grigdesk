# Иконки пользовательских плагинов

Иконку задаёт `nav.icon` манифеста `plugin.json`. Поддерживаются два формата:

- имя общей иконки из `web/src/shared/navIcons.ts`, например `search` или `gauge`;
- собственный SVG-контур с префиксом `svg:`, который поставляется прямо в манифесте.

```json
{
  "nav": {
    "path": "/ext/example",
    "label": "Пример",
    "icon": "svg:M12 3 4 6v6c0 5 8 9 8 9s8-4 8-9V6l-8-3z",
    "group": "dock"
  }
}
```

Контур — содержимое атрибута `d` элемента `path` для `viewBox="0 0 24 24"`.
Оболочка задаёт цвет из темы, обводку и скругления. Несколько контуров объединяются
в одной строке командами `M`. Добавлять иконку каждого плагина в ядро не нужно.

Общая функция `navIconPath` принимает именованные и собственные иконки. Её используют
боковая навигация, правая рейка, меню инструментов и мобильное меню.
Каталог и настройки используют `pluginIconPath`: объявленная иконка, затем известная
иконка по id, иначе нейтральный знак `plugin`.

Собственный контур ограничен 4096 символами после удаления крайних пробелов,
начинается с `M`/`m` и координат, содержит только команды SVG path, числа и разделители.
Разметка SVG/HTML, обработчики событий, URL и data URI не принимаются. Строка
передаётся только как значение `path.d`, без вставки HTML. Неверное объявление
показывает запасной знак. Неизвестные имена также не читаются из прототипа карты.

Манифест читается сервером при старте. После изменения `nav.icon` человек
перезапускает API и обновляет окно. Для первого подключения формата `svg:` нужно
обновить сборку web; последующие иконки поставляются вместе с плагинами.
Агент из чата сервер не перезапускает.
