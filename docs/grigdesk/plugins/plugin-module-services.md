# Сервисы и срок жизни модуля плагина

Модуль плагина v1 — доверенный ESM с обязательным default-компонентом, объявленный
в `entrypoints.web`. Его прежние поля
`pluginId`, `api`, readonly `locale`/`settings` и собственный переводчик `t` сохранены.
`PluginModuleContext` в `web/src/pluginRuntime/contextServices.ts` добавляет сервисы
одного отзываемого экземпляра. Пример пакета и рецепт сборки — в [документе автора](author-contract.md).

## Спрос панели и слота

Первый спрос объявленной панели или слота загружает модуль и вызывает необязательный
start(context). Он возвращает void, cleanup или Promise одного из этих результатов.
Один экземпляр на плагин и поколение разделяют все владельцы. До спроса imports нет;
commands/themes не исполняются. CSS подключает только панель перед mount.

Последний release отзывает signal, подписки и уведомления; поздний async cleanup
выполняется один раз. Скрытая панель сохраняет DOM, ввод и регистрации подписок.
Выход, offline, смена владельца/профиля, выключение и замена модуля отзывают доступ.
После online требуется свежий каталог. При временном обрыве того же владельца
панель сохраняет компонент и CSS, затем получает новый context без повторного setup.
Подробности — [восстановление панели](plugin-panel-reconnect.md) и
[синхронизация каталога](plugin-module-catalog-sync.md).

## События

```ts
context.events.on(event, listener, { lifetime?: 'panel' | 'background' } = {}): () => void
```

Это псевдосигнатура: listener получает только `data` события выбранного имени и своего
pluginId. В общем `/api/events` добавлено имя `plugin-event` с envelope
`{pluginId, event, data}`. Собственного EventSource нет; битые и чужие envelope отбрасываются,
исключение одного listener не мешает другим.

По умолчанию lifetime=panel. При active=false транспортная подписка снимается, регистрация
сохраняется до off/unmount и восстанавливается при показе один раз. Если есть Vue scope,
его dispose тоже вызывает off. Вне scope панельными регистрациями владеет runtime;
последний unmount очищает их. Отсутствующий prop active означает true.
Lifetime=background разрешён только во время start по первому спросу и до его остановки, в том числе
для регистрации после await. Signal и ручной off идемпотентно снимают доставку.

## Оповещения

`context.providers.onChanged(listener)` получает только invalidation общего
`providers-update`, без payload. Подписка активна при panelActive, снимается через
disposer/signal/scope; setup-регистрация перепривязывается при новом prop context.
Сведения об исполнителях плагин перечитывает через свой API.

`context.openSettings({pageId, entityId?})` открывает общую форму настроек с источником
button. Отозванный signal или неживой context возвращает false без requestOpen.

API включает upload(FormData, {timeoutMs?, signal?}), getBlob(path) и
postBytes(path, BodyInit, {headers?}) с контрактами общего транспорта. У multipart
Content-Type/boundary выставляет браузер. У getBlob/postBytes signal не добавляется.
Все три метода проверяют /api-путь и используют общий обработчик 401.

```ts
context.alerts.show({ id, title, body?, detail?, tone?, sticky?, openPanel?, actions? }): boolean
context.alerts.dismiss(id): void
context.alerts.clear(): void
```

Необязательные params — query собственной панели: до 16 строковых полей,
ключ до 64 и значение до 512 символов, без controls, массивов и prototype-ключей.
Ядро не интерпретирует предметные поля. Системная ссылка сортирует и кодирует params;
кнопка открытия передаёт `{type:'open',params}` в общую очередь dock.
При openPanel=false цель полностью отсутствует. Невалидные params дают false.

Необязательные actions содержат `{id, label, run}` для явного действия, например
повтора неудачного чтения состояния фоном. Label имеет обычный тип UiText; run
возвращает void или Promise<void>. Callback копируется при show и вызывается только
пока signal и context действуют: сохранённая кнопка старой эпохи ничего не запускает.
Битый массив действий отклоняется целиком до показа. Actions не задают scope или
target; цель собственной панели по-прежнему определяется openPanel/params.

Wrapper передаёт PluginPanelProps.intents с общими id/type/params; событие
consume-intent(id) возвращается к dock.consume. Route query ждёт доступной панели,
затем попадает в ту же очередь; только принятый query очищается через replace.

Local id — непустая строка. Ядро строит scope `plugin:<encodedPluginId>` и id
`<scope>:<encodedLocalId>`; передать чужой scope/target через фасад нельзя. Одинаковые
local id разных плагинов независимы. Общий центр связывает тост, историю и системный канал.
Кнопка «Открыть панель» по умолчанию открывает только доступный модуль отправителя;
`openPanel: false` убирает цель. Системная ссылка — `#/ext/<encodedPluginId>`.
Неизвестный/выключенный плагин не переводит человека на конвейер.

Выключение и отзыв эпохи снимают область даже при закрытой панели; старый context уже
не показывает и не снимает уведомления новой эпохи. Используется общий лимит центра
в 20 тостов, отдельной квоты плагина нет. Полный raw UI-фасад сохранён: это удобное
владение уведомлениями для trusted-кода, а не изоляция произвольного JS.

## Новый чат

```ts
context.askAgent({ workdir, title, draft }): Promise<string>
```

Все поля обязательны: title — непустая строка, draft — строка, workdir — ChatWorkdir.
Поддержаны GrigDesk, проект с repoKey и существующий абсолютный путь, в том числе вне
зарегистрированных проектов. Пропущенный workdir не подставляет GrigDesk.
Сначала helper ждёт chat.ensure() и выбранную defModelRef; при отсутствии модели
возвращается понятная ошибка RU/EN с просьбой выбрать модель в чате.
Холодная загрузка читает постраничный каталог `/api/chat/store/list` вместе с выбранной
моделью; новый черновик добавляется после применения этого каталога, сохраняя прежние чаты.

POST `/api/chat/workdir/preview` получает modelRef и candidate `{taskId: null, workdir}`
с signal экземпляра. Проверяются capability switch=resume/reseed, roots=single/multi,
абсолютный target.cwd и собственное нормализуемое target.workdir. Сервер сохраняет
прежние запреты root/home и ограничения адаптера. Для path используется canonical cwd,
поэтому допустимые симлинки не отвергаются сравнением с исходной строкой.

После preview доступ и модель проверяются повторно. Без промежуточного await создаётся
одна newSession с title/draft/подтверждённой папкой, затем открывается
`/chats?openChat=<id>` штатным механизмом, включая узкий экран. Возвращается id.
Сообщение не отправляется, исполнитель не запускается. Серверные причины сохраняются;
отказ, смена модели и отзыв доступа не создают чат и переход.
Если `newSession` отказал после сброса загрузки списка, helper возвращает ошибку
`chatStoreNotLoaded` и не открывает URL с пустым id.

## Своя панель

```ts
context.panel.open(): Promise<boolean>
context.panel.close(): Promise<boolean>
context.panel.setExpanded(value: boolean): boolean
```

Команды замыкают pluginId и проверяют живой экземпляр, чужой id не принимают. Open идёт
через общий launcher с текущим маршрутом и общим порогом 900 px. Плагин с объявленной панелью доступен одному launcher на маршруте и в доке.
Повторный open на своей /ext-странице фокусирует её без повторного перехода.

Close собственной /ext-страницы ведёт в /chats и сохраняет док под ней. Close/expand
дока разрешены только когда нет tool-страницы, док видим и activeTool — этот pluginId.
На узком экране, чужой/скрытой панели или странице setExpanded возвращает false без
мутации; ширина не меняется. Успешный open дока делает свой плагин активным, сохраняя
геометрию и предпочтения других инструментов.

Старое окно без рабочей import map сохраняет локальный unsupported и работающее ядро.
Перед включением модуля обновляют сервер и пакеты окон; произвольный JS останавливается
кооперативно через signal и cleanup, а не принудительным завершением.
