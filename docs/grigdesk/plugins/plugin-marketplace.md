# Каталог и установка плагинов

«Настройки → Плагины» объединяет каталог сайта и установленные плагины. Кнопка
«Установить из Git…» доступна в общей шапке. Бывший адрес plugins.install переносится
в общий раздел без автоматического запуска диалога. Параметры, enabled и placements
по-прежнему сохраняются общей сессией через «Применить».

Публичный каталог читается сервером автоматически: основной сайт grigdesk.com,
резервный grigdesk.ru. Старые запросы читают только `/api/plugins/v1/index.json` с api1.
Новое окно добавляет `api=2` к GET `/api/plugin-catalog` и `/api/plugin-catalog/:id`:
сервер пробует обе выдачи `/api/plugins/v2/`, затем обе v1. Настройка окружения
не нужна, localhost не используется. Браузер читает только свой origin под общим auth guard.
HTTP 400 старого сервера на первом index переключает окно на прежние пути до закрытия store;
остальные ошибки не вызывают понижения. Режим публикуется вместе с проверенным снимком.
Порядок переключения и согласование карточек описаны в [выборе источника](catalog-failover.md).

Кеш существует в памяти процесса: fresh пять минут, stale до суток, после ошибки
тридцатисекундный cooldown. Boot не ждёт сеть. Максимум ответа индекса и карточки —
2 MiB: README сайта до 256 тыс. символов вместе с заметками занимает в UTF-8 около 1 MiB.
Одна попытка сайта ограничена пятью секундами; при переходе карточки на резервный сайт
этот срок общий для его индекса и карточки. Общий срок чтения карточки — двенадцать
секунд. Используется HTTPS, redirects запрещены.
Modern index имеет до четырёх попыток, всего до двадцати секунд; окно ждёт двадцать пять.
Legacy index сохраняет прежний бюджет окна пятнадцать секунд. Кеши режимов независимы.

Карточка и индекс должны принадлежать одному generatedAt и описывать один ID,
repository и latest. Установка из сохранённого stale каталога недоступна до обновления.
При смене снимка UI предлагает перечитать сведения: выбранная карточка, сброшенная или
прерванная новым индексом, показывает ошибку, а не пустой выбор. Если перепроверка перед
установкой нашла другую версию или SHA, клик не теряется молча — видна подпись о смене.
Версия, которой нет среди совместимых в новом снимке, заменяется старшей совместимой.
Версия ниже установленной из каталога не ставится; кнопка называет установленную версию.
«Открыть задание установки» открывает диалог без прежнего выбора каталога. README и
заметки показываются исходным текстом, HTML и скрипты не исполняются.

Происхождение определяется по ID и источнику вместе. Публичные HTTPS/SSH GitHub адреса
одного repository считаются эквивалентными. Другой host, repository или ID не совпадает.
Official/community берутся из реестра и не означают аудит безопасности. Для ручной копии
без managed source показывается отсутствие указанного источника.

Готовый пакет вне свежего каталога получает предупреждение об неизвестном источнике;
при недоступности проверки показывается невозможность проверить источник. Предупреждение
и подпись финальной кнопки относятся к actual ready job и сохраняются после reopening.
Пока идёт проверка, apply недоступен; после отказа сети ручной Git можно подтвердить.

Каталог выбирает максимальную стабильную версию с поддерживаемым api (1 или 2) и minimum не выше
версии приложения. Отсутствующий minimum не гарантирует совместимость: UI показывает
«Совместимость не заявлена». Архив, отсутствие подходящего релиза, системный ID или
установленная копия с другим/неизвестным источником блокируют install из карточки.

Источник, версия, expectedId и expectedSha переходят в прежний Git installer. Тег,
изменившийся относительно выбранного SHA, даёт checkout_mismatch до fetch/npm.
Установщик повторно проверяет настоящий пакет; public JSON не заменяет этих проверок.
Apply остаётся отдельным явным подтверждением с job id и reviewToken. Новый плагин
появляется выключенным; update/rollback сохраняют прежние контракты и требуют ручных
перезапуска GrigDesk и перезагрузки окна.

Раздельная публикация сайта выполняется отдельно: v1 сохраняет api1-релизы, v2 содержит
api1/2 с прежним `schemaVersion: 1`. Контракт публикации и доверия модулю —
[установка api2](plugin-module-install.md).
Закрытие окна не отменяет задание.

Состояние вкладки, фильтров и выбора живёт в открытой сессии настроек. Переход к адресу
параметра открывает установленные плагины. Узкая витрина показывает список и карточку
последовательно; оба направления сохраняют выбор и управляют фокусом.
