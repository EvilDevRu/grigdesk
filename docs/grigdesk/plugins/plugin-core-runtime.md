# Серверные сервисы core

Пользовательский плагин с объявленным entrypoints.server получает проекты, песочницы, чтение кода и
model-only вызовы через `options.core`. Отдельного `options.hostServices` и отдельной
версии этих сервисов нет. Оконный модуль продолжает использовать `context.api`.

Публичные структурные типы находятся в `packages/plugin-types/src/coreRuntime.ts`
и экспортируются серверным входом `@grigdesk/plugin-types/server`. Поля расширения
необязательны для проверки возможностей старых сборок сервера.
Плагин проверяет нужные методы до работы; отсутствие метода не разрешает fallback
на coding-исполнителя. Загрузчик выдаёт расширение совместимым пакетам v1 с серверным входом.

| Метод `core` | Назначение |
|---|---|
| `project(id)` | Актуальные сведения о проекте из сервиса приложения. |
| `listProjects()` | Текущие ProjectSummary с title, repos и archivedAt; подробный project(id) сохраняет свой контракт. |
| `environment()` | Ленивый frozen снимок runtimeRoot, defaultLibraryDir, protectedDirs и nodeExecutable. |
| `sandboxes()` | Живой обзор песочниц, включая привязку к проекту и состояние стенда. |
| `holdSandbox(task)` | Action lease общего guard; ручка содержит проверку владения и `release()`. |
| `readSourceText(root, relative, limit)` | Начало обычного текстового файла, до `limit + 1` символов для обнаружения усечения. |
| `validateModel(ref)` | Проверка каталога, model-only capability и выбранного effort без вызова модели. |
| `modelText(input)` | Одноразовый model-only вызов с отменой, timeout и квитанцией. |
| `lock(directory)` | Общий mkdir-lock с проверкой PID/starttime и освобождением своего владения. |
| `digest(value)` | SHA256 канонического JSON; порядок ключей не меняет отпечаток. |

Приложение подключает свои сервисы через внутренний `runtimeServices` загрузчика.
`createPluginRuntimeServices` не читает файлы и модели при создании; запросы данных
выполняются лениво. Расширение не зависит от наличия панели интерфейса.

`environment()` не выдаёт config, ключи или настройки исполнителей. Массив protectedDirs
тоже заморожен; в него входят системные хранилища, каталог пользовательских пакетов,
активные control/config деревья фабрики, в том числе после переноса данных.
Снимок собирает единая createPluginEnvironment(config) в server/src/lib; её используют
production factory и изолированные integration fixtures, без второго списка путей.
Node выбирается ядром: в source это текущий Node, в комплекте — вложенный executable.
Отсутствие вложенного Node обнаруживается при вызове, без поиска в PATH и fallback на ELF.

`modelText` принимает только ref модели, текст, signal, timeout и callbacks допуска
и квитанции. Он не выдаёт исполнителя и не передаёт модели cwd, coding tools, чат или
сессию. После выбора модели `core` повторно проверяет включение плагина, затем вызывает
его `beforeCall`. Выключение во время resolver запрещает оплачиваемый вызов.
Timeout — целое число от 1 до 300000 мс, текст и ответ — до 131072 символов.

Текстовый model-only поддерживают также DeepSeek и допущенный режим GLM через отдельный
`runUntrusted` и [закрытый профиль DSH](../chat/dsh-model-only.md). Они не получают tools,
файлы проекта, MCP или историю чата; GLM сохраняет выбранный режим, его ключ и допуск выпуска.
Оба объявляют `images: false`, поэтому потребители изображений продолжают их исключать.
Наличие capability само по себе не обходит каталог, auth и проверку допуска.

Квитанция содержит выбранные ref/effort и сообщённые исполнителем модель и стоимость.
Отсутствующие telemetry остаются `null`. `onReceipt` вызывается до проверки ответа,
поскольку неверный ответ также мог стоить денег. Для записи квитанции используется
синхронный callback; в body HTTP он не передаётся.

Читатель не следует вложенным символическим ссылкам, не принимает выход из корня,
бинарные и специальные файлы. Лимит — целое число от 0 до 1048576 символов.
Корень и политика отбора исходников определяются разрешённым проектом или песочницей
у вызывающего сервиса. Общая реализация — `shared/node/readContainedText.ts`;
прежний импорт Showcase сохранён как re-export.

После обновления ядра и пакета требуется ручной перезапуск сервера. Из агентского чата
работающий сервер не перезапускается. Профильные проверки — `plugin-core.test.js`,
`plugin-types.test.js` и тесты настоящего loader зависимого плагина.
