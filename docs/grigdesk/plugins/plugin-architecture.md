# Плагины GrigDesk

Плагин = отключаемый блок: ссылка в одной из групп навигации, строка каталога
и панель подробностей в «Настройки → Плагины», свои API/настройки. `nav.group` принимает `rail`, `tools` или
`dock`, отсутствующее/невалидное значение нормализуется в `rail`; `nav.order` задаёт
порядок внутри группы. При разнесённом rollout новый web восстанавливает group/order
старых серверных manifest только для известных встроенных `system: true` плагинов;
пользовательский legacy-manifest остаётся в `rail`. Реестр: `server/src/lib/pluginsRegistry.ts` (SYSTEM =
video, code, analysis, shelf, inbox, telegram, github, ssh, db, docker, showcase, studio3d) + скан пользовательских `plugins/<id>/plugin.json` (+опц. `server.js`, роуты
в ЖЁСТКОМ префиксе `/api/ext/<id>/` (механика Fastify, перекрыть системное нельзя), контракт версионирован полем `api` (=1), регистрация на старте — вкл/выкл требует рестарта, у системных нет).
Состояние — prefs (`plugins`, `pluginSettings`). Модуль `modules/plugins/` декорирует
`fastify.pluginEnabled(id)` / `fastify.pluginSettings(id)` — регистрируется ДО модулей-плагинов;
системные модули (media, code, task-shelf, inbox, telegram, github) гейтят каждый роут живой проверкой (тумблер без рестарта → 404
plugin_disabled). Диктовка чата (`/api/chat/transcribe`) НЕ входит в плагин video — не гейтится.
SSH также гейтит каждый HTTP/WebSocket route живой проверкой; выключение закрывает его
server-owned сессии и ожидания без рестарта. Полный контракт — [ssh.md](ssh.md).

**Умолчание вкл/выкл объявляет манифест, а не сорт плагина.** `isEnabled(prefsData, manifest)`
берёт явный выбор человека из prefs, иначе — `manifest.defaultEnabled ?? !!manifest.system`.
Признак `system` тоже живёт в манифесте (в `SYSTEM` и в скане), `modules/plugins` его больше
не дописывает: вторая копия правды разошлась бы с первой. Inbox включён по умолчанию;
Telegram и GitHub системные, но выключены: их страницы просят provider credentials и не
должны появляться сами у каждой установки.

Серверный manifest отвечает только за размещение ссылки. Встроить Vue-компонент в правый
док может лишь явная запись клиентского `shared/tools/registry.ts`: произвольный user plugin
не получает frontend runtime одним JSON-полем. Фронт: `stores/plugins.ts`, VideoView,
InboxView, TelegramView, GitHubView и `ToolHost` для Code/Shelf показывают заглушку при выключенном плагине
(по `plugins.loaded && !plugins.enabled(id)`, а `404 plugin_disabled` от сервера в этом
случае НЕ показывается красной плашкой — это состояние, а не поломка). Выключение Code
размонтирует Monaco, выключение Shelf скрывает строки/чип, но не удаляет entries; прямые
`/code` и `/shelf` остаются под понятной заглушкой.
Раздел «Настройки → Плагины» показывает список по категориям и подробности выбранного
объекта (`views/settings/pages/PluginPage.vue`). Поиск и независимые фильтры сохраняются
в общей сессии. Тумблер, параметры и размещения правят черновик; «Применить» отправляет
полный values/placements перед enabled. Ошибка сохраняет ввод, «Отмена» отбрасывает
неприменённое. Выключенный плагин можно настроить заранее. Установка, источник и
подготовка остаются явными операциями. Все controls и подтверждения приходят из ui.ts.

**Категория (`category` манифеста) режет каталог по РОДУ РАБОТЫ, а не по месту в
интерфейсе**: место объявляет `nav.group` и отвечает на другой вопрос. Список категорий
общий для сервера и веба — `shared/plugins/pluginsContracts.ts`: `work` («Задачи и связь»), `dev`
(«Разработка»), `knowledge` («Показ работы») и `other` («Прочее»). Неизвестное или
пустое значение нормализуется в `other` — чужой плагин не заводит на экране свою группу;
подмену заявленной категории скан пишет в журнал. Разнесённый rollout работает как с
`nav`: свежий web восстанавливает категорию известных `system: true` плагинов, пока
сервер ещё не перезапущен.

**Настройка типа `model`** (их четыре и они независимы: `triageModel` плагинов Analysis,
Inbox и video — см. [video.md](../media/README.md) — и `commitMessageModel` плагина Code)
хранит объект
`{provider, model, effort?}`, а варианты берёт из живого реестра `/api/providers` —
`optgroup` по исполнителям, как в чате. Для `<option>` используется JSON-пара, сопоставленная с реестром: у локальных исполнителей id модели сам бывает со слэшами и
двоеточиями, и разобрать склейку обратно нечем. Вендор в манифест не зашивается:
модель у каждого своя, а зовётся она общим путём (`resolveModelRef` → адаптер; конкретный
сценарий выбирает безопасный transport — для Inbox, video и Code это `runUntrusted`,
а Analysis требует опубликованную provider-ом capability `scopedWorkspace`).
Выбор, пропавший из реестра (сняли CLI, переименовали модель), показывается отдельным
пунктом «— нет в реестре»: молча показать «не выбрана» нельзя — в настройках он остался,
и сервер всё ещё ходит именно ей.

**Усилие — отдельный контрол рядом, а не вариант в списке моделей**: одна и та же модель
работает и быстро, и вдумчиво. Лестницу объявляет сама модель (`model.efforts`), пустая
означает «уровень передать нечем» — контрола нет вовсе, как слайдера в чате. Пустой выбор
значит умолчание исполнителя и уезжает ОТСУТСТВИЕМ ключа, а не пустой строкой. Уровень
сверяется с реестром перед каждым ходом (`resolveInboxTriageTarget` используется и
model-only генератором Code): настройка живёт
долго, а `--effort xhigh` у модели без такой ступени не игнорируется, а роняет запуск CLI.
Устаревший уровень снимается с записью в журнал и остаётся видимым в настройках с
пометкой «нет у этой модели».

## Жизненный цикл 3D

Системный studio3d выключен по умолчанию. Его `/api/studio3d/*` закрыт auth guard
и живым plugin gate (404 plugin_disabled); заказы/reconcile/close требуют human session.
При выключенном старте нет файловых эффектов, scan, history или обращения к исполнителю.
Включение открывает проверенную библиотеку и lock, выполняет resume и расписание.
Выключение прекращает новые отправки и автоимпорт, сохраняет исход уже отправленного
POST и дочитывает принятые платные результаты в прежнюю библиотеку. После выключенного
перезапуска resume ждёт включения. Смена libraryDir проходит prepare/commit/rollback
до prefs; активные/unknown/leased входы закрывают переход. Подробнее —
[API и lifecycle](studio3d-server.md), [контракт раздела](../guide/studio3d.md).
