# Проверка Git-изменений: серверный контракт

Просмотр исходников и версий конфликта остаётся только для чтения. Ручные редакторы
исходников и результата merge исключены. Работа над проверкой изменений не создаёт задач
и комментариев Б24.

## Сравнения и версии

`file-diff` дополнительно возвращает необязательный SHA256 `fingerprint`. Он учитывает
статус, старый путь, наличие, режимы и сырые байты обеих сторон. Настройки отображения
не участвуют в fingerprint. Старый клиент может игнорировать это поле.

`POST review-fingerprints` принимает до 500 descriptors `group/path/base/to/work`
в `comparisons`. Ответ содержит только descriptors и fingerprints; исчезнувшее изменение
имеет `fingerprint: null`. Содержимое файлов не передаётся в этом ответе.

`GET conflict?path` читает актуальный unmerged-файл: `base`, `ours`, `theirs`, `work`
независимы. У каждой стороны есть `presence`, `binary`, `tooBig`, `content` и fingerprint.
Отсутствие стадии отличается от пустого файла. Просмотр не меняет индекс.

## Частичный индекс

`GET partial-diff?group=work|staged&path` возвращает канонические hunks, атомы строк
и token. Дополнительный fingerprint связывает канонические атомы с показанным
клиенту снимком сторон. Атом замены объединяет удалённую и добавленную строку. Клиент передаёт
`POST partial-index` только группу, путь, token и `atomIds`; клиентский patch не принимается.
Конфликтные, бинарные и слишком большие файлы не получают частичный индекс.

Применение держит настоящий `index.lock`, проверяет token и выполняет `git apply --cached`
на частной копии индекса. Перед атомарной публикацией стороны сверяются повторно.
Чужой lock и любой отказ до публикации сохраняют настоящий индекс и рабочие файлы.
Текст staged-переименования снимается с индекса с сохранением нового имени.

## Действия над областью

`POST action-preview` и `POST action-execute` принимают группу, действие и одну область:
явные `paths` (до 500) либо `directory`. Действия: `stage`, `unstage`, `discard`,
`clean-new`, `delete-new-dir`. Preview возвращает точные `eligible`, `excluded` с причинами
и token состава. Execute пересчитывает состав до записи. Fingerprint порции зависит
от выбранных путей, поэтому независимая следующая порция не устаревает после первой.

`discard` возвращает tracked-файлы рабочего дерева к индексу, исключая конфликты и новые
файлы. `unstage` сохраняет диск, включая репозиторий до первого коммита. `clean-new`
удаляет только перечисленные неотслеживаемые файлы. Удаление целой новой папки отдельно
запрещено при tracked, staged, ignored, служебном содержимом, ссылках и вложенном Git.
После буквального `git clean -f` удаляются только опустевшие каталоги внутри выбранной папки.

Execute возвращает `completed`, `failed`, `unattempted` и `ok`. При сбое порции обработка
останавливается; выполненные порции не откатываются и не повторяются автоматически.

## Ignore и обзор

`POST ignore-preview` и `POST ignore` требуют явного `target`: `shared` для корневого
`.gitignore`, `local` для Git-resolved `.git/info/exclude`. Локальные правила общие для
linked worktrees. Правила anchored и буквальные; существующие байты и EOL сохраняются,
дубли не добавляются. Внешняя правка после preview, чужой lock и symlink файла правил
дают отказ. Файлы остаются на диске; tracked-пути не снимаются с индекса.

`GET patch` принимает одну из областей `path`, `directory`, JSON-массив `paths` либо всю
группу. Отбор и дедупликация происходят до ограничений 300 файлов и 2 МБ.
Граница каталога включает завершающий `/`, поэтому `src` не захватывает `src-other`.

Все новые endpoints используют общий auth, gate и проверку принадлежности worktree.
Входные пути проверяются буквально, по скрытым каталогам и фактическим предкам;
ссылки наружу не дают доступа к внешним байтам. Мутации проходят общий mutex worktree.
