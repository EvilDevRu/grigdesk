# Обновление плагина при следующем запуске

Обычный управляемый runtime обновляется [без перезапуска](plugin-hot-runtime.md):
при отсутствии `prepareReplace` ядро закрывает собственный Fastify через `onClose`.
Резервный сценарий ниже нужен для runtime, который не подтвердил безопасную остановку,
например после неудачного import/register. После подтверждения замены такого пакета installer
сохраняет `awaiting_restart` вместо требования выключить плагин и дважды перезапустить
GrigDesk. Файлы текущей версии и enabled-настройка остаются прежними до следующего старта.

Это отдельный исход подтверждённого apply, с прежними job id и reviewToken. Повтор apply
возвращает тот же результат; неправильный token запрещён. Job удерживает общий install slot,
его можно явно отменить. Закрытие мастера, потеря HTTP-ответа и повторное открытие не отменяют
намерение. Неподтверждённый `ready` при перезапуске по-прежнему становится `interrupted`.
Проверка обновлений не переписывает метаданные подтверждённой версии, ожидающей запуска,
чтобы её собственный результат не сделал согласованный снимок устаревшим.

При boot, после owner lock и recovery прежних транзакций, но до scan/import плагинов,
installer заново проверяет manifest, совместимость, Git SHA/config, payload кандидата,
identities current/previous и снимок установленной записи. Только после этого применяется
обычная durable-транзакция с previous/архивом и восстановлением после сбоя. Старый runtime
не получает право замены по одному `busyReason`: его gate по-прежнему требует lease.

При отказе повторной проверки до транзакции job становится `failed`, прежняя установленная
копия сохраняется. Неопределённая файловая транзакция блокирует import затронутого плагина.
Занятость, незавершённый drain и ошибки hook не превращаются в отложенное обновление.
Драйверы БД и rollback сохраняют прежний протокол замены.

Мастер показывает «Пакет подготовлен» до подтверждения и «Обновление ждёт перезапуска»
после сохранения намерения. Он предлагает отмену и закрытие, не показывает успех установки
или повторный apply и не перезапускает сервер сам. Enabled и настройки сохраняются; после
следующего запуска загружается новая версия без повторного включения плагина.

Проверки: `plugin-install-scheduled.test.js`, `plugin-install-routes.test.js`,
`plugin-install-view.test.js`, `plugin-install-store.test.js`,
`plugin-install-dialog.component.test.js`. Профильные тесты используют временные Git-пакеты,
новый installer instance и настоящий Fastify loader.
