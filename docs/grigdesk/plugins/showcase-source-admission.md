# Допуск источника, подключения стенда и запуска работы

Source входит в снимок сборки. Ожидать его сохранения внутри prepareScript поздно:
снимок уже содержал бы прежнюю тему. Служба регистрирует snapshotMutationRequests и
pendingBuildStarts синхронно до первого await. Встречное действие получает script_busy;
после завершения можно повторить запрос с текущей редакцией. Счётчик выдерживает
параллельные повторы HTTP, отметки снимаются в finally. Уже идущий run защищён
списком активных сборок. Разбор без смены source сборка по-прежнему может дождаться.

Подключение цели резервирует targetChangeRequests до resolver. Attach отвергает
работу того же ролика, включая ещё не опубликованные jobs/run:
manualScriptRequests, pendingBuildStarts, pendingTargetWork и активные задания.
Работа другого ролика не мешает подключению.

Встречные requestScript/startBuild проверяют смену цели до await. Публичные
assemble/prepareData/startRecording/synthesizeScenes проходят targetWork: резерв
живёт от входа до регистрации задания или отказа. После этого защиту продолжает
active-job. Внутренние стадии BuildRun используют прежние функции — сам run уже
владеет допуском. Новая глобальная блокировка, отмена чужого задания или ожидание
другого ролика не вводятся.

UI-ответ привязан к владельцу: фактическая эпоха открытого id и намерение маршрута,
зафиксированное до GET. Уход A→B(pending)→A инвалидирует старую цепочку даже без
фактического открытия B. Общее apply охраняет success, error и conflict-reload
правки/attach/voice/adapt. SSE-refresh передаёт того же owner и не начинает навигацию.
Create при уходе оставляет созданную запись на сервере, но не открывает её поверх B.
Reshoot сохраняет job в общем списке без позднего открытия карточки.

Подтверждённая адаптация сначала сохраняет pending-черновики. Title нормализуется
точным trim/fallback сервера; watcher снимает только принятый draft перед модельным
текстом. При отмене, конфликте или отказе сохранения ввод остаётся. Поздний ответ
прежнего ролика не меняет ошибку и набранный текст нового.

Проверки: `showcase-free-create.test.js`, `showcase-wizard.test.js`,
`showcase-store.test.js`, `showcase-view.component.test.js`,
`showcase-owner.component.test.js` с настоящими actions, Pinia и route watcher.

Явная пересъёмка с proof держит общий script-резерв и snapshotMutationRequests до
регистрации record job. Сначала проверяются sceneId и занятость; устаревший proof
перепроверяется через ensurePrepared/keepScenes. targetWork отвергает активный
script-резерв до await; force отвергает ещё не зарегистрированную прямую работу
через pendingTargetWork. Прямой synth/assemble/seed и перепроверка не запускаются
встречным порядком. Другие ролики этим резервом не блокируются.

Готовность подготовки данных перечитывается при смене ref/поколения/данных того же
ролика. Пока новый рецепт читается, прежняя готовность скрыта.
View проверяет owner и номер запроса перед присваиванием seed: поздний null
прежнего ролика не стирает готовность нового. Подтверждение подготовки также связано
с карточкой, где оно было открыто.
