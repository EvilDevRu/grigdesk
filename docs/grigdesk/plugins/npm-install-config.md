# npm ci: ignore-scripts не запрещает исполняемый файл из конфигурации

Проверено на npm 10.9.4 в изолированной offline-фикстуре: пакет содержал Git-зависимость,
lockfile и `.npmrc` с `git=./git-wrapper`. Wrapper создавал тестовый marker и передавал
аргументы системному git. Команда `npm ci --omit=dev --ignore-scripts --no-audit
--no-fund --offline` завершилась успешно, marker появился. Пользовательские конфиги,
кэш и внешняя сеть в проверке не использовались.

`ignore-scripts` отключает lifecycle scripts из package.json. Конфигурационный параметр
`git` отдельно выбирает команду, которой npm получает Git-зависимости; project `.npmrc`
участвует в настройке npm. Поэтому из флага нельзя выводить, что никакой файл пакета
не исполнится при установке зависимостей.
[Документация npm ci](https://docs.npmjs.com/cli/v10/commands/npm-ci/),
[параметр git](https://docs.npmjs.com/cli/v10/using-npm/config/#git),
[источники конфигурации](https://docs.npmjs.com/cli/v10/configuring-npm/npmrc/).

При подготовке недоверенного пакета до подтверждения требуется отдельно контролировать
project config, источники всех зависимостей, выбираемые бинарники и дочернюю среду.
Тест аргументов `npm ci` не доказывает отсутствие исполнения: проверка должна запускать
настоящий npm с безвредным marker в одноразовой offline-фикстуре.

У той же версии npm userconfig и globalconfig должны указывать на разные пустые файлы:
если оба указывают на `/dev/null`, npm отказывает из-за повторной загрузки одного config.
