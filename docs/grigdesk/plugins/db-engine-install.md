# Устанавливаемые драйверы баз данных

Принятые решения: общий установщик пакетов,
единый список движков, приоритет встроенных id, активация ручным перезапуском и
привилегированный DB SPI. Дополнительных решений человека для этих правил не требуется.

В панели «Базы» операция «Установить драйвер из Git…» открывает общий диалог установки.
Адрес и стабильная версия ведут к предпросмотру; отдельное «Применить» передаёт reviewToken.
До применения entry не исполняется и пакет не публикуется. Драйверы пока не входят в
публичный каталог: источник считается неизвестным, перед применением показаны предупреждения.
Обновление сначала готовит карточку, откат требует отдельного подтверждения.
Предпросмотр отмечает `engine.json`, новый и прежний объявленные entry как чувствительные
изменения. Смена имени входного файла не скрывает изменение прежнего кода; чтение старого
манифеста для этой отметки не исполняет драйвер.

Пакет устанавливается в `db-engines/<id>/` папки данных. В корне обязателен `engine.json`:

```json
{
  "id": "example-db",
  "label": "Пример СУБД",
  "kind": "db-engine",
  "api": 1,
  "minimum": "0.0.0",
  "entry": "entry.mjs"
}
```

`id` содержит 1–41 строчную латинскую букву, цифру, дефис или подчёркивание; первый символ —
буква или цифра. Имена прототипов запрещены. `label` непустой, до 128 символов.
`minimum` — стабильная версия X.Y.Z, не выше версии сервера. `entry` — обычный `.mjs`
внутри пакета без ссылок, скрытых сегментов, traversal и `node_modules`.
Версия установки берётся из Git-тега; необязательный `version` должен совпадать с ним.
`install.npm` использует общую политику плагинов: lock v2/v3, проверка всего графа,
запрет Git/file/link/URL dependencies и скриптов. Корневой lock выбирает npm в корне.

Default export entry объявляет `id`, `label`, JSON-совместимые `capabilities` и восемь методов:

- `open({ profile, password, stream, openStream })` возвращает handle; пароль приходит Buffer.
- `close(handle)` завершает подключение.
- `schema(handle)` возвращает схему.
- `analyze(text, handle)` классифицирует запрос и используемые таблицы.
- `inspectRights(handle, session)` сообщает о правах подключения.
- `estimate(handle, request, settings)` оценивает запрос.
- `execute(handle, request)` выполняет запрос с лимитами ядра.
- `cancel(handle, run)` отменяет запрос.

Это привилегированный код: он получает пароли профилей, SSH-каналы и доступ к сети.
Проверка SPI не доказывает честность анализа запросов и проверки прав. До старта проверяется
только пакет; восемь методов и возможности проверяются при импорте на старте сервера.
Ядро использует общий SPI для профиля, сессии, запросов, отмены и аудита.

Пути задаются `dbEnginesDir` / `GRIGDESK_DB_ENGINES_DIR` и
`dbEngineInstallsStatePath` / `GRIGDESK_DB_ENGINE_INSTALLS_STATE_PATH`.
Умолчания — `db-engines/` и `state/db-engine-installs.json` в папке данных.
Установщики плагинов и драйверов имеют разные state, `.grigdesk-install` и owner lock.
Пересечение roots/state и ссылки в настроенных путях отклоняются до создания ресурсов.
Git/npm, публикация, предыдущая копия, durable intent и recovery общие для обоих родов пакета.

Recovery установщика выполняется до внешнего scan/import. Повреждённое состояние или
второй owner блокирует внешние пакеты; встроенные движки остаются доступны. Дефект одного
манифеста, импорта или SPI даёт безопасную диагностику в панели и журнале сервера.
Внешний id не может перекрыть встроенный: коллизия отклоняется до импорта.

Реестр строится один раз на старте. Установка, обновление и откат требуют ручного
перезапуска сервера. Замена не обрывает подключения: opening, живая сессия или closing
дают `engine_busy`; нужно вручную закрыть подключения и повторить применение.
После успешной замены новые подключения этого движка требуют перезапуска. Другие движки
продолжают работать. Обновление интерфейса и GET не сканируют и не импортируют драйверы.

`/api/db/engines` сохраняет единый массив `engines`, дополненный `errors`, картой `installs`
и `installHealth`. В форме профиля остаётся один селект; сведения об источнике и действия
относятся только к выбранному внешнему движку. Pending установка видна в задании до рестарта.
Маршруты `/api/db/engine-installs` требуют включённого раздела «Базы» и браузерной сессии;
CLI/internal-токен не читает их статус. Мутации дополнительно проверяют Origin и JSON.

В source внешние entry импортируются по file URL; в SEA — через штатный ESM bridge.
Генерируемая таблица встроенных движков сохраняется, скачанные пакеты в неё не входят.
