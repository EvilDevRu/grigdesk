# Источник рассказа: задача Б24 и комментарий

Разбор получает явно выбранную задачу, комментарий человека и карту подключённого
стенда. Источник хранится в текущем формате проекта как `{taskId:string|null,note:string}`.
Отсутствующий выбор — null: без задачи и без комментария. Связь со стендом сама
не назначает задачу рассказу.

`normalizeShowcaseSource` убирает пробелы по краям. Номер — 1–12 цифр, пустая строка
превращается в null; комментарий — до 2000 знаков. `showcaseSourceEqual` сравнивает
канонические объекты. Перестановка полей и пробелы по краям смысла не меняют.

PUT `/api/showcase/:id/source` принимает expectedRevision и source. Редакция — только
положительное безопасное целое, без приведения строки. HTTP проверяет лишние поля
до проекции декодером; негодная форма даёт bad_source и не вызывает службу.
Источник можно сохранить до подключения стенда. Отдельного GET списка источников нет.

Панель загружает заголовок из общего стора задач; нецифровой номер не инициирует
запрос. Поздние заголовок и ошибка отбрасываются при смене номера или ролика;
смена ввода сразу снимает прежнюю подпись. Сервер при разборе добирает задачу через taskDetails. Отказ портала не
отменяет работу по комментарию и карте. Текст задачи остаётся недоверенным материалом:
он не получает инструментов, сессии, рабочей области и права расширять политику.

Черновик панели переживает чужое обновление записи: появляется предупреждение и
«Вернуть сохранённый». Собственная очистка до null не считается внешней правкой. Переключение на другой ролик начинает его собственный ввод.
Применение сохраняет источник и запускает сборку пустого ролика либо подтверждённый
повторный разбор существующего.

BriefSource и scriptSource фиксируют источник принятого брифа и сценария. Изменение
source не превращает прежние сцены в новый рассказ: scriptReady и ensurePrepared
проверяют равенство до короткого пути по proof. Новый бриф строится перед сценами,
если прежний принадлежал другому источнику. Сохранённые clip/log не обходят эту проверку.

Source входит в содержательный снимок BuildRun. Повтор requestId с иным источником
даёт build_request_conflict. Допуск сохранения, разбора, сборки и подключения цели
описан в [контракте конкурентных действий](showcase-source-admission.md).

Читается текущая схема проекта2. Несовместимый номер схемы даёт schema_mismatch;
сохранённые файлы не преобразуются автоматически.

Проверки: `showcase-story-task.test.js`, `showcase-wizard.test.js`,
`showcase-build.test.js`, `showcase-build-recorded.test.js`,
`showcase-source-panel.component.test.js`, `showcase-owner.component.test.js`.
