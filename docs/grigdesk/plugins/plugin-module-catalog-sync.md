# Выключение модуля из другого окна

После успешной смены enabled сервер отправляет существующее SSE-событие `state-change`
с телом `{plugins: true}`. Сигнал относится к каталогу ядра и не является именованным
событием авторского модуля. Отказ переключения и повтор прежнего значения его не отправляют.
Уведомление следует за принятием изменения и не меняет серверные hooks плагина.

`main.ts` передаёт bootstrap runtime подписку на общую шину вкладки. В авторизованной
эпохе main/page получает сигнал и перечитывает `/api/plugins` с signal этой эпохи.
Подтверждённый disabled останавливает экземпляр в каждом подключённом окне: отзываются
context.signal, подписки, свои уведомления и CSS, cleanup вызывается один раз.
Старый context больше не разрешает новые уведомления и открытие панели.
Человеку не нужно вручную обновлять каталог второй вкладки.

`hello` при восстановлении SSE тоже запрашивает свежий каталог: выключение могло
произойти во время разрыва соединения. Несколько сигналов во время запроса объединяются
в следующий запрос после него; параллельные циклы загрузки не создаются.
Сетевой отказ сам не запускает повторный опрос. Следующий сигнал или явное обновление
позволяет повторить запрос. Выход, смена владельца и HMR снимают подписку и отменяют
старые запросы; surface не устанавливает этот фоновый обработчик.

Механизм использует существующий `/api/events`: второго EventSource и новой межоконной
пересылки сервисов нет. В каждой вкладке сохраняется собственный экземпляр runtime.
