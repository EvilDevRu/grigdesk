# Модульные панели пользовательских плагинов

Оконный runtime исполняет доверенный ESM из entrypoints.web по декларациям панели и слота.
Единый вход автора, проекции и пределы — [манифест v1](manifest-v1.md).
Установка и проверка ресурсов — [установка модуля](plugin-module-install.md).

Модуль содержит готовый default-компонент Vue. Панель требует contributes.panels;
без этой декларации навигации нет. Адрес — /ext/идентификатор, от 900 px доступна
рейка. Один ToolHost сохраняет экземпляр при разворачивании, detachable=false.
Неверный пакет остаётся в каталоге как несовместимый и не импортируется.

DTO entrypoints.web содержит публичные entry/css/locales без серверных путей.
Static-раздача ограничена собственным dir, закрыта auth и admission включения;
каждый запрос повторяет no-link проверку. Installer и scanner используют общий resolver.

## Общий граф окна

`web/scripts/pluginRuntimePlugin.mjs` выпускает два entry с preserveSignature=strict:
`pluginRuntime/vue.ts` экспортирует Vue, `pluginRuntime/ui.ts` — весь `web/src/ui.ts`.
HTML получает import map до module script/preload, с хэшированными адресами именно
текущей сборки. Отдельной library-сборки, копии UI и external для ядра нет. Ядро
сохраняет обычные импорты и запускается независимо от поддержки карты.

Автор импортирует `vue` и `@grigdesk/ui`. Весь набор runtime-экспортов ui.ts доступен:
primitives (кнопки, поля, checkbox/radio/select/range/switch), composites (вкладки,
поиск, выбор, группы, строки, поля), feedback (сообщения, progress, тосты), overlays
(диалоги, popover, tooltip), confirm/prompt/alert, директива tooltip, язык и диагностика
слоёв. Канонический список — [ui.ts](../../../web/src/ui.ts).

Loader реально импортирует оба bare-имени и сравнивает ref/reactive и
UiButton/confirmDialog/useUiLayer с обычными импортами ядра до entry. Одна проверка
HTMLScriptElement.supports не считается подтверждением совместимости. Неуспех даёт
локальное unsupported, остальные инструменты работают. Desktop/Android получают
карту из своей статики окна, а пакет плагина — через `/api` с общей cookie.

В dev карта указывает на `/src/pluginRuntime/*.ts`. Изменение загруженного фасада или
его транзитивной зависимости вызывает full-reload: внешний ESM не участвует в HMR и
иначе удержал бы старые экземпляры. Собственный app, hosts и SSE плагин не создаёт.
Диалоги и подсказки пользуются общими hosts, Escape закрывает верхний слой окна.

## Контекст и срок жизни

Default — заранее скомпилированный компонент с setup/render или функция. Wrapper
передаёт context, active, compact, presentation внутри текущего Vue app.
Прежние поля контекста сохраняют свои значения:

- api — get/post/put/patch/del общего apiClient, только пути `/api/…`, с общей
  сессией и обработкой 401; токенов и нового транспорта нет;
- locale — readonly ref языка окна;
- settings — глубоко readonly computed эффективных values текущей карточки;
- t — собственный createTranslator по JSON ru/en, с параметрами, ru fallback,
  затем явным fallback или ключом. Словари ядра не меняются.

Язык/values обновляются реактивно без повторного import и потери ввода. Запись
настроек остаётся общей операцией настроек плагина. JSON читается через api.get с
RequestOptions.signal; массивы и значения, отличные от строк/объектов, отвергаются.

Контекст также содержит `signal`, `events`, `alerts`, `askAgent` и `panel`;
точные сигнатуры и границы — в [контракте сервисов](plugin-module-services.md).
Подписки панели используют общий SSE и отключаются при active=false без пересоздания DOM.
Уведомления имеют собственную область плагина, по умолчанию открывают его панель.
«Спросить агента» проверяет папку сервером, затем открывает новый чат с неотправленным
черновиком. Команды дока замкнуты на свой pluginId.

После подтверждённого входа каталог обновляется без импорта модулей. Первый спрос
панели или объявленного слота вызывает optional named start(context). Панель и слот
делят один экземпляр и context; последний release вызывает cleanup. Настройки, язык,
скрытие и разворот не перезапускают hook. Каждая вкладка владеет своим runtime.
Surface-окна отдельного фонового запуска не имеют.
Выход, offline оболочки, смена владельца/профиля и выключение плагина отзывают signal,
подписки и свои уведомления. Возвращение online создаёт новую эпоху со свежим каталогом.
Cleanup кооперативный, вызывается один раз, включая поздний результат async start.
При временном обрыве того же владельца панель сохраняет ввод и CSS; свежий каталог
возвращает ей новый общий с фоном context без повторного setup. Панельные подписки
из setup следуют за prop context; старый объект остаётся отозванным.
Подробности — [восстановление панели](plugin-panel-reconnect.md).
Выключение в другом окне доходит через общий SSE и перечитывание каталога;
[отзыв runtime](plugin-module-catalog-sync.md) не требует ручного обновления вкладки.

CSS выпускается отдельно: готовый JS не импортирует CSS. Фоновая загрузка не добавляет
link-элементы. Панель ждёт свои стили перед mount и снимает их при ошибке/отмене/unmount;
ошибка CSS панели не останавливает работающий фон. CSS ядра уже загружен
через main.ts; собственного загрузчика стилей UI нет. Автор ограничивает свои селекторы
корнем панели, CSS sandbox не предоставляется.

Загрузка карты/CSS/ESM ограничена 30 секундами. Abort и поколение подавляют поздний
результат import. Ошибки загрузки, ресурсов и дочернего компонента дают сообщение
RU/EN на месте панели; onErrorCaptured возвращает false, исключение не рисуется HTML.
Ошибка обработчика компонента также снимает панель — как у существующей границы слота.
Изменённый модуль или стили плагина подхватываются после перезагрузки окна; повтор после
ошибки загрузки — тоже.

## Сборка автором и обновление

Для render-компонента на JavaScript:

```sh
npx esbuild src/panel.js --bundle --format=esm --outfile=ui/panel.js --external:vue --external:@grigdesk/ui
```

Default-компонент, пример и полный контракт автора — [plugins/README.md](../../../plugins/README.md).
CSS и ru/en JSON кладутся в ui отдельно. SFC предварительно компилируется сборкой
автора с теми же external; runtime template compiler не предоставляется.
Пакет `@grigdesk/plugin-types` собирается в отдельную папку для dev-проекта автора:
подключение, mapping `@grigdesk/ui`, версии Vue и правило пересборки описаны в
[контракте типов](plugin-types.md). Он содержит и типы полного UI-фасада, включая
служебные экспорты с пометкой `@internal`; готовый плагин пакет типов не загружает.

Сначала обновляют сервер и пакеты desktop/Android, затем устанавливают пакеты v1.
Обычные обновление и откат заменяют поколения ресурсов через общий каталог без
перезапуска окна. Старое окно новую панель не получит. Проверка import map выполняется
при загрузке; доверенный код не изолирован средствами ОС. UI-фасад сохранён полностью.
