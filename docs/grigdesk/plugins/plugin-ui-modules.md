# Модульные панели пользовательских плагинов

Задача 93031: первая порция оконного runtime для доверенных пользовательских панелей.
Формат api1 с `web/index.html` остаётся прежним. Api2 добавляет `webModule`, не меняет
серверные hooks/lifecycle и не добавляет установку api2 из Git.

## Пакет и каталог

```json
{
  "id": "my-panel",
  "api": 2,
  "name": "Моя панель",
  "webModule": {
    "dir": "ui",
    "entry": "panel.js",
    "css": ["panel.css"],
    "locales": { "ru": "ru.json", "en": "en.json" }
  }
}
```

`dir` — непустой подкаталог пакета, entry — готовый ESM `.js`/`.mjs`; CSS и языки
необязательны. Остальные пути относительны dir. Нормализатор путей общий со scanner и
installer; модуль и nav по умолчанию разрешаются только scanner после проверки файлов.
Api1 игнорирует новое поле. Неподдерживаемые версии по-прежнему не поднимаются.
Неверное объявление модуля даёт предупреждение и не уничтожает карточку плагина.

`server/src/lib/pluginWebModule.ts` проверяет обычные файлы без ссылок и скрытых
компонентов. Отдельная static-раздача ограничена dir и `/api/ext/<id>/module/`, закрыта
общим auth guard; синхронный allowedPath проверяет компоненты lstat при каждом запросе.
Раздача регистрируется при старте для включённых плагинов, `needsRestart` учитывает модуль.
Изменения живого включения остаются вне этой порции.

DTO `PluginWebModule` содержит только `{entry, css, locales}` с собственными URL.
`PluginListItem.web` остаётся строкой/null; старый каталог без webModule принимается.
Store и loader проверяют адреса до сети и исполнения. Модуль имеет приоритет над iframe
при обеих декларациях, без автоматического перехода к iframe при ошибке.
Без nav валидный модуль получает dock-ссылку по имени с иконкой plugin. Явные group/order
сохраняются, адрес всегда `/ext/<id>`. От 900 px доступна рейка, ниже — маршрут.
Один render-site ToolHost сохраняет экземпляр при разворачивании; detachable=false
убирает только действие открепления модульного инструмента.

## Общий граф окна

`web/scripts/pluginRuntimePlugin.mjs` выпускает два entry с preserveSignature=strict:
`pluginRuntime/vue.ts` экспортирует Vue, `pluginRuntime/ui.ts` — весь `web/src/ui.ts`.
HTML получает import map до module script/preload, с хэшированными адресами именно
текущей сборки. Отдельной library-сборки, копии UI и external для ядра нет. Ядро
сохраняет обычные импорты и запускается независимо от поддержки карты.

Автор импортирует `vue` и `@grigdesk/ui`. Весь набор runtime-экспортов ui.ts доступен:
primitives (кнопки, поля, checkbox/radio/select/range/switch), composites (вкладки,
поиск, выбор, группы, строки, поля), feedback (сообщения, progress, тосты), overlays
(диалоги, popover, tooltip), confirm/prompt/alert, директива tooltip, язык и диагностика
слоёв. Канонический список — [ui.ts](../../../web/src/ui.ts).

Loader реально импортирует оба bare-имени и сравнивает ref/reactive и
UiButton/confirmDialog/useUiLayer с обычными импортами ядра до entry. Одна проверка
HTMLScriptElement.supports не считается подтверждением совместимости. Неуспех даёт
локальное unsupported, остальные инструменты работают. Desktop/Android получают
карту из своей статики окна, а пакет плагина — через `/api` с общей cookie.

В dev карта указывает на `/src/pluginRuntime/*.ts`. Изменение загруженного фасада или
его транзитивной зависимости вызывает full-reload: внешний ESM не участвует в HMR и
иначе удержал бы старые экземпляры. Собственный app, hosts и SSE плагин не создаёт.
Диалоги и подсказки пользуются общими hosts, Escape закрывает верхний слой окна.

## Контекст и срок жизни

Default — заранее скомпилированный компонент с setup/render или функция. Wrapper
передаёт context, active, compact, presentation внутри текущего Vue app.
`context = {pluginId, api, locale, settings, t}`:

- api — get/post/put/patch/del общего apiClient, только пути `/api/…`, с общей
  сессией и обработкой 401; токенов и нового транспорта нет;
- locale — readonly ref языка окна;
- settings — глубоко readonly computed эффективных values текущей карточки;
- t — собственный createTranslator по JSON ru/en, с параметрами, ru fallback,
  затем явным fallback или ключом. Словари ядра не меняются.

Язык/values обновляются реактивно без повторного import и потери ввода. Запись
настроек остаётся общей операцией настроек плагина. JSON читается через api.get с
RequestOptions.signal; массивы и значения, отличные от строк/объектов, отвергаются.

CSS выпускается отдельно: готовый JS не импортирует CSS. Каждый load владеет своими
link-элементами, снимает только их при ошибке/отмене/unmount. CSS ядра уже загружен
через main.ts; собственного загрузчика стилей UI нет. Автор ограничивает свои селекторы
корнем панели, CSS sandbox не предоставляется.

Загрузка карты/CSS/ESM ограничена 30 секундами. Abort и поколение подавляют поздний
результат import. Ошибки загрузки, ресурсов и дочернего компонента дают сообщение
RU/EN на месте панели; onErrorCaptured возвращает false, исключение не рисуется HTML.
Ошибка обработчика компонента также снимает панель — как у существующей границы слота.
Изменённый модуль или стили плагина подхватываются после перезагрузки окна; повтор после
ошибки загрузки — тоже.

## Сборка автором и обновление

Для render-компонента на JavaScript:

```sh
npx esbuild src/panel.js --bundle --format=esm --outfile=ui/panel.js --external:vue --external:@grigdesk/ui
```

Default-компонент, пример и полный контракт автора — [plugins/README.md](../../../plugins/README.md).
CSS и ru/en JSON кладутся в ui отдельно. SFC предварительно компилируется сборкой
автора с теми же external; runtime template compiler и пакет типов не предоставляются.

Сначала обновляют сервер и пакеты desktop/Android, затем кладут и включают api2
обычным обнаружением с ручным перезапуском. Старое окно новую панель не получит.
Реальная поддержка import map определяется проверкой во время загрузки, minSdk
Android этого не гарантирует. Перенос 3D, слоты, события, уведомления, команды дока,
открепление в окно и installer api2 относятся к последующим порциям.
