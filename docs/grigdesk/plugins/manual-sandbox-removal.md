# Снос ручного стенда без журнала подъёма

Стенд, поднятый вне GrigDesk, может не иметь записи о профиле в журнале. Если
подходящих профилей несколько, обзор сохраняет `profile: null` и
`removableReason: unknown_owner`: сервер не выбирает скрипт по путям или портам.

Карточка такого ручного стенда показывает открытую секцию «Удаление стенда» с
выбором профиля. Обе кнопки сноса заблокированы до выбора. Если выбранный профиль
исчезает из каталога, выбор очищается, соседний профиль не подставляется.
Профиль повторяется в подтверждении вместе с условиями сохранения изменений.

`POST /api/sandboxes/:task/down` принимает необязательный `profile`. Сервер
проверяет форму имени, наличие профиля и доступность его `down.sh`. Известный
владелец не заменяется другим профилем: несовпадение даёт `profile_mismatch`.
Стенды конвейера, общего checkout и внешнего владельца по-прежнему отклоняются
с `pipeline_owned`, занятые стенды защищает общая аренда lifecycle.

Поле `canDismantle` в профиле отделяет возможность сноса от `canRaise`: архивный
профиль и профиль без `up.sh` могут удалять существующие стенды. Удалённая
регистрация проекта для выбора недоступна. Старые ответы без `canDismantle`
читаются с прежним `canRaise` как запасным признаком.

Выбор применяется к одному запросу сноса; сам реестр стенда не переписывается.
Запущенное задание, как и обычный снос, сохраняет профиль в журнале GrigDesk.
Обычный снос передаёт `FACTORY_DOWN_WORKTREE=keep`, принудительный — `force`.

Проверки: `sandbox-lifecycle.test.js`, `sandbox-http-gate.test.js`,
`sandboxes-store.test.js`, `sandboxes-view.component.test.js` и сценарий ручного
стенда в `sandboxes-responsive.test.mts`. Браузерный сценарий проверяет выбор,
отмену подтверждения и тело запроса на широком и узком экранах с синтетическим API.
