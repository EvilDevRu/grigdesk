# Общий установщик пакетов драйверов

Задача №100000000000. Установщик драйверов переиспользует полный git-цикл
`PluginInstallService` из `server/src/lib/packageInstall`, а не каталог или runtime плагинов. Различия пакета задаёт
`InstallPackagePolicy`: первоначальная и повторная проверка, чтение манифеста,
выделение чувствительных файлов и предупреждения preview. По умолчанию сохраняется
прежняя политика `plugin.json`. Драйверы БД используют тот же сервис
с `packageKind: db-engine`; политика трекеров передаётся отдельно и не меняет их DTO.

`createDriverInstallService` принимает отдельные `driversDir` и `statePath`.
Целевая папка — `drivers/<id>`, журнал — `state/driver-installs.json` в папке данных.
Блокировки, staging и previous принадлежат этому экземпляру; журнал установки
плагинов он не использует. Внутреннее поле журнала `plugins` сохраняет прежний
формат общего сервиса.

Пакет драйвера содержит `driver.json` с `contract: 1`, semver-версией,
именем, безопасным id и схемой настроек; точка входа — обычный `driver.ts`.
Системный `own` зарезервирован. Плагинные manifest/nav/category/web и поле `legacy`
не принимаются. Проверка пакета, подготовка, apply и recovery не импортируют его код.

HTTP-регистратор `/api/driver-installs` использует общие строгие схемы и допуск
session/Origin/JSON. Внешний job содержит `driverId`, а операции обновления и отката
находятся в `/drivers/:id/update` и `/drivers/:id/rollback`. Подключение регистратора
и сервиса к приложению выполняет сборка зависимостей, отдельно от каталога плагинов.

Удаление — `POST /drivers/:id/remove` с тем же session/Origin/JSON допуском.
Общая операция ждёт runtime lease, удаляет current/previous и сохраняет реквизиты.
Выбор доски и пометка до рестарта описаны в [удалении драйвера](../b24/driver-removal.md).

## Lease не означает публикацию

Общий apply сначала закрывает допуск runtime и получает lease, затем повторно
проверяет подготовленный digest и установленные копии. При отказе до файлового
эффекта он завершает lease как `reverted`. Это освобождение допуска, а не
установка. Успешная публикация завершает другой lease как `installed`; повтор уже
подтверждённого apply не создаёт нового lease и не меняет журнал.

## Предварительный просмотр и интерфейс

Driver API дополняет preview проверенным payloadDigest из durable кандидата; reviewToken
остаётся отдельным разрешением apply. После публикации digest берётся из установленной
записи. Plugin HTTP serializer сохраняет прежнюю форму. Необходимость рестарта возвращает
серверный runtime flag, а не сам факт статуса done.

Настройки доски показывают подготовку, предупреждение о серверном коде, изменения,
ошибки и исход установки. Управляемые current/previous читаются через driver check API.
Откат сохраняет requestId, revision и previous digest до POST; после потери ответа
повторяет тот же запрос. Закрытие диалога не отменяет серверное задание: повторное
открытие восстанавливает current и незавершённое намерение из отдельного driver namespace.
