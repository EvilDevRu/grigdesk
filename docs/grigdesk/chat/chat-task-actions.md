# Действия задачи в чате

Под лентой чата, привязанного к задаче, нет полосы «На конвейер» / «Уже на конвейере →»
и «Исправлять». Запуск задачи и переход на конвейер доступны в карточке задачи.
Между лентой и композером остаются условные вопросы и разрешения агента; сам композер сохранён.

Селект задачи по-прежнему загружает список через `/api/tasks` и подтягивает названия задач.
Чат больше не загружает статус конвейера ради кнопки под лентой. Отдельные загрузки конвейера
в карточке задачи и на доске сохраняются.

Кнопка больше не создаёт и не переоткрывает Debug-чат; метод `openDebugFor` удалён из стора.
Существующие Debug-разговоры остаются обычными открываемыми чатами. История не мигрирует
и не удаляется, поля `purpose` и `sourceChatId` сохраняются при создании и записи сессии.
`purpose` также нужен [server-owned companion-чату](server-owned-companion.md).

Карточка открывает параметры запуска своей кнопкой `openLaunch`. В ui-сторе больше нет
флага автоматического открытия параметров запуска при открытии карточки из чата.

Проверки:

- `tests/web/chat-task-tooltip.component.test.js` монтирует чат с задачей и сообщениями:
  проверяет загруженное название в селекте и подсказке, отсутствие узлов полосы и кнопок,
  наличие композера и отсутствие вызова загрузки конвейера. Проверка узлов не измеряет геометрию.
- `tests/web/task-modal-launch-profile.component.test.js` нажимает кнопку запуска в карточке,
  выбирает параметры и проверяет вызов `launch` с нужным payload.
- `tests/web/chat-send-context.test.js` проверяет запрет перепривязки companion-чата.
- `tests/web/factory-single-engine-ui.test.js` проверяет текст исходников: в чате нет
  `openTaskLaunch` и прямого вызова `tasks.launch`. Это проверка кода, а не клика в интерфейсе.
