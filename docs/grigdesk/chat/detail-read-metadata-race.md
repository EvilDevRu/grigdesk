# Прочтение чата во время загрузки ленты

При открытии непрочитанной шапки адресная загрузка сообщений и PATCH `unread:false`
могут выполняться одновременно. Они согласуются внутри одной
singleflight-загрузки; собственная отметка прочтения не требует ручного повтора.

Перед применением detail окно дожидается уже поставленного в очередь PATCH этого чата.
Изменение головы через собственный PATCH или чужое SSE не отвергает detail той же версии.
При несовпадении окно автоматически перечитывает только эту ленту, сохраняя состояние
загрузки. Всего допускаются три чтения: непрерывные изменения на медленной сети
завершаются понятной ошибкой и кнопкой повтора, а не бесконечным loading.
Повторный ответ обязан соответствовать подтверждённой версии; устаревшая лента не
становится основанием записи или ссылок на steps. Адресная сверка после повтора
не откатывает подтверждённый PATCH на голову с прежней revision.

Удаление, подмена объекта чата или dispose запрещают применять поздний ответ.
Несохранённая разница метаданных сохраняется поверх принятой ленты: например,
снятая метка непрочитанного не возвращается, если GET успел раньше дебаунса PATCH.
Серверная копия остаётся основанием dirty-проверки, поэтому местные правки затем сохраняются.

Проверки: `chat-lazy-history.test.js`, `chat-revision-races.test.js` — совпавшая и новая
версия SSE во время GET, PATCH прочтения, сохранение переименования, непрерывные изменения
и успешный повтор после прекращения записей.
