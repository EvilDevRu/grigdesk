# Уточнение в активный ход Qwen

Адаптер объявляет `inTurnInput` протокола 1 для текста и картинок с подтверждением `forwarded`.
После отправки `session/prompt` он регистрирует порт через `onInTurnReady`.
Поэтому обычная кнопка отправки передаёт уточнение в работающий ход вместо очереди
следующего хода. Картинки передаются структурированными частями ACP;
[форматы, лимиты и границы чтения](qwen-image-input.md).

`qwen/inTurn.ts` хранит принятый текст только внутри этого запуска. Запрос
`craft/midTurnSendNow` будит CLI, который может прервать текущую генерацию и запросить
`craft/drainMidTurnQueue`. Runtime проверяет точные `sessionId` и `promptId`, затем
однократно отдаёт сообщения. Только этот drain подтверждает передачу как `forwarded`;
включение текста моделью отдельно не утверждается. К уточнению добавляется просьба
ответить до финала и продолжить исходную задачу.

Пока CLI ждёт ответа на свой вопрос, канал закрыт с причиной `awaiting_answer`.
После ответа он открывается в том же активном ходе. Отмена, завершение и закрытие
порта снимают ожидание ещё не переданных сообщений. Отказ send-now удаляет их из
местной очереди с явной причиной; автоматического повторного prompt нет.
Чужой или поздний drain не получает текст другого запуска.

Текстовые блоки публикуются через `onAssistantMessage` при смысловой границе, включая
drain и конец хода. Их id совпадают с текстовыми шагами, поэтому общий журнал и лента
не дублируют ответ. Последний блок становится финальным ответом; полный текст хранится
отдельно от ограниченного предпросмотра шага.

Проверки `qwen-runtime.test.js` и `qwen-provider.test.js` покрывают очередь, закрытие,
отказ передачи и публичную capability. `qwen-native-tools.test.js` запускает настоящий
CLI с локальным API: незавершённая генерация получает уточнение, следующий запрос
содержит его текст, ответы сохраняют отдельные id, поздняя передача отклоняется.
Это проверка транспорта без оплаченного запроса; поведение живой модели и браузерная
приёмка после ручного перезапуска сервера выполняются отдельно.
