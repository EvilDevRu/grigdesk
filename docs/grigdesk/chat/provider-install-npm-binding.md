# Подключение установленной npm-копии CLI

Для npm-команды адаптер объявляет `npmBinding`: имя исполняемого файла, поле config
и имя переменной bin в `.env`. Общий сервис не ветвится по имени исполнителя.
Claude, Codex и host Kimi используют этот контракт для первой установки и обновления.

После нулевого кода установки тот же абсолютный npm с тем же окружением выполняет
`prefix -g`. Сервис находит исполняемый файл `<prefix>/bin/<имя>` и передаёт его
адаптеру через временную копию config. Проверка версии и сравнение с известной latest
происходят до изменения действующей конфигурации.

Проверенный путь сохраняется общим `updateEnvFile`, затем применяется к config и
окружению текущего сервера. Это подключает новую копию сразу для последующих запусков
и сохраняет выбор после перезапуска. Порядок PATH, бинарник прежней копии и её файлы
не меняются. Сохраняется путь npm-ссылки, чтобы следующий update мог заменить её цель.

Отказ установки, отсутствие npm-бинарника, нераспознанная или устаревшая версия
и отказ сохранения `.env` оставляют прежний bin. Код ноль у npm сам по себе не даёт
успеха. Отсутствующий `envPath` также запрещает объявить успешное подключение.
Причины `npm_binary_missing` и `npm_binding_failed` переводятся на RU/EN.

`tests/server/providers-install-npm.test.js` проверяет три декларации, запись выбора
в `.env` и окружение, переход Kimi с закреплённого native-пути на npm через настоящий
probe временных CLI и отказы до активации. Пакеты и CLI владельца тесты не меняют.
