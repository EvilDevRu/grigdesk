# Ключи доступа исполнителей задаются окном и живут в .env папки данных

Описанный ниже writer обслуживает прежний credentials-контракт адаптеров без
`accessProfiles`. Профильный серверный контракт хранит новые ревизии отдельно и отвечает
`409 profile_access_required` на старый POST. Правила задачи 100000000014 —
[профили доступа](access-profile-rules.md): GLM API и Coding Plan сохраняются раздельно;
повторный вход DeepSeek требует подтверждения неизвестного аккаунта, сохраняет ID/историю,
начинает новую native-сессию и не активирует неактивный профиль. Отмена не меняет доступ.

Ключи API исполнителей (DeepSeek, GLM, Tripo) человек задаёт кнопкой «Задать ключи…» /
«Изменить ключи…» в блоке «Ключи доступа» карточки исполнителя («Настройки →
Исполнители»). Хранилище — `<папка данных>/.env` либо `GRIGDESK_ENV_FILE`. В `state/`,
prefs и браузерные настройки ключи не попадают. Ручная правка `.env` продолжает работать.

## Контракт адаптера

Какие переменные нужны, объявляет сам адаптер полем `credentials`: массив либо
`(config) => массив`. Ядро и Vue вендоров не знают.

```ts
credentials: [
  { env: 'GRIGDESK_GLM_API_MODE', kind: 'choice', label: 'Режим доступа Z.ai',
    options: [{ value: 'api', label: 'Обычный API' }, { value: 'coding-plan', label: 'Coding Plan' }] },
  { env: 'ZAI_API_KEY', kind: 'secret', label: 'Ключ обычного API', hint: '…' },
]
```

`env` — имя `A-Z0-9_`, `kind` — `secret` или `choice` (у выбора обязателен непустой
`options`; у варианта может быть своя `hint`). Необязательное `when: { env, value }` говорит, что
запись нужна, только пока выбор `env` равен `value` — так GLM показывает ключ лишь своего режима.
Условие держится, только если ссылается на объявленный выбор и его вариант; сломанное условие
снимается, а не прячет поле. Сломанная запись, повтор имени и падение функции дают пустую или урезанную
декларацию. Произвольную переменную через маршрут записать нельзя. Нормализация живёт в
`server/src/lib/executorCredentials.ts`, правило имени — общее с писателем (`isEnvName`).
Маршрут — `server/src/modules/providers/credentials.ts`; кэши реестра и лимитов остаются у
модуля `providers`, маршрут только просит их сбросить.

## Проекция и маршрут

`GET /api/providers` отдаёт у карточки `credentials[]`. В каждой записи — декларация
и поля `set`, `inFile` (`true`/`false`, `null` — файл не прочитан), `preview` и `value`.
У секрета `value` всегда `null`, а `preview` — `…` и четыре последних символа, только если ключ
длиной от 16 символов. У выбора `value` — текущий вариант. Источник истины для `set` —
окружение процесса: именно его видят исполнители. Если `set` верно, а `inFile` ложно, значит
ключ задан вне `.env` (окружение службы). Окно предупреждает, что сохранение запишет его в файл.

`POST /api/providers/:id/credentials` с телом `{ values: { ИМЯ: строка | null } }` закрыт общим
auth guard. Он принимает только объявленные имена. У выбора допустимы только объявленные
варианты, у секрета — непустая строка; пробелы по краям обрезаются. `null` удаляет
переменную из `.env`. Из памяти процесса она снимается, только если была в файле: ключ,
заданный вне `.env`, правка файла убрать не может. Запись идёт общим писателем
[`lib/envFile.ts`](../server/env-file-writer.md). Ошибка ввода даёт 400, а состояние файла,
которое правит человек (неоднозначная строка, ссылка, конфликт), — 409. При ошибке окружение
не меняется. После успеха сервер переносит значения в `process.env` и сбрасывает кэш карточек
и лимитов. Каталог моделей он перечитывает в фоне, чтобы окно не ждало CLI и сеть всех
исполнителей. Сразу после записи и сброса рассылается `providers-update` с
`credentials: id`, а по завершении каталога — обычное обновление без этого маркера.
Ошибка фонового refresh не превращает успешную запись в отказ сохранения.

Поколения реестра и usage защищают смену аккаунта: поздние ответы не записывают
кэш/backoff/seen и присоединяются к актуальному чтению. Сбрасывается пауза только
изменённого исполнителя, соседние previous и backoff сохраняются. Окно после ACK
или SSE-маркера удаляет прежний usage и перечитывает registry/usage сразу; поздний
GET и credential-проекция ACK не откатывают карточку. Подробнее —
[смена аккаунта](executor-types.md#смена-аккаунта).

## Почему без перезапуска

Адаптеры читают ключ из `process.env` в момент хода: DeepSeek — `buildDeepSeekChildEnv`,
GLM — `resolveGlmAccess` по ссылке на `process.env`. Конвейер получает `DEEPSEEK_API_KEY`
и `ZAI_API_KEY` файлом `route-secrets.env` (0600, атомарная замена) при каждом запуске
маршрута, а без ключей прежний файл удаляется. Ключ Coding Plan этапам не передаётся ни
юнитом, ни отвязанным процессом; ключ с переводом строки или NUL отменяет запуск до записи.
Поэтому новый ключ действует со следующего хода и запуска. Сменившийся ключ даёт новый `authProfileId`, и разговор
начинает новую сессию исполнителя. Ручная правка `.env` по-прежнему требует перезапуска:
сервер читает файл только при старте.

Это правило не обещает обновить окружение уже живого процесса агента. Tripo читает
`TRIPO_API_KEY` и `TRIPO_REGION` на каждой проверке баланса; совпадение имён с CLI
не означает передачу новых значений всем runtime, которые могут фильтровать env.

## Общий модал

`web/src/views/settings/pages/ProviderPage.vue`, вкладка «Доступ». Секреты вводятся
в UiPasswordInput с autocomplete=new-password; пустое поле означает «не менять»,
placeholder показывает признак и хвост сохранённого ключа. Выбор режима немедленно
меняет видимые поля, но API получает изменения только по общему «Применить».
Скрытый неприменённый ввод остаётся адресуемым с возможностью отмены.

Удаление доступно при inFile=true, подтверждается при правке и создаёт намерение
удаления до Apply. Отказ сохраняет приватный ввод. Публичный state не содержит
значения секрета; закрытие сессии и потеря авторизации удаляют ввод.

Тесты: `tests/server/executor-credentials.test.js`,
`tests/web/provider-credentials.component.test.js`.
