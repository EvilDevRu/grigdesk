# Фильтры списка чатов

Сегмент «Активные / Архив» заменил тумблер архива; кнопка «Фильтры» раскрывает панель.
Фильтрация серверная, выбор запоминается.

## Панель

- Кнопка с воронкой и счётчиком активных фильтров раскрывает встроенную панель под
  шапкой списка (паттерн доски задач). На узкой раскладке панель занимает всю колонку.
  Видимой надписи нет на любой ширине: название «Фильтры чатов» остаётся в подсказке
  и доступной подписи, где также сообщается число активных фильтров.
  Воронка — голая иконка UiIconButton (без коробки-кнопки); счётчик активных
  фильтров — угловой бейдж иконки, а не отдельная плашка в ряд.
- Область — лёгкий pill-переключатель «Активные / Архив» (контекст `chat-scope`
  в patterns.css): утопленный лоток без внешней рамки и разделителя, активная
  область — скруглённая плашка. Режим «все вперемешку» не вводился (решение
  владельца). Переключатель занимает ширину по содержимому и не растягивается
  на всю колонку: прежде две пустые половины коробок выглядели формой, а не
  переключателем вида. Иконка фильтров стоит сразу за вкладками одним левым
  кластером, поэтому строка читается как единый toolbar.
- Счётчик архива — необязательный бейдж сегмента (`badge` опции UiSegmentedControl),
  а не « · N» в подписи: название остаётся коротким, число читается отдельной тихой
  плашкой с табличными цифрами. Пустой архив бейдж не показывает; у выбранного
  сегмента плашка получает акцентный оттенок. Стиль бейджа общий — в patterns.css.
- Состояние: независимые кнопки «Непрочитанные», «Ждут ответа», «Работают»
  с декоративными цветными точками. Выбранная кнопка получает общий accent-тон
  и aria-pressed; повторное нажатие снимает фильтр.
- Панель отделена общей рамкой и подложкой; подписи полей без верхнего регистра.
  Сброс — кнопка со стрелкой сверху рядом с подписью состояния, с подсказкой
  «Сбросить фильтры»; она недоступна при пустом наборе.
- Режим задачи и номер, а также исполнитель и свежесть образуют по две колонки.
  При внутренней ширине панели до 250 px обе пары переходят в одну колонку
  по container query, независимо от ширины окна. Поля заполняют свои колонки.
- Задача: номер (приоритет над режимом), режимы «С задачей» / «Без задачи».
- Исполнитель: выбор из живого реестра; «Любой» снимает ограничение.
  Legacy-модель резолвится реестром на сервере.
- Свежесть: скользящие сутки (24 часа) / неделя (7 суток) / месяц (30 суток)
  по updatedAt, в архиве по closedAt (решение владельца).

## Контракт

- GET /api/chat/store/list принимает unread/waiting/working=0|1, task=any|none|номер
  (1–12 цифр), provider (1–40 символов A-Za-z0-9_-), fresh=day|week|month и project.
  Пропущенный или пустой project означает все чаты, `@none` — чаты без проекта,
  идентификатор формата `^[a-z0-9][a-z0-9_-]{0,40}$` — точное совпадение.
  Проект `none` остаётся обычным идентификатором. Исторический идентификатор
  удалённого проекта совпадает с его сохранившимися чатами; без совпадений список пуст.
  Неверное значение — 400 bad_chat_page.
- Фильтры входят в ключ страницы chatPageKey и в scope снимка курсора: продолжение
  и 410-пересбор работают в том же наборе фильтров. Пустые фильтры сохраняют прежний
  двухэлементный ключ.
- Ответ страницы несёт filtersProtocol: 1; клиент без флага (старый сервер) кнопку
  фильтров не показывает и не отправляет сохранённые фильтры. Дополнительный
  `projectFiltersProtocol: 1` подтверждает поддержку project независимо от остальных
  фильтров. Параметр project применяется до пагинации и входит в ключ и область
  курсора; пересбор после 410 сохраняет проект и глубину.
- top-сверка POST /api/chat/store/changes принимает те же фильтры в top и возвращает
  только совпадающие topHeads. Успешная страница или проба подтверждает протокол.
  Дельта changes с явным флагом принимает его, отсутствие флага сохраняет текущее
  значение. Поздняя дельта прежнего поколения фильтров отбрасывается.
- `catalogProjectId` в шапке — метка каталога. Для свободного чата берётся явный
  проект из нормализованного workdir. Для связанной задачи сначала берётся доверенный
  проект задачи, затем сохранённый явный проект, затем null. Обычный путь, папка
  GrigDesk и номер задачи сами по себе проекта не задают. Та же метка используется
  в списке, точечной шапке, PATCH, SSE и сверке. Каталог не назначает проект чатам,
  не мигрирует историю и не меняет рабочие корни или права.
- «Ждут ответа» — pendingPerms; «Работают» — activeRuns и фоновые запуски.

## Поведение окна

- Выбор фильтров хранится в localStorage (chat.list.filters); повреждённый JSON
  откатывается к пустым фильтрам, сбой записи не ломает фильтрацию. Область
  «Активные / Архив» хранится отдельным ключом chat.list.scope и восстанавливается
  при монтировании. Выбор проекта хранится отдельно для профиля машины и области
  авторизации. Он восстанавливается после успешного каталога и подтверждения протокола.
  Сбой загрузки сохраняет последний принятый каталог и выбор; удаление регистрации
  возвращает ко всем чатам.
- Восстановленные фильтры применяются только после подтверждения filtersProtocol
  первой страницей; на старом сервере фильтры не отправляются, при потере флага
  активные фильтры снимаются, сохранённый набор не затирается. При HTTP 400
  фильтрованной страницы выполняется одна проба без фильтров/cursor: только валидная
  страница без флага подтверждает откат. Тогда обычный список перечитывается;
  поздний ответ старого поколения не возвращает флаг. Отказ пробы или подтверждение
  протокола сохраняет исходную ошибку с повтором. Если успешная проба подтверждает
  только потерю project, снимается только проект, остальные фильтры остаются.
- При закрытой панели активные фильтры показаны чипами с удалением; открытая
  панель показывает выбор в controls без дублирующих чипов. Сброс возвращает пустой набор;
  пустая выдача предлагает сброс.
- Полоса и компактный выбор чатов используют активные проекты. Архивация выбранного
  проекта снимает проектный фильтр, сохраняя открытый разговор и его рабочую папку.
- Создание чата возвращает активный список и сбрасывает обычные фильтры. Проект и
  текст поиска сохраняются. В активном проекте новый чат получает явный выбор его
  рабочей папки, в «Без проекта» — папку GrigDesk, в «Все чаты» — обычные настройки
  нового разговора. Для новой папки
  действует штатный серверный preview.
- Членство загруженных строк подтверждает сервер. Для активного проектного списка
  без поиска и других фильтров полная локальная сессия без задачи видна по её
  выбранной папке до включения строки серверной страницей. Локальные изменения
  шапки в остальных случаях не пересчитывают фильтр; _refreshChatSearch принудительно запрашивает новую первую страницу и
  восстанавливает прежнюю глубину, минуя ensure-кэш. Изменения во время запроса
  объединяются в следующий проход; applyingPage не допускает рекурсии от ответа.
  Принятые головы полной/dirty ленты проходят ту же инвалидацию. Изменения
  waiting/working приходят через существующие runtime SSE, включая разрешения SSH/БД,
  без запросов на токены. Собственный window PUT ACK запускает ту же очередь.
- Если первый отказ старого сервера приходит от POST top при reconnect, он
  направляется в проверку GET-протокола. Подтверждённый откат позволяет продолжить
  сверку pending/active/deliveries; обычные сетевые/HTTP ошибки не считаются успехом.
- Ошибка refresh сохраняет прежние строки и needsRefresh; retryChatPage возвращает
  первую страницу и прежнюю глубину. Ошибка обычного продолжения повторяет cursor.
- searchEpoch закрепляется до ensure: поздняя начальная загрузка не затирает
  восстановленный или выбранный в это время фильтр.
- После reconnect сверка дополняет страницу: строки, переставшие попадать под
  фильтр, остаются до следующей загрузки страницы — единый контракт с поиском.
- Поиск q сочетается с фильтрами в одном scope.

Компоновка и паспортная иконка описаны в [навигации по проектам](../web/chat-project-navigation.md).
