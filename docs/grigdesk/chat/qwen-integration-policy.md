# Правило подключения Qwen Code

Решение человека в задаче №1: полная интеграция Qwen Code для чата и конвейера,
со всеми моделями из живого каталога, включая сторонние OpenAI-совместимые сервисы.
Собственный бинарник Qwen не собирается: внешний npm-пакет `@qwen-code/qwen-code`
устанавливается и обновляется штатной карточкой исполнителя.

Первичное подключение работает без ручного JSON: карточка сохраняет ключ и выбор сервиса,
а GrigDesk получает живой каталог API и готовит `modelProviders` в приватной среде CLI.
Список дополнительно подтверждается native metadata выбранного CLI. Установка и переустановка
не требуют ручного создания пользовательского settings-файла. Каталог без заданного сервиса
использует Alibaba Model Studio в Сингапуре; другие сервисы выбираются явно, без перебора ключом.

Существующий `modelProviders` CLI имеет приоритет и не переписывается. Новая модель должна
появляться после перечитывания каталога без выпуска GrigDesk. Фиксированный список моделей
не заменяет этот контракт. Получение квот пока не реализовано в GrigDesk; интерфейс явно
называет это ограничением интеграции.

Ключи задаются общим окном доступа и хранятся в `.env` папки данных; публичные ответы
содержат только признак и маскированный хвост. Подключение GrigDesk использует API-ключи.
Точка чата и раннер конвейера проверяются отдельно: одна карточка не подтверждает
полноту интеграции. Живая приёмка с настоящим ключом остаётся отдельным обязательным шагом.
