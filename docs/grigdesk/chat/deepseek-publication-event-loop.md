# Публикация DeepSeek сохраняет работу event loop

`publishDeepSeekGeneration`, `activateDeepSeekGeneration` и `forkDeepSeekHome`
выполняют полную проверку поколения через `readDeepSeekArtifactAsync`.
Асинхронный путь проверяет тот же payload, ссылки, hashes и host/journal contract,
что синхронный, и использует общий integrity cache. Проверки перед копированием,
переиспользованием build и переключением current сохраняются.

Это важно для уже работающего web-процесса A при подготовке B. WebSocket-клиент
находится в процессе вызывающего кода и должен успевать отвечать на Ping.
SDK Gateway по умолчанию посылает Ping каждые две секунды; после двух пропущенных
ответов следующий тик закрывает соединение. Длительный синхронный обход файлов
мешает обработать Pong, даже если отдельный процесс SDK и модель работают.

Асинхронная проверка отдаёт управление event loop во время файловых операций.
Heartbeat SDK и сроки runtime не изменяются. Смена current по-прежнему сохраняет
generation и home уже запущенного A; async не разрешает запуск повреждённого B.

Настоящий rollback-сценарий в `tests/server/deepseek-runtime-rollback.test.js`
проверяет живой A во время публикации B, запись B-журнала, совместимую копию для A
и отказ будущего формата. Подготовка variant также использует асинхронную проверку,
чтобы файловая работа фикстуры не блокировала её WebSocket-клиент.

Намеренное удержание первого HTTP отдельно ограничено по
[правилу жизни фикстуры](../testing/fixture-held-turn-deadline.md).
