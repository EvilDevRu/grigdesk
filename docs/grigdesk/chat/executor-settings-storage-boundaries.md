# Границы хранения и запуска настроек исполнителей

Проверено по реализации 1 октября 2026 года. Контракт нового блока —
[нативные настройки исполнителей](executor-native-settings.md).

## Адресная запись и конкуренция

Контейнер лежит в `providerSettings[providerId].nativeSettings`:
`{ format: 1, revision, overrides: { [fieldId]: { path, value } } }`.
Изменение одного пути увеличивает revision всего provider. Равный set и повторный
unset отсутствующего пути — no-op. После удаления последнего override контейнер
с revision сохраняется: старая вкладка не получает право записи с ревизией ноль.
Повреждённый/неизвестный формат отклоняется без перезаписи файла.

`PrefsStore.updateProviderSettings()` перечитывает фактически сохранённые prefs и
выполняет короткую синхронную транзакцию с tmp+rename. Внутри неё нет await.
Новый writer проверяет CAS storage revision, актуальность поколения каталога,
schema revision, тип и ownership до записи. После commit не запускается RPC,
который мог бы превратить успешное сохранение в ошибку HTTP.

Старый `POST /api/providers/:id/settings` сначала ожидает декларацию/валидацию,
затем через ту же транзакцию меняет только выбранную локальную ручку. Запись
устаревшего объекта `providerSettings` целиком устранена. Тест задерживает старую
async-декларацию, выполняет новый set, отпускает старую запись и проверяет обе правки.
Чужой provider, SSH и ранее сохранённые native overrides сохраняются.

## Публичные prefs и недоступный источник

`publicPrefsView()` исключает весь `nativeSettings` из GET prefs и успешного POST
общих prefs. Внутреннее чтение остаётся полным. `PROTECTED_PREFS` по-прежнему закрывает
запись `providerSettings` общим маршрутом. Новый каталог выдаёт только безопасную
проекцию типизированных полей; секретные slots/enum/const и значения неактивных
overrides не попадают в ответ. Сырое stderr discovery не выдаётся человеку.

`set` принудительно проверяет источник, даже внутри TTL. Stale/unavailable или
исчезнувшая capability запрещают его кодом 503. `unset` не вызывает discovery и
даже не требует построения доступного контекста CLI: достаточно актуальной storage
revision. Последний безопасный каталог используется только для ответа удаления.

## Снимок запуска и повторное открытие

Чат вызывает совместимую обёртку `prepareChatNativeSettings()` после ожидания очереди;
DeepSeek Factory вызывает общий prepare с consumer `pipeline` перед новым узлом. Контейнер
удаляется из плоских локальных `providerSettings`; адаптер получает отдельный
неизменяемый план. Изменение prefs во время подготовки не меняет выбранный снимок.
Без сохранённых overrides дополнительного discovery нет.

Factory каждый раз читает тот же `PrefsStore.readStored()` по host-owned
`GRIGDESK_PROVIDER_PREFS_PATH`, учитывающему серверный `GRIGDESK_PREFS_PATH`. Второго
хранилища нет. Только ENOENT означает отсутствие overrides; повреждённый или недоступный
файл запрещает prompt. Путь передаётся явно и для transient systemd service, не уходит
в model/MCP env. Подробнее: [DeepSeek в конвейере](../pipeline/deepseek-native-settings-runtime.md).

Источник и права повторно сверяются с cwd запуска. Несовместимый с конкретной
папкой активный override даёт 409 до prompt; недоступный источник — 503. Глобальный
выбор не удаляется. Уже подтверждённые неактивные поля исключаются из плана.

`fingerprintOf` пула читает только верхние `spec[field]` из `restartOn` и не раскрывает
dot-path. Поэтому Claude/Codex объявляют scalar `nativeSettingsFingerprint`.
Отпечаток строится из контекста и принятых путей/значений; storage revision, время
discovery, случайный путь временного профиля и неактивные поля в него не входят.
Равный применяемый набор после refresh переиспользует процесс. Новый набор и reset
переоткрывают его на следующем ходе с прежним session id, без interrupt busy-хода.

Kimi/DeepSeek открывают процесс каждого хода. Для Kimi host setter получает копию
`config.toml` вместо symlink. Для DSH — отдельный документ внутри launch directory
вместо shared home. Следующий запуск после reset читает исходный base, поэтому
значение не остаётся в файле предыдущего запуска.

## Служебные потребители

Настройки исполнителей также читают `analysis/analyzer.ts`, `analysis/arbiter.ts`,
`inbox/triage.ts`, `codeCommitMessage.ts` и `media/meetingPlan.ts`. Они не передают
подготовленный `nativeSettings`; вложенный контейнер prefs сам по себе не превращается
в CLI payload. `runUntrusted` сохраняет прежний ограниченный контракт.
