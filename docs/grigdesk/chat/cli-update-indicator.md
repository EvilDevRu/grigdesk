# Индикатор «вышла новая версия» — есть, автообновления НЕТ

- Сервер проверяет npm latest через 30 секунд после старта, раз в 6 часов и вручную
  через `POST /api/providers/check-updates`. Claude/Codex используют свои официальные пакеты,
  Kimi в host — `@moonshot-ai/kimi-code`, соответствующий native release. В contained Kimi
  не проверяет host latest и не предлагает обновление. Пустой ответ не затирает прежний latest.
- `latest`/`updateAvailable`/`checkedAt` приходят в карточках `/api/providers`; изменение
  публикуется через `providers-update`. Пока latest неизвестен, точки нет. Автообновления нет.
- Установка и обновление открывают [общее окно](provider-cli-installation.md) из всплывашки
  исполнителя и страницы настроек. Глобальная блокировка принадлежит серверу, состояние и итог
  сохраняются между вкладками и перезагрузкой. Отставший CLI предлагает обновление в топбаре,
  ручное обновление установленного CLI также доступно в настройках. Активный статус открывает
  прежний ход, «Показать результат» открывает последний итог без нового запуска.
- Точка новой версии и прежний вывод итогов не сдвигают соседние секции карточки. Успех смены
  версии не обещает пересборку моделей, если каталог завершился предупреждением.

- Итог доступен в общем окне и под действиями на странице исполнителя. Открытие результата
  не запускает команду повторно и не сбрасывает несохранённые настройки. Лимиты, MCP и ключи
  остаются в прежних разделах страницы.

- **Грабли проверки версий:** заголовок `Accept: application/vnd.npm.install-v1+json` на эндпоинте
  `/latest` даёт **406** (abbreviated-формат — только для полного документа пакета). Сеть на стенде
  флапает (VPN): один и тот же запрос то падает, то отвечает за 0.5 с — поэтому три попытки с паузой,
  а пустой ответ НЕ затирает прошлый результат (иначе индикатор гас бы сам по себе).
