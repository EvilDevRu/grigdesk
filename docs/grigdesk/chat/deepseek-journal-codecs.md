# Codec журналов в бинарной поставке

`runtime-info.journal` описывает физический формат upstream Session JSONL:
`write` — формат новых записей, `read` — форматы, которые поставка умеет восстановить.
Сборщик читает `currentVersion` скомпилированного first-party session-format-catalog.
Этот catalog требует полную смежную цепочку физических codec от v0 до текущего формата.
Числа не дублируются в константах launcher.

Проверенный snapshot пишет v3 и читает v0, v1, v2, v3. V0 хранится в `session.jsonl`,
последующие — в `session.vN.jsonl`. Директория проекта кодирует cwd из header; перемещение
журнала в произвольную директорию при прежнем cwd корректно считается corruption.

Проверка настоящего ELF возобновляет фикстурные журналы каждого объявленного формата:
сохраняются sessionId и счётчик предыдущего хода, ответ приходит от loopback model API.
При миграции исторический файл сохраняется, новые записи идут в текущую generation.
Прямой запуск Harness с будущим `session.v99.jsonl` отказывает до model call.

Для миграции JSONL backend использует отдельный `lib/worker.cjs`. Его надо собирать и включать
в resource gate вместе с workers code-runtime и workflow. Обычная сборка только `lib/index.js`
проходит создание новых сессий, но не доказывает чтение исторических форматов.
