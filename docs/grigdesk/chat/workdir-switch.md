# Смена рабочей папки посреди разговора: Claude и Codex помнят разговор, DeepSeek начинает заново

Сменить cwd между ходами без потери памяти умеют не все исполнители. Замер сделан 27.09.2026
на Claude Code 2.1.283 и codex-cli 0.157.1: две пустые git-папки, в первой один короткий ход
«запомни слово», во второй — продолжение того же разговора на самой дешёвой модели. DeepSeek
Harness `0.1.5-rc.2` проверен по коду установленной версии.

| Исполнитель | Продолжение из другой папки | Что видит агент |
|---|---|---|
| Claude | `-p --resume <id>` находит сессию, слово помнит | вложение `environment` с новой рабочей папкой; CLAUDE.md новой папки приходит вложением `instructions` на том же ходу |
| Codex | `thread/resume` с новым `cwd` продолжает тот же thread | новую папку из контекста окружения; `turn/start.cwd` по схеме — «для этого и следующих ходов» |
| DeepSeek | `session/resume` отвечает `session cwd does not match` | нечего видеть: cwd сессии неизменен, ответвления сессии в ACP нет |
| Kimi | GrigDesk сам открывает новую сессию: cwd входит в identity binding | — |

У Claude журнал разговора остаётся в каталоге проекта исходной папки и дописывается туда же,
а автопамять после перехода берётся из каталога новой папки. Правила прежней папки из истории
никуда не деваются: после перехода агент видит оба набора, новый — последним.

При явной смене папки GrigDesk использует capability адаптера. Claude/Codex
продолжают разговор, DeepSeek/Kimi предлагают выжимку прежней сессии или явный сброс.
Выжимка сохраняется до закрытия сессии, а затем один раз передаётся следующему обычному
ходу. Старый вызов без протокола переноса при вынужденной ротации binding получает
предупреждение в истории и результате. Подробности —
[серверный переход](workdir-transition-preconditions.md) и
[интерфейс папки](../guide/chat-workdir.md).
