# Видимость окна установки и отказы запуска

Общий компонент установки остаётся смонтированным для подписки на SSE. Сам `UiDialog`
создаётся при открытии: его Teleport добавляется после уже открытых настроек и остаётся
поверх них на общем уровне `dialog`. Вход из топбара закрывает исходную всплывашку до
подтверждения или просмотра результата. Закрытие окна не сбрасывает черновик настроек
и не прерывает серверную работу.

Отказ POST до создания операции хранится отдельно от снимка сервера. Успешный GET,
повторное чтение или SSE не стирают причину отказа и запасную команду выбранного
исполнителя. В частности, при 409 с чужой активной операцией или 500 с пустым снимком
окно продолжает показывать причину и «Открыть в терминале». Старый результат этого же
исполнителя не подменяет новый отказ. Подтверждённый новый запуск сбрасывает предыдущую
ошибку; обнаружение соответствующей новой серверной операции разрешает неизвестный
исход потерянного POST. Смена сессии очищает клиентское состояние.

При неодновременном обновлении старый сервер может прислать реестр без `installation`
и ответить 404 на чтение состояния. Для установленного CLI с `canUpdate` сохранён
прежний `POST /api/providers/:id/update`. Общий диалог сначала предупреждает, что
этот сервер не передаёт описание команды и ход установки; команда не придумывается
браузером. Запрос выполняется один раз, итог виден в прежней карточке и всплывашке,
а остальные действия установки в текущем окне заблокированы до его завершения. Сервер с новым
описанием использует только фоновый протокол; ошибка его запуска не переключает
клиент на прежний маршрут и не создаёт повторной команды.

Проверка порядка слоёв требует изображения или проверки порядка рисования поверхностей:
наличие диалога в DOM и hit-test недостаточны. Нижний диалог может принимать hit-test,
если перекрывающие его настройки помечены `inert`, но продолжают рисоваться сверху.
