# Оставшаяся копия CLI после удаления npm

Удаление выбранной npm-копии может открыть другую установку из официального installer
в PATH. `installed` и версия отражают оставшуюся программу. Итог на вкладке «Обзор»
называет удалённую и текущую версии: «Версия X удалена. Сейчас используется другая
установленная копия: Y» (`providerLifecycleAnotherCopy`).

Для распознанных npm/native-копий доступны одинаковые штатные действия: обновление
CLI, переустановка и удаление программы по `canUpdate`/`canReinstall`/`canUninstall`.
Когда копий нет, доступна установка. Пользовательские подписи не называют способ
установки, карточка и всплывашка не предлагают отдельную кнопку установки в терминале.
Неизвестные копии не получают автоматического обслуживания.

Обновление копии из официального installer идёт через общий preview/token/start,
прогресс GrigDesk и проверку версии. Команда берётся из `installation(config).install`
без npm-контекста; для Kimi это официальный `install.sh`. Наличие npm на машине
не переключает обслуживание выбранной копии на npm.

Удаление ограничено объявленными адаптером `externalCli(config, home).native[]`:
программным root и entry. Данные аккаунта и разговоров остаются на месте.
Подробности защиты и восстановления — [стратегия официальной установки](provider-native-lifecycle.md).
Подтверждение показывает краткий итог, а команду и пути — под «Подробности».
Терминал остаётся запасным действием после сбоя установщика.

Проверки: `tests/server/providers-install-routes.test.js` воспроизводит переход
npm → native, v2 update/uninstall и совместимый POST update;
`tests/server/provider-lifecycle-service.test.js` проверяет границы удаления и auth;
`tests/web/settings-provider-settings.component.test.js` и
`tests/web/provider-install.browser.test.js` проверяют действия и подтверждения в обоих местах.
