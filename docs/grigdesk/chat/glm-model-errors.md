# Сообщения об ошибках модели GLM

`classifyGlmModelError()` переводит окончательные `AUTH` и `QUOTA` в безопасные ошибки
адаптера. Общее ядро чата передаёт их `message` в ответ отказа и сохранённую ошибку ленты.
Остальные переходные причины доставки остаются общему runner-у.

Перед передачей ошибки runner-у адаптер проверяет бизнес-код в JSON-тексте ответа Z.ai.
Коды `1308`, `1310` и `1316`–`1321` означают исчерпанное окно Coding Plan и дают
`glm_quota_exhausted`, даже если Harness назвал ошибку `RATE_LIMIT` из-за HTTP 429.
Человек видит подтверждённый код, пояснение об исчерпанном лимите и совет дождаться сброса;
его время можно проверить в лимитах GLM. Автопродолжение GrigDesk для такого хода запрещено.
Коды `1302` (частота) и `1305` (перегрузка) остаются переходными. Одного упоминания числа
в тексте недостаточно: требуется поле `code` JSON-ошибки. `AUTH` сохраняет приоритет.
Значения кодов сверены с [официальной таблицей Z.ai](https://docs.z.ai/api-reference/api-code).

Если текст ошибки Harness содержит JSON-код Z.ai `1113`, в том числе при `RATE_LIMIT`,
пользователь видит пояснение:
недостаточно средств или отсутствует пакет ресурсов; следует проверить тип ключа и доступ
к выбранному плану. Сообщение прямо указывает, что этот ответ не подтверждает исчерпание
подписки. HTTP-статус показывается только при наличии числового префикса в полученной ошибке.
По одному тексту `Insufficient balance` код `1113` и HTTP-статус не выдумываются.

Публичный код `glm_quota_exhausted` сохранён ради совместимости. Его прежний общий текст
об исчерпанной квоте заменён нейтральным пояснением об ограничении квоты, баланса или пакета.
Тело провайдера не переносится в чат: сообщение состоит из собственных переводов RU/EN
и проверенных числовых кодов. Ключи, контакты и пути из исходной ошибки не показываются.
Серверная строка по умолчанию остаётся русской и не интерпретируется клиентом как ключ перевода.

`tests/server/glm-model-errors.test.js` проверяет коды, отсутствие утечки и переводы.
`glm-runtime.test.js` проверяет окончательный отказ по `1310` после действий инструмента;
`glm-vendored-protocol.test.js` подтверждает на настоящем Harness, что `1310` приходит
как `RATE_LIMIT` и распознаётся адаптером. В этой протокольной проверке внутренние повторы
запроса отключены исследовательским overlay (`maxRetries: 0`). Исправление применяется после
`turn/end`: собственные повторы запроса внутри Harness оно не меняет.
Настоящий ELF в `glm-vendored-turn.test.js` проверяет сообщение 1113 и единственный запрос;
`glm-live-binary.test.js` — перенос пояснения через HTTP чата в диагностический отчёт smoke.
