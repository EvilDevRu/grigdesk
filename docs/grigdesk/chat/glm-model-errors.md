# Сообщения об ошибках модели GLM

`classifyGlmModelError()` переводит окончательные ошибки в безопасные сообщения адаптера.
Общее ядро чата передаёт их `message` в ответ отказа и сохранённую ошибку ленты.
Переходные причины доставки остаются общему runner-у.

Перед передачей ошибки runner-у адаптер проверяет бизнес-код в JSON-тексте ответа Z.ai.
Коды `1308`, `1310` и `1316`–`1321` означают исчерпанное окно Coding Plan и дают
`glm_quota_exhausted`, даже если Harness назвал ошибку `RATE_LIMIT` из-за HTTP 429.
Человек видит подтверждённый код, пояснение об исчерпанном лимите и совет дождаться сброса.
Время сброса можно проверить в лимитах GLM.

Окончательные отказы в доступе получают `glm_model_access_denied` с отдельным пояснением.

| Код Z.ai | Причина |
| --- | --- |
| `1309` | Срок действия GLM Coding Plan истёк |
| `1311` | Текущий план не даёт доступа к выбранной модели |
| `1313` | Доступ ограничен по политике добросовестного использования |
| `1314` | Срок действия корпоративного Coding Plan истёк |
| `1315` | Ключ предназначен только для корпоративного Coding Plan |

Одного упоминания числа в тексте недостаточно. Требуется поле `code` JSON-ошибки.
`AUTH` сохраняет приоритет. [Официальная таблица кодов Z.ai](https://docs.z.ai/api-reference/api-code).

Если текст ошибки Harness содержит JSON-код Z.ai `1113`, в том числе при `RATE_LIMIT`,
пользователь видит пояснение:
недостаточно средств или отсутствует пакет ресурсов; следует проверить тип ключа и доступ
к выбранному плану. Сообщение прямо указывает, что этот ответ не подтверждает исчерпание
подписки. HTTP-статус показывается только при наличии числового префикса в полученной ошибке.
По одному тексту `Insufficient balance` код `1113` и HTTP-статус не выдумываются.

Публичный код `glm_quota_exhausted` сохранён ради совместимости. Его прежний общий текст
об исчерпанной квоте заменён нейтральным пояснением об ограничении квоты, баланса или пакета.
Тело провайдера не переносится в чат: сообщение состоит из собственных переводов RU/EN
и проверенных числовых кодов. Ключи, контакты и пути из исходной ошибки не показываются.
Серверная строка по умолчанию остаётся русской и не интерпретируется клиентом как ключ перевода.

## Повторы

Маршрут GLM исключает `RATE_LIMIT` из списка внутренних повторов Harness. Одну и ту же
метку Harness даёт как временным ограничителям, так и окончательным ошибкам с HTTP 429.
Чат получает первый отказ и либо сразу показывает причину, либо продолжает ход с паузой.
`1302` (частота) и `1305` (перегрузка) относятся к переходным причинам. Исчерпанная квота,
отказ в доступе или недостаток баланса завершают ход. Повторы при обрыве сети, таймауте,
пустом ответе и ошибке сервера по-прежнему ограничены политикой маршрута.

Эта настройка передаётся из серверного профиля в установленный Harness. Для применения
достаточно собрать сервер GrigDesk и перезапустить приложение.

## Проверки

`tests/server/glm-model-errors.test.js` проверяет коды, отсутствие утечки и переводы.
`glm-runtime.test.js` проверяет окончательный отказ по `1310` после действий инструмента;
`glm-vendored-protocol.test.js` подтверждает на настоящем Harness, что `1310` приходит
как `RATE_LIMIT` и распознаётся адаптером. `glm-vendored-turn.test.js` проверяет один запрос
для `1311`, `1113` и `1302` с обычной политикой маршрута. Только `1302` даёт чату сигнал
к автопродолжению. `glm-chat.test.js` проверяет текст `1311` и единственный prompt через
штатную доставку результата чата. Автоматические тесты используют локальный ответ Z.ai.
