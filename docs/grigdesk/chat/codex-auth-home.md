# Проверка авторизации Codex игнорирует CODEX_HOME

Карточка Codex в GrigDesk собирается из двух независимых результатов:
`probe` исполняет выбранный `codex --version`, а `auth` проверяет наличие файла
`~/.codex/auth.json`. Реестр `modules/providers/index.ts` считает исполнителя доступным
только при `probe.ok && auth.available`.

Текущий `server/src/lib/executors/codex.ts:auth` не учитывает `CODEX_HOME`:
он всегда использует `os.homedir()` и `.codex/auth.json`. При этом
`readCodexThreadTokenInfo` в том же адаптере использует `CODEX_HOME` для поиска журнала.
Успешный поиск CLI через PATH не устраняет это расхождение.

Изолированная проверка с временным HOME воспроизводит поведение без запуска модели
и без чтения настоящих ключей: файл `{}` создаётся только в отдельной папке,
выбранной через `CODEX_HOME`, — `auth.available` равен false. Добавление такого же
файла в стандартную `~/.codex` меняет результат на true. Содержимое файла текущая
проверка не разбирает; существование файла само по себе также не доказывает рабочую
авторизацию у сервиса.

Это проверенное ограничение GrigDesk. Оно не устанавливает причину любого прежнего
случая «Codex недоступен» и не подтверждает авторизацию настоящего CLI.
Обнаружение команд из nvm при ограниченном GUI PATH проверяется отдельно:
[PATH бинарного сервера](../server/server-binary-path.md).
