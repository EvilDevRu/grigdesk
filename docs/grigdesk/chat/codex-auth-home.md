# Проверка подключения Codex учитывает выбранный home

Карточка Codex в GrigDesk собирается из двух независимых результатов:
`probe` исполняет выбранный `codex --version`, а `auth` проверяет наличие файла
`auth.json` в home выбранного профиля, затем CODEX_HOME и стандартном `.codex`.
Реестр `modules/providers/index.ts` считает исполнителя доступным
только при `probe.ok && auth.available`.

`server/src/lib/executors/codex.ts:auth` получает окружение профильного снимка. При этом
`readCodexThreadTokenInfo` в том же адаптере использует `CODEX_HOME` для поиска журнала.
Успешный поиск CLI через PATH сам по себе не подтверждает авторизацию.

Карточка прежнего подключения проверяет наличие файла и не доказывает рабочий доступ
у сервиса. Новый мастер подтверждает результат отдельно через account/read после
уведомления CLI о завершении login. Реальные входы проверяются с владельцем.

Это проверенное ограничение GrigDesk. Оно не устанавливает причину любого прежнего
случая «Codex недоступен» и не подтверждает авторизацию настоящего CLI.
Обнаружение команд из nvm при ограниченном GUI PATH проверяется отдельно:
[PATH бинарного сервера](../server/server-binary-path.md).
