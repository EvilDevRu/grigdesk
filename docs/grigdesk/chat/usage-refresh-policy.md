# Общее автообновление квот и адресная проверка

В «Настройки → Исполнители» над выбором исполнителя находится один общий параметр
«Автообновление квот». Он принадлежит выбранному серверу и применяется общей кнопкой
«Применить». До применения меняется только черновик. Параметр не входит в
`adapter.settings` и не имеет отдельных значений для исполнителей.

## Умолчание и хранение

`providerUsageAutoRefresh` хранится в PrefsStore. Только литерал `true` разрешает
автоматические измерения; отсутствие поля, повреждённое значение или нечитаемый файл
при начальном чтении дают false. Миграция не нужна. POST prefs принимает только boolean;
иной тип возвращает 400 `bad_preference` без частичной записи. Повреждённый файл
по-прежнему защищён от перезаписи ответом 500 `prefs_corrupted`.

`providerUsagePolicyRevision` — серверная монотонная ревизия. Она начинается с нуля,
повышается только при смене boolean и записывается вместе с ним одной tmp+rename
операцией. HTTP не может записывать её: 400 `protected_preference`. GET/ACK prefs
раскрывают ревизию; обычный перезапуск сохраняет её. После восстановления старой
резервной копии нужно обновить окна, чтобы их память о новой ревизии не мешала старым данным.

## Серверная политика

При false обычный GET, периодический тик, переподключение окна и общий фоновый hook
`refreshProvidersUsage`, в том числе вызванный прогнозом, не измеряют квоты. Последние
значения и время успешного измерения сохраняются. До первого замера карта может быть
пустой; это не свободная квота и не бесконечная загрузка. UI предлагает нажать ↻.
Плагин прогноза остаётся включённым и принимает новые ручные снимки; сторонняя
статистика внешних плагинов не управляется этим параметром.

Сохранённая политика синхронно применяется до ACK prefs. При включении отдельно запускается
проверка устаревших квот; сохранение не ждёт поставщика. Период с открытым окном — пять
минут. Фоновый hook использует порог половины периода и тот же запрет автоматики.
Повторная доставка того же снимка допустима и не создаёт новую точку прогноза.

## HTTP и доставка

- `GET /api/providers/usage` измеряет устаревшие квоты только при включённой автоматике.
- `GET /api/providers/usage?cached=1` всегда пассивен, включая режим true.
- `POST /api/providers/usage/refresh` требует `{ providerId: string }` и измеряет только
  выбранного исполнителя независимо от режима. Пустой, неверный, пробельный или слишком
  длинный id даёт 400 `provider_required`; сообщение предлагает выбрать исполнителя и
  обновить окно приложения. Неизвестный id даёт 404 `unknown_provider`. Отказы не измеряют квоты.
- Общий auth guard закрывает эти маршруты и prefs до побочных эффектов.

HTTP и SSE `providers-usage` возвращают полную карту всех имеющихся снимков:
`{ usage, autoRefresh, autoRefreshRevision }`. Отсутствие ключа означает отсутствие замера.
Ручная проверка не освежает соседние проценты, даты, backoff и прогнозы. Старые клиенты
могут игнорировать metadata; старый клиент без id получает понятный 400 вместо общего force.

Prefs GET/ACK и usage/SSE используют общий revision guard providers store. Меньшая ревизия
не откатывает принятый режим или карту квот. Ответ старого сервера без metadata не стирает
известный режим. Открытые настройки наблюдают ревизию через существующий SSE-мультиплексор,
перечитывают общий prefs-ресурс и сохраняют dirty-ввод с обычным конфликтом. Сбой этого
чтения виден в форме; повтор перечитывает данные без записи.

## Планировщик, паузы и гонки

`createProviderUsagePoller` ведёт TTL, single-flight и поколение отдельно для каждого
исполнителя. Совпадающие запросы делят одно чтение, разные не блокируют друг друга.
Кнопка сохраняет минимальный интервал 15 секунд и не обходит персональный backoff после
429 или `Retry-After`. Ошибка источника сохраняет прежние полосы и дату успешного замера,
помечает данные stale и сообщает причину. Общий декоратор использует нейтральное
«Повторите проверку». У отдельных адаптеров Kimi, Claude, Codex и Tripo унаследованные
сообщения могут обещать автоматический повтор; при false они не разрешают фоновый опрос.

Выключение запечатывает видимую live-проекцию в сырой снимок без продвижения `checkedAt`
и `dataCheckedAt`, затем очищает оверлей. Sink при false ничего не меняет. Автоматические
in-flight теряют право записывать снимки, backoff, историю вёдер и vendor-status; уже
отправленный read-only запрос может закончиться. Ручной запрос, включая присоединившийся
к auto, сохраняет разрешение. При его отказе merge использует последний запечатанный
снимок. Shutdown отменяет свои внешние операции и ждёт drain.

Поколение политики отделено от поколения аккаунта: после включения прежний sink снова
работает. Смена credentials или профиля отзывает только данные и poll своего аккаунта.
Смена runtime сохраняет возраст и Retry-After, помечает снимок stale и не запускает
внеочередной общий опрос. Удаление CLI отзывает недействительные данные; новые измерения
в ручном режиме от этих действий не появляются.

Окно держит один manual одновременно: spinner у выбранного исполнителя, соседние кнопки
временно недоступны. Рутинный GET в это время пропускается, forced GET объединяется
одним флагом. После manual выполняется один cached GET. Reconnect сохраняет прежнюю
карту как stale, отзывает старый ответ и гарантирует этот пассивный resync. Ошибка ручной
доставки видна только у выбранного исполнителя даже при более свежем общем SSE; повтор
снимает её. Смена credentials очищает только соответствующую ручную ошибку.

## Холодный старт, проверка и откат

Снимки квот живут в памяти сервера: обновление страницы получает текущий снимок, после
перезапуска при false он пуст до первого ручного измерения. Дискового архива квот нет.
Откат к старому коду возвращает прежний автоматический режим: старый сервер не гарантирует
сохранение запрета. Формат prefs совместим, удаления данных и миграции нет.

Поведение проверяют синтетические providers-usage-policy, providers-usage-tick, прежние
usage/access/runtime-тесты и mounted settings-usage-policy/provider-usage-error.
Живая приёмка нового поведения ожидает владельца: ручной перезапуск сервера, обновление
окна/приложения, приёмка в браузере. Реальные проверки квот у поставщиков не запускались.
