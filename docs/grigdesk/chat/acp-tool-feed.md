# Общий ACP-нормализатор инструментов

Qwen и Kimi получают инструменты в одинаковом ACP-формате: `tool_call`/`tool_call_update`
с `kind`, `rawInput`, `locations` и массивом `content` (вложенные текстовые блоки,
структурные диффы, картинки). Разбор живёт в `server/src/lib/chat/acpSteps.ts`:
`parseAcpContent` достаёт текст и диффы, картинку заменяет заглушкой `STEP_IMAGE_TEXT`;
`acpToolStep` рисует строку вызова (Bash-команда, Read-путь, Edit-дифф, Grep-паттерн,
превью аргументов у незнакомых и MCP). Пределы унаследованы от Kimi: 20 файлов,
16 КиБ диффа, 500 символов пути; итог обрезается 400/600 символов.

Qwen подключает обе функции через `createQwenToolSteps` (`qwen/steps.ts`) в живом ходе
и фоновом коллекторе; строка обновляется тем же id при изменении ограниченной проекции,
включая значения прежних аргументов, kind/title и отдельно досланный путь. Точные дубли
пропускаются, устаревшие поля прежнего типа очищаются; kind/title не понижаются поздней
дельтой `other`, итог выпускается один раз. Исход итога
определяет `qwenToolFailed`, включая штатный LSP со статусом completed и текстом ошибки.
Новый путь Read заменяет прежний: непустые locations текущей дельты имеют приоритет,
затем path/file_path её rawInput; отсутствие нового пути сохраняет старый. Последний путь
запоминается ещё до определения kind и используется при повышении в Read. Edit продолжает
накапливать несколько файлов. Текст terminal-итога идёт только в res, а не в команду
или preview вызова; terminal rawInput/metadata/дифф могут обновлять строку.
Kimi делегирует те же функции своим stateful-нормализатором (`firstString` экспортирован
для `mergeToolUpdate`); серверный web-поток Kimi форматирует итог через
`kimiServerResultStep` с теми же пределами. Он принимает строки, массивы ACP-блоков,
прямой text/image-блок и объект с массивом content; неизвестный объект сохраняется
ограниченным JSON, скаляры — `String(output ?? '')`. У Kimi аддитивно появляются заглушка картинок,
дифф из пары old/new в rawInput и очистка устаревшего preview при обогащении строки.

Исправление действует на новые ходы после ручного перезапуска сервера: сохранённые
ленты не переписываются, окно рисует любой `res.text` как есть. Поле `files` tool-шагов
Qwen участвует в серверном подсчёте правленых файлов (итог Telegram-пульта, успешный res
подтверждает), заголовки строк — в досье прерванного хода. Текстовые блоки Qwen закрываются
на любом событии инструмента, включая in_progress.

Проверки: `qwen-tool-feed.test.js`, `acp-tool-step.test.js`,
`kimi-step-lifecycle-contract.test.js`, `kimi-server-feed.test.js`, `qwen-tool-results.test.js`.
Native-проверка с настоящим CLI (`GRIGDESK_QWEN_BIN`) — отдельная, по желанию человека.
