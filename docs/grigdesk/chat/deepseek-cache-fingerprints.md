# Проверка прогретого кэша DeepSeek

После холодной распаковки launcher полностью хеширует файлы и проверяет modes и links.
`.ready.json` format 2 хранит `ino`, `size`, `mode`, `mtimeNs`, `ctimeNs` из
`lstat({ bigint: true })`. Decimal strings сохраняют точные значения; массив записей
следует порядку защищённого payload index. Снимок включает каталоги и сам package root.

При обычном тёплом старте launcher сверяет полный состав дерева и fingerprints всех
записей. Если всё совпало, содержимое файлов не читается. Изменение ctime, inode, mode,
size, mtime, пропажа или лишний путь направляет проверку в полный путь. Hash mismatch
даёт прежний отказ; совпавшие hashes позволяют обновить snapshot. `--verify` всегда
считает полные hashes независимо от снимка.

ctime обновляет ядро при записи и смене прав; пользователь не может произвольно вернуть
прежнее значение. Cache закрыт правами 0700 и принадлежит пользователю. Этот механизм
рассчитан на ту же границу доверия, что и сам ELF: пользователь, способный менять cache,
способен заменить executable. Marker не является подписью против такого владельца.

Запись marker идёт под package lock в существующий inode с `O_NOFOLLOW`; directory entry
не меняется. Иначе сохранение snapshot само изменяло бы root mtime/ctime и каждый тёплый
запуск снова хешировал бы всё дерево. После публикации rename fingerprint root обновляется.
Повторный lstat после полного hash обнаруживает изменение файлов во время проверки.

Read-only modes задаются при сборке бинарной generation до расчёта её hashes и buildId.
Общий generation verifier сравнивает фактические mode и bytes точно; исключений для
read-only cache у него нет. Legacy-сборка использует прежний режим builder.
