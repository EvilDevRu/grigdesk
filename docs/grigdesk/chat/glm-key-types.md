# Тип ключа GLM и ошибка 1113 при активной подписке

## Раздельный биллинг ключей

По [руководству Z.ai от 16.10.2026](https://docs.z.ai/devpack/notice/api-key-management),
новые ключи разделены по продуктам. Проверено по официальной документации 28.10.2026.

| Тип ключа | Где получают | Источник оплаты |
| --- | --- | --- |
| Standard API Key | API Keys → Standard API Key | баланс или пакеты обычного API |
| Ключ индивидуальной подписки | API Keys → Personal Coding Plan | квота индивидуального плана |
| Team Plan Key | Team Coding Plan → My Plan | квота командного плана и места |

Для новых ключей смена endpoint не меняет источник оплаты. Даже на адресе Coding Plan
Standard-ключ не использует подписку. Старые ключи с классификацией `Compatible`
сохраняют прежние правила: общий endpoint использует баланс, Coding Plan endpoint —
подписку аккаунта, который имел план. Классификацию проверяют в кабинете; имя локальной
переменной `ZAI_CODING_API_KEY` само по себе тип ключа не задаёт.

Официальный [Quick Start](https://docs.z.ai/devpack/quick-start) указывает адрес
`https://api.z.ai/api/coding/paas/v4` для OpenAI Chat Completions. Этот адрес использован
в [прямой проверке](glm-coding-plan-smoke.md), поэтому ошибка адреса в ней исключена.

## Что доказывают Pro и ответ 1113

В GrigDesk уровень `Pro` приходит из `monitor/usage/quota/limit`. Этот ответ показывает
квоты аккаунта; он не содержит проверяемой классификации ключа для модельных запросов.
Чтение usage и допуск запуска раздельны. Отображение Pro не подтверждает расход подписки
конкретным ключом, а закрытый допуск модели не отменяет подписку.

По [справочнику ошибок Z.ai](https://docs.z.ai/api-reference/api-code), `1113` означает
отсутствие доступного баланса или пакета. Для перегрузки указан `1305`, для ограничения
частоты — `1302`, для окон подписки — `1308` и `1310`. Один HTTP-статус `429` причины
не различает: нужен код из тела ответа.

Прямые запросы 28.10.2026 в 10:45 UTC вернули `1113` для всех трёх моделей уже вне пика.
Официальный [обзор Coding Plan](https://docs.z.ai/devpack/overview) задаёт пик по будням
14:00–18:00 UTC+8, то есть 06:00–10:00 UTC. Ожидание окончания этого окна не объясняет
сохранение ошибки в проверке после 10:00 UTC.

## Граница диагноза и следующий шаг

При активной подписке и правильном endpoint сначала проверяют классификацию ключа.
Если выбран Standard, для подписки нужен ключ из Personal Coding Plan. Если выбран
Compatible или ключ плана, но сохраняется `1113`, причина требует дальнейшей проверки
прав на стороне Z.ai; руководство рекомендует передать поддержке детали ошибки и request ID,
не раскрывая ключ. Свежесть подписки и здоровые окна сами по себе эти случаи не различают.

В первой проверке тип сохранённого ключа не установлен. Чтение `zaiUserInfo` с тем же
источником ключа успешно, но не дало организации и проекта для получения списка
классификаций из кабинета. Сырые персональные данные не сохранялись. Запросы модели,
чтение квот и live smoke в этой диагностике не повторялись; допуск режима не менялся.

В [последующей проверке подписки и шлюза](glm-entitlement-diagnostics.md) подтверждены
`VALID`, `SUCCESS`, активный текущий период и отсутствие блокировки. Два модельных
маршрута снова дали `1113`; метаданные нового кабинета вернули HTTP 403. Тип ключа
и точная причина отказа по-прежнему не установлены.
