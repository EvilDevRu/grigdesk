# Повтор установки CLI при плохой сети

Общий `ProviderInstallService` повторяет команду установки или обновления при явной
временной сетевой ошибке. Правило действует для всех адаптеров, использующих этот сервис,
включая прежний маршрут `POST /api/providers/:id/update` и его fallback через `updateCmd`.
Сервер не повторяет ход агента и не меняет управляемую поставку DeepSeek/GLM.

Всего допускаются три попытки. Перед второй выдерживается 2 секунды, перед третьей —
5 секунд. Команды и паузы делят общий срок 10 минут. Возвращаются результат и диагностика
последней команды; потоковый хвост сохраняет вывод всех попыток по одному разу.

Повторяются сетевые коды curl, включая TLS-обрыв `curl: (35) … unexpected eof while reading`,
ошибки DNS, сброс/таймаут соединения, `fetch failed`, HTTP 429 и 5xx, соответствующие коды
npm. Ненулевой код без такой диагностики окончателен. Ошибки прав, места на диске,
отсутствующего CLI, сертификата, отмена, сигнал, лимит workspace и общий timeout не
повторяются. Исключение runner также окончательно: его происхождение не подтверждает
безопасную остановку процесса.

Admission и id операции остаются прежними на всё время ожидания. До следующей команды
runner должен подтвердить остановку предыдущего worker, а private state — очистить его
identity. При неизвестном ownership или ошибке сохранения повтор запрещён. Остановка
сервера отменяет паузу и сохраняет `interrupted`; восстановление после рестарта команду
не запускает. Версия и список моделей проверяются только после успешной команды.

Необязательное поле `retry: { attempt, attempts }` в снимке сообщает номер предстоящей
или выполняющейся повторной попытки. Окно показывает его на русском и английском только
во время фазы скачивания/установки. Старые снимки без этого поля остаются допустимыми;
новый клиент не принимает повреждённый счётчик.

Проверки: `tests/server/providers-install-retry.test.js` и
`tests/web/provider-install-dialog.component.test.js`. Они используют временные процессы
и подмены, без установки CLI на машину.
