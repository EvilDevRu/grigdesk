# Вывод и сообщения установки CLI

Хвост операции пополняется только потоковыми `onStdout` и `onStderr` общего runner.
Его итоговые `stdout` и `stderr` содержат уже переданные байты и используются для прежнего
ответа маршрута обновления, без повторного добавления в хвост. Это сохраняет порядок
поступления потоков и однократность строк после успеха и отказа.

Клиент показывает сохранённые результаты из первого снимка без принудительного обновления
реестра исполнителей. Один `providers.load(true)` выполняется, когда увиденная этим клиентом
активная операция с тем же id появилась среди завершённых. V2 также перечитывает реестр
после нового финала при пропущенной активной фазе. Первый снимок и повтор уже известного
итога пересборку не запускают. Переход V1 → V2 той же revision только раскрывает прежнюю
историю; более высокая revision сохраняет обновление после пропущенной операции.
Подробности — [повторное чтение после старта](../web/provider-startup-reloads.md).

Собственные причины сервиса передаются как `{ code, message }`: `error` операции, элементы
`warnings` и `blockedReason`. Ответ отказа запуска передаёт код в `error` и конкретную
причину в `message`. Непустой `message` показывается как получен даже для известного кода:
один код может описывать разные пути и причины отказа. Когда сообщения нет или оно пустое,
клиент использует перевод известного кода на текущем языке. Переключение RU/EN меняет
подписи окна и запасные тексты без запроса к серверу, сохраняя серверную причину.
Предупреждение об отказе каталога моделей не отменяет успех установки CLI.

Текст команды, её сырой вывод и неизвестные причины остаются данными. Для совместимости
декодер принимает также прежние строковые `warnings` и `blockedReason`; строки не считаются
ключами перевода. Диагностический `message` любого кода показывается как получен.
