# Изображения в результате рабочего инструмента Codex

Снимок `grigdesk_browser` возвращается в Codex как типизированный `inputImage`.
Лента не сериализует этот блок в JSON с base64: нормализатор заменяет его общей
заглушкой `STEP_IMAGE_TEXT`, сохраняя соседние текстовые блоки результата.

До отправки ответа dynamic tool адаптер сохраняет проверенный JPEG в приватную
папку `tool-images-*` внутри настроенного каталога артефактов. Путь связывается с
`callId` и передаётся в нейтральном поле `tool.imagePath`. Байты не попадают в SSE
и историю чата. Папка имеет режим `0700`, файл — `0600`; имена назначает сервер.
На один ход сохраняется не больше 32 изображений, каждое до 2 МиБ.

Окно показывает миниатюру при раскрытии успешного шага через существующий
`GET /api/chat/:id/image?path=`. Правила корней, формата и доступа те же, что у
[картинок в шагах Read](step-images.md). Ссылка открывает общий просмотрщик,
удалённый файл даёт подпись «Изображение недоступно». Поле пути сохраняется в
истории, поэтому миниатюра доступна и после завершения хода и повторной загрузки.

Ошибка записи артефакта не меняет доставку исходной картинки агенту: сервер пишет
предупреждение, а лента остаётся с текстовой заглушкой. Без настроенного каталога
артефактов и после исчерпания квоты сохраняется та же заглушка без base64.
Старые ленты с уже обрезанным base64 не переписываются и картинку не восстанавливают.

Проверки: `chat-step-stream.test.js`, `codex-app-server-contract.test.js`,
`browser-executor.test.mts` и `step-list.test.js`.
