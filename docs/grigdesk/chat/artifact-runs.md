# Папка артефактов хода и срок хранения

На Linux обычный ход с проектом получает папку
`<артефакты GrigDesk>/chat-runs/projects/<project-id>/<run-id>/`. Для хода без проекта
используется `<артефакты GrigDesk>/chat-runs/<run-id>/`. Проект берётся из сохранённого
выбора чата или доверенной записи прогона задачи. Обе папки находятся в общем хранилище,
вне рабочих копий, поэтому в репозиториях не требуется `.gitignore`.

Ход получает путь в подсказке, когда исполнитель принимает дополнительные папки
и ему доступно общее хранилище. Если выдать папку невозможно, сохраняется прежний
сценарий. Служебные slash и сжатие не создают папку запуска.

Сервер записывает принадлежность запуска чату и identity каталогов вне рабочих
копий, в `state/chat-artifact-runs/`. Абсолютные ссылки на картинки и документы
работают после исчезновения worktree. Источник документа использует идентификатор
запуска, поэтому удаление соседнего каталога не меняет адрес источника. Уже
зарегистрированные каталоги сохраняют прежние адреса до истечения срока хранения.

Срок начинается со времени завершения хода. После старта и затем раз в сутки сервер
проверяет завершённые записи. Через 14 суток удаляется только зарегистрированный
каталог, чей физический путь и inode остались прежними. При занятой блокировке сервер
повторит проверку позднее. Каталог с неизвестным исходом после аварии сохраняется.

Чтобы сохранить результаты, создайте пустой `.keep` внутри папки запуска до истечения
срока. Закрепляется вся папка и все её ссылки. Тот же маркер может поставить агент по
просьбе пользователя. Если его убрать, следующий проход сможет удалить просроченную
папку. Старые общие темы обрабатывает [явная уборка](../server/artifacts-cleanup.md).

`tests/server/chat-artifact-runs.test.js` проверяет путь вне рабочих копий, срок, занятую
блокировку, закрепление, подмену пути ссылкой и чтение после удаления рабочей копии.
Приёмка на пользовательских артефактах не выполнялась.
