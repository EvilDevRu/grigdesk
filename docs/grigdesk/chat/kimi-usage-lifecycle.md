# Завершение служебной проверки лимитов Kimi

Проверка лимитов запускает отдельный краткоживущий `kimi web`, без модельного хода.
Раньше остановка модуля исполнителей снимала только таймер будущих опросов:
уже начатый запрос и его процессы могли пережить выход основного сервера.
Дополнительно npm/native launcher мог завершиться раньше своего потомка;
сигнал одному launcher и проверка его `exitCode` не доказывали остановку брокера.

## Владение и остановка

`server/src/modules/providers/index.ts` передаёт опросам `deps.signal` и учитывает
незавершённые вызовы адаптеров. Шаг drain сервера и Fastify `preClose` отменяют
сигнал, снимают таймер и ждут завершения вызовов вместе с их cleanup. `preClose`
срабатывает до ожидания HTTP-соединений, поэтому запрос лимитов можно отменить
даже при закрытии сервера с активным читателем. После отмены новые фоновые опросы
не запускаются, запоздавший результат не меняет состояние лимитов и не рассылает SSE.

Адаптер Kimi передаёт сигнал в `requestKimiManagedUsage`. Отмена запрещает spawn,
прерывает ожидание готовности и HTTP-чтение, отменяет обычную паузу повтора;
следующая попытка после отмены не запускает CLI. Завершение процесса остаётся
в `finally` и входит в ожидание остановки модуля.

Каждый запуск брокера получает отдельную process group через `detached: true`.
Сигналы направлены только группе собственного запуска, включая npm/native
потомков. После штатного HTTP shutdown либо отказа запуска группа получает TERM,
до двух секунд ожидается `close` со всеми pipe, затем KILL завершает остатки
группы даже при уже вышедшем launcher. После KILL даётся ещё до двух секунд на
`close`; отсутствие подтверждения вызывает ошибку cleanup. Неподготовленный
прямой запуск и подготовленный запуск через lease helper используют эту же границу.

Это контракт штатной остановки. Принудительное убийство самого сервера без выполнения
drain/preClose не запускает JavaScript cleanup. Самостоятельные серверы других
рабочих копий и внешние сессии исполнителей имеют собственный жизненный цикл.

## Проверки

`tests/server/kimi-usage-lifecycle.test.js` использует настоящие локальные процессы
и HTTP-заглушку без аккаунта. Проверяются отмена до spawn, ожидание запуска и HTTP,
отмена между попытками, потомок живого и уже вышедшего launcher, `app.close()`
и drain координатора. После остановки проверяется отсутствие живого worker,
запоздавших SSE и повторного опроса. Соседние проверки — `kimi-usage-startup`,
`kimi-provider`, `providers-usage-tick`, `external-cli-process`.
