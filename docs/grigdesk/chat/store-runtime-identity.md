# Стабильный владелец runtime-состояния чата

Pinia devtools оборачивает каждый action
новым Proxy поверх реактивного store. Поэтому `this` разных actions не является
стабильным ключом WeakMap: setter и обработчик ACK получают разные runtime-карты.
Это теряло намерение выбора при старом ACK и при сверке после серверной записи.

Runtime-карты чата используют исходный объект store через Vue `toRaw`: намерения,
подтверждения истории, проекции сохранения и кэш списка имеют одного владельца.
Обращения из getters, actions, загрузки, удаления и dispose используют тот же ключ.
Сам чат остаётся реактивным; runtime не попадает в состояние Pinia, API или страховку.

На стенде с devtools воспроизведены и затем устранены откат модели после reset,
откат нового выбора при задержанном первом ACK и потеря эффорта после серверного reset.
Тестовая Pinia без установки приложения не включает эту обёртку actions, поэтому
офлайн-проверки стора дополняются проверкой общего web-клиента.

Правила сохранения и CAS описаны в [контракте переключения модели](model-switch-revert.md).
