# Повторные обходы при сохранении

Проверено 29.10.2026 после добавления [индексов каталога](chat-catalog-lookup.md).
Общий `_persist` сохраняет прежний поиск изменённых записей, но повторно использует
результаты подготовки в пределах одного синхронного прохода.

Загруженные активные и архивные чаты отбираются один раз. Эти же массивы задают
порядок проекций, проверок dirty и записей страховочного снимка. Полный список
объектов используется и для проверки удалённых id, и для очистки кэша проекций.

Для dirty-проверки уже есть кэшированный JSON-отпечаток; проверка steps читает
только id и массивы messages. Поэтому отдельные `slimOf`/`archivedSlimOf` копии
ради каждого сравнения больше не создаются. Полные копии для страховки готовятся,
когда накоплен `needSnapshot` и не мешает восстановление прежних снимков.
Снимок всё так же записывается до PUT. Сетевой запрос получает свежую отдельную
копию через прежнюю очередь `_writeChat`.

У незагруженных голов сравниваются четыре поля из прежней нормализованной
проекции `_headMetadata`: название, прочтение, принадлежность архиву и время
закрытия. Для такого сравнения не создаются две JSON-строки на каждую запись.
Runtime-поля не вызывают PATCH, а значения по умолчанию остаются прежними.

Проверки в `tests/web/chat-persistence-projection.test.js` подтверждают dirty
для каждого из четырёх полей и его снятие после возврата исходного значения,
а также прежние порядок снимка/PUT и сохранение вложенных правок сообщений.
Проверки ленивой истории и step-reuse сохраняют запрет записи placeholder
как полной истории и прежнее подтверждение шагов.

Эти изменения сокращают работу одного прохода. Они не вводят реестр dirty-чатов,
новые таймеры, отложенные страховки или другую схему CAS. Полный проход остаётся
линейным по каталогу; его длительность проверяется отдельно от HTTP ACK.
