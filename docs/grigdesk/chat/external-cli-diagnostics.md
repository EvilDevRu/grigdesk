# Диагностика внешних CLI и свежесть лимитов

Claude, Codex и host Kimi объявляют capability `externalCli`. Реестр дополнительно возвращает
`installation.inventory`: найденные копии, npm/native/unknown происхождение, aliases, выбранную
копию, команду из переданного PATH и признак расхождения. Contained Kimi, DeepSeek, GLM и API-провайдеры
эту возможность не получают. Опись только читает файлы; она не является разрешением на удаление.

Npm-копия подтверждается физическим global package root, именем package.json и declared bin внутри
пакета. ELF в npm-пакете остаётся npm-копией. Отсутствующая ссылка или entry отмечаются как broken;
aliases одной копии объединяются, а рабочий entry сохраняет свою физическую identity даже при
битой соседней ссылке. Native-кандидаты ограничены объявленными адаптером путями и ELF-заголовком;
их версия и пригодность к изменению этим чтением не подтверждаются. Неизвестные wrappers не запускаются.

Копия с физическим корнем внутри `D/state/npm-global`, I или R получает `origin=grigdesk`;
пользовательская — `origin=user`. Origin нужен только для migration preview, а не для
разрешения удаления: сервер повторно сверяет пакет, версию и symlink.

Поиск ограничен PATH, явным absolute-bin, объявленными native entries и одним уровнем версий nvm.
Рекурсивного обхода HOME нет. `resourceKey` обозначает ресурс установки, `installationId` — снимок
identity для проверки изменений. Смена файла должна менять последний идентификатор.

## Успешный замер отдельно от доставки

Только адаптеры с `usagePresentation.freshness` получают `lastSuccessfulAt`, `runtimeGeneration`,
`pollIntervalMs`, `usageSchema`. Успешным считается неустаревший ответ со state=ok и непустыми
полосами или ресурсами. Ошибка, доставка кэша и живой patch не обновляют время успешного замера.
До первого успеха оно равно null. Общая нормализация остальных провайдеров сохраняет прежнее поведение.

В интерфейсе такие данные устаревают после двух интервалов опроса, истечения окна, ошибки или
разрыва доставки. После reconnect повтор того же успешного замера не снимает stale: нужен новый.
Процент при сбросе не обнуляется предположением. В поповере расход подписан «Израсходовано» и
показано время замера либо его отсутствие. Используются существующие таймеры и общая SSE-шина.

Внутренний `invalidateProviderRuntime` меняет поколение, снимает старый live overlay, сохраняет
Retry-After и время замера. Удаление очищает активные полосы и ресурсы. Замена кэшированной проекции
не запускает внеочередной опрос здоровых соседей и не продлевает TTL. Номер поколения включает
случайный идентификатор запуска сервера: после перезапуска старый процесс не считается тем же runtime.

Прогноз хранит историю, но не соединяет samples разных runtime, usageSchema, длительности окна и
календарных месяцев. До нового успешного замера после invalidation текущий прогноз имеет unknown;
при удалении история не стирается. Старые файлы прогноза без segment продолжают читаться.

Проверки: provider-install-inventory, providers-usage-tick, usage-forecast и web provider-usage-summary.
