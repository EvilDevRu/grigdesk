# Живые квоты аккаунта поверх опроса

Полосы квот показывают расход всего аккаунта. В строке чата показан остаток
`100 − pct`, во всплывашке исполнителя — расход. Токены одного хода не пересчитываются
в проценты подписки. Денежные ресурсы сохраняют свою валюту.

## Источники и доставка

Опрос `usage()` остаётся источником набора полос, подписей, групп, длительности окон,
ресурсов, состояния и времени замера. Отдельный оверлей меняет только процент и сброс
полосы с тем же ключом. Неизвестный ключ при непустом снимке игнорируется. До первого
успешного снимка без полос допускается полоса из события; состояние отказа остаётся отказом.

Живые события приходят через существующий `providers-usage`: в сообщении всегда полная
карта исполнителей. Дубликаты не рассылаются повторно. Patch не читает и не очищает
кэш опроса, не меняет его TTL, паузу после 429 и `Retry-After`, не записывает историю
появления вёдер. Пока в последнем опросе нет записи хотя бы одного известного исполнителя
(в том числе после сброса ключей), событие сохраняется без отдельной рассылки.
Полную карту публикует ближайший общий опрос.

| Источник | Нативное окно | Ключ полосы | Единицы |
| --- | --- | --- | --- |
| Codex 0.163.0, `account/rateLimits/updated` | Слоты ведра `rateLimits` | Тот же `limitId:slot`, что у опроса | Целый `usedPercent`, Unix-секунды сброса |
| Claude 2.1.302, `rate_limit_event` | `unifiedWindows.five_hour` | `session` | Доля `utilization` умножается на 100 один раз |
| Claude 2.1.302, `rate_limit_event` | `unifiedWindows.seven_day` | `weekly_all` | Доля `utilization`, сброс из Unix-секунд в ISO |

Codex с `limitId: null` использует общее ведро `codex`, как запасной формат опроса.
Разреженные уведомления не стирают прежние метаданные полями `null`.
Claude использует верхний `utilization` только для явно названного `five_hour` или
`seven_day`, если такого окна нет в `unifiedWindows`. Событие без чисел не создаёт квоту.
`seven_day_overage_included` не обозначает модельную неделю: её обновляет только опрос.

## Порядок событий и поколение аккаунта

Сбросы сравниваются по времени, а не строкой ISO. Разница до минуты означает то же
окно; одинаковый процент и разница сброса до секунды — дубликат. Старое окно отвергается.
В одном окне событие не уменьшает расход; более поздний сброс допускает уменьшение.
`resetsAt: null` означает неизвестный срок и сохраняет известный сброс из оверлея или
снимка. При неизвестном сроке одинакового процента достаточно для признания дубликата.
Проекция в том же окне берёт больший расход из снимка и оверлея; если окно снимка
новее окна оверлея больше чем на минуту, старый оверлей для этой полосы не применяется.
Успешный опрос может уменьшить расход и снимает только события, существовавшие перед
началом чтения этого исполнителя. Снятие откладывается до завершения всего общего опроса,
чтобы GET во время ожидания медленного соседа сохранил живые значения поверх прежнего кэша.
События, полученные во время чтения, остаются поверх ответа с учётом свежести его окна.

Поколение ведётся отдельно по исполнителю. Сохранение его ключей доступа инвалидирует
старые обработчики и очищает его оверлей, сохраняя паузы соседей. Успешное действие
ресурса очищает только свой оверлей без смены поколения. Обработчик привязан к процессу,
работает между ходами и не проверяет завершившийся `runId`. Ошибка обработчика не роняет ход.

## Свежесть и ограничения

Событие не освежает `checkedAt`, `dataCheckedAt`, `stale` и не отменяет отказ вендора.
В чате истёкший сброс помечает сохранённые цифры устаревшими; новый остаток 100% не
выдумывается. Компонент держит один таймер на ближайший сброс и снимает его при закрытии.
Смена исполнителя или ссылки на его запись квот переставляет таймер; прочие изменения
статуса хода этого не делают.

Прогноз не получает новую дату замера от patch: повторный `dataCheckedAt` не удлиняет
ряд. Он остаётся прогнозом по времени опросов, а не отдельным потоком живых измерений.
Если первый увиденный прогнозом SSE несёт ранее неизвестный штамп опроса, существующий
слушатель может принять его как первый снимок; отдельного признака источника у события нет.

Внешний вход через CLI не меняет поколение сервера: у Claude и Codex нет серверного
маршрута credentials. Следующий опрос сверяет аккаунтные данные.
Запасной HTTP-формат Claude сохраняет ключи `five_hour`/`seven_day`; события с ключами
`session`/`weekly_all` такие полосы не обновляют. `weekly_scoped` без `display_name`
по-прежнему может иметь неуникальный ключ. Эти границы не исправляются угадыванием модели.

Проверки: `provider-usage-live`, `providers-usage-tick`, `chat-live-sessions`,
`codex-app-server-contract`, `claude-rate-limit-events`, `provider-usage-sse`.
Кадры в тестах синтетические; сравнение с реальной консолью аккаунта не выполнялось.
