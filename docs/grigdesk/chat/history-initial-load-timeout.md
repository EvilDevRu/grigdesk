# «На телефоне нет чатов» = вся история одним GET не укладывается в таймаут

Симптом: окно на медленном пути (телефон через сеть и TLS-трубу, слабый канал) после входа
показывает пустой раздел «Чаты». Ошибки нет; компьютер с тем же сервером видит все чаты.
В журнале сервера у такого окна `GET /api/chat/store` остаётся без `request completed`,
повтор приходит ровно через 30,7 с после первого.

Причина: `_load()` в `web/src/stores/chat.ts` берёт всю историю одним
`GET /api/chat/store` — активные и архивные чаты вместе с лентами сообщений. Ответ
не сжимается и растёт с историей без верхней границы: на долгоживущей установке он
достигает сотен мегабайт, и даже loopback отдаёт его за секунды. Общий клиент
`web/src/shared/apiClient.ts` ограничивает GET 30 с и повторяет один раз через 700 мс.
Второй таймаут попадает в `catch` с `j = null`. Если в браузере нет снимка (новое
устройство, свежая привязка), стор помечается `loaded` пустым, без видимой ошибки.

Сверка по `hello` после переподключения тоже читает полный `GET /api/chat/store`.
Каждый разрыв SSE снова гонит всю историю.

Данные на сервере это не портит: полный `PUT /api/chat/store` сохраняет чаты,
отсутствующие в теле ([хранилище истории](history-storage.md)).

Смежное: запись истории уже точечная по той же причине — объём запроса не должен зависеть
от числа накопленных чатов ([лимит тела PUT](history-request-size-limit.md)). Чтение
первой загрузки этому правилу пока не следует.
