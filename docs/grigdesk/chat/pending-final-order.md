# Порядок финалов при нескольких окнах

Пока агент отвечает, человек может поставить несколько вопросов в очередь. Окно сохраняет
их до получения финалов, поэтому в файле все вопросы могут стоять перед уже готовыми ответами.
Позиция вопроса сама по себе не определяет, куда вставить следующий ответ.

Перед следующим запуском `InTurnHistory.project` переносит pending в историю. Новый финал
встаёт после сообщений своего запуска и после уже записанных ответов более ранних ходов.
Иначе итог третьего хода мог попасть перед первым и вторым, а синхронизация разносила эту
перестановку по окнам. Более ранние ходы определяются порядком вопросов с `turnId` в ленте;
связь ответа с ходом берётся из `turnId` либо прежнего `pid`, равного id принятого хода.
Текст ответа и часы устройств для этого не сравниваются.

Уже известный итог не переносится и не дублируется: сохраняется прежняя проверка устойчивого
ключа. Формат файлов, порядок durable-записи и подтверждения pending остаются прежними.

Проверка: `tests/server/chat-turn-delivery-store.test.js` ставит четыре хода из двух окон
и проверяет порядок, отсутствие пропусков и дублей в обоих окнах и серверном файле.
`tests/server/chat-in-turn-history.test.js` проверяет проекцию уточнений и устойчивые ключи.
