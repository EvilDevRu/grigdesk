# Kimi: heartbeat потока событий

Чаты Kimi получают события через WebSocket `/api/v1/ws` процесса `kimi web`.
Контракт клиента совместим с 0.33.0 и heartbeat протокола v2 из Kimi Code 2.3.1.
В 0.33.0 сервер не посылает эти пинги.

## Протокол и тайминги

В 2.3.1 кадр `server_hello` объявляет `protocol_version: 2` и `heartbeat_ms: 10000`.
Каждые 10 секунд сервер отправляет JSON-кадр:

```json
{"type":"ping","timestamp":"2030-01-01T00:00:00Z","payload":{"nonce":"example-nonce"}}
```

Клиент отвечает без ожидания событий хода:

```json
{"type":"pong","payload":{"nonce":"example-nonce"}}
```

Nonce должен совпадать. Если `payload.nonce` отсутствует или не является строкой,
клиент отправляет пустую строку. `ping` обрабатывается транспортом и не передаётся
в `onEvent`; остальные кадры до и после него доставляются обычным порядком.
Ошибка отправки `pong`, когда сокет уже закрывается, поглощается.

Сервер считает время с последнего входящего кадра клиента. После двух интервалов
тишины (не менее 20 секунд) ближайший такт heartbeat закрывает сокет с кодом `1001`
и причиной `heartbeat timeout`. Любой входящий кадр клиента сбрасывает отсчёт.
Исходящий текст агента этот отсчёт не сбрасывает.

## Симптом и причина

Клиент раньше отправлял только начальный `subscribe`. Поэтому после обновления до
2.3.1 длинный ход обрывался примерно на третьем такте, около 30 секунд после подписки,
с ошибкой «Поток событий Kimi закрылся до завершения хода.».

Теперь транспорт отвечает на каждый `ping`, поддерживая поток даже во время долгого
действия без событий агента. Если сервер всё же закрывает сокет посреди хода,
драйвер включает код и причину в ошибку:

> Поток событий Kimi закрылся до завершения хода (код 1001: heartbeat timeout).

Такой сбой не получает признак `stopped`. Если есть только код, показывается только
код; без статуса и причины сохраняется прежний текст. Служебный WebSocket-код `1005`
означает отсутствие статуса в close-кадре и не показывается как причина сервера.

## Проверка и применение

`tests/server/kimi-server-events.test.js` проверяет nonce, фильтрацию `ping`, доставку
обычных кадров и гонку отправки при закрытии. Фейковый сервер повторяет heartbeat
с интервалом 100 мс: молчащий клиент отключается через два интервала, исправленный
принимает кадр на шестом такте. `tests/server/kimi-server-failures.test.js` проверяет
код и причину ошибки, отсутствие ложного `stopped` и закрытие без статуса.
Модель в этих проверках не вызывается.

Правка вступает в силу после ручного перезапуска GrigDesk. Пересборка web не нужна.
