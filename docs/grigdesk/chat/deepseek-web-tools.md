# Веб-инструменты и разрешения DeepSeek

Штатные `web_search` и `web_fetch` входят в список инструментов чтения политики
`deepseek/src/host/toolPermissionPolicy.mjs`. Они разрешены без отдельного подтверждения
в режимах `default`, `auto` и `read-only`. Gate проверяет точное имя и доверенную
регистрацию текущего запуска; похожее имя или недоверенная реализация разрешения не получают.
Запрос или отказ другого native listener сохраняется.

Ранее оба имени отсутствовали в списке: даже в «Авто» gate возвращал `ask`, а сервер
доставлял обязательный разовый вопрос человеку. Поэтому разрешение `web_fetch` могло
останавливать обычное исследование в интернете.

Допуск инструмента не меняет его сетевой backend, ключи и оплату. Штатные проверки
адресов, редиректов, размера ответа и таймаутов Harness продолжают действовать;
содержимое страницы остаётся недоверенными данными. Файловые права, shell и проектные MCP
регулируются прежней [политикой разрешений](deepseek-tool-permissions.md).

Проверки: `tests/deepseek/toolPermissionPolicy.test.mts` покрывает три режима, недоверенную
регистрацию и похожие имена; `toolPermissionGate.test.mts` исполняет оба инструмента через
настоящий native registry с подсчётом эффектов и отсутствия вопросов.
`tests/server/deepseek-tool-permission-parity.test.js` проверяет настоящий ELF и оба
веб-инструмента в `auto`: вопросов нет, внешний поиск останавливает тестовый fetch guard,
а обращение к loopback-странице отклоняет штатная сетевая проверка Harness.
Платные запросы и внешние страницы в этих проверках не используются.

Политика упакована внутрь автономного ELF: изменение применяется после его пересборки
и штатной установки. Уже запущенный ход использует прежнюю поставку; следующий получает
новую без перезапуска сервера. Правка политики также меняет identity общего Harness:
для установки нужен повторный [живой допуск GLM](glm-binary-admission.md) режима потребителя.
[Порядок поставки](deepseek-binary.md).
