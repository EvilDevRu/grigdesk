# Kimi host: проверка команд в GrigDesk

При активном запрете SSH или прямых DB-клиентов host-адаптер чата использует отдельный
канал команд `grigdesk-command/run_command`. Обычный текст проходит с включённым плагином
БД; отказ политики относится к отдельной команде. Возможность адаптера называется
`command-broker`. Внутренний ACP host сохраняет отказ до запуска, contained сохраняет
сетевую песочницу.

## Профиль и допуск хода

Для каждого server-хода создаётся отдельный home. TOML разбирается `smol-toml`, копия
получает глобальный `tools.disabled = ["Bash"]` с сохранением прежних запретов. Исходный
файл не переписывается. Пользовательские sessions доступны через ссылку; при первом
запуске sessions создаётся в исходном home и переживает удаление копии.

После применения native settings и выбора сессии адаптер читает `/api/v1/tools`:
только явный `Bash.active === false` допускает prompt. Холодная resumed-сессия сначала
загружается snapshot. Неизвестная форма или ошибка этого доказательства закрывает весь
ход, поскольку отсутствие встроенного Bash ещё не подтверждено. Глобальный запрет
действует также в yolo и дочерних агентах, независимо от approvals и hooks.

Служебный MCP добавляется в копию `mcp.json`. Одноимённый пользовательский MCP удаляется
из этой копии даже при отказе создания канала. Отказ канала сохраняет текстовый диалог
с закрытым Bash. При обеих выключенных политиках преобразование профиля не применяется.

## Допуск команды

Сервер владеет cwd, env и снимком SSH/DB-политики на ход. MCP принимает только command и
целочисленный timeout_ms (от 1 мс до двух часов; умолчание две минуты). Нельзя передать
свой каталог, окружение, разрешение или scope. Приватный IPC проверяет nonce, который
не передаётся в prompt. Это существующий транспорт work-mcp с отдельным dispatcher.

Перед командой читаются нативные ограничения Bash. Затем `evaluateDirectCommand`
проверяет прямые SSH/DB-клиенты; deny запрещает запуск, unknown следует действующей
настройке strictUnknownDbClient. Исключение или повреждённый verdict запрещают команду.
После этого применяется обычное разрешение режима чата: manual/plan спрашивают,
auto использует общий классификатор с kind execute, yolo пропускает только этот спрос.
После ожидания разрешения нативные ограничения читаются повторно.

Разрешённая команда запускается через общий `packageInstall/runCommand` и
`/bin/bash --noprofile --norc -c`. Supervisor ограничивает вывод и срок, при остановке
снимает своё дерево. Ошибка команды, timeout или отмена не означают откат её эффектов.
При cleanup сначала отменяются собственные задания и ожидания разрешения, затем
закрывается канал и удаляется overlay. Поздний ответ человека не запускает команду.

## Пользовательские ограничения

Permission rules и Bash PreToolUse hooks из исходного TOML/native settings не переводятся
приблизительно в правила нового MCP: при их наличии команды закрываются с объяснением,
текст сохраняется. Некорректный regex matcher консервативно закрывает команды без
исключения, которое оборвало бы текстовый диалог.

В Kimi 0.33.0 проверены закрытые GET диагностического RPC: session/workspace disabledTools,
agent main profile data, agent main permission rules и полный sessionActivity.folds.
Effective hooks включают плагины Kimi: чтение externalHooksRunnerService/summary идёт
после ожидания его ready. Любой непустой список live permission rules, любой эффективный
PreToolUse hook, неизвестная форма или ошибка RPC запрещают команду. Консервативный
отказ включает правила/hook для других инструментов: их точная адаптация не реализована.

При любом живом дочернем scope команды закрываются, поскольку stdio MCP не удостоверяет
ID вызывающего агента. Проверяется полный folds, включая background/detached/nested,
а не только публичный roster. Даже завершивший ответ ребёнок может сохранять живой
scope до следующего хода; после его удаления или следующего хода допуск возвращается.

Диагностический RPC включается только для controlled host: Kimi слушает loopback и
требует private bearer token. Endpoint, token и произвольный RPC не выдаются модели.
При неподтверждённом протоколе новой версии команда остаётся закрытой.

## Проверка и границы

Unit/integration проверки находятся в `tests/server/kimi-command-*.test.js` и
`kimi-runtime.test.js`. `kimi-controlled-installed.test.js` запускается с явным
GRIGDESK_TEST_KIMI_CONTROLLED_BIN и синтетическим home/loopback Anthropic SSE-сервером.
Он проверяет fresh/resume, обычную команду, внешний DB-клиент, native session/profile/rules,
плагин с Bash hook и дочерние foreground/background/detached scope, без настоящей модели.
Запуск без переменной пропускается и не доказывает контракт установленного CLI.

Это защита от прямых штатных клиентов кооперативного агента. Скрытые подключения из
разрешённой программы, обфускация и код того же UID вне этой границы; сетевой изоляции
host не получает. PTY, отдельный менеджер фоновых задач и перенос команд между ходами
не создаются. Ранее запущенные процессы ретроактивно не отзываются.
