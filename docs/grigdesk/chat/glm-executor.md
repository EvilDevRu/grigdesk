# Исполнитель GLM (Z.ai)

GLM работает в обычном чате GrigDesk через тот же автономный ELF DeepSeek Harness, что и
DeepSeek: плагин `llm-pi-ai` с библиотекой pi-ai монтируется только в процесс GLM, маршрут —
встроенный провайдер `zai`. Агентный цикл, инструменты, approvals и журнал сессии принадлежат
DSH. Подробности — в документах контракта: доступ и допуск, профиль запуска, ход, политика
инструментов, MCP, каталог, память, стоп и маршрут чата (ссылки в README раздела).

## Допуск

Карточка видна всегда. Настроенный разрешённый режим объявляет `run`, а допуск актуального выпуска
проверяется перед запуском. Запись допуска — пара режима и identity
совместимости сборки; её добавляют после compiled-тестов сборки и короткой живой проверки режима
скриптом `server/scripts/glmLiveSmoke.mts --mode api --confirm-live --binary <ELF>
--cache-dir <отдельный cache>`. Любое изменение входов
identity (commit DSH, патчи, композиция, lock сборки, pi-ai, исходники плагина, ревизии профиля и
политики, адрес режима) закрывает GLM до повторного допуска. Смена `GRIGDESK_GLM_API_MODE`
требует перезапуска службы: загрузчик кэширует адаптеры.

При закрытом режиме карточка остаётся в настройках, а значок верхней панели скрывается:
[проекции видимости и эффект перезапуска](glm-setup-visibility.md).

| Режим | Основание доступа | Проверка | Вердикт |
| --- | --- | --- | --- |
| `api` | оплата по расходу с баланса Z.ai | профиль `grigdesk-glm-profile-v3` с foreground критиком прошёл live 8/8; каждый ELF требует точного metadata admission | разрешён политикой |
| `coding-plan` | подписка Z.ai | live smoke 28.10.2026 с новым ключом прошёл все восемь проверок; каждый ELF требует точного metadata admission | разрешён политикой |

Живая проверка идёт через временный Fastify с модулем чата и DI-адаптером: временные homes, чат
и рабочая папка, ключ — из `.env` папки данных поверх окружения запуска (оболочка из чата держит
значения со старта сервера, а `node --env-file` уже заданные переменные не перекрывает); скрипт ключ
не печатает. Не больше восьми ходов. Сценарий: ответ; маркерные чтение, правка и команда; размышление и результат
инструмента; resume; foreground критик с дочерним чтением; отказ политики;
стоп во время approval; повтор принятого хода по `turnId`.
Отчёт — без ключа и без постоянных путей; содержит kind, mode, compatibility,
packageId и SHA выбранного ELF, а также [HTTP-ошибки модели](glm-smoke-http-errors.md).
После отказа первого ответа сценарий останавливается.
[Offline-проверка инструмента](glm-smoke-binary.md)
не подтверждает живой допуск нового выпуска.
[История проверок Coding Plan](glm-coding-plan-smoke.md) сохраняет первый отказ `1113`
и последующий полный успех с новым ключом. Запись в исходниках не расширяет metadata
старого ELF: нужен выпуск с admission выбранного режима.

## Ограничения

- В профиле чата v3 действует [native gate](glm-native-gate.md): результат проверки обязателен
  до body инструмента, включая дочерние сессии. Foreground spawn/fork наследуют модель,
  инструкции и ограничения; дети работают с `approvalPolicy: never`, вопросы возвращают корню.
  Background/continuable, прямые child approvals/questions пока закрыты.
- Legacy Factory/ACP сохраняют hook. Его fail-open ограничение не относится к native gate
  профиля чата v3: аварийный hook там мог пропустить эффект до реакции серверного сторожа.
- Проектные MCP в первую поставку не входят: DSH не спрашивает approval для MCP-инструментов.
- `ZAI_API_KEY` и `ZAI_CODING_API_KEY` в окружении службы наследуют дочерние процессы других
  исполнителей (Claude, Codex, Kimi) — так же, как сегодня `DEEPSEEK_API_KEY`.
- Публикация новых ELF DSH требует зелёных compiled-тестов GLM. Совместимые
  обновление и откат сохраняют память чата; несовместимый журнал начинает память заново
  с заметкой, лента сохраняется.
- Нет триажа, анализатора, нативных настроек, картинок на вход, режима «Только чтение»
  в обычном чате и других endpoint-ов (BigModel, OpenRouter). Текст в активный ход поддержан;
  картинки — нет: [ограничение инструмента и файловая политика](glm-image-input.md).
  Отвязанный этап фабрики поддержан с отдельным контекстом хоста:
  [контракт этапа](glm-factory-stage.md).
