# Поиск по каталогу при сохранении чатов

Проверено 29.10.2026. Лёгкий каталог не устраняет стоимость поиска по массивам:
`_persist` проверяет полноту записей, затем изменения метаданных незагруженных
голов. Прежние `_find`, `_get` и `isArchived` на каждом таком шаге снова обходили
активный список и архив. Поэтому сохранение даже неизменённого каталога получало
квадратичную стоимость независимо от размера сообщений и steps.

В синтетической проверке 1779 голов, из которых 12 активны, один `_persist`
без снимка и сетевых запросов читал id около 9,5 миллиона раз. Замеры подтвердили
длинную синхронную работу именно без сериализации полной переписки.

## Индексы и инвалидация

Store вычисляет отдельные индексы `Map` активного списка и архива через Pinia
getters. Они читают состав соответствующего массива и id его объектов. Изменение
названия, текста, черновика или runtime-полей не перестраивает индекс. Добавление,
удаление, перестановка, замена массива или объекта и изменение id учитываются Vue
без отдельной ручной синхронизации.

`session`, `active`, `_find`, `_get` и `isArchived` используют эти индексы.
Активный список сохраняет приоритет перед архивом; при повторном id внутри списка
выбирается первый объект, как у прежнего `Array.find`. Индексы принадлежат экземпляру
store, не входят в `$state`, PUT или страховочный снимок и не хранят прежние списки.

Локальный поиск передаёт в общий projector только title, taskId и messages.
Подтверждённая сводка счётчиков собирается из проверенных числовых полей, epoch и sequence.
Обе границы обходятся без двойного утверждения типов через `unknown`; правила принятия
сводки и приоритет локального/серверного фрагмента остаются прежними.

После прогрева первичное исправление уменьшило число чтений id примерно до
14 тысяч. Последующее [сокращение повторных обходов](chat-persist-passes.md)
уменьшило его примерно до 12 тысяч. Это линейный проход проверок; индексы
не меняют dirty/CAS, адресную загрузку, очередь PUT и восстановление страховки.

## Проверки и границы

`tests/web/chat-persistence-projection.test.js` ограничивает число чтений id при
повторном сохранении большого незагруженного каталога и проверяет отсутствие
лишних detail, PATCH и PUT. Отдельный сценарий проверяет замену объекта, перенос
между списками, удаление, изменение id, приоритет и `$reset`.

Это дополнение к [кэшу служебных JSON-проекций](chat-save-projection-cache.md):
он исключает повторную сериализацию неизменённых сообщений, а индексы исключают
повторный поиск самих чатов. Начальное построение индекса и каждый полный проход
`_persist` всё ещё зависят от числа записей. Сам по себе успешный синтетический
замер не подтверждает отсутствие всех фризов в установленном окне; для этого
используется [штатный журнал производительности](../web/chat-performance-logging.md).
