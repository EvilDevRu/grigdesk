# Приоритет npm при установке и обновлении CLI

Карточка `/api/providers` и `ProviderInstallService` используют общий
`providerInstall/commands.ts`. Resolver ищет исполняемый файл npm в абсолютных каталогах
PATH сервера и передаёт его путь адаптеру через `installation(config, { npm })`.
Пустые и относительные каталоги, каталог с именем npm и файл без права запуска не подходят.
Собственный npm packaged runtime исключён, пользовательский npm далее в PATH допускается.
Перед стартом доступность проверяется заново; кэш карточки не закрепляет старую команду.

Если npm доступен, Claude, Codex и Kimi объявляют одну команду для установки и обновления:
`npm i -g <пакет>@latest`. Runner получает найденный абсолютный путь npm и отдельный argv.

| Исполнитель | Официальный npm-пакет | Если пользовательского npm нет |
| --- | --- | --- |
| Kimi | `@moonshot-ai/kimi-code` | Прежний официальный `install.sh` для установки и host-обновления |
| Claude | `@anthropic-ai/claude-code` | Прежний native installer для установки, настроенный `claude install latest` для обновления |
| Codex | `@openai/codex` | Прежний `codex update`; первая установка требует npm и выдаёт `npm_missing` |
| DeepSeek, GLM | Не используются для установки runtime из карточки | Управляемая поставка сохраняет отдельные установку и обновление |
| Tripo | CLI не устанавливается | API-провайдер с настройкой ключа |

Официальные способы сверены 24.10.2026:
[Kimi](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/getting-started.html#npm-installation)
требует Node.js от 22.19.0;
[Claude](https://code.claude.com/docs/en/setup#install-with-npm) — от 22;
[OpenAI](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)
документирует `npm install -g @openai/codex@latest` для установки и обновления.

Отсутствие npm выбирает прежний способ до запуска. Ошибка уже выбранной npm-команды
не переключает установку на другой installer; сетевые повторы работают в прежнем бюджете.
Вход в аккаунт остаётся отдельным действием. Contained Kimi по-прежнему запрещает update,
DeepSeek/GLM по-прежнему запрещают установку и update через общую карточку.

После успешной npm-команды сервис узнаёт её global prefix, проверяет новую копию через
адаптер и сохраняет её абсолютный путь как bin исполнителя в `.env`, config и окружении
текущего сервера. Поэтому закреплённая старая native-копия больше не оставляет отказ
`version_stale` после установки свежего npm-пакета. Подробности —
[подключение npm-копии](provider-install-npm-binding.md).
Порядок PATH и файлы прежней копии не меняются. Неизвестная latest сохраняет прежний
контракт проверки версии; при известной latest проверяется новая копия.

Проверки: `tests/server/providers-install-npm.test.js` использует реальные декларации трёх
адаптеров и fake probe/runner. Проверяются карточка и job, обе операции, прежние команды при
отсутствующем/неисполняемом npm, исключение packaged npm и изменение PATH между карточкой и
стартом. Регрессия с настоящим probe Kimi и временными CLI проверяет переход с native
на npm и сохранение прежнего bin при отказе. Настоящие пакеты на машину тесты не устанавливают.
