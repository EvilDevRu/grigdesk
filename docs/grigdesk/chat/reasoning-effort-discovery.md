# Эффорты обнаруживаются динамически

- **Эффорты обнаруживаются динамически:** Claude — парсингом `claude --help` и безопасными
  пробами известных скрытых имён, Codex — полем
  `supportedReasoningEfforts` каждой модели из `model/list`.
  **У Claude ладдер и гейт — разные оси, и путать их нельзя.** `--help` перечисляет ступени,
  которые понимает CLI (имена и порядок), и живой список по-прежнему перебивает устаревший
  сохранённый — это отдельный инвариант `resolveModelEfforts`. Но принимает ступень не каждая
  модель: `--effort xhigh` на Opus 4.6 не игнорируется, а роняет запуск. Кому что доступно,
  объявляет реестр бинаря (`capabilities`: `effort`, `xhigh_effort`, `max_effort`), а применяет
  необязательный метод контракта `modelEfforts(model, ladder, discoveredEfforts)` — вызывается в
  `getModelsRegistry` рядом с `modelFamily`, для правленных руками (`custom`) записей не
  зовётся. Имена гейтованных ступеней нигде не зашиты: `effortGates` собирается по всему
  реестру из суффикса `_effort`, поэтому новая ступень не потребует правки под каждую модель.
  Модель без возможности `effort` (Haiku 4.5, Sonnet 4.5) получает пустой список — слайдера нет.

- **Происхождение списка передаётся отдельно от fallback.** Необязательный третий аргумент
  фильтра — результат текущего `executor.efforts` до смешивания с сохранёнными ступенями:
  `readonly string[] | null`. Неизвестный тип и отказ discovery нормализуются в `null`;
  отсутствие аргумента тоже не доказывает свежесть. Адаптеры, которым это не требуется,
  продолжают игнорировать аргумент. Ядро не знает имён скрытых режимов и не ветвится по вендору.

- **[Claude ultracode](claude-ultracode.md) — запрос режима, а не обещание workflow.**
  Известное скрытое имя отображается в базовую `xhigh`; при отсутствии базы в свежей
  справке режим снимается. Скрытая проба требует версии Claude Code без отказа для кандидата
  и явного отказа контрольного имени при той же комбинации `--effort … --version`.
  Публичное имя из справки обходится без проб; режим всегда один и в конце списка.
  Автоматическая модель требует проверенные capabilities, `effort`, разрешённую базу,
  собственный гейт режима, если он объявлен, и свежее подтверждение CLI.
  Неизвестные capabilities снимают только известные режимы; `effortUnverified` снимает
  все ступени. При `null` discovery обычный сохранённый fallback сохраняется, скрытый
  режим из старого снимка удаляется. `custom` остаётся явным ручным исключением.
  Runtime-фильтр не меняет сохранённую форму каталога и не требует миграции schema.

- **Обновление CLI — кнопкой в настройках → «Исполнители»** (`POST /api/providers/:id/update`,
  команда — свойство исполнителя `updateCmd`: `claude install latest`, `codex update`). После обновления
  сбрасываются оба кэша, каталог моделей перечитывается у обновлённого исполнителя.
