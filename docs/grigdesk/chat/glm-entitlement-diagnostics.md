# Подписка GLM и доступ к модельному шлюзу

Читай, если квоты доступны, а запрос модели получает отказ. Наличие активной подписки
и успешный опрос usage не доказывают, что конкретный ключ может оплачивать запрос модели.
Тип ключа проверяется по [правилам ключей](glm-key-types.md).

## Разделение причин

- Отказ admission GrigDesk возникает до модельного запроса; его основание — metadata
  ELF, режим и отпечаток совместимости. См. [бинарный допуск](glm-binary-admission.md).
- Ответ шлюза проверяется по HTTP-статусу и коду в очищенном теле. Один `429` не различает
  отказ баланса, квоты и частоты запросов.
- Метаданные подписки показывают её состояние, но не заменяют классификацию ключа
  и не доказывают применение плана конкретным модельным маршрутом.

Внутренние адреса кабинета не являются стабильным публичным API. Диагностика сохраняет
только необходимые признаки состояния, без аккаунтов, заказов, почты и ключей.
Неуспешное чтение метаданных не означает недействительную подписку.

## Проверка официальным клиентом

При явно разрешённой живой проверке можно сравнить один запрос с тем же режимом и ключом
в изолированном официальном клиенте. Нужно учитывать повторы клиента и фактический адрес.
Одинаковый отказ вне GrigDesk исключает его admission как причину этого HTTP-ответа,
но не устанавливает тип ключа или причину отказа у провайдера.

Успех другого ключа локализует различие, но не доказывает категорию прежнего ключа.
Для обращения к провайдеру сведения о времени и запросе сохраняются локально с очищенным
телом ошибки; секреты не передаются. [Баланс и каталог](glm-api-control.md) проверяют
другие границы и не заменяют успешный модельный запрос или [полный smoke](glm-coding-plan-smoke.md).
