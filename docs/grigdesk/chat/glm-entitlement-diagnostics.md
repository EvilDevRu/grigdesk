# Проверка подписки GLM отдельно от модельного шлюза

## Состояние подписки

Кабинет Z.ai читает `GET https://api.z.ai/api/biz/subscription/list`. В диагностике
28.10.2026 этот адрес принял ключ режима в `authorization` без `Bearer` и вернул
конверт с HTTP 200 и `code: 200`. Проверяли только чтение; настройки, оплату и ключи
не меняли. Адрес взят из публичного JavaScript кабинета, а не из документированного
контракта модельного API, поэтому его доступность не гарантирована.

Для диагностики достаточно разрешённой проекции записи:

| Поле | Наблюдённое значение | Вывод |
| --- | --- | --- |
| `productName` | `GLM Coding Pro` | выбран продукт Pro |
| `status` | `VALID` | подписка действительна |
| `paymentType` | `SUCCESS` | API сообщает успешную оплату |
| `inCurrentPeriod` | `true` | действует текущий период |
| `banStatus` | `0` | блокировка аккаунта в записи не отмечена |

Идентификаторы аккаунта, заказы, почта и ключи в проекцию не входят. Квоты повторно
не опрашивались. Эти поля исключают версию неоплаченного текущего периода по ответу
кабинета, но не доказывают тип API-ключа и применение плана модельным шлюзом.

## Два модельных маршрута

В 11:15 UTC того же дня сделано по одному запросу `glm-5.3` с пользовательским `ping`
и `max_tokens: 16`, без повторов:

| Маршрут | Авторизация | Результат |
| --- | --- | --- |
| `POST /api/coding/paas/v4/chat/completions` | `Authorization: Bearer <ключ>` | HTTP 429, `error.code: 1113` |
| `POST /api/anthropic/v1/messages` | `x-api-key: <ключ>`, `anthropic-version: 2023-06-01` | HTTP 429, `error.code: 1113` |

Оба адреса опубликованы в [Quick Start Z.ai](https://docs.z.ai/devpack/quick-start).
Ответ OpenAI сохранил прежний текст `Insufficient balance or no resource package. Please recharge.`
Ответ Anthropic содержал тот же текст в обрамлении кода и идентификатора запроса.
Полные тела и диагностические заголовки сохранены локально; Anthropic дал `request_id`
и заголовок `request-id`, оба маршрута — `x-log-id`. В общей документации их значения
не публикуются. Перед записью маскируются секреты; проверка артефактов прошла.

Отказ воспроизводится вне GrigDesk и без запуска ELF. Это подтверждает отказ шлюза Z.ai
и исключает серверный admission GrigDesk как причину именно этих HTTP-ответов.
Успешная оплата сама по себе не различает неправильный тип ключа и сбой применения
плана; см. [раздельные типы ключей](glm-key-types.md).

## Предел чтения метаданных

`zaiUserInfo` возвращает контактные поля и идентификаторы аккаунта, но не тип ключа
и не список организаций/проектов. Сырые значения этих полей не сохранялись.
Адрес новой страницы кабинета `/biz/customer/getCustomerInfo` с этим API-ключом
и формой `Bearer` вернул HTTP 403 без JSON. Поэтому получить организацию и проект
для чтения классификации из `/biz/v1/organization/.../projects/.../api_keys` не удалось.
Браузерная авторизация кабинета и API-ключ не считались взаимозаменяемыми.

Тип текущего ключа остаётся не установлен. Следующий необходимый факт — категория
этого ключа в ЛК: Personal Coding Plan, Compatible или Standard. Если категория
плановая, для разбора на стороне Z.ai уже подготовлены статус оплаты, точные запросы,
время, полные ответы и `request_id`; автоматически поддержке ничего не отправлялось.
Окончательная причина `1113` до этой сверки не установлена.

Политика режима, admission, smoke, окно доступа и `usage.ts` в этой диагностике
не менялись; новый live smoke тогда не запускался. Coding Plan после этой диагностики оставался закрытым.

[Дополнительный контроль без ЛК](glm-api-control.md) установил нулевой денежный
API-баланс и доступность каталога. Запрос бесплатной модели завершился таймаутом
без HTTP-ответа. Эти проверки не определили категорию ключа и не подтвердили
окончательную причину отказа.

## Проверка официальным клиентом

28.10.2026 официальный Claude Code 2.1.312 установлен только в отдельном каталоге
артефактов и запущен с пустыми HOME/рабочей папкой, без инструментов, MCP и сохранения
сессии. Тот же ключ передан процессу через окружение, настройки приложения не менялись.
Использован опубликованный [маршрут Claude Code для Z.ai](https://docs.z.ai/devpack/tool/claude).

Диагностический посредник переслал на Z.ai ровно один исходный запрос клиента:
`glm-5.3`, `max_tokens: 64`, ноль инструментов, фактический user-agent
`claude-cli/2.1.312 (external, sdk-cli)`. Провайдер вернул HTTP 429 и код `1113`.
Полное тело сохранено с маскированием секретов. Семь повторов клиента получили
локально сохранённый отказ; новых запросов провайдеру они не создавали. После
75 секунд диагностический процесс клиента остановлен своим таймером.

Это подтверждает воспроизведение отказа на запросе официального клиента в проверенной
конфигурации. Оно не устанавливает тип ключа и не подтверждает исправность привязки
подписки. Изменением GrigDesk такой ответ провайдера не был устранён.

После последующей замены ключа [новые прямые запросы и полный live smoke](glm-coding-plan-smoke.md)
прошли успешно, и Coding Plan получил допуск. Это не устанавливает тип прежнего ключа
и не объясняет окончательно его `1113`; выводы этого документа относятся к прежнему ключу.
