# Алиасы CLI отдельными пунктами НЕ показываются

- **Алиасы CLI отдельными пунктами НЕ показываются.** `opus`/`sonnet`/`haiku`, а также
  rollout-алиасы Codex вроде `codex-auto-review` — та же модель под другим
  именем: два пункта на одно и то же путают. Алиас привязан к модели, в
  которую CLI его резолвит, полем `aliases: ['opus']` у самой свежей версии семейства. Сохранённый
  где-то выбор `opus` резолвится в неё и в UI (`providers.resolveModelId` — селект и отправка), и на
  сервере (`modelInfo` ищет и по `aliases`). После обновления бинаря тот же старый выбор сам станет
  Opus 5 — смысл алиаса сохранён, хардкода нет.
  **Но `aliases` — плавающие CLI/legacy-имена, schema-2 `modelRef` по ним НЕ разрешается:**
  versioned ссылка `{provider:'claude', model:'opus'}` притворялась бы закреплённой, хотя
  после обновления переехала бы на другую версию. Для снятых с каталога ТОЧНЫХ id есть
  отдельное поле `modelRefAliases`; resolver проверяет его только внутри уже указанного
  provider-а и возвращает канонический `model.id`.
  **Таким versioned-алиасом стал вариант `[1m]` у модели со ВСТРОЕННЫМ миллионом** (`native_1m`):
  окно у `claude-opus-5` и `claude-opus-5[1m]` одно, поэтому два пункта в селекте — два
  одинаковых выбора. Запись остаётся одна, а снятый exact id лежит в `modelRefAliases`.
  Мигратор истории (`migrateChatModelRecord`) и миграция дефолта тем самым переписывают старый
  `{provider:'claude', model:'claude-opus-5[1m]'}` в базовый id при ближайшем чтении/записи;
  без этого уже versioned чат после сворачивания пункта получал бы `unknown_model`.
  У модели, которой суффикс окно РЕАЛЬНО поднимает (Opus 4.6, Sonnet 4.6: 200k → 1M),
  вариант остаётся отдельным пунктом — решает `context.native_1m` из реестра, а не список
  в коде. При `CLAUDE_CODE_DISABLE_1M_CONTEXT` исключение шире: все `[1m]`-пункты скрыты,
  а их versioned id мигрируют через `modelRefAliases` в соответствующие базовые
  200k-модели.

- **Модель нового чата не фиксируется при создании**: в сессии пусто = «по умолчанию», конкретный id
  берётся из реестра при показе и отправке (`providers.defaultModelId` — сильнейшая не-`extra` у
  доступного исполнителя). Фиксировать при создании нельзя: реестр к тому моменту может быть ещё не
  загружен (из-за этого новый чат открывался на алиасе `opus`).
