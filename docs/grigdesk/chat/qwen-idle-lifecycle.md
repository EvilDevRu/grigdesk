# Qwen Host: уборка после подтверждённого простоя

Qwen Host не ограничен числом сессий. Свободный процесс закрывается после 30 минут
подтверждённого простоя; работа, ожидающие расписания и неизвестное состояние защищают
его. Закрытие процесса сохраняет историю и native sessionId для следующего сообщения.

## Почему одного heartbeat недостаточно

В Qwen Code 0.27.3 `collectActiveWorkHolds()` и `hasRunningBackgroundTasks()`
не перечисляют будущие `CronScheduler.jobs` и `wakeups`. Пустой active-work поэтому
не разрешает завершение процесса. Native `onlyIfUnheld` использует тот же неполный
набор holds и сам по себе также не защищает ожидающий таймер.

## Полный статус внутри выбранного процесса

`qwen/idleBridge.ts` допускает только проверенную npm-поставку 0.27.3 с точным SHA256
ACP-модуля. Под reader launcher готовятся приватные файлы в staging Host. Установка
Qwen не переписывается. Контролируемый Node preload дополняет только закреплённый
ACP-модуль при загрузке; его хеш повторно проверяется в дочернем процессе.

Preload переживает штатный native relaunch до загрузки ACP. После загрузки
`NODE_OPTIONS` и переменная конфигурации моста снимаются: команды, LSP и другие
дочерние программы не наследуют дополнение. Mandatory guard и private-parent nonce
не меняются; новые методы требуют native `privateParentState === 'trusted'`.

Дополнение предоставляет два внутренних ACP-метода:

- `qwen/status/session/grigdesk-idle-status-v1` — полный снимок собственной сессии;
- `qwen/control/session/grigdesk-idle-close-v1` — условное закрытие со свежей проверкой.

Снимок учитывает native holds, активный пользовательский ход, мониторы, будущие cron
и wakeup, очередь cron, ожидающие публикации scheduler, gate-проверки и активную цель.
Причины имеют нейтральные типы и количества; тексты заданий, команд и ключи не передаются.
Для wakeup доступно время будущего срабатывания. Неизвестная структура даёт `unknown`.

Те же дополнительные причины включаются в native holds. Поэтому `onlyIfUnheld`
повторно видит их под native close gate после асинхронных операций, включая запись
истории. Если появилась работа, закрытие отклоняется и gate освобождается. При успехе
история подтверждённо записана; дополнительный запрос модели для auto-memory extract
при автоуборке не запускается. Затем Host launcher подтверждает пустой собственный scope.

## Таймер и гонки

`QwenLiveSession` запрашивает статус каждые 5 секунд с RPC-сроком 3 секунды.
Ошибка, чужая session identity, неизвестная схема и противоречивый снимок дают `unknown`.
Завершение процесса снимает опрос; одновременно выполняется не больше одного запроса.

Общий пул получает `hooks.onActivity` и optional `handle.closeIfIdle` без ветвления
по имени исполнителя. Для keepAlive таймер допускается только по подтверждённому `idle`.
Период считается от первого свободного снимка и не продлевается повторными idle.
Новая работа и сообщение человека обнуляют период. Разрыв подтверждений больше 20 секунд
не засчитывается как простой; после восстановления начинается полный интервал заново.

Перед закрытием пул повторно проверяет свежесть и занятость поколения и резервирует
его в общем `closing`: следующий send ждёт решения. Native проверяет полное состояние
ещё раз. Отказ сохраняет процесс; ошибка scope или неизвестный исход сохраняет запись
и показывает неизвестный статус. Успех записывается причиной «подтверждённый простой».
Прочие исполнители сохраняют прежнюю политику таймеров и обычного пула.

## Интерфейс и совместимость

`GET /api/chat/sessions` передаёт `activity` и `idleAtMs`. Страница процессов
показывает причину удержания, время до wakeup или оставшееся время простоя.
Неизвестное состояние явно приостанавливает автоуборку. Жёсткий лимит числа Qwen
не возвращается, вытеснение по заполнению обычного пула к нему не применяется.

Непроверенная версия или изменённый ACP-файл работают с прежней защитой keepAlive:
автоуборка не получает допуска. Это видно как неподтверждённый статус. После обновления
CLI профиль проверяется заново; версия сама по себе не разрешает патч произвольного
исходника. Для применения серверных изменений нужен ручной перезапуск GrigDesk.

## Проверки

- `qwen-idle-lifecycle.test.js`: виртуальное время, расписание, снятие последней причины,
  свежесть, неизвестный статус, отказ scope, повторный send и гонка закрытия.
- `qwen-idle-bridge.test.js`: неизвестные версии и изменённый исходник не получают допуска.
- `qwen-idle-native.test.js`: настоящий CLI и локальный синтетический API; подтверждённое
  закрытие, продолжение с той же native памятью, будущий wakeup и cron до срабатывания.
- `qwen-native-tools.test.js`: сохранены native Host shell/subagent и запрет SSH.
- `settings-live-sessions.component.test.js`: причины удержания, неизвестный статус и таймер.

Native-проверки требуют Linux user systemd и отдельного app unit, работают с временными
HOME и локальной моделью. Оплаченная модель не использовалась; ручная проверка в основном
приложении остаётся после перезапуска.
