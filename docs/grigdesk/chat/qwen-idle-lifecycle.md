# Qwen Preview.2 Host: состояние процесса и автоуборка

В Preview.2 режим «Хост» сохраняет процесс между сообщениями и освобождает его при
ручном закрытии, сбросе памяти или остановке GrigDesk. Запись о процессе содержит
`activity.state: unknown`. До появления достоверного состояния свободного процесса
автоуборка простоя не применяется. Сессии «Хост» сохраняют `keepAlive` и `limitExempt`.

## Контракт процесса

Preview.2 ACP передаёт `session/update` для вывода внутреннего продолжения. Сборка
не посылает отдельного завершения для этого продолжения и подтверждённого снимка
состояния фоновой работы. Опция автоуборки требует доказательства отсутствия всех
работ и ожидающих таймеров плюс проверки условия на стороне процесса при закрытии.
Режим «Хост» Preview.2 оставляет планировщики и фоновые tools вне разрешённого профиля.

Ручное закрытие проверяет состояние и пустоту своей cgroup в user systemd. После этого
снимается reader и удаляется временный профиль. Локальная native история сохранится
для следующего сообщения, которое откроет новый процесс. [Режим «Хост»](qwen-native-tools.md#режим-хост).

## Проверки

- `qwen-preview-host.test.js` использует настоящий Preview.2 с локальным API и user systemd.
- `qwen-host-lifecycle.test.js` проверяет гонки открытия и повтор закрытия области.
- `qwen-idle-lifecycle.test.js` проверяет общую политику пула виртуальным временем,
  включая отсутствие автоуборки при неизвестном или устаревшем статусе.
