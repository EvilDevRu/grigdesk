# Состояние исполнителя после удаления выбранной копии

Успешное удаление снимает явную привязку к удалённому CLI из config, окружения
процесса и `.env`. Правка файла настроек входит в preview и видна под «Подробности». Возврат к имени
команды позволяет обычному discovery показать оставшуюся копию из пользовательской
оболочки; другие npm/native-копии не удаляются. Если копий больше нет, исполнитель
становится недоступен. Авторизация, настройки и история сохраняются. У Kimi удаляется
только `~/.kimi-code/bin`, остальная `.kimi-code` сохраняется.

Привязка снимается только если её путь принадлежит выбранной установке. Новый
выбор в config, сделанный во время операции, сохраняется. Общий писатель `.env`
сверяет ожидаемое значение под своей очередью; чужая правка файла не затирается.
Ошибка снятия привязки после удаления даёт `needs_attention`, сохраняет сведения
для восстановления и не повторяет удаление при ручном подтверждении.

После мутации перечитываются версии и реестр. Удаление также обновляет каталог
моделей; состояние лимитов учитывает, доступен ли другой CLI после снятия старой
привязки. Наличие capability свежести лимитов не управляет очисткой кэша реестра.

Окно перечитывает карточки при новом финале v2, даже если событие active было
пропущено. Первый снимок сохранённой истории и повтор того же финала не запускают
повторное чтение. Отсутствующий или повреждённый выбранный путь подписывается
«Выбранный в GrigDesk путь недоступен».

Проверки: `provider-lifecycle-service`, `provider-lifecycle-recovery`,
`env-file`, `provider-install-store`, `provider-cli-inventory.component` и
`providers-usage-tick` в соответствующих каталогах `tests/server` и `tests/web`.

Распознанная оставшаяся копия из официального installer получает обычные действия
обновления, переустановки и удаления. Способ установки не меняет подписи карточки:
[действия оставшейся копии](provider-native-after-uninstall.md).
