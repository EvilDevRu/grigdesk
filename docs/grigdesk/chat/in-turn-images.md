# Картинки в уточнении работающему агенту

Картинку можно передать агенту посреди хода, как и текст, — она не ждёт конца хода в
очереди. Возможность объявляет адаптер полем `inTurnInput.images: true`; реестр
провайдеров публикует его в `inTurn.images`. Сейчас его объявляют Codex и Claude.
У Kimi, DeepSeek и GLM поля нет: сообщение с вложением у них по-прежнему уходит в
очередь после текущего хода.

## Путь

Композер отправляет в `POST /api/chat/in-turn` поле `attachments: [{file, name}]` —
имена файлов, уже загруженных через `/api/chat/upload`. Немедленная отправка возможна,
только когда исполнитель объявил картинки, все вложения черновика — картинки и их не
больше `IN_TURN_ATTACHMENT_LIMIT` (10). Иначе та же кнопка ставит сообщение в очередь, а
подсказка называет причину. Текст при картинке может быть пустым.

Сервер проверяет каждый файл тем же правилом, что вложения обычного хода: только
PNG, JPEG, WebP или GIF внутри каталога вложений, без симлинков и выхода по пути. Любой
негодный элемент отклоняет запрос целиком (`400`). Если адаптер картинок не объявил,
ответ — `409 in_turn_unavailable` с причиной `unsupported`. Принятые картинки хранятся в
receipt как `{file, name, url, mime}` — в той же форме, что вложения сообщения истории,
поэтому пузырь уточнения показывает миниатюры и после F5, и в истории. Набор файлов
входит в отпечаток идемпотентности: тот же id с другими картинками — конфликт `409`.

Перед передачей модуль чата заново проверяет файлы: если картинка пропала после приёма,
доставка получает `failed`, а агент — не пустую ссылку. Текст уточнения получает тот же
блок `[Вложения]` с путями, что обычный ход, а порт адаптера — проверенные пути `images`.

## Как картинку получает агент

- **Codex.** `turn/steer` принимает в `input` элементы `localImage` с путём; app-server
  сам читает файл и отдаёт изображение модели. Схема установленного `codex-cli 0.161.0`
  это подтверждает (`codex app-server generate-json-schema`, тип `UserInput`).
- **Claude.** Байты картинки в stream-json не передаются: строка ввода CLI ограничена
  1 МиБ, а обычный скриншот больше. Агент открывает файл инструментом Read по пути из
  блока `[Вложения]`. Без разрешения CLI запрещает Read вне рабочих каталогов, поэтому
  каждый запуск чата получает опцию `attachmentsDir`. Адаптер дописывает правило
  `Read(//<каталог вложений>/**)` в `permissions.allow` настроек `--settings` и сохраняет
  нативные правила. Правило лежит в настройках, а не в `--allowedTools`: путь с пробелом
  там не разрезается. Строгий режим `workspaceAccess` заменяет `permissions` своими и это
  правило не получает.

## Проверено

Офлайн: `tests/server/chat-in-turn-{core,api,history}.test.js`, `codex-in-turn.test.js`,
`claude-in-turn.test.js`, `tests/web/chat-in-turn.component.test.js` и
`tests/web/chat-in-turn-store.test.js`.

Вживую на установленных CLI (синтетическая однотонная красная картинка, цвет в тексте
не назван):

- Codex: `node tests/fixtures/codex-app-server/liveSmoke.mjs <каталог> <codex> image` —
  ответ «картинка красного цвета» пришёл до финала, затем исходная задача завершилась.
- Claude: `claude -p` без правила отклоняет Read картинки вне рабочей папки
  (`permission_denials`); с правилом в `--settings` читает её и называет цвет. Ход через
  адаптер с уточнением посреди `sleep` прочитал картинку без отказов инструментов.
