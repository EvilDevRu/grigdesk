# Проверка installer-хуков npm между версиями CLI

Установка и переустановка npm-исполнителей проходит пропускной пункт
`assertReviewedNpmHooks` (`server/src/lib/providerInstall/npmGraph.ts`): каждый
пакет графа с install/uninstall-хуками или `binding.gyp` требует проверенного
профиля в `server/src/lib/providerInstall/npmReviewedHooks.json`.

Сначала выбирается точный набор `name@reviewedVersion` для проверки: состав и значения
lifecycle-команд и sha256 всех файлов должны совпасть. Повреждённый точный
профиль нельзя обойти профилем другой версии. Если точного профиля нет,
проверяются профили того же имени: новая версия принимается при полностью тех
же командах, наличии всех файлов и совпадении каждого sha256. Наличие
`binding.gyp` также должно соответствовать профилю.

При переносе допуска между версиями дополнительно сверяется состав каталогов
файлов хуков: каждый файл и подкаталог должен быть представлен путями из
`files`. Новый модуль, лишний каталог или ссылка вместо проверенного файла либо
каталога требуют ручной проверки. Корень пакета не считается каталогом хуков:
изменения самого CLI и прочих ресурсов допускаются. Для корневого хука вроде
`install.cjs` проверяются его байты и lifecycle-команды; новый lifecycle-хук
отклоняется независимо от расположения файла.

`graphIdentity` (`npmStrategy.ts`) сравнивает реестровый `dist.integrity` с
профилем только при точном совпадении версии. При допуске по байтам новой версии
её собственный integrity записывается в граф preview. Полный граф, cache и
offline-прогон по-прежнему фиксируются до подтверждения; `start` повторяет
проверку перед записью в пользовательский prefix. Пакет без lifecycle-хуков и
`binding.gyp` профиля не требует.

Изменённые команды, байты или состав каталогов хуков дают
`installer_strategy_unverified` (HTTP 409, в окне — «Способ установки этой версии
не проверен»). Удаление проверяет граф уже установленной копии. Прежний гейт
требовал точной версии всегда: поэтому удаление Kimi 2.3.3 проходило, а установка
свежей 2.4.0 отказывала, хотя хуки не изменились.

Проверено 28.10 на живых пакетах: `@moonshot-ai/kimi-code@2.4.0` и
`@anthropic-ai/claude-code@2.1.312` побайтово совпадают с прежними профилями
(2.3.3 и 2.1.311) по всем файлам хуков, отличаются только версией и integrity.
Обе версии добавлены в список с собственными integrity и проходят гейт;
`@openai/codex@0.165.0` проходит без профиля — в его графе нет install-хуков.

Порядок расширения списка тот же, что в
[прецеденте 2.3.1](provider-install-stale-binding.md): скачать пакет
`--ignore-scripts` в изолированный prefix, сверить sha256 каждого файла хука с
проверенным профилем прошлой версии и `dist.integrity` с реестром. Для неизменных
хуков отдельная запись каждой версии больше не обязательна; при расхождении
байтов или команд нужен ручной обзор скриптов и новый проверенный профиль.

Проверки: `provider-install-npm-graph.test.js` покрывает перенос допуска, приоритет
точного профиля, изменённый байт, команду, новый модуль, `binding.gyp`, отсутствие
файла и ссылки. `provider-install-npm-strategy.test.js` проверяет разные integrity
между версиями, прежнюю строгость точной версии и отказ до mutation, если в
offline-прогоне появился непроверенный модуль.
