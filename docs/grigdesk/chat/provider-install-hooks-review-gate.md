# Свежая версия CLI не проходит проверку installer-хуков

Установка и переустановка npm-исполнителей проходит пропускной пункт
`assertReviewedNpmHooks` (`server/src/lib/providerInstall/npmGraph.ts`): каждый
пакет графа с install-хуками или `binding.gyp` требует точного профиля
`name@reviewedVersion` в `server/src/lib/providerInstall/npmReviewedHooks.json`,
побайтово совпадающими файлами хуков и тем же `dist.integrity` tarball. Профиль
привязан к версии: вышедшая в npm новая версия CLI с теми же байтами хуков всё
равно отклоняется кодом `installer_strategy_unverified` (HTTP 409, в окне —
«Способ установки этой версии не проверен»). Удаление при этом проходит: гейт
проверяет граф установленной копии, чья версия уже внесена в список.

Проверено 28.10 на живых пакетах: `@moonshot-ai/kimi-code@2.4.0` и
`@anthropic-ai/claude-code@2.1.312` побайтово совпадают с прежними профилями
(2.3.3 и 2.1.311) по всем файлам хуков, отличаются только версией и integrity.
Сухой прогон расширенного списка эти версии пропускает; `@openai/codex@0.165.0`
проходит без профиля — в его графе нет install-хуков.

Порядок расширения списка тот же, что в
[прецеденте 2.3.1](provider-install-stale-binding.md): скачать пакет
`--ignore-scripts` в изолированный prefix, сверить sha256 каждого файла хука с
проверенным профилем прошлой версии и `dist.integrity` с реестром; при
расхождении байтов версия не вносится, пока человек не проверит скрипты.
Прогон проверки сохранён в `~/.grigdesk/artifacts/kimi-reinstall/`.
