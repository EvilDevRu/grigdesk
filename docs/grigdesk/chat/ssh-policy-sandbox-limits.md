# Запрет прямого SSH — рубеж кооперативного агента, не same-uid sandbox

`blockDirectSsh` закрывает штатные попытки `ssh`/`slogin`, `scp`, `sftp`, `autossh`,
`ssh-copy-id`, `sshpass` с SSH-клиентом и удалённый `rsync`. У Claude, Codex и DeepSeek это
server-owned command-hook; режим прав Bash
независим и не отменяет запрет, включая `dontAsk` и `bypassPermissions`. Kimi contained
держит сетевую границу, а Kimi host при включённой настройке вообще не начинает ход.

Это защита от прямого действия кооперативного агента, а не от намеренного обхода процессом
того же uid. Обфускация вроде `base64 | sh`, собственный SSH-клиент или вложенный запуск
из разрешённой программы могут пройти мимо matcher. `SSH_AUTH_SOCK` намеренно не очищается,
а Git по SSH не блокируется: удаление сокета не закрывает парольный вход, зато ломает
обычный `git push`. Уже начатая команда ретроактивно не отзывается.

После подтверждённого выключения запрета прямые SSH-команды получают обычные права
процесса GrigDesk. Это не будущий SSH-инструмент: отдельного подтверждения команды и его
журнала не будет. Старый PWA не знает диалога, поэтому сервер отвечает ему
`confirmation_required`; нужно обновить web-бандл, а не обходить guard новой ручкой.

Конфликт с пользовательскими правилами Claude проверен установленным CLI без внешней сети:
временные `HOME` и `CLAUDE_CONFIG_DIR` содержали синтетический `permissions.deny`, а
GrigDesk передал дополнительный `--settings` со своим hook и нативным deny. В режиме
`bypassPermissions` пользовательский deny сохранился, оба источника запрета сработали,
ни один marker-процесс не запустился. Поэтому GrigDesk не пишет собственный массив
`permissions.deny` и не отменяет молча пользовательские deny-правила.

У DeepSeek command-hook исполняет плагин DSH `hooks-claude-code`, и его канал не закрывается
при сбое самого hook. Блокирует только exit 2; exit с другим кодом, смерть по сигналу,
невозможность запуска и истечение `timeout` (в профиле — 5 с) считаются неблокирующей ошибкой,
и ход продолжается. Нечитаемый файл hooks даёт лишь предупреждение «no hooks registered».
Под перегрузкой машины запрет SSH/БД у DeepSeek поэтому может пропустить команду. Проверено
по исходникам вендоренного DSH (`hook-protocol` `runner.ts`, `codec.ts`), на сборке не запускалось.
