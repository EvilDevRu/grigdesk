# Веб-поиск и чтение страниц GLM

Политика чата `grigdesk-glm-policy-v4` и политика этапов
`grigdesk-glm-factory-policy-v4` разрешают штатные инструменты Harness по точному имени:

- `web_search` — тип действия `search`;
- `web_fetch` — тип действия `read`.

Оба имени входят в общий `GLM_NATIVE_TOOLS`. Чат проверяет их через native gate,
ACP и Factory — через прежний hook. Разрешение действует в обоих файловых режимах
Factory; оно не меняет файловую границу, запреты прямого SSH/БД и состав MCP.
Неизвестные имена и варианты вроде `web_search_extra` остаются запрещены.

## Провайдеры и сеть

Строки `web`, `web-search-deepseek`, `web-fetch-http` уже входят в профиль запуска;
изменение списка разрешений не добавляет новый поисковый backend.
Штатный `web_search` использует `deepseek-official`: отдельный запрос к
Anthropic-совместимому Messages API DeepSeek с ключом `DEEPSEEK_API_KEY`.
Allowlist окружения GLM передаёт только ключ его маршрута
`GRIGDESK_GLM_ROUTE_KEY`, поэтому разрешение инструмента само по себе не обеспечивает
поисковые credentials. Ключ Z.ai не становится ключом поиска DeepSeek; отсутствие
ключа провайдера возвращается модели как ошибка инструмента.

`web_fetch` анонимно читает публичный HTTP(S) через штатный `http` provider.
Ограничения Harness на адреса, редиректы, объём и таймаут сохраняются; в частности,
разрешённый вызов к loopback не достигает локального HTTP-сервера.
Содержимое страниц остаётся недоверенными данными.

## Ревизия и поставка

Профиль остаётся `grigdesk-glm-profile-v3`, меняется ревизия политики. Требования
`server/deepseek-host-contract.json` и producer `deepseek/compatibility/glm.json`
синхронизированы с v4; старые записи admission не переносятся. Для применения нужны
новая поставка DSH, успешная живая проверка с `--admit`, включение допуска в metadata
следующей сборки и обновлённый сервер. До этого обычный запуск с несовместимым ELF
или без допуска закрыт прежними проверками. Сам агент сервер не перезапускает.

Проверки: `glm-contract`, `glm-policy`, `glm-factory-policy` и `metadata` сверяют
точный набор, типы, настоящий hook и ревизии. `glm-vendored-policy` проверяет
разрешающие proof native gate и сохранение запрета loopback на настоящем DSH
с синтетической моделью; эта проверка не выдаёт живой допуск выпуска.
