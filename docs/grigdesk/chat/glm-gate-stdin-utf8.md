# GLM: повреждение UTF-8 при чтении stdin проверки инструментов

## Симптом и причина

До исправления длинный вызов `write` с русским текстом мог завершить весь ход сообщением
«Обязательная проверка GLM отказала; ход остановлен». Размер сам по себе не запрещён:
ошибка зависит от того, попала ли граница блока pipe внутрь многобайтного символа.

В `server/scripts/glmToolPolicyHook.mts`, функция `stdin()`, каждый Buffer отдельно
превращался в строку через `String(chunk)`. Незавершённый UTF-8 символ на границе
блоков заменялся на U+FFFD. Склейка строк уже не восстанавливала исходные байты.
JSON мог оставаться корректным, но SHA-256 разобранных аргументов переставал совпадать
с привязкой вызова. Helper возвращал exit 2 с причиной
«аргументы native gate не совпали» до исполнения инструмента.

`deepseek/src/host/glmGate.mjs` воспринимает ненулевой exit как поломку проверки,
пишет `grigdesk/glm-policy-error` и отменяет дерево. Деталь stderr в это событие
не переносится; `server/src/lib/glm/nativeGuard.ts` показывает общую ошибку.
Это отказ инфраструктуры проверки, а не решение политики запретить конкретный файл.

## Исправление и проверки

`stdin()` использует стандартный `StringDecoder('utf8')`: незаконченный символ
сохраняется между блоками, после EOF вызывается `decoder.end()`. Ограничение 4 МиБ
проверяется по накопленному количеству исходных байтов до их декодирования.
Проверки policy, binding и SHA-256 остаются прежними. Ревизия профиля и формат
журнала не меняются; исправление не требует сброса памяти разговора.

Причина подтверждена изолированным запуском прежнего helper без выполнения `write` и без сети:

1. Подготовить валидные policy, binding и JSON аргументов с многобайтным текстом;
   вычислить `policyHash` и `sha256` через `glmGateHash`.
2. Передать JSON в stdin двумя записями с паузой, разрезав UTF-8 символ между байтами.
3. Получить exit 2 и несовпадение аргументов. При независимом декодировании блоков
   появляются символы U+FFFD, которых не было в исходном тексте.
4. Контроль с теми же аргументами, представленными через ASCII `\uXXXX`, проходит.
   Копия helper с `process.stdin.setEncoding('utf8')` перед чтением также проходит
   исходный разрез: decoder сохраняет незаконченный символ между блоками.

На длинном входе воспроизводится и естественное разбиение pipe; размер блока
не является контрактом и не должен закрепляться как допустимый размер документа.

Регрессия `tests/server/glm-policy-stdin.test.js` передаёт заданные блоки Buffer
через stdin настоящего entry. Для исходника и собранного `glm-tool-policy-hook.mjs`
проверяются все внутренние разрезы 2-, 3- и 4-байтовых символов длинного `write`,
хэш legacy hook, допуск ровно 4 МиБ, отказ на следующий байт и несовпадающий хэш.
На прежнем helper проверки UTF-8 и legacy-хэша падают; после исправления проходят.

Дополнительно пройдены `glm-policy`, `glm-gate-protocol`, `glm-factory-policy`
и `server-binary-hooks`. Это проверка исходников и собранных helper-ов, без платного
запроса к модели и без обновления работающего приложения. В установленной поставке
helper входит в серверный пакет; для применения нужна поставка с исправлением.

## Сохранность результата

Вызов остаётся в native-журнале как `tool/call`, затем идут ошибка проверки,
ошибочный `tool/result` и отмена хода. Если `write` остановлен на этой проверке,
его тело не исполнялось. С разрешения человека подготовленное содержимое можно
извлечь из аргументов вызова в отдельный артефакт. Извлечённый текст остаётся
черновиком: наличие содержимого в журнале не доказывает завершение его ревью.

После применения исправления можно отправить новое сообщение в тот же разговор.
Журнал прежнего вызова сохраняется; автоматический повтор операции не выполняется.
