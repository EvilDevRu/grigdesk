# Восстановление сохранённых мобильных ходов

При чтении истории и фоновой сверке `MobileHistory` материализует ранее принятые ходы
с меткой `mobileOwner`. Реплика и ответ связываются через `turnId`. Итог подтверждается
после устойчивой записи журнала и истории. При отказе записи файл pending остаётся
до следующей сверки. Восстановление не запускает исполнителя повторно.

Обычный HTTP-запрос не назначает `mobileOwner`. Устаревший PUT сохраняет канонические
реплики. Очистка поднимает эпоху, а удаление чата оставляет tombstone, поэтому поздний
итог не восстанавливает прежнюю ленту.

Прямые тесты `tests/server/mobile-history.test.js` проверяют материализацию и ACK,
отказы записи, эпоху, дедупликацию, метаданные сессии и завершённые блоки.
Общий CAS остановки хода проверяет `tests/server/mobile-chat-actions.test.js`.
