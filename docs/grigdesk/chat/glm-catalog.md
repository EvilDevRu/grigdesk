# Каталог моделей GLM и уровни рассуждения

Каталог GLM читает настоящий ACP-процесс той же generation DSH: свой home каталога
(`<корень homes>/<identity[:16]>/catalog`), пустой проект, без проектных MCP и без prompt —
модельных запросов нет. `session/new` даёт модели, уровни каждой модели читаются после
`session/set_config_option` её выбора. Кэш, TTL и сохранение прежнего каталога при сбое —
у общего реестра моделей; своего кэша у адаптера нет. `catalogLive: false`, ключ кэша —
identity совместимости, режим и отпечаток ключа.

- В каталоге только маршрут `zai`; id модели — JSON-пара `["zai","<модель>"]`.
- Уровни модели — прочитанный список без пустого «Provider default» (GLM всегда отправляет
  уровень); список из одного значения превращается в пустой — выбора нет.
- glm-4.7 и glm-5-turbo не передают `reasoning_effort` на wire: все их уровни давали одно и то
  же `thinking: enabled`. Маршрут задаёт им `modelOverrides` с единственным уровнем `high`,
  поэтому выбора уровня у них нет. glm-5.2 — `off, high, max`; glm-5.3 — `low, high, max`.
- Без допущенного режима, ключа или при несовпавшей identity сборки `catalog()` возвращает
  `null`, процесс не запускается.
- Выбор модели и уровня в ходе подтверждает сам DSH: неизвестная модель или уровень дают отказ
  `session/selectModel` до prompt — `glm_model_mismatch` / `glm_effort_mismatch`.
