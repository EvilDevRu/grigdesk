# Счёт и лимиты GLM (Z.ai)

Карточка GLM показывает состояние по выбранному режиму доступа (`GRIGDESK_GLM_API_MODE`); режим и
ключ читаются из живого окружения службы, поэтому окно «Ключи доступа» меняет их без перезапуска.

## Откуда данные

Открытого API баланса у Z.ai нет. Личный кабинет `z.ai/manage-apikey/billing` берёт данные из
адресов `https://api.z.ai/api/...`, и они принимают ключ API в заголовке `authorization` как есть
(без `Bearer`); запросы бесплатные и только читают:

| Режим | Адрес | Что даёт |
| --- | --- | --- |
| `api` | `GET biz/customerService/zaiUserInfo` | номер клиента (`customerNumber`) |
| `api` | `POST platform-charge-zai/business/accountBalance` с `{ customerId }` | `totalBalance` и `accountList`: тип 10 — наличные, 11 — бонус, 12 — кредит |
| `coding-plan` | `GET monitor/usage/quota/limit` | `level` и `limits`: `TOKENS_LIMIT` unit 3/number 5 — окно 5 часов, unit 6/number 1 — неделя, `TIME_LIMIT` — MCP за месяц; `percentage`, `nextResetTime` в мс |

Без номера клиента адрес баланса отвечает «The current user can only view their own data!».
Адрес квот для ключа без подписки отвечает кодом 500 «当前用户不存在coding plan». Ответы — конверт
`{ code, msg, data }`: успех только при `code: 200`.

## Что видит человек

- `api`: ресурс «Баланс USD» (итог, наличные, бонус, кредит при наличии), ссылка «Пополнить счёт» и
  прогноз по снимкам баланса — общий с DeepSeek; снимки лежат в `balance-log.json` корня private
  homes GLM (0600). Нулевой итог подсвечен как исчерпанный.
- `coding-plan`: полоски «5 часов», «Неделя», «MCP за месяц» со временем сброса и ресурс уровня
  подписки со ссылкой на её страницу. После уровня идёт [ресурс «Тариф»](glm-tariff.md): фаза,
  местное время следующей смены, расписание и обе цены пика. Разбор квот сверен с публичными
  утилитами, а не с живой подпиской.
- Номер клиента и почта из ответа кабинета наружу не выходят.

## Сбои

Сеть до Z.ai рвёт TLS-рукопожатие: сетевой срыв повторяется сразу, до восьми попыток; ответ
сервера не повторяется. 401/403 — `auth_required`, 429 — `rate_limited`, конверт не 200 или ответ без
суммы — `unavailable` со словом Z.ai. Адреса внутренние: их смена даёт «недоступно», а не ноль.
Общий модуль usage при пустом ответе держит прежние данные с пометкой давности.

Сторож тарифа отдельно читает публичные Markdown-страницы Z.ai без ключа: раз в сутки, после
сетевого отказа — через час для отказавшего источника. Подтверждённое изменение часов, дней
или расходов делает «Тариф» бедой; недоступность, неразобранная страница и сверка старше недели
остаются в пояснении настроек. Сбой сторожа или записи его снимка не отменяет полученные квоты.
Источники окон и расходов: [обзор Coding Plan](https://docs.z.ai/devpack/overview) и
[обновление от 30.07.2026](https://docs.z.ai/devpack/notice/usage-revision), проверено 21.10.2026.


## Отсутствующий процент

Окна `TOKENS_LIMIT` и `TIME_LIMIT` без конечного неотрицательного `percentage`
пропускаются. `null`, пустая строка, boolean и строки `NaN`/`Infinity` не означают
свободную квоту. Явный ноль сохраняется; непустые числовые строки принимаются.
Общая нормализация сохраняет сотые процента и ограничивает верхнюю границу 100.
Ресурс тарифа, месячные окна MCP и денежные ресурсы от этого не меняют единицы.
