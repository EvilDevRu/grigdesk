# Qwen Code: границы подключения и внешние источники

GrigDesk запускает проверенный нативный Qwen Code 1.0.0-preview.2 на Linux x64 через
стандартный ACP по stdio. Карточка ставит закреплённый ELF в папку данных.
[Поставка, установка и квоты](qwen-preview-runtime.md).

## Чат и конвейер

Чат получает адаптер из `server/src/lib/executors/` через `getProviderAdapters`.
Наличие метода `run` и универсального типа определяет допуск к чатам. Go Factory
использует свой runner и передаёт тот же закреплённый CLI в совместимый ACP-процесс.
Метаданные модели и запись результата фабрики проверяются отдельно от чата.
[Границы выбора раннера](../pipeline/runner-selection-boundaries.md).

В `factoryRouteCli.ts` запуск через systemd передаёт доступ через отдельный
`EnvironmentFile`. При запуске без systemd ключ берётся из окружения. При обоих
способах модельный ключ остаётся на стороне одного локального шлюза GrigDesk.

## Доступ и живой каталог

GrigDesk использует модельные API-ключи. Адаптер объявляет `DASHSCOPE_API_KEY`
и проверенные `envKey` из `modelProviders`. Выбор сервиса и региона действует
на адрес, которому разрешено отправлять ключ. Запросы каталога и модели отклоняют
переадресацию. Публичные ответы содержат только маскированное состояние ключа.
[Правило подключения](qwen-integration-policy.md).

Явный `modelProviders` из настроек CLI имеет приоритет. Источник проекта
определён `config.rootDir`, а не папкой произвольного чата. Файлы читаются
JSONC-парсером и входят в fingerprint вместе с состоянием доступа. Пустая явная
конфигурация или повреждённый файл показывают ошибку источника.

Без явного источника `qwen/discovery.ts` запрашивает `GET <baseUrl>/models`
выбранного OpenAI-compatible сервиса. Действие использует `isolatedFetch`
с ограничением времени и размера. Пустой и неверный каталоги, HTTP-ошибки и
отсутствующий ключ видны в карточке. Подписка QwenCloud Individual/Team
использует выбор QwenCloud Token Plan, отдельный от Alibaba Coding Plan.

Одинаковые bare id разных маршрутов сохраняются отдельно. Модели без поддержки
текстового чата доступны в полном каталоге с причиной. Краткий выбор отбирает
чатовые модели по данным API и известной модальности. Отказ одного доступа
помечается для его fingerprint. Успешное считывание каталога проверяет только
доступ к списку. Авторизованная генерация владельца подтверждается отдельным ходом.

## Модель и сессия

Отдельное создание ACP-сессии подтверждает запуск выбранного Preview.2.
Список для интерфейса строится из живого снимка настроек. CLI сообщает только
текущий native id `<provider>/<model>` в `configOptions`. GrigDesk сверяет id
запрошенного маршрута до отправки `session/prompt` и сохраняет подтверждённую
модель в результате. Опциональное окно каталога берётся из данного маршрутом
`generationConfig.contextWindowSize`. Оно не проверяет предел реального запроса.

Каталог Preview.2 не объявляет неподтверждённых уровней reasoning. Некорректный
выбор отклоняется до оплачиваемого вызова. Память зависит от чата, физических
рабочих корней и identity доступа. Callback сохранения sessionId завершается
до prompt. Дельты replay не публикуются новым ответом. Вложения передаются
ACP-байтами после проверки пути, формата и размера.
[Контракт изображений](qwen-image-input.md).

Запрос `session/prompt` живёт до результата хода с отдельным аварийным пределом
24 часа. Отмена завершает свой процесс или прерывает свой prompt в режиме «Хост».
Терминальные статусы инструмента и результаты сохраняются с одинаковым callId.
[Срок ожидания](qwen-prompt-lifetime.md), [блоки потока](qwen-stream-blocks.md).

## Допуск файлов и инструментов

В обоих режимах GrigDesk запускает проверенный inode ELF через bwrap с
управляемым read-only профилем. Он запрашивает допуск через
`session/request_permission` и проверяет native имя инструмента, аргументы,
сессию, физические пути, состояние отмены и SSH до выдачи разрешения.
`.env` и `.qwen` маскируются в выданных рабочих корнях, включая внутри
символьных ссылок. Управляемый профиль отключает автоматические hooks
и разрешает только выданные MCP. Ранний выход bwrap показывает очищенную причину,
после завершения процесса освобождается reader.

Режим «Хост» требует явного согласия, настройки живых процессов и отдельной
пользовательской области systemd. Он открывает доступ к файлам и службам
пользователя и сохраняет обязательную проверку инструментов. Память изолирована
от обычного профиля. Factory и model-only не получают этот доступ.
[Инструменты и управление областью «Хост»](qwen-native-tools.md#режим-хост).

## Проверка

Нативные тесты получают абсолютный путь к проверенному ELF из
`GRIGDESK_QWEN_BIN`. Нужен работающий Linux bwrap. Для реальной проверки «Хоста»
тесты дополнительно запускаются в своей пользовательской systemd scope с
`GRIGDESK_TEST_QWEN_SESSION_BUS`. Генерация направлена только на синтетический
loopback API. Профильный набор проверяет установку из оригинального архива,
чат, Go Factory, разрешения, запреты, отмену, память и результаты инструментов.
Реальная подписка и её остаток не подтверждены.
