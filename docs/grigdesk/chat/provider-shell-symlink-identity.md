# Разные ссылки на один CLI в двух формах Bash

`userCliEnvironment` сравнивает выбор `node`, `npm` и имени исполнителя в обычном
интерактивном Bash (`-ic`) и интерактивном login Bash (`-lic`) по `realpath`.
Например, `~/.local/bin/codex` и `<npm-prefix>/bin/codex` могут вести к одному
entry пакета: это одна установленная копия, а не `shell_conflict`.

Исходные пути команд и PATH обеих оболочек сохраняются для последующего запуска.
Нормализация применяется только при сравнении; rc-файлы и ссылки не изменяются.
Физический путь фиксируется сразу после снимка каждой оболочки. Если его нельзя
проверить, операция возвращает `shell_probe_failed`.

Разные физические файлы, даже с одинаковым содержимым, остаются конфликтом.
Alias/function Bash не становятся допустимыми командами. Проверки npm-prefix и
userconfig сохраняются; effective global prefix обеих форм сверяется отдельно
перед подготовкой установки.

Отказ подготовки в окне называется по выбранной операции: установка, обновление,
переустановка, удаление или перенос. Переустановка не подписывается обновлением.

Проверки: `tests/server/user-cli-environment.test.js` воспроизводит ссылки и
настоящие разные файлы; `provider-lifecycle-service.test.js` проводит переустановку
с двумя ссылками через prepare/start до итога. Компонентный
`tests/web/provider-install-dialog.component.test.js` проверяет подписи на RU/EN.
