# Ошибки подготовки и системные отказы хода

Принятый ход может завершиться до запуска исполнителя: например, `createWorkIpc`
не смог создать временную папку из-за `ENOSPC`. Такой отказ проходит через общий
обработчик `runChatTurn`, сохраняет итог в pending под исходным `turnId` и отправляет
`chat-done` без `runId`. Это относится и к явному отказу подготовки, а не только к
исключениям. Событие отправляется внутри очереди чата, до запуска следующего сообщения;
`queued` сохраняет число ожидающих ходов.

Зарегистрированное исполнение завершает собственный `finally`: общий обработчик
не дублирует его `chat-done`. Регистрация запуска и подготовка окружения тоже находятся
под этим `finally`, поэтому сбой после появления активного запуска освобождает его.
Синхронный маршрут возвращает ошибку через HTTP, как и раньше; отказ служебной выжимки
сохраняет код и статус `ChatWorkdirError`.

Окно при `chat-done` с `turnId`, но без `runId` сначала забирает pending, затем сверяет
`/api/chat/active`. Нельзя просто погасить статус или отфильтровать событие по предыдущему
`runId`: предыдущее исполнение может ещё забирать свой итог, а следующее уже работать.

`server/src/lib/chat/turnError.ts` объясняет известные системные коды:

| Код | Что видит человек |
| --- | --- |
| `ENOSPC` | Недостаточно места; освободить место для временных файлов или данных GrigDesk |
| `EDQUOT` | Исчерпана дисковая квота; освободить место или увеличить квоту |
| `EACCES`, `EPERM` | Не хватает прав доступа; проверить права GrigDesk |
| `EROFS` | Файловая система только для чтения; восстановить запись |
| `EMFILE`, `ENFILE` | Исчерпан лимит открытых файлов; освободить ресурсы или увеличить лимит |

Классификация использует строковый `error.code`, а не поиск слов в произвольном тексте.
Известная ошибка не показывает внутренний путь сервера; исходное исключение подготовки
попадает в серверный журнал. Неизвестная ошибка сохраняет причину. Тот же formatter
используется для ошибок уже запущенного исполнителя, с сохранением его шагов и контекста.
Эта обработка не освобождает место сама и не запускает повтор автоматически: после
устранения причины человек отправляет новое сообщение. Устойчивая доставка итога
по-прежнему требует возможности записи pending в папку данных.

Проверки:

- `tests/server/chat-turn-delivery-store.test.js`: настоящий сервер и стор окна,
  `ENOSPC` при создании IPC, следующий успешный запуск и отказ из очереди после ответа.
- `tests/server/chat-turn-preparation.test.js`: порядок конца и следующего старта,
  явный отказ, синхронный маршрут, неизвестная причина и системная ошибка исполнителя.
