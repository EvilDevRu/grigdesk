# DeepSeek Harness

DeepSeek и GLM используют автономный бинарник `bin/deepseek`, собранный пакетом
`deepseek/`. В нём закреплённые Harness, worker Node, зависимости и лицензии. Чат использует
web RPC/events на loopback, каталог моделей и Factory — ACP. Ключи остаются в данных службы.

## Установка

Сборка из чистого checkout и подготовка pinned dependencies описаны в
[README пакета](../../../deepseek/README.md). После сборки в отдельный каталог:

```bash
npm --prefix deepseek run install:binary -- --binary /absolute/release/deepseek \
  --target "$PWD/bin/deepseek" --host-contract "$PWD/server/deepseek-host-contract.json"
node server/scripts/deepseekRuntimeInfo.mts --probe
```

Пути передаются абсолютными: `npm --prefix deepseek` запускает установщик из `deepseek/`, и
относительный `bin/deepseek` превращается в несуществующий `deepseek/bin`.

Первый переход требует обновления сервера и ручного перезапуска владельцем. Последующие
совместимые замены ELF не требуют перезапуска: текущий ход завершится на прежнем бинарнике,
следующий получит новый. `grigdesk-ctl deps` и обновление GrigDesk проверяют поставку,
а Harness не собирают. Отсутствующий ELF не мешает остальным исполнителям.

Harness не требует системного Node. Поддерживается Linux x64/glibc; shell, bubblewrap
и средства управляемых команд остаются требованиями инструментов. Первая распаковка
занимает время и диск; приватные поколения кэша пока не удаляются автоматически.
`GRIGDESK_DEEPSEEK_BIN` задаёт абсолютный путь другого совместимого ELF GrigDesk.
Stock `dsh` и режимы `installed`/`external` не поддерживаются.
[Состав](deepseek-vendored-composition.md) и [поставка](deepseek-binary.md).

Ключ задаётся в «Настройки → Исполнители → DeepSeek → Ключи доступа». Сервер записывает
`DEEPSEEK_API_KEY` в `.env` папки данных GrigDesk и сразу применяет его без перезапуска
([контракт окна](executor-credentials.md)). Можно и вручную вписать ключ в `.env`
папки данных, но не в браузерные настройки, проектный `.env` или настройки Factory. Приватное
состояние можно разместить отдельно:

```text
GRIGDESK_DEEPSEEK_RUNTIME_HOME=/private/runtime/deepseek
```

После ручного изменения окружения нужен рестарт сервера; ключ из окна действует сразу.
Затем в «Настройки → Исполнители» нажмите «Перепроверить». Карточка показывает наличие ключа и точную версию,
но metadata-probe не делает модельный запрос и потому не может подтвердить, что ключ принят
API или что сеть доступна. Каталог моделей перечитывается metadata-only ACP-сессией без
`session/prompt`.

## Счёт во всплывашке топбара

Лимитов подписки у DeepSeek нет — API оплачивается с предоплаченного счёта. Поэтому
всплывашка исполнителя в топбаре показывает не полосы окон, а ресурсы счёта:

- **Баланс** по каждой валюте из `GET /user/balance` (остаток, пополнение и бонус) со
  ссылкой на пополнение. Пустой счёт или `is_available: false` подсвечиваются как беда.
- **Тариф** показывает текущую фазу и абсолютный момент следующей смены: пик `×2`
  подсвечивается жёлтым, скидка `50 %` — зелёным. Часы переводятся в местную зону сервера.
  Во всплывашке видна только короткая сводка, полное расписание и ссылка на тарифы — в
  «Настройки → Исполнители». Календарь праздников КНР лежит константой в
  `server/src/lib/deepseek/tariff.ts`; его обновляют раз в год после официального уведомления
  Госсовета, не предполагая даты ещё не опубликованного года.
- **Сторож страницы цен.** Окна пика и множитель — константы того же файла, а API тарифов у
  DeepSeek нет, поэтому раз в сутки адаптер перечитывает публичную страницу цен (без ключа
  службы) и сверяет с константами фразу о пиковых часах, оговорку о буднях и праздниках,
  фразу о размере скидки и пары «off-peak/peak» таблицы. Расхождение делает «Тариф» бедой с
  перечислением того, что изменилось на сайте, — такой note виден и во всплывашке; правят
  константы, и тревога снимается после рестарта без новой сверки, потому что снимок хранит
  факты страницы, а вывод строится при чтении. Переверстанная страница («не разобрано»),
  недоступный сайт и сверка старше недели упоминаются только в note настроек. Снимок —
  приватный `pricing-check.json` в runtime home; после отказа сети повтор через час. Снимок
  страницы для тестов — `tests/fixtures/deepseek-pricing-2026-09-21.html`.
- **Прогноз** — «хватит на ~N дн.» по темпу расхода за последние сутки. Темп считается по
  собственным снимкам баланса (те же пять минут, что и у остальных исполнителей), и только по
  убыли между соседними снимками: пополнение темп не занижает. Пока наблюдений меньше двух
  часов, прогноза нет; если за сутки остаток не менялся — «расход стоит». Меньше трёх
  дней — красный, меньше двух недель — жёлтый.

Снимки лежат в приватном `balance-log.json` внутри runtime home и держатся неделю. Ключ в
тексты всплывашки и в журнал не попадает; отказ ключа (`401`) показывается как
«DeepSeek отклонил ключ API службы». Блок плагина «Прогноз лимитов» для DeepSeek не
строится: у него нет окна с процентом, прогноз счёта — в самих ресурсах.

## Режимы чата

- **Спрашивать** (`default`) — читает свободно, перед правкой, shell-командой или внешним
  инструментом ждёт решения человека. Разрешение разовое; карточка показывает полную команду,
  предлагаемое содержимое или дифф. Служебные SSH/БД используют собственный брокер подтверждений.
- **Авто** (`auto`) — обычные файлы внутри рабочей папки создаёт и редактирует самостоятельно.
  Shell-команды выполняются в штатной песочнице Harness; явное расширение доступа,
  правки чувствительных файлов через файловые инструменты, неоднозначные пути и проектные MCP
  подтверждает человек. Отдельного классификатора опасных команд в Harness нет:
  удаление внутри разрешённой папки само по себе вопроса не вызывает.
- **Только чтение** (`read-only`) — запись исходников, shell и расширение песочницы запрещены.
  Проектные MCP не запускаются. Списки рабочих SSH/БД и чтение схемы идут через существующий
  брокер; exec/query отклоняются до вызова MCP. Вопросы и внутренний список дел сохраняются.

Чату требуется ELF с capability `toolPermissions`; старая поставка получает просьбу обновить
бинарник до запуска модели. Native gate проверяет вызов до эффекта, а финальный guard не
позволяет обойти проверку другим разрешающим обработчиком. Реальная граница записи равна
realpath cwd; список доверенных каталогов её не расширяет. Для разового выхода за границу
требуется явное разрешение человека. [Контракт и проверки](deepseek-tool-permissions.md).

На проверенном Linux backend `bwrap` с `enforcement: full` блокировал относительный `../`,
абсолютный внешний путь и symlink наружу и для file tools, и для shell. Чтение sibling-файла
вне cwd оставалось доступно. `/tmp` в `workspace-write` был приватным эфемерным каталогом
namespace, а в `read-only` запись туда была запрещена. Если controlled smoke на другом
хосте не подтверждает эти свойства, соответствующий режим нельзя включать или ослаблять
автоматически.

Сам DSH всё равно пишет служебные данные в приватный `DSH_HOME`: профиль, журнал сессии и
projection cache. Это не agent write. Status/work MCP запускаются вне tool sandbox и получают
только явно переданные env/args. Hook-команды, напротив, живут под policy сессии и не имеют
гарантированной записи в state; `/tmp` hook-а нельзя считать постоянным хранилищем.

## Проектные MCP-серверы

Чат передаёт список MCP в одноразовом overlay web-профиля до запуска DSH.
В ACP runtime список передаётся через `session/new`/`session/resume`. Кроме служебного
`grigdesk-work` чатовый адаптер добавляет записи из `.mcp.json` проекта — того же файла, что
читают Claude и Kimi: `{ "mcpServers": { "<имя>": { "command", "args", "env" } } }`.
Читаются два слоя — у корня репозитория и в cwd разговора (cwd перекрывает одноимённые
записи), поэтому проект без `.git` внутри чужой рабочей папки получает свои серверы. В V1
поддерживаются только stdio-записи: команда — абсолютный путь либо имя, найденное по PATH
сервера; `url`/`type: http`, отсутствующий исполняемый файл и повреждённые поля не роняют ход,
а пропускаются с предупреждением в журнале. Имена `grigdesk-work` и `grigdesk-perm` зарезервированы.
В проверенном ACP-пути DSH монтирует серверы с `failOnStartupError`:
неподнявшийся сервер срывает создание сессии,
поэтому проектный сервер обязан стартовать даже без своего backend и возвращать ошибки
инструментами. Список передаётся на каждом ходу, так что правка файла действует со следующего
сообщения. Тест: `tests/server/deepseek-project-mcp.test.js`.

## Factory

Политики Factory отдельны от подписей чата:

- `workspace-write` разрешает агенту менять cwd проекта;
- `state-only` переводится в DSH `read-only` с `approval: never` и допускается только после
  подтверждения неизменности source на текущем хосте;
- `transactional-write` для DeepSeek V1 не поддерживается и останавливает запуск до prompt.

Любой неожиданный permission request в Factory получает `reject-once`. Агент не получает
`STATE_DIR`, control token или второй writable root. `stage_progress` и `stage_result`
проходят через отдельный server-owned MCP и настоящие скрипты протокола; текст «готово» сам
по себе этап не закрывает. Billing usage для Factory помечается `unavailable`, а не нулём.

Включать DeepSeek в боевую primary/failover-цепочку следует только после metadata-only host
preflight и disposable-smoke обоих файловых режимов. Доказанный отказ неверного ключа до
любой model/tool activity допускает failover. 413, 429, обрыв журнала, ошибка после
активности и любой неизвестный исход не переигрывают этап автоматически.

## Ограничения V1

- механическую файловую границу обеспечивает sandbox DSH; policy hooks fail-open;
- запрет прямых SSH/DB-команд — command-hook, а не сетевой firewall;
- сеть и запуск процессов песочница не ограничивает;
- writable root одна — cwd сессии, и в чате, и в Factory: второй области ACP не принимает
  (`additionalDirectories is not supported`). Overlay тоже получает realpath cwd, без
  расширения до каталога-предка. Вложенные каталоги доступны для записи. О каталогах вне
  границы лента предупреждает один раз на разговор, о вложениях — на каждом ходу. Читать файлы
  вне области агент может, писать — только через эскалацию `danger-full-access`, и каждую
  такую попытку подтверждает человек;
- обрыв связи с API посреди хода показывается как прерывание с кнопкой «Продолжить ход»:
  сессия цела, сделанное видно в ленте, продолжение — обычное сообщение в ту же сессию;
- native fanout и `transactional-write` не заявлены;
- `@`-импорты раскрываются stateless на каждом prompt и расходуют контекст;
- процесс DSH создаётся на каждый ход; сохранённая сессия возобновляется по server-owned
  binding и только с тем же realpath cwd;
- ACP `usage_update` описывает заполненность контекста, не стоимость. Billing-счётчики V1
  не публикует; расход виден только как убыль баланса счёта.

## Обновление и откат

Бинарник обновляется отдельно от GrigDesk. Откат — установка прежнего ELF тем же
установщиком. Совместимый журнал сохраняет сессию и память; несовместимый вызывает новую
сессию с заметкой, сохраняя ленту. Первый переход переносит legacy home по identity
установленного прежнего runtime. Обновление upstream требует source review, compiled gates
и отдельного допуска изменившегося GLM compatibility; любой будущий upstream автоматически
совместимым не считается. [Обновление и откат](deepseek-upstream-update-rollback.md).

Нативные настройки требуют metadata приватного ACP-моста. Неисправный ELF даёт отказ
до prompt; автоматического fallback нет. Технические ограничения —
[DEEPSEEK.md](../../engine/DEEPSEEK.md).
