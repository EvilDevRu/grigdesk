# «DeepSeek не пишет в соседний каталог» = граница записи — папка разговора, а не доверенный каталог

Симптом: доверенный каталог шире рабочей папки чата (например, общий корень всех рабочих
копий), а DeepSeek всё равно отказывается менять файлы соседнего репозитория или просит
разрешение на каждую такую запись. Свою границу он называет папкой, из которой начат
разговор.

Причина — в самом DeepSeek Harness, а не в модели. До выбора папки чата GrigDesk вычислял самый глубокий
доверенный каталог-предок cwd и клал его в overlay как `sandbox-policy.workspaceRoot`
(`server/src/lib/deepseek/runtime.ts`). Но закреплённая версия DSH (`0.1.5-rc.2`) берёт
границу вызова агента из cwd сессии: `SandboxPolicyService.resolve({ session })` возвращает
`session.header.cwd ?? workspaceRoot`. Значение из overlay — только запасная граница для
вызовов без сессии. Сессию GrigDesk всегда открывает с `cwd` (ACP `session/new` и
`session/resume` без него не работают), поэтому граница записи равна realpath cwd чата.
Через этот же `resolve` идут файловые инструменты (`str_replace_editor`), bash и строка
`sandbox:policy`, которую модель видит в контексте: «may modify files under the session
workspace: <cwd>». Отсюда и «нельзя вне установленной папки».

Второй области записи у DSH нет: `session/new` с непустым `additionalDirectories` отвечает
`additionalDirectories is not supported`. Без эскалации DeepSeek пишет только внутри папки,
из которой начат разговор; всё остальное — через `danger-full-access` с подтверждением
человека. Расширить область можно только выбором cwd, а не списком каталогов.

Теперь overlay получает строго realpath cwd; доверенный предок из `extraDirs` не
участвует в расчёте. Предупреждение ленты называет эту же фактическую границу, поэтому
внешние репозитории больше не выдаются за заранее разрешённую область записи.

Юнит-тесты правки не поймали: они проверяют, что GrigDesk пишет в overlay, а не что DSH с этим
делает, а живого хода с записью в соседний каталог не было. Факт установлен чтением кода
установленной версии: `dsh-sandbox-policy` (`resolve`), `dsh-acp` (`session/new`,
`validateWorkspaceParams`), `dsh-tool-bash` и `dsh-tool-str-replace-editor` (policy по
сессии). Живая проверка — один ход с cwd внутри доверенного каталога и записью рядом:
ожидаются маркер `[sandbox: file access denied under workspace-write mode]` и запрос
эскалации.
