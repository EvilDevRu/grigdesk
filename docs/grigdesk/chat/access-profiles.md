# Профили доступа и единая граница запуска

Capability `accessProfiles` принадлежит адаптеру: способы, поля, режим, ограничения изоляции,
миграция прежнего доступа и проверка ключа. Ядро и интерфейс не перечисляют поставщиков.
Адаптер без capability сохраняет прежний credentials-контракт.

## Хранилище и операции

`lib/accessProfiles/store.ts` хранит приватные ревизии credentials и manifest в каталоге
`state/access-profiles`. UUID профиля, ревизия доступа и поколение совместимости памяти
различаются. Один manifest содержит `activeProfileId`, метаданные, попытки и operation IDs.
Неизменяемая secret revision записывается до атомарного durable commit manifest.
DTO не содержит secretRef, окружение, home и приватное account evidence.

Первое чтение импортирует объявленные адаптером прежние подключения. Исходный `.env`
и CLI homes сохраняются. Legacy home остаётся ссылкой; он не объявляется изолированным.
Повторная миграция не создаёт новые UUID. Обычный API GLM и Coding Plan импортируются
отдельно; активным остаётся объявленный прежний режим.

Профильные HTTP-маршруты находятся под общим `/api` auth guard. Создание, ввод шага,
активация и переименование имеют operationId; повтор узнаёт сохранённый исход.
Активация сверяет revision списка, переименование и удаление — revision профиля.
Активный профиль и профиль с незавершённым входом удалить нельзя.

## Запуск и память

Общий декоратор реестра выбирает immutable snapshot до внешнего эффекта. Чат резервирует
его до runtime/settings/binding; служебные run/runUntrusted используют тот же декоратор.
Снимок не зависит от последующего изменения process.env или env HTTP-запроса.
Секреты других способов удаляются из окружения выбранного доступа.
Потеря входа в `run`, открытии живой сессии и её `send` наблюдается по тому же снимку:
следующий ход блокируется до повторного входа без переигрывания предыдущего.
Смена доступа отзывает общий кэш моделей и позднюю сборку прежнего профиля. Отдельный
scope аккаунта исключает чужой каталог; обычный refresh токена сохраняет алиасы старых моделей.

Короткий межпроцессный mutex согласует выбор снимка и запись work reservation с
переключением. Reservation содержит PID/starttime; неизвестный владелец блокирует
переключение. Работа, ожидание подтверждения, фон и сон считаются занятостью.
Свободные живые процессы чата закрываются перед подтверждением смены доступа.
Закрепление конвейера описано [отдельно](../pipeline/access-profile-pins.md).

История хранится отдельно от native session. Binding использует UUID и приватное поколение памяти. Оно меняется при ручном повторном
входе, если адаптер не подтвердил совместимость resume. Обычный refresh токена его не меняет.
Неизвестность аккаунта при повторном вводе ключа требует явного выбора до commit;
подтверждение начинает новую native-сессию с заметкой, сохраняя переписку.
Для GLM API customerNumber сравнивается приватно; обновление ключа того же аккаунта
не повышает accountGeneration. Это не обещание переноса памяти по наличию auth-файла.

## Мастер и отказы

Попыткой владеет сервер: attempt/step ID, revision, срок, cancel/retry, проверка результата.
Шаги: fields, open-url, display-code, enter-code, choice, waiting, verifying, result.
Показ ссылки и код CLI → сайт не означают успех. Код сайт → CLI отправляется одному
ожидающему child. Неизвестные версии и prompts не принимают произвольный терминальный ввод.

Codex 0.166.0 использует app-server device-code RPC и account/read; Claude 2.1.80 — TUI
`/login`, PTY и `auth status`; Kimi 2.4.1 — `login --region global` device-code flow.
После уведомления Codex об успешном входе подтверждается аккаунт `type: chatgpt`.
`requiresOpenaiAuth` описывает провайдера и может оставаться `true` после входа;
этот флаг не используется как признак отсутствия авторизации.
URL проверяется по HTTPS allowlist адаптера. Сырой PTY-вывод не публикуется.
Неподдерживаемая версия завершает попытку с причиной, сохраняя основное подключение.
Добавление CLI при занятости запрещено: изоляция всех внешних keyring не доказана.

Сохранение и активация разделены. Cancel и поздний ответ не заменяют прежний доступ.
После штатного закрытия или доказанной смерти владельца незавершённая попытка получает interrupted; сохранённый commit
узнаётся чтением. Auth-required блокирует новые ходы, сеть остаётся временным отказом,
квота не считается отсутствием входа. Чужой аккаунт автоматически не выбирается.
Целый ход после неизвестного результата не повторяется.
Профильный отказ нового хода возвращает `409 access_auth_required`: HTTP 401
принадлежит сессии GrigDesk и не используется для потерянного доступа исполнителя.

Сравнение аккаунта импортированного API-профиля выполняется вне mutex. Если прежний
ключ уже отозван или поставщик не ответил, новый проверенный ключ требует явного
подтверждения неизвестности аккаунта; его сохранение не зависит от работоспособности старого ключа.

Claude refresh сериализуется штатным lock credential home. Публикация новой ревизии
сверяет исходный snapshot; поздний exchange не затирает новый профиль и не продолжает
чтение старым токеном. Реальные аккаунты, login и квоты проверяются с владельцем;
offline-протокольные fixtures не подтверждают настоящую авторизацию.
До приёмки остаётся проверить на стенде с загруженной веткой: общий мастер,
переключение между окнами, reload/reconnect и реальные CLI-входы с владельцем доступа.

Профильные тесты: `tests/server/access-*.test.js`; пользовательский мастер —
`tests/web/access-attempts.test.js` и `access-profiles.component.test.js`.

Управляемый login удерживает отдельный reader установки CLI от проверки версии до выхода
дочернего процесса. Порядок защиты: access admission, затем installation lease.
PID/starttime владельца и child сохраняются приватно. При аварии сервера прежний child
останавливается только после проверки его identity; неизвестный holder блокирует новый вход.
Срок живого CLI ограничен десятью минутами, сохранённый commit при восстановлении не теряется.
Terminal-состояние попытки не снимает допуск, пока CLI жив или ещё готовится к запуску.
Отмена во время подготовки сохраняет этот признак до регистрации и остановки child.
PTY начинает login только после сигнала о сохранённой identity. Если сервер погиб до
этого сигнала, закрытие stdin не позволяет дочернему CLI начать вход.
Восстановление после аварии проверяет и останавливает также child отменённой попытки,
сохраняя её результат отмены и запрет позднего применения.

Claude импортирует прежний собственный API-ключ GrigDesk с приоритетом над окружением,
а CLI-ссылку сохраняет отдельно. Новый CLI-профиль не наследует API-ключ или endpoint
другого подключения из shell. Overlay доступа применяется после shell environment,
включая чтение нативных настроек. Данные служебного транспорта хода сохраняются.

Путь постоянного прогноза включает профиль, режим и поколение аккаунта. Ревизия токена
проверяется отдельно для поздних ответов; same-account refresh не сбрасывает журнал.
Повторный вход проверяет revision целевого профиля, а режим существующего профиля менять
нельзя: иной режим сохраняется новым профилем.

Новый управляемый CLI login использует приватные HOME и XDG-каталоги попытки. После
сохранения те же пути закрепляются в runtime профиля и применяются после shell.
Импортированное основное подключение сохраняет прежний host home без копирования.
Это ограничивает файловые footprints; изоляция внешнего keyring всё равно не обещается.

Неполная конфигурация служебного потребителя использует каноническую папку данных,
а не относительный путь из отсутствующего значения. Сервис доступа выбирает снимки
только адаптеров своего реестра; внешние каталоги с другим набором адаптеров
сохраняют прежнее поведение без ложного «неизвестный исполнитель».
