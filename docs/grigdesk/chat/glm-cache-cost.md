# Кеш контекста и стоимость хода GLM

Читай при разборе расхода токенов. Один агентный ход может содержать много запросов,
каждый из которых снова передаёт контекст. Стоимость зависит от суммы токенов всех
запросов, а не только от длины последнего ответа. Процент кеша одной сессии не является
гарантией для другой модели, аккаунта или хода.

Для денежного API оценка складывается из некешированного входа, чтения и записи кеша
и выхода, умноженных на соответствующие ставки. Ставки и единицы берутся из актуального
каталога используемой generation; данные каталога могут отставать от счёта провайдера.
Кредиты Coding Plan и денежный баланс не смешиваются; см.
[кредитные окна](glm-credit-windows.md) и [тарифные фазы](glm-tariff.md).

## Проверка разрешённого журнала

Формат журнала DSH — цепочка сжатых кадров; чтение одного кадра не даёт весь ход.
Пути и codec описывает [контракт журналов](deepseek-journal-codecs.md).
Расход модельного ответа находится в `data.usage` события `assistant/message`.
`inputTokens` — некешированный вход, `cacheReadTokens` и `cacheWriteTokens` — отдельные
категории кеша. Их сумма даёт весь вход запроса; повторно прибавлять кеш к уже полному
счётчику нельзя. Неудачная `assistant/attempt` может не содержать usage.

Сопоставление со списанием учитывает все запросы и задержку обновления баланса.
Отсутствующая usage не превращается в нулевую стоимость. Работа с личным журналом
требует отдельного разрешения; суммы и тексты конкретной сессии не входят в общий документ.
