# Кеш Z.ai и цена хода GLM

Кеш контекста у GLM через DSH срабатывает сам: GrigDesk для него ничего не включает. На живых
ходах агента (десятки запросов подряд) из кеша приходило 97–98% входа. Списание в журнале
баланса сходилось с расчётом по журналу сессии с точностью около 10%.

Цена агентного хода складывается в основном из перечитывания контекста. Каждый шаг агента — это
отдельный запрос, который заново отправляет весь разговор. На полной `glm-5.3` за 8 минут
агент сделал 54 запроса со средним контекстом около 50 тыс. токенов и выходом около 270 токенов.
Это около $0,86, из них 81% — чтение кеша, а без кеша вышло бы около $3,9. Поэтому цена растёт
как «число шагов × размер контекста», а не по объёму ответа.

Тариф берётся из таблицы pi-ai в собранной generation (`providers/data/zai.json`, USD за 1 млн
токенов): `glm-5.3` — вход 1,40, вход из кеша 0,26, выход 4,40; `glm-5.3-flash` — 0,075, 0,015
и 0,25. Тот же объём работы на flash примерно в 17 раз дешевле.

## Как проверить

Журнал сессии DSH лежит в home чата GLM: `sessions/<projectKey(cwd)>/<id>/session.v3.jsonl.zstd`.
Это цепочка zstd-кадров: `zstd -dc` читает их все, а `zlib.zstdDecompressSync` из Node отдаёт
только первый. Расход одного запроса к модели — `data.usage` события `assistant/message`.
Поля не пересекаются: `inputTokens` — некешированный вход, `cacheReadTokens` и
`cacheWriteTokens` — кеш; весь вход запроса — их сумма. Неудачная попытка
(`assistant/attempt`) usage может не нести. pi-ai берёт кеш из
`prompt_tokens_details.cached_tokens` ответа Z.ai, адаптер DSH передаёт его дальше, только когда
он больше нуля.

Снимки баланса — `balance-log.json` в корне homes GLM; списание Z.ai может отставать от запросов
на несколько минут.
