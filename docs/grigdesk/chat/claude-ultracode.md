# Claude: ступень ultracode запрашивает workflow

GrigDesk предлагает `ultracode` последней ступенью общего слайдера Claude, после `max`,
если он доступен. Это запрос глубины `xhigh` и делегирования задач при доступном
workflow. Список и подсказка приходят из адаптера через общий runtime-каталог;
отдельного переключателя и ветвления web по Claude нет.

## Что подтверждает каталог

| Факт | Проверка | Граница |
| --- | --- | --- |
| CLI понимает имя уровня | Список `--help` либо положительная и отрицательная пробы `--version` | Не доказывает доступность workflow |
| Модель совместима с базовой глубиной | Проверенные capabilities, `effort` и разрешённая `xhigh` | Не доказывает настройки аккаунта/сессии |
| Workflow доступен и включён | Session-specific `get_settings.applied.ultracodeAvailable` / `ultracode` | Общий каталог эти данные не читает |

`ultracodeRequested` в [settings readback](executor-settings-discovery.md) обозначает
запрос режима, а не его активность. Слайдер предлагает запрос; он не выдаёт глобальную
пробу CLI за session-specific `ultracodeAvailable=true`.

## Discovery и допуск модели

Адаптер читает `claude --help`. Известное имя `ultracode` требует `xhigh` в этом свежем
списке. Если имя скрыто, запускаются только `--effort <имя> --version`, без prompt:

- Контроль `__grigdesk_invalid_effort__` должен завершиться с кодом 0, выдать строку
  версии Claude Code в stdout и `Unknown --effort value` для этого имени в любом потоке.
- Кандидат `ultracode` должен завершиться с кодом 0, выдать ту же форму версии без
  диагностического отказа в stdout или stderr. Просто semver внутри ошибки недостаточен.
- CLI, печатающий версию для любого effort, контроль не проходит. Timeout каждой пробы
  ограничен 5 секундами, буфер — 64 КиБ; ошибка оставляет обычные ступени из справки.

Публичное имя из справки не требует скрытой пробы. Без базы режим удаляется; при
дубликатах остаётся один экземпляр в конце. Обычные имена и их порядок сохраняются.
Отказ или неразобранная справка возвращают `null`.

Для автоматической модели режим допускается только при свежем подтверждении CLI,
capability `effort` и разрешённой базовой `xhigh`. Гейты `_effort` остаются динамическими;
если каталог объявит отдельный `ultracode_effort`, его тоже нужно разрешить. Отсутствующие
capabilities сохраняют обычный fallback, но снимают режим. `effortUnverified=true`
возвращает пустой список даже при сохранённых last-known capabilities.

Старый сохранённый `ultracode` не подтверждает текущий CLI: без свежего discovery режим
снимается при runtime-сборке, обычный fallback остаётся. Файл каталога не переписывается,
миграции схемы нет. Явные `custom`-модели сохраняют ручной список и описания, обходят
фильтр адаптера и не получают этих автоматических гарантий.

## Запуск и независимые настройки

Обычный чат и разовый coding-запуск передают `--effort ultracode` как есть. Смена
`high → ultracode → high` использует прежний механизм переоткрытия процесса с тем же
sessionId; одинаковое усилие переиспользует процесс. Пул ждёт конца работающего фона
до смены параметров по [существующему контракту](background-run-lifecycle.md).

Untrusted model-only ход передаёт базовую `xhigh`; обычный `max` и отсутствие усилия
сохраняются. Изоляцию обеспечивают прежние пустые tools/setting sources, safe mode,
strict MCP, отключённые customizations/persistence, временный cwd и отсутствие
workspace/resume/native overlay. Замена имени effort лишь предотвращает запрос режима
этим флагом и сама по себе не доказывает отсутствие субагентов.

Native/внешний `ultracode=true` остаётся независимым. Смена ступени на `high` или `max`
не гарантирует выключения workflow, включённого настройками. Владение native-ключами
и их приоритеты не меняются. Конвейер и плагины используют тот же каталог; фактический
workflow в one-shot `claude -p`, включая `chatLiveSessions=false`, не проверен.

## Проверки и ограничения

2026-10-08: на установленном Claude Code 2.1.293 подтверждены обе пробы `--version`:
кандидат принимается, контроль предупреждает о неизвестном значении. Запросов к модели
не было. Ранее прочитанный бинарь связывает `ultracode` с глубиной `xhigh`; независимый
режим настраивается также через `--settings` / `apply_flag_settings`.

149 связанных серверных тестов прошли без пропусков: `claude-efforts`, `claude-catalog`,
`models-registry`, `inbox-untrusted-executors`, `chat-live-sessions`, `provider-settings`.
Они проверяют fake CLI с точным argv, отрицательные ответы/timeout/overflow, допуск и
старый снимок, custom, отсутствие записи каталога, изоляцию и переоткрытие пула.
Снятие допуска по базе или свежести действительно делает соответствующие тесты красными.
Читаемость, типы сервера и тестов прошли. Это доказательство программного контракта.

Живой workflow, session-specific applied, фон настоящих субагентов и браузерная приёмка
после ручного перезапуска не выполнены. Для них нужны отдельная приёмка и разрешённый
модельный ход; fake CLI и `--version` их не заменяют. Обещаний количества субагентов
или численного расхода нет.
