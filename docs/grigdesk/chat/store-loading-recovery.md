# Загрузка списка чатов и восстановление связи

Стор различает ещё не подтверждённый список (`loaded=false`), текущую попытку (`loading`)
и причину отказа (`loadError`). Только успешно прочитанная первая порция `GET /api/chat/store/list?page=1&archived=0&limit=40`
с `listProtocol:2`, `historyWindowProtocol:1`, page/summary и валидными версиями шапок
разрешает перейти в `loaded=true`. Пустые массивы допустимы:
`ensure()` создаёт первый обычный чат только при нулевых глобальных active/archived.
Пустая текущая порция сама по себе не означает пустую историю сервера.

Пока сервер не подтвердил список, «Чаты» показывают загрузку либо сообщение об отказе
с причиной и кнопкой «Повторить». Ошибка имеет приоритет над поиском, архивом и пустой
подписью. Во время следующей попытки причина остаётся видимой, появляется загрузка,
кнопка повтора выключается. Успех снимает ошибку без перезагрузки окна.

Причины: отсутствие связи, молчание сервера, ошибка сервера, отсутствие доступа.
HTTP 503 локальной трубы с кодами `offline`, `disconnected`, `connecting`, `no_machine`
означает отсутствие связи; прочие 503 относятся к ошибке сервера. HTTP 401/403 означают
отсутствие доступа. В сторе хранится категория, а перевод разрешается при показе:
смена RU/EN не повторяет загрузку и не меняет данные чатов.

## Защита до первого успеха

Сохранённая браузерная копия до успешного GET скрыта. При отказе она не читается,
не удаляется и не перезаписывается. Создание нового чата отключено с видимым объяснением
как в списке чатов, так и в паспорте проекта. Общий `newSession()` возвращает `null`.
После ожидания загрузки проект проверяет готовность повторно и переходит в «Чаты»
только при получении id созданного разговора.

До готовности `_persist()` не пишет ни страховочную копию, ни историю, ни метаданные
(модель, режим, недавние папки, активный чат). Отложенная запись проверяет готовность
повторно. Прямые `_writeChat()` и `_putChat()` отклоняются до инициализации рабочей папки;
очередь не выдаёт ложного подтверждения. Pending, active и сверка доставок ждут загрузки,
поэтому подтверждение pending не может удалить ещё не сохранённый ответ.

После успешного списка страховка сравнивается по каждому id, сохраняя остальные шапки.
Частичная копия восстанавливается через собственный window PUT с проверкой базы;
прежняя полная копия объединяется с адресным ограниченным окном. Скрытая лента
после восстановления возвращается к голове, без неявного открытия. При отказе адресного чтения или записи исходная страховка остаётся доступной.
После восстановления идут pending → waiting → active → доставки. Подробности нового
протокола и границы полноты — [лёгкий список](lazy-history.md).

У продолжения списка и старых сообщений собственные loading/error/cursor. Отказ сохраняет
показанные данные, повтор использует ту же границу. 410 списка требует явного обновления,
409 истории — свежего ограниченного окна. Новый протокол не использует full fallback.

## Ожидание и повторы

Начальный порционный GET `/api/chat/store/list`, адресное чтение окна ленты и read-only POST
`/api/chat/store/changes` при reconnect используют `idleTimeoutMs: 30000` и `retry: false`. Сторож начинает отсчёт до fetch, обновляется
на заголовках и каждой непустой части тела. Пустые части не продлевают ожидание.
Общего предела длительности нет: передача может идти дольше 30 секунд, пока приходят данные.
После EOF сторож снимается до разбора JSON. UTF-8 декодируется потоком, в том числе при
разрезании многобайтного символа между частями. Не-JSON HTTP-ошибка сохраняет HTTP-статус.

Повтором первой загрузки владеет стор: паузы 1, 2, 4, 8, 16, затем 30 секунд до успеха.
Отказ доступа не запускает таймер. Ручной повтор, `online`, переход документа в `visible`,
SSE `hello` и повторный `ensure()` при возвращении в «Чаты» могут начать попытку раньше.
Переход в `hidden` сам загрузку не запускает. Срабатывание таймера в скрытом документе
откладывает попытку до возвращения в `visible`. Скрытая поверхность не загружает ленту.
Эти события присоединяются к уже начатому проходу, без второго GET. Успех сбрасывает
паузу и выключает таймер.

Runtime с Promise, контроллерами, таймером и отписками находится в WeakMap по raw-экземпляру
стора, вне Pinia state. `dispose` снимает слушателей, таймер и подписку на общий SSE,
отменяет запросы и запрещает применять поздний ответ. Новый EventSource не создаётся.

Уже подтверждённая история при неудаче последующей сверки остаётся готовой и видимой;
следующее `hello` использует прежний порядок сверки. Встроенный повтор apiClient для
этой сверки также выключен. У прочих запросов прежние правила: GET ждёт 30 секунд
и имеет один повтор через 700 мс после сетевого сбоя; мутации автоматически не повторяются.

Серверное хранение, прежний мобильный API и Telegram-пульт этим контрактом не меняются.
