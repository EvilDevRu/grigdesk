# Выход хода и последний контекст

Токены рядом с секундомером — выход текущего хода. Контекст — последний измеренный вход
основного агента, включая соответствующие кэш-поля источника. Это две независимые метрики;
при уменьшении контекста после сжатия сохраняется меньшее измерение.

| Исполнитель | Выход текущего хода | Последний контекст |
| --- | --- | --- |
| Claude | В partial-потоке накопительный `message_delta.usage.output_tokens` по каждому обращению; без замера — оценка текста, аргументов и сообщённых дельт размышлений. `result` исправляет свой сегмент, включая уменьшение; сегменты одного хода складываются | Основное assistant-событие; субагенты и явный replay замер не меняют |
| Codex | Прирост `total.outputTokens`; reasoning уже входит в выход | `last.inputTokens`; cached input повторно не прибавляется |
| Kimi | Сумма `turn.step.completed.usage.output` основного агента; повтор ключа шага заменяет вклад | Слияние частичных `agent.status.updated`: `contextTokens` и `maxContextTokens` |
| DeepSeek / GLM | Существующая сумма выходов по обращениям DSH | `inputTokens + cacheReadTokens + cacheWriteTokens` последнего обращения |
| Qwen | Сумма `_meta.usage.outputTokens` обращений основного агента; субагенты не учитываются | `usage_update.used`; окно — `usage_update.size` |

## Claude

Счётчик различает обращения по `stream_event.event.message.id` у `message_start`. Новый `message_start`
задаёт новое обращение даже при повторно использованном id. Полные assistant-блоки
закрывают соответствующие блоки partial-потока, а не прибавляют их второй раз.
Точный output включает reasoning: `system/thinking_tokens` его не увеличивает.
Смешанная сумма точных и оценённых вкладов сохраняет знак «≈». Подтверждённый ноль
принимается, отсутствующий usage не обнуляет прежний замер.

Уточнение, вставшее в очередь, может дать ещё один `result` внутри одного хода.
Первый `message_start` после предыдущего `result` закрепляет итог завершённого сегмента
и открывает следующий. Новый `result` исправляет только свой сегмент; поздние блоки без
начала нового обращения не возобновляют завершённый счётчик.

До первого замера этого хода прогресс передаёт только выход и его достоверность:
поля контекста отсутствуют и не стирают сохранённый замер прошлого хода. Исключение —
`compact_boundary`: после него прежний контекст явно объявляется `unavailable` до нового замера.

Флаг `--include-partial-messages` включён только у stream-путей. Разовый execFile-путь
и недоверенный запуск сохраняют ограниченный буфер stdout без этого флага.
Шаги ленты по-прежнему создаются из полных событий, а не из partial-дельт.
События partial-потока до начала фонового ответа не заполняют `preBackground`.
Одни partial-дельты не выставляют `madeProgress` для автопродолжения: признак работы
по-прежнему подтверждают прежние полные события и `system/thinking_tokens`.

## Kimi и DSH

Kimi 0.33.0 присылает метрики в фактических событиях шагов и статуса. Основной агент —
`agentId: main`; отсутствие поля поддерживается для старых кадров. Подагент не меняет
метрики и не завершает основной ход. Внутренний `turn.started` не сбрасывает счётчик
пользовательского хода. Legacy `session.usage_updated` используется только для контекста.
Патчи `{usage}`, `{model}`, `{planMode}` и `{swarmMode}` не обнуляют размер. При отсутствии
окна в статусе runtime использует известное окно модели из каталога.

DSH принимает вход только как конечное неотрицательное число; `null` не становится
контекстом 0. Некорректные или отсутствующие кэш-слагаемые не добавляются. Неприсланное
окно не выдумывается. Последний снимок доходит через runtime в итог хода.

Успех, остановка и обычная ошибка сохраняют последний контекст для повторного открытия
чата. Синхронная ошибка остаётся HTTP 500; у принятого хода результат имеет `role: error`
в pending. Повтор прогресса не удваивает ни выход, ни контекст.
При ошибке отсутствие контекстных полей не вызывает пустую правку истории. Отказ записи
замера попадает в журнал сервера и не заменяет исходную ошибку хода в HTTP или pending.

## Qwen

CLI шлёт `session/update` двух видов: `usage_update {used, size}` — последний контекст
основной сессии и её окно, и пустой `agent_message_chunk` с `_meta.usage`
(`inputTokens`, `outputTokens`, `cachedReadTokens`) после `executionLifecycle` ended
каждого обращения. Выход хода — сумма `outputTokens` основного агента; reasoning уже
входит в `outputTokens`. Кэш последнего обращения: `readTokens = cachedReadTokens`,
`uncachedTokens = inputTokens - cachedReadTokens`; запись кэша CLI не сообщает,
и отсутствие поля не выдумывается нулём.

Признак субагента берётся из `executionLifecycle.subagentId` и живёт до следующего
started: поздние usage и `usage_update` субагента не меняют ни выход, ни контекст,
ни кэш основного агента. Некорректные числа не обнуляют прежний замер; отсутствующий
`usage_update` не подменяет контекст нулём. Живой снимок уходит вторым аргументом
`onProgress`, итог хода сохраняет контекст и кэш для повторного открытия чата.
Форма событий проверена зондом настоящего CLI на синтетическом API
(`qwen-cli-contract`), коллектор — `qwen-runtime`.

Проверки: `claude-token-meter`, `chat-live-context`, `kimi-server-turn`, `kimi-runtime`,
`deepseek-server-thoughts`, `glm-runtime`, `deepseek-vendored-chat`, `chat-provider-routing`,
`qwen-runtime`, `qwen-cli-contract`.
