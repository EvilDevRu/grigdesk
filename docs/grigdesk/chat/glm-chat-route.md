# GLM в маршруте чата и в интерфейсе

GLM проходит общим путём чата без веток по вендору: тот же auth guard, протокол доставки по
`turnId`, pending, SSE и общий диалог разрешений.

- Общий auth guard закрывает карточки исполнителей, статус MCP и ход GLM: без сессии — 401,
  исполнитель не запускается.
- Принятый ход (`202` по `turnId`) кладёт итог в pending; повтор тем же `turnId` после F5 — `duplicate`
  без нового запуска; одна запись ответа.
- `glm_ambiguous_outcome` уходит в pending как ошибка вместе с полученными шагами — они видны после
  переподключения; повтора хода нет.
- Неизвестный для GLM режим (`plan` и т.п.) ядро через `allowedMode` превращает в режим по умолчанию —
  включить план для GLM нельзя. Прямые потребители с `plan`, Factory и scoped workspace отклоняются
  адаптером до процесса; триаж и анализатор исключают GLM по capability (нет untrusted-ввода и scoped
  workspace).
- В «Авто» эскалация песочницы (внешний путь) идёт человеку: представление несёт
  `requiresExplicitUser`. Отказ с комментарием возвращает `commentDelivered: false`.
- Знак GLM в `ProviderIcon` — штриховая «Z» (официального SVG с подходящей лицензией нет), цвет
  карточки нейтральный. `modelRef { provider: 'glm', model: '["zai","glm-5.3"]' }` сохраняется и
  переживает перезагрузку, даже когда runtime GLM недоступен.
