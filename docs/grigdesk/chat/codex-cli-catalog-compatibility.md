# Модель Codex пропала из селекта = урезанный каталог устаревшему CLI, а не снятая модель

Симптом: модель исчезла и из выбора в GrigDesk, и из `/model` в TUI самого Codex, но уже
выбранная в `~/.codex/config.toml` продолжает работать — ходы через неё идут как ни в чём не
бывало. Читается как «модель убрали с аккаунта, конфиг просто ещё держится», и время уходит
на поиск замены и на правку сохранённых чатов.

`model/list` app-server — это **витрина picker, а не список допустимых значений `-m`**, и
состав витрины зависит от версии CLI: устаревшему отдают урезанный набор, хотя бэкенд
по-прежнему принимает `-m <снятый id>`. Проверяется одним дешёвым ходом:
`codex exec --sandbox read-only -m <id> --json "ответь одним словом: ок"`.

Живой случай 21.08.2026, хронология по `fetched_at` и mtime (локальное время):

| время | что |
|---|---|
| 16:35 | последний ход на `gpt-5.6-sol`, CLI 0.145.0 |
| 16:41 | `~/.codex/models_cache.json` перечитан: **6** моделей, `client_version: 0.145.0` — sol пропал |
| 16:44 | прямой `model/list` подтверждает 6 записей, при этом `codex exec -m gpt-5.6-sol` отрабатывает |
| 16:47 | обновлён пакет `@openai/codex` до 0.149.0 |
| 16:55 | кэш перечитан: **9** моделей, sol снова `isDefault: true` |

Вернулись заодно `gpt-5.4` и `gpt-5.3-codex-spark` — урезали не одну модель, а витрину целиком.

Поэтому первый вопрос при пропаже модели — **версия CLI**, а не судьба модели: `codex --version`
против `client_version`/`fetched_at` в `~/.codex/models_cache.json`. Индикатор «доступно
обновление» на этот вопрос вовремя не отвечает: проверка npm идёт раз в 6 часов, а сеть флапает
(в том же замере `registry.npmjs.org` не ответил вовсе). Сама пропавшая модель и есть повод
проверить версию.

Ручная запись `custom: true` в `<папка данных>/state/models.json` — крайний путь на случай, когда
обновление не помогло: она переживает пересборку каталога, но помечается `unknown: true`
и обещает выбор, которого может уже не быть.
