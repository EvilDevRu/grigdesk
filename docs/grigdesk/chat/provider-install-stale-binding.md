# Установка после удаления прежнего пути

Если абсолютный путь выбранного CLI отсутствует, а терминал видит другую
доказанную npm-копию, обычная кнопка «Установить» обслуживает эту оставшуюся
копию на месте. Preview показывает её prefix, версию, заменяемые файлы и снятие
устаревшей привязки в `.env`. При отсутствии оставшейся копии используется
обычный пользовательский prefix npm.

Подготовка не меняет настройки. Старт проверяет отпечаток отсутствующего пути:
появившийся там файл требует нового подтверждения. После проверки установленной
версии и выбора терминала снимается только прежняя привязка, с проверкой значения
в `.env`; новый выбор человека сохраняется. Данные аккаунта и shell rc не входят
в изменения.

Две существующие копии по-прежнему дают отдельную причину `cli_selection_conflict`.
Она больше не переводится как «имя команды занято»: этот текст относится только
к занятому файлу назначения. Отдельной команды массового переноса установок в
релизном интерфейсе и API нет.

Проверки: `provider-lifecycle-service.test.js` воспроизводит отсутствующую
привязку, появление файла после preview и конфликт двух существующих копий.
`officialLifecycleSmoke.mjs` повторяет установку с отсутствующей привязкой
после полного цикла настоящего npm-пакета в изолированных HOME и prefix.

Для Kimi проверен цикл npm `2.3.1 → 2.3.3 → reinstall → uninstall → install`,
затем обычная установка с отсутствующей привязкой. `postinstall` и все пять
его модулей у 2.3.1 побайтно совпали с проверенным профилем 2.3.3; в
`npmReviewedHooks.json` добавлены отдельные версия и integrity tarball 2.3.1.
Неизвестные версии и изменённые скрипты по-прежнему не проходят проверку.
