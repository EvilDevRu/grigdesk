# Цельные текстовые блоки Qwen

ACP передаёт `agent_thought_chunk` и `agent_message_chunk` как дельты. Один ответ
мог стать десятками карточек «Размышление» и строк с отдельными словами, поскольку
адаптер отправлял каждую дельту непосредственно в общий sink как готовый шаг.

`qwen/steps.ts:createQwenTextSteps` накапливает дельты размышления и ответа в отдельных
буферах до явной границы. ACP может чередовать каналы даже посреди слова: закрытие
блока при каждой смене рода текста превращало «Компоненты настоящие» в отдельные
реплики «Компоненты настоя» и «щие». Повторная сборка одного канала сохраняет пробелы
и переводы строк независимо от дельт другого. Пустой текст и служебные metadata-события
не разрывают блоки. Первый update нового инструмента закрывает блоки его участника;
поздние результаты, heartbeat и досылка аргументов не разрезают текущую генерацию.
Запрос разрешения закрывает поток владельца инструмента. Drain уточнений закрывает
только основной поток: повторный drain после прерывания может отделять уже полученный
текст даже с пустой очередью. Final guard проверяет допуск, не меняя текстовые буферы.

Время и порядок блоков определяют первые дельты каждого канала; id обозначает смысловой
блок. Память каждого буфера ограничена `STEP_THINK_LIMIT` либо `STEP_TEXT_LIMIT`
с маркером сокращения. Обычный ход и фоновый коллектор используют одну сборку. Полный
ответ собирается runtime отдельно и этим ограничением не обрезается. Завершение,
ошибка и отмена выпускают хвост ровно один раз; replay загрузки сессии остаётся скрытым.
Перед prompt публикуется `start` с подтверждённой моделью, папкой и режимом.

`createQwenSteps` разделяет потоки по native `_meta.parentToolCallId`: текст и
размышления каждого ребёнка имеют отдельные буферы, инструменты и результаты сохраняют
`parent` даже в sparse updates. Завершение вызова Agent выпускает хвост только его ребёнка.
При ошибке, отмене и завершении хода выпускаются все оставшиеся потоки ровно один раз.
Без этого разделения инструменты одного субагента разрезали слова другого, а их ответы
склеивались с основным. Native-журнал содержал цельный текст, история GrigDesk — обрывки.

В чате законченный текстовый блок основного агента также публикуется как `onAssistantMessage` с тем же
id. Реплика видна отдельно от свёрнутых шагов; последний полный блок становится
финальным ответом. Предыдущие ответы в том же ходе остаются в журнале и не дублируются
в финале. Без callback публикации, например у factory runner, результат сохраняет
собранный текст основного агента за весь ход. Тексты детей остаются ограниченными
предпросмотрами шагов под своим Agent; они не публикуются как самостоятельные ответы
основного агента и не подменяют финал. [Доставка уточнений](qwen-in-turn.md).

## Старые сохранённые ответы

Qwen объявляет `legacyTextStepDeltas`; `/api/providers` передаёт этот признак в
`capabilities`. Общая лента склеивает соседние `think` или `text` без id только при
этом признаке. Граница инструмента и другой род шага сохраняются; новые блоки с id
не склеиваются. Ветвления Vue по вендору нет.

Прежние чередующиеся блоки с id автоматически не пересобираются: их сохранённые
реплики уже опубликованы отдельно. Исправленная сборка применяется к новым ходам
после обновления и ручного перезапуска сервера.

Это проекция отображения: JSON истории и тексты реплик не переписываются. Существующие
длительности и ключ первой строки сохраняются; раскрытие не теряется при пересчёте.
Без capability поведение остальных исполнителей остаётся прежним.

Проверки: `qwen-stream.test.js`, `qwen-runtime.test.js`, `qwen-provider.test.js`,
`qwen-cli-contract.test.js`, `qwen-tool-feed.test.js` и `step-list.test.js`. Они покрывают живую и сохранённую ленту,
лимиты, ошибку потока, отмену, reader lease и отображение прежних токеновых шагов.
Форматирование строк и итогов инструментов — [acp-tool-feed.md](acp-tool-feed.md).
`qwen-subagent-stream.test.js` воспроизводит параллельный текст двух детей, sparse
результаты инструментов, вложенность и завершение; одинаковый сценарий проверяет
foreground и background. Native-проверка подтверждает настоящую метку parent текста
ребёнка и отсутствие его текста в основном ответе.
Тест настоящего CLI с локальным API отдельно чередует `reasoning_content` и `content`
посреди слов и проверяет цельные шаги, одну опубликованную реплику и финальный ответ.
Оплаченная модель и текущий разговор пользователя этой проверкой не затрагиваются.
