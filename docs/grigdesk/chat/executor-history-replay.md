# История для исполнителя с новым процессом на ход

Перед executor ядро синхронизирует канонические сообщения и pending под lock истории.
Возвращённая свежая запись используется для `chatHistory`: в ней уже есть ответ
предыдущего хода, даже если вкладка закрыта и PUT истории/ACK pending не выполнялись.

`historyBeforeTurn` отрезает текущую user-реплику по turnId и более поздние сообщения
очереди. Текущий message передаётся отдельно, со служебным контекстом ядра.
Для legacy без turnId удаляется только совпавшая последняя user-реплика.

Адаптер с fresh-процессом воспроизводит эту историю как данные, не исполняя прежние
tool calls. Собственное хранилище разговора ему не нужно. Барьер и срез истории
общие для исполнителей; vendor-условий в ядре нет. Сквозная проверка GigaCode
с настоящим store покрывает очередь A → B и восстановление ответа после F5.
