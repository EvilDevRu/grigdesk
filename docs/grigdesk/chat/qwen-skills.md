# Общие навыки Qwen в чате и песочнице

Адаптер Qwen публикует в `commands()` пользовательские bundles
`~/.agents/skills/<каталог>/SKILL.md`. Это тот же каталог, куда сервер доставляет
встроенные навыки и откуда их берут GLM и DeepSeek. Меню `/` показывает имя и описание
с `kind: 'skill'`, `run: 'prompt'`; отдельного реестра имён нет.

`skills/userSkillCommands.ts` содержит общий сканер metadata. Qwen включает
`bundlesOnly`, поскольку его CLI не загружает плоские Markdown-файлы как навыки.
Поддерживаются ссылки на каталоги навыков; повреждённые записи пропускаются.
`user-invocable: false` скрывает пункт меню, `disable-model-invocation: true`
оставляет явный вызов. Меню использует общую строгую проверку имени и invocation-полей
[сканера Harness](harness-skill-menu.md); тела и native-поля читает Qwen.

## Передача в песочницу

Перед ходом чата `qwen/skills.ts` разрешает физический общий каталог и цели ссылок
на bundles с `SKILL.md`. Runtime добавляет их в `readonlyRoots` серверного guard.
Sandbox передаёт каталог через native `skills.directories`, а выданные read-only пути —
через `context.includeDirectories`, чтобы CLI мог читать справочники и скрипты навыков.
Пользовательские настройки и исходные навыки не переписываются.

bwrap монтирует эти каталоги только для чтения после writable рабочих корней.
Повторный mount того же назначения может сузить доступ с записи до чтения.
Поэтому навык не становится изменяемым, даже когда его каталог выбран рабочей папкой.
Соседний home не монтируется; вложенная ссылка на невыданный внешний файл не расширяет
доступ. Shell также остаётся внутри mounts. Навык не меняет режим подтверждений,
запрет SSH или рабочие корни записи.

Передача общего каталога добавлена для sandbox-чатов. Factory сохраняет прежние
источники, а Host продолжает использовать native пользовательские настройки.
Каталог читается заново при следующем ходе; пересборка `/api/providers` обновляет меню.
Навыки только из другой рабочей папки или личных каталогов других CLI в глобальное
меню не добавляются.

## Вызов из меню

Навык отправляется обычным сообщением без служебного `slashCommand`. Общий маршрут
чата распознаёт явное `/имя` по `commands()` и оставляет его в начале prompt:
native ACP раскрывает slash-навык только там. Контекст страницы, задача, вложения,
подсказки, запрос названия и выжимка памяти сохраняются после пользовательского текста.
Неизвестная команда не получает специальной обработки. Это общий контракт навыков,
без ветвления ядра чата по исполнителю.

## Проверка

`harness-skill-commands.test.js` проверяет metadata, ссылки, скрытые и явно вызываемые
навыки, пропуск flat-файлов и обновление списка. `chat-slash-commands.test.js` проверяет
обычный маршрут сообщения с UI-контекстом и запросом названия.
`chat-slash-menu.component.test.js` монтирует ChatSession: поиск и выбор навыка Qwen
отправляют обычный ход вместе с вложениями.

`qwen-skills-native.test.js` проверен с настоящим CLI 0.27.3, bwrap и локальным
синтетическим API: каталог в запросе модели, загрузка Skill, чтение ресурса по ссылке,
отказ записи инструментом и shell, закрытый соседний секрет и раскрытие явного
slash-навыка с аргументами и подсказками. Проверен также read-only при совпадении
навыка с workspace. Реальный аккаунт и платные запросы не используются.
Проверка живого меню установленного сервера требует ручного перезапуска после правок;
компонентная проверка её не заменяет.
