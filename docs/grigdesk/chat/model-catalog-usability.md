# Пригодность моделей для чата и порядок свежести

Краткий список выбора показывает только модели, пригодные для текстового чата,
и ставит свежие выше прежних. Правило общее для всех исполнителей: пригодность и
свежесть — данные каталога, а не ветвление по вендору в ядре чата или Vue.

## Нечат-модели

- Признак `nonChat` с причиной `nonChatReason` объявляют данные каталога.
  Источники по приоритету: явная выходная модальность сервиса (`architecture.output_modalities`
  без `text` — например, OpenRouter), затем таблица семейств Qwen
  (`server/src/lib/qwen/modelClassification.ts`), затем ручная `custom`-запись
  `models.json`, которая перекрывает живой каталог.
- Таблица семейств — декларативные данные: видео (`wan*`, `happyhorse-*`),
  изображения (`wan*-image*`, `wanx*`, `qwen-image*`), синтез речи (`*-tts-*`,
  `cosyvoice*`, `sambert*`), распознавание (`*-asr-*`, `paraformer*`, `sensevoice*`),
  realtime (`*-realtime*`), эмбеддинги и реранжирование. Новая версия известного
  семейства попадает под то же правило; новое семейство добавляется одной строкой
  данных. Глоб сверяется с голым id без учёта регистра.
- Неизвестная модель остаётся чатовой (fail-open, продуктовое решение 2026-11-12):
  каталог обещает появление новых моделей без правки кода, а ошибочно скрытая
  полезная модель хуже видимой лишней.
- Реестр (`resolveRuntimeModels`) помечает нечат-модель `extra: true`: краткий
  список её не показывает, «Показывать все модели» показывает с причиной.
  Запуск отвергает сервер в `resolveModelTarget` кодом `non_chat_model` с причиной
  из каталога — до очереди, binding и session state.
- В выборе чата, арбитра и плагинов нечат-вариант запрещён (`disabled`) и помечен
  «не для чата»; причина доступна в подсказке. Сохранённый выбор не меняется сам.

## Что доказал настоящий CLI

Зонд metadata настоящего CLI 0.27.2 на синтетическом loopback API (без платных
запросов) показал: `availableModels[]` отдаёт `description: null`, а
`_meta.modalities` описывает только входные модальности (например, `image`/`video`
у `qwen3.7-plus`). Видео-, TTS- и embedding-id CLI подтверждает как обычные
чатовые маршруты с общим окном 200k и не объявляет их выходную модальность.
Поэтому пригодность нельзя вывести из подтверждения CLI — её объявляют данные.
Сам CLI маршрутизирует такие модели только через ручные флаги `modelProviders`
(`imageOnly`, `realtimeOnly`), которые автоматический каталог не проставляет.

## Свежесть и порядок

- `createdAt` записи приходит из `created` ответа сервиса (Unix-время, проверяется
  на конечность и диапазон) и нормализуется в ISO. Отсутствие или мусор даты
  не выдумывает свежесть.
- Если сервис не объявляет дату, реестр ставит `firstSeen` — момент первого
  наблюдения записи (`mergeCatalogModel`). Штамп персистит в `models.json`
  и переживает пересборки; «свежая» в этом случае значит новая в каталоге,
  а не дата релиза вендора.
- Единый порядок `resolveRuntimeModels`: `tier` по убыванию, затем свежесть
  (`createdAt` сильнее `firstSeen`) по убыванию, затем `id` для детерминизма.
  Порядок ответа сервиса больше не определяет положение модели.
- `CATALOG_SCHEMA` поднят до 13: работающие экземпляры пересобирают каталог
  по новым правилам отбора и порядка.

## Границы проверки

Автоматически проверены: классификация семейств, маркировка модальности и `created`
в discovery без утечки признаков в settings CLI, `extra` и порядок реестра,
сохранение `firstSeen`, отказ запуска `non_chat_model` через настоящий chat API
и запрещённый вариант в селекте чата. Ответ живого сервиса с полем `created`
и оплаченный smoke не проверялись: если сервис дату не отдаёт, порядок задаёт
`firstSeen`.

Проверки: `tests/server/qwen-model-classification.test.js`,
`tests/server/qwen-discovery.test.js`, `tests/server/models-registry.test.js`,
`tests/server/chat-provider-routing.test.js`,
`tests/web/chat-model-availability.component.test.js`.
