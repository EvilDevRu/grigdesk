# Стоп и падение GLM: что гарантировано

- Стоп до запуска процесса, во время привязки сессии и до prompt — ни одного prompt; каталог
  запуска удаляется, процесс завершается.
- Стоп во время инструмента или ожидания approval: ход завершается `stopped`, начатая команда
  дальше не выполняется (процесс runtime завершён), поздний ответ на approval — отказ.
- Остановка binary web использует собственную process group и бюджеты 6+2 с:
  [binary lifecycle](deepseek-binary-lifecycle.md). Эскалация и неподтверждённый disposal
  дают cleanup отказ, каталог запуска сохраняется. Штатный stop удаляет каталог запуска,
  сохраняя home и журнал. Legacy embedded web сохраняет ожидание 2 с и SIGKILL своего процесса.
- Падение runtime после эффекта инструмента: ход завершается `glm_ambiguous_outcome`, повтора нет.
  Если binary lifecycle не подтверждает штатную очистку (в том числе после `SIGKILL`),
  внешний код — `deepseek_binary_cleanup`; первичный отказ остаётся в `cause`.
  При следующем явном ходе DSH восстанавливает журнал и сообщает модели, что исход вызова неизвестен
  (повторять только идемпотентное, иначе проверить состояние или спросить человека). Сам runtime
  эффект не повторяет; повтор возможен только как новое решение модели — новый `callId`, новый
  проход native gate политики (legacy Factory/ACP — hook).
- Принятый, но не отвеченный prompt после падения заново не отправляется: следующий явный ход
  уходит модели со своим сообщением.
