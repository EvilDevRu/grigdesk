# npm-установка из GrigDesk и обычный терминал

В packaged-режиме `shared/node/packagedEnvironment.ts` задаёт дочерним процессам
`npm_config_prefix=D/state/npm-global`, если окружение не содержит допустимого
абсолютного prefix вне серверного комплекта. Здесь D — папка данных GrigDesk.
Это защищает проверенный комплект от изменений глобальными npm-командами.
Новая политика относится только к явно запрошенной установке внешнего CLI:
операция снимает этот защитный prefix и использует внешний пользовательский каталог.
Helpers, плагины, встроенный PTY и стартовый discovery сохраняют прежнее окружение.

## Независимая проверка Bash

Поддержана только абсолютная `SHELL`, чей realpath является Bash. Интерактивная и login-форма
запускаются обычными `-ic`/`-lic` без `--norc` и без дополнительного source. PATH этих
probes фиксирован: `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`; в нём нет
папок данных и поставки, выбранного Node и обнаруженных сервером nvm-каталогов. HOME, USER,
LOGNAME, SHELL, locale и пользовательские параметры сохраняются, а `BASH_ENV`, `ENV`,
`GRIGDESK_*` и защитный npm-prefix снимаются. Startup-файлы сами должны сформировать
пользовательское окружение.

Протокол — ровно 11 строковых полей через NUL с завершающим NUL: версия, nonce, статус,
PATH, вид node, путь node, вид npm, путь npm, вид имени CLI, путь имени CLI, effective prefix.
Bash пишет их builtin `printf` в файл scratch-каталога операции, поэтому шум rc не считается
ответом, а Node внутри комплекта не нужен. Сервер проверяет версию, nonce, количество, enum
и предел 64 КиБ; stdout/stderr ограничены и не журналируются. Probe ограничен 15 секундами
и отменяется вместе со своей группой процессов. Зависание или повреждённый протокол
деградируют в окружение из env-копии с предупреждением `shell_probe_failed` и
`terminal=needs_setup`, а не блокируют установку пакета.

Alias или function для npm/node — отказ автоматической npm-ветки: `type -P` молча не обходит
их. Для неподдержанной оболочки startup не выполняется, npm/Node берутся из env-копии,
а результат — `terminal=manual/needs_setup` с каталогом и ручной инструкцией.
Zsh и Fish автоматически не изменяются.

## Управляемый блок PATH

После core commit пишутся интерактивный `.bashrc` и эффективный login-файл: существующий
`.bash_profile`, иначе `.bash_login`, иначе `.profile`. Новый `.bash_profile` поверх
существующей логики `.profile` не создаётся. Один блок
`# >>> GrigDesk external CLI PATH >>>` … `# <<< GrigDesk external CLI PATH <<<`
содержит объединение активных внешних bin-каталогов; источник актуальности — текущие
npm-bindings адаптеров, поэтому неактивный прежний prefix из блока исчезает. Каждый каталог
включён один раз; повторное применение не наращивает PATH, а чужой PATH сохраняется.
Сначала пробуется порядок «новый каталог, затем прочие», затем перестановки: порядок
выбирается только если каждое управляемое имя разрешается в свой bin. Невыполнимый порядок,
повреждённый или продублированный блок, symlink и read-only rc — конфликт/ручная настройка,
файл при этом не перезаписывается.

Writer сверяет bytes+mode+identity цели, пишет временный файл в том же каталоге, делает fsync
и rename, затем fsync каталога. Режим существующего файла сохраняется, режим HOME и родителя
не меняется, приватный writer состояния к shell-файлам не применяется. Конкурентное изменение
оставляет чужой файл. После записи обе формы Bash проверяются снова: отсутствие alias/function,
путь команды, realpath npm-entry и буквальный запуск `<имя> --version` в этой оболочке.
Только два успешных запуска дают `terminal=ready`; неподдержанная shell, неудачный writer,
ранний return rc и ненайденная команда дают `needs_setup`, чужое имя — `conflict`.
Это не откатывает уже подключённую npm-копию.

Login-команда строится из безопасно экранированного нового абсолютного bin и
декларативных `loginArgs` адаптера. Без `loginArgs` сохраняется прежняя `loginCommand`.
Enter не отправляется ни установкой, ни входом.

Проверки: `provider-install-bash-environment.test.js` (протокол, baseline, alias/function,
timeout, чужой SHELL) и `provider-install-bash-path.test.js` (блок, union, порядок,
симметрия login, пробелы в путях, конкурентная правка, ранний return, настоящий запуск CLI).
`providers-install-external-shell.test.js` проверяет ту же границу настоящим npm и двумя Bash.
