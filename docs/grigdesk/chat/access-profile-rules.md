# Правила профилей доступа исполнителя

Профиль доступа принадлежит исполнителю и отличается
от профиля проекта конвейера. Сохранение подключения и его активация — отдельные действия.
Одновременно активен один профиль исполнителя; выбор для отдельного разговора или узла
и одновременная работа разных профилей в первую версию не входят.

## Два режима GLM

Обычный API и Coding Plan — два независимых сохраняемых профиля, даже у одного аккаунта Z.ai.
У каждого свой режим, ключ, маршрут и статистика. Ключ другого режима не служит запасным.
Оба подключения сохраняются в списке, активным может быть одно.

## Повторный вход DeepSeek

Ответ баланса DeepSeek не содержит подтверждённой идентичности аккаунта. При повторном
вводе ключа показывается: «Аккаунт не удалось определить; новый ключ может относиться
к другому аккаунту». До явного подтверждения прежний доступ не заменяется.

Подтверждение сохраняет идентификатор профиля и историю чата, но требует новой native-сессии
с объяснением потери памяти. Отмена не меняет доступ и память. Повторный вход в неактивный
профиль не активирует его. Хэш ключа не доказывает принадлежность аккаунта.

Для GLM API сравнение использует приватный customerNumber. Известный тот же аккаунт
и неизвестный аккаунт DeepSeek — разные случаи; обновление токена не доказывает смену аккаунта.

## Серверное хранение

Контракт `accessProfiles` принадлежит адаптеру. Серверные маршруты
`/api/providers/:id/access-profiles` используют приватное хранилище
`state/access-profiles/<исполнитель>`: отдельные неизменяемые ревизии credentials и один
атомарно записываемый manifest. Каталоги имеют режим 0700, файлы — 0600.
Публичный список не содержит secretRef, home или account evidence.

Миграция сохраняет исходный `.env` и ссылки на прежние CLI homes. Новые профильные операции
не пишут в `.env`. Прежний маршрут credentials у адаптера с capability возвращает
`409 profile_access_required`; у остальных адаптеров остаётся общий писатель `.env`.

Профильные offline-проверки не подтверждают настоящие CLI-входы, квоты и перенос памяти.
Эти проверки выполняются с владельцем доступа.
