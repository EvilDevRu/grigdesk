# В кратком списке моделей — только свежая версия каждого семейства

- **Правило одно для всех исполнителей.** `resolveRuntimeModels()` в
  `server/src/lib/modelsRegistry.ts` прогоняет runtime-копию каталога через
  `markSupersededModels()` из `shared/chat/modelFamily.ts`: в каждом семействе актуальной
  остаётся одна модель, прежние версии получают `extra: true`. Актуальная выбирается тем же
  правилом, что разрешает ссылку на семейство (`sol` → свежая Sol): не-`extra` сильнее,
  затем больший `tier`. Поэтому модель по умолчанию и разрешение семейства от краткого списка
  не меняются. `models.json` при этом не переписывается.
- **Флаг только добавляется.** Что исполнитель скрыл сам, не всплывает: у Claude бинарь
  помнит исторические id (`KEEP_VERSIONS = 1`), у Codex app-server присылает `hidden` и
  замену `upgrade`. Если скрыта самая свежая запись семейства, актуальной становится следующая.
- **Нечат-модели тоже уходят в `extra`.** Признак `nonChat` с причиной объявляют данные
  каталога: явная модальность сервиса, таблица семейств Qwen, ручная `custom`-запись.
  Краткий список их не показывает, «Показывать все модели» показывает с причиной,
  запуск отвергает сервер кодом `non_chat_model`. Неизвестная модель остаётся чатовой.
  Подробности — [пригодность каталога](model-catalog-usability.md).
- **Порядок — сила, затем свежесть.** При равном `tier` выше свежая запись:
  `createdAt` из `created` сервиса, иначе `firstSeen` реестра (момент первого наблюдения,
  переживает пересборки); равенство разрешает `id`. Порядок ответа сервиса положение
  модели больше не определяет.
- **Семейство должно означать линию версий одной модели.** Его объявляет адаптер (`family` в
  записи или `modelFamily()`). DeepSeek, GLM и Qwen семейства не объявляют: их ACP-каталог его не
  публикует, а общее `default` на все модели правило прочло бы как версии одной и спрятало
  V4-Pro. Политика `FAMILY=default` конвейера живёт в собственном каталоге движка
  (`server/scripts/deepseekRuntimeInfo.mts`) и от этого не зависит. Kimi объявляет
  семейства по `wireModel`, и все они разные. Что K3 заменил K2.7, а V41-Flash — V4-Flash,
  каталоги не говорят, поэтому эти модели остаются в кратком списке. Угадывать по имени нельзя.
  QwenCloud и другие источники Qwen могут отдавать несколько поколений Qwen вместе с
  моделями других разработчиков; все подтверждённые записи остаются видимыми без `family=default`.
- **Форма модели идёт вместе с ней.** Запись с `variantOf: <id>` (у Claude — вариант `[1m]`,
  поднимающий окно 200k → 1M) остаётся видимой, пока видима базовая модель. Вариант у модели
  со встроенным миллионом свёрнут в `modelRefAliases` и отдельным пунктом не бывает.
- **Показывать ли `extra`, решает настройка «Показывать все модели»** (Настройки →
  ИИ-исполнители → Модели, prefs `showAllModels`, отдаётся вместе с `/api/providers`). Фильтрует фронт:
  переключение мгновенное, за списком на сервер не ходим. Выбранную модель не прячем никогда,
  иначе селект теряет значение.
- **Состав списка задаёт каталог**: чего в нём нет, из реестра уходит (иначе он копит всё,
  что когда-либо видел любой CLI). Переживают пересборку только записи с `custom: true` —
  ручные, у них же сохраняются правки имени/окна/эффортов.
