# Абсолютный путь в правах CLI пишется ДВУМЯ слэшами, иначе правило молчит

Симптом: проверяющий узел с политикой `state-only` спокойно правит файлы рабочего дерева
инструментами `Write`/`Edit`, хотя запрет на них в правах стоит и виден в
`agent-settings-<STAGE>.json`. Ловит правку только посмертный сторож — уже после того, как
узел отработал, то есть ценой всего хвоста маршрута.

Причина в диалекте пути. В правилах прав Claude Code путь по умолчанию считается
ОТНОСИТЕЛЬНЫМ каталогу проекта; абсолютный записывается с двумя слэшами:

| форма | что означает |
|---|---|
| `Edit(src/**)` | `<каталог проекта>/src/**` |
| `Edit(/home/user/x/**)` | `<каталог проекта>/home/user/x/**` — почти наверняка не существует |
| `Edit(//home/user/x/**)` | `/home/user/x/**` |

Средняя строка и была багом: правило выглядит осмысленным, читается как абсолютный путь,
но не совпадает ни с чем — и отказа при этом нет, потому что правило формально валидно.
Замер живым `claude -p` (haiku): с `Edit(/tmp/X/proj/**)` агент создал оба запрошенных
файла, с `Edit(//tmp/X/proj/**)` — ответил «нет разрешения на запись» и не создал ни одного.

Цена: 27.08.2026 проверяющий узел вернул env-файл песочницы к версии базовой ветки —
снёс схемы задачи и `REDIS_HOST=redis`, без которого тесты внутри контейнера не видят Redis.
Сторож остановил маршрут кодом 75 за шаг до приёмки. Правило `Write(...)`/`Edit(...)` на
каталоги проекта в правах стояло всё это время.

Две смежные тонкости того же места:

- **`Write(...)` и `NotebookEdit(...)` CLI для файловых проверок не смотрит вовсе.** Он
  говорит это прямо в предупреждении: «only `Edit(path)` rules are... Edit rules cover all
  file-editing tools». Проверено: запрет `Edit(//dir/**)` блокирует именно инструмент
  `Write`. То есть стену держит `Edit`, а две другие формы — украшение.
- **`Read(//**)` в том же файле давно написан верно**, и запрет control root тоже
  (`tool_control="//${CONTROL_DIR#/}"` с явным комментарием про синтаксис). Знание в файле
  было — не доехало до соседнего блока.

Сторож — `tests/engine/unit/route-agent-permissions.sh`: он проверяет и наличие двухслэшевой
формы, и ОТСУТСТВИЕ однослэшевой. Прежняя редакция теста пиннила именно сломанную форму,
поэтому давала ложную уверенность: правило есть, тест зелёный, стены нет.
