# Codex: hooks не заменяют строгие ручные подтверждения

В [официальном контракте hooks](https://learn.chatgpt.com/docs/hooks) описано ограничение:
`PreToolUse` с `permissionDecision: "ask"` пока не реализует ожидание подтверждения.
Такой ответ считается ошибкой hook, после которой вызов инструмента может продолжиться.
Поэтому этот JSON нельзя использовать как механизм «спросить человека перед действием».

Там же указано, что некоторые пути инструментов обходят общий hook path. В частности,
`write_stdin` для уже запущенного unified exec не проходит PreToolUse повторно.
Наблюдение предыдущего запуска не доказывает согласование последующих новых stdin-байтов.
Hooks являются дополнительным контролем; одно наличие enabled hook не доказывает
полноту границы всех действий агента.

Схема установленного Codex 0.164.0 отдельно объявляет native command/file/permissions
approval requests и collaborationMode plan. Наличие этих полей не доказывает запрос
подтверждения каждого действия внутри workspace-write. Такое поведение требует
проверки реального исполнения, включая отсутствие эффекта до ответа и после отказа.

Текущий адаптер GrigDesk использует собственный deny-hook прямого SSH/БД и проверяет
его регистрацию при handshake; этот hook не является общей системой ручных разрешений.
Обычный чат по-прежнему использует native Auto-review. Эффекты ask-hook на этой
установке в рамках проверки документации не запускались: ограничение выше взято из
официального контракта, а не из отчёта выполненного tool turn.
