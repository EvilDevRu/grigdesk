# Предпросмотр разрешений Kimi

Серверный Kimi передаёт `tool_input_display` как объект `ToolInputDisplay`, а прежний
формат мог содержать строку. Преобразование объекта через `String(...)` давало
`[object Object]` одновременно в описании и блоке команды окна разрешения.

`server/src/lib/kimi/serverApproval.ts` переводит запрос в общие поля карточки:

- `command` — точная команда из структурного блока либо прежней строки;
- `description` — строковое описание, summary или action;
- `file_path` — точный путь файла, включая пробелы по краям;
- `details` — содержимое записываемого файла либо подробности generic-блока;
- `diff` — точная пара before/after для diff и file_io/edit, включая пустую сторону.

Незнакомый объект показывается форматированным JSON в подробностях. Адаптер не превращает
объект в строку неявно и не требует знания формата Kimi от Vue или ядра чата.
Тип действия `kind` сохраняет прежние источники `approval.kind/action`: вид предпросмотра
не меняет решение общей политики «Авто». Разрешение, отказ, запоминание на сессию
и пояснение возвращаются прежним протоколом.

Форма сверена с [ToolInputDisplay в исходниках Kimi](https://github.com/MoonshotAI/kimi-code/blob/7ccac2b45b8a3481c76f771bb99c043b562de2c5/packages/agent-core-v2/src/tool/toolInputDisplay.ts).
Проверки: синтетические события через настоящий runtime в `tests/server/kimi-runtime.test.js`
и отображение Write в `tests/web/chat-permission.component.test.js`.

Серверные изменения применяются после ручного перезапуска GrigDesk. Сам исполнитель
из чата сервер не перезапускает; уже открытая карточка остаётся прежним снимком запроса.
