# Лимит страницы истории при восстановлении GLM

При восстановлении длинного разговора `createGlmTreeObserver` дочитывает
ранние события через `session/page` с `maxMessages: 100`. Это число сообщений,
а не событий или байтов: одна страница может содержать сотни records и
превысить 2 МиБ даже при корректном JSON и успешном RPC.

`DeepSeekWebClient.rpc` имеет собственный потоковый читатель тела ответа с
пределом **32 МиБ** (`32 * 1024 * 1024` байта). Один путь чтения используется
и с внешним `AbortSignal`, и без него. Составной сигнал запроса объединяет
внешнюю отмену с таймаутом и прерывает как `fetch`, так и чтение тела через
`reader.cancel()`. После чтения или отказа блокировка reader освобождается.

Превышение 32 МиБ сохраняет публичный контракт: `DeepSeekWebError` с кодом
`deepseek_bad_response`, текстом «DeepSeek web вернул повреждённый RPC-ответ»
и `uncertain = true`. Предел считается по байтам, а не по длине JSON-строки.
Лимит **2 МиБ** (2 097 152 байта) остаётся только у загрузчика схем настроек
`readSettingsJson`; RPC-клиент больше от него не зависит. Корректная страница
истории больше 2 МиБ принимается в пределах собственного лимита RPC.

До исправления RPC с переданным сигналом использовал `readSettingsJson`.
Корректная страница больше 2 МиБ ошибочно считалась повреждённым ответом.

Наблюдатель восстанавливает историю до prompt, поэтому `turnFailure` адаптера
GLM превращал этот отказ в `glm_runtime_start_failed` — «GLM не запустился
до отправки сообщения». Исходная причина в этой ветке не сохраняется.
Новая короткая сессия при этом запускалась успешно.

Воспроизведение на отдельной копии журнала подтвердило HTTP 200, корректный
envelope и превышение именно байтового лимита. Изменение только размера
страниц на `maxMessages: 20` в диагностическом клиенте позволило дочитать
историю и дойти до границы отправки prompt без сброса памяти и обращения
к модели. Это диагностическая проверка, а не изменение product-контракта:
рабочий адаптер продолжает запрашивать 100 сообщений на страницу.

Регрессия покрыта `tests/server/deepseek-server-client.test.js`: страница
3 МиБ с сигналом и без него, байтовый предел 32 МиБ для обоих путей и отмена
сигнала посреди чтения с проверкой вызова `reader.cancel()` и отказа promise.
