# Наличие CLI в топбаре и опросе лимитов

Универсальная карточка появляется в топбаре при `chatEnabled !== false` и хотя бы
одном признаке `available === true` или `installed === true`. Установленный CLI без
авторизации остаётся видимым: приглушённая иконка и подсказка недоступности позволяют
перейти ко входу. Без установленного CLI иконка исчезает. Для узких типов правило
прежнее: требуется `available === true`. Настройки сохраняют полный список карточек.

Перед опросом лимитов CLI сервер использует последний probe реестра либо прошлого
опроса. Результат хранится минуту; после истечения срока выполняется только probe
адаптера, без сборки каталога моделей, авторизации и описи установок. Lifecycle-событие
сбрасывает этот результат адресно. API-адаптеру наличие CLI не требуется.

При `probe.ok === false` сервер не вызывает `usage` и не пишет предупреждение
«usage исполнителя не получен». Удаление вне GrigDesk и удаление через интерфейс
формируют одну запись:

- `state: 'unavailable'`, `stale: true`;
- сообщение «Программа исполнителя удалена. Установи CLI для проверки лимитов.»;
- пустые `bars` и `resources`;
- сохранённые времена замера, `lastSuccessfulAt` и персональный `Retry-After`.

Поля свежести остаются capability адаптера `usagePresentation.freshness`. При первом
обнаружении удаления меняется поколение runtime и снимается живой оверлей. Повторные
тики возвращают тот же снимок: время и поколение не освежаются. До первого успешного
замера `lastSuccessfulAt` равно `null`.

Отсутствие CLI намеренно останавливает и чтение по сохранённым токенам: например,
Claude без бинаря не показывает лимиты даже при живом `~/.claude/.credentials.json`.
Если CLI установлен, отсутствие авторизации обрабатывается адаптером как раньше:
`usage` вызывается и может вернуть `auth_required`. Ошибка выполнения probe сама по
себе не считается доказательством удаления.

Проверки наличия продолжаются. После переустановки очередной probe с `ok: true`
снимает заморозку; ближайший обычный тик возобновляет опрос с соблюдением сохранённого
`Retry-After`. Это относится и к CLI, ранее удалённому через интерфейс. Иконка
возвращается при штатном обновлении реестра окна, без перезапуска сервера.

`tests/server/providers-usage-tick.test.js`,
`tests/web/executor-types.component.test.js`.
