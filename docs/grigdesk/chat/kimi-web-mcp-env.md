# Kimi web: окружение MCP объектом

В host-режиме `buildKimiHostWebHome` создаёт временный home для `kimi web`.
Его `mcp.json` объединяет пользовательские `mcpServers` со служебными MCP текущего
хода, включая `grigdesk-work`. Исходный пользовательский файл не переписывается.

## Формат env

Kimi ожидает `env` как объект со строковыми значениями. Рабочий IPC GrigDesk передаёт
окружение в формате ACP: массив пар `{name, value}`, в том числе пустой `env: []`.
Перед записью служебных серверов host-адаптер приводит его к формату Kimi:

| Вход | Запись в mcp.json |
|---|---|
| Поле отсутствует | Поле `env` отсутствует |
| `env: []` | Поле `env` отсутствует |
| `env: [{name: 'A', value: '1'}]` | `env: {A: '1'}` |
| `env: {A: '1'}` | Тот же объект |
| `env: {}` | Пустой объект сохраняется |

Преобразование выполняет общий серверный модуль `server/src/lib/mcpEnvironment.ts`.
Для ACP-массива он возвращает объект, при повторе имени побеждает последнее значение;
готовый объект возвращает без изменений. Пустой массив даёт `{}`, а решение исключить
поле принимает Kimi host. DeepSeek использует тот же преобразователь и сохраняет
прежнюю запись пустого окружения в своём overlay. Валидация входных значений остаётся
обязанностью вызывающей стороны.

## Симптом и причина

До исправления host-адаптер записывал массив `env` как есть. Kimi отвергал весь
объединённый файл с сообщением `mcp config initial load failed` и пояснением
`expected record, received array`. Поэтому в чате не загружался ни один MCP:
ни `grigdesk-work`, ни пользовательские серверы из исходного `mcp.json`.
Ошибка существовала и в 0.33.0; она независима от heartbeat в 2.3.1.

Исправление относится к host-пути. Contained-путь с `serverMcpFile` не записывает
`env`; его контракт не меняется.

## Проверка и применение

`tests/server/kimi-host-web-home.test.js` проверяет пустой и непустой ACP-массив,
готовый объект, сохранность пользовательского MCP и исходного файла.
`tests/server/deepseek-profile.test.js` проверяет преобразование ACP-окружения,
повтор имени и сохранение прежней сериализации пустого окружения в web-профиле.
Проверки не запускают модель.

Правка вступает в силу после ручного перезапуска GrigDesk. Пересборка web не нужна.
