# Видимость доплаты и пустые ответы

Контракт задачи №93018 дополняет [подключение исполнителей](executor-integration.md#оплата-сверх-подписки).
Карточки доплаты создаёт адаптер после подтверждения настоящих данных, а не компонент UI.

- Kimi: `parseKimiUsageResources` возвращает Extra Usage и «Месячный объём», когда есть
  хотя бы окно лимита или объект кошелька. Ключ `kimi-extra-usage` одинаков у кошелька и
  справочного состояния; `kimi-monthly-volume` всегда без процента и полосы.
  Новая `quota.usages` передаёт месячный расход отдельной полосой; ресурс получает текст
  расхода и составляющую кода. Правила — [форматы квот Kimi](kimi-quota-format.md).
- Codex: `parseCodexUsageResources` допускает карточку без состояния `credits`, если есть
  окно, контроль трат или заработанный сброс. Сама карточка отсутствие данных не подтверждает.
  Ресурс `spend-control` сохраняет собственное условие появления по данным сервиса.
- Ошибка или пустой ответ не создаёт справочных ресурсов и сохраняет прежнюю классификацию.
  `mergeProviderUsage` по-прежнему сохраняет прошлый снимок при сбое с `stale: true` и прежним
  временем данных; успешный новый ответ без кошелька заменяет прежний баланс серой карточкой.
- Общий `ProviderUsageResources` показывает те же карточки в настройках и во всплывашке.
  Ссылки не имеют `scope: 'live'`, поэтому во всплывашке скрыты. Компьютер и телефон получают
  одинаковые ресурсы; новые собственные подписи имеют русский и английский переводы.

Чтение лимитов Kimi остаётся через CLI без доступа GrigDesk к OAuth-ключам и сырому API Kimi.
Управление Claude, баланс DeepSeek и квоты личного GLM Coding Plan эта задача не меняет.
