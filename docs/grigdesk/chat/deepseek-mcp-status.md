# DeepSeek: безопасный список проектных MCP

В «Настройки → Исполнители → DeepSeek» установленный CLI объявляет MCP capability
через настоящий `mcpStatus`, даже если ключ модели не задан. Общий реестр исполнителей
не читает MCP: список получает отдельный `GET /api/providers/deepseek/mcp`.

## Источник и область

[Helper списка](../../../server/src/lib/deepseek/mcpStatus.ts) использует тот же
[reader](../../../server/src/lib/deepseek/projectMcp.ts), что и чатовый запуск.
Для настроек ему передаётся явно заданный абсолютный `config.rootDir` — папка GrigDesk.
Без неё возвращается фиксированная ошибка до чтения файлов. Подстановки `process.cwd()` нет.

Reader объединяет `.mcp.json` ближайшего корня Git и указанной папки; без Git читает
только эту папку. Порядок слоёв и фильтрация совпадают с запуском. Выключенный локальный
дубликат после фильтрации не удаляет одноимённую корневую запись. Изменять эту семантику
нужно отдельно, с регрессиями запуска.

В панели прямо сказано, что другая папка чата может дать другой список. Это диагностика
конфигурации папки GrigDesk, а не обзор всех проектов, глобальных DSH-конфигов или сессий.

## Публичный ответ

Карточка содержит ровно `name`, пустой `target`, `scope: 'project'`,
`state: 'configured'` и пустой `detail`. Имена сортируются по русской локали без
изменения источника. Команда, args, env, пути, `file` и сырые warnings не передаются.
Имя остаётся публичным ключом владельца файла; секрет, помещённый в само имя,
не скрывается. Vue выводит имя обычным текстом, без интерпретации HTML.

Показаны только выбранные для запуска stdio-серверы с найденной executable-командой.
Выключенные записи и служебные `grigdesk-work`/`grigdesk-perm` не получают карточек.
HTTP и повреждённые записи остаются за существующей границей reader.

Успех имеет поля `state: 'ok'`, `note`, `emptyText`, `servers`. Строка «Настроен»
и серый индикатор обозначают наличие конфигурации. Соединение не проверяется,
CLI/MCP не запускаются, runtime, домашний каталог и сессии не создаются, файлы не меняются.

| Результат reader | Что видит человек |
| --- | --- |
| Есть хорошие записи без warnings | Имена, «Настроен» и пояснение области |
| Нет файлов, пустой состав или только выключенные записи без warnings | «Для папки GrigDesk нет MCP-серверов, выбранных для запуска.» и пояснение области |
| Есть хорошие записи и warnings | Те же карточки и нейтральное предупреждение о неполноте чтения или проверки |
| Warnings есть, хороших записей нет | Фиксированная ошибка списка для папки GrigDesk |
| Reader или проекция бросили исключение | Фиксированная ошибка чтения для папки GrigDesk |
| Папка отсутствует, пустая или относительная | Фиксированная ошибка абсолютной папки, без обращения к reader |

Warnings не позволяют точно отличить плохую запись от I/O-ошибки, поэтому helper
не разбирает их текст и не утверждает конкретную причину. Ошибка имеет ровно
`state: 'error'`, `error`, `servers: []`; исходное исключение не публикуется и не
пишется в новый журнал. При такой ошибке HTTP остаётся 200, а панель показывает
ошибку вместо успешного пустого списка.

## Общие границы

[Маршрут providers](../../../server/src/modules/providers/index.ts) добавляет
`checkedAt`, кэширует на прежние 60 секунд и обходит кэш через `?refresh=1`.
Отдельного TTL, store или механизма опроса у DeepSeek нет. Общий auth guard
защищает реестр и MCP до вызова адаптеров и моделей.

Общее необязательное `emptyText` позволяет адаптеру пояснить пустое состояние;
без него сохраняется «Серверов не настроено.». Условия показа панели остаются
`mcp && installed`, без веток по вендору и без требования модельного входа.

Отображение вынесено в общий `ProviderMcpStatus`; страница передаёт снимок store
и обрабатывает `refresh`, сохраняя единственный существующий опрос. Группировка
и scoped CSS принадлежат компоненту. Границы и проверка переноса —
[панель MCP](../web/provider-mcp-panel.md).

Вложенные сетки MCP используют `minmax(0, 1fr)`: длинное имя сокращается внутри
своей строки и сохраняет видимость статуса и пояснения. Без ограничения всех трёх
сеток колонка наследовала минимальную ширину имени и создавала внутренний overflow.
Прокрутка длинного списка по-прежнему ограничена 360 px.

Офлайн-стенд providers подменяет `adaptersOf` и `modelsOf`. Эти источники используются
в MCP GET, проверке версий, сборке и refresh каталога. Default-путь продолжает
вызывать настоящие реализации. Маршрут обновления CLI сохраняет refresh моделей,
но тест MCP не запускает обновление.

## Доказательства

- [Unit- и файловые тесты](../../../tests/server/deepseek-mcp.test.js): проекция,
  безопасные состояния, Git/cwd/PATH, I/O/JSON, сохранение хороших записей,
  побайтная неизменность файлов и executable-marker без запуска.
- [HTTP-тесты](../../../tests/server/providers-mcp-route.test.js): capability настоящего
  адаптера, изоляция синтетическим id, ленивость, кэш A → B, refresh, auth и canary
  во всём JSON ответа.
- [DOM-регрессии](../../../tests/web/settings-mcp.component.test.js): общий `emptyText`,
  недоступная модель, configured/idle, текстовое имя с HTML, ошибки, refresh и
  отсутствие самоперезапуска реактивного асинхронного опроса.
- Геометрия проверяется отдельным Vite/Chrome-стендом настоящего SettingsModal и нативной
  панели на своих fixtures; `tests/web/e2e/settings-modal.e2e.mjs`. DOM-тесты CSS-геометрию не доказывают.

Реальное подключение MCP эти проверки не обещают: страница настроек намеренно его не делает.
