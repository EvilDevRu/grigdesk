# Лента хода агента (как в чате VS Code)

- У ленты один provider-neutral контракт (`lib/chat/streamSteps.ts`): `start`
  (фактическая модель + режим прав), `think`, `text`, `tool` (вызов инструмента с превью по типу:
  команда Bash, файл Read/Write, дифф Edit, запрос Grep…), `res` (результат: ok/ошибка + краткий вывод),
  `note` (ретраи API, компакт, повтор пустого запуска). Общий sink ставит timestamp, режет всё длинное и ограничивает
  ход 400 шагами (хранение скользящее, трансляция безусловна — см. [грабли](turn-feed-broadcast-limit.md)).
  **Вытеснение окна не молчит**: место самого старого шага занимает строка-счётчик
  «… ранние шаги хода скрыты: N». Окно одно на всех — `shared/chatStepsWindow.ts` держит и sink,
  и копию `activeRuns`, и ленту в сторе браузера; три разошедшиеся копии этой арифметики
  выдавали обрезанную ленту за полный отчёт о ходе.
  Каждый executor держит свой normalizer (`_claudeSteps.ts`, `_codexSteps.ts`,
  `_kimiSteps.ts`); новый ИИ добавляет такой же рядом с executor-ом, без условий
  в `modules/chat` или Vue.
- **Незнакомый элемент обязан деградировать в строку, а не исчезать.** Normalizer, который
  перечисляет типы поимённо (так устроен Codex), молча терял и вызов, и его результат на всём,
  чего не было в списке: человек читал ленту как полный отчёт и видел меньше действий, чем
  агент сделал. Общий fallback показывает такой элемент строкой с его типом и подписью из
  первого содержательного поля; события без вызова (сжатие контекста, режим ревью, работа
  субагента) идут `note`. Строка вызова при этом ОБНОВЛЯЕМАЯ: досланные подробности
  (растущий патч) уходят вторым шагом с тем же `id` и накапливаются в ней, а не заводят вторую
  строку; пустое поле поздней версии прежнее значение не затирает (`item/completed` у Codex
  часто приходит без аргументов).
- Вложенность шага (субагент `Agent`/`Task` у Claude) — поле `parent` с id родительского вызова; по нему
  `StepList` рисует шаг вложенным. `sub` — только строка-подпись (путь файла, сервер MCP,
  пространство имён), она показывается в раскрытии. Раньше вложенность ехала булевым `sub`, и
  `describeTool` перекрывал её путём: `Edit` в корне хода выглядел вложенным, а у вложенного Bash
  в раскрытии стояло «true». Старые сохранённые ленты с `sub: true` `StepList` читает как
  вложенные, но путём не показывает.
- У tool-шага есть необязательное поле `files: string[]` — нормализованные пути файлов,
  которые инструмент изменил (Claude Write/Edit, Codex `fileChange`, Kimi Edit), и rich-форма `changes: [{path, kind, diff}]`. `diff` бывает unified
  patch от Codex либо точной парой `{old,new}` из ACP Kimi. **У app-server patch лежит в
  `diff` только у `update`: для `add`/`delete` там содержимое файла целиком**, без единого
  знака строки — нормализатор Codex (`patchOf`) разворачивает его в один hunk с нужным
  знаком (`@@ -0,0 +1,N @@` / `@@ -1,N +0,0 @@`). Пока он читался как patch, созданный файл
  показывался «+0 −0»: строки без отступа терялись, строки с отступом шли контекстом в обе
  колонки. Ленты, сохранённые до этой нормализации, `unifiedDiff(patch, kind)` на фронте
  всё равно раскладывает по нужной стороне, а серверный разрыв «… сокращено …» рисует
  отдельной строкой, а не склеивает половины. Один шаг хранит не более 20
  файлов и 16 КиБ diff-текста; пропущенный хвост явно отмечается `omittedChanges` и `preview`.
  Заполнять контракт обязаны все четыре встроенных адаптера одинаково; из `preview` пути
  не восстанавливаются. Поле `files` читает серверный подсчёт
  правленых файлов (строка итога Telegram-пульта): учитываются только шаги с
  успешным `res`, дубли путей схлопываются.
- **У общего sink размышления свой лимит — `STEP_THINK_LIMIT` 6000 символов** против
  `STEP_TEXT_LIMIT` 1200 у остального текста (`STEP_DIFF_LIMIT` 2000 на кусок диффа).
  Executor вправе передать уже bounded preview; общий sink не увеличивает его обратно.
  Общие 1200 резали рассуждение на первом же абзаце, и в ленте оставался огрызок фразы:
  со стороны это выглядело как «размышлений не видно вовсе» — ровно та жалоба, с которой
  лимит и развели.
  Размышление — единственный шаг, который человек читает целиком, а не проглядывает.
- Путь: `executor run(onStep)` → `modules/chat` → SSE `chat-step {chatKey, step}` → стор копит в
  `sess.steps` → `views/chat/StepList.vue`. Claude читает свой stream-json, Codex — JSON-RPC
  notifications app-server по мере прихода. Его normalizer склеивает delta-события agent message,
  reasoning summary и command output, а multi-file patch берёт из `fileChange.changes` /
  `item/fileChange/patchUpdated`. Правка показывается уже по `item/started` (патч к этому моменту
  на диске: ожидание `item/completed` прятало применённую правку у оборванного хода целиком).
  Показывается только опубликованное summary;
  `item/reasoning/textDelta` и legacy `raw_content` намеренно игнорируются. Служебные уведомления
  хода лента объявляет своими `note`: подменённая модель (`model/rerouted`), сжатие контекста,
  предупреждения и сетевой ретрай — у последнего берётся `error.message` и `willRetry`, а не
  весь объект `TurnError` целиком, иначе штатный ретрай читается сырым JSON и выглядит поломкой.
  Копия шагов лежит в `activeRuns`, поэтому F5 посреди хода не теряет уже показанное
  (`GET /api/chat/active` отдаёт `steps`).
- **Развёрнутое Codex summary** запрашивается через thread config
  `model_reasoning_summary: "detailed"` и `turn/start.summary: "detailed"`. Дефолтное summary
  у CLI короткое; приватную цепочку этот режим не включает. Объём размышления в ленте задаёт модель, а
  не режим: у gpt-6-astra (и gpt-6-sol, gpt-5.6-sol) это с сентября 2026 только заголовок `**…**` около
  50 знаков при `auto`, `detailed` и `none`, у gpt-6.1-sol — абзацы до ~2,3 тыс. знаков. С Codex CLI
  0.162.1 (с 10.10.2026) `turn_context.summary` в ходах GrigDesk — `"none"`, но gpt-6.1-sol и с ним
  присылает развёрнутые summary. Kimi ACP присылает sparse lifecycle
  `tool_call`/`tool_call_update`: stateful normalizer копит состояние по `toolCallId`, ждёт
  canonical upgrade либо terminal fallback и выпускает ровно один `tool` и один `res`.
  `agent_thought_chunk` склеивается в один `think` перед следующим действием или в конце хода;
  у Claude размышление приходит блоками `thinking` потока.
- После ответа лента переезжает в сообщение (`msg.steps`) и показывается свёрнутой строкой
  «Ход агента: N действ. · M размышл.». У ходов с отдельными блоками ответов интерфейс
  делит её на участки между репликами, сохраняя [порядок переписки](conversation-timeline.md).
  Старт остаётся перед первым ответом, каждый участок действий сворачивается на своём месте.
  Упавший ход ленту тоже сохраняет: сервер отдаёт при
  ошибке только текст, поэтому стор кладёт в сообщение `role: error` то, что успело доехать по
  SSE, — иначе по чему разбираться, докуда агент дошёл. `StepList` предпочитает `changes`,
  показывает отдельный блок для каждого файла, разбирает unified patch и суммирует статистику.
  Старый `diff: {old,new}` остаётся fallback и строится LCS; оба варианта рисуются В ДВЕ КОЛОНКИ —
  слева «было», справа «стало» (`splitRows`: подряд идущие del/add ставятся друг напротив друга,
  лишние строки получают пустого соседа; свыше 400 строк LCS вырождается в полный replace).
  Осиротевший `res` (его `tool` вытеснило окно) рисуется своей строкой «Итог», а не пустотой.
- **Всплывашки держим компактными** — они живут над композером и не должны съедать экран:
  у разрешения кнопки в строке заголовка, команда — блоком с переносами; у вопроса варианты —
  строками с пояснением, поле своего ответа скрыто за пунктом «свой ответ…»; вся плашка
  ограничена по высоте со скроллом (`max-height: 38vh`).
- Время размышления («думал 12 с») считается по `at` соседних шагов — от предыдущего шага к `think`:
  блок размышления приходит уже готовым, поэтому его длительность — это пауза ПЕРЕД ним.
  Используется исходный порядок прихода до [расстановки детей под вызовом](subagent-step-placement.md).
- Подряд идущие одинаковые `note` схлопываются в одну строку с «×N» (ретраи сети идут сериями).
- **Пустой запуск повторяется один раз, и лента об этом ГОВОРИТ.** Ход, в котором не было
  ни одного обращения к модели (`emptyRun`), GrigDesk запускает заново — границу повтора объявляет
  сам executor (`lib/chat/retryContract.ts`). Человек при этом видит два `start` подряд, поэтому
  между ними `modules/chat` ставит свой `note` уровня `warn` («Пустой запуск: агент не сделал ни
  шага — повторяю ход»): у адаптера такого события нет, а лента обязана объяснять собственные
  строки. Сохранённая лента склеивает обе попытки — шаги пустого запуска, отметка, шаги повтора,
  — чтобы история совпала с показанным живьём. Служебная отметка идёт мимо аттестации озвучки:
  она не шаг исполнителя и `speechSafe` не снимает.
