# Установка Qwen: проверенный hook микрофонного backend

Штатная npm-установка Qwen проходит общий
[gate проверки installer-хуков](provider-install-hooks-review-gate.md).
Для Linux x64 графа `@qwen-code/qwen-code@0.27.2` обнаружены 14 пакетов и один
пакет с install-хуком: `@qwen-code/audio-capture@0.27.2`.
Без его проверенного профиля prepare возвращает `installer_strategy_unverified`.

## Отказ подготовки 0.27.3

Проверка 13.11.2026 на скачанном с `--ignore-scripts` графе Qwen 0.27.3
воспроизводила `installer_strategy_unverified` для `@qwen-code/audio-capture@0.27.3`.
В графе 14 пакетов; единственный пакет с установочным кодом — audio-capture.
Команда `node install.js` и семь из десяти закреплённых файлов совпадают с профилем
0.27.2. Отличаются три prebuild: `darwin-arm64`, `darwin-x64` и `win32-x64`.
Linux prebuild, `install.js`, `binding.gyp` и native-исходники совпадают.
Gate проверяет весь профиль, поэтому до добавления нового профиля изменения
чужой платформы также блокировали Linux-подготовку.
Добавление нового профиля требует отдельной проверки изменившихся бинарных файлов;
совпадение Linux-байтов само по себе не разрешает пакет целиком.

Скачивание inspection-пакета завершается успешно, затем отказ возникает до
`graphIdentity`, offline-прогона и изменения пользовательской установки.
Прежний `lifecycleFailure` сохранял код, но заменял его сообщение общим
«Подготовка операции не удалась»: непустой общий текст скрывал перевод кода.
Исправленный сервис передаёт для этого отказа пустой `message`, и клиент показывает
существующую понятную причину на языке окна. Подробные собственные сообщения
сервиса сохраняются, сторонний текст неизвестной ошибки не раскрывается.

## Аудит различий 0.27.3

Повторная загрузка `@qwen-code/audio-capture` обеих версий из npm подтверждает
SHA-512 tarball, подписи реестра и Sigstore provenance с identity официального
`.github/workflows/release.yml` репозитория QwenLM/qwen-code.
Subject provenance совпадает с SHA-512 скачанного архива; исходники установщика,
`binding.gyp` и три native-файла совпадают с
[commit публикации](https://github.com/QwenLM/qwen-code/tree/70a487be84b2a14daae21b9c2369b0ad243646dd/packages/audio-capture).
Повторно скачанный пакет также побайтно совпадает с пакетом исходного отказа.

Состав обоих архивов одинаков: 18 файлов. Кроме версии в `package.json` и трёх
prebuild, все файлы побайтно совпадают. Разбор форматов объясняет все отличия:

| Prebuild | Изменённые байты | Изменившиеся поля |
| --- | ---: | --- |
| darwin-arm64 | 48 | UUID сборки и SHA-256 первой страницы в ad-hoc CodeDirectory |
| darwin-x64 | 16 | UUID сборки |
| win32-x64 | 31 | COFF/debug timestamps и CodeView PDB GUID |

После исключения только перечисленных полей бинарники побайтно совпадают;
машинный код, импорты и прочие данные сохраняются. Для ARM64 проверены хеши
всех 171 страниц CodeDirectory обеих версий: изменившийся хеш соответствует
первой странице с новым UUID. Нормализация использовалась только при аудите;
рабочая проверка по-прежнему сравнивает полный SHA-256 каждого файла.

В изолированной пробе реестр профилей дополнен в памяти точным профилем 0.27.3
с новым registry integrity и полными SHA-256 десяти закреплённых файлов.
Реальные `prepareNpmStrategy`, `revalidateNpmStrategy` и `executeNpmStrategy`
прошли с настоящим npm в отдельном prefix и сетевом пространстве без сети.
Версия CLI подтверждена; Linux-addon загружен без запуска записи микрофона.
Изменение одного байта addon с этим профилем сохраняет отказ gate.
Рабочий `npmReviewedHooks.json` при аудите не изменялся. После аудита точный профиль
0.27.3 добавлен рядом с профилем 0.27.2; полный SHA-256 файлов и registry integrity
закреплены отдельно для каждой версии. Та же установка без сети повторно прошла
с рабочим реестром, без подмены массива профилей. Это проверка установки
на Linux, не выполнение бинарников macOS/Windows и не оплаченный smoke модели.

Регрессия `provider-lifecycle-service.test.js` воспроизводит через HTTP отказ
настоящей проверки неизвестного hook и повреждённого графа до старта операции,
сохранение собственной подробной причины и скрытие стороннего текста.
`provider-install-dialog.component.test.js` проверяет перевод обоих кодов на RU/EN
и отсутствие подтверждения или старта после отказа подготовки.

## Что проверено и закреплено

`install.js` запускает `node-gyp-build` без дополнительных команд. Сначала проверяется
готовый addon; при отсутствии рабочего prebuild запускается `node-gyp rebuild`.
Ошибка native backend печатает предупреждение, но сам hook заканчивается кодом 0:
это необязательная возможность голосового ввода внешнего CLI, не транспорт чата GrigDesk.
Загрузка addon регистрирует функции; запись микрофона начинается только явным вызовом.

В `npmReviewedHooks.json` закреплены точная lifecycle-команда, registry integrity пакета
и sha256 десяти файлов: `install.js`, `binding.gyp`, три файла `native/` и пять addon
в `prebuilds/`. Рассмотрены N-API-код, macOS permission helper и выбор prebuild/build
в зависимости `node-gyp-build@4.8.4`. Заголовок `miniaudio.h` побайтно совпадает с
[upstream 0.11.22](https://github.com/mackron/miniaudio/blob/0.11.22/miniaudio.h).

`binding.gyp` содержит исходники и системные библиотеки, без build actions или загрузок.
На Linux используются `dl`, `pthread`, `m`; miniaudio по умолчанию загружает аудиобиблиотеки
динамически. Для сборки нужны Python 3, make, C++ toolchain и заголовки выбранного Node.
macOS и Windows имеют отдельные системные библиотеки в том же проверенном `binding.gyp`;
локальная проверка исполнения и сборки проведена на Linux x64.

## Offline и старт

`npmStrategy.prepareHeaders` готовит локальные заголовки выбранного Node для любого
проверенного пакета с `binding.gyp`, включая fallback Qwen после prebuild. Ограничение
только именем `node-pty` оставляло бы `node-gyp` возможность загружать их при start:
сам `node-gyp` не соблюдает npm `--offline`. При отсутствии подходящих локальных
заголовков prepare возвращает `node_headers_unavailable` до подтверждения операции.
Заголовки входят в snapshot подготовки и передаются как `npm_config_nodedir`.

Prepare скачивает пакет с `--ignore-scripts`, проверяет профиль и фиксирует полный граф
с integrity. Перед start повторяются snapshot, toolchain и offline-проверка графа.
Сама установка выполняется штатным npm offline с включёнными lifecycle scripts;
пользовательская политика npm не переписывается. Проверка scripts не отключается.

Проверены реальные install и reinstall 0.27.2 через эти функции, с отключённой сетью
на revalidate/start: обычный prebuild и принудительная сборка из исходников.
Оба addon загружены без запуска записи, версия CLI подтверждена. Изменение hook,
`binding.gyp`, исходника или prebuild по-прежнему отклоняется gate.
Это проверка установщика в одноразовом prefix; браузерная приёмка карточки
и оплаченный smoke остаются отдельными обязательными проверками.
