# Рабочая папка чата и границы записи

Выбор хранится в `workdir`: `grigdesk`, `project {projectId, repoKey}` или `path {path}`.
Форму проверяет `shared/chat/chatWorkdir.ts`, фактические пути —
`server/src/lib/chat/workdir.ts`. Старый чат без поля означает GrigDesk; явное повреждённое
значение не нормализуется в разрешённую папку. Продуктовый контракт —
[рабочая папка разговора](../guide/chat-workdir.md).

Приоритет: рабочие копии задачи из `parseSandboxRepositories`, репозитории доверенно
связанного проекта задачи, сохранённый выбор. Для проекта основной корень берётся по
явному `repoKey`, затем по `defaultRepoKey`, затем по порядку `projectRepos()`. Неизвестный
ключ, исчезнувший проект, пустой список или невалидный реестр задачи отклоняют запуск.
Выбор архивного проекта запрещён; существующая привязка продолжает работать.

Неизвестный доверенный профиль задачи без tombstone пропускается до сохранённого
выбора папки; подробности — [исчезнувший профиль задачи](task-project-fallback.md).

Удаление регистрации сохраняет исторические корни в приватном `project-workspaces.json`
владельца истории. Снимок проекта содержит ревизию, репозитории и основной ключ и действует
только при следующей ревизии tombstone для сохранённого разговора с тем же проектом.
Рабочие копии задачи остаются первыми. Снимок не участвует в каталоге и новом выборе;
публичное создание разговора и переход к удалённому проекту получают
`409 workdir_unknown_project`. Старые сообщения, шаги и bindings не переписываются.
Штатная материализация legacy сохраняет оба разговора даже при удалении между записями.

Каждый корень проходит realpath, проверку каталога и доступности; `/` и домашний каталог
целиком запрещены. Алиасы остаются в `copies`, физические корни в `extraDirs` не повторяются.
Результат содержит `cwd`, `extraDirs`, `source`, `copies`, предупреждения и `workspaceKey`:
SHA-256 нормализованного выбора, задачи, провайдера, capability и реальных корней. Вложения
добавляются отдельно и в этот ключ не входят. Контекст страницы не задаёт cwd или права.

Адаптер объявляет `workdir: {switch: 'resume'|'reseed', roots: 'multi'|'single'}` либо
функцию от config. Setup-only и сломанная декларация дают `null`. Чистый `validateWorkdir`
позволяет заранее проверить запреты Kimi contained; отвергнутые extras не передаются как
доступные. Ограничение single-root оставляет cwd неизменным, без общего предка.

Свободный legacy-вызов без chatKey работает из `config.rootDir`, задачный — по тем же
доверенным источникам задачи. С chatKey выбор читает сервер; несовпадение taskId маршрута
даёт `409 stale_chat_workdir`. Новый клиент передаёт ожидаемые workdir/workspaceKey; сервер
сверяет их до приёма и заново под блокировкой после ожидания в очереди.

Глобальный список `prefs.trustedDirectories` удалён из UI, API и запуска. Старое поле
игнорируется при чтении и исчезает при следующей записи prefs. Дополнительные корни задач,
проектов и вложений сохранены. DeepSeek всегда передаёт `workspaceRoot = realCwd`, поэтому
overlay и предупреждение соответствуют фактической границе записи DSH.
