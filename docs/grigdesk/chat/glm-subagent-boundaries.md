# GLM: границы контроля субагентов

Этот документ сохраняет результаты исследования профиля до v3. В текущем коде чата
foreground spawn/fork защищены [native gate и наблюдением дерева](glm-native-gate.md).
Ниже описаны исходные пробелы legacy hook и основания нового контракта; факт наличия
кода не заменяет admission конкретного ELF.

Проверено 27.10.2026 по серверному коду, закреплённому Harness и одноразовому стенду
на настоящем бинарнике. Модель заменена локальным HTTP/SSE-сервером; ключ синтетический,
внешний fetch запрещён. Рабочие homes и политика обычных чатов не изменялись.

## Откуда брался запрет до v3

Обычный чат DeepSeek использует web-профиль и штатный Agent preset. Список
`DISABLED_ROWS` в `server/src/lib/deepseek/profile.ts` применяется к ACP-профилю, а не к web-чату.
У GLM поверх того же web-профиля включён PreToolUse hook с matcher `*` и коротким
списком `GLM_NATIVE_TOOLS`. Штатный preset объявляет `subagent` и `subagent_fork`,
а hook отказывает их вызовам: [политика GLM](glm-tool-policy.md).

## Что уже умеет Harness

Синхронный spawn с `run_in_background: false` после исследовательского разрешения
имени `subagent` дошёл до дочерней модели `glm-5.3`. В запросе ребёнка были инструкции
одноразового проекта; разрешённая запись создала файл. Hook выполнялся и в ребёнке.
Остановка родительского хода при ожидающем модельном запросе ребёнка дала `stopped`
и подтверждённое завершение процесса.

Исходник `packages/subagent/subagent/src/child-agent.ts` отдельно задаёт наследование
provider/model/effort, cwd, preset и прямого родителя. Эти механизмы уже существуют;
отдельный агентный цикл для GLM не требуется.

## Что не охватывал прежний серверный сторож

`runDeepSeekServerTurn` открывает один `session/follow` с адресом корневой сессии.
Harness фильтрует этот поток по точному session id. Поэтому дочерние `tool/call`,
`hook/result` и `tool/result` не попадают в `createGlmTurnGuard` корневого хода.

Для ребёнка нужен адрес `{kind: 'subagent', parentSessionId, childSessionId, mode}`.
Адрес `{kind: 'session', sessionId: <ребёнок>}` Harness отвергает. Прямую связь и режим
ребёнка можно читать из события `subagent/catalog` родителя; для потомков связь проверяется
на каждом уровне. Эти данные отличаются от произвольных имён и текста инструментов.

Два наблюдения на стенде после разрешения делегирования:

- При пропуске исследовательским hook маркеров **только дочерней сессии** разрешённая
  файловой песочницей запись ребёнка выполнялась, а корневой ход завершался успешно.
  Это воспроизведение пробела наблюдения; production hook намеренно не повреждался.
- Корректный вызов дочернего `bash` с `sandbox_permissions: danger-full-access` и
  `justification` получил «user rejected», хотя обработчик подтверждений GrigDesk не
  вызывался. Помимо отсутствия дочернего контекста у корневого сторожа, native Harness
  закрепляет у ребёнка `approvalPolicy: never` и отклоняет эскалацию до remote waterfall.
  Прямые вопросы человека ребёнку тоже недоступны: `DELEGATED_CALLER`.
  Эти [native-контракты](glm-delegation-contracts.md) не меняются добавлением подписки.

Наличие hook у ребёнка само по себе не означает, что хост проверяет его работу.
Остаточный fail-open риск моста hooks также описан в [политике](glm-tool-policy.md).

## Проверка обязательного контроля до эффекта

В отдельном исследовательском профиле установлен native обработчик `tools/pre-execute`.
Он ожидает результат того же policy helper и разрешает продолжение только при exit 0
и дескрипторе, совпавшем по имени, call id и sha256 канонических аргументов.

| Сценарий | Наблюдение |
| --- | --- |
| Исследовательски разрешённый spawn, штатный hook | Ребёнок наследует модель и инструкции, файл создан |
| Дочерний запрос расширения прав, нынешний серверный сторож | Отказ без обращения к обработчику человека |
| У ребёнка отсутствуют маркеры hook, нынешний сторож | Файл создан, корневой ход успешен |
| Те же отсутствующие маркеры, обязательный native обработчик | Запись отклонена до создания файла |
| Native обработчик и корректный разрешающий дескриптор | Файл создан |
| Стоп при ожидающем дочернем модельном запросе | `stopped`, процесс завершён |

Native обработчик был только прототипом стенда и не включён в поставку. Опыты не
доказывают работу fork, continuable/background, workflow, нескольких одновременных
детей, восстановления после сбоя или настоящего API Z.ai. Допуск выпуска не изменён.

Основные места проверки: `server/src/lib/glm/{policy,permissions,runtime}.ts`,
`server/src/lib/deepseek/{profile,serverTurn}.ts`; в закреплённом Harness —
`packages/api/session-controller/src/history.ts`, `packages/subagent/subagent/src/child-agent.ts`,
`packages/subagent/subagent/src/catalog.ts` и
`packages/hooks/hooks-claude-code/src/index.ts`.
