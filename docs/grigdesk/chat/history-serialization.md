# Порционная сериализация истории

Проверено 29.10.2026. Sparse PUT исключает тела старых шагов из сети, но сервер
всё ещё хранит полный JSON. Раньше `saveOne` сериализовал его для no-op, затем
повторно для новой revision. `patchExecution` готовил исходный JSON даже при
выключенной проверке `skipUnchanged`. Обновление шапки дополнительно сериализовало
историю при проверке миграции. Эти обходы выполнялись без уступки event loop.

`server/src/lib/chat/historySerialization.ts` кодирует сообщения отдельно,
проверяя бюджет 8 мс между ними. После исчерпания бюджета используется
`setImmediate`. Поля и порядок ключей, пропуски, JSON-экранирование и контекст
`toJSON` у значений сохраняются. Результат рассчитан на обычную JSON-запись чата.
Отдельное сообщение, строка и итоговая склейка остаются синхронными: это
порционная обработка, а не жёсткая гарантия 8 мс для произвольного входа.

Для новой revision заменяется уже закодированное поле; сообщения второй раз
не читаются. Проверка no-op, слияние, проверка refs, CAS и атомарная публикация
остаются под прежним per-chat lock. `patchExecution` готовит прежний снимок
только при `skipUnchanged`, до callback, который может менять исходную запись.
Миграция и обновление шапок также используют порционное кодирование.

`tests/server/chat-history-serialization.test.js` проверяет совпадение байтов
с `JSON.stringify`, сохранность результата при нескольких сменах revision,
отсутствие повторного чтения steps и уступку event loop на большой истории.
Прежние API-тесты проверяют no-op, ошибки записи, refs и совместимость истории.

Это не меняет формат файлов или протокол и не убирает стоимость чтения,
`JSON.parse`, UTF-8, диска и холодного GET. Браузерный ввод следует измерять
с [приёмником, отделённым от Playwright](../testing/chat-performance-isolation.md).
