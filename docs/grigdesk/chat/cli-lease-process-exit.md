# Reader lease и завершение посторонних процессов

Внешний CLI удерживает reader lease выбранной копии. Обслуживание установки
разрешается после выхода её процессов; закрытый stdout сам по себе не доказывает
исчезновение всех участников сессии. Qwen использует этот же контракт через bwrap.

## Гонка снимка `/proc`

`sessionAlive` в `server/src/lib/providerInstall/leases.ts` читает список `/proc`,
а затем `stat` каждого процесса. Список не удерживает процессы: посторонний PID
может завершиться между этими двумя операциями. Чтение исчезнувшего процесса
возвращает как `ENOENT`, так и `ESRCH`.

Оба кода означают отсутствие этого процесса и позволяют продолжить сканирование.
Они не доказывают выход остальных участников сессии: каждый оставшийся процесс
проверяется отдельно. Ошибки доступа и другие неизвестные ошибки сохраняют
занятость lease. Проверка собственного child по PID и времени старта не меняется.

До обработки `ESRCH` исчезновение постороннего процесса могло дать ложный
`provider_in_use` после выхода Qwen. Ошибка уборки заменяла уже готовый результат
хода или исходный отказ API; автоматический повтор модели такой сбой не исправляет.
Исправление относится к доказательству выхода процессов, а не к правам модели,
срокам ожидания или политике повторов.

## Проверка

Подготовленные Qwen runtime, factory и native-сценарии проверяют завершение хода,
отмену, API-ошибки и освобождение выбранной копии. Существующий набор
`tests/server/provider-install-leases.test.js` проверяет reader/exclusive,
живого ребёнка после SIGKILL holder и подтверждённое закрытие цепочки.

При адресной проверке ошибки `/proc` нужны три исхода: `ESRCH` постороннего PID
не мешает освобождению уже завершённой сессии; `EACCES` запрещает освобождение;
живой участник собственной сессии также сохраняет reader.
