# MCP «не удалось получить» и мёртвые кнопки карточки = опрос перезапускал сам себя

Симптом: в «Настройки → Исполнители» блок MCP пишет «Не удалось получить список», а
кнопки карточки (в том числе «Обновить» CLI) не срабатывают — запросы в Network стоят
«(ожидает)». Сервер при этом здоров: curl на `/api/providers/<id>/mcp` отдаёт 200 с живым
списком за секунды.

Причина: опрос запускал `watchEffect`, а зависимости он собирает сам, по факту чтения.
Внутри `providers.loadMcp` стор ЧИТАЕТ `prov.mcp` (чтобы не потерять прошлый список на
время загрузки) и туда же ПИШЕТ ответ — уже после await, то есть вне текущего прогона
эффекта. Значит наблюдатель подписан на собственное следствие: каждый ответ перезапускал
его, и открытая вкладка исполнителей молотила опрос всех троих без конца. Минутный кэш
сервера делает круг мгновенным, а на истечении кэша десятки одновременных `claude mcp
list` / codex app-server не укладываются в 30-секундный таймаут GET — отсюда «не удалось
получить». Пул из шести соединений браузера при этом занят насмерть, поэтому POST
`/api/providers/<id>/update` не получает сокета вовсе.

Правило: наблюдатель, который вызывает ДЕЙСТВИЕ стора, перечисляет источники ЯВНО —
`watch(() => tab === "providers" && prov.loaded, …, { immediate: true })`. `watchEffect`
допустим только там, где тело ничего не пишет в то, что читает.

Стенд обязан быть реактивным: фейковый стор плоским объектом Vue не отслеживает, синхронная
запись ответа прячет второй круг, и такой тест зацикливание не видит вовсе. В
tests/web/settings-mcp.component.test.js стор обёрнут в `reactive`, а `loadMcp` ждёт сеть
перед записью — без этого проверка проходит по другой причине.
