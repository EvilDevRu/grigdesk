# Подсказки уровней усилия

Каждый адаптер исполнителя объявляет `effortHints`: карту кратких русских объяснений
по имени уровня. `resolveRuntimeModels()` прикладывает к модели справку только для
её разрешённых `efforts`. Общий реестр и Vue не ветвятся по вендору.

Проверено 2026-10-08:

| Исполнитель | Смысл доступных уровней |
| --- | --- |
| Codex | `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` управляют глубиной рассуждения; `ultra` добавляет автоматическое делегирование субагентам. Состав зависит от модели. |
| Claude | `low`, `medium`, `high`, `xhigh`, `max` управляют тщательностью работы и расходом токенов, включая рассуждение и инструменты. `ultracode` запрашивает глубину `xhigh` и делегирование при доступном workflow. Допуск режима требует свежего discovery и проверенной базовой глубины модели. |
| Kimi Code | Проверенная конфигурация исполнителя объявляет K3 уровни `low`, `high`, `max`; у остальных моделей выбора нет. Новые upstream-возможности не расширяют pinned-конфигурацию автоматически. |
| DeepSeek | `off` выключает рассуждение; `low`, `high`, `max` задают его усилие. |
| GLM | Каталог читает уровни каждой модели: например, `off/high/max` у GLM-5.2 и `low/high/max` у GLM-5.3. Модели с единственным действующим уровнем не получают слайдер. |
| Qwen Code | Каждая модель читается через native `configOptions`. Например, Qwen4 получает `none/low/medium/xhigh`, а toggle-only модели — `none/default`. Сторонние модели через Qwen имеют собственные наборы CLI; единого списка на сервис нет. |

Имена уровней не означают одинаковое поведение у разных исполнителей. В частности,
API Kimi и DeepSeek отображают входное `ultra` в `max`; это не режим делегирования Codex.
GrigDesk не добавляет такие API-алиасы в список выбора.

У Qwen `none` отключает thinking, `default` использует настройку модели по умолчанию
и также служит включением thinking для toggle-only модели. Сам факт наличия native-уровня
не является платной проверкой поддержки параметра удалённым аккаунтом. Профильные проверки
с настоящим CLI и локальным API подтверждают передаваемое поле `reasoning_effort` у Qwen4.

Подсказка Claude `ultracode`: «Глубина xhigh; запрашивает делегирование задач при доступном
workflow. Расход может вырасти». Это [запрос режима](claude-ultracode.md), не подтверждение
session-specific availability. Внешние/native-настройки независимы: обычная ступень
не гарантирует выключения workflow. Тест описаний разрешает упоминание делегирования
у `ultra` Codex и `ultracode` Claude; он не доказывает отсутствие субагентов в остальных режимах.

В чате наведение или фокус внутри эффорта показывает краткое сравнение всех доступных
ступеней. `aria-valuetext` нативного range объясняет выбранный уровень; пустое значение
озвучивается как умолчание исполнителя. Замороженный выбор остаётся неактивным.
Явный `hint` места настройки сохраняет приоритет над общей справкой.
В настройках арбитра и модельных настройках плагинов справка есть у выбранного значения
и в `title` нативных `option` (разрешённое исключение контракта подсказок).

Описание не определяет доступность: новый уровень остаётся выбираемым. Известные
уровни получают русское объяснение адаптера. Если описания нет, справка честно говорит
«Описание этого уровня пока недоступно». Ручная `custom`-модель может задать свои описания.
Подготовка runtime-справки не меняет сохранённый каталог.
