# Отказ процесса во время запуска GLM

Полученный от web-процесса URL ещё не означает готовность: затем сервер получает
cookie авторизации. Выход или ошибка дочернего процесса на любой из этих стадий
прерывает startup. Общий `serverRuntime.ts` связывает события `exit`/`error`
с отдельным AbortController авторизации; после готовности эти startup listeners снимаются.

Cleanup по-прежнему принадлежит `binaryProcess.ts`: нештатный выход даёт ошибку
`deepseek_binary_cleanup` и сохраняет каталог запуска для диагностики. Сроки ожидания
и правила сигналов собственной process group не меняются.

Unit-тесты запускают metadata double настоящим дочерним процессом. Они проверяют
выход до URL, отказ spawn и выход после URL при зависшем loopback auth-запросе.
Последний сценарий должен завершиться отказом раньше таймаута HTTP-авторизации.
