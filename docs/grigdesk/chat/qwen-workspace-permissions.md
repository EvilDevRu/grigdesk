# Qwen: дополнительные корни и native «Авто»

Адаптер объявляет `workdir: { switch: 'reseed', roots: 'multi' }`. Общий выбор рабочей
папки передаёт дополнительные репозитории проекта или рабочие копии задачи через
`extraDirs`, как для других многокорневых исполнителей. Основной cwd сохраняется;
общий предок каталогов не становится рабочей областью.

## Пути, песочница и память

`qwen/workspace.ts:resolveQwenWorkspace` используется адаптером и прямым runtime.
Все пути проходят общую `validateWorkdirPath`: абсолютный существующий каталог,
доступный для чтения и обхода, после realpath. Корень ФС и весь home запрещены.
Дополнительные корни очищаются от повторов, включая ссылки на одну папку, и сортируются.
Корень внутри скрываемой `.env` или `.qwen` другого корня отвергается до запуска,
чтобы metadata не обещала путь, который перекрывает файловая маска.

Подготовленный settings в приватном home передаёт подтверждённые `extraDirs` и
выданные read-only ресурсы через `context.includeDirectories`. Последние остаются
только для чтения в bwrap и серверном guard; среди них —
[общие навыки](qwen-skills.md). Пользовательские settings не переписываются.
bwrap монтирует рабочие корни с записью, сначала родителей, затем вложенные каталоги.
Серверный guard проверяет файловые инструменты по тому же набору физических корней;
символическая ссылка на невыданную папку не даёт доступа. Shell остаётся внутри mounts.

В каждом рабочем корне `.env` и `.qwen` закрываются пустыми read-only данными.
Ссылки сохраняются на хосте; исходное содержимое не читается агентом через эти пути.
Ссылка, перекрывающая любой рабочий или служебный корень, запрещена. Исходные права
и запреты прямого SSH действуют и для дополнительного каталога.

Набор дополнительных корней входит в binding durable home. Перестановка путей и
ссылки на те же каталоги сохраняют resume; добавление или удаление корня требуют
новой native-памяти через общий переход рабочей области. Прежний binding без
дополнительных корней сохранён. История GrigDesk остаётся в чате.

Служебный каталог вложений исключается из дополнительных корней по физическому пути:
Qwen получает картинки байтами ACP. Наличие картинки не меняет binding и не выдаёт
CLI весь каталог вложений. Сессия со старой формулой, включавшей этот каталог, продолжает
использовать прежний home после точной проверки маркера памяти.
[Продолжение после вложения и остановки](qwen-prompt-lifetime.md#продолжение-после-сообщения-с-вложением).

## Режим «Хост» и документация плагинов

В режиме «Хост» (`allowHostAccess`, подтверждение при включении) bwrap не используется:
монтирования рабочих корней и масок `.env`/`.qwen` нет, файловые инструменты выполняет
сам CLI с правами пользователя сервера, а `run_shell_command`/`monitor` проверяет
серверный reverse guard по identity сессии и настройке прямого SSH. Предупреждения
о файловой изоляции песочницы к Host не относятся; Host не выдаётся за новую изоляцию.
Набор корней, режимы прав и запрет прямого SSH сохраняются; смена профиля отделяет
native-память, переписка GrigDesk остаётся. Подробнее —
[штатные инструменты Qwen](qwen-native-tools.md#режим-хост).

Папки документации включённых плагинов (`pluginDocsDirs`) доступны в обоих режимах:
в песочнице они монтируются только для чтения после realpath/дедупликации, запись
и чтение соседних папок пакета запрещены; уже доступные рабочие корни сохраняют свои
права. В Host документацию читает сам CLI через includeDirectories overlay.

## Режимы

«Спрашивать» передаётся как `default`, «Авто» — как native `auto`, «План» — `plan`,
«Без подтверждений» — `yolo`. До prompt runtime проверяет наличие выбранного режима
в `session.modes.availableModes` и ждёт ACK `session/set_mode`. Нет подмены `auto`
на `default` или `yolo`; неподдерживаемый режим требует обновления CLI.

Native auto самостоятельно разрешает обычные правки в рабочей области и использует
свой классификатор для других действий. Классификатор может отправлять дополнительные
запросы модели и расходовать квоту аккаунта. Отказ не превращается в автоматическое
разрешение; при недоступности классификатора CLI может запросить решение человека.
Reverse permission проходит через окно GrigDesk с `requiresExplicitUser`: общий
auto-классификатор GrigDesk не подменяет требование native fallback. Отмена обесценивает
позднее решение, а final guard и файловая песочница действуют после native-решения.

Этот контракт проверен для внешнего Qwen Code 0.27.2 по ACP. Документация upstream:
[дополнительные каталоги](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/settings/),
[режимы разрешений](https://qwenlm.github.io/qwen-code-docs/en/users/features/approval-mode/).

## Проверки

`qwen-workspace.test.js` проверяет канонические корни, маски секретов во втором корне,
запрет третьего, привязку памяти и отказ неизвестного режима до prompt.
`qwen-native-workspace.test.js` запускает настоящий CLI на синтетическом loopback API:
запись файлов и shell во втором корне, различие auto/default при resume, обе ступени
классификатора, его недоступность и сохранение изоляции. Настоящий ключ и платная
генерация для этих тестов не используются.
