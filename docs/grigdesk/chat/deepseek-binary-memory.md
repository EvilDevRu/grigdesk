# Память DeepSeek при обновлении бинарника

Binary-поставка выбирает home `<deepseekRuntimeHome>/chats/<sha256(chatKey)>`, без
packageId или buildId. Маркер `.grigdesk-runtime.json` содержит только формат 1 и
провайдера `deepseek`. Security profile включает ревизию политики и права, а учётная
запись, модель и cwd остаются отдельными полями session binding.

Обновление A→B и откат B→A с совместимым форматом журнала сохраняют sessionId.
Настоящий loopback-прогон проверяет память по предыдущим сообщениям в запросах модели,
совпадению home и профиля безопасности.

Перед resume проверяется самая новая canonical generation журнала: `session.jsonl`
означает v0, `session.vN.jsonl` — положительную версию; поддерживается суффикс `.zstd`.
Имена с ведущими нулями и временные файлы не считаются committed generation. Выбирается
численно высшая версия, как в upstream: наличие читаемого старого файла рядом с новым
не разрешает молча вернуться к старой памяти.

Если версия отсутствует в `journal.read` выбранного descriptor, текущий ход создаёт новую
сессию и сообщает: «Память исполнителя начата заново: формат журнала несовместим».
Ранний `onSessionCreated` сохраняет новую sessionId через общий CAS до prompt. Лента и
pendingSeed проходят прежний общий путь чата; старый журнал не меняется. Отсутствующий
журнал даёт `deepseek_session_missing` до запроса модели.

Legacy home и профиль переносятся при первом переходе по buildId установленной
generation, сохраняя sessionId через CAS при прежних правах.
[Контракт перехода](deepseek-binary-cutover.md) не поддерживает возврат к embedded.
