# Прочтение чатов между устройствами

При одновременной работе нескольких окон старый снимок мог вернуть `unread:true`
после прочтения того же ответа на другом устройстве. Сервер сохранял актуальную метку
при stale PUT, но повтор клиента переносил только модель, effort и mode. Получив свежую
revision, клиент повторно записывал старую метку непрочитанного.

Подтверждённая история окна теперь хранит короткий ключ последнего окончательного ответа
рядом с отпечатком записи. Перед повторным PUT клиент сверяет этот ключ с местной лентой
и свежей серверной шапкой. Для одного ответа прочтение сохраняется; новый серверный ответ
не считается прочитанным по старой местной отметке. Новый местный итог, добавленный первым
stale PUT, сохраняет свою метку, если после этой записи серверная revision не менялась.
Ключи освобождаются вместе с подтверждениями истории при удалении и dispose.

Для незагруженной ленты чужое прочтение того же ответа применяется поверх несохранённого
названия. Оно не становится обратным PATCH `unread:true`. Более старая шапка каталога
отбрасывается по revision, включая ответ, задержавшийся после собственного PATCH прочтения.
Формат истории и сетевой протокол остаются прежними.

Сервер при переносе pending в историю не считает ответ новым, если финал уже лежит в ленте:
живое окно сохраняет его по SSE без `pid`, и повтор pending лишь дополняет то же сообщение
по паре `runId`+`assistantMessageId`. Раньше такой перенос взводил `unread:true` задним
числом — прочитанный ответ возвращал точку «не прочитано» на всех устройствах при очередном
reconcile.

Клиент не глушит запись прочтения отпечатком «уже отправлено», если местная метка разошлась
с последней подтверждённой шапкой: `dirty`, очередь persist и оба PUT-скипа проверяют это
расхождение. После успешной записи окно подтверждает метку в своей шапке, чтобы принудительный
обход не повторялся. Загруженная лента применяет чужую шапку тем же правилом `sameReply`, что
и лёгкая: при том же финальном ответе местное прочтение не превращается обратно в
«не прочитано», а погашенная сервером метка не держится местным состоянием.

Проверка: `tests/web/chat-unread-sync.test.js` использует настоящий Fastify-модуль,
файловую историю и независимые store трёх окон. Проверяются полные ленты и лёгкие шапки,
обычный PUT и refs, повторное открытие, новые местные и серверные ответы, прочтение при
чужом переименовании, поздняя шапка и молчаливый чужой flip метки. Дополнение финала
pending без взвода метки проверяют `tests/server/chat-step-reuse.test.js` (юнит и
сквозной reconcile). Проверка не обращается к пользовательской переписке.
