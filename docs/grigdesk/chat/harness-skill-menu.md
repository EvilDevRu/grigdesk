# Навыки GLM и DeepSeek в меню чата

Адаптеры GLM и DeepSeek публикуют в `commands()` общий пользовательский каталог
`<home>/.agents/skills`. Меню по `/` показывает навыки как `/имя` с описанием из
YAML frontmatter. Это штатный синтаксис явного вызова навыка в Harness; `$имя`
остаётся синтаксисом Codex.

`server/src/lib/skills/userSkillCommands.ts` (совместимый экспорт из
`deepseek/skillCommands.ts`) читает bundles `<каталог>/SKILL.md`,
плоские `*.md` и ссылки на них. Имя берётся из обязательного `name`, проверяется
как kebab-case; обязательное `description` сворачивается в строку до 120 символов.
Повреждённый YAML, отсутствующие файлы и некорректные invocation-поля пропускаются.
`user-invocable: false` скрывает пункт; `disable-model-invocation: true` сохраняет
явный вызов человеком. Оба поля принимают boolean, 0/1 и строковые варианты
true/false, yes/no, on/off без учёта регистра — как файловый provider Harness.

Встроенные навыки сервер доставляет сам: при каждом старте он зеркалит каталоги
`tools/skills` корня комплекта в `~/.agents/skills` (`server/src/lib/skills/bundledSkills.ts`).
Имена из комплекта перезаписываются — репозиторий остаётся источником текста; записи
пользователя без такого имени не трогаются, повреждённый навык пропускается, а отсутствие
каталога-источника не мешает подъёму сервера. Оба allowlist ресурсов включают
`tools/skills` в сборку; аудит автономного payload требует файл `grigdesk-connect-project/SKILL.md`.
В меню попадают метаданные установленных файлов, отдельного реестра встроенных навыков нет.

Каталог `/api/providers` общий для всех чатов, поэтому не сканирует проектные
корни и приватные DSH homes отдельных разговоров. Навыки, доступные только в
другом cwd или личном каталоге Codex/Claude, в него не подмешиваются. Чтение списка
не запускает Harness и не обращается к модели; обновление реестра перечитывает файлы.

В контракте команды `kind: 'skill'` отличает `/навык` от служебной CLI-команды.
Выбор пункта отправляет обычный ход: сохраняет контекст страницы, вложения, запрос
названия и доставку уточнения/очереди во время активного ответа. Сервер отвергает
попытку передать этот пункт через служебный `slashCommand`. Инструкции раскрывает
сам Harness, а доступ инструментов определяется прежней политикой исполнителя.
Явный известный `/навык` стоит в начале prompt, контекст страницы и прочие подсказки
передаются после него. Тот же сканер metadata с ограничением на bundles используется
для [навыков Qwen](qwen-skills.md).

Локальные `/compact`, `/clear`, `/reset`, `/new` сохраняют приоритет над
одноимёнными навыками. Неподтверждённые команды интерактивного DSH не объявляются
исполняемыми пунктами меню.

Проверки: `tests/server/bundled-skills-install.test.js`,
`tests/server/harness-skill-commands.test.js`,
`tests/server/chat-slash-commands.test.js`,
`tests/web/chat-slash-menu.component.test.js`.
