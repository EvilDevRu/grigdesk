# Инструмент руководства

`grigdesk_help` предоставляет оглавление (`index`), ограниченный поиск (`search`, query)
и чтение (`read`, id, необязательный offset). ID — стабильное имя статьи, не путь.
Неизвестные поля, URL, cwd и параметры рабочей области не принимаются.

Обычный chatModule получает HelpService явным портом и добавляет инструмент в общий registry.
Он доступен всем существующим исполнителям, в том числе в режиме только чтения. MCP и
динамические инструменты Codex используют тот же descriptor и invoke; host policy
DeepSeek/GLM классифицирует три действия как чтение. Наличие сервиса входит в scope key.
Сбой ресурса возвращает `help_unavailable`; отсутствие статьи — `help_not_found`.

Оглавление, выдача и чтение содержат version, commit, revision и locale. Результат чтения
возвращает href, text, offset и nextOffset; порция — 12 000 Unicode code points. При
ненулевом nextOffset агент дочитывает продолжение. Поиск нормализует регистр и ё/е,
учитывает заголовок, keywords и текст; пустой запрос возвращает пустую выдачу.

Короткая подсказка руководства добавляется только в prompt обычного хода. Сохранённая реплика,
native slash и сжатие не получают этот блок. Подсказка не расширяет файловые права,
workspace, доступ к MCP или разрешения внешних действий. Model-only, недоверенные служебные
запросы и фабричные инструменты не получают новый порт через этот механизм.
Документация пользовательских плагинов и существующая подсказка pluginDocs сохраняются отдельно.

Подсказка и descriptor направляют к справке как вопросы, так и просьбы выполнить действие
в GrigDesk. Обычные операции используют доступные штатные инструменты и CLI из руководства;
внешние задачи — `tracker`, а из исходников — `bin/grigdesk-ctl tracker`. Если нужной команды
нет, агент использует `grigdesk_browser` в пределах доступа и сообщает о недостающем доступе.
Просмотр задач, состояния конвейера и настроек не является поводом запускать Vite, сборку
или второй экземпляр GrigDesk. Dev-стенд используется для проверки изменений интерфейса
либо по прямой просьбе поднять его. Это инструкция выбора способа работы, а не запрет
shell на уровне политики и не гарантия соблюдения правила моделью.

Проверки: `help-tool.test.mts`, дополнительные HELP-сценарии `plugin-docs.test.js` и
`browser-chat-wiring.test.js`: настоящий registry, оба транспорта, исходная история,
служебные ходы и шесть исполнителей, включая Qwen, без реального платного запроса.
Проверка доставки правил в prompt не заменяет живую приёмку выбора инструментов моделью.
