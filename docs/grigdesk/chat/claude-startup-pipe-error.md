# Ошибка канала при неудачном запуске Claude

Выявлено 01.10.2026 в [проверке полного сервера на отдельном порту](../web/chat-runtime-smoke-check.md).
Дефект не исправлен этим изменением. Участок `server/src/lib/executors/_claudeStream.ts`
не менялся в исправлении фризов и при проверке совпадал с HEAD.

## Подтверждённый случай

В изолированном окружении `PATH` не содержал каталог установленного Node.
Тестовый CLI с `#!/usr/bin/env node` завершался с ошибкой «node: No such file or directory».
После отправки нового хода полный сервер писал user-сообщение в stdin этого процесса.
Socket выдал асинхронную ошибку `EPIPE`; необработанное событие `error` завершило сервер.

Браузер до этого успешно загрузил историю и сохранил черновик через step-reuse.
Причина падения воспроизведена отдельно прямым запуском того же CLI с тем же
ограниченным `PATH`. После включения каталога текущего `process.execPath` в `PATH`
полный браузерный сценарий прошёл без изменения продуктового транспорта.

## Почему ошибки процесса недостаточно

`openClaudeStreamSession` слушает `child.on('error')`, но stdin — отдельный поток.
`writeLine` проверяет `state.exited` и `child.stdin.destroyed` до записи; закрытие
между проверкой и асинхронным результатом `write()` этой проверкой не покрывается.
Внешний `try/catch` не ловит последующее событие `error` на Socket.

Это проверенный случай неправильного окружения CLI. Поведение всех вариантов
раннего завершения процесса отдельно не исследовалось. Исправление требует
обработки ошибки stdin как ошибки сессии: завершить активный ход, отклонить
ожидающие control-запросы, уведомить lifecycle и сохранить обычные гарантии
durable pending. Простое подавление события не доказывает завершение очередей.

До отдельного исправления успешный прогон здорового CLI не является гарантией,
что ошибочная настройка запуска не завершит сервер. Ошибка ссылок на историю
и совместимость старого PUT проверяются независимо от этого транспорта.
