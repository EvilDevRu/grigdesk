# Обслуживание копии из официального установщика

`nativeStrategy.ts` обслуживает распознанную inventory-копию `source=native` в общем
`ProviderInstallService`. Первая установка и npm-копии сохраняют npm-стратегию.
Для обновления и переустановки используется `installation(config).install` адаптера
без npm-контекста. Это повтор официальной установки актуального выпуска; точная
переустановка прежней версии с offline graph относится только к npm-стратегии.

Подготовка читает пользовательское Bash-окружение без обязательного Node/npm,
проверяет объявленные root/entry, владельцев и права дерева и запускает только
`entry --version`. Installer до подтверждения не выполняется. Программный root
должен быть физическим каталогом внутри HOME. Root, предки вплоть до HOME и все узлы
дерева должны принадлежать текущему uid. Запись для всех (`mode & 0o002`) запрещена;
групповая запись (`mode & 0o020`) допустима только при `gid === process.getgid()`.
Например, каталог `bin` с режимом `0775` и своей основной группой проходит проверку.
Дополнительные группы процесса не считаются своей основной группой. У ссылок
проверяется uid, а биты доступа самой ссылки не учитываются. Одинаковая проверка
действует при prepare и revalidate перед mutation; identity дерева включает gid.
Проверки предков в `assertNativeTargets` и обхода дерева в `nativeIdentity` используют
общее правило `hasForeignWrite`: собственная групповая запись не становится конфликтом.
Внешний entry допустим только как объявленная ссылка внутрь root.
Ссылки внутри дерева не обходятся при снимке, backup и удалении.

Отказ по владельцу или правам имеет код `native_ownership_unverified` и сообщение
с проблемным путём. UI показывает это исходное сообщение сервера. Общий код
`installation_conflict` тоже сохраняет точную причину сервера: текст про занятое имя
команды появляется только тогда, когда сервер сообщает именно этот конфликт.
Исходные сообщения остаются данными и не переводятся при смене языка интерфейса.
Это правило действует и для остальных известных кодов; перевод по коду используется
только при отсутствии текста: [контракт сообщений](provider-install-output-and-messages.md).

Token связан с identity копии, байтами дерева, inode, владельцами, окружением,
декларацией адаптера и привязкой в config/файле окружения. Чужая ручная привязка
блокирует подготовку; её изменение после preview блокирует старт. Перед mutation
привязка сверяется повторно. Общие admission, exclusive lease и проверка запущенных
внешних процессов действуют так же, как для npm.

До mutation сохраняется durable intent и собственный backup программного root.
Update/reinstall выполняют официальный installer под worker ownership с выводом
в общее окно. Успех требует распознанной версии выбранного entry, отсутствия отката
версии и достижения известной актуальной версии. Затем сверяются configured bin
и выбор нового терминала. Неудачная замена восстанавливается из проверенного backup,
когда пути остаются доказанными; иначе результат — `needs_attention`.

Uninstall не запускает installer или shell-команду удаления: сервер удаляет только
объявленный root и внешний entry-ссылку. У Kimi root — `~/.kimi-code/bin`, поэтому
credentials, настройки и история рядом с ним не входят ни в footprint, ни в backup.
Снятие привязки использует общий CAS-писатель `.env`; после release перечитываются
реестр и модели. Другая копия программы остаётся доступной.

После рестарта destructive-фаза автоматически не повторяется. Native intent
сохраняет блокировку до ручного подтверждения отсутствия удалённой программы либо
проверки установленной версии. Npm recovery и прежняя migration остаются отдельными
стратегиями того же сервиса. Contained Kimi и managed DeepSeek/GLM сюда не попадают.

Проверки: `provider-lifecycle-service.test.js` покрывает update/reinstall без npm,
preview/commit удаления с сохранением данных, подмену root/entry и чужую привязку,
update/reinstall/uninstall при `0775` своей группы, отказ при чужом uid,
world-writable и group-writable чужой группы у предков, каталогов и файлов
как на prepare, так и на start удаления и обновления;
`providers-install-routes.test.js` — HTTP при `0775`, причину отказа по правам и прежний POST update;
`provider-install-store.test.js` — исходную причину отказа вместо ложного конфликта имени;
`provider-lifecycle-recovery.test.js` — блокировку и ручное подтверждение после рестарта.
