# API-баланс и дополнительный контроль GLM без ЛК

## Что удалось проверить

28.10.2026 после подтверждения активного оплаченного Pro выполнен дополнительный
контроль тем же источником `ZAI_CODING_API_KEY`. Ключ, режим и admission не менялись.

| Проверка | Результат | Что подтверждает |
| --- | --- | --- |
| `GET /api/paas/v4/models` | HTTP 200, 11 моделей | каталог доступен; ответ содержит `object`, `data`, у модели — `id`, `object`, `created`, `owned_by` |
| Чтение `platform-charge-zai/business/accountBalance` | HTTP 200, `code: 200`, `totalBalance: 0` | отдельный денежный API-баланс нулевой |
| Один запрос `glm-4.7-flash` через обычный API | `TimeoutError` через 45 секунд, HTTP-ответ не получен | контроль генерации не дал проверяемого результата |

Номер клиента для чтения баланса получен из `zaiUserInfo` и использован только в памяти.
Локальный отчёт о балансе содержит признаки нулевого/положительного остатка, без
идентификаторов аккаунта и отдельных финансовых операций. В ответах каталога и
диагностических заголовках классификации ключа не найдено.

Официальный [прайс Z.ai](https://docs.z.ai/guides/overview/pricing) на момент проверки
указывает нулевую цену GLM-4.7-Flash и GLM-4.5-Flash. Выданный каталог эти модели
не включил. Для контроля сделан один прямой запрос `glm-4.7-flash`: `ping`,
`max_tokens: 16`, `thinking: { type: disabled }`. Платных модельных запросов,
повторов при таймауте и повторного опроса квот в этой проверке не было.

## Границы вывода

Нулевой API-баланс согласуется с `1113`, если запрос оплачивается вне подписки.
Он не доказывает, что текущий ключ — Standard: тот же отказ может требовать разбора
применения плана на стороне Z.ai. Каталог моделей также не является подтверждением
возможности генерации или типом ключа. Таймаут бесплатной модели не означает ни
исчерпанную подписку, ни успешный контроль.

Самый прямой независимый тест — заведомо новый ключ из Personal Coding Plan и один
запрос к Coding Plan endpoint. Успех нового ключа при отказе старого локализует
проблему к старому ключу; одинаковый отказ требует дальнейшего разбора со стороны Z.ai.
Тест в официально поддерживаемом клиенте с тем же ключом может отдельно проверить
влияние клиента, но его результат заранее неизвестен. Наличие подходящего ключа
нельзя заменить сменой endpoint, догадкой по каталогу или пополнением баланса для
проверки подписки.

Предыдущие проверенные факты и сохранённые причины отказов:
[активный Pro и два модельных маршрута](glm-entitlement-diagnostics.md).
Тип текущего ключа и окончательная причина `1113` остаются не установлены.
