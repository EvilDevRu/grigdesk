# Баланс, каталог и генерация GLM

Читай при диагностике доступности GLM. Три результата проверяют разные возможности:

| Проверка | Что подтверждает | Чего не подтверждает |
| --- | --- | --- |
| Каталог моделей | Успешное чтение списка | Право на генерацию и тип ключа |
| Денежный API-баланс | Состояние отдельного баланса | Остаток подписки Coding Plan |
| Ответ модели | Успех конкретного запроса | Полный smoke и совместимость остальных сценариев |

Таймаут без HTTP-ответа не классифицируется как исчерпанная квота или успешная проверка.
Нулевой API-баланс сам по себе не доказывает, что используется Standard-ключ.
Смена endpoint и название переменной окружения также не определяют источник оплаты.

Ключ и режим проверяются по [контракту доступа](glm-access-contract.md), категория —
по [правилам ключей](glm-key-types.md). Живой запрос требует разрешения; заявленная
бесплатность модели должна проверяться по актуальному прайсу до такого запроса.
Личные балансы, идентификаторы и результаты конкретных попыток остаются локально.

Связанная диагностика — [подписка и модельный шлюз](glm-entitlement-diagnostics.md).
