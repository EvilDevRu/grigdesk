# Выбор подтверждения установки в браузерной проверке

Всплывашка исполнителя и окно настроек также имеют `role=dialog`.
После клика сразу открывается окно обслуживания, которое ждёт HTTP-подготовку
с фазой «Проверка подготовки». В это время `getByRole('dialog').last().waitFor()`
может найти его до подтверждения: имя исполнителя уже есть, подготовленной команды ещё нет.

В `provider-install.browser.test.js` подтверждение выбирается по `role=dialog`
и вложенному `.ui-dialog-host__message`. Команда изначально скрыта под «Подробности»:
проверка сначала убеждается в `aria-expanded=false` и отсутствии видимого блока кода,
затем раскрывает детали, сверяет команду и нажимает подтверждение.

Ответ preparation также должен соответствовать строгому DTO: `loginCommand`
принадлежит job, но не подготовке. Лишний ключ отклонялся декодером и открывал
окно ошибки вместо подтверждения; прежний локатор маскировал эту исходную причину.
