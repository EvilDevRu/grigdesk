# Живой замер production-сборки через посредника с CLI-токеном

Сервер больше не раздаёт `web/dist`, а локальная труба окна отвечает посторонним
клиентам `403 pipe_forbidden`. Чтобы снять геометрию свежей сборки на рабочем API,
нужен свой маленький HTTP-посредник:

- статика из `web/dist`, неизвестный путь — `index.html`;
- `/api`, `/shots` и `/vscode` пересылаются на сервер (по умолчанию порт 8140) с
  заголовком `x-grigdesk-token` из файла CLI-токена; `Host` и `Origin` переписываются на
  адрес сервера, cookie снимается; SSE проходит обычным `pipe` ответа;
- `/api/auth/state` посредник отвечает сам (`authenticated: true`, `configured: true`,
  строковый `clientScope`): публичная проверка смотрит только на cookie окна.

Токен читается внутри скрипта и не выводится. Скрипты и снимки — в папке артефактов.

## Что открывается и что нет

Маршруты Доски, Конвейера, Чатов, Маршрутов, Проектов (в том числе `#/projects/<id>`),
Песочниц, Входящих и все страницы настроек открываются. Настройки открываются адресом
`#/settings?page=<id каталога>`; окно появляется через несколько секунд, его стоит ждать
по `[role=dialog]`. Страницы «Речи» требуют полного Chromium —
[ловушка headless-shell](headless-shell-settings-crash.md).

Под CLI-токеном не загружаются:

- инструменты-плагины (Код, Полка, БД, Docker, 3D, Документы) — остаются на
  «Проверяю доступность инструмента…»;
- «Подключения → Доступ к серверу» — ответ `session_required`.

Эти места проверяются в окне приложения или разбором исходников.
Каждый сценарий начинай с нового документа: смена hash переносит Pinia и открытые
диалоги ([карта экранов](../web/ui-screen-inventory.md)).
