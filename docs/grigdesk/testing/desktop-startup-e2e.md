# E2E старта окна: корень-фикстура, изолированное окружение и отказы

`tests/desktop/e2e/startup.e2e.mjs` (SE-01…17) проверяет [старт окна](../web/desktop-startup.md)
настоящим dev Electron внутри `tests/desktop/e2e/isolated-session.sh`:

```bash
NODE_TEST_MAX_RSS_MB=4096 GRIGDESK_E2E_WEB_DIST="<сборка web>" \
  bash tests/desktop/e2e/isolated-session.sh \
  bash tests/run-node-tests-safe.sh --test-concurrency=1 --test tests/desktop/e2e/startup.e2e.mjs
```

Перед запуском нужна свежая `npm --prefix desktop run build`: сценарии грузят `desktop/dist`.
Без `GRIGDESK_E2E_WEB_DIST` пропускается только SE-10. Необязательный `GRIGDESK_E2E_ARTIFACTS`
получает снимок заставки `splash.png` для глаз человека.

## Фикстуры

Тест сам строит во временном каталоге корень-фикстуру (`tests/desktop/e2e/server-fixture.mjs`):
`server/src/app.ts` на синтаксисе JS поднимает заглушку `stub.mjs` на `GRIGDESK_PORT`, после
listen пишет ключ окна (каталог 0700, файл 0600) и журнал событий `start`, `listen`, `exit` с
именами переменных окружения, `PATH` и `LD_LIBRARY_PATH`. SIGTERM и разрыв IPC закрывают её с
кодом 0, SIGUSR2 — кодом 75, как перезапуск. `GRIGDESK_E2E_FIXTURE_DELAY_MS` задерживает listen,
`GRIGDESK_E2E_AUTH_DELAY_MS` задерживает только ответ `/api/auth/state` (по умолчанию 0),
не обмен ключа и не hello. `GRIGDESK_E2E_FIXTURE_PACKAGED_COOKIE` включает страницу,
которая закрывает окно сама.
Ворота `deploy/require-vpn.sh` пропускают сразу, с `GRIGDESK_E2E_GATE_HOLD` пишут свой pid и
ждут SIGTERM, а с `GRIGDESK_E2E_GATE_OPEN_FILE` отказывают строкой настоящих ворот, пока файла
нет: SE-16 держит VPN закрытым до мягкого срока 30 секунд, проверяет подпись ожидания,
причину и кнопку машин, затем открывает ворота и проверяет восстановление в том же документе.

`runtime.json` пишется в `XDG_DATA_HOME` сессии и удаляется после сценария, поэтому сценарии
идут строго по одному, а `startup.e2e.mjs` и `window.e2e.mjs` — разными запусками сессии.
Вне одноразовой сессии (`XDG_DATA_HOME` не в `/tmp/`) сценарии пропускаются: тест никогда не
пишет descriptor в настоящий профиль.

SE-10 запускает настоящий GrigDesk: временный корень со ссылками `server` и `shared` на
рабочее дерево, своими воротами и синтетическим `.env`, весь `isolatedEnv`, `GRIGDESK_ENV_FILE`
и отдельный `GRIGDESK_LOG`. Без своего журнала путь по умолчанию через ссылку `server` попал бы
в журнал живого сервера.

## Окружение Electron

`desktopLaunchOptions({ isolateEnv: true })` строит окружение по списку-разрешению:
`DISPLAY`, `XAUTHORITY`, `DBUS_SESSION_BUS_ADDRESS`, `HOME`, `XDG_*` каталоги, `GSETTINGS_BACKEND`,
`NO_AT_BRIDGE`, `PLAYWRIGHT_BROWSERS_PATH`, `LANG`, `PATH` из каталога Node и системных; плюс
явные добавления, кроме `HOME`, `XDG_*`, `DBUS_*`. Порт, ключи и маркеры живого сервера из
окружения исполнителя в приложение и его сервер не попадают.

В таком окружении нет `XDG_CURRENT_DESKTOP`, и Chromium выбирает открытое хранилище паролей —
окно отказывается стартовать из-за проверки связки ключей. Сценарии передают
`--password-store=gnome-libsecret`, как проверка пакета.

## Наблюдения и отказы

Заставка — окно с `file:…/splash/index.html`, главное — окно origin локальной трубы. Видимость
читается через `BrowserWindow` главного процесса; пока заставка жива, главное окно не должно
быть видимым ни в одном наблюдении. `launchDesktop` для `window.e2e.mjs` ждёт показа
главного окна, `launchDesktopRaw` возвращает приложение сразу.

Сбой транспорта или чужой HTTP-порт отражается состоянием профиля в уже показанном
интерфейсе. Отсутствующий runtime оставляет интерфейс приложения с localAvailable:false;
машины открываются по кнопке.
При перезапуске собственного сервера документ остаётся прежним; труба обновляет сессию.
«Закрыть заставку как человек» — `close()` окна заставки: только он порождает событие
`close`, программный `destroy()` — нет.

Изолированная сессия изредка возвращает 1 при успешном прогоне из-за FUSE-точки портала
документов — [помеха среды](isolated-session-doc-portal.md): повторить один раз.

Выбранный local ждёт сервер, вход и готовую рабочую область под заставкой до 30 секунд от show.
SE-17 задерживает listen на 6 секунд и auth/state на 1,5 секунды: главное окно скрыто до входа,
при первом показе уже online и без `.workspace-waiting`. Ошибка запуска (SE-08) или срок (SE-16)
открывают живое главное окно с причиной и выбором машин, без fatal-диалога.
Удалённая машина и отсутствие установки/выбора сохраняют быстрый старт (SE-REMOTE/SE-13).
Точный предел проверяется ручными часами ST-L02, E2E допускает задержку доставки до 5 секунд. Второй экземпляр
не создаёт дополнительного главного окна и не запускает вторые ворота; одновременно может
завершаться штатный переход от заставки к первому кадру. Закрытие заставки сохраняет
геометрию, хотя профиль уже может быть мигрирован и записан как v2.

SE-15 закрывает заставку до показа главного окна. showSplash предшествует prepare, поэтому
миграция может ещё не начаться: полный v1-файл остаётся прежним. Если атомарная запись
миграции уже завершилась, проверяется полный нормализованный v2 с локальным профилем,
допустимым выбором и прежней геометрией. Это две допустимые точки отмены, а не обязанность
записать v2 до закрытия заставки. Общий assertCancelledStartupSettings проверяется unit-тестом;
сам SE-15 требует разрешённой среды supervisor.

Тестовый UI в `stub.mjs` содержит `.shell` без `.workspace-waiting`: он представляет уже
готовую страницу. `launch.mjs` ждёт главное окно до 45 секунд, оставляя запас над production-
бюджетом. DW-E1 проверяет быстрый показ готового UI, DW-E8 — второй экземпляр, DW-E12 — геометрию.
UC-E01 проверяет срок недоступного явного local, UC-E03 — показ после listen и входа с прежней
защитой cookie и DOM, UC-E02 — пустой старт. SE-05b закрывает заставку после spawn до listen
и проверяет штатный выход собственного сервера.
