# IPC-барьер удерживает дочерний процесс

Неразрешённый Promise сам по себе не удерживает event loop Node. Дочерняя фикстура
может отправить `barrier` через IPC, затем завершиться без сигнала, пока родитель
ещё обрабатывает сообщение. Успешный `child.kill('SIGKILL')` также не доказывает
причину уже начавшегося завершения; проверка `child.signalCode` может получить null.

В `tests/server/fixtures/routes-publication-child.mjs` барьер перед отправкой
сообщения вызывает `process.channel?.ref()`. Открытый IPC удерживает child до
аварийной остановки родителем. Ожидание и хуки публикации не меняются; родитель
по-прежнему требует именно SIGKILL, затем проверяет восстановление публикации,
неизвестный current и освобождение lock.

Для проверки такой гонки полезно задержать родителя между получением барьера
и SIGKILL. Фикстура должна оставаться живой весь этот интервал. При завершении
родителя IPC закрывается; дополнительный бесконечный таймер не нужен.
