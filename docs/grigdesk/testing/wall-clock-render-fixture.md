# Точное время в компонентном тесте

Если тест задаёт `startedAt` перед асинхронной подготовкой браузера и компиляцией
SFC, время между подготовкой props и монтажом входит в отображаемую длительность.
Проверка точного текста `2:05` становится зависимой от скорости машины: компонент
может правильно показать `2:06`, а assert сообщит, что времени нет.

Для проверки формата и наличия времени фиксируй `Date.now` через
`t.mock.method(Date, 'now', () => now)` до подготовки стенда и вычисляй `startedAt`
из того же `now`. Контекст Node test автоматически восстанавливает метод после
теста. Assertions остаются точными; реальные интервалы компонента и его очистка
при размонтировании сохраняются.

Сценарий `LINE-01` в `tests/web/chat-thinking.component.test.js` проверяет строку
действия, длительность `2:05`, расход и SVG. Проверка обновления времени требует
отдельного управления часами; замороженный `Date.now` не доказывает работу тика.
