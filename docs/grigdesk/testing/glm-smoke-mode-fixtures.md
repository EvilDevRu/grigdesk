# Фикстуры режимов smoke и адаптера GLM

`runGlmLiveSmoke` и CLI в `server/scripts/glmLiveSmoke.mts` принимают `api` и
`coding-plan`. Неизвестный режим отклоняется с `glm_mode_not_admitted` до файловой
системы; оба известных режима требуют абсолютные пути binary/cache до чтения ELF.
Прежний запрет Coding Plan нельзя проверять вызовом с `workRoot: '/missing'`:
разрешённый режим справедливо доходит до `mkdtemp`.

CLI-проверки раннего отказа используют действительно неполные аргументы: отсутствие
`--confirm-live` или обязательных путей. Полная комбинация Coding Plan синтаксически
допустима и не обязана завершаться кодом `2`. Дочерний процесс получает собственные
`GRIGDESK_HOME`, `GRIGDESK_ENV_FILE` и `GRIGDESK_ARTIFACTS_DIR`, чтобы даже регрессия
проверки аргументов не открыла личный env-файл или каталог отчётов.

Допущенный адаптер объявляет `untrustedText` через отдельный `runUntrusted`. Прямой
чатовый `run` сохраняет отказ Factory/plan/scoped/untrusted до запуска процесса.
Структурные тесты различают эти входы; объявленная capability не разрешает обход
модельного режима. `commands()` доступен и у setup-only карточки без режима доступа.

Пакетный `glm-compatibility.test.mts` закрепляет точные identity уже выполненных живых
допусков и неизменяемость экспортируемого списка. Порядок записей не определяет допуск:
сравнение сортирует режимы, не меняя frozen array. После доказанного обновления admission
ожидаемые identity обновляются вместе с записью пакета.

Loopback-сценарии используют синтетический ключ и fetch guard. Они проверяют
протокол, HTTP-ошибки, остановку и resume; ранние CLI-пробы не выполняют model call.
Эти проверки не доказывают живую доступность Coding Plan или CLI-запись `--admit`.
