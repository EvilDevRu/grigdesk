# Порядок проверок новой системы обновления

Решение человека для задачи 100000000010: сохранить сданные 5 GREEN и 16 RED;
проверки ещё отсутствующих механизмов перенести после реализации.

Сданный тест не переписывается ради удобного RED. Ошибка импорта, ранний отказ формата
или неподдерживаемая раскладка не доказывают эффект подготовки, worker или восстановления.
После появления production-границы проверяется её наблюдаемый результат; аудит независимо
повторяет проверки. Зелёный счётчик прежнего набора не заменяет новые процессные,
браузерные и сквозные доказательства.

При запрете менять закреплённые тесты исполнитель сохраняет их снимок и честно называет
непроверенный остаток. Реальные Actions-артефакты и ручная приёмка не объявляются выполненными
по результату фикстуры. Полный набор проекта этим правилом не запускается.

Хост закрепляет manifest и суммы тестов после `done` узла TESTS; исход `failed` новый
снимок не создаёт. Если TESTS дополнил набор и вернул дефект продукта в BUILD, после ремонта
набор должен снова пройти через TESTS с исходом `done`. BUILD сохраняет подготовленные тесты
и manifest: замена manifest прежней копией не согласует дополненные тесты со старым снимком.
Доверенный снимок и его указатель меняет только штатный хостовый хук TESTS.
