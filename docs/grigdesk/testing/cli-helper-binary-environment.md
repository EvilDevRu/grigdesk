# Унаследованный серверный ELF меняет установку CLI-фикстуры

Упакованный helper получает `binary` из `GRIGDESK_SERVER_BINARY`. Это штатный контекст
внешнего ELF: `runtimeInstallationRoot()` указывает на его установку, хотя ресурсы helper-а
могут находиться в другом каталоге. Контракт задан в `server/scripts/sea/context.mts` и
`server/src/lib/runtimePaths.ts`.

Если тест наследует эту переменную от агента сервера, перенос своего helper-а не изолирует
установку. Проверки `tests/cli/menu-packaged.test.mts` могут увидеть команды разработки
исходного дерева либо не обнаружить запуск окна в журнале своей заглушки. Такой отказ
воспроизводится и с исходным меню без изменений оформления.

Прежний барьер «без TTY сохраняет open» при этом не просто краснел: helper открывал настоящее
`bin/grigdesk-app` рабочей установки. Под песочницей Codex (`bwrap`, `no_new_privs`)
`fusermount` не монтирует AppImage, и на рабочем столе остаётся бессрочное оповещение
«Cannot mount AppImage, please check your FUSE setup». Без песочницы откроется второе окно.
FUSE машины при этом исправен: обычный запуск монтирует тот же файл. Теперь пустой вызов
показывает справку; явный выбор открытия в меню по-прежнему требует изоляции установки.

`tests/cli/helpers/sandbox.mts` удаляет `GRIGDESK_SERVER_BINARY` из окружения ребёнка вместе
с другими машинными путями. Тогда переносимый helper определяет собственный корень по URL,
а тесты проверяют свою установку. Продуктовый выбор ELF и его контекст не меняются.
