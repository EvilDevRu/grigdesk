# Снимок состояния при проверке повторного close установщика

`PluginInstallService.recover()` нового владельца вызывает общий resolver установки.
Даже при `apply: null` resolver вправе удалить подтверждённые остатки из durable очереди
`cleanup` и записать обновлённое состояние. Завершённое задание при этом остаётся `done`.

Проверяя, что повторный `close()` прежнего владельца не пишет после освобождения owner
lock, снимайте эталон после `recover()` нового владельца, непосредственно перед `close()`.
Сравнение с более ранним снимком ошибочно приписывает прежнему владельцу штатную очистку
нового. Тест должен отдельно сохранить проверки durable outcome, освобождения workers и
запрета новому владельцу захватить lock до завершения старой транзакции.

Этот порядок применяется к apply и rollback в сценарии `M45-effects` файла
`tests/server/plugin-install-service-concurrency.test.js`.
