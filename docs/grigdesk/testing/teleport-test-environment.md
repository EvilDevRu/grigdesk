# Модалка «не открылась» в веб-тесте = стаб Teleport работает только при NODE_ENV=test

**Где:** любой компонентный веб-тест, который монтирует поверхность с модалкой —
`UiDialog` внутри проверяемого SFC (`tests/web/*.component.test.js`).

Симптом: диалог «не открывается». `wrapper.find('.ui-dialog')` пусто, хотя клик
прошёл и состояние открытия выставлено. Лечить тянет лишними `flushPromises` и
поиском ошибки в самом компоненте — виновата сборка теста.

Механика: `UiDialog` рендерит содержимое через `<Teleport to="body">`. Стаб VTU
(`global: { stubs: { teleport: true } }`) оставляет его на месте ТОЛЬКО в dev-ветке
Vue, а она включается по `process.env.NODE_ENV`. Без строки `process.env.NODE_ENV =
'test';` в начале файла теста стаб молча не действует: содержимое уезжает в
`document.body`, и поиск внутри wrapper его не видит. В `browser.document` оно при
этом есть — проверка `body.innerHTML.includes('ui-dialog')` отличает эту причину от
настоящей поломки за один шаг.

Лечение: ставить `process.env.NODE_ENV = 'test';` до импорта компонента и монтировать
со стабом телепорта — тогда модалка живёт внутри wrapper и её поля доступны обычными
`get/setValue`. Альтернатива без стаба — искать поверхность по `browser.document` и
оборачивать найденный узел в `DOMWrapper`.

Проверено на разделе «Настройки → Плагины»: тест каталога с NODE_ENV работал, а
соседний тест того же компонента без него падал на «модалка не открылась».
