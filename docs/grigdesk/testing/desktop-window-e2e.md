# Сквозная проверка локального окна

`tests/desktop/e2e/window.e2e.mjs` запускает настоящий dev Electron с Chromium sandbox
через `isolated-session.sh`. Все окна используют собственные абсолютные userData и
путь ключа внутри root теста. Helper сохраняет HOME/XDG/D-Bus обёртки и удаляет
NODE_OPTIONS/ELECTRON_RUN_AS_NODE только из окружения Electron-child.

Чистые `desktopLaunchOptions` проверяются `tests/desktop/launch-helper.test.js`.
Второй экземпляр запускается обычным spawn с теми же options, без добавленных
Playwright inspector flags. Импорт helper сам по себе Electron не запускает.

Окно стартует через [заставку](../web/desktop-startup.md), поэтому `launchDesktop` ждёт показа
главного окна, а не первой страницы: заставки `file:…/splash/index.html` уже нет, а видимое
окно открыло origin локальной трубы (до 30 с, минимум заставки — 2 с). `launchDesktopRaw` не ждёт
ничего — для [сценариев старта](desktop-startup-e2e.md). Сценарии offline при
старте живут там: интерфейс доступен независимо от сервера. Здесь отказ ключа проверяется
после показа (DW-E10), настройки оболочки доступны и без связи (SW-E03).

HTTP-заглушка слушает `listen(0, '127.0.0.1')`, не освобождает пробный порт перед bind.
Offline-сценарий и boot настоящего сервера вынужденно используют свободный порт
с отдельным резервированием. Их возможный конфликт порта учитывается отдельно.
Журнал заглушки хранит метод, путь, Host и наличие авторизации, без ключей и cookie.

Перехват `shell.openExternal` устанавливается и проверяется внутри main до действий.
Дочернее окно ожидается listener, поставленным перед кликом. Внешние ссылки проверяются
настоящими `mouse.click`: отменённая main-навигация оставляет ожидание следующего
Playwright locator незавершённым. Перед первым кликом ожидаются видимость нативного окна
и trial-проверка ссылки: ранний mouse.click может потеряться до показа окна.
Координаты сохраняются до кликов, а каждый результат
подтверждается точным списком вызовов shell. Системный браузер не запускается.

Настоящий GrigDesk поднимается через `pluginBootFixture` со своим состоянием. Проверки
не передают окну готовую fixture session или CLI cookie. Вход без пароля читает ключ
из effective env после публикации. После показа отозванная сессия с отсутствующим ключом или
ключом с правами 0644 даёт локальный отказ, исправление файла восстанавливает вход.
Response/pageerror listeners ставятся до контролируемого reload. SSE проверяется по
статусу и Content-Type; отдельный короткий fetch читает `event: hello` и отменяет reader,
не дожидаясь завершения постоянного EventSource продукта.

Отказ настоящей регистрации `/sw.js`, включая query, проверяется вместе с успешной
загрузкой обычного JS. Service worker API не подменяется, заранее засеянного профиля нет.
Cleanup закрывает Electron, затем собственные серверы и только после этого удаляет root.

```bash
npm --prefix desktop run build
NODE_TEST_MAX_RSS_MB=4096 PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/ms-playwright" \
  bash tests/desktop/e2e/isolated-session.sh \
  bash tests/run-node-tests-safe.sh --test-concurrency=1 --test tests/desktop/e2e/window.e2e.mjs
```

`PLAYWRIGHT_BROWSERS_PATH` нужен DW-E13 и DW-E14: они запускают обычный Chromium Playwright.
Обёртка подменяет HOME и XDG, и без этой переменной оба падают на «Executable doesn't exist»
в кэше временного HOME — это окружение, не регрессия ([кэш Playwright](playwright-xdg-cache.md)).

Нормальные размеры обязательны. Maximized проверяется отдельным подслучаем; отсутствие
оконного менеджера в Xvfb даёт NOT RUN этого подслучая. Разрешённый Notification API
не доказывает показ уведомления Linux; настоящий микрофон также требует ручной проверки.

## Общий модал настроек

SW-E01–04 проверяют точный прежний адрес, fixed DOM event, повтор/меню/native shortcut,
отказ для offline-документа и закрытие приложения на собственной HTTP-заглушке.
SM-E01–09 используют настоящий изолированный GrigDesk: один BrowserWindow, сохранение
документа, маршрута, текста и чата, общий Apply, nested/Escape/dirty-close и ошибку,
cold settings/browser/legacy/auth, клавишу при фокусе xterm, закреплённый UI и второй
экземпляр. DU-E05 отдельно проверяет один terminal/PTY и его прежний DOM.

Каталог web задаёт абсолютный `GRIGDESK_E2E_WEB_DIST`. Перед проверкой требуется
собственная сборка с `--outDir`; отсутствие index.html означает NOT RUN. Скриншоты
пишутся в абсолютный `GRIGDESK_E2E_ARTIFACTS`. Подготовка и запуск не меняют рабочий
web/dist, сервер или пакет человека. Физическая Ctrl+Alt+S доставляется через
`webContents.sendInputEvent`; Playwright keyboard проверяет ввод внутри документа.
Zoom125/200 проверяется через `setZoomFactor` при открытом общем модале.

«Открыть чат» и перезапуск сервера проверяются также same-document unit-тестами
с API-фикстурами. Готовый пакет проверяется [отдельным smoke без inspector](desktop-window-package.md).
Отсутствие дисплея, бинарника или доступного sandbox означает NOT RUN с точной причиной.

Дополнительные сценарии проверяют публичную инструкцию сервера чистому Chromium и
отсутствие серверных UI/JS, миграцию прежней cookie с сохранением clientScope, новую сессию
в памяти трубы при следующем запуске окна, восстановление сессии в чате без потери hash. Сессии Electron не засеваются:
даже старая cookie миграции сначала выдана входом по файлу ключа и сохранена самим окном.
Сценарий потери сессии меняет только файл своего сервера и перезапускает только его child.
GET/HEAD после 401 повторяется однократно после общего обновления сессии; POST не повторяется. Рабочие профиль, порт, ключ и сервер не используются.
Короткий DW-E16 со stub отдельно проверяет явную перезагрузку того же URL с hash и
обновление истёкшей сессии трубой. Автоматическое восстановление DW-E15 сохраняет документ.

## Геометрия desktop

WT-E01 проверяет собственные кнопки в топбаре: отсутствие нативного overlay, место для кнопок
при ресайзе и масштабе, их блокировку под настройками и медиа, drag/no-drag и одиночный Alt.
Нативный ввод идёт через `sendInputEvent` с контрольным Tab. Дополнительно снимается
собственный Xvfb-дисплей, чтобы исключить второй набор системных кнопок над страницей.

DU-E01–07 используют ту же настоящую key-only фикстуру: один первый кадр независимо
от прежнего ключа плотности, общий модал без потери разговора, сохранение
черновика и размеров после повторного запуска, body overlays и Escape, один terminal/PTY
при ресайзе и открытии настроек, постоянная рейка, zoom125% и восстановление сессии.

Перед запуском обязательно проверить `index.html` в собственном абсолютном
`GRIGDESK_E2E_WEB_DIST`, чтобы helper не выбрал рабочий `web/dist` по умолчанию.
`GRIGDESK_E2E_ARTIFACTS` задаёт абсолютный каталог PNG и отделяет снимки текущей проверки
от прежних запусков. Без него снимки идут в `~/.grigdesk/artifacts/desktop-window-e2e/screens`. Проверенная отдельная сборка не означает обновления рабочего окна.

UI-E01 проверяет упакованный `desktop/dist/ui` на настоящем изолированном сервере:
замена рабочего dist после запуска, пять разделов, семь панелей, настройки той же
версии и запрет Alt/Ctrl+R/Ctrl+Shift+R/F5 с контрольным Tab. UI из рабочего dist
для этого сценария не используется.
