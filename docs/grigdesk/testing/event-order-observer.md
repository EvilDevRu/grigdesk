# Порядок событий проверяется при доставке, а не после опроса

Если фикстура последовательно пишет ответ и финал в stdout, транспорт вправе
получить их одним чтением. Опрос массива событий через таймер найдёт ответ уже
после завершения хода. Проверка текущего `settled` в этот момент измеряет момент
опроса, хотя нормализованные callbacks могли прийти в правильном порядке.

Состояние хода фиксируется внутри callback завершённого ответа. После окончания
также сравниваются позиции ответа и итогового блока в полученной хронологии;
отсутствующий финал или обратный порядок не проходят проверку. Ожидание через
polling может остаться способом дождаться события, но не свидетельством порядка.

Это используется в `tests/server/codex-in-turn.test.js`: все прежние проверки
одного исходного хода, адресации steer, продолжения работы и отказа позднего ввода
сохранены. Производственный адаптер и transport fixture не меняются.
