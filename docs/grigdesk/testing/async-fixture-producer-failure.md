# Ожидание сигнала фикстуры связано с исходной операцией

Тест может ждать сигнал локального HTTP-приёмника, пока начатый ход ещё выполняется.
Если ход откажет до запроса, сигнал не придёт. Одного таймаута внутри хода недостаточно:
его Promise отклонится, а тело теста продолжит ждать сигнал и не вызовет `t.after`.

В `tests/server/deepseek-runtime-rollback.test.js` ожидание первого запроса использует
`Promise.race([firstHttp, first])`. Отказ исходного хода завершает тест и запускает
очистку HTTP-приёмника и временных каталогов. После штатного первого запроса тест
продолжает сценарий и отдельно ожидает результат хода после снятия удержания.

Это правило относится к любому сигналу фикстуры, который может породить только
одна асинхронная операция: ждать надо также её отказ, иначе общий прогон зависнет
вместо красного результата.
