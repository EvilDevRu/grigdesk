# Проверка единого приложения

Все Node-тесты запускаются через `tests/run-node-tests-safe.sh`. Несколько файлов собственного
набора выполняются с `NODE_TEST_MAX_RSS_MB=4096` и `--test-concurrency=2`. Для Electron нужна
одноразовая D-Bus/Keyring/Xvfb сессия; разные e2e-файлы запускаются последовательно из-за
фиксированного диапазона портов труб. Тестовые серверы используют случайные порты.

`tests/desktop/e2e/client.e2e.mjs` проверяет показ без сервера, добавление двух машин,
раздельное хранилище origin, переходы, offline, pin, несовместимость и отзыв. Повторная
привязка удалённой машины проверяет очистку прежнего origin до загрузки документа.
`pipe-upstream.test.js` отдельно проверяет потоковые тела, SSE и upgrade, отмену ожидающего
ключа, обновление местной сессии и запрет повтора POST. Обычный отказ прав не означает отзыв.

`startup.e2e.mjs` сохраняет проверки владения собственным сервером, второго экземпляра,
заставки и геометрии. Сервер и VPN больше не являются воротами показа главного окна.
`window.e2e.mjs` использует локально запечатанный пакет UI: запросы к машине идут через API,
дочерние документы используют origin трубы. Восстановление сессии сохраняет рабочий документ
и открытый общий модал настроек.

JVM-тесты `mobile/android/client/src/test` проверяют HTTP framing, общие векторы привязки,
профили, shell, отмену и решения жизненного цикла. Настоящий TLS-стенд принимает клиентский
сертификат и проверяет pin, POST 5 МиБ, SSE и бинарный туннель. Ворота Android — Gradle:
`tools/mobile build`, `:client:testDebugUnitTest` и `:client:lintDebug`. Они не заменяют
проверку на устройстве.

Удаление выбранного профиля в `client.e2e.mjs` выполняется кнопкой в списке машин с
подтверждением. Само удаление вызывает навигацию: ожидание результата запроса через
`page.evaluate` может потерять уничтоженный контекст, хотя запрос успешно выполнен.

Браузерные `client-responsive.test.js` и `client-phone.test.js` поднимают свой Vite без
живого API. Проверяются телефон, планшет в двух ориентациях и desktop, текст 100%/130%,
длинный код, вопрос, разрешение и карточка задачи. Изменение visualViewport моделирует
сокращение видимой области; реальная клавиатура Android принимается на устройстве.

Готовые ELF и AppImage проверяет [packaged smoke](desktop-window-package.md) обычным spawn
без inspector. Это подтверждает встроенный интерфейс и fuses, сохраняя защиту пакета.

Приёмка человеком остаётся отдельной: установка Linux, местный и удалённый чат, события,
терминал, файл, SSH с паролем, VDS при наличии и страница плагина. На Android дополнительно
нужны QR, микрофон, фон, блокировка, поворот и системные диалоги. Отсутствующие устройство,
ключ подписи или разрешённая команда среды отмечаются NOT RUN с точной причиной в журнале
конкретного прогона. Автоматический GREEN не подтверждает эти действия.
