# Таймаут навигации браузерной фикстуры

В `tests/web/provider-install.browser.test.js` ожидание элементов ограничено вызовом
`page.setDefaultTimeout(2000)`, а навигации — `page.setDefaultNavigationTimeout(30000)`.
Первое открытие страницы явно использует `timeout: 30000` и `waitUntil: 'domcontentloaded'`,
а `second.reload()` наследует тридцать секунд и ждёт `load`. Проверки прежнего id операции,
единственного POST и общей блокировки выполняются после загрузки страницы.

Без отдельного navigation timeout вызов `setDefaultTimeout(2000)` также задавал две секунды
для `reload()`. Это приводило к отказу до проверок восстановления операции.

Фикстура `client-browser.mjs` обслуживает исходное приложение через Vite. Перезагрузка
повторно запрашивает больше тысячи модулей, включая Monaco и Markdown. Истечение срока
ожидания `load` само по себе не доказывает сбой восстановления серверной операции:
страница может продолжить загрузку и показать прежний job с общей блокировкой.

При таком отказе отдельно замеряют событие загрузки и проверяют прежний id операции,
отсутствие повторного POST и блокировку соседнего действия. Диагностический опыт с
задержкой сети 30 мс воспроизводит двухсекундный timeout, после которого эти проверки
проходят. Опыт не меняет исходники или API продукта. Ожидание навигации в тесте должно
допускать загрузку приложения; требования к восстановлению проверяются по состоянию UI.
