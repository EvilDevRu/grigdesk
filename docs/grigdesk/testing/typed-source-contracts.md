# Проверки исходника после переноса на TypeScript

Проверка текста исходника должна допускать синтаксис TypeScript и обязательное
многострочное оформление. Смена расширения в загрузчике сама по себе этого не обеспечивает.

В `PipelineView.pipelineContextDetails` объект `details` содержит `taskId`, `stageId`
и `tab`. Сторож читаемости требует разнести три поля по строкам. Регулярное выражение
с запретом перевода строки между полями отвергает такое оформление при прежних значениях
и неизменном исполняемом коде.

В `TaskModal.launchPayload` обращение `launchForm.value!` содержит утверждение наличия
значения. Этот оператор удаляется при компиляции и не меняет тело запроса. Проверка
текста `launchForm.value.profile` без учёта `!` не доказывает сохранность API-контракта.

Для проверки состава объекта подходит обход TypeScript AST. Текстовая проверка должна
допускать пробелы, переводы строк и завершающую запятую между теми же полями. Поведение
поставщика контекста и содержимое команды отдельно закрепляют компонентные сценарии.

SSE получает имена из `WEB_SSE_SIGNALS` общего контракта, а не локального array literal.
`sseSubscriptions.js` проверяет присваивание и цикл подписки в `useSse`, затем сверяет
обработчики с настоящим общим списком. Снимки экспортов и формы stores учитывают новые
публичные поля, не требуя отсутствия функциональности, добавленной после TS-миграции.
При нескольких фабриках store выбирается по прежнему `$id`, а не по первому export:
появление own-ветви не меняет идентификатор tracker store в baseline.
Runtime baseline включает восстановление авторизации, пагинацию и окна истории чатов,
состояние смешанных источников, новые exports установщика и актуальные workspace routes.
Проверка потребителей не сканирует игнорируемые `docs/plans` и `docs/local`: это локальные
планы и опыт машины, а не поставляемая документация или исполняемые импорты.

Baseline читаемости сохраняет только фактически оставшийся долг. Перед его сокращением
проверяются отсутствие новых нарушений и неувеличение каждого счётчика; исчезнувшие
сигнатуры удаляются, чтобы проверка точного совпадения оставалась зелёной.

Публичные типы own-ветвей избранного и отметок включают настоящий Pinia `$onAction`.
Это позволяет App передавать их межоконной синхронизации без приведения к полному tracker store.
