# Веб-тест монтирует SFC дважды — а работает со сторами первого теста

**Где:** `tests/web/*.component.test.js` — все, кто компилирует `.vue` через `compileScript`
и грузит результат как `data:`-модуль.

Симптом обманчивый: второй тест в файле падает, а в дампе DOM стоит разметка с данными
ПЕРВОГО. Выглядит как «компонент не перерисовался» или «стор не сбросился» — и лечить
тянет заглушки, хотя виноват загрузчик модулей.

Механика: заглушки подставляются заменой импортов на `globalThis.__что-то`, и в собранном
модуле это **top-level `const`** — вычисляется один раз при первом импорте. А сам модуль
Node кэширует по URL, то есть по всей строке `data:text/javascript;base64,…`. Байты кода
у двух монтирований одного файла совпадают: `id` (scopeId) в вывод `compileScript` **не
попадает** — его дописывает уже плагин сборщика (проверено на `TaskModal.vue`: две
компиляции с разными `id` дают побайтово равный текст, `data-v-…` в нём нет). Значит второй
`import()` возвращает первый модуль с уже привязанными сторами.

Лечится хвостом-nonce в самом URL — `…base64,${код}#${n}`: фрагмент код не меняет, а ключ
кэша делает разным. Образцы — `tests/web/telegram-connect.component.test.js` и
`telegram-expand.component.test.js`; там же на всякий случай разведены имена pinia-сторов
(`defineStore('…-'+nonce)`), чтобы совпадение id не сложило состояние двух тестов.

**Второе свойство того же загрузчика: у `data:`-модуля нет базового пути.** Любой
оставшийся в скомпилированном SFC относительный импорт падает
`ERR_UNSUPPORTED_RESOLVE_REQUEST`, причём **на этапе импорта модуля**, то есть роняет
не один тест, а весь файл разом — новый `import { useTaskSeenStore } from
'../stores/taskSeen.ts'` в `TaskModal.vue` погасил оба его компонентных теста, хотя к
проверяемому поведению отношения не имел. Поэтому КАЖДЫЙ импорт вью заменяется
заглушкой прямо в исходнике (`.replace(…, 'const … = globalThis.__…')`), а список замен
обязан идти вровень с импортами компонента: добавили импорт во вью — добавьте замену в
тестах, которые его монтируют.

**Заглушка нужна не всякому импорту: ЧИСТЫЙ модуль подставляется настоящим.** Относительный
путь из `data:`-модуля не резолвится, но абсолютный `file://` — резолвится, и для модуля без
Vue/pinia/DOM это лучше заглушки: тест проверяет то самое правило, что работает в бою. Приём
уже был у `shared/factoryDebug.ts`; так же подставлялся и `shared/companion-run.js`, пока его
не сняли вместе с компаньоном (2026-09-10):

```js
const PURE_MODULE_URL = pathToFileURL(fileURLToPath(
  new URL('../../web/src/shared/<pure-module>.js', import.meta.url),
)).href;
// …
.replace("from '../shared/<pure-module>.js';", `from "${PURE_MODULE_URL}";`)
```

Заглушка на его месте означала бы, что правило чистого модуля проверяется копией,
написанной в тесте, — то есть не проверяется вовсе.

**И то же самое ловит ПРАВКУ существующего импорта, а не только новый.** Замена ищется
по ТОЧНОЙ строке, поэтому снятие одного имени из уже заглушённого импорта
(`import { documentLinkFromClick, documentRouteHref } …` → `import { documentLinkFromClick } …`)
делает `.replace()` промахом, импорт остаётся живым и файл умирает целиком. Симптом сбивает
с толку сильнее, чем у нового импорта: падают ВСЕ тесты трёх файлов сразу
(`chat-slash-menu`, `chat-task-tooltip`, `chat-dictation` — 45 штук), причём с именами про
диктовку, меню команд и кольцо контекста, то есть про что угодно, кроме тронутой ссылки.
Правило простое: тронул строку импорта в SFC — прогони `grep` этой строки по `tests/web`.

**Заодно про «проверить замером»:** happy-dom раскладку не считает —
`getBoundingClientRect()` там нули, `scrollWidth` равен `clientWidth` всегда. Поэтому
статический контракт стережёт CSS-правило, а реальную геометрию автоматически измеряет
отдельный headless Chrome: `npm --prefix web run test:ui-browser`. Он запускает dev-only
gallery во временном профиле и проверяет матрицу viewport-ов; ручной взгляд не заменяет
этот gate.
