# Отказ запуска браузера оставляет Vite открытым

В `tests/web/helpers/client-browser.mjs` сервер Vite начинает слушать до
`chromium.launch()`, а `t.after` регистрируется только после успешного запуска браузера.
Если нужной ревизии Playwright нет, запуск сразу сообщает `Executable doesn't exist`,
но сервер остаётся открыт и удерживает процесс Node. Тестовые сценарии могут уже
показать отказы, а общий прогон не завершится до внешнего таймаута.

Воспроизведение не требует менять установленный браузер: отдельному процессу задают
`PLAYWRIGHT_BROWSERS_PATH` на пустую временную папку и вызывают `clientBrowser`.
Контекст, собирающий callbacks `after`, получает ноль callbacks; после исключения
`process.getActiveResourcesInfo()` содержит `TCPServerWrap`. Ограниченный внешний
запуск завершается кодом 124. С доступным браузером регистрируется очистка,
которая закрывает сервер, и процесс завершается самостоятельно.

Исправление должно регистрировать очистку по мере получения ресурсов, до следующих
операций, способных выбросить исключение: кэш, сервер, браузер. Отказ закрытия одного
ресурса также не должен мешать освобождению остальных. Само отсутствие браузера
остаётся ошибкой окружения; подавлять её или считать такой тест пройденным нельзя.

При разборе старого таймаута нужно учитывать изменение окружения между запусками:
установка браузера после начала зависшего прогона позволяет новому прогону пройти,
но не освобождает сервер, оставленный первым процессом. Успех нового прогона не
опровергает утечку при неуспешной подготовке.

См. также [ревизии браузеров Playwright](playwright-browser-revision.md) и
[перенаправление кэша](playwright-xdg-cache.md).
