# Проверка соединения трекера

`POST /api/trackers/test-connection` принимает `driverId`, `settings` и `expectedRevision`.
Проверка доступна только браузерной сессии с JSON и своим Origin, как запись настроек.
Схема драйвера проверяется до импорта; `own`, удалённые и неизвестные драйверы отклоняются.
UI отправляет только видимые поля текущего режима схемы.

Проверка адресует драйвер в редакторе независимо от подключения доски. Черновик объединяется
с его сохранёнными реквизитами по тем же правилам, что при записи: пустое поле сохраняет
прежнее значение. Файлы реквизитов, выбор и ревизия доски не меняются, SSE смены нет.

Реестр удерживает общий lease пакета на время проверки. Отдельный экземпляр получает
временный каталог, cookie-файл и очередь; после `testAuth` вызывается `dispose`, затем
удаляется временный каталог. Cookie и кеш авторизации действующей доски не используются.
Импорт остаётся загруженным в ESM, поэтому последующая замена пакета требует перезапуска
по обычному контракту реестра.

Успех возвращает `{ ok: true }`, отказ авторизации — `{ ok: false, error }`.
Значения секретных полей и их URL-кодированные формы маскируются в тексте отказа.
Неизвестное исключение драйвера получает общий текст без исходного сообщения.
Устаревшее поколение, недоступность пакета и некорректный запрос возвращаются как ошибки HTTP.

Доска называет выбранный драйвер в сообщении об отказе обновления; без каталога остаётся
нейтральная подпись трекера. Подробности показывают исходную причину чтения.
Общий API использует `tracker_error`, а dashboard сохраняет структурированные ошибки ядра.

Проверки: `tests/server/tracker-connection.test.js` и
`tests/web/tracker-connection.component.test.js` покрывают черновики, сохранённый секрет,
временную сессию, отсутствие переключения, защиту API и сообщения Jira.
