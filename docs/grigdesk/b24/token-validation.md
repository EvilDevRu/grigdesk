# Валидация токенов подключения

Jira Cloud принимает email и API-токен Atlassian вместо пароля аккаунта.
[Atlassian указывает переменную длину токенов](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/),
поэтому фиксированная длина или единственный обязательный префикс не используются.
[Контракт Basic auth Jira](https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/)
отдельно описывает замену пароля API-токеном. Токены со scopes используют другой адрес API;
проверка соединения также обнаруживает несовместимость токена с транспортом драйвера.

В режиме токена Б24 REST получает OAuth `access_token`, а не пароль и не URL вебхука.
[Документация OAuth Б24](https://apidocs.bitrix24.com/settings/oauth/index.html)
показывает получение токена и его отдельный срок действия. Проверка формата не подтверждает
срок, права или принадлежность аккаунту. Режим пароля Б24 остаётся отдельным режимом схемы.

Строковое секретное поле может объявить `format: 'api-token'`. Для уже установленных
пакетов распознаётся общая подпись `core.trackerAccessToken`; имена поставщиков и id
драйверов в валидации не участвуют. Логика находится в
`shared/trackers/settingsValidation.ts` и используется web и HTTP.

Локальная проверка использует широкий алфавит `b64token` из
[RFC 6750 §2.1](https://www.rfc-editor.org/rfc/rfc6750.html#section-2.1): латинские буквы,
цифры, `-._~+/` и завершающий `=`. Пробелы, переносы, кавычки, префикс `Bearer `,
URL и кириллица отклоняются без изменения ввода. Длина и наличие префикса не фиксируются.
Это фильтр явных ошибок, а не способ доказать, что введённая строка не является паролем.

При сохранении все схемы и видимые токены проверяются до первой записи. Новый непустой
токен проходит `testAuth` через отдельную временную сессию драйвера. Отказ останавливает
всю запись: credentials, выбор, revision и SSE не меняются. Поэтому пароль допустимого
алфавита также не записывается. Сеть недоступна — форма сохраняет черновик для повтора.

Пустой ввод использует сохранённый секрет; обязательный токен без сохранённого значения
вызывает ошибку поля. Скрытый токен не проверяется в режиме пароля. Ошибка HTTP имеет
код `tracker_token_invalid`, `driverId` и `field`, но не содержит введённого значения.
UI открывает нужный редактор, показывает причину возле поля и сохраняет черновик.
Формат проверяется также перед явной проверкой соединения.

Профильные проверки: `tracker-token-validation.test.mts`,
`tracker-token-validation.test.js`, `tracker-token-validation.component.test.js`.
