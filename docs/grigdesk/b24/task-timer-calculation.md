# Таймер задачи: timer_elapsed из B24 всегда 0 — считать от timer_started_at

**Где:** `web/src/shared/format.ts` (`liveTimerSec`), потребители — `TaskModal`, `BoardView`,
`PipelineView`.

`getTodayData` отдаёт `timer_elapsed = 0` даже у задач с `timer_running = true` (проверено:
ноль у всех четырёх идущих). Настоящая точка отсчёта — `timer_started_at`, **Unix в СЕКУНДАХ**
(не мс), адаптер кладёт её в `timerStartedAt` — поле добавляется в `_getDashboard`, в `mapTask`
его нет. Исходно все три места считали `timerElapsed + (now − boardLoadedAt)`, то есть показывали
**возраст открытой вкладки**: задача, взятая в 13:50, после F5 показывала «0:00:40».

У идущего таймера накопленное НЕ прибавляем — если B24 однажды начнёт заполнять `timer_elapsed`,
прибавка даст двойной счёт текущей сессии.

Ещё две особенности того же ответа, на них легко обжечься:
- `timer_running = true` бывает у **нескольких** задач сразу (все «взятые», у кого таймер не
  остановлен), а `activeTimer.task_id` — один. Это разные вещи.
- Панель `BoardView` обязана строиться через `tasks.filter(timerRunning)`. Глобальная
  всплывашка получает тот же полный набор, а поставленные в ней на паузу задачи временно
  оставляет для кнопки повторного запуска; её счётчик всё равно считает только
  `timerRunning`. `find` здесь молча скрывает остальные таймеры, хотя навигационный чип
  правильно считает их все.
- В `worked_tasks`/`today.hours` идущие задачи **не попадают** — туда падает уже зафиксированное
  время, после остановки таймера. Сверять одно с другим бессмысленно.
