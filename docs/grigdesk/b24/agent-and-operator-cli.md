# CLI для агента и оператора

Доступные команды:

```text
tracker boards                    # включённые доски и default
tracker dashboard
tracker task <id>
tracker comment <id> <текст>
tracker timer <id> start|pause|stop
tracker start <id>
tracker complete <id>
tracker renew <id>
tracker analyze <id>           # очередь триажа
tracker launch-options <id>    # профиль, маршруты и подсказки
tracker launch <id>            # запуск из JSON-объекта stdin
tracker create                 # JSON читается из stdin
tracker users [запрос]
```

Без явной цели команды используют доску по умолчанию; оценка и запуск сначала проверяют own-запись. `--board <id>` перед командой
или после неё выбирает конкретный драйвер: `tracker task 42 --board jira`.
Для create также доступно поле `board` в JSON; флаг меняет только URL, stdin передаётся
без изменения байтов. Разные цели в URL и JSON отвергает сервер. После `--` флаги
считаются буквальным текстом комментария. У локальных команд и `boards` цели нет.

`boards` печатает JSON включённых внешних драйверов в сохранённом порядке: `id`, `name`,
`status`, `default`, `reason`. Собственные задачи в этот список не входят.
Неизвестная или выключенная цель даёт явный отказ; обращения к дефолту вместо неё нет.

Для analyze/launch-options/launch флаг `--board` сначала читает адресный context,
проверяет полный source и передаёт его серверу в body/query.source. Launch читает один
JSON-объект с прежними полями запуска (profile, route, title, description, acceptanceCriteria и т. д.).
Выбирайте профиль и маршрут по launch-options. Противоречие source в stdin и --board,
неверный JSON или не-объект дают код 2 до POST. Без флага source не добавляется; явно
указанный source в launch stdin сохраняется. Unknown/disabled context даёт отказ без fallback.
`start` по-прежнему означает renew + timer, а `launch` запускает конвейер.

Просьба «поставь задачу в Битриксе» выполняется сразу через `tracker create`, без поиска
другого API и без предварительной проверки сессии:

```bash
tracker create <<'JSON'
{"title":"Краткий заголовок","description":"Суть, шаги и проверяемые кейсы","priority":1}
JSON
```

Текст задачи содержит конкретные ID, URL и даты, если они известны, но не содержит код
или неподтверждённые гипотезы о причине, если человек их не просил. После успеха достаточно
вернуть номер или ссылку задачи.

Поля создания:

- `priority`: `0` низкий, `1` средний, `2` высокий; поддерживаются и словесные алиасы.
- `responsibleId`: обычно не передавать либо передавать `null` — клиент подставит текущего
  пользователя. Значение `0` не является дефолтом и уходит на портал буквально; портал
  отвечает ошибкой о несуществующем исполнителе, команда завершается кодом 22 и печатает
  в stderr причину из ответа сервера. Свой ID виден в `tracker dashboard`, другого исполнителя
  нужно сначала найти через `tracker users <запрос>`. Конкретные пользовательские ID не
  хардкодятся.
- `groupId`: пропуск, `null` или `0` означает задачу без группы.
- `createdById`: без явной необходимости не передавать — портал использует владельца сессии.
- `images`: список файлов, которые клиент сначала загрузит на диск портала.

Проверка валидности приоритета выполняется до входа и загрузки файлов. Ошибка авторизации
или портала возвращается самой командой; отдельный профилактический запрос не нужен.

## Результат и коды выхода

Успех — код 0 и тело ответа GrigDesk в stdout без изменений. При отказе stdout пуст, а
причина по-русски — в stderr:

- 22 — HTTP вне 2xx (включая redirect) или сеть: `Запрос к GrigDesk завершился ошибкой HTTP
  <код>: <причина>`, где причина — поле `message` ответа сервера, либо
  `Не удалось связаться с GrigDesk.`; после 300 с ожидания сообщение предупреждает, что
  операция могла выполниться, и просит проверить результат перед повтором;
- 1 — нет токена (`Нет токена: <путь>.`) или неверные настройки; HTTP не выполняется;
- 2 — неверные аргументы (причина и справка `tracker --help`) либо неверный stdin запуска/конфликт source.

`start <id>` подавляет отказ возобновления и возвращает только ответ запуска таймера. Запрос
`users` из нескольких слов берётся в кавычки: лишний аргумент — код 2. Адрес, токен, сборка
и установка — в [команде tracker](binary-cli.md).
