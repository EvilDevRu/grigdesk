# CLI для агента и оператора

## С чего начать

Задачи внешних трекеров, включая Discript, читаются и создаются через `tracker`.
Это команда терминала, отдельного MCP-инструмента для неё не требуется.
Если `tracker` недоступен по имени, из корня исходников используй
`bin/grigdesk-ctl tracker` с теми же аргументами. Обёртка запускает готовый бинарник,
а при его отсутствии — исходник; сборка для такого вызова не нужна.

Если человек назвал трекер, укажи его явно через `--board <id>`. Если id неизвестен,
один раз прочитай `tracker boards` и выбери id по имени. Например, Discript CRM
поставляется драйвером `grigdesk-b24-discript`; активное подключение определяется
живым списком. Не меняй default ради одной задачи. Встроенной доски нет.

Просьба «можем ли создать» требует проверки, без пробной записи: `boards` подтверждает
включение и состояние, но не право записи. Поддержка создания объявлена в
`GET /api/trackers` (`capabilities.create`), право конкретного пользователя проверяет
внешний сервис при записи. Чтение задачи или доступная кнопка не доказывают успешное создание.
Для этой проверки не нужны запуск Vite и открытие формы в браузере.

Просьба «создай/поставь задачу» выполняется сразу адресной командой `create`.
Отдельная проверка сессии перед ней не нужна: отказ вернёт сама команда.
Браузер используется для запроса проверить интерфейс либо если нужное действие
не поддерживается CLI, а не для поиска уже описанной команды.

## Команды и выбор доски

Доступные команды:

```text
tracker boards                    # включённые доски и default
tracker dashboard
tracker task <id>
tracker comment <id> <текст>
tracker timer <id> start|pause|stop
tracker start <id>
tracker complete <id>
tracker renew <id>
tracker create                 # JSON читается из stdin
tracker users [запрос]
```

Без явной цели команды используют доску по умолчанию. `--board <id>` перед командой
или после неё выбирает конкретный драйвер: `tracker task 42 --board jira`.
Для create также доступно поле `board` в JSON; флаг меняет только URL, stdin передаётся
без изменения байтов. Разные цели в URL и JSON отвергает сервер. После `--` флаги
считаются буквальным текстом комментария. У локальных команд и `boards` цели нет.

`boards` печатает JSON включённых внешних драйверов в сохранённом порядке: `id`, `name`,
`status`, `default`, `reason`. Встроенного источника задач нет.
Неизвестная или выключенная цель даёт явный отказ; обращения к дефолту вместо неё нет.

## Создание

Адресная команда сохраняет цель независимо от того, какая доска выбрана по умолчанию.
Пример для Discript (id подключения предварительно известен):

```bash
tracker --board grigdesk-b24-discript create <<'JSON'
{"title":"Краткий заголовок","description":"Суть, шаги и проверяемые кейсы","priority":1}
JSON
```

Без конкретного трекера `tracker create` использует текущую доску по умолчанию.
При отсутствии команды по имени пример вызывается как
`bin/grigdesk-ctl tracker --board grigdesk-b24-discript create` с тем же stdin.

Текст задачи содержит конкретные ID, URL и даты, если они известны, но не содержит код
или неподтверждённые гипотезы о причине, если человек их не просил. После успеха достаточно
вернуть номер или ссылку задачи.

Поля создания:

- `priority`: `0` низкий, `1` средний, `2` высокий; поддерживаются и словесные алиасы.
- `responsibleId`: обычно не передавать либо передавать `null` — клиент подставит текущего
  пользователя. Значение `0` не является дефолтом и уходит на портал буквально; портал
  отвечает ошибкой о несуществующем исполнителе, команда завершается кодом 22 и печатает
  в stderr причину из ответа сервера. Свой ID виден в `tracker dashboard`, другого исполнителя
  нужно сначала найти через `tracker users <запрос>`. Конкретные пользовательские ID не
  хардкодятся.
- `groupId`: в Б24 пропуск, `null` или `0` означает задачу без группы. В GrigTasks
  проект обязателен. Ошибка отсутствующего проекта исправляется отдельной задачей драйвера.
- `createdById`: без явной необходимости не передавать — портал использует владельца сессии.
- `images`: список файлов для загрузки на портал, только если выбранный драйвер
  объявляет `capabilities.attachments`. При отсутствии поддержки сервер возвращает
  `attachments_unsupported`; не обещай прикрепить скриншоты и не теряй их молча.

Проверка валидности приоритета выполняется до входа и загрузки файлов. Ошибка авторизации
или портала возвращается самой командой; отдельный профилактический запрос не нужен.

## Результат и коды выхода

Успех — код 0 и тело ответа GrigDesk в stdout без изменений. При отказе stdout пуст, а
причина по-русски — в stderr:

- 22 — HTTP вне 2xx (включая redirect) или сеть: `Запрос к GrigDesk завершился ошибкой HTTP
  <код>: <причина>`, где причина — поле `message` ответа сервера, либо
  `Не удалось связаться с GrigDesk.`; после 300 с ожидания сообщение предупреждает, что
  операция могла выполниться, и просит проверить результат перед повтором;
- 1 — нет токена (`Нет токена: <путь>.`) или неверные настройки; HTTP не выполняется;
- 2 — неверные аргументы: причина и справка `tracker --help`.

`start <id>` подавляет отказ возобновления и возвращает только ответ запуска таймера. Запрос
`users` из нескольких слов берётся в кавычки: лишний аргумент — код 2. Адрес, токен, сборка
и установка — в [команде tracker](binary-cli.md).

При неизвестном результате создания не повторяй POST, пока не проверил наличие задачи
на той же доске. Успешный номер при дальнейшем чтении также адресуй через `--board`.
