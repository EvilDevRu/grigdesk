# CLI для агента и оператора

Доступные команды:

```text
b24 dashboard
b24 task <id>
b24 comment <id> <текст>
b24 timer <id> start|pause|stop
b24 start <id>
b24 complete <id>
b24 renew <id>
b24 create                 # JSON читается из stdin
b24 users [запрос]
```

Просьба «поставь задачу в Битриксе» выполняется сразу через `b24 create`, без поиска
другого API и без предварительной проверки сессии:

```bash
b24 create <<'JSON'
{"title":"Краткий заголовок","description":"Суть, шаги и проверяемые кейсы","priority":1}
JSON
```

Текст задачи содержит конкретные ID, URL и даты, если они известны, но не содержит код
или неподтверждённые гипотезы о причине, если человек их не просил. После успеха достаточно
вернуть номер или ссылку задачи.

Поля создания:

- `priority`: `0` низкий, `1` средний, `2` высокий; поддерживаются и словесные алиасы.
- `responsibleId`: обычно не передавать либо передавать `null` — клиент подставит текущего
  пользователя. Значение `0` не является дефолтом и уходит на портал буквально; портал
  отвечает ошибкой о несуществующем исполнителе, команда завершается кодом 22 и печатает
  в stderr причину из ответа сервера. Свой ID виден в `b24 dashboard`, другого исполнителя
  нужно сначала найти через `b24 users <запрос>`. Конкретные пользовательские ID не
  хардкодятся.
- `groupId`: пропуск, `null` или `0` означает задачу без группы.
- `createdById`: без явной необходимости не передавать — портал использует владельца сессии.
- `images`: список файлов, которые клиент сначала загрузит на диск портала.

Проверка валидности приоритета выполняется до входа и загрузки файлов. Ошибка авторизации
или портала возвращается самой командой; отдельный профилактический запрос не нужен.

## Результат и коды выхода

Успех — код 0 и тело ответа GrigDesk в stdout без изменений. При отказе stdout пуст, а
причина по-русски — в stderr:

- 22 — HTTP вне 2xx (включая redirect) или сеть: `Запрос к GrigDesk завершился ошибкой HTTP
  <код>: <причина>`, где причина — поле `message` ответа сервера, либо
  `Не удалось связаться с GrigDesk.`; после 300 с ожидания сообщение предупреждает, что
  операция могла выполниться, и просит проверить результат перед повтором;
- 1 — нет токена (`Нет токена: <путь>.`) или неверные настройки; HTTP не выполняется;
- 2 — неверные аргументы: причина и справка `b24 --help`.

`start <id>` подавляет отказ возобновления и возвращает только ответ запуска таймера. Запрос
`users` из нескольких слов берётся в кавычки: лишний аргумент — код 2. Адрес, токен, сборка
и установка — в [команде b24](binary-cli.md).
