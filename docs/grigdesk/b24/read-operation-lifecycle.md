# Срок и отмена чтений Б24

Адаптер держит одну физическую promise-очередь для сессии портала. Чтения идут через
`B24ReadOperations`, мутации — через ту же очередь с новой версией объединения.
Истечение публичного срока не освобождает физическую очередь: следующий элемент
начинается после фактического окончания активной работы.

## Общее чтение

Одинаковый ключ в одном экземпляре адаптера и одной версии операций разделяет работу.
Срок — 25 000 мс с постановки в очередь до разбора тела. Присоединение потребителя
не продлевает его. Отменённый в очереди callback не вызывает клиент портала.
Постановка любой мутации меняет версию: обновление после действия читает заново.

Подписчики отменяются независимо. Уход последнего прерывает общую работу; новое чтение
получает новый срок. Контекст AsyncLocalStorage передаёт общий AbortSignal всем
вложенным raw(), включая вход и POST, которыми портал обслуживает чтение.
Signal остаётся действующим при чтении тела после получения заголовков. Отмена
не запускает повтор fetch. Вызовы вне контекста чтения сохраняют прежние правила повторов.

GET связывает подписку с незавершённым HTTP-ответом: aborted входящего запроса и close
ответа до writableEnded снимают потребителя. Нормальный ответ отменой не считается.
Обработчики снимаются при любом исходе. Это распространяется на dashboard, карточку,
комментарии, пользователей, группы и холодную identity трёх локальных хранилищ.
POST/PUT/DELETE не получают отмену ушедшего HTTP-клиента.

## Владелец сессии

Готовая identity текущего поколения возвращается копией до физической очереди.
Холодное определение имеет общий срок и отмену; неизвестная identity остаётся отказом,
а не пустым набором локальных меток. `invalidate()` отменяет чтения и сбрасывает кэш.
Проверка signal перед публикацией не позволяет позднему результату восстановить старый scope.
Кэш живёт только в памяти экземпляра адаптера и не выбирается запросом окна.

Изменение baseUrl, login или password создаёт новое поколение. Cookie jar адаптера имеет
суффикс sha256 от нормализованного адреса портала без конечных слешей и login.
Пароль не входит в имя файла. Прежний общий cookie-файл не импортируется и не удаляется;
первый вход использует настроенные credentials. Работа прежнего аккаунта остаётся
под общей очередью и пишет только свой jar. Прямой B24Client вне адаптера сохраняет
прежний контракт пути cookie.

## Диагностика

Штатный `fastify.log.debug` получает этапы queued, started, request, headers, settled.
Разрешённые поля: закрытое имя operation, phase, outcome, attempt, status, ms, waitMs.
Settled фиксирует исход ожидания подписчиков; при отмене физическая работа может
ещё завершаться, сохраняя место в очереди.
Операции: identity, dashboard, task, taskPage, users, groups, probe.
В журнал не попадают ключ объединения, URL/query, task id, логин, cookies,
тело задач, сообщения ошибок и стеки. Отказ наблюдателя не влияет на чтение.

Проверки: `b24-read-operations`, `b24-read-fetch`, `b24-adapter-reads`, `b24-read-http`
в `tests/server/`; фикстуры используют барьеры, управляемые часы и локальный HTTP.
