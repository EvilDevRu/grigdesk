# Граница B24

Задача №100000000000: доска и действия используют общий runtime реестра трекеров и
совместимый фасад `/api/b24/*`; ссылка на внешнюю задачу принадлежит драйверу.
Медиа использует локальный pipeline, вход в фабрику — `engine/bin/factory`.
Команда `b24` идёт по цепочке `b24/src` → собранный `bin/b24`
→ локальный HTTP API GrigDesk (`/api/b24/*` с CLI-токеном); без сборки `bin/grigdesk-ctl b24`
исполняет тот же исходник. Прямого клиента портала, cookies и кредов у команды нет: сессией
портала владеет сервер ([команда b24](binary-cli.md)). Сессионный клиент, разбор HTML,
загрузка файлов и показатели доработанного портала принадлежат отдельному пакету
`b24-custom`. Встроенный `b24-stock` использует исходящий REST с access token.
Ядро передаёт драйверу только его credentials, постоянные пути и общую очередь;
потребители не получают сырой клиент. Прямых путей к checkout драйвера в runtime ядра нет.
Полный контракт авторизации, HTTP и мутаций — в [b24.md](README.md).
