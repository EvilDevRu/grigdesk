# Восстановление чтения доски Discript CRM

HTTPS-драйвер `grigdesk-b24-discript` использует один срок 25 секунд для
`getDashboard`. Он покрывает профиль для холодной identity, страницы всех ролей
и активные таймеры. Драйвер учитывает отмену HTTP-потребителя. Фасад пропускает
обновление состояния подключения при такой отмене. Окончательный отказ одного
чтения отменяет оставшиеся операции доски.

Известная временная ошибка DNS, соединения или чтения успешного HTTP-ответа
разрешает один повтор упавшего GET с паузой 500 мс. При повторе используются
тот же срок и сигнал. Другие успешные чтения доски не запускаются повторно.
Ответы с HTTP-ошибкой, ошибки TLS и JSON не повторяются. Правила отдельных
запросов карточки, проверки токена и записи остаются прежними.

Фасад после загрузки подтверждает identity из кэша драйвера для текущего адреса
и токена. Проверка соединения читает профиль заново. Если обновление завершилось
ошибкой, панель сохраняет последний успешный снимок по правилам
[общей доски](unified-board.md).

При подробном уровне `host.traceRead` передаёт попытку с `operation=dashboard`,
`phase=settled`, длительностью и `transport.resource` из набора
`identity`, `tasks`, `timers`. Поле `transport.code` содержит код из закрытого
списка, `deadline` при истечении общего срока или `unknown`. Диагностика
исключает URL, query, реквизиты, тело и исходный текст исключения.

Регресс проверяет `tests/dashboard-recovery.test.js` пакета. Живая проверка
требует установки обновления драйвера и ручного перезапуска GrigDesk.
