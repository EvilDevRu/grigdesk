# Источники драйверов трекера

`shared/trackers/driverSources.ts` содержит встроенные ярлыки репозиториев;
`server/src/lib/trackers/driverSources.ts` добавляет локальную надстройку:

- «Битрикс24» — `https://github.com/EvilDevRu/grigdesk-b24`.
- «Jira» — `https://github.com/EvilDevRu/grigdesk-jira`.

Запись содержит только `title` и `url`. Она не регистрирует драйвер и не гарантирует
публикацию репозитория. Id и совместимость определяет пакет через `driver.json`
и обычную валидацию установщика. Реестр читает только установленные пакеты из
[каталога драйверов](driver-directory.md).

## Локальная надстройка

`config.driverSourcesPath` указывает на `<data>/driver-sources.json`, по умолчанию
`~/.grigdesk/driver-sources.json`. Файл — массив объектов с непустыми строками
`title` и `url`; адрес должен использовать HTTP(S). Краевые пробелы удаляются.

Записи объединяются по строке URL: локальный заголовок заменяет встроенный,
новые адреса добавляются в конец. Дубликат URL внутри файла отменяет всю надстройку.
Неверный JSON, схема или ошибка чтения также дают пустую надстройку и warn сервера.
Отсутствующий файл штатен и не создаёт предупреждения. Сервер не переписывает файл.

`GET /api/trackers/sources` возвращает `{ sources: [{ title, url }] }` под общим
auth guard. Чтение доступно всем авторизованным клиентам, не требует установленных
пакетов и перечитывает локальную надстройку при запросе. Запросов к репозиториям нет.

## Мастер установки

Каталог используется на первом шаге [мастера трекеров](../web/tracker-install-wizard.md).
Выбор карточки не выполняет Git-запросов. «Далее» открывает отдельный шаг версий,
а подготовка и применение требуют отдельных действий. Собственный адрес поддерживает
те же HTTPS/SSH/file источники, что серверный установщик. Его черновик сохраняется
между переключениями карточек; смена адреса сбрасывает чужие версии и тег.

Каталог не содержит ожидаемый id и не доказывает доступность репозитория. Пакет
проверяется обычной политикой driver.json. Ошибки и пустой каталог сохраняют ручной
ввод; активное серверное задание восстанавливается на собственном шаге.

Проверки — tests/server/tracker-sources.test.js и tests/web/tracker-sources.component.test.js.
