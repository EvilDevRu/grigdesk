# Нейтральный API трекера

HTTP-модуль `server/src/modules/tracker/index.ts` обслуживает `/api/tracker/*`.
Прежняя семья `/api/tracker/*` сохранена и означает драйвер по умолчанию.
Адресная семья `/api/tracker/<driverId>/*` обслуживает конкретный включённый драйвер.
Старые адреса Б24, предшествовавшие нейтральному API, не восстанавливаются.
Обработчики сохраняют прежние операции и тела успешных ответов. Общие отказы внешнего
драйвера имеют нейтральный код `tracker_error`; dashboard сохраняет код и HTTP-статус
известного `TrackerError`, включая `tracker_unavailable` и `tracker_context_changed`.
Статус отказа не определяется поиском слов в сообщении поставщика.
Полка, избранное и просмотренное используют тот же новый префикс в собственных модулях.

Web и desktop через общий web обращаются к новым путям. Исходники команды в `utilities/tracker/internal/`
тоже используют `/api/tracker/*`; имя и публикация собранного бинарника — отдельный шаг выпуска.
При отсутствии бинарника в diff задачи агент не переименовывает установленный пользовательский CLI.

Телефон использует те же маршруты и карточку задачи через общий интерфейс.
Выбор источника определяется включёнными драйверами на выбранном сервере.

Флаг подключения собственных задач называется `trackerConfigured`.
Внутренние имена портов, сериализатора чтения и разбора task id нейтральны.
Внешнюю ссылку задачи возвращает драйвер через sourceUrl; ядро не собирает URL портала.

Поля прежних сохранённых снимков и правил, значения source и коды валидации сохраняют
формат данных. Их переименование потребовало бы отдельного решения о совместимости.
Текст и ключи изменённых надписей доски добавлены одновременно в русскую и английскую локали.

Адресные поколения, JSON `board`, миграция выбора и PNG описаны в
[контракте нескольких драйверов](multi-driver-board.md).
