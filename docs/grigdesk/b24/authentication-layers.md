# Авторизация и слои

Сессионный клиент отдельного пакета драйвера входит на кастомный портал как браузер:
отправляет форму `/salary/?login=yes`, хранит сессионные cookies и использует
`bitrix_sessid` для CSRF. `USER_REMEMBER=Y` делает сессию долгоживущей. При сетевом сбое,
потере авторизации или протухшем sessid клиент выполняет ограниченные ретраи, а не
бесконечный цикл.

- Отдельный пакет драйвера содержит протокол портала, cookies, задачи, таймеры,
  комментарии, файлы и статусы. Сессионные вызовы проходят через `host.serial`:
  клиент не потокобезопасен, параллельные операции с общей сессией приводили к `Client Error`.
- `server/src/lib/trackers/facade.ts` — нейтральный фасад общего реестра трекеров.
- `server/src/modules/tracker/index.ts` — локальный HTTP API GrigDesk.
- `server/src/lib/trackers/credentialsStore.ts` — общее серверное хранилище реквизитов
  драйверов в `tracker-credentials.json` с режимом `0600`; каждый host видит только свою запись.
  Подключение задаётся в настройках трекера на доске, прежний файл реквизитов не читается.
- `b24/` — команда `b24` (собранный `bin/b24`) поверх локального HTTP API GrigDesk; портал
  она не вызывает. Токен — `GRIGDESK_TOKEN`, иначе файл `GRIGDESK_CLI_TOKEN_PATH`, по умолчанию
  `<папка данных>/state/cli-token`; адрес — `GRIGDESK_URL`, иначе `http://localhost:<порт>`
  по `GRIGDESK_PORT` (8140). Старую раскладку команда не читает ([команда b24](binary-cli.md)).

Локальное расширение резервного dashboard может использовать отдельный cookie-файл.
Это допустимо только при полной изоляции от основного cookie jar GrigDesk; конкретная
реализация и её путь документируются внутри соответствующего профиля.
