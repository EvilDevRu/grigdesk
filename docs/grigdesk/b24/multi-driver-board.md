# Несколько драйверов и доска по умолчанию

Принятые правила:

- Внешние драйверы работают одновременно, задачи образуют единую ленту «Мои задачи».
  Отдельных досок-вкладок для драйверов нет.
- После отключения или удаления доски по умолчанию дефолтом автоматически становится
  первый оставшийся включённый драйвер в сохранённом порядке. Пустой набор даёт `null`.
- Логотип пакета — только неанимированный PNG. При отсутствии картинки используется
  монограмма имени. SVG и внешние URL не поддерживаются.

## Серверный контракт

Файл выбора содержит `{drivers, default, revision}`. Прежний `{externalId, revision}`
мигрирует атомарно с сохранением подключения и ревизии; отсутствие прежней ревизии
означает ноль. Файл и его временная копия имеют права `0600`.

Каталог сохраняет `drivers` как массив описаний, `activeIds`, `externalId` и `revision`.
Дополнительно возвращаются `enabledIds` и `default`; `externalId` всегда равен дефолту.
В настройках `drivers` — массив id. Прежняя запись `externalId` включает выбранный
драйвер и делает его дефолтом, сохраняя другие включения. Запись `null` выключает
текущий дефолт с автоматическим выбором следующего.

Прежние `/api/tracker/*` адресуют дефолтный драйвер. Адресные
`/api/tracker/<driverId>/*` фиксируют конкретную цель для карточек, мутаций,
справочников и личных меток. `GET .../context` подтверждает полный `source`,
`generation` и `capabilities` без dashboard. Заголовок поколения на адресной ручке
сравнивается с поколением этого драйвера; на прежней — с общей ревизией выбора.
Пара `[source,id]` различает одинаковые числовые номера разных источников.

`POST .../tasks` принимает необязательное поле `board`. Оно выбирает цель до проверки
поколения и вложений и не передаётся пакету. Конфликт адреса и поля —
`400 tracker_target_conflict`; неизвестная цель — 404, выключенная — 409.
Прежние клиенты без явной цели продолжают работать с дефолтом без пересборки.

Смена дефолта не меняет адресное поколение другого драйвера. Смена реквизитов меняет
поколение и ревизию данных затронутого пакета. Drain ждёт принятые вызовы только
затронутых драйверов. Сетевой отказ dashboard отражается в каталоге отдельно от
закрытия ESM; повторное чтение допускает восстановление. Событие `trackers-changed`
сохраняет `externalId` и `revision` для прежних потребителей.

Числовой анализ остаётся операцией дефолтной доски. Явный чужой источник отвергается
до постановки в очередь; исторический `grigdesk` также отклоняется.
Личные хеши, файлы меток и имена файлов анализа не меняются.

## Логотип

Необязательное `driver.json.logo` задаёт обычный относительный путь внутри пакета.
Пределы: 256 КиБ включительно и от 1 до 512 пикселей по каждой стороне. Проверка
PNG-контейнера, отсутствие APNG и запрет симлинков действуют при scan, установке,
подготовленном пакете и откате до исполнения кода.

Каталог публикует только `/api/trackers/<id>/logo/<digest>`. Выдача защищена общим
входом и повторно проверяет файл и digest. Замена, удаление или подмена симлинком
дают 404; успешный ответ — `image/png`, `nosniff`, `no-store`. Ради картинки
выключенный пакет не активируется.

## Клиент и CLI

CLI поддерживает `boards`, `--board <id>` и серверное поле create.board. Набор включений
и дефолт в форме независимы от выбранного редактора реквизитов. Неизменённые значения
и пустые секреты не отправляются как смена подключения.

Диалог «Новая задача» предлагает доступные включённые внешние доски с `capabilities.create`.
Доступный дефолт выбирается при открытии; иначе требуется явный выбор доски.
Проекты читаются у выбранной доски, а адресное создание сохраняет её поколение
и полный источник для открытия карточки. Подробности — в [контракте общей доски](unified-board.md).

Web хранит отдельные снимки, эпохи и ревизии данных драйверов. Карточки подтверждают
источник через адресный context, а их мутации сохраняют захваченное поколение. Полные
ссылки различают личные метки, гидратацию полки, оповещения и таймеры одинаковых номеров.
Первый успешный список каждой внешней ветки устанавливает свою baseline просмотра.

Чтения используют общую локальную полосу и отдельную полосу портала на драйвер;
одновременно читаются не более двух портальных тел. Мутации не занимают эти полосы.
Межоконный снимок v2 переносит все ветки без второго SSE и без отражения принятого снимка.
Автоматические проверки используют изолированные HTTP-фикстуры; живая браузерная приёмка
выполняется отдельным этапом после устранения блокеров подготовленных тестов.
