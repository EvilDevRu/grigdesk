# Новый импорт в экране валит весь его тест = подмена модуля не экспортирует это имя

Тесты экранов на happy-dom (`tests/web/*.component.test.js`) компилируют SFC вместе со
всеми детьми через `compileVue` и подменяют модули целиком строкой: `stubs` вида
`{ '../../actions/showcase': ACTIONS_STUB, '../../ui': UI_STUB }`. Подмена — отдельный
модуль ровно с перечисленными экспортами. Стоит экрану или любому его дочернему
компоненту импортировать новое имя — операцию, константу текста или контрол из
`web/src/ui.ts`, — сборка графа падает до первого теста:

```
No matching export in "cockpit-stub:../../actions/showcase" for import "…"
```

Красными становятся ВСЕ тесты файла, хотя код рабочий, а typecheck и сборка зелёные:
у экрана «Презентации» после добавления блока «О чём ролик» упали 54 из 54.

Что делать в том же заходе:

- новое имя операции — двойником в подмене действий: он пишет вызов в
  `harness().calls` и возвращает значение из harness, которое тест задаёт сам;
- новый контрол — реэкспортом настоящего примитива из `src/components/…` в подмене
  UI, как соседние строки;
- новый дочерний компонент компилируется в том же графе, поэтому его импорты тоже
  идут через эти подмены — их надо дописать, даже если сам экран не менялся.

Двойник, которого никто не зовёт, падения не вызывает, поэтому лишнее имя в подмене
безопасно, а недостающее — нет.
