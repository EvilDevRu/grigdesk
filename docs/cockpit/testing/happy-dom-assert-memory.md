# Упавший assert с узлом happy-dom съедает всю память — веб-тест запускай через сторож памяти

DOM-узел happy-dom нельзя передавать в `assert.equal` / `deepEqual` ни одной из сторон: хватает
одного узла против `undefined` или `null`. Если сравнение упало, форматтер `node:assert` строит
представление узла, а за узлом тянется весь граф окна. Вместо короткого отчёта процесс растёт
больше чем на гигабайт в секунду, причём вне V8 heap: `--max-old-space-size` его не
останавливает, RSS уходил за 49 ГБ при потолке heap 4 ГиБ. На машине с большой подкачкой ядро
такой процесс не убивает: система уходит в свопинг и встаёт, OOM в журнале ядра нет, выручает
только жёсткий сброс.

Так старый тест tooltip-а сравнивал `tip.parentElement` с `body`, но между ними законно стоял
`TRANSITION-STUB`: под потолком heap 768 МиБ один файл дошёл почти до 1 ГиБ RSS и упал, а без
потолка несколько параллельных тестовых процессов забивали ОЗУ и swap. Позже «красный» тест
проверял отсутствие кнопки через `assert.equal(buttonByText(...), undefined)`, пока кнопка ещё
была на месте, — голый `node --test` на одном этом файле за две с половиной минуты занял всю ОЗУ
и подкачку.

Обёртка `@vue/test-utils` взрывается так же: она держит `element`, и упавший
`assert.equal(wrapper.find('button'), undefined)` упёрся в потолок 2 ГиБ сразу после вызова.

Сравнивается только ограниченное скалярное значение: `actual === expected`,
`Boolean(querySelector(...))`, `tagName`, текст или атрибут. Это правило проверяет
`tests/web/dom-assertion-memory.contract.test.js`: он узнаёт запросы к DOM, поиск test-utils по
селектору, выбор из набора (`[...nodes].find(fn)`, `findAll(...)[0]`), результат `mount`,
помощника файла, который возвращает узел или обёртку (`buttonByText(...)`), и переменную с таким
значением. `notEqual` против примитива разрешён: он падает, только когда узла нет. Помощника из
другого модуля и значение, присвоенное после объявления, сторож не видит — такой результат
оборачивай в `Boolean(...)` сам.

Вторая защита — `tests/run-node-tests-safe.sh`: он задаёт `--max-old-space-size` и следит за
суммарным RSS группы тестовых процессов, останавливая её выше потолка (по умолчанию heap 1024 МиБ
и 2048 МиБ RSS). Через него идут `npm --prefix web run test:components` и `npm --prefix server
test` (6144 МиБ RSS на всю группу параллельных файлов). **Голый `node --test` этой защиты не
получает**, поэтому отдельные веб-тесты запускай так: `bash tests/run-node-tests-safe.sh --test
<файлы>`. Заминированный файл сторож останавливает на 2 ГиБ за секунды. Бюджет RSS общий на всю
группу: несколько файлов запускай с `--test-concurrency=2` и `NODE_TEST_MAX_RSS_MB=4096`, иначе
при параллельности по умолчанию сторож останавливает даже здоровый прогон тестов документации.
Лимиты не заменяют исправление опасного assert, но не дают следующей ошибке теста положить всю
машину.

Тесты под сторожем получают временную `COCKPIT_HOME`: она своя у каждого прогона и удаляется
после него. Папку артефактов сторож при этом передаёт настоящую — `COCKPIT_ARTIFACTS_DIR` из
окружения, если она задана, иначе `<настоящая папка данных>/artifacts` (по умолчанию
`~/.cockpit/artifacts`). Поэтому снимки, кэши сборок и временные стенды тестов переживают
прогон. Если внешняя папка данных неверна (не проходит [проверку пути](../server/data-home.md)),
переменная не передаётся: артефакты остаются во временной папке данных и удаляются вместе с ней.
