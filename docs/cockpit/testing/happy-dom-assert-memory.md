# Упавший assert с happy-dom может съесть всю память до показа ошибки

Нельзя передавать DOM-узлы happy-dom напрямую обеими сторонами `assert.equal` / `deepEqual`.
Если узлы не совпали, форматтер `node:assert` пытается построить их представление и раздувает
строку до OOM вместо короткого отчёта. Так старый тест tooltip-а сравнивал
`tip.parentElement` с `body`,
но между ними законно стоял `TRANSITION-STUB`: под потолком heap 768 МиБ один файл дошёл почти
до 1 ГиБ RSS и упал, а без потолка несколько параллельных тестовых процессов забивали ОЗУ и swap.

Сравнивается только ограниченное скалярное значение: `actual === expected`,
`Boolean(querySelector(...))`, `tagName`, текст или атрибут. Это правило проверяет
`tests/web/dom-assertion-memory.contract.test.js`. Вторая защита живёт в `web/package.json`:
`test:components` ограничивает каждый worker через `--max-old-space-size=768` и одновременно
запускает не больше четырёх файлов через `--test-concurrency=4`. Эти лимиты не заменяют
исправление опасного assert, но не дают следующей ошибке теста положить всю машину.
