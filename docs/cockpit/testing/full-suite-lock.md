# Замок полного прогона

`tests/run-all.sh` берёт неблокирующий kernel lock через `flock` на
`.state/run-all.lock`. Второй запуск в том же дереве завершится с кодом 3 до тестов.
Так несколько прогонов не кодируют одновременно одни и те же видеофикстуры.

Файл замка сохраняется после завершения. Его наличие и записанный PID не означают,
что проверка ещё идёт: состояние блокировки принадлежит открытому дескриптору.
Дескриптор наследуют дочерние процессы, поэтому они могут удерживать замок после
завершения родителя. Ядро освобождает его после закрытия последнего дескриптора.

Свободность проверяется без удаления файла: `flock -n .state/run-all.lock true`.
Успех означает свободный замок в момент проверки; сам `run-all.sh` повторно берёт
его атомарно при старте. Удаление занятого файла не освобождает старую блокировку
и может позволить второму процессу создать другой inode с отдельным замком.

Сначала дождитесь результата уже запущенной проверки. Не завершайте чужие процессы
и не считайте старую строку PID доказательством брошенного запуска. Процессы могут
быть скрыты отдельным PID namespace; подробнее —
[паузы в выводе тестов](buffered-test-progress.md).
