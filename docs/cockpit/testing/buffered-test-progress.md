# Пауза в TAP-выводе не доказывает зависание тестов

При параллельном `node --test` вывод файлов публикуется в установленном порядке.
Долгий файл может задержать видимый результат остальных, даже когда они продолжают
работать. Время изменения общего лога показывает последнюю публикацию вывода,
а не последнюю активность дочерних процессов.

В проверенном полном серверном наборе вывод остановился после
`deepseek-update-transition.test.js`. Следующий `deepseek-upstream-update.test.js`
собирал candidate и запускал вложенные compiled parity tests. Он успешно завершился
примерно за 12 минут; весь серверный набор после этого сообщил ноль ошибок.
Вызов compiled gate через `execFile` также удерживает его stdout до завершения.

Перед выводом о зависании нужно проверить дерево своих процессов, работу дочерней
сборки и предусмотренный срок операции. Если среда команд изолирует PID namespaces,
новый `ps` может не видеть процессы прежнего вызова: пустой список не доказывает их
завершение. Одного неизменного лога недостаточно для остановки.

Прерывание общего прогона не становится успешным результатом, даже если завершённые
пакеты зелёные. Сохранённый код прерывания и отдельные проверки оставшихся пакетов
дополняют отчёт; они не заменяют успешный полный прогон.
