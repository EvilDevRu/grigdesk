# Фоновый Bash может сделать проверку SIGINT ложно красной

`runner-contract.sh` проверяет окно восстановления signal traps: после установки своего
обработчика он посылает себе INT и ожидает его повторного исполнения. Запуск полного
набора через `nohup bash -c '…' &` в неинтерактивной оболочке передаёт дочернему Bash
игнорируемый SIGINT. Установить обычный INT trap в такой оболочке уже не получается:
`trap -p INT` остаётся `trap -- '' SIGINT`. Поэтому последняя проверка сообщает
`expected=[replayed] actual=[]` даже при неизменённых launcher и тесте.

Контрольный опыт — один скрипт с установкой trap, выводом `trap -p INT` и `kill -INT
"$BASHPID"`. В обычном запуске он печатает свой обработчик и выполняет его;
при запуске через `nohup … &` печатает игнорирование и не вызывает обработчик.
Отдельный `runner-contract.sh` через `setsid --wait bash -c '…'` без `&` прошёл49/49
при том же коде, тогда как запуск через фоновую обёртку снова упал на проверке49.

Для проверки сигналов отсоединяй сессию через `setsid --wait`, сохраняя лог и код выхода,
а длительный вызов инструмента держи открытым до завершения. Не объясняй этот отказ
случайностью и не меняй launcher, пока не проверено унаследованное состояние сигналов.
Полный прогон, уже завершившийся с ненулевым кодом, зелёным не объявляется: отдельный
повтор подтверждает только проверенный файл и причину его прежнего отказа.
