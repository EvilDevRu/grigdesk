# Сторож, читающий текст задачи, ловит фикстуру, а не страницу

Сторож страницы конвейера проверял, что на ней нет кнопок управления B24-таймером
(показывать таймер можно, управлять — нельзя, это работа доски). Искал он их по
доступному тексту ВСЕХ кнопок: `text() + aria-label + title`, совпадение по
`/таймер/ && /запуст|пауз|останов/`.

Тулбар фильтров получил подсказки, перечисляющие задачи поимённо
(`#101: Идущий B24-таймер`), и подсказка уехала в `title` чипа. Сторож честно нашёл
«таймер» и «Остановленный» в одной кнопке и покраснел — при том, что кнопки управления
таймером на странице по-прежнему нет. Названия в фикстуре описывают сценарий теста, и
менять их, чтобы обойти сторож, значит чинить симптом.

Правило то же, что у гейта арбитра по `stall.stop`, а не по заголовку остановки:
**сторож обязан читать машинную роль элемента, а не текст, который пишет человек.**
Название задачи приезжает с портала, и задача «Остановить таймер» — законное имя.
Поэтому кнопки с ролями, чей текст является ДАННЫМИ (`pipeline-title` рисует название
задачи, `pipeline-project` и `pipeline-project-overflow-option` — имя профиля,
`pipeline-status-filter` — список задач в подсказке), из обхода исключены явным списком,
а сама проверка осталась прежней: подделанная кнопка «Остановить таймер» её по-прежнему
роняет (проверено вставкой такой кнопки в разметку).
