# Проверка старта сервера использует своё состояние

`tests/server/app-boot-smoke.test.js` поднимает дочерний сервер на выделенном свободном
порту. Окружение строится с нуля, HOME и все изменяемые хранилища направлены во временный
root. В частности, там находятся usage forecast, web-log и media HF: их обычные defaults
при старте обращались бы к состоянию живого Cockpit, а web-log запускает уборку файлов.
Файлы удаляются только после завершения созданного проверкой дочернего процесса.
Путь [ключа окна](../server/window-key.md) обе boot-фикстуры задают под собственным root.
Plugin boot helper собирает effectiveEnv один раз и передаёт его в before, child,
чтение своих файлов и fixture.env; внешний либо относительный override ключа
отвергается до spawn.

`tests/run-all.sh` запускает оба расширения docs-тестов через memory guard с общим RSS
4096 МиБ и concurrency 2. Отсоединение полного прогона сохраняет сигналы через
`setsid --wait`: [ловушка фонового SIGINT](background-sigint.md).
