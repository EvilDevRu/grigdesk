# Мобильный контракт v1

Граница приложения — `/api/mobile/v1`. Серверный контракт живёт в
`server/src/lib/mobile/{contract.ts,mobileContractSchema.ts,mobileContract.schema.json}`,
его независимая копия — в `mobile/src/api/`. Изменения обязательных полей или enum
требуют новой версии API либо совместимого расширения; клиент не угадывает значение.

Ответы проверяются до чтения продуктовых полей. Отсутствие обязательного поля,
неподдерживаемая версия или значение закрывают работу до обновления приложения.
`GET /hello` сообщает `api`, `minApp`, время сервера и устройство. Несовместимый `minApp`
оставляет экран обновления и запрещает POST, включая повтор сохранённой очереди.

Все пути ниже имеют префикс `/api/mobile/v1`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /hello`, `POST /pair` | Проверка версии/личности и первая привязка |
| `GET /chats`, `GET /chats/:id` | Существующие чаты и страницы общей истории |
| `GET /chat-options`, `POST /chats` | Каталог настроек и создание чата |
| `POST /chats/:id/settings`, `/read` | Модель/эффорт и прочтение показанной ревизии |
| `POST /chats/:id/workspace/preview`, `/workspace` | Предпросмотр и подтверждение задачи/папки |
| `GET /attention` | Счётчики ожиданий, остановок и непрочитанных |
| `POST /chats/:id/messages`, `POST /chats/:id/stop` | Принятый ход и остановка показанного запуска/очереди |
| `GET /chats/:id/deliveries` | Доказательство приёма по clientId |
| `GET /chats/:id/media/:ref` | Проверенный растр из собственного media/workspace чата |
| `GET /waiting`, `GET /waiting/:pid/details`, `POST /waiting/:pid` | Вопросы, полное основание разрешений, ответ |
| `GET /tasks`, `GET /tasks/:id`, `GET /tasks/:id/plan` | Конвейер и страницы основания ворот |
| `POST /tasks/:id/gate`, `/resume`, `/stop` | Действие по токену показанной попытки |
| `GET /b24/tasks`, `GET /b24/tasks/:id`, `GET /b24/tasks/:id/launch-options` | Б24 и точный снимок вариантов запуска |
| `POST /b24/tasks/:id/launch` | Подтверждённый вариант запуска по actionToken |
| `GET /operations/:key` | Сохранённый результат или состояние доставки |
| `GET /events` | Один SSE-поток приложения |
| `GET /app`, `GET /app/apk` | Проверенный выпуск APK |

Неизвестный сертификат допускается только к `hello`/`pair`. Остальные пути требуют
зарегистрированное, неотозванное устройство; основной `/api` в этом сервере отсутствует.
Все POST, кроме pair, требуют `Idempotency-Key` и исходное Unix-время в миллисекундах
`X-Cockpit-Operation-Created-At`: [доставка операций](operation-delivery.md).

История листается с revision и курсором: новое содержание не смешивается со старой страницей.
Основание разрешения/ворот также имеет contentRevision; действующий actionToken выдаётся
после полного чтения. Вопросы передают устойчивые questionId/optionIds, типизированное
value и допустимый свободный текст. Комментарий, который исполнитель не умеет принять,
отмечается через `commentDelivered`/`textDelivered`, не скрывается.

## Список чатов и картинки

`GET /chats` строит строки из шапок файлов истории без сообщений: сервер кэширует шапку
по inode, размеру и mtime файла и перечитывает только изменённые. Полная история всех
чатов для списка не читается. Компаньон создаётся или поднимается из архива общим
ensure только тогда, когда живого Компаньона без задачи в шапках нет.

Сообщение приходит частями `text`, `code` и `image`; Markdown-картинка с локальным путём
становится частью `image`. Форматирование `text` безопасно разбирает приложение. `media` ответа собирается из успешных шагов `Read` и
`GenerateImage` с растровым путём. Исполнители записывают вызов шага и его итог
отдельными записями ленты с общим `id`, поэтому картинка выдаётся по паре вызов/итог,
как миниатюра в окне Кокпита. Байты отдаёт `GET /chats/:id/media/:ref` по тем же
правилам рабочей папки чата, что и окно: служебный `.state` вне `artifacts` корня закрыт.

## События

SSE начинает `ready:{api:1}`, затем передаёт `chat`, `chats`, `waiting`, `tasks`, `b24`
как сигналы перечитать данные. `heartbeat` каждые 15 секунд поддерживает живость;
его получение не перезагружает экран. Нативный owner владеет watchdog и reconnect,
JavaScript не запускает второй цикл. Native ограничивает отдельные line/data до 64 KiB,
JSON REST — до 2 MiB; сервер ограничивает входное тело 256 KiB.

## Совместимость

Золотые DTO лежат в `tests/fixtures/mobile-contract/v1/`. Замороженный decoder и схема
зафиксированной границы v1 — в `tests/fixtures/mobile-contract/baseline/`.
Baseline нельзя переписывать вслед за текущей реализацией ради зелёного теста.
Проверки совместимости используют сервер, мобильную копию и frozen decoder независимо.

Необязательные поля `provider`, `preview`, `activity` описаны в
[планшетном разговоре](tablet-chat.md#совместимое-расширение-api).
Необязательные `hello.features`, `modelRef`, `unread`, `settings` и новые маршруты
описаны в [управлении чатом](chat-controls.md). Без feature старого сервера новые
запросы не отправляются; прежние сценарии продолжают работать.
