# Порт конвейера (SVG-граф)

Граф конвейера — порт `engine/lib/dashboard.py` (server-rendered Python) в Vue+JSON.
Разнесён: **сервер** считает данные, **клиент** рисует геометрию.

## Сервер (`server/src/lib/factory-graph.js`)

- `loadGraph(profilesDir, profile)` — читает и кеширует `profiles/<profile>/graph.json`.
- `graphForRoute(g, route)` — узлы (оверрайд профиля поверх каталога `stages.js`), status
  `keys`, route-specific `runnerKeys`, optional, vb, pos, edges. Это **только legacy-ветка**:
  реестр с `CATALOG_PROTOCOL=route-v2` рисуется из закреплённого бандла (`route-graph.js`),
  fallback запрещён. Профиль, перешедший на v2, разметку `routes/pos` в `graph.json` может не
  держать вовсе, поэтому её отсутствие — названная ошибка («нет разметки маршрута …»), которая
  доезжает до человека ответом `404`, а не падение на `undefined` внутри.
- `computeNodeStatuses({ pf, pos, keys, optional, mtimeMs })` — **порт `pipeline_statuses`**:
  - `_ST_MAP`: done/approved→done, running→run, waiting→wait, failed/rejected→stall, blocked→skipbad.
  - `skipped` у optional-узла → `skip`, иначе `skipbad` (аномалия).
  - idle-заполнение (незаписанные этапы до последнего тронутого = «нет данных»).
  - ворота ждут, если всё до них done/skip — **только исторические реестры** (v1 записи
    `waiting` не делал); реестр `route-v2` верит только явной записи движка `GATE_*=waiting`:
    проекция опережает журнал, когда диспетчер встал fail-closed после захода узла, и
    доинференс рисовал ворота, которых маршрут не достиг. Гард «преждевременно»
    при недоделанном хвосте.
  - инвариант линейности (активен ровно один узел); возврат после reject приёмки.
- `parseLoops(stagesLog)` — возвраты `возврат в X из-за KEY` → счётчик по узлу; `halted`.

`getTaskGraph(task)` собирает всё + `nodeMeta` (AT/DUR/FANOUT/FAILS/TOKENS, runner chain,
семейства и effective effort моделей, actual/reason и последние attempt с фактическими
`model`/`effort` из `logs/runs/`) + проектную/задачную `runnerPolicy` + `progress`
(done/total/current) + порты стенда из `tNNNN.env`. Если движок
поставил `STALLED_HUMAN` или оборвался, ответ также содержит `stall` с причиной, подсказкой
и `node`; соответствующий узел получает `stall`/`fail`, даже если реестр этапа остался
в `running`. Причина дублируется в `nodeMeta.<node>.stall` для модалки конкретного агента.

### Время работы попытки

Для исполняемой `route-v2`-попытки `timing.workSec` — сумма интервалов реально запущенных
runner-процессов из `logs/runs/tNNNN/<STAGE>/<RUN>/`: начало берётся по времени создания
каталога run, конец завершённого запуска — по финальной записи `meta.env`. Запуски до
`createdAt` проверенной attempt отсекаются, bootstrap Scout не входит в закреплённый маршрут,
активный run дотикивает клиент. Поэтому пауза между падением оркестратора и `resume` не
приписывается следующему этапу. Значение помечено `approximate`, потому что run-артефакты —
диагностическая телеметрия; если уже исполнявшийся маршрут потерял их, API отдаёт `timing=null`,
а не заведомо ложную цифру.

`GATE_WAIT_S` по-прежнему берётся из проверяемой движковой проекции отдельно. Исторические
read-only реестры могут использовать старый route ledger: его рабочий интервал — расстояние
между событиями, поэтому UI явно называет такое значение оценкой.

## Клиент (`web/src/shared/graph-geom.js`)

**Порт `node_geom`/`edge_path`** (1:1 с dashboard.py):
- `nodeGeom`: `code` → ромб (hw 70, hh 27); иначе прямоугольник, `hw = max(58, ([...label].length+2)*3.8+14)`,
  hh 17. **`[...label].length`** (код-пойнты, эмодзи=1) — иначе рёбра промахиваются по краям.
- `edgePath`: 12 типов маршрутизации (`h`, `v`, `arc_up`/`_hi`, `arc_down`/`_hi`/`_x2`/`_x3`,
  `arc_reject`, `to_sandbox`/`from_sandbox`) — кубические Безье с ручными коэффициентами. START_DOT=(30,55).
- `computeViewBox` — тесный холст по узлам (порт `graph_viewbox`), убирает пустоту зашитого vb.

`FactoryGraph.vue` рисует: узлы по типу (агент/человек/код — рамки), 9 статусов (`ns-*`: обводка/
заливка/пульс/свечение), рёбра (`e-off`/`e-on`/`e-flow` «ток» / `e-fail`/`e-loop` возвраты), метки
(`MARKS`) и provider/model agent-узла. Остановка показывается не только цветом узла:
над рабочей схемой есть явная плашка с этапом, причиной, числом сбоев и подсказкой.
`reference`-режим — эталонная схема без статусов
(раздел «Маршруты»). Клик по узлу → `emit('node')` → модалка этапа с цепочкой, попытками,
причиной failover, причиной остановки и безопасной командой переключения активного run.
Live-переключение показывается только при живом оркестраторе: после stop исторические
`status=run`/`runner.actual` не считаются процессом, вместо кнопки switch модалка даёт выбрать
stage override, который вступит в силу по кнопке «Продолжить прогон».

### Текст человека в модалке: у ворот и у возврата он разный

Модалка одна на все узлы, но поле для текста в ней бывает в двух смыслах, и путать их нельзя —
их по-разному принимает движок:

| где | когда видно | куда уходит |
|---|---|---|
| **ворота, «✗ Отклонить»** | `isGate` + статус `wait`/`premature`, после нажатия «Отклонить» | заданием агенту того узла, куда ведёт возврат (`human-note` в промпте захода) |
| **обычный узел, «▶ Перейти сюда»** | не ворота, попытка исполняемая | причиной события `human-rewind` и тем же блоком в промпт захода |

Ключевое: **при «✓ Принять» текст не уходит никуда** — `route_v2_gate_decide` обнуляет
`reject_feedback` на любом исходе, кроме `rejected`. Поэтому поле у ворот принадлежит именно
отклонению и раскрывается по кнопке, а не висит над обеими: висящее поле обещало доставку,
которой при принятии нет, и человек писал в него разбор, уходивший в пустоту. Решение делится
на два шага («Принять» / «Отклонить» → «Что доработать» + «Отправить на доработку» / «Отмена»),
текст остаётся в поле при отказе движка и стирается «Отменой».

Отказ `gate_rejected` с текстом «нельзя доставить» означает, что возврат ведёт в узел, который
исполняет не агент (`executor != agent`) — читать указание там некому. Модалка не показывает
голое «Ошибка: …», а называет оба выхода: отклонить без текста либо сначала вернуть конвейер
кнопкой «▶ Перейти сюда» на узел нужного агента.

Поле возврата стоит своей секцией рядом с кнопкой «▶ Перейти сюда», а не в ряду с чатом и
диффом: своей кнопки «отправить» у него нет — указание уезжает тем же запросом, что и возврат.

Подпись у уже записанного `nodeMeta.comment` зависит от узла и статуса (`stageCommentLabel`):
один и тот же ключ реестра `<КЛЮЧ>_COMMENT` у обычного узла — «Замечание», у отклонённых ворот
— «Отправлено агенту на доработку», а у принятых честно называется комментарием, который
агенту не уходил (движок его выбросил, но проекция реестра запись сохранила — старые прогоны
такие ещё содержат).

### Модель и effort в модалке узла

Маршрут не несёт model policy: его `runKey` только выбирает stage, а
`server/src/lib/runner-state.js` резолвит `MODEL_<STAGE>_<PROVIDER>_*` →
`MODEL_DEFAULT_<PROVIDER>_*` из `profiles/<profile>/runners.env`. API отдаёт результат в
`nodeMeta.<node>.runner.models[provider]`.

В цепочке исполнителей модель и effort показаны одной строкой, например
`gpt-5.6-sol · effort ultra`. Если provider уже запускался, UI берёт effort последней его
попытки из `runner.attempts[].effort`; это значение launcher записал в
`logs/runs/t<TASK>/<STAGE>/<RUN>/meta.env`.
Так завершённый этап продолжает показывать фактический effort даже после смены policy.
До первого запуска или при legacy telemetry без `EFFORT` используется effective policy.
Строки «Попытки запуска» всегда показывают собственные `model · effort`, когда эти поля
присутствуют, и не приписывают исторической попытке новое значение из профиля.

good `#3fb950`, warn(serious) `#e0a33a`, bad(critical) `#f0564c`, рамки узлов агент `#e0873f` /

## Стадии — глобальный enum (`server/src/lib/stages.js`)

`STAGES` — каталог всех стадий (kind + подпись по умолчанию), `StageKind` (agent/human/code).
Профили ССЫЛАЮТСЯ на id и оверрайдят через graph.json (`resolveNode`). `GET /api/factory/stages`.
Редактор «Маршруты» уже использует этот каталог: стадии выбираются из общей библиотеки,
цепочка/возвраты/промпты сохраняются по проектам. Сам `profiles/<profile>/graph.json` остаётся
engine-контрактом координат и runtime-графа, а не редактируется как произвольный JSON из UI.
