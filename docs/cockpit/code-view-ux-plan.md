# План упрощения выбора проекта и дерева файлов в «Коде»

Статус: **план; реализация не начата**

Дата: **2026-08-01**

## 1. Цель

Сделать левую панель плагина «Код» понятной без знания устройства Git:

- вместо трёх безымянных селектов оставить два логических уровня — проект и рабочую копию;
- явно объяснять, какой репозиторий, worktree и ветка сейчас открыты;
- в режиме Git дать переключение изменённых файлов между обычным списком и деревом каталогов,
  как в VS Code;
- не менять read-only модель плагина и не добавлять новые серверные запросы.

Под «файлами в гите» в этом плане понимается блок «Не в коммите» на вкладке Git. Проводник на
вкладке «Код» уже отображает каталоги деревом и лениво загружает их при раскрытии.

## 2. Что есть сейчас

В `web/src/views/CodeView.vue` последовательно выбираются три сущности:

1. `project` — проект из общего реестра Cockpit;
2. `repoKey` — один из репозиториев проекта, например `be` или `fe`;
3. `treePath` — конкретная рабочая копия этого репозитория: основная либо Git worktree задачи.

Сами уровни модели корректны, но в интерфейсе селекты не имеют подписей. Второй селект к тому же
скрывается, если репозиторий один, поэтому смысл третьего меняется визуально в зависимости от
проекта. Пользователь видит технические пути, имена worktree и ветки, но не понимает, какое
решение от него требуется.

На вкладке Git сервер уже возвращает каждый изменённый файл с полным относительным путём в
`git.files`. Клиент рисует эти элементы одним плоским циклом. Для древовидного режима данных API
достаточно: дерево можно собрать в браузере без изменений `server/src/modules/code/index.js` и
`server/src/lib/git.js`.

## 3. Целевой интерфейс выбора контекста

### 3.1. Два логических уровня

В верхней части панели должны остаться:

- поле **«Проект»** — существующий общий выбор проекта;
- поле **«Рабочая копия»** — единый выбор пары `репозиторий + worktree`.

Клиент строит вычисляемый список контекстов:

```text
project
  -> repo { key, dir }
       -> tree { path, main, name, task, branch }
            = context { repoKey, treePath, ...данные для подписи }
```

Внутреннее состояние `repoKey` и `treePath` сохраняется, потому что именно эту пару ожидают
действующие API `ls`, `file` и `git`. Отдельных пользовательских селектов для этих полей больше
нет: выбор одного `contextId` атомарно устанавливает оба значения и затем сбрасывает/перезагружает
состояние панели.

### 3.2. Подписи вариантов

Варианты «Рабочей копии» группируются по репозиторию через `optgroup`, если репозиториев несколько.
В подписи не показывается полный абсолютный путь — он остаётся в `title` как диагностическая
подсказка.

Пример:

```text
Проект: cockpit

Рабочая копия:
  cockpit
    Основная · master
    Задача t8165 · task-8165
  engine
    Основная · master
    Слот bui-wt-3 · feature/code-view
```

Правила подписи:

- основное дерево: `Основная · <ветка>`;
- worktree с распознанной задачей: `Задача <task> · <ветка>`;
- прочий worktree: `<имя каталога> · <ветка>`;
- detached HEAD: вместо ветки показывается `detached HEAD`;
- метка репозитория показывается заголовком группы либо частью единственной статической строки.

Если доступна ровно одна рабочая копия, второй селект не нужен: вместо него показывается
неинтерактивная строка **«Рабочая копия: <репозиторий> · Основная · <ветка>»**. Так интерфейс не
заставляет выбирать там, где выбора нет.

### 3.3. Поведение и восстановление выбора

- Общий проект по-прежнему хранится в `cockpit-project` и синхронизируется с «Проектами» и
  «Маршрутами».
- Выбранный контекст хранится отдельно для каждого проекта, например в
  `cockpit-code-context:<project>`; сохраняется непрозрачный клиентский идентификатор, а не
  абсолютный путь как часть UI-контракта.
- После возврата на страницу сначала восстанавливается сохранённая пара. Если worktree удалён или
  репозиторий переименован, используется основное дерево первого доступного репозитория.
- При смене контекста очищаются выбранный файл, диф, раскрытые каталоги и ошибка старого контекста;
  затем загружается корень проводника и, если открыта вкладка Git, изменения новой рабочей копии.
- Репозитории без доступного Git-дерева не попадают в список рабочих копий. Если рабочих копий нет
  совсем, панель показывает список недоступных путей и ссылку на раздел «Проекты», а не пустой
  селект.

## 4. Дерево изменённых файлов на вкладке Git

### 4.1. Переключатель вида

В заголовке **«Не в коммите»** справа добавляется компактная двухпозиционная кнопка:

- «Дерево» — иконка вложенных каталогов;
- «Список» — иконка строк.

Кнопка видна только на вкладке Git, имеет `title`, `aria-label` и `aria-pressed`. Для нового
пользователя исходный режим — **дерево**; последний выбор сохраняется в `localStorage` под общим
ключом `cockpit-code-git-view`, потому что это предпочтение интерфейса, а не свойство проекта.

### 4.2. Построение дерева

Из `git.files[].path` строится префиксное дерево:

- каждый сегмент до последнего становится каталогом;
- последний сегмент хранит исходный объект файла целиком, включая `status`, `add`, `del`,
  `binary`, `tooBig` и содержимое для дифа;
- каталоги идут раньше файлов, внутри групп — сортировка по имени;
- файлы в корне остаются на нулевой глубине;
- одинаковые имена в разных каталогах не конфликтуют: ключом файла остаётся полный путь;
- переименованный файл группируется по новому пути, уже находящемуся в `file.path`.

Как и в существующем проводнике, на экран выводится плоский массив только видимых строк с
`depth`, а раскрытие контролирует `Set` полных путей каталогов. При первом включении дерева все
каталоги с изменениями раскрыты, чтобы переключение сразу меняло представление, а не скрывало
файлы. После ручного сворачивания состояние сохраняется при обновлении Git в той же рабочей копии;
несуществующие после обновления каталоги из набора удаляются.

Строка каталога содержит шеврон и имя. Строка файла сохраняет текущие статус `A/M/D/R`, счётчики
добавленных/удалённых строк и обработчик выбора дифа. Переключение вида не меняет `gitSel`, поэтому
открытый справа diff не сбрасывается.

### 4.3. Обычный список

Существующий плоский режим остаётся доступен без изменения поведения:

- показывается полный относительный путь;
- сохраняются статус и счётчики;
- клик открывает тот же Monaco diff;
- обновление и переключение side-by-side продолжают работать независимо от вида списка.

## 5. План реализации

### Этап 1. Чистая модель данных

1. Вынести в `web/src/shared/code-tree.js` чистые функции:
   - построение списка рабочих контекстов из `repos[].trees`;
   - выбор сохранённого либо безопасного начального контекста;
   - построение дерева изменённых файлов и разворачивание его в видимые строки.
2. Не кодировать `repoKey` и `treePath` строковым разделителем, который может встретиться в пути.
   Хранить таблицу `contextId -> context` и работать с парой полей как с данными.
3. Зафиксировать детерминированную сортировку и поведение для пустых/недоступных репозиториев.

### Этап 2. Упрощение селектов

1. В `web/src/views/CodeView.vue` заменить `setRepo()` и отдельный `setTree()` одним пользовательским
   обработчиком `setContext()`; низкоуровневую установку пары оставить внутренней функцией.
2. Добавить видимые подписи «Проект» и «Рабочая копия».
3. Сгруппировать варианты рабочей копии по репозиториям и заменить единственный вариант
   статической строкой.
4. Добавить восстановление выбора на проект и безопасный fallback после удаления worktree.
5. Привести строку в топбаре к той же терминологии: `проект · репозиторий · рабочая копия · ветка`.

### Этап 3. Переключение Git «список/дерево»

1. Добавить состояние `gitView`, его чтение/запись в `localStorage` и доступную кнопку в заголовок
   «Не в коммите».
2. Для режима дерева построить вычисляемые строки и отдельный набор раскрытых Git-каталогов.
3. Переиспользовать размеры отступов, шеврон и состояния hover/selected существующего проводника,
   чтобы два дерева выглядели одинаково.
4. Не дублировать логику открытия дифа: и плоская, и древовидная строка вызывают существующий
   `selectGit(file.path)`.
5. Проверить узкую панель: длинные имена обрезаются многоточием, а полный путь доступен в `title`.

### Этап 4. Тесты и документация

1. Добавить `tests/web/code-tree.test.js` для чистой модели:
   - один и несколько репозиториев;
   - основное дерево и worktree задачи;
   - восстановление валидного и протухшего контекста;
   - вложенные, корневые, удалённые и переименованные файлы;
   - сортировка каталогов/файлов и сворачивание веток.
2. Добавить компонентный тест `tests/web/code-view.component.test.js` со стабами API и Monaco:
   - на экране не больше двух логических полей выбора;
   - выбор рабочей копии отправляет правильные `repo` и `root` во все запросы;
   - кнопка меняет список на дерево и восстанавливает предпочтение;
   - клик по вложенному файлу открывает diff по полному пути;
   - смена вида не сбрасывает выбранный diff.
3. После реализации обновить описание плагина «Код» в `CLAUDE.md` и при необходимости
   `docs/cockpit/architecture.md`: два UI-уровня выбора, но прежняя серверная пара
   `repo + root`.

## 6. Проверка

Автоматически:

```bash
npm --prefix web test
npm --prefix web run build
```

Ручная матрица:

| Сценарий | Ожидаемый результат |
|---|---|
| Один проект, один репозиторий, только main | Один селект проекта и статическая рабочая копия |
| Один проект, несколько репозиториев | Рабочие копии сгруппированы по понятным меткам репозиториев |
| У репозитория несколько worktree | Видны «Основная», задача/слот и ветка; выбор открывает правильный корень |
| Сохранённый worktree удалён | Страница без ошибки переходит на доступное основное дерево |
| У проекта нет путей | Понятная ссылка на «Проекты», пустых технических селектов нет |
| Git без изменений | Сообщение о чистом дереве; переключатель не создаёт пустую структуру |
| Изменения на 4–6 уровнях вложенности | Каталоги раскрываются/сворачиваются, файл открывает правильный diff |
| Переключение дерево → список → дерево | Выбранный файл и diff справа сохраняются |
| Обновление Git | Состав и счётчики обновляются, допустимые свёрнутые каталоги сохраняются |
| Ширина менее 900 px | Подписи и кнопка доступны, пути не раздвигают панель |

## 7. Критерии приёмки

- Пользователь видит максимум два логических элемента выбора: «Проект» и «Рабочая копия».
- Из подписи рабочей копии понятно, открыт main или worktree задачи и какая это ветка.
- В интерфейсе больше нет безымянного отдельного выбора репозитория и отдельного выбора дерева.
- Все действующие API продолжают получать точные `repoKey` и `treePath`; серверный контракт не
  меняется.
- На вкладке Git одной кнопкой переключаются плоский список и дерево каталогов.
- Древовидный режим сохраняет статусы, счётчики, выбор файла и открытие Monaco diff.
- Предпочтение вида и последняя валидная рабочая копия восстанавливаются после перезагрузки.
- Проводник файлов, Git-дерево, пустые состояния и узкий экран проверены автоматическими тестами и
  ручной матрицей.

## 8. Не входит в эту работу

- редактирование файлов или Git-операции из Cockpit;
- изменение формата реестра проектов;
- изменение API `repos`, `ls`, `file` или `git`;
- объединение файлов проводника и списка изменений в одно дерево;
- поиск по файлам, фильтры, breadcrumbs и вкладки нескольких открытых файлов;
- переименование терминов Git на сервере или изменение правил обнаружения worktree.
