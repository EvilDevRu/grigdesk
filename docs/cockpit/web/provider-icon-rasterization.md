# Сглаживание маленьких знаков исполнителей

Выравнивание видимой высоты не гарантирует одинаковую резкость знаков.
`ProviderIcon.vue` масштабирует исходные SVG до рисунка высотой примерно 14 CSS px
в кадре 15 CSS px. Масштаб и ширина получаются дробными; тонкие детали разных
логотипов занимают разное число физических пикселей.

До привязки к пиксельной сетке на стенде с полным `AppShell.vue`, шириной окна
1920 CSS px и DPR=1 кадры начинаются
на y=19, а верх видимого рисунка находится около y=19.5. Ширины кадров Codex и Kimi
после округления раскладки составляют 14.796875 и 14.171875 CSS px. Толщина штриха
Claude после масштабирования — около 1.57 CSS px. У знаков и их кнопок проверены
`filter: none` и `opacity: 1`.

Границы между физическими пикселями сглаживаются при отрисовке, поэтому маленькие
детали могут выглядеть мягкими. При DPR=2 половина CSS px уже соответствует целому
физическому пикселю; ощущение резкости зависит также от масштаба браузера и дисплея.
Эти замеры описывают стенд, а не неизвестные настройки экрана человека.

Теперь в топбаре применяется [привязка левой границы SVG](provider-icon-pixel-snap.md)
к физическим пикселям. Она устраняет дробное положение рисунка по горизонтали;
вертикальная ось остаётся общей для всей строки. Внутренние детали и кривые SVG
по-прежнему сглаживаются.

При доводке резкости нужно оценивать снимок при DPR=1 и обычном масштабе вместе
с геометрией. Привязка кадра к целым координатам сама по себе не выравнивает
внутренние контуры SVG. Принудительное отключение сглаживания ухудшает диагонали
и округлые контуры, поэтому требует отдельной визуальной оценки.
