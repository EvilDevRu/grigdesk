# Service Worker кэширует — правки не видны без «Обновить»

PWA (`vite-plugin-pwa`, `registerType: 'prompt'`) кэширует ассеты. После пересборки страница
крутит СТАРУЮ версию, пока в конце рейки (внизу сайдбара, под «Свернуть»; на телефоне —
правая, прилипшая плитка нижнего ряда) не загорится синяя плитка «Обновить кокпит»
(`features/cockpit-update/CockpitVersionTile.vue`, `usePwaStore.needRefresh`). Та же плитка
в тихом состоянии показывает запущенную версию с точкой «есть релиз», а во время серверной
установки — стадию; в топбаре индикатора версии больше нет.
При отладке в браузере это выглядит как «правка не применилась» — на самом деле нужно обновить SW.
`index.html` отдаётся с `no-cache`, ассеты (`/assets/*`) — `immutable`.

**Браузер Playwright MCP — отдельное окно со своей сессией и своим кэшем.** Вход человека
в его обычной вкладке туда не переносится: кокпит покажет форму входа, пока не залогинишься
в самом окне автоматизации по `http://localhost:8140`. Что вход уже есть,
надёжнее проверять не по виду страницы, а запросом `/api/auth/state`.

Одного `registration.update()` для показа свежей сборки МАЛО: старый SW продолжает отдавать
свой precache, и в дело идёт ещё HTTP-кэш `index.html`. Рабочая последовательность —
`getRegistrations().unregister()` + `caches.keys()/delete()`, затем переход по адресу с новым
query (`/?nocache=<метка>#/...`). Проверять надо не «на глаз», а по имени загруженного чанка:
`performance.getEntriesByType('resource')` против свежего имени в `web/dist/assets/` — иначе
замеры описывают прошлую сборку и правки выглядят «не применившимися».
