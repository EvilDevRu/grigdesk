# Tooltip/popover живут в <body>: scoped-селектор consumer-а до surface не дотянется

**Где:** `web/src/components/overlays/UiTooltip.vue` и `UiPopover.vue`; product-код
импортирует их только из `web/src/ui.ts`.

Пока подсказка была `position: absolute` внутри страницы, она пряталась: скролл-контейнер
(`.content` шелла, списки, панели чата) обрезал её по своей границе — у полей в верхней части
формы «Агентов» верхние строки уходили под топбар, — а модалки (`z-index: 100/120`) перекрывали.
Теперь обе поверхности ВСЕГДА телепортируются в `<body>` и позиционируются от вьюпорта;
semantic layer даёт им уровень выше модалок и баннеров. `place()` поджимает координаты к экрану
и меняет фактическое placement, если с запрошенной стороны места нет.

Плата: surface больше не потомок компонента-вызова, поэтому scoped-CSS вида
`.my-trigger :deep(.ui-tooltip)` всегда мимо. Tooltip получает точечные размеры через
`surface-style`, popover — через обычный `style` самого `UiPopover`; повторяемый skin меняется
только в `web/src/styles/components/overlays.css`. Класс триггера ставится прямо на VNode в
слоте `#trigger`. Интерактивное содержимое нельзя класть в tooltip: для него нужен `UiPopover`,
а action закрывает его через slot-prop `close('action')`. Положение пересчитывается на скролле,
ресайзе и через `ResizeObserver`, потому что содержимое может догрузиться уже раскрытым.

Строковая директива `v-tooltip` использует один `UiTooltipHost` в `App.vue`. Его поверхность
тоже находится в `body`; skin `.ui-tooltip--plain` задаётся в `overlays.css`, сохраняет
переводы строк и пользуется тем же расчётом положения. Богатая командная справка использует
skin `.ui-tooltip--code`. Подсказки не отнимают верхний интерактивный слой у диалога,
поэтому его замыкание Tab продолжает работать. Подробности — в [контракте подсказок](tooltips.md).

Проверять замером, а не глазами: навести и сверить `getBoundingClientRect()` с вьюпортом плюс
`document.elementFromPoint` по центру — перекрытие на скриншоте видно не всегда.
