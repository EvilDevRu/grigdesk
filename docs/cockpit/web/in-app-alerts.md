# Оповещения: тост в окне, системное — когда окна нет

`shared/alerts.ts` направляет события в общий центр тостов и системный канал.
Человек «здесь», когда `document.visibilityState === 'visible'` и `document.hasFocus()`:
в этом случае показывается только тост. Если документ скрыт или другое приложение забрало
фокус, показываются тост и системное уведомление. При отсутствии метода `hasFocus` видимый
документ считается активным. Кнопка «Проверить» в настройках по-прежнему напрямую проверяет
системный канал через `shared/notify.ts`.

| Событие | id | scope | Тон | Исчезает само | Действия и цель |
| --- | --- | --- | --- | --- | --- |
| Ответ агента | `chat-<chatId>` | `chat:<chatId>` | accent | Через 8 секунд | Открыть чат |
| Разрешение | `chat-ask-<pid>` | `chat:<chatId>` | warning | Нет | Разрешить / Отклонить для простого запроса; Открыть чат |
| Вопрос | `chat-ask-<pid>` | `chat:<chatId>` | warning | Нет | Открыть чат |
| Ворота | `conveyor-<taskId>` | `task:<taskId>` | warning | Нет | Открыть конвейер |
| Авария или затык | `stall-<taskId>:<kind>:<stage>` | `task:<taskId>` | danger | Нет | Открыть конвейер |
| Молчание | `silence-<taskId>:<stage>` | `task:<taskId>` | warning | Нет | Открыть конвейер |
| Результат 3D | `studio-<versionId>` | `studio:<modelId>` | accent / danger | Ready: 8 секунд; failed: нет | Открыть модель и версию |
| Ошибка сохранения истории | `chat-save-error` | — | danger | Нет | Крестик |
| Новое событие полки | `task-shelf-<taskId>-<fingerprint>` | `task:<taskId>` | accent | Через 8 секунд | Открыть задачу поверх раздела |

Для старого запроса без `chatKey` область пуста и перехода в чат нет. Вопросы и ответы
видимого чата не оповещают: остаётся прежний контракт registered surface `_visible`.
SSH- и DB-подтверждения поступают отдельной сверкой waiting и тостов не создают.
Отказ через тост идёт без пояснения; постоянное разрешение до конца сессии остаётся в чате.

Тост гаснет после ответа, события `chat-permission-done` из другого окна или устройства,
либо когда сверка waiting больше не содержит запрос. Видимый чат при `markRead` гасит все
тосты своей области даже без unread. Снятые ворота, авария и молчание гасят свои события
при успешной сверке конвейера; отказ чтения списка задач сохраняет прошлые оповещения.
Восстановление сохранения истории гасит её ошибку. Потеря сессии очищает все тосты.
Исчезновение тоста закрывает системное уведомление с тем же id — через экземпляр
Notification. Service worker не используется; иконка — встроенный PNG data URL.

Быстрое разрешение допустимо только для объекта `kind: 'perm'`, который тост может
показать целиком. Отклоняются источники SSH и DB; `ExitPlanMode` и запросы с планом;
непустой `input.kind` (включая внешнюю страницу); непустые варианты выбора и diff;
дополнительные непустые поля input вне `description`, `file_path`, `command`, `details`;
текст длиннее 400 символов. Пустая строка, null и undefined у дополнительного поля не
добавляют содержания. Полный detail собирается из четырёх разрешённых полей в указанном
порядке, с trim и разделением строками. Пустой detail допустим: чат тоже показывает только
название инструмента.

Системное уведомление содержит адрес цели: `#/chats?openChat=<id>` для чата,
`#/shelf?openTask=<id>` для задачи и `#/pipeline` для конвейера. Идентификаторы кодируются.
Оболочка поглощает только `openChat` и `openTask`, сохраняя остальные параметры адреса.
Параметр `task` не используется: он уже принадлежит странице «Диф». Открытие чата ждёт
загрузки истории и передаёт одноразовый `revealRequest`; страница «Чаты» раскрывает сам чат
даже на телефоне, где обычное начальное состояние показывает список.

Стопка находится сверху под панелью: справа 12 px, а от ширины 900 px — 56 px, с учётом
правой рейки дока. До 759 px занимает ширину окна с боковыми отступами 8 px. Нижний угол
мешал бы отправке сообщения, особенно для срочного тоста без таймера. Видны три новейших
тоста, новейший первым; центр хранит до двадцати. Повтор id заменяет тост и делает его
новейшим. Остаток обозначается «Ещё N», кнопка «Скрыть все» очищает центр.

Таймер работает только при видимом документе. Наведение и клавиатурный фокус внутри тоста
ставят его на паузу; смена фокуса между кнопками не запускает таймер. Возобновление даёт
полную длительность. Слой `toast` имеет приоритет 90, ниже `dialog` (100): модальное окно
делает фон inert. Тосты не регистрируются в стеке Escape и журнале окна, закрываются
крестиком или действием. UI-kit не знает API, Pinia и роутер; product-код использует только
публичную границу `web/src/ui.ts`.

## История оповещений

Колокольчик в верхней панели, слева от настроек, открывает историю оповещений этого окна
(`shared/alertHistory.ts`, вид — `features/alerts/AlertHistoryPopover.vue`). Запись создаётся
на каждый показанный тост, новейшие сверху, не больше 50. История живёт в памяти вкладки:
в ней текст переписки, поэтому на диск она не пишется. Её стирают потеря сессии
и кнопка «Очистить».

Состояние записи определяется тем, как ушёл тост. Центр тостов сообщает причину ухода
(`subscribeToastDismissals`):

| Причина | Состояние | Значок колокольчика |
| --- | --- | --- |
| Тост на экране | на экране | не считается |
| Истёк таймер или вытеснен лимитом | пропущено | считается |
| Крестик, «Скрыть все», нажатое действие | просмотрено | не считается |
| Повод исчез (`dismissAlert`, `dismissAlertScope`) | разобрано | не считается |

Повод может исчезнуть и после ухода тоста: пропущенный ответ становится разобранным, когда
чат открыли обычным путём. Открытие истории отмечает пропущенное просмотренным; до закрытия
всплывашки такие строки подсвечены подписью «пропущено». «Открыть» в записи использует ту же
открывалку, что и тост. Новое событие с тем же id переводит прежнюю живую запись
в просмотренные.

На телефоне сводка статуса в верхней панели шире экрана. Поэтому она сжимается и
обрезается справа, а колокольчик и настройки остаются у края.

Текст тоста мельче основного: заголовок 12,5 px, тело 12 px в две строки, команда 11 px.
Кнопки компактные (26 px), крестик висит в углу и не отнимает ширину у трёх кнопок
разрешения. Значок слева показывает тон: сведения, ожидание человека, поломка. Тосты
въезжают справа и уходят туда же.

Раздел 3D получает terminal состояние через постоянный shell subscriber и
`studio-changed` → перечитывание задач. Семантический dedup не даёт повторить тост
при reconnect. Текущая открытая модель подавляет свой тост; кеш после ухода со страницы
его не подавляет. Цель `studio` открывает `#/3d?model=…&version=…` без token URL
или абсолютного пути в уведомлении. Потеря сессии и отключение прекращают эту подписку.
