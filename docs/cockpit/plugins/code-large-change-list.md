# «Код» замерзает на новом репозитории = тысячи файлов в индексе, все каталоги раскрыты

Симптом: в проекте с новым репозиторием (ещё ни одного коммита, всё добавлено `git add`)
панель «Код» отвечает с задержкой в секунды, особенно раздел «Изменения».

Причина — объём DOM, а не сервер. До первого коммита группа «В индексе» содержит весь
репозиторий, а при первом снимке панель раскрывает все каталоги групп
(`reconcileGitOpenDirs`). Замер на репозитории из ~8 тыс. файлов: дерево изменений —
9141 строка и ~102 тыс. DOM-узлов, открытие раздела замораживало окно одной задачей на
7,3 с, переключение «дерево/список» — ещё на 5,7–6,1 с. Каждая строка — несколько
компонентов (строка, «+/−», у рабочего дерева ещё popover), а `CodePanel` — один большой
компонент, так что любая смена его состояния заново сравнивала все строки.

Лечение — окно строк [`VirtualRows`](../web/virtual-rows.md) в дереве файлов, дереве и
списке изменений. Тот же замер после: открытие раздела — 0,27 с долгих задач и ~2,2 тыс.
узлов, переключение вида — до 0,29 с; прокрутка в любую точку и колесом подряд пустых
мест не оставляет. Оставшиеся ~150 мс — построение групп и путей каталогов в
`codeTree.ts` по всем файлам снимка, их окно не убирает.

Проверять такие жалобы надо замером в живом окне, а не глазами: число
`.git-file-line`, `document.getElementsByTagName('*').length` и долгие задачи через
`PerformanceObserver({ type: 'longtask' })` сразу показывают, рисует ли панель лишнее.
