# Границы каталога и протокола Tripo

Потребители входят через `server/src/lib/tripo/catalog.ts`. Он явно реэкспортирует
26 значений и три типа запросов. Нижние модули не импортируют фасад: общие значения
читаются из `catalogValues.ts`, ошибки ответов — из `taskErrors.ts`.

| Модуль | Ответственность |
| --- | --- |
| `catalogValues.ts` | Датированные модели, ручки, типы задач, допустимость native-входа, пулы |
| `catalogFields.ts` | Поля, подсказки и готовые наборы; порядок зависимых полей |
| `catalogValidation.ts` | Нормализация значений, несовместимости, ошибки и предупреждения |
| `catalogPricing.ts` | Оценка цены по датированному прайсу и курсу кредита |
| `requestPayload.ts` | Тела запросов v3, native/file-входы, отдельные запросы движений |
| `taskResponses.ts` | Ответы задач, роли файлов, записи импорта, фильтр параметров и usage |
| `taskErrors.ts` | Классификация отказов запроса и задачи, публичные сообщения |

Ценовые подсказки вариантов принадлежат полям, а численный расчёт — ценам. Общие
наборы моделей и типов задач имеют одного владельца. Порядок инициализации значений
важен: обратная карта типов строится после прямой, варианты моделей — после имён.

Стоимость задачи остаётся nullable: отсутствие числа и строковое число дают `null`.
Роли файлов и устойчивые output IDs, неизвестный remote status, фильтрация секретов
в импортированных параметрах и происхождение записей сохраняются на границе протокола.
Изменение прайса или версии API требует отдельного изменения контракта.
