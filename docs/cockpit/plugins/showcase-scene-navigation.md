# «Сборка остановлена. locator.waitFor: Timeout…» у «Собрать ролик» = продолжение ждало каркас экрана, с которого предыдущая сцена ушла; страницы фичи не было в карте — теперь экраны находятся сами

Симптом (ролик 8702, 16.09.2026): «Собрать ролик» встал с «Сборка остановлена. locator.waitFor:
Timeout 30000ms exceeded… waiting for locator('button[role="combobox"]:has(svg.lucide-trending-up-down-icon)')»,
в карточке — «Сцен пока нет». Стенд живой, вход прошёл, три предыдущие репетиции того же
разбора были успешными (`rehearsals/*/result.json` в каталоге ролика).

**Корень — карта + правило продолжения.** `profiles/<PROFILE>/showcase/screens.json` знала только
«Список проектов» и «Проверка позиций», а фича 8702 живёт в «Настройки проекта → Частота»
(`/389/settings/volume`). Модель дошла туда найденными на ходу элементами (сайдбар «Настройки
проекта» → «Частота») внутри screenId `positions`, следующую сцену объявила продолжением
(`continuesPrevious: true`) того же `positions`, а репетиция перед продолжением ждёт условие
готовности ОБЪЯВЛЕННОГО экрана — фильтр динамики над таблицей позиций, которого на странице
настроек нет. Ожидание стояло вне try/catch действий, поэтому таймаут не стал наблюдением для
цикла починки, а уронил сборку сырым текстом Playwright (с селектором внутри). Глубже: автопоиск
репетиции находил только ЭЛЕМЕНТЫ объявленных экранов, экран (маршрут) объявить не умел, а
наблюдения не несли URL — три ролика из четырёх (8665, 8513, 8702) требовали правки карты руками.

**Починено 16–18.09.2026.**
1. `script/rehearsal.ts`: срыв готовности у продолжения — наблюдение с ошибкой («экран не готов
   после предыдущей сцены: её действия увели с него — назови в screenId открывшийся экран или
   начни сцену заново») и `completed: false`; у головной сцены — остановка с понятной причиной
   («стенд не прогрет или карта экранов отстала»); кадр `scene-N-action--1.webp` остаётся в
   каталоге попытки. Срок настраивается `readyTimeoutMs` (тест — 1,5 с).
2. **Экраны находятся сами** (`script/observation.ts` `currentScreen`, `pagePathOf`): если
   действие сменило адрес в пределах origin цели, страница становится экраном `page:<путь>`
   (заголовок из h1–h3 или document.title, готовность по каркасу: заголовок → `main` → `body`,
   данные ждёт затишье сети). Найденные элементы ложатся на найденный экран, наблюдение несёт
   `path`. Модель может назвать `page:…` головой сцены — запись откроет адрес сама (`goto`).
   Найденные элементы (`observed-…`) вправе назвать любая сцена (`resolvableElements` в
   репетиции, writer и recordingOps): клик, уводящий на другую страницу, и `waitVisible` уже на
   ней — одна сцена. Экран `page:…` без прежнего отчёта восстанавливается из адреса
   (`screenFromPageId`, готовность `body`). Права не расширены: найденное остаётся read-only.
   В списке сцен такой экран подписан «страница /…» (`sceneText.ts` `screenLabelOf`).
   Живой прогон на 8702 (`.state/artifacts/showcase-8702/discover/rehearse-dry-run.mts`, карта
   без экрана настроек): клик «Настройки проекта» → `page:/389/settings` (34 элемента), клик
   «Частота» → `page:/389/settings/volume` (68 элементов, сводка найдена), голова сцены на нём +
   продолжение — completed; у <PROFILE> нет h1–h3, готовность вышла `main, [role=main]`.
3. Карта <PROFILE> всё же дополнена (экран `frequencySettings`, путь окна «Обновить частоту» из
   8698, ссылка `projectSettingsLink`) — ради подписей и элементов с POST (тумблеры сохраняются
   `/restify/project-checks/actions?action=save`, политика профиля это разрешает); «Запустить»
   по-прежнему не в карте. Урок: **состояние стенда в подписях не писать** («на этом стенде
   W выбрана», «Десктоп выключен») — через день расписание на 8702 уже было другим; состояние
   живёт в наблюдениях, подписи описывают только устройство элемента.

**Заодно.** Стенд 8702 стоял в режиме конкурентов (`#competitorsGrid` вместо `#filtersTable`) —
UI-настройка тестовой учётки на сервере стенда, `frequencyTopCell` из карты в этом режиме не
виден; возвращено кликом по `.reset-btn`. Тумблер «Москва/Десктоп» меняет сводку «проходов»,
в окне «Обновить частоту» — стоимость (200 → 300 лимитов при одном добавленном тумблере).
