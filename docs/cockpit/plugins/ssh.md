# SSH-плагин

## Состояние и подключение

Описание соединения (`projectId`, метка, роль, host, port и user), known-hosts и журнал
лежат в приватном `server/.state/ssh` с правами 0600/0700. Пароль вводится человеком при
каждом подключении, передаётся телом `application/octet-stream` только по HTTPS либо с
localhost/loopback и не хранится и не попадает в prefs, `.state`, argv, env, журнал или
клиентский JSON. Системные `ssh` и `sshpass` не запускаются: транспортом владеет `ssh2`.

Перед паролем клиент делает probe host key. Неизвестный ключ проходит явный TOFU-диалог;
изменившийся ключ блокирует вход и требует отдельного решения «заменить». Challenge
одноразовый и короткоживущий, а известный отпечаток проверяется при самом подключении.

Сессией владеет процесс Cockpit. Закрытие окна или unmount панели отсоединяет только
браузерный WebSocket; явное закрытие вкладки сессии завершает её. Панель монтируется
единственным `ToolHost`, держит один xterm/attach WebSocket и при переключении внутренних
вкладок подключает его к другой живой сессии. Human shell и agent exec — разные SSH-каналы:
`cd`, окружение и запущенные программы человеческого shell агенту не передаются. SFTP
доступен только человеку; в схеме инструмента агента файловых действий нет.

Ход агентской команды человек видит в терминале: эхо врезается ВНИЗ, в fan-out окон и буфер
повтора, и в SSH не уходит — поэтому напечатанное не может стать вводом чужой оболочки и не
наследует её состояние. Рамка запуска несёт саму команду (она тоже недоверенный текст:
управляющие последовательности снимаются, многострочность сворачивается в одну строку),
затем идёт поток вывода по мере поступления, затем итог с кодом возврата или причиной обрыва
(`access_revoked`, `session_lost`). Переносы приводятся к CRLF — канал exec работает без PTY,
и голый LF уводил бы вывод лесенкой. Объём эха ограничен 64 KiB на команду, иначе крупный
вывод вытеснил бы собственную историю человека из буфера повтора; при срезе итог сообщает,
сколько байт показано из скольких. Выключается настройкой плагина «Эхо команд агента
в терминал».

## HTTP, WebSocket и SSE

- `GET/POST /api/ssh/connections`, `PUT/DELETE /api/ssh/connections/:id` — профили.
- `POST /api/ssh/connections/:id/host-key/probe` и
  `POST /api/ssh/host-key/:challengeId` — проверка и явное доверие ключу.
- `GET /api/ssh/sessions`, `POST /api/ssh/connections/:id/sessions` и
  `DELETE /api/ssh/sessions/:sid` — server-owned lifecycle.
- `PUT /api/ssh/sessions/:sid/agent-access` — явный допуск агента.
- `GET /api/ssh/sessions/:sid/terminal` — WebSocket human shell (`in`, `resize`).
- `GET /api/ssh/sessions/:sid/files`, `GET .../files/download` и
  `POST .../files/upload` — human-only SFTP.
- `GET /api/ssh/audit` — пагинированный журнал команд агента.
- `POST /api/ssh/approvals/:pid` — origin-aware ответ `{allow, comment}`.

SSE `ssh-sessions`, `ssh-permission` и `ssh-audit` — только инвалидации в общем потоке
`/api/events`. Полный список ожиданий восстанавливает
`GET /api/chat/waiting?include=ssh`; без opt-in SSH-записи не выдаются.

## Агент и подтверждения

Исполнителю объявляется один `supervised_ssh`: `list` возвращает только `label` и `role`,
`exec` принимает этот селектор и полную команду. Host, port, user и fingerprint не входят
ни в descriptor, ни в результат, историю или prompt. Scope берётся только из trusted
attempt ledger: task id → доверенный attempt.profile → существующий project. Свободный чат
и недоверенная/legacy-задача получают null scope и не видят сессий.

Доставка общая, но транспорт соответствует исполнителю: Claude получает локальный MCP,
Codex — dynamic tool app-server, Kimi и DeepSeek — MCP через ACP
(у Kimi contained с mount). Descriptor и dispatcher едины. В ядре чата нет выбора по вендору.

Для всех команд действует одна общая очередь чата; broker кладёт в неё запись
`origin: 'ssh'`.
Auto-allow, remember и режим прав исполнителя её не обходят. Ответ из чата и SSH-панели
идёт одним методом в `/api/ssh/approvals/:pid`; generic
`/api/chat/permission/:pid` SSH-origin отвергает. Пояснение к отказу необязательно —
трение стоит на разрешении, а не на запрете, — и, если оно есть, возвращается агенту. Закрытие/обрыв сессии и снятие доступа немедленно отменяют ожидание.

Вывод считается недоверенным: управляющие последовательности снимаются, данные явно
маркируются, а head+tail ограничиваются `outputLimitKiB`. При срезе агент видит
«показано N из M» и не получает обрезанный результат как полный. Между половинами стоит
видимая строка `… середина удалена …`, и она занимает место ВНУТРИ лимита: без неё
оборванная строка головы склеивалась с началом хвоста в одну, и агент цитировал строку,
которой на сервере не было. При лимите меньше двух таких меток она пропускается —
отдать половину крошечного бюджета служебной строке хуже, чем показать больше вывода. Маркировка снижает риск,
но не устраняет prompt injection из логов удалённого сервера; человек должен считать
такой вывод потенциально враждебным. `command_failed` и `session_lost` — разные результаты.
Журнал хранит команду, человеческое решение, комментарий и ограниченный результат 30 дней;
пароля и полного сырого вывода в нём нет. Помимо журнала человек видит ход выполнения вживую:
команда и её вывод дублируются эхом в терминал сессии (см. «Состояние и подключение»).

Связанные границы описаны в [агентах чата](../chat/README.md),
[архитектуре](../overview/README.md) и [граблях](README.md#грабли).
