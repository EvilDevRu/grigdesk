# Параллельные записи журнала песочницы

Редкий `ENOENT` при переименовании временного JSON в lifecycle песочницы возникал
из-за общего имени `<запись>.tmp`. Обзор, таймер слежения и завершение профильного
процесса могут одновременно сохранять снимок одного задания. Первый `rename`
забирал временный файл, второй уже не находил его. Даже до переименования
параллельные `writeFile` могли писать в один файл.

`writeSandboxJournalRecord` в `server/src/lib/sandboxes/registry.ts` теперь создаёт
отдельный временный файл для каждого вызова, рядом с конечной записью. Создание
использует `wx` и права `0600`, замена конечного JSON остаётся атомарной. `finally`
удаляет свой временный файл, в том числе при ошибке записи или переименования.
Читатель видит один целый снимок; последнее завершённое переименование определяет
его содержимое. Эта гарантия не заменяет аренду стенда или согласование переходов
состояния в службе lifecycle.

Регрессия в `tests/server/sandbox-registry.test.js` удерживает два настоящих
`writeFile` перед первым переименованием. На общем временном имени один вызов
стабильно отклоняется; после исправления оба завершаются, журнал содержит один
из исходных снимков целиком и временных файлов не остаётся. Соседние проверки
lifecycle, действий профиля и HTTP-прав также проходят.
