# Выполненный прогон shared-профиля не уходил с экрана: закрывать было нечем

Кокпит **не архивирует задачу сам** — это осознанно: пока прогон на экране, у него
живые `report.md`, `plan.md` и граф, а архив (`~/.factory/state/archive/`) человек не
листает. Реестр в архив переносит человек кнопкой, и кнопок для этого две:

| у задачи есть | кнопка | что делает |
|---|---|---|
| своя песочница | «⏏ снести стенд» | сносит стенд и архивирует прогон заодно |
| стенда нет | «✓ закрыть задачу» | только архивирует (плюс удаляет пустую ветку) |

Третий случай в это деление не попадал: **shared checkout с внешним стендом**
(`WORKSPACE_MODE=shared` / `STAND_OWNERSHIP=external`).
Сносить чужой стенд кокпиту запрещено (`shared_workspace_lifecycle_forbidden`), значит
первой кнопки нет по определению; а вторая пряталась по условию «нет порта фронта» —
и в shared-режиме порт есть ВСЕГДА, потому что стенд общий и живёт вне задачи.
Доведённый до конца прогон висел на экране навсегда: убрать его было нечем ни одной
кнопкой, ни одним API.

Ловушка в самом условии: «есть порт» молча означало «есть НАША песочница». Правило —
**закрытие разрешено, когда кокпиту нечего сносить: стенда нет ЛИБО стенд не его**
(`canCloseTask` в `PipelineView.vue`). Серверный `/api/tasks/:id/close` shared-режим
умел с самого начала: пропускает гард живого стенда, не трогает ветки
(branch lifecycle к общему рабочему дереву не применяется даже read-only пробой) и
только переносит проекцию реестра в архив.
