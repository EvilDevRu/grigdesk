# Просмотр документов

В Cockpit есть встроенный read-only предпросмотрщик документов. Он открывает `.md`,
`.markdown` и `.txt` с сервера, а также изображения из сообщений чата — в одном модальном
окне поверх текущего экрана, в том числе на планшете.

Это **core-модуль, не плагин**:

- сервер явно регистрирует `modules/documents` в `app.js`;
- модуль не входит в реестр плагинов, не имеет manifest/toggle и не добавляет пункт навигации;
- web-ядро `features/documents/DocumentPanel.vue` встроено в глобальный модал;
- `/documents` остаётся скрытым lazy route для прямых и старых deep-link ссылок;
- содержимое не копируется в историю чатов, prefs, localStorage или отдельную базу.

## Ссылка и источники

Постоянный адрес использует не абсолютный путь хоста, а `DocumentRef`:

```text
{ source: "cockpit", path: "docs/cockpit/architecture.md" }
```

Ему соответствует route:

```text
#/documents?source=cockpit&path=docs%2Fcockpit%2Farchitecture.md
```

Старые ответы агентов уже содержат абсолютные ссылки вида `/<absolute-path>/file.md`.
Chat renderer превращает
такую ссылку во внутренний адрес с параметром `open`, а обычный клик перехватывает глобальный
модал без ухода со страницы чатов.

**Просмотрщик документов — только один из трёх исходов файловой ссылки в чате.** Общий
резолвер `features/code/links.js` (`chatFileLinkHref`) разбирает их по порядку: `.md`/
`.markdown`/`.txt` — сюда; файл под известным деревом репозитория — в панель «Код»
(`#/code?…`, см. [architecture.md](architecture.md)); остальные локальные пути —
**вердикт `false`, и ссылка рендерится ТЕКСТОМ**. Последнее принципиально: markdown-рендерер
пропускает обычный относительный путь своим allowlist-ом и раньше рисовал синюю ссылку на
`chat.js`, клик по которой открывал пустую вкладку на origin кокпита. Ссылка не имеет права
обещать открытие, которого не будет, поэтому `false` понимают оба пути рендера — и обычный,
и allowlist raw HTML этого viewer-а. Fragment не отправляется HTTP-серверу, а
`POST /api/documents/resolve` проверяет путь без записи его в access-log query и возвращает
`DocumentRef`. Сам `GET /api/documents/file` принимает только `source + относительный path`.
Модифицированный клик и сохранённые deep links по-прежнему могут открыть route `/documents`.

Ссылка с суффиксом `:42` открывает точную строку в нумерованном исходнике. Для Markdown
можно переключаться между исходником и отрендеренным предпросмотром.

Первый источник `cockpit` подключён в `server/src/app.js` и указывает на `config.rootDir`.
Следующие источники добавляются через `DocumentReader.addRootProvider()` либо массив
`rootProviders` при сборке приложения. Сам reader не импортирует проекты, чаты или Factory.

## Граница безопасности

API находится за общим auth-гардом и дополнительно применяет файловые ограничения:

- источник обязан быть зарегистрирован сервером;
- разрешены только относительные пути внутри источника;
- root и целевой путь проверяются через realpath, на Linux происхождение открытого file
  descriptor повторно сверяется через `/proc/self/fd`;
- выход через `..` или symlink за пределы root запрещён, конфликтующие source id закрываются отказом;
- как документы читаются только обычные `.md`/`.markdown`/`.txt` файлы;
- относительные PNG/JPEG/GIF/WebP загружаются отдельным `/api/documents/asset` из того же
  source; SVG намеренно не разрешён;
- максимум — 1,5 МБ, только валидный UTF-8 без NUL;
- ответ помечен `Cache-Control: private, no-store`;
- raw HTML во всех сообщениях по умолчанию экранируется. Viewer документов отдельно включает
  строгий allowlist разметки: разрешены типографские теги, таблицы, ссылки и картинки, но
  удаляются скрипты, стили, обработчики событий и опасные URL.

Относительные ссылки на другие текстовые документы остаются внутри того же source. HTTP(S) и
mailto-ссылки продолжают открываться как внешние. Предпросмотрщик ничего не редактирует,
не перечисляет каталоги и не индексирует содержимое.

## Проверка

- `tests/server/documents-reader.test.js` — providers, конфликты roots, realpath/symlink,
  тип/размер/UTF-8, локальные картинки и HTTP;
- `tests/web/documents-links.test.js` — абсолютный bridge, стабильные refs, относительные ссылки
  и повторная проверка URL Markdown-рендерером;
- `tests/web/code-links.test.js` — мост в панель «Код», приоритет документов, подавление
  мёртвых ссылок (в том числе в raw HTML) и молчание моста без карты деревьев;
- `npm --prefix web run build` — компиляция lazy route и Vue-компонента.
