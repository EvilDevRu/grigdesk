# Приём файла: список расширений, а не одни MIME-маски

**Масок `video/*`/`audio/*` в диалоге выбора мало.** Нативный диалог разворачивает маску
в список расширений и сравнивает их ПОБУКВЕННО, поэтому запись с айфона (`IMG_4793.MOV` —
именно так её отдаёт Telegram) в диалоге серая: выбрать нечем, хотя конвейер разбирает
такой файл как любой другой. Проверяется это тем же вызовом, каким конвейер тянет звук
(`ffmpeg -vn -ac 1 -ar 16000 -c:a pcm_s16le`): на `.MOV` он отдаёт нормальный wav.
Отсюда `MEDIA_EXTENSIONS` в `VideoView.vue` — явные расширения в ОБОИХ регистрах; прежние
маски оставлены для браузеров, которые фильтруют по типу файла, а не по имени.

**Перетаскивание на карточку — второй путь к тому же обработчику.** Зона `dropzone` и так
нарисована, но принимала она только клик; при этом бросок остаётся единственным способом
отдать запись, если диалог всё же спрячет её (другой браузер, другой набор расширений).
Идущий разбор перетаскивание не перебивает — у пикера в это время `disabled`, и второй
путь обязан вести себя так же, иначе запись подменялась бы на середине распознавания.
Сторожа — `tests/web/video-section.component.test.js`.
