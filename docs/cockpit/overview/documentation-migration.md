# Перенос знаний в документацию

`docs/` — источник знаний о Cockpit, доступный в обычном клоне. Для чтения документации
не нужны работающий сервер, прежняя SQLite-база или инструмент `knowledge_search`.
История снятого плагина сохранена в [отдельном документе](knowledge-base-history.md).

## Проверка полноты

При сверке исходной базы и результата переноса учтены все 268 записей: 265 общих записей
собраны в 231 документ, ещё 3 записи сохранены в 3 локальных документах. Склейки объединяют
разделы одной темы. Исходные тексты найдены в выгрузке с учётом уровней заголовков,
новых адресов ссылок и обезличивания примеров.

Восемь записей после выгрузки уточнены при снятии плагина: из действующего описания убраны
его API, инструменты, страница, настройки и регистрация. Это изменение контракта;
прежнее устройство плагина осталось в истории. Новые документы после переноса в эти
числа не входят.

Общие примеры используют `<PROFILE>` и `<TASK>`. Конкретика машины сохранена отдельно
в `docs/local/`, включая соответствия обезличенных примеров в `docs/local/cases.md`.
Этот слой не входит в Git и требует отдельной резервной копии.

## Как поддерживать структуру

- Сначала читать README нужной области, затем связанные документы. Поиск по содержимому —
  `rg` по `docs/`; для игнорируемых локальных заметок — `rg --no-ignore` по `docs/local/`.
- Новый файл называть коротко по смыслу, английскими словами через дефис: например,
  `history-storage.md`. Заголовки и текст оставлять русскими, оглавления — `README.md`.
- При переименовании обновлять оглавления, ссылки между областями и локальные ссылки
  в `docs/local/`. Последние не проверяются общими тестами, поскольку отсутствуют в клоне.
- Действующий контракт сверять с кодом. Исторический разбор описывает причину изменения,
  но сам по себе не подтверждает, что прежний API или путь исходника ещё существует.
- Строка «Источник до переноса» сохраняет происхождение записи: указанный путь относится
  к прежней документации, а не к текущему файлу, который нужно открыть. Для навигации
  использовать Markdown-ссылки на действующие документы.
- Снятые решения явно помечать как историю.
- Подключать документы по ссылкам. `@`-каскад корневых инструкций содержит только
  `CLAUDE.local.md`; README областей и тела документов в него не входят.

Проверка ссылок, полноты оглавлений, приватных идентификаторов и корневого каскада:

```bash
node --test tests/docs/*.test.mjs tests/docs/*.test.mts
```

Оба расширения обязательны: проверка структуры документации написана в `.mts`.
Тесты не подтверждают семантическую актуальность каждого исторического наблюдения:
изменённый контракт нужно проверять по его реализации в том же заходе.
