# Машинные переменные — .env в папке данных, общий для всех способов запуска

Файл `<папка данных>/.env` читают systemd-юнит (`EnvironmentFile=`), `bin/cockpit` и
`deploy/restart.sh` (серверные run/dev и restart — `node --env-file`, CLI — `util.parseEnv`).
Раньше набор переменных зависел от того, чем подняли
сервер: `deploy/restart.sh` подставлял путь к venv распознавания сам (строкой в скрипте), юнит —
нет. Поднятый руками кокпит диктовку распознавал, поднятый systemd (то есть после каждой
перезагрузки) падал с ENOENT, и разница ничем не объяснялась.

Строки `Environment=` в установленном юните не помогают: `deploy/install.sh` перегенерирует
`~/.config/systemd/user/cockpit-server.service` из шаблона на каждом прогоне, правки пропадают.
Синтаксис `.env` — общий знаменатель systemd и `node --env-file`: `KEY=VALUE`, без `export`,
без подстановки `$VAR`, `~` и `%h` (пути только абсолютные). После ручной правки `.env` —
перезапуск. Код правит файл только [общим писателем](env-file-writer.md). Ключи исполнителей,
заданные окном «Ключи доступа», действуют без перезапуска: сервер сразу переносит их в своё
окружение.

Четвёртый способ запуска — сервер под [приложением Кокпита](desktop-owned-server.md). Окно
находит копию по `$XDG_DATA_HOME/cockpit/desktop/runtime.json` (его пишет `cockpit desktop
install`: корень, Node и при необходимости папку данных), читает `.env`
(`COCKPIT_ENV_FILE` или `<папка данных>/.env`) через
`util.parseEnv` и передаёт серверу окружение графического сеанса, дополненное ключами файла:
окружение процесса важнее `.env`, как у `--env-file`. PATH — как у юнита (`~/.kimi-code/bin`,
`~/.local/bin`, каталог Node), `NODE_ENV` не задаётся. После ручной правки `.env` нужен
перезапуск сервера: кнопкой в настройках или закрытием и открытием окна.

Сам сервер также читает файл на раннем старте, до конфигурации. Присутствующий ключ
окружения, даже пустой, важнее файла. `COCKPIT_HOME` и `COCKPIT_ENV_FILE` в файле
запрещены: они выбирают его снаружи. Раскладка и перенос — [папка данных](data-home.md).

`COCKPIT_RELAY_PROJECT` выбирает compose project локального контейнера для `cockpit relay …`.
Без него принимается только точное значение метки `config_files`, равное compose-файлу
этой копии. Переменная нужна при нескольких локальных посредниках или при использовании
нескольких compose-файлов. CLI читает её при каждом вызове; перезапуск сервера не нужен.
Окружение процесса важнее `.env`, а shell-подстановки файла не исполняются.
