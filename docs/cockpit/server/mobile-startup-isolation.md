# Отказ мобильного входа не мешает запуску кокпита

Основной HTTP-сервер слушает `127.0.0.1:8140` по умолчанию. Отдельный мобильный
TLS-вход запускается после основного `listen` и слушает `127.0.0.1:8144`.
Порт и каталог его состояния задаются `COCKPIT_MOBILE_PORT` и `COCKPIT_MOBILE_DIR`.

`MobileService.start()` проверяет private stores, ключ и сертификат, затем открывает
TLS-вход. Занятый мобильный порт, повреждённый список телефонов или ошибка ключа
закрывают мобильный сервис. Основной сервер продолжает обслуживать локальный вход,
чаты и API. В защищённом `/api/mobile/status` возвращаются `server.up: false` и
понятная ошибка; добавление посредника при таком состоянии отвечает 503.

Настройки находятся в «Настройки → Доступ → Приложение на телефоне». Мобильный
сервис не создаёт посредников и не устанавливает исходящие подключения без
сохранённой конфигурации. Порт TLS остаётся локальным; отдельный посредник
получает исходящее соединение от мозга.

Проверка `tests/server/app-boot-smoke.test.js` запускает настоящий `app.ts` во
временных каталогах. Проверяются обычный старт, конфликт мобильного порта и
повреждённый `devices.json`: основной `/api/health` и `/api/chat/active` отвечают 200,
неавторизованный `/api/mobile/status` отвечает 401. У работающего мобильного входа
проверяется IPv4 loopback и отсутствие IPv6 listener. Дополнительная проверка
сервиса — `tests/server/mobile-admin-api.test.js`.
