# Сервер и Node SEA

Проверено 17 октября 2026 года по исходникам, документации Node и пробной сборке
через esbuild. Штатной SEA-сборки у сервера пока нет: `server/package.json`
запускает `node src/app.ts`. Проверка упаковки не включает запуск готового SEA.

## Возможности Node

SEA помещает Node и код приложения в один исполняемый файл. Для самого такого
приложения отдельная установка Node не требуется. Возможности зависят от версии:

- [Node 22.22.1](https://nodejs.org/download/release/v22.22.1/docs/api/single-executable-applications.html)
  принимает встроенный CommonJS-скрипт; blob создаёт `--experimental-sea-config`,
  затем его внедряет, например, `postject`. Файлы assets доступны через `node:sea`.
- [Node 26.12.0](https://nodejs.org/api/single-executable-applications.html)
  документирует ESM-вход и `--build-sea`. Флаг сборки появился в 25.5.0.
  С 26.9.0 `useVfs` даёт встроенным assets файловые операции и загрузку модулей,
  включая относительные импорты и пакеты. VFS доступна только для чтения.
  Native addons требуют извлечения на настоящий диск перед загрузкой.

Поддержка SEA находится в активной разработке; VFS имеет отдельный статус ранней
разработки. Наличие API в Node 26 не означает его наличия в минимальной версии
проекта. Исполняемый файл привязан к платформе и архитектуре включённого Node.

## Что показала пробная сборка

Проверка `server/src/app.ts` с esbuild 0.25.12 использовала `bundle: true`,
`platform: node`, `target: node22`, `write: false`, без изменения исходников
и без запуска приложения:

- `format: cjs` отказывает на двух верхнеуровневых `await` в `app.ts`
  и сообщает об отсутствии `import.meta` в CommonJS.
- `format: esm` собирает статически доступный граф. Это не проверка автономности:
  метаданные результата не содержат драйверов из `lib/db/engines/` и файлов
  адаптеров исполнителей, которые реестр импортирует по вычисленному пути.
- В результате остаются необязательные загрузки `bufferutil`, `utf-8-validate`,
  `cpu-features` и `sshcrypto.node`. Их отсутствие само по себе не доказывает
  неработоспособность: например, `ssh2` перехватывает отказ native crypto binding.

## Привязки текущего кода к файловой установке

| Область | Проверенный контракт |
| --- | --- |
| Корень установки | `config.ts` и `startDataHome.ts` вычисляют его относительно `import.meta.url`. От корня зависят движок, VERSION, seed и другие ресурсы. |
| Исполнители | `lib/executors/index.ts` читает каталог через `readdirSync` и выполняет вычисляемый `import()`. |
| Драйверы БД | `lib/db/engineRegistry.ts` читает каталог и импортирует каждый файл адаптера. |
| Дочерние процессы | MCP, обработка медиа, 3D, запись, installer и обновлятель запускают отдельные скрипты через `process.execPath`; installer также использует `fork()`. |
| Вспомогательные ресурсы | Python-помощники терминала, речи и обработки медиа находятся относительно исходных модулей. Playwright installer ищет `package.json` и `cli.js` установленного пакета. |
| Desktop | `desktop/src/serverProcess.ts` запускает системный Node и `server/src/app.ts`; описание установки содержит `root` и `node`. |
| Обновление | `workers/cockpit-update-worker.js` работает с git-снимком, устанавливает npm-зависимости и публикует каталоги сборок. Это контракт обновления файловой установки. |

В SEA `process.execPath` указывает на исполняемый файл приложения. Поэтому
существующие вызовы `<process.execPath> <script>` нельзя считать универсальным
запуском Node: они снова входят в приложение. Для помощников нужен отдельный
контракт запуска, например режимы того же бинарника или отдельный runtime.

VFS может сохранить загрузку встроенных модулей по файлам, но её пути нельзя
передавать внешним программам как обычные файлы хоста. Python-скрипты и другие
такие ресурсы требуют размещения на диске. Сборка сервера также не включает
автоматически внешние CLI исполнителей, Python, браузер, модели речи и движок.

Настройки и пользовательские данные уже отделены от кода через
[единую папку данных](data-home.md). Это совместимо с неизменяемым бинарником;
переходу мешают перечисленные контракты ресурсов, запуска и обновления.
