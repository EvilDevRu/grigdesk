# Вход в кокпит: один пользователь, сессионная cookie, гард на ВЕСЬ /api

`lib/authStore.ts` (учётка + сессии), `plugins/auth.js` (гард), `modules/auth` (эндпоинты),
`views/LoginView.vue` + `stores/auth.js`. Пароль — scrypt-хеш в `server/.state/auth-account.json`
(0600), сессии — в `auth-sessions.json`, поэтому рестарт сервера не выкидывает с планшета.

**Закрыто ВСЁ `/api`, включая GET и upgrade вебсокета** — прежняя модель «читать свободно
в доверенной сети» не годится: кокпит отдаёт историю чатов, дифы, состояние фабрики, а терминал
даёт шелл. Хуки Fastify выполняются и для WS-роутов, поэтому терминал закрыт тем же гардом
(проверено: upgrade без сессии → `401`, а не `101`). Публичны только `/api/auth/{state,login,setup}`
и `/api/health`.

**401 вместо серверного редиректа — сознательно.** Фронт это PWA: редирект на навигации
конфликтует с service worker'ом (тот отдаёт закешированную оболочку вместо страницы логина).
Поэтому статика публична (секретов в ней нет), оболочка грузится всегда и сама показывает вход
по 401. Проверено: отзыв сессии на сервере → приложение само возвращается на экран входа.

**`COCKPIT_TOKEN` УБРАН, не возвращать.** Он обязан был дублироваться во фронт через
`VITE_COCKPIT_TOKEN`, а Vite подставляет env в бандл на сборке — секрет лежал в публичном JS
открытым текстом (проверено сборкой с тестовым значением: значение находится в `index-*.js`).
При открытом чтении это не защита вовсе. Заодно из терминала убран `?token=` — секрет в query
оседает в логах, cookie этого не делает.

**Грабля scrypt:** при `N=32768, r=8` требуется ровно 32 МиБ, и это же дефолтный `maxmem`
в Node → `error:030000AC ... memory limit exceeded`. Передавать `maxmem` явно (у нас 64 МиБ).

**КРИТИЧНО: гард решает по МАТЧЕННОМУ РОУТУ, а не по `request.raw.url`.** Роутер Fastify
декодирует percent-encoding ПЕРЕД сопоставлением, поэтому `/%61pi/terminal` попадает
в обработчик `/api/terminal`. Первая версия гарда сравнивала сырую строку с префиксом `/api/`
— и такой запрос проходил как «статика». Был полный обход входа: анонимно читались
`/api/chat/store` и `/api/tasks`, проходили POST-мутации, а PTY-вебсокет отдавал
`101 Switching Protocols`, то есть шелл на машину без пароля. Правильный источник истины —
`request.routeOptions.url` (шаблон вида `/api/tasks/:id/graph`): он не зависит ни от кодирования,
ни от query, ни от лишних слэшей. Строковые проверки сырого URL для авторизации НЕ использовать.

**`/shots/*` тоже под гардом** (`PROTECTED_STATIC`). Это скриншоты приёмки
тестируемого приложения — данные проектов и содержимое задач; имена предсказуемы
(`t<номер задачи>-…`). Раньше отдавались анонимно (проверено: реальный PNG приходил без сессии).
Публичной остаётся только оболочка `web/dist` — без неё не показать экран входа.

**`trustProxy` НЕ включать без реального прокси.** С ним клиент сам назначает себе
`request.ip` через `X-Forwarded-For`, и лимит попыток входа обходится сменой заголовка
на каждый запрос. TLS терминируется в самом Fastify, прокси перед кокпитом нет.

**`/api/health` не публичный:** отдаёт имя хоста и абсолютные пути (`stateDir`, `factoryHome`),
а экрану входа не нужен — тому достаточно `auth/state`.

**Внутренний токен для дочерних процессов.** `permission-prompt-tool` чата живёт в дочернем
процессе `claude`, cookie у него нет, а достучаться до сервера обязан. Для этого в `app.js`
генерируется `internalToken` (`randomUUID()` на каждый запуск, только в памяти), уезжает в env
дочернего процесса как `COCKPIT_INTERNAL` и принимается гардом в заголовке `X-Cockpit-Internal`.
На диск и в конфиг не попадает.

**`fastify.inject` изнутри сервера — тоже клиент гарда, и отказ у него МОЛЧАЛИВЫЙ.**
Хуки выполняются и для inject, поэтому внутренний вызов без `X-Cockpit-Internal`
получает `401` ровно так же, как браузер без сессии. Пока вызов читающий, отказ
неотличим от штатной пустоты: вотчер автоматического арбитра
(`listTasks` в `app.js`) ходил в `GET /api/tasks` без заголовка, получал `401`,
возвращал `[]` — и при включённой настройке `arbiter.auto` не разобрал НИ ОДНОЙ
остановки, не оставив в журнале ни строки. Диагноз при этом уводит куда угодно:
настройка включена, вид остановки подходящий, код вотчера верный. Правило: каждый
внутренний inject несёт токен (образец — `pultCallApi` рядом), а непредвиденный код
ответа пишется в журнал — пустой список не имеет права молчать. Сторож —
`tests/server/app-internal-inject.contract.test.js` (статический: динамически такое
ловится только полным подъёмом сервера с живой фабрикой).

**Смена пароля сбрасывает все сессии** (украденная cookie перестаёт работать), но текущему
устройству сразу выдаётся новая — иначе владелец выкинул бы сам себя. `setup` доступен ровно
пока пароль не задан: потом только `409`, чтобы никто не переустановил пароль в обход.

**Поллинги надо гасить при потере сессии** (`stopPolling` у board/system, зовётся из `App.vue`):
иначе интервалы молотят в закрытый API и сыпят 401 в консоль на экране входа (было 14 ошибок).

**Действие обновления PWA обязано оставаться доступным ВНЕ ветки авторизации.** В рабочей
оболочке `features/pwa/UpdateBanner.vue` встроен в топбар `AppShell`, а `App.vue` монтирует тот же
компонент отдельной верхней полосой, пока пользователь не вошёл. Иначе service worker держит
старую сборку, пользователь на экране входа, а кнопки «Обновить» нет — залипшая версия не
лечится из интерфейса. Само обновление авторизации не требует (работает с SW, `sw.js` — публичная
статика). Проверено полным циклом: новая сборка → `reg.update()` → действие появилось НА ЭКРАНЕ
ВХОДА → клик → версия применилась.

**Связка с TLS:** по http пароль уходит открытым текстом, поэтому для доступа вне localhost TLS
обязателен, и от него же зависит флаг `Secure` у cookie (на http его ставить нельзя — браузер
выбросит cookie и вход сломается молча). Экран входа честно предупреждает, когда TLS выключен.
