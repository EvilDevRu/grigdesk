# Доступ с других устройств снят: кокпит слушает только loopback

Из исходников удалены собственный HTTPS/CA и встроенный VPS-шлюз. После ручного
перезапуска сервер использует один HTTP-сокет `127.0.0.1:<COCKPIT_PORT>` (8140 по
умолчанию). Интерфейс отдаёт этот же сервер; стенды открываются прямыми портами машины.
Контракт запуска, авторизации и настроек — [локальный доступ](loopback-access.md).

`ss -ltn` подтверждает адрес прослушивания, но не отсутствие внешнего перенаправления:
установленный отдельно SSH-туннель или обратный прокси способен переслать запрос на
loopback. До подтверждения владельцем новой версии и очистки машины нельзя считать
старый живой доступ отключённым. Новый bind проверяет
`tests/server/app-boot-smoke.test.js`, конфигурацию и вход —
`tests/server/loopback-only.test.mts`.

Старый доступ снят по решению владельца. VPS расшифровывал трафик и сам отдавал код
страницы; страница входа и оболочка за ней были открыты интернету. Домашний HTTPS
требовал доверия к собственному CA на уровне ОС. Удалённые оповещения и действия
продолжает обслуживать Telegram-пульт.

## История обсуждения

Прежняя схема публиковала каждый порт стенда отдельным поддоменом и делила cookie
между поддоменами. Публичная ссылка с одним хостом ограничивала такую топологию.
Собственный CA требовал установки корня на каждом устройстве; дополнительный
VPN-клиент конфликтовал с занятым VPN-слотом мобильной ОС. Внешние туннели, включая
Cloudflare Tunnel, обсуждались с учётом посредника, расшифровки и ограничений передачи.
Это история прежних вариантов, а не инструкции или актуальные гарантии сервисов.

Старое возражение о POST чата на весь ход больше не описывает текущий транспорт:
[приём по turnId](../chat/concurrent-send-transport.md) освобождает HTTP-соединение
сразу после принятия хода. Новый удалённый доступ проектируется отдельно.
