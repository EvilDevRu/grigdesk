# MCP-серверы исполнителя — блок в той же плашке

## MCP-серверы в карточках исполнителей

- В разделе «Настройки → Исполнители» список MCP находится в раскрываемой панели
  установленного исполнителя с MCP capability. У остальных пустого блока нет.
- Секция занимает высоту по содержимому; длинный список прокручивается в пределах
  360 px. Сводки и раскладка описаны в
  [контракте гармошки](../web/executor-settings-accordion.md).
- Список загружается отдельным запросом `GET /api/providers/:id/mcp`. Результат кэшируется
  на 60 секунд; кнопка «Обновить» обходит кэш. Модельная авторизация исполнителя не нужна
  для чтения списка: достаточно, чтобы CLI был установлен.
- Общие состояния в интерфейсе:
  - `ok` — «Подключён», живое соединение подтверждено CLI;
  - `failed` — «Не подключился»;
  - `needs-auth` — «Нужна авторизация»;
  - `configured` — «Настроен», конфигурация найдена, но соединение не проверялось;
  - `disabled` — «Выключен»;
  - `remote` — аккаунтный коннектор, живость которого локально не проверяется;
  - `unknown` — состояние неизвестно.
- Адаптер исполнителя может передать свои названия разделов и подсказки. Поэтому команды
  авторизации Claude, Codex и Kimi не зашиты во Vue-компонент.
- Необязательное `emptyText` адаптера задаёт подпись пустого списка; без него остаётся
  «Серверов не настроено.». Исполнитель без `mcpStatus` не получает пустой блок.

### Claude

- Живое состояние берётся из `claude mcp list`.
- Пользовательские и проектные определения дополняются данными из `~/.claude.json`,
  проектного `.mcp.json` и кэша `mcp-needs-auth-cache.json`.
- Аккаунтные коннекторы показываются отдельным разделом `claude.ai`.

### Codex

- Живое состояние берётся из метода app-server `mcpServerStatus/list`.
- `codex mcp list --json` добавляет команду или URL и служит запасным источником, если
  живой метод недоступен. В таком случае сервер показывается как «Настроен», а не как
  «Подключён».
- Таблицы инструментов, переменные окружения и HTTP-заголовки в API Cockpit не передаются.
  Данные авторизации в аргументах команды и query-параметрах URL скрываются.

### Kimi

- Публичный ACP Kimi 0.31.x не умеет перечислить MCP без создания сессии. Создавать
  временную сессию для страницы настроек нельзя: она запустила бы настроенные stdio-процессы.
- В host-режиме Cockpit безопасно читает и объединяет конфигурацию Kimi в порядке её
  приоритета: `<KIMI_CODE_HOME>/mcp.json`, legacy-файл `<корень-git>/.mcp.json`, затем
  `<рабочий-каталог>/.kimi-code/mcp.json`.
- Записи Kimi показываются как «Настроен» или «Выключен»; живость проверяется самим Kimi
  при создании новой сессии.
- MCP-серверы из плагинов Kimi этот файловый список пока не обещает показывать.
- В contained-режиме пользовательские и проектные MCP намеренно изолированы. Карточка
  показывает пояснение и пустой список, а внутренний `cockpit-work` пользователю не выводится.

### DeepSeek

- Тот же reader, что обслуживает чатовый запуск, читает `.mcp.json` у ближайшего корня
  Git и в явно заданной абсолютной папке кокпита (`config.rootDir`). В другой папке чата
  список может отличаться; область названа в панели, в том числе при пустом результате.
- В список входят только выбранные для запуска stdio-серверы с найденной executable-командой.
  Выключенные записи и служебные `cockpit-work`/`cockpit-perm` не показываются.
- Имена показываются как «Настроен», серым индикатором. Страница не запускает CLI/MCP,
  не создаёт сессии и не проверяет соединение. Команда, args, env, пути и raw warnings
  не передаются браузеру; имя остаётся публичным ключом конфигурации.
- Хорошие записи при warnings сохраняются с нейтральным пояснением неполноты.
  Warnings без серверов, исключение или незаданная абсолютная папка дают фиксированную
  ошибку, а отсутствие файлов или только выключенные записи — успешный пустой список.
- «Обновить» использует существующий refresh и кэш 60 секунд; модельный API-ключ
  для чтения списка не нужен. Детали и проверки —
  [безопасный список MCP DeepSeek](deepseek-mcp-status.md).

Отдельной кнопки «переподключить» нет: жизненным циклом MCP-процессов владеет сессия CLI.
Кнопка «Обновить» только заново получает диагностику или перечитывает конфигурацию.

## Настройка Claude fastMode

`claude.fastMode` («Ускоренный вывод») хранится в настройках исполнителя. Каждый
headless-запуск получает явное значение через `--settings {"fastMode":…}`; доступность
режима и списание usage credits проверяет установленный Claude CLI.

Источник до переноса: `docs/cockpit/chat-agents.md`, запись «MCP-серверы исполнителя — блок в той же плашке».
