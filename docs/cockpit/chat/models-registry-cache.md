# Реестр моделей: устаревший отдаётся сразу, пересборка одна и в фоне

`getModelsRegistry()` в `server/src/lib/modelsRegistry.ts` читают сохранение истории
чата, приём хода, триаж и конвейер. Пересборка реестра опрашивает всех исполнителей:
`probe()` запускает их CLI и вместе занимает секунды, на нагруженной машине — больше.
Пока кэш реестра на минуту ждал пересборку синхронно, первое сохранение чата после
минуты тишины держало отправку сообщения на это время, а параллельные сохранения
запускали каждое свою пересборку.

## Контракт

- Кэш — по абсолютному пути файла реестра. Свежий (моложе `CACHE_MS` = 60 с) отдаётся
  из памяти.
- Устаревший отдаётся сразу, и запускается фоновая пересборка. Пока она идёт, другие
  вызовы получают тот же прежний реестр и новую не запускают.
- Без готового реестра (первый вызов после старта) вызов ждёт сборку; параллельные
  вызовы ждут ту же сборку. Её сбой получают все ждавшие, следующий вызов пробует снова.
- Сборки одного файла идут строго по очереди. `refresh: true` ставит свою сборку в конец
  очереди и ждёт её, поэтому поздняя фоновая сборка не затирает результат `refresh`.
- Сбой фоновой пересборки оставляет прежний реестр; следующая попытка — не раньше чем
  через `CACHE_MS`. Ошибку увидит только явный `refresh`.
- Свой кэш карточек `GET /api/providers` (probe и авторизация каждого исполнителя) этим
  контрактом не покрыт.

Проверки — `tests/server/models-registry-cache.test.js`: время подменяется через
`t.mock.timers` только для `Date`, сборка ставится на паузу внутри `discoverModels`
синтетического исполнителя.
