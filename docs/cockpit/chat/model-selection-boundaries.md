# Границы сборки каталога и переключения модели

Сверено по исходникам и синтетическим проверкам 30.09.2026.
Общий контракт сохранённых данных — в [границах снятия адаптера](executor-removal-boundaries.md).

`server/src/lib/modelsRegistry.ts`, `getModelsRegistry()`, обновляет сохранённый каталог
и отбирает зарегистрированных исполнителей. Только после этой проверки
`resolveRuntimeModels()` готовит копии моделей для runtime: получает общий список усилий
один раз на исполнителя, уточняет семейство и доступные ступени, сортирует по tier.
Справочные поля и custom-записи сохраняются; подготовка runtime-копий не пишет файл.
Отбор по регистрации не вызывает probe/auth и не зависит от доступности исполнителя.

В `web/src/views/chat/ChatSession.vue` проверка `requiresContextReset()` отделена от
действия `onModelChange()`. Она сравнивает прежнего исполнителя из реестра либо
сохранённой пары с новым. Сброс нужен при смене исполнителя, если есть sessionId,
объявлен sessionBinding либо прежний адаптер отсутствует у сохранённого чата.
Последний случай учитывает seed без видимого sessionId.

`onModelChange()` снимает выбранный id с DOM до ожидания, подтверждает reset и лишь
затем меняет модель. Отказ возвращает селект к прежнему значению. Проверку необходимости
reset нельзя заменять проверкой доступности: зарегистрированный, но временно недоступный
исполнитель продолжает владеть своей памятью.

Регрессии закреплены в `tests/server/models-registry.test.js`,
`tests/web/chat-model-availability.component.test.js` и `tests/web/chat-model-ref.test.js`.
Фикстуры пишут синтетическую историю и подменяют реестр отдельно от проверок:
schema-2 чат не проходит через предварительный save, а web-стор получает отсутствие
адаптера после своей обычной инициализации. Чтение реальных пользовательских данных
для этих проверок не требуется.
