# Локальная картинка в ответе агента

Markdown-картинка с абсолютным путём на диске не публикует файл. В полном чате
`ChatSession.vue` задаёт только `resolveHref` для обычных ссылок, а `shared/md.ts`
оставляет адрес картинки без преобразования. Браузер воспринимает `/home/…/frame.png`
как HTTP-путь на сервере кокпита; это не доступ к файловой системе машины.

Чтобы показать готовое изображение в ответе, загрузи его через существующий
`POST /api/chat/upload` (multipart, поле `file`) и используй возвращённый `url`:

```markdown
![Подпись кадра](/api/chat/attachment/<имя-из-ответа-upload>)
```

Загрузка и чтение вложения находятся за общим auth guard. Локальный исполнитель
использует [штатную авторизацию CLI](../server/authentication-and-cli-token.md),
браузер — свою сессию; секреты в Markdown не попадают. Загрузка создаёт копию
изображения, исходный файл проекта остаётся на месте. Перезапуск и сборка не нужны.

Перед отправкой проверь `GET` возвращённого URL: статус 200, нужный MIME и совпадение
SHA-256 с исходником. Затем проверь, что `mdToHtml` сохраняет этот URL в `img.src`.
Такой путь проверен на четырёх PNG; состояние пользовательского окна эта проверка
не подтверждает. Картинки из результата vision-инструмента сами по себе не заменяют
ссылки на вложения в итоговом ответе.

Связанный контракт: [вложения и диктовка](attachments-and-dictation.md).
