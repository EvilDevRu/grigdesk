# GLM и DeepSeek: безымянные действия, «вытеснено из ленты» и обрывки ответа

Симптом в живой ленте GLM и DeepSeek: строка действия без имени — только «•» и «…»;
ниже такие же безымянные «Итог · действие вытеснено из ленты ✓»; перед промежуточной
репликой стоит её первый фрагмент («Пр», «Д»); строка состояния весь ход пишет
«Работаю с инструментом».

Причина — web-поток DSH (`session/follow`) переводился в шаги ленты в `serverTurn.ts`
в обход словаря инструментов `steps.ts`, по которому работает ACP-поток:

- `tool/call` давал шаг с полями `tool`, `kind` и `text`. Лента, мобильный фасад,
  Telegram и выжимка остановленного хода читают `name` и `title`.
- Итог брал id и исход из `message.toolCallId` и `message.isError`. У настоящего
  `tool/result` этих полей нет: `ToolResultMessage` несёт id вызова в `source.callId`
  и в единственном блоке `tool-result` (`toolCallId`), а `isError` — в этом блоке.
  Итог получал пустой id и не находил свой вызов, поэтому вызов считался незакрытым, а
  ошибка инструмента рисовалась успехом. Текстом итога был JSON-дамп блоков.
- Шаг текста получал сырой id блока `<attemptId>-<index>`, а реплика — `storageMessageId()`
  от него: attemptId DSH имеет вид `<сессия>:<номер>`, и двоеточие хранилище не принимает.
  Окно не узнавало в шаге показанную реплику и рисовало его отдельно. В SSE шаг уходит
  один раз, с первой дельтой, поэтому был виден обрывок.

Тестовый фейк DSH повторял неверную форму `tool/result`, поэтому тесты проходили.

Теперь оба потока DSH собирают строку действия через `deepSeekToolStep`: `bash`, `read`,
`write`, `edit`, `grep` и `glob` становятся Bash, Read, Write, Edit, Grep и Glob с заголовком,
командой или диффом; у MCP и прочих инструментов заголовок — аргументы, а не повтор имени.
`deepSeekToolResultStep` берёт id из `source.callId` или блока, исход и текст — из блока,
картинку заменяет общей заглушкой `STEP_IMAGE_TEXT`. Шаг текста несёт `storageMessageId`.
Фейк и встроенные фикстуры отдают форму настоящего DSH.

Проверка: `tests/server/deepseek-server-thoughts.test.js` — пара вызова и итога из событий
настоящей формы, исход ошибки и общий id шага текста и реплики; `tests/server/glm-runtime.test.js`
— то же через адаптер GLM и фейковый процесс DSH; `tests/server/deepseek-steps.test.js` —
заголовки MCP и прочих инструментов.

Исправление действует после ручного перезапуска Cockpit и только для новых ходов.
Сохранённые шаги прежних ходов не переписываются: безымянные строки в них остаются.
