# Типы исполнителей и Tripo

Тип исполнителя отделяет карточку сервиса от допуска к чату. Общий список,
нормализация, порядок групп и правило топбара лежат в `shared/chat/executorTypes.ts`:
`universal` — «Универсальные», `3d` — «3D-генерация». Отсутствующий, пустой или
неизвестный тип считается универсальным; пробелы вокруг известного типа обрезаются.

`getProviderAdapters()` содержит все карточки. `getExecutors()` допускает только
адаптеры с `run` и универсальным типом — тот же `isChatExecutor` используется в
`/api/providers.chatEnabled`, `executorFor` и возможностях scoped workspace и
недоверенного ввода. Универсальная setup-only карточка сохраняет объявленные команды
и режимы в настройках, оставаясь вне runtime-реестра. Узкий адаптер
даже с ошибочно объявленным `run` не получает моделей в карточке, runtime-реестре
и `providerRegistry`. Сохранённые custom-модели исключённого исполнителя не входят
в результат `modelsRegistry`.

## Настройки и топбар

Настройки содержат все карточки, сгруппированные по типам. Пустые группы пропускаются;
при единственной группе заголовка нет. Порядок реестра внутри группы сохранён.
Общая [гармошка](../web/executor-settings-accordion.md) раскрывает одного исполнителя
на обе группы; скрытые через `v-show` панели сохраняют введённые значения.

Универсальная иконка видна при `chatEnabled !== false`, включая недоступный CLI.
Узкая иконка видна только при `available === true`. У Tripo это наличие непустого
ключа, а не доказательство принятой авторизации. Ошибка ключа и нулевой баланс
сохраняют иконку и видимую причину. API-карточка не обещает установку CLI или будущий чат.

## Tripo: чтение счёта

`server/src/lib/executors/tripo.ts` объявляет `type: '3d'`, `kind: 'api'` и
ключи `TRIPO_API_KEY` / `TRIPO_REGION`. Первый регион, `ov`, международный;
`cn` — Китай. Чтение неизвестного региона совместимо с `ov`, запись choice
принимает только объявленные варианты. Окружение читается при вызове, а одна
проверка фиксирует согласованную пару ключа и региона до первого ожидания.

Адаптер не имеет `run`, LLM-каталога, MCP или установки. Его capability `studio3d`
объявляет действия, расчёт и заказы для отдельного [раздела 3D](../plugins/studio3d-providers.md),
сохраняя прежний чатовый допуск.
`server/src/lib/tripo/account.ts` выполняет только `GET /v3/account/balance`
с Bearer-авторизацией, без редиректов. Без ключа возвращает `auth_required` без сети.

| Регион | API | Ссылка «Пополнить» |
|---|---|---|
| `ov` | `https://openapi.tripo3d.ai` | `https://developers.tripo3d.ai/billing` |
| `cn` | `https://openapi.tripo3d.com` | `https://developers.tripo3d.com/billing/recharge` |

Успех требует объектов envelope/data, числового `code === 0`, конечных чисел
`balance` и `frozen`. Строки и отсутствующие поля не приводятся к нулю.
Отрицательный баланс допустим, отрицательный резерв — некорректный ответ.
Баланс уже доступен: резерв не вычитается повторно. Результат — текстовый ресурс
«Кредиты» с резервом, если он положительный, и ссылкой своего региона. Числа
показываются до сотых; склонение зависит от показанного значения. Баланс ≤ 0
подсвечивается. Денежным ресурсом этот остаток не считается.

HTTP 401 означает отказ авторизации; 403 предлагает проверить ключ, права и регион;
429 означает временное ограничение. Их состояние не зависит от body. Прочие
non-2xx, включая редирект и 5xx, дают `unavailable`. Для 2xx коды 1000/1001
означают авторизацию, 1007/2000 — ограничение; 1002/1005 поддерживаются как
совместимый нейтральный отказ доступа. Ошибки JSON/схемы дают `unavailable`.

Попытка ограничена восемью секундами вместе с body, вся проверка — 25 секундами.
Сетевой срыв или таймаут повторяется до трёх попыток с паузами 250/500 мс;
HTTP/API-отказ и повреждённый JSON внутри вызова не повторяются. Будущий
`Retry-After` либо `X-RateLimit-Reset` продлевает общую персональную паузу providers,
если он длиннее собственной шкалы. Сырые сообщения, заголовки, request id и
исключения не публикуются и не журналируются; используются локальные русские строки.

## Смена аккаунта

Успешная [запись credentials](executor-credentials.md) синхронно инвалидирует
реестр и usage, снимает backoff только изменённого исполнителя и сразу рассылает
`providers-update` с `credentials: id`. Каталог моделей обновляется в фоне;
ошибка проверки после commit не отменяет сохранение ключа.

Общий `createUsageReadCache` отделяет поколения снимков: старый успех или отказ
присоединяется к чтению актуального поколения. Loader проверяет актуальность до
изменения backoff/seen и кэша, читатели — перед публикацией HTTP/SSE. Конкурентные
читатели разделяют одну загрузку. Соседние аккаунты сохраняют previous и паузы
после очистки общего кэша; прежние ресурсы изменённого аккаунта не merge-ятся.

Стор окна после ACK или credentials-события убирает его usage, инвалидирует летящие
GET реестра и лимитов и перечитывает оба снимка без минутного throttle. ACK не
присваивает credentials карточке; поздний ACK запускает чтение текущего состояния.
Во время проверки прежний баланс и ссылка региона отсутствуют. Reconnect общего
SSE перечитывает снимки; отключённой вкладке мгновенная синхронизация не обещается.
Внутренние поколения сервера не сохраняются и не сравниваются между перезапусками.

Имена переменных совместимы с Tripo CLI, но Cockpit не читает его конфиг и не
устанавливает CLI. Новый ключ не передаётся автоматически уже живым дочерним
процессам; отдельные runtime дополнительно фильтруют окружение.

## Источники и проверка

Контракт подтверждён публичными страницами
[Account v3](https://developers.tripo3d.ai/en/docs/account),
[Error Handling](https://developers.tripo3d.ai/en/docs/error-handling),
[Rate Limits](https://developers.tripo3d.ai/en/docs/rate-limits),
[официальным plugin](https://github.com/VAST-AI-Research/Tripo3D-Plugin-dsh) и
[китайским порталом](https://developers.tripo3d.com/).
Два документа расходятся в деталях кодов ограничения, поэтому HTTP имеет приоритет.
Оба региона проверяются офлайн-фикстурами v3; живой аккаунт и переход после входа
по ссылке пополнения требуют отдельной ручной проверки.

Знак из [Lobe Icons](https://github.com/lobehub/lobe-icons) использует `currentColor`;
исходный путь, revision и полный MIT notice лежат в
`web/public/third-party-notices.txt` и копируются стандартной сборкой в web/dist.

Проверки: `executor-types.test.js`, `tripo-provider.test.js`, тесты общего usage
и credentials на сервере; `executor-types.component.test.js`, проверки иконок,
credentials и `providers-model-ref.test.js` в окне. Новый web со старым server
сохраняет прежние универсальные карточки; старый web не гарантирует новый UX
и очистку снимков после смены credentials.


Capability `studio3d` описывает операции, поля/наборы, нормализацию, quote, account snapshot,
submit/poll/history и происхождение файлов/native. Реестр раздела использует только
адаптеры с `type: '3d'` и этой capability, затем добавляет «Локально». Общие Vue формы
не ветвятся по вендору. [Контракт раздела](../guide/studio3d.md) и
[Tripo API v3](../plugins/tripo-api.md) описывают оплату и восстановление отдельно от чата.
