# Ollama — локальный HTTP-исполнитель

- **Ollama — локальный HTTP-исполнитель** (`executors/ollama.js` + `_ollama-client.js`
  + `_ollama-tools.js`): полноценный агентский ход — инструменты, режимы прав, эффорт,
  картинки, — но всё это даёт САМ КОКПИТ. Демон приносит только модель: он не ходит по
  файлам, не спрашивает разрешений и не держит сессию. Слэш-команд и обновления CLI нет
  (`commands`/`updateCmd` не объявлены). Транспорт — HTTP API демона: probe/auth →
  `GET /api/version`; каталог (живой, `catalogLive`) → `GET /api/tags`, окно контекста
  каждой модели — из `POST /api/show` (первый ключ `model_info` на `.context_length`,
  кэш по digest модели; не узнали → 32768), tier — число миллиардов параметров из
  `parameter_size`; ход → `POST /api/chat` со стримом NDJSON (`thinking` → think-шаги
  ленты, `content` → text-шаг раунда, финальный чанк отдаёт
  `prompt_eval_count`/`eval_count` → `contextTokens`, `contextWindow` = num_ctx). Демон
  недоступен → каталог возвращает `null` (реестр оставляет прошлый список), ход падает
  с понятным «демон Ollama не отвечает на <host>».
  - **Что модель умеет, решает она сама** — `capabilities` из того же `/api/tags`
    (старый демон их там не кладёт → добираем из `/api/show`, кэш общий): `tools` включает
    инструменты, `vision` — вложения-картинки, `thinking` — эффорт. Хардкода возможностей
    нет: новая модель включает их фактом своей поддержки. **Эффорт объявлен БИНАРНЫМ**
    (`efforts: ['low','high']` → `think: true|false`): замер показал, что `think:
    "low"|"medium"|"high"` демон принимает без ошибки, но длина рассуждения от уровня не
    зависит — три уровня были бы враньём слайдера. **Эффорт не выбран — поле `think` не
    шлём вовсе**: у думающей модели дефолт демона — думать, и подставленный `false` молча
    отнял бы у неё рассуждения.
  - **Инструменты исполняет кокпит** (`_ollama-tools.js`): `read_file`, `list_dir`, `grep`,
    `write_file`, `edit_file`, `bash` — объявляются полем `tools` запроса, модель возвращает
    `tool_calls`, цикл «ответ → выполнить → снова запрос» крутится в `run()` до ответа без
    вызовов (`MAX_TOOL_CALLS = 40` сейчас — post-batch soft threshold: весь уже объявленный
    batch выполняется, затем инструменты снимаются и модель просят подвести итог). Это не
    hard cap: oversized batch способен пересечь 40. Результат инструмента режется до
    4000 символов: он уезжает обратно в контекст, а окно локальной модели мало.
  - **Песочница путей — `realpath` внутрь cwd хода или дополнительного корня проекта/задачи**
    («Настройки → Исполнители»); симлинк наружу отсекается именно резолвом, а для записи
    в ещё не созданный файл резолвится глубочайший существующий предок. Выход за границу —
    отказ ИНСТРУМЕНТУ (модель читает его и исправляется), а не падение хода.
    **У `bash` границы путей нет** — оболочка дотянется куда угодно; это осознанно (сборка
    и тесты), держится он подтверждением человека и общим fail-closed классификатором.
  - **Режимы прав** — свои (`modes()` → `toolModes()`, спрашивать о них некого): `plan`
    (только чтение), `manual` (подтверждение на каждую правку и команду), `auto`
    (классификатор), `acceptEdits` (правки молча, команды спрашивают), `dontAsk`. Мост
    всплывашки общий — тот же `direct`-путь, что у Kimi (см. [разрешения инструментов](work-tools.md)).
  - **Правила проекта в системном блоке**: перед первым сообщением читаются `AGENTS.md`
    и `CLAUDE.md` рабочего каталога — и ТОЛЬКО они (по 24k символов каждый). Их
    `@`-включения намеренно не раскрываются: весь `docs/` проекта — около 75k токенов,
    то есть порядка двух минут префилла на КАЖДЫЙ ход (замер). Нужный документ модель
    дочитает `read_file` сама, о чём в системном блоке сказано прямо.
  - **Свои настройки из UI** (prefs `providerSettings.ollama`): `host` — адрес демона
    (у всех разный: localhost, локальная сеть, машина за VPN; машинный override — env
    `COCKPIT_OLLAMA_HOST`); `numCtx` — размер контекста (дефолт 32768: собственный дефолт
    Ollama 2048–4096 для разговора ничтожен); `keepAliveMin` — сколько держать модель
    в памяти после хода (дефолт 5, `0` — выгружать сразу; уезжает полем `keep_alive`).
    Плюс три строки-справки `kind: 'info'` (своего контрола нет, фронт рисует подписью
    с пояснением): память машины, что сейчас загружено в демон, и **во что обходится
    выбранный num_ctx в гигабайтах** — вся арифметика была и раньше, её просто никогда
    не показывали человеку. `info` в prefs не пишется (`readonly_setting`): значение
    вычисляется заново каждый раз.
  - **Потолок `numCtx`** `settings(config)` вычисляет async от железа: бюджет KV-кэша =
    свободная VRAM (nvidia-smi, кэш 5 мин) + 60% свободной ОЗУ − веса модели из
    `/api/tags`, делённый на оценку байт/токен из `model_info`
    (`block_count × kv_heads × (key+value) × 2`; `head_count_kv: null` → GQA-эвристика
    `ceil(head_count/4)`), кламп в [2048, context_length] с округлением до 1024; демон
    молчит → 131072. **Уже загруженная модель прибавляется обратно в бюджет**
    (`/api/ps`): её веса и так вычтены из свободной памяти, и без этого оценка уходила
    в минус — см. [грабли](ollama-memory-accounting.md). Та же оценка едет в записях каталога
    (`maxNumCtx`), а `run()` клампит num_ctx по per-model потолку выбранной модели.
    `MIN_AGENT_NUM_CTX = 8192` — floor только при ужатии **большего** requested значения:
    явно сохранённые 512/2048/4096 не повышаются до 8192. При обрезке — шаг `note` и
    `contextWindow` = фактический num_ctx. Это характеристика текущего чата, а не
    политика контекста конвейера.
  - **Всплывашка исполнителя в шапке** (`usage()`): подписочных лимитов у локального
    демона нет и не будет, поэтому показываем локальную реальность — полосы занятости
    видеопамяти и ОЗУ, состояние демона (версия + адрес) и ресурс на каждую загруженную
    модель из `/api/ps`: сколько её в VRAM против ОЗУ, фактическое окно контекста, через
    сколько выгрузится, и кнопка «Выгрузить из памяти» (`usageActions['unload-model']` →
    `keep_alive: 0`). Это же мгновенно объясняет, почему первый ход после перерыва долгий.
    Имя модели в ключ ресурса не годится (`qwen3.6:latest` не проходит `[a-z0-9_-]`) —
    ключи `loaded-<N>`, имя живёт в подписи.
  - Демон stateless → историю разговора executor реплеит из server-owned истории чата
    (`opts.chatHistory`; note/error пропускаются, хвостовой дубликат текущего сообщения
    срезается по суффиксу — клиент сохранил его до POST). Сброс памяти и сжатие-выжимкой
    обнуляют sessionId → история не реплеится. Сессия синтетическая `ollama:<chatKey>` —
    кольцо контекста и кнопка сжатия работают штатно (compaction по умолчанию `summary`).
    Рассуждение обратно в контекст не возвращается (моделям qwen это прямо не
    рекомендовано, а места в локальном окне занимает много).
  - **Ограничение осталось одно:** сверх num_ctx Ollama молча обрезает начало разговора —
    следи за кольцом контекста и жми сжатие.
  - **Узлы схем конвейера Ollama не исполняет, и одной настройкой это не включается.**
    Раннеры движка — bash-адаптеры (`engine/lib/runners/*.sh`), они ожидают агентский CLI:
    сессии, структурированный вывод, status-запросы, объявление возможностей. У Ollama
    такого CLI нет (`ollama run` — голый REPL). Реальный путь — тонкая CLI-обёртка над тем
    же циклом инструментов плюс свой раннер; после этой работы она стала дешевле, потому
    что цикл уже написан.
