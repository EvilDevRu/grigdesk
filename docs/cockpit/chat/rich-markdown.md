# Оформление ответа агента: код, схемы, дифф, плашки и картинки

В полном ответе и в реплике внутри хода используется общий `RichMarkdown`.

- Код подсвечивается по языку. При наведении или фокусе доступны подпись языка и
  «Копировать код»: копируется исходник с пробелами и переводами строк. На сенсорном
  экране кнопки видны постоянно. Блок длиннее 24 строк свёрнут до 320 px и раскрывается.
- Закрытый блок `mermaid` становится схемой. «Показать код» открывает исходник,
  «Показать схему» возвращает уже готовую картинку. Ошибка оставляет код и пояснение.
- `diff` и `patch` выделяют добавленные и удалённые строки и заголовки диапазонов;
  строки метаданных `+++`/`---` не считаются добавлением/удалением.
- Цитата с отдельной первой строкой `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`
  или `[!CAUTION]` получает русскую подпись и цветную полосу. Регистр не важен;
  маркер с текстом в той же строке остаётся обычной цитатой.
- PNG/JPEG/GIF/WebP по пути в рабочей области показываются прямо в ответе. Клик
  по картинке или схеме открывает существующий просмотрщик документов.
- Пока агент печатает незакрытый блок, виден простой код. Дописывание хвоста сохраняет
  готовые блоки, их раскрытие и переключение схемы на исходник.
- Недоступное или повреждённое изображение заменяется подписью. HTML в подписи
  остаётся текстом; повторной бесконечной загрузки нет.

## Разбор и загрузка

`shared/md.ts` разделяет `lexMarkdown` и `mdTokensToHtml`; прежний `mdToHtml`
комбинирует их. Один lexer разбирает весь ответ, включая reference definitions.
`markdown/segments.ts` отделяет только ограждённые блоки верхнего уровня. Ключи
состоят из позиции и вида куска; реактивные резолверы ссылок обновляют HTML без
повторного lexer для неизменённого текста. При дописывании весь текущий ответ
разбирается заново, готовые fence-компоненты с прежними props сохраняются.

Отступной код и блоки внутри списков/цитат остаются обычными `<pre>`. За пределами
чата `mdToHtml` также добавляет заголовки плашек, но новые цвета принадлежат
`RichMarkdown`. Raw HTML, URL и классы проходят прежний строгий sanitizer;
плашкам разрешены только фиксированные классы на `blockquote` и заголовке.

Подсветчик `codeHighlight.ts` лениво загружает ядро Shiki, JavaScript regex engine
и одну из 21 фиксированных грамматик. Неизвестный язык, код длиннее 20 000 символов
и ошибка загрузки оставляют простой код. Цвета задаёт палитра `--md-code-*` в
`tokens.css`, включая `--md-code-token-keyword`, `-string`, `-comment` и `-function`.
Результат — текстовые токены со стилями; HTML от библиотеки не вставляется.

Закреплены `shiki@4.5.0` (Node ≥20) и `mermaid@12.1.0` (Node ≥22.12).
Shiki предоставляет `createHighlighterCore` и `createCssVariablesTheme` из
`shiki/core`, `createJavaScriptRegexEngine` из `shiki/engine/javascript` и
грамматики `shiki/langs/*.mjs`. `marked@14` сохраняет reference-ссылки при
передаче уже разобранных токенов parser-у.

## Граница Mermaid

Mermaid работает в отдельном IIFE asset, собранном `buildMarkdownRenderer.mjs`
перед `dev` и `build`. Главная страница импортирует только клиент очереди. Сам asset получает родитель
через `fetch` без cookies, поэтому его может отдать precache Service Worker.
Доверенный текст bundle вставляется в srcdoc через script с nonce; `<` в JSON
экранируется, чтобы строки bundle не закрыли HTML script. Готовый исходник asset сохраняется
на время жизни клиента. Nonce получает 128 случайных бит через `getRandomValues`,
доступный и в обычном HTTP-контексте. Отмена и таймаут прерывают незавершённый fetch; следующий
запрос начинает новую загрузку, а поздний результат прежней игнорируется.
Скрытый iframe имеет `sandbox="allow-scripts"` без `allow-same-origin`; CSP
разрешает доверенный renderer script по случайному nonce, inline стили и data-картинки. Сетевые
изображения, шрифты, connect и прочие внешние ресурсы запрещены. Opaque origin
не имеет доступа к DOM, storage и cookies родителя. Frame скрыт через visibility,
сохраняя layout для SVG; синхронные измерения внутри библиотеки остаются.

Вход ограничен 50 000 символами и 300 рёбрами. Frontmatter и `%%{…}%%` directives
отвергаются. `securityLevel: strict`, HTML labels выключены; защищённые настройки
берутся из стандартного secure-списка библиотеки и расширены темой, config и
параметрами HTML. Для задания родитель передаёт только исходник и allowlist цветов в hex.
Палитра задаёт явно и цвета, которые Mermaid иначе вывел бы из тёмного `primaryColor`.
Доли круговой диаграммы (`pie1…pie6`) берутся из акцентов кокпита, иначе доли и легенда
сливаются. Строки атрибутов ER (`rowOdd`/`rowEven`) берутся из фонов карточек: иначе первая
строка получает светлый фон под светлым текстом. Диаграмма Ганта рисуется шириной 720 px
с осью `%d.%m`: на ширине iframe (1200 px) в колонке чата подписи нечитаемы, а полные даты
налезают друг на друга. Вид `journey` использует `foreignObject` и показывается кодом.
Обработчики
клика Mermaid не подключаются: текст схемы в картинке не выделяется, исходник
доступен через «Показать код».

Протокол принимает сообщения только своего iframe с текущим requestId.
Одновременно выполняется один запрос, ожидают не более 32; лишний получает
fallback. Таймаут 15 секунд и отмена активного запроса удаляют iframe; следующий
запрос создаёт новый. Ожидающий отменённый запрос удаляется из очереди.
Перед созданием frame общий renderer ждёт кадр родителя, затем запускает таймаут.
Пустой результат до 16×16 px пересоздаёт frame и повторяет задание один раз;
подробности — [измерение схем](mermaid-layout.md).

Ответ SVG ограничен 2 млн символов и повторно проверяется родителем: запрещены
script, foreignObject, внешние href/resources, обработчики событий, анимации и
опасные CSS. Размер — до 4096 px по стороне и 4 млн px площади при 1×. SVG
получает естественный размер 2×, а `<img>` в чате — размеры 1×: линии резкие,
схема не растягивается. Service Worker precache скачивает renderer и языковые
чанки при установке/обновлении; без SW они загружаются по необходимости. После
готовности precache новые схемы и новые языки работают offline, в том числе
в свежей странице после обновления SW. Файловый API требует доступного сервера.

## Добавление нового вида

1. Добавить значение `FenceKind` и строку в `FENCE_KINDS` в `segments.ts`.
2. Создать `Fence<Вид>.vue` с `code` и `closed`. Чистую тяжёлую библиотеку грузить
   через подменяемый lazy loader; библиотеку, создающую DOM или загружающую ресурсы
   из недоверенного текста, помещать в изолированный renderer asset.
3. Добавить ветку в `RichMarkdown.vue` и стили там же.
4. При отказе показывать исходник через `FenceCode`.

## Проверки

`tests/web/helpers/compile-vue.js` объявляет Mermaid и Shiki в `LAZY_EXTERNALS`:
компонентные тесты не бандлят тяжёлые библиотеки заново. Loader-ы подменяются явно;
случайный import failure не считается тестом fallback. Новый прямой lazy import
тяжёлого пакета нужно добавить в этот список.

Для счётчика HTML тестовый `'../md.ts'` делает `export *` из настоящего модуля и
перекрывает только `mdTokensToHtml`. Проверки ссылок используют настоящий lexer
и parser, сохраняя definitions. Протокольные тесты используют фабрику renderer;
браузерные — настоящий собранный asset и HTTP-приёмник запрещённых ресурсов.
Сторож `check-chat-performance.mjs` считает lexer, HTML, подсветку и схемы;
неизменённые ответы при progress/reorder/waiting/step/duplicate дают ноль вызовов.
Контрольное дописывание проверяет, что счётчики видят новый текст и закрытие блока.
