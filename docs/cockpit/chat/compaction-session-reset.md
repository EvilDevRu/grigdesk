# «Codex сжал контекст хода» через четверть часа после ручного сжатия и досье вместо ответа = выжимка не закрывала живую сессию

Симптом (14.09.2026, чат Codex на 157k токенов): нажали сжатие на кольце, плашка «контекст сжат» есть,
следующее сообщение ушло с выжимкой первым блоком — а через 15 минут в ленте «Codex сжал контекст
хода», и ход заканчивается не работой, а досье «Задача… Что осталось… Ограничения» (это выжимка
уже родного компакта Codex, отданная как ответ). Живой прогон брошен на полпути, кольцо после
хода показывает 23k — как будто всё сработало.

Причина: **сжатие выжимкой не закрывало живую сессию исполнителя.** Клиент честно обнулил
`sessionId`, но живой процесс (`lib/chat/liveSessions.ts`) с прежним thread остался, а пустой
id следующего хода пул считает «окно ещё не знает id», не «начни заново» — и поднимает прежний
thread через `thread/resume`. Итог: полный старый контекст + выжимка сверху, сжатия не было.
Проверяется по rollout Codex: ход после «сжатия» лежит в файле СТАРОГО thread
(`~/.codex/sessions/.../rollout-*-<старый id>.jsonl`), нового файла нет.

Что сделано: после сжатия `summary` сервер гасит живую сессию и отдаёт `sessionId: null`
(как явный сброс памяти); клиент применяет итог сжатия и из `pending` (перезагрузка окна
посреди сжатия), а восстановленный из `pending` вопрос показывает без блока выжимки — раньше
она всплывала синим «сообщением пользователя». Сторожа: `tests/server/chat-live-sessions.test.js`
(«сжатие выжимкой гасит живую сессию…») и `tests/web/chat-compact-sync.test.js` WEB-07…09.
Родного компакта (Claude, Kimi) это не касается: у них сессия та же.
