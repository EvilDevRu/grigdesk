# Свои настройки исполнителя объявляет сам executor

Здесь `executor` означает адаптер Cockpit. Текущие декларации содержат вручную
выбранные поля и не являются полным каталогом настроек установленного CLI.
Источники для автоматического обнаружения и ограничения их полноты разобраны
в [анализе нативных настроек](executor-settings-discovery.md).

- **Свои настройки исполнителя объявляет сам executor** — поле `settings`:
  `[{ id, kind, label, hint?, value, disabled?, note?, confirm? }]`. Схема приходит от исполнителя,
  выбор человека лежит в prefs (`providerSettings`), склейка — `lib/providerSettings.ts`;
  сохранение — `POST /api/providers/:id/settings` (`{ settingId, value }`). Ядро про смысл
  ключа не знает: принимает ТОЛЬКО объявленный id и приводит значение к типу `kind`, поэтому
  чужой ключ в prefs не попадёт. Фронт рисует по `kind` (`stores/providers.saveSetting`,
  оптимистично с откатом).

- Настройки находятся в раскрываемой панели исполнителя и занимают высоту по
  содержимому. Фиксированные 220 px больше не нужны: одновременно открыт один
  исполнитель. Своего tabindex у тела нет, клавиатура проходит по самим ручкам.
  Раскладка описана в [контракте гармошки](../web/executor-settings-accordion.md).
