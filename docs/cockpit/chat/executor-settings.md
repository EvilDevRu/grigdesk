# Свои настройки исполнителя объявляет сам executor

- **Свои настройки исполнителя объявляет сам executor** — поле `settings`:
  `[{ id, kind, label, hint?, value, disabled?, note?, confirm? }]`. Схема приходит от исполнителя,
  выбор человека лежит в prefs (`providerSettings`), склейка — `lib/providerSettings.ts`;
  сохранение — `POST /api/providers/:id/settings` (`{ settingId, value }`). Ядро про смысл
  ключа не знает: принимает ТОЛЬКО объявленный id и приводит значение к типу `kind`, поэтому
  чужой ключ в prefs не попадёт. Фронт рисует по `kind` (`stores/providers.saveSetting`,
  оптимистично с откатом).

- **Высота блока настроек задана, а не подогнана под содержимое: 220 px, как у списка MCP.**
  Число ручек у исполнителей разное (у одного один тумблер, у Ollama семь позиций), и по
  содержимому одноимённые разделы соседних карточек вставали бы на разной высоте, а поздний
  ответ реестра двигал бы вниз всё, что под ним, вплоть до кнопки «Обновить». Лишнее
  прокручивается внутри своего тела (`.pvsetbody`), карточка от этого не растёт. Своего
  tabindex у тела нет: внутри живые ручки, и клавиатура доезжает до нижних табом по ним.
