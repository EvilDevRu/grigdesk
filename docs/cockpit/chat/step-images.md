# Картинка в строке Read ленты хода

Раскрытая строка `Read` показывает миниатюру, если путь `sub` ведёт к PNG, JPEG, GIF или
WebP и итог вызова успешен. Миниатюра встаёт на место строки «[изображение]»: так
нормализатор Claude записывает блок картинки в результат. Строка общая для сервера и окна —
`STEP_IMAGE_TEXT` в `shared/chatSteps.ts`. Сами байты картинки в ленту и историю не попадают:
нет ни base64, ни копии файла.

Адрес строит `chatWorkdirImageHref` — ветка «путь на диске» из `chatImageHref` картинок
ответа; адрес со схемой и готовый `/api` она не пропускает. Картинку отдаёт
`GET /api/chat/:id/image?path=` с ограничениями [локальной картинки](assistant-image-links.md):
только рабочая папка разговора, `.state/artifacts/`, проверка сигнатуры формата и `no-store`.
Внешний URL, SVG и путь без растрового расширения миниатюру не дают. Отказ сервера или
ошибка декодирования оставляют подпись «Изображение недоступно».

Правило не зависит от исполнителя: лента знает только имя шага `Read` и путь `sub`.
Claude, DeepSeek/GLM и Kimi присылают такой шаг сами. Элемент Codex `imageView`
нормализатор приводит к нему же. Сгенерированную картинку Codex (`imageGeneration`)
сохраняет вне рабочей папки, поэтому её строка миниатюру не получает.

Запрос уходит только при раскрытии строки; отказавший адрес лента помнит и повторно не
запрашивает. Обычный щелчок перехватывает тот же обработчик чата, что у картинок ответа, и
открывает общий просмотрщик; щелчок с модификатором — ссылку в новой вкладке. Старые
сохранённые ленты показывают картинку по тому же правилу. URL не фиксирует снимок файла:
если файл заменён или удалён, строка покажет текущий файл или подпись. Картинку вне рабочей
папки, например из `/tmp`, миниатюра не показывает.
