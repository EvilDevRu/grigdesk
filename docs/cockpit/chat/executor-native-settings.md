# Нативные настройки исполнителей Cockpit

Реализация и транспортные проверки от 1 октября 2026 года. Исходное исследование —
[источники установленных CLI](executor-settings-discovery.md).

## Каталог и область действия

Новый блок в раскрытой карточке исполнителя строится из схемы источника. Ядро и Vue
не содержат реестра его нативных ключей. `GET /api/providers` сообщает только
`settingsCatalog`; discovery начинается при открытии выбранной карточки. Открытая
карточка проверяет свежесть раз в минуту; закрытие снимает таймер. «Перепроверить»
обновляет также опубликованную схему, если источник использует её.

В форме сначала видны доступные действия. Поиск находит параметры по имени, пути
и описанию; недоступный справочник пока полностью скрыт в интерфейсе, оставаясь
в каталоге. Сохранённый выбор со сбросом, черновики и ошибки сохраняются в рабочей части.
Состояние выбора видно у поля; путь, default и длинное описание — под «Подробнее».
Устройство и регрессия большого каталога — [форма дополнительных настроек](../web/native-settings-form.md).

Значения сохраняются как переопределения Cockpit. Для DeepSeek проверенные общие поля
действуют в чатах и новых узлах конвейера; доказанно web-only поля отмечены «Только чаты».
Другие провайдеры сохраняют чатовую область. Область формы задаёт adapter capability,
поддержку поля — `appliesTo` и `consumerSupport` совместимого protocol 1.
Значения выбираются после ожидания очереди или перед новым узлом. Изменение prefs
не прерывает busy-процесс и не меняет его immutable snapshot при уточнении in-turn.
Служебные задачи и пользовательские глобальные конфиги этот слой автоматически не получают.

| Маршрут | Контракт |
| --- | --- |
| `GET /api/providers/:id/settings/catalog` | Публичный каталог, состояние источника и сохранённый выбор |
| Тот же GET с `?refresh=1` | Принудительная проверка источника |
| `POST /api/providers/:id/settings/overrides` | `{ fieldId, operation, revision, schemaRevision, value? }` |

`fieldId` — JSON-кодирование массива сегментов пути. `set` требует собственное `value`
и актуальные ревизии схемы/хранилища. `unset` запрещает `value`, принимает
`schemaRevision: null` и работает при недоступном CLI; ревизия хранилища всё равно
проверяется. Ответ `{ ok: true, changed, catalog }` подтверждает сохранение для
следующего запуска. Старый `POST /api/providers/:id/settings` продолжает обслуживать
локальные ручки Cockpit. Авторизация обоих новых маршрутов — общий guard `/api`.

## Схема, значения и запреты

JSON Schema и OpenAPI нормализуются отдельно от Schemastery. Поддержаны примитивы,
typed enum, однозначный nullable, вложенные группы и атомарные массивы примитивов.
Объект целиком и индексы массива не являются адресами записи. Нулевые ограничения
сохраняются; `multipleOf` считается от нуля, Schemastery `step` — от объявленного min.
OpenAPI 3.0 boolean exclusive bounds не смешиваются с числовыми bounds JSON Schema.

Сложный union/enum, неизвестный dialect/тип/constraint и неподтверждённый канал остаются
read-only в каталоге и пока скрыты в форме. Managed policy, secret и ownership
распространяют запрет на потомков.
Модель, effort, sandbox, рабочие корни, hooks, MCP и прежний `fastMode` имеют свои
существующие владельцы; второй редактор этих параметров не появляется.

Default, base и override представлены раздельно как `known/unset/unknown/redacted`.
Только `known` содержит значение. Неизвестный base не подменяется schema default;
`set(null)`, `set(false)`, пустая строка и `unset` остаются разными операциями.
Публичная проекция скрывает секретные значения и enum/const секретного поля,
не выдаёт сырые schemas, configs и значения неактивных overrides.

Удаление поля подтверждается свежим источником с `complete` coverage соответствующей
области. Ошибка discovery оставляет последний каталог `stale`, а не объявляет поля
удалёнными. Старые overrides остаются в storage с причиной неактивности и удаляются
явным reset. При активных overrides недоступный источник запрещает новый запуск
кодом 503; несовместимость с cwd конкретного чата — 409 через `channel.refuse`.

## Проверенные транспорты

Версии прочитаны из установленных бинарей 1 октября 2026 года. Пробы использовали
собственные временные профили, соседние значения и secret sentinel; модельные
запросы не выполнялись. Количества полей не являются производственными константами.

| CLI и профиль | Полнота discovery | Запись и reset | Сведения CLI |
| --- | --- | --- | --- |
| Claude Code 2.1.285, stream-json, разовый/persistent | Опубликованная схема + `get_settings`, `partial`; неизвестные ключи не типизируются по значениям | Общий JSON-слой `--settings`; set/reset проверены, включая argv `--resume` и control readback на собственной синтетической истории | `effective` доказывает чтение слоя; общего applied для каждого ключа нет |
| Codex CLI 0.159.2, app-server | Сгенерированная установленным CLI схема Config — `partial`; пагинированные `features` — `complete`; latest-схема сама по себе не разрешает запись | TOML `-c` в argv процесса и JSON config thread; set/reset и `thread/resume` проверены с собственной синтетической rollout-записью | Process `config/read` не доказывает override отдельной thread |
| Kimi Code 0.33.0, host web | POST OpenAPI — `complete` в пределах объявленной области записи; нетипизированные/GET-only ветки read-only | POST config направлен в собственную копию `config.toml`; новый процесс после reset наследует исходный файл; тот же session id читается после обоих открытий | Принятие конфигурации подтверждено; поведение модели не проверялось |
| Kimi Code 0.33.0, contained web | Схема доступна для просмотра | `unsupported`: config смонтирован read-only, надёжный изолированный путь POST отсутствует | Поля read-only с причиной |
| DeepSeek Harness 0.1.5-rc.2, web-профиль, зарегистрированные namespaces | `settings/describe` и Schemastery, `complete` для объявленных namespaces | `settings/mutate` с namespace revision в отдельном документе каждого запуска; reset возвращает shared base, `session/create` возобновляет тот же id | Readback настроек доказывает принятие слоя, а не результат модельного хода |

Встроенный DeepSeek дополнительно проверен 2 октября 2026 года через приватные ACP
`_cockpit/settings/describe` и `_cockpit/settings/mutate`. Общий `maxTokens` меняет
фактический HTTP `max_tokens` в обоих транспортах настоящего runtime с loopback API.
Мост не объявляется инструментом модели. Отказ или неизвестный readback принятого
override блокирует prompt. Недоступная ACP-схема сохраняет форму и значения чата,
помечает pipeline `unverified` и запрещает новый узел с неопределённым активным override.
Подробности: [области consumers](native-settings-consumers.md),
[settings-мост](deepseek-private-settings-bridge.md).

Проверка resume без модельного хода подтверждает совместимость конфигурационного
канала и протокола открытия. Она не оценивает качество продолжения диалога.
В форме используется «сохранено для следующего запуска; применение в чате не
подтверждено». Внутренний `confirmed` разрешён только достоверным `applied`;
`accepted/effective` дают `sent`, несовпадение — `overridden`, отсутствие сведений —
`unknown`. Общего обещания «применено ко всем чатам» нет.

## Границы реализации и проверки

Общие сервисы находятся в `server/src/lib/executorSettings/`, маршруты —
`server/src/modules/providers/settings.ts`, web API/store —
`web/src/shared/providerSettingsApi.ts` и `web/src/stores/providerSettings.ts`.
Форма использует контролы `web/src/ui.ts`. Изоляция записи, CAS и fingerprint
описаны в [границах хранения и запуска](executor-settings-storage-boundaries.md).

Проверки `provider-settings-*.test.js`, `providers-native-settings-route.test.js`
и три web-файла покрывают схемы, API/storage, секреты, конкурирующие записи,
v1→v4, фактический вход четырёх fake CLI, resume/reset, очередь, immutable snapshot
и in-turn. Сценарий нового поля использует пятый synthetic provider без vendor-условий.
Браузерная проба формы проверяет 340/360/760/1200 px, labels, клавиатуру,
typed enum, null/reset, список и появление нового поля после refresh.

Локальные RED/GREEN, результаты адресных проверок, снимки браузера и безопасные
итоги реальных проб лежат в `~/.cockpit/artifacts/executor-settings-tdd/`; каталог вне git
и не нужен для запуска тестов. После изменения серверного кода работающий Cockpit
требует ручного перезапуска; агент из чата сервер не перезапускает.
