# Ollama: пустой ответ на второй ход = загруженную модель вычли из памяти дважды

Симптом: первый ход после старта демона работает, а следующий возвращает пустой ответ
(в ленте — одно размышление, текста нет), `contextWindow` при этом **2048**.

Причина: `estimateMaxNumCtx` (`executors/_ollama-client.js`) считает бюджет KV-кэша как
«свободная VRAM + 60% свободной ОЗУ − веса модели». Пока модель НЕ загружена, это верно.
Как только демон её поднял, её веса уже вычтены из свободной памяти операционной
системой — и вычитание повторялось вторично. Для 23-гигабайтной модели бюджет уходил
в минус, потолок схлопывался в пол ползунка (2048), `run()` честно ужимал туда `num_ctx`,
а в такое окно не влезает даже системный блок с правилами проекта и объявлением
инструментов. Модель отвечала пустотой, и выглядело это как «сломался исполнитель».

Обе стороны починены:

- **занятое уже загруженной моделью возвращается в бюджет** — `estimateModelMaxNumCtx`
  спрашивает `/api/ps` и передаёт `loaded: {vramBytes, ramBytes}` в оценку (замер живьём:
  потолок 2048 → 71680);
- **`MIN_AGENT_NUM_CTX = 8192` — пол, ниже которого оценка ужимать не имеет права**
  (`executors/ollama.js`). Оценка памяти — эвристика, а при нехватке Ollama доложит часть
  слоёв на процессор, а не упадёт: цена ошибки в меньшую сторону несопоставимо выше, чем
  в большую. Настройку ниже 8192 человек поставить может — пол не поднимает выбранное
  значение, только не даёт **оценке** опустить его.

Проверки — `tests/server/ollama-provider.test.js` (оба случая зафиксированы отдельными
тестами: единица `estimateMaxNumCtx` с `loaded` и ход, где веса больше всей памяти).
