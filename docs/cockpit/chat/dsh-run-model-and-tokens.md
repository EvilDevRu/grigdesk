# GLM и DeepSeek: «запр.» в строке состояния и крошечный счётчик токенов

Симптом во время хода GLM или DeepSeek: справа в строке состояния модель весь ход подписана
«запр.» — запрошена, но не подтверждена, — а счётчик слева показывает сотни или тысячи токенов
после многих минут работы и то растёт, то падает.

Причина «запр.»: Claude, Codex и Kimi сообщают модулю чата фактическую модель через
`onRunMetadata`, ход DSH не сообщал её никогда. Канал не доходил и до него: адаптеры GLM и
DeepSeek не передавали `onRunMetadata` в `runDeepSeekServerTurn`.

Причина счётчика: DSH присылает `usage` один раз на запрос к модели, с полным итогом этого
запроса. Ход подставлял в счётчик `outputTokens` последнего запроса вместо суммы за ход, а между
итогами — оценку по символам всего текста хода. Модуль чата меняет пометку «≈» только когда она
передана явно, поэтому после точного числа оставалась пометка прошлой оценки.

Теперь ход DSH называет модель дважды. Первый раз — до prompt, по обратному чтению выбора сессии
из снимка `session/follow` (`projections.values.modelSelection.next`): источник `session`. Второй
раз — в каждом `assistant/message` по `message.source`, где DSH записывает provider и model
маршрута, которым отправил запрос: источник `response`. Пара переводится в id каталога
`JSON.stringify([provider, model])`, тот же, что у выбора модели. Модель попадает и в результат
хода (`actualModel`). Неполная пара подтверждением не считается.

Счётчик — сумма по запросам хода: точный `outputTokens`, где итог пришёл, иначе оценка по
символам текста и размышления этого запроса. Пометка `tokensIsEstimate` передаётся всегда.

Живой размер контекста — сумма `inputTokens`, `cacheReadTokens` и `cacheWriteTokens`. По
контракту DSH эти поля не пересекаются: `inputTokens` — только некешированный хвост запроса,
и при работающем кеше одно это поле давало кольцу сотни токенов вместо десятков тысяч.

Проверка: `tests/server/deepseek-server-thoughts.test.js` — модель сессии и ответа, отсутствие
подтверждения без названной модели, сумма расхода по запросам; `tests/server/glm-runtime.test.js` —
модель сессии через адаптер GLM и фейковый процесс DSH.

Исправление действует после ручного перезапуска Cockpit.
