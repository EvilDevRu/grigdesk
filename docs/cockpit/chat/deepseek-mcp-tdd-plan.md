## 2. Проверенные факты и границы задачи

Ниже — снимок исходного дерева перед реализацией. Итоговый контракт описан в
[безопасном списке MCP](deepseek-mcp-status.md).

1. Каталог выставляет `mcp: typeof ex.mcpStatus === 'function'`.
2. Vue показывает панель при `p.mcp && p.installed`. Модельный вход для списка не нужен.
3. GET `/api/providers/:id/mcp` уже существует, кэширует ответ на 60 секунд и принимает `?refresh=1`.
4. DeepSeek читает `.mcp.json` у ближайшего корня Git и в cwd. Без Git корнем считается cwd.
5. Парсер возвращает только выбранные для запуска stdio-серверы с найденной executable-командой.
6. Выключенные записи отбрасываются. HTTP, повреждённые записи и зарезервированные имена дают warnings.
7. `warnings` — внутренние строки: в них могут быть пути, текст ошибки JSON и значения из файла.
8. `config.rootDir` — папка установки кокпита. Глобальная страница настроек не знает cwd каждого чата.
9. `opts.getProviderAdapters` используется через `adaptersOf` не во всём providers-модуле:
   MCP GET и фоновый `checkUpdates` пока вызывают настоящий `getProviderAdapters`.
   Сам каталог моделей тоже не подменяется; его вызывают `buildRegistry`, refresh реестра
   и маршрут обновления CLI. Одного `opts.getProviderAdapters` для изоляции стенда недостаточно.
10. Ошибки чтения файла reader тоже складывает в `warnings`, а не обязательно бросает.
    Поэтому наличие warnings не позволяет отличить плохую запись от ошибки доступа или JSON.
11. `compileSettingsView` работает через Node-компилятор без обработки `<style>`.
    Этот helper годится для DOM-тестов, но не для проверки геометрии в браузере.

Существующую семантику `projectMcp.ts` сохранить. В частности, слои объединяются после фильтрации
записей: выключенная запись cwd сейчас не является tombstone для одноимённой записи корня Git.
Новый список должен совпадать с результатом существующего reader, а не обещать другую семантику.
Исправление этого поведения, если оно понадобится, требует отдельной задачи с регрессиями запуска.

Не расширять задачу следующими возможностями:

- редактирование, добавление и удаление MCP через UI;
- HTTP/SSE-транспорт, конфигурация плагинов или чтение глобального DSH_HOME;
- поиск по всем проектам и приватным чатам, выбор другого cwd из браузера;
- запуск DSH, создание сессии, model request, соединение с MCP или проверка его backend;
- изменение динамической формы нативных настроек, политики прав или транспорта чатового хода;
- переписывание общего store, SSE, опроса MCP, кэша или дизайна карточки.

## 3. Решения, которые исполнитель не должен придумывать заново

### 3.1. Откуда брать список

Метод `deepseek.mcpStatus(config)` вызывает новый `readDeepSeekMcpStatus(config)`.
Helper использует существующий `readProjectMcpServers(config.rootDir)`.
Парсер JSON, поиск корня Git, разрешение PATH и слияние слоёв повторно не писать.

Для этого списка нужен заданный абсолютный `rootDir`. При отсутствии, пустой строке или
относительном пути вернуть безопасную ошибку и не вызывать reader. Не подставлять `process.cwd()`:
это может незаметно показать конфигурацию другой папки. Нормальный сервер уже задаёт `rootDir`.

Список относится к папке кокпита. В другой рабочей папке чата результат может отличаться.
Это пояснение обязательно видно в успешной панели даже при пустом списке. Для ошибки
папку кокпита называет само поле `error`: существующая ветка ошибки не отображает `note`.

### 3.2. Что отдавать браузеру

Новый файл: `server/src/lib/deepseek/mcpStatus.ts`.

Предусмотреть две экспортируемые функции:

- `composeDeepSeekMcpServers(servers)` — принимает уже разобранные `ProjectMcpServer[]`
  и строит публичные карточки. Это чистая функция, без чтения файлов и изменения входа.
- `readDeepSeekMcpStatus(config, deps = {})` — читает через `deps.readProject || readProjectMcpServers`.
  `readProject` имеет тип существующей функции; зависимость нужна только для unit-тестов.

Типы helper объявить рядом: `DeepSeekMcpConfig`, `DeepSeekMcpServerCard`, `DeepSeekMcpStatus`.
В конфиге helper нужен только `rootDir?: string`. Не добавлять второй общий контракт всех providers.

Публичная карточка имеет ровно эти поля:

```ts
{
  name: server.name,
  target: '',
  scope: 'project',
  state: 'configured',
  detail: '',
}
```

Имена сортировать через `localeCompare` с локалью `ru`, не мутируя входной массив.
Пустой `target` намеренный: для этой версии списка достаточно имени. Это позволяет совсем
не переносить в tooltip команды, аргументы, env, токены и пути runtime. Не копировать server через spread.
Само имя — публичный ключ из конфигурации; гарантии скрытия произвольного секрета внутри имени нет.
В тестах утечек canary помещать в закрытые поля, а имя отдельно проверять как обычный текст:
строка с HTML-разметкой не должна создавать элементы или обработчики в DOM.
Служебные `cockpit-work` и `cockpit-perm` не добавлять в источник: reader уже исключает такие записи.

`configured` означает «Настроен», серый индикатор. Статус строки `ok` («Подключён») здесь запрещён:
соединение не проверялось. Верхний `state: 'ok'` означает успешное получение списка, а не подключение.

### 3.3. Тексты и ошибки

Обычный успешный ответ helper:

```ts
{
  state: 'ok',
  note,
  emptyText: 'Для папки кокпита нет MCP-серверов, выбранных для запуска.',
  servers,
}
```

Ошибка helper имеет точную форму `{ state: 'error', error: <фиксированный текст>, servers: [] }`.
Тип `DeepSeekMcpStatus` — union успеха и ошибки с discriminator `state`; успешный ответ
всегда содержит `note`, `emptyText` и `servers`. Поля `file`, `warnings`, `checkedAt` и `cached`
helper не возвращает. В API ошибка чтения остаётся HTTP 200 со `state: 'error'`.

Базовый `note`, с разбивкой строк в коде для предела 110 символов:

> Показана конфигурация MCP для папки кокпита. В другой папке чата список может отличаться.
> Соединение не проверялось. Показаны только stdio-серверы, выбранные для запуска.

Все сообщения ошибок фиксированные; текст исключения, `file` и содержимое `warnings` наружу не идут.

| Результат чтения | Ответ helper |
| --- | --- |
| Файлов нет / файл пустой по составу / все записи выключены; warnings нет | `ok`, базовый note, `servers: []` |
| Есть серверы, warnings нет | `ok`, базовый note, публичные карточки |
| Есть серверы и warnings | `ok`, те же карточки; к note добавить текст ниже |
| Серверов нет, warnings есть | `error`, `servers: []`, фиксированная ошибка ниже |
| Reader бросил исключение | `error`, `servers: []`, фиксированная ошибка чтения ниже |
| `rootDir` отсутствует / пустой / относительный | `error`, `servers: []`, ошибка папки; reader не вызывать |

Суффикс note для частичного результата:

> Конфигурация MCP для папки кокпита прочитана или проверена не полностью.
> Список может быть неполным; проверьте `.mcp.json` и команды запуска.

Ошибка при warnings без серверов:

> Не удалось получить список MCP для папки кокпита.
> Проверьте `.mcp.json` и команды запуска.

Ошибка чтения: «Не удалось прочитать конфигурацию MCP для папки кокпита.»

Ошибка папки: «Для списка MCP не задана абсолютная папка кокпита.»

Не возвращать предупреждения отдельным массивом и не писать сырые исключения в новый log.
Это важно и для битого JSON: сообщение `JSON.parse` может содержать кусок исходного файла.
Не разбирать текст warnings для выбора диагноза: reader не предоставляет типизированных причин.
При частичном результате хорошие записи должны оставаться видимыми.
При полной ошибке интерфейс должен показать ошибку, а не «Серверов не настроено».
Reader и построение карточек выполнять внутри одной границы `try/catch` helper: общий маршрут
при необработанном исключении публикует его message. Общий catch маршрута в этой задаче не менять.

`checkedAt` и `cached` добавляет существующий маршрут. Helper не создаёт собственный TTL.

### 3.4. Минимальное дополнение общего UI

Добавить необязательный метаданный текст `emptyText` в документированный ответ `mcpStatus`.
В существующем пустом состоянии `SettingsView.vue` использовать:

```vue
{{ mcpOf(p).emptyText || 'Серверов не настроено.' }}
```

Условие показа, общий control skin, действия и fallback остальных исполнителей сохранить.
Никаких условий по `p.id === 'deepseek'`. Store уже сохраняет весь ответ, менять его не нужно.
Это дополнение убирает ложную подпись о ненастроенных серверах, когда записи есть, но выключены.
