# Подтверждение pending

Веб-окно переносит итог из `/api/chat/pending` в историю и ждёт успешного сохранения чата.
Затем оно ждёт ответа на `DELETE /api/chat/pending/:id`. Завершение `_collectPending()`
означает, что проход подтверждений закончен; следующий проход не обгоняет незавершённый DELETE.

Для мобильного хода сервер перед удалением сверяет общий durable журнал и историю.
При ошибке записи он возвращает `503 history_not_durable` и оставляет pending для следующей
сверки. Копия ответа в браузере сама по себе не разрешает удалить серверный итог.

Сбой DELETE перехватывается отдельно: сохранённый ответ остаётся в истории, а pending
подбирается повторно по прежнему устойчивому id. Отсутствующий на сервере чат также
подтверждается через завершённый DELETE.

Проверки: `tests/server/chat-step-reuse-flow.test.js` прогоняет настоящий веб-стор с новым
и прежним способом сохранения; `tests/server/mobile-history.test.js` проверяет отказ
durable ledger и повторное подтверждение.
