# Границы модулей уточнений и ответов

`server/src/lib/chat/messageIdentity.ts` задаёт ключ сообщения для слияния истории,
проекции следующего хода и защиты канонических записей от устаревшего PUT окна.
У ответа агента пара `runId`/`assistantMessageId` важнее `pid`: перенос через pending
не создаёт вторую реплику. Записи без постоянного id сравниваются по роли и тексту;
слияние по-прежнему учитывает кратность одинаковых сообщений.

`ChatAssistantPublisher` в `server/src/lib/chat/assistantPublisher.ts` связывает
callback адаптера с журналом `ChatAssistantMessages`. Он назначает sequence при
первом появлении блока, публикует черновики из памяти и завершённые блоки после записи.
Перед финалом хода `flush(runId)` ждёт зарегистрированные операции и возвращает
ошибку записи, даже если адаптер не ждал callback и операция уже завершилась.
Маршруты и запуск исполнителя остаются в `server/src/modules/chat/index.ts`.

В окне `web/src/stores/chatInTurn.ts` строит видимую группу уточнений и ответов,
сохраняя метаданные уже известных сообщений. Оба пути получения финала — pending
и синхронный HTTP-ответ — вызывают `applyAssistantFinal`: существующий блок того же
запуска дополняется, новый добавляется. Обновление Pinia и сохранение истории остаются
в `web/src/stores/chat.js`.

Общий продуктовый контракт — [уточнение работающему агенту](in-turn-messages.md).
Барьер записи проверяет `tests/server/chat-in-turn-replies.test.js`, перенос финала
и восстановление потерянного ответа POST — `tests/web/chat-in-turn-store.test.js`.
