# Границы хранения и запуска настроек исполнителей

Проверено по коду 30 сентября 2026 года при рецензировании
[плана динамических настроек](executor-settings-tdd-plan.md).
Ниже описано текущее устройство; предусмотренные планом изменения ещё не реализованы.

## Запись общего объекта

Старый `POST /api/providers/:id/settings` в
`server/src/modules/providers/index.ts` читает весь `providerSettings`, затем ожидает
`applyProviderSetting` и записывает полученный объект целиком. Декларация `settings`
может быть асинхронной. Запись другого запроса между чтением и завершением ожидания
может быть потеряна, в том числе у другого исполнителя.

`PrefsStore.write()` в `server/src/lib/prefsStore.ts` синхронен и использует tmp+rename,
но мержит верхний уровень prefs: переданный `providerSettings` заменяет прежний целиком.
Атомарность файла не устраняет устаревание вложенного снимка. Поэтому изолированный
CAS нового маршрута без изменения старого writer не обеспечивает сохранность overrides.

Проверка для реализации: задержать старый запрос на async-декларации, завершить новую
адресную запись, отпустить старый запрос и проверить сохранность обеих правок.

## Публичные ответы prefs

`GET /api/settings/prefs` в `server/src/modules/settings/index.ts` возвращает
`prefs.read()`, успешный POST — `prefs.write(body)`. Оба ответа содержат настройки
исполнителей целиком. `PROTECTED_PREFS` запрещает менять `providerSettings` общим POST,
но не фильтрует их чтение и не скрывает вложенные значения в ответе успешной записи.

Добавленный внутрь `providerSettings` контейнер автоматически попадёт в эти ответы.
Новая публичная проекция должна исключить его в обоих маршрутах; внутреннее чтение
prefs остаётся полным. Фильтрации только ответа каталога недостаточно.

## Повторное открытие сессии

`fingerprintOf` в `server/src/lib/chat/liveSessions.ts` читает `spec[field]` для каждого
имени из `restartOn`. Путь через точку не раскрывается. Массивы сортируются, остальные
значения сериализуются как есть.

Для нативного плана требуется отдельное верхнее строковое поле
`nativeSettingsFingerprint`. Передача `nativeSettings.fingerprint` как имени поля
даст undefined; передача всего плана включит лишние ревизии и временные данные.

## Служебные потребители

Настройки исполнителей читает не только чат: среди потребителей есть
`analysis/analyzer.ts`, `analysis/arbiter.ts`, `inbox/triage.ts`,
`codeCommitMessage.ts` и `media/meetingPlan.ts` в `server/src/lib/`.
Появление вложенного контейнера в prefs само по себе не должно менять их запуск.
Подготовленный план нативных настроек передаётся отдельным полем только чатовым путём.
