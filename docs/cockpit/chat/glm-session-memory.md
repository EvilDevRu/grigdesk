# Память GLM: привязка сессии, resume и рабочая папка

GLM объявляет `sessionBinding` и `workdir: { switch: 'reseed', roots: 'single' }`; CAS
привязки, ротация и сброс памяти — общие механизмы чата.

- `authProfileId` — `glm-env-key:<16 hex>` от режима доступа и ключа; ключ наружу не выходит.
- `securityProfile` — `cockpit-glm-profile-v2:<sha256>` от ревизии профиля, identity сборки,
  режима и флагов SSH/БД. Недоступная сборка — отказ с кодом `glm_*`, который чат показывает.
- Смена ключа, режима, identity сборки, флагов или cwd начинает новую сессию; home чата —
  `<корень homes>/<identity[:16]>/<sha256(chatKey)>`, отдельно от homes DeepSeek, переноса home
  между поколениями нет.
- DSH на `session/create` с неизвестным id молча создаёт новую сессию с этим id. Поэтому перед
  resume GLM проверяет журнал `sessions/<projectKey(cwd)>/<id>/session.v*.jsonl[.zstd]` в home
  чата: нет журнала (чужой чат, другая папка, небезопасный id) — `glm_session_missing` до
  запуска процесса. Повреждённый журнал DSH отвергает при создании сессии — тоже
  `glm_session_missing`; новая сессия не создаётся.
- Сброс памяти во время активного хода ядро отклоняет (409), поэтому поздний `onSessionCreated`
  этого хода не может вернуть сброшенную привязку.
- Вложения и дополнительные каталоги в рабочую область не добавляются; в ленту хода идёт
  предупреждение.
- Summary-сжатие: запрос выжимки видит прежний разговор, выжимка сохраняется в `pendingSeed`
  чата, привязка ротируется; окно вклеивает выжимку в следующее сообщение новой сессии.
