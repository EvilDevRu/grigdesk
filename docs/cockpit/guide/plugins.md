# Плагины: слоты, размещения и область

Как плагин встаёт в интерфейс кокпита и чем человек этим управляет. Реестр плагинов,
тумблер и настройки описаны в заголовке `server/src/lib/pluginsRegistry.ts`; здесь —
контракт встраивания, общий для системных плагинов и (в будущем) пользовательских с
собственным кодом веба.

## Слоты

Слот — именованное место в ядре, куда плагины ставят свои компоненты. Ядро называет
слот и даёт контекст; кто в нём стоит, ядро не знает.

- **Область владеет своими слотами.** Файл `shared/slots/<область>Slots.ts` объявляет
  имя, тип контекста и подпись для настроек; пространство имён в имени называет хозяина
  (`provider.*`, дальше `board.*`, `chat.*`). Оглавление `shared/slots/index.ts` только
  объединяет типы и подписи — содержания в нём нет. Новый слот = запись в файле области,
  строка импорта в оглавлении и `<PluginSlot>` в нужном месте ядра.
- **`<PluginSlot name="…" :context="…">`** (`web/src/plugins/PluginSlot.vue`) рисует
  размещения слота по порядку; имя проверяется типом, контекст — типом слота. Каждое
  размещение стоит в своей границе ошибок: упавший компонент плагина показывает «Плагин
  «id» не отрисовался» на своём месте, соседи и хозяин слота живут дальше. Пока список
  плагинов не загружен, слот пуст.
- **Реестр размещений** (`web/src/plugins/registry.ts`): `registerPlacement({ pluginId,
  slot, component, order })`. Записи статичны, включённость плагина и размещения слот
  читает из стора плагинов при отрисовке — тумблеры действуют без перезагрузки.
- **Системные плагины веба** живут в `web/src/plugins/<id>/index.ts` и регистрируют
  размещения там; загрузчик `web/src/plugins/index.ts` собирает их через
  `import.meta.glob`, точка входа импортирует только его. Добавить плагин — добавить
  папку; ядро не правится.

Слоты сегодня:

| Слот | Контекст | Где |
|---|---|---|
| `provider.popover.after-bars` | `{ providerId }` | всплывашка исполнителя в топбаре, под полосами лимитов |

## Размещения в манифесте

Плагин объявляет, какие слоты умеет занимать: `placements: [{ slot, default? }]`.
Компонент к слоту привязывает код веба плагина, манифест только называет места — чтобы
настройки могли их включать и гасить. Незнакомый слот из чужого манифеста отбрасывается
с предупреждением: место могло появиться в версии кокпита, которой на машине ещё нет.

Состояние тумблеров — prefs `pluginPlacements: { <id>: { <slot>: boolean } }`, умолчание —
`default` манифеста (иначе включено). `/api/plugins` отдаёт `placements: [{ slot, label,
enabled }]`, `PUT /api/plugins/:id/settings` принимает `placements: { <slot>: boolean }`
рядом со значениями — только по заявленным слотам. В диалоге настроек это группа
«Размещение»: тумблер на каждое место, гасит место, не выключая плагин.

Поля запроса независимы: отсутствие `values` сохраняет параметры, отсутствие
`placements` сохраняет размещения. Переданный `values` заменяет набор параметров
плагина (пустой объект возвращает умолчания), а `placements` меняет только перечисленные
места. Ответ всегда содержит `values`; при изменении одних размещений это прежние
эффективные значения параметров.

Параметры и размещения редактируются в отдельном черновике. Кнопка «Сохранить»
применяет их после успешного ответа; закрытие формы отбрасывает несохранённые изменения.
При ошибке сохранения черновик остаётся доступен для повтора, а рабочее состояние
плагина не меняется. Плагин с одними размещениями тоже считается настраиваемым:
у него есть кнопка сохранения, и он попадает в фильтр каталога «С параметрами».

## Область по исполнителям

Тип настройки `providers` — массив id из живого реестра исполнителей, пустой — «все».
Диалог рисует галочку на каждого исполнителя и называет пустой выбор словами («Ни один
не отмечен — значит все»); сервер принимает только строки-идентификаторы без повторов.
Смысл области задаёт сам плагин: прогноз лимитов, например, не замеряет полосы
исполнителей вне области и не показывает у них блок.

## Что плагин пока не может

Занять место, которого ядро не объявило слотом; заменить или обернуть элемент ядра;
вмешаться в ход чата. Первое решается новым слотом по запросу, второе и третье — темы
отдельных контрактов (обёртки, серверная шина действий и фильтров). Пользовательские
плагины (`plugins/<id>/`) могут объявлять `placements`, но своего кода веба у них пока
нет — размещения заработают вместе с `web.js` следующей версии манифеста.
