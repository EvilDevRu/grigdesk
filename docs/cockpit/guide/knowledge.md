# База знаний и файловая резервная копия

База знаний — локальное хранилище проверенных записей. Человек читает полную запись по
живой ссылке карты `/knowledge/<uuid>`, агент — через `knowledge search` и `knowledge read`.

## Хранение и доступ

- База по умолчанию лежит вне git: `~/.config/cockpit/knowledge/knowledge.db`. Каталог
  создаётся с режимом `0700`, файл — `0600`; путь меняет `COCKPIT_KNOWLEDGE_DB_PATH`.
- HTTP работает под общим auth guard в `/api/knowledge`. Живой gate инструмента
  `knowledge_search` возвращает `plugin_disabled`, отказ хранилища — `knowledge_unavailable`.
- Изменение и удаление требуют `expectedRevision`; устаревшая ревизия даёт
  `knowledge_conflict`. В git не хранится ничего: ни корпус записей, ни карты
  `docs/cockpit/*.md` — они локальны для машины и закрыты `.gitignore`.

## Поиск и CLI

Поиск использует русский стеммер: «деплой» находит «деплоя», но «сборка» не находит
«сборок»; «перезапустить» также не находит «перезапуск». Формы с беглой гласной и сменой части речи
нужно искать отдельно либо явно включать в текст или теги. Результаты ранжирует BM25;
пустой запрос возвращает пустой список `items`. CLI-команды `knowledge search "<тема>"`,
`knowledge read <uuid>` и `knowledge write` используют коды exit: код 0 — успех,
код 1 — запись/результат не найдены,
код 2 — конфликт, хранилище или карта недоступны, код 64 — неверные аргументы.

Cockpit добавляет собственный `bin/` в PATH дочерних агентов и явно передаёт его
transient-прогонам конвейера вместе с настроенным `COCKPIT_KNOWLEDGE_DB_PATH`, чтобы CLI
использовал ту же базу, что сервер. Launcher-ы также добавляют пользовательские каталоги CLI.
Поэтому агент находит `knowledge` из чужого рабочего дерева без симлинка в `~/.local/bin`;
установщик сохраняет симлинк для обычного пользовательского shell.

`knowledge write` создаёт запись с `project`, `repository`, `kind`, `title`, `body`, `tags`;
правка по UUID использует их без project и с `--expected-revision`, а `knowledge_search` —
с `action: write`. Расхождение ревизии даёт
`knowledge_conflict` без перезаписи. Delete исполнителю недоступен. Свободный чат правит UUID
в проекте записи, но не создаёт без trusted project. `{actor, channel, ref}` задаёт сервер
без runtime/task/run id.

Первый тег обязателен для всех путей создания и изменения, включая HTTP и интерфейс.
Он задаёт тему карты: строчные латинские буквы, цифры и дефисы, без дефиса по краям.
Неверная тема отклоняется до изменения записи, ревизии и поискового индекса.

Запись инструментом чата учитывает режим прав: `plan` запрещает её; `manual`, `default`
и пустой режим требуют решения человека. Явные режимы `acceptEdits`, `dontAsk`,
`bypassPermissions` и `yolo` разрешают правку без повторного вопроса; `auto` использует
общую проверку разрешений для действия редактирования. Отсутствие канала подтверждения
закрывает запись. Подтверждение показывает тело правки и метаданные, комментарий отказа
возвращается агенту. После ожидания повторно проверяются ревизия, проект, живой плагин
и активность хода. Sandbox самого исполнителя не выдаёт неявного разрешения на запись
в серверную БД вне его рабочего каталога.

## Один файл экспорта и импорта

Кнопка «Экспортировать» вызывает `POST /api/knowledge/backup/export` и скачивает один
самодостаточный JSON-файл `cockpit-knowledge-YYYY-MM-DD.json`. Envelope содержит
`schemaVersion: 1`, `snapshotHash` SHA-256 и UUID-сортированный массив `records`. У каждой
записи ровно поля `id`, `title`, `body`, `tags`, `kind`, `project`, `repository`,
`sourceDocument`, `revision`, `updatedAt`; `sourceDocument` совпадает с `tags[0]`.

«Импортировать» вызывает preview `/api/knowledge/backup/import/preview`, затем apply
`/api/knowledge/backup/import/apply` с тем же файлом, `snapshotHash` и решениями. CAS
позволяет оставить базу или взять файл; устаревший/неполный batch отменяется целиком,
повторный импорт — semantic no-op, отсутствующие записи не удаляются.

Export/import — human-only действия и дерево не меняют. После write точечно обновляется карта
темы; при переносе — старая и новая. Строка карты несёт только заголовок и два тега: ревизия в
git-файле стареет сразу, для `--expected-revision` годится лишь свежая из `knowledge read`, а
правка одного тела карту не меняет вовсе. Безопасный `tags[0]` создаёт карту.
Полная пересборка всех карт остаётся ручным действием человека «Обновить карты» через
`POST /api/knowledge/maps/refresh`. `tags[0]` — единственный владелец темы.

HTTP/MCP и отдельные CLI-процессы обновляют карты под общей kernel-блокировкой
`<путь-базы>.maps.lock`: она берётся до чтения снимка и удерживается до конца записи
или отката всей серии. Ошибка посторонней старой записи не блокирует точечное обновление
другого проекта или темы: область выбирается до проверки записей.

Карта адресуется парой «проект + тема»: тема даёт имя файла, проект — репозиторий. Корень
карт проекта — рабочий каталог его агента (`PROFILE_AGENT_CWD` профиля фабрики), а для
проекта без bash-профиля — единственный репозиторий реестра. Так оглавление ложится туда,
где агент стартует, и подхватывается его собственным `@`-каскадом, а не каскадом кокпита.
Несколько корней без явного выбора и полное отсутствие путей дают `maps_root_unknown`:
заход обрывается целиком, уже записанные карты откатываются. Бюджет контекста считается
на проект.

## Замеры

Исторический замер 29.08.2026: три пробные sample-записи; размер карт измерялся в байтах,
как и размер body, а прежний исторический каскад занимал ≈100 КБ.

Документальный тест бюджета считает `AGENTS.md`, `CLAUDE.md` и транзитивный `@`-каскад,
включая `CLAUDE.local.md`. Карты вне каскада читаются по требованию и в предел не входят.
Замер этой установки 2026-09-06: файлы занимают 48 774 UTF-8 байт, с резервом теста
512 байт — 49 286 при пределе 60 000. Это размер файлов, а не замер токенов модели;
исполнители без поддержки `@` читают документы по инструкции `AGENTS.md`.

Поле `contextBytes` ответа обновления карт и документальный тест используют один обход
транзитивного `@`-каскада: повторные импорты и циклы считаются один раз, неимпортированные
карты исключены. API возвращает байты файлов без резерва теста и без оценки токенов модели.
