# Журнал окна

Журнал окна — общий диагностический журнал браузера, который сохраняется на сервере
Кокпита: ошибки Vue, JS, ресурсов и stores, отказы и медленные ответы API, переходы,
SSE, auth, жизненный цикл страницы, UI-слои и ручные отметки человека. Запись
показывает наблюдаемый механизм; одна запись сама по себе не доказывает причину сбоя.

## Общий уровень логирования

Переключатель «Настройки → Диагностическое логирование» управляет трассой фабрики,
диагностическим logger-ом сервера и журналом окна. Источник истины — глобальная
настройка `factory settings debug`; отдельного флага для окна нет. Профильные и
задачные переопределения действуют только на соответствующие запуски фабрики,
причём глобальный уровень ограничивает их сверху. Поэтому «Выключено» выключает
всю диагностическую трассу, даже если у задачи записан `verbose`.
Обязательные журналы действий и короткий audit фабрики сохраняются отдельно.

| Уровень | Журнал окна | Сервер | Фабрика |
| --- | --- | --- | --- |
| Выключено | Новых записей нет; очередь очищается | `silent` | debug trace выключен |
| Только ошибки | Ошибки Vue, JS, ресурсов и stores, отказы API и SSE, ручные отметки | `error` | ошибки |
| Ошибки и контекст | Плюс переходы, UI-слои, SSE, auth и жизненный цикл страницы | `info` | решения |
| Подробно | Плюс медленные запросы, фокус и видимость вкладки | `debug` | подробная трасса |

Решение о допустимости события находится в `shared/diagnosticLogging.ts` и
применяется до записи в кольцо и очередь. Сервер повторно проверяет каждую
пачку, в том числе её дампы. Открытые окна узнают о смене настройки по общему
SSE; после внешнего изменения через CLI уровень также обновляется при возврате
вкладки или не позже очередной минутной проверки. При недоступном сервере окно
использует последний подтверждённый уровень вкладки до его срока действия;
истёкший уровень становится «Выключено» даже после F5. При первом запуске без
него до 100 очищенных ранних событий остаются только в памяти: после получения
уровня допустимые записи переходят в журнал, а при «Выключено» буфер стирается.
При восстановлении связи сервер отклонит записи, которые новый уровень больше
не разрешает.

## Что записывается

Каталог событий и схема разрешённых полей находятся в `shared/webLogContracts.ts`.
Браузер и сервер независимо применяют эту схему, включая записи внутри дампа.
Debug-события (переходы, UI-слои, фокус, видимость) отдельно не отправляются: их
видно в дампе ошибки или ручной отметки.

- **Маршрут окна** — шаблон зарегистрированного маршрута, например `/projects/:id?`.
  Список шаблонов в контракте тест сверяет с `web/src/router.js`.
- **Путь API** — шаблон из живой таблицы маршрутов сервера, например
  `/api/tasks/:id/graph`. Сервер собирает шаблоны `/api` хуком `onRoute` и отдаёт их
  по `GET /api/web-log/routes`; окно сводит реальный путь к самому точному шаблону
  до записи, а приёмник заменяет на `other` любой шаблон, которого нет в таблице.
  До первой загрузки каталога узнаются только пути входа и самого журнала; после F5
  каталог берётся из `sessionStorage`, после перезапуска сервера перечитывается.
- **Ошибка** — имя, категория и сообщение из закрытых списков (прочие сообщения —
  `unclassified`), стек — только кадры файлов сборки. У ошибки Vue есть источник
  (`render`, `setup`, `native-event`, `mounted` и другие — из кода production-сборки
  или текста dev-сборки) и имя компонента; у ошибки store — имя store и action.
  Отказ API внутри действия store записывается один раз, как `api.fail`: запись
  `store.error` его не дублирует. Ошибки Vue по-прежнему печатаются в консоль DevTools.
- **Ресурс** — тег и категория: `chunk-load` для файлов сборки, `resource`,
  `external`, `data`, `blob`.

Автоматически не сохраняются содержимое экрана и полей, HTML, тексты чатов,
тела запросов и ответов, cookie, токены, query/hash и реальные параметры маршрутов.
Неизвестные маршруты и API-пути становятся категорией `other`. Имена stores,
actions и компонентов берутся из исходного кода и проверяются шаблоном
идентификатора. Исключение — намеренно введённый человеком комментарий к отметке
длиной до 500 символов. Он хранится локально на сервере.

Повторы подавляются до записи: из одинаковых ошибок проходят первые пять за минуту.
Одинаковость определяет сигнатура из уже очищенных полей — вид события, имя,
категория и первый кадр ошибки, компонент, store и action, метод, путь и статус
запроса. Разные ошибки одного вида считаются отдельно. Когда минутное окно
закрывается, число подавленных повторов пишется сводкой `log.suppressed`.

## Доставка и хранение

Ключ записи — `(page, seq)`: `page` новый для каждого документа, `tab` служит
только для сопоставления вкладок. Очередь до 200 записей и 64 КиБ сохраняется
в `sessionStorage` до отправки. При доступном storage неподтверждённые записи
переживают F5. После закрытия вкладки, вытеснения очереди или аварийного
завершения браузера сохранность не гарантируется. Beacon при уходе — одна
попытка отправки; подтверждением служит только ответ обычного POST.

На сервере журнал находится в `config.webLogDir`. По умолчанию это
`server/.state/web-log`, переопределение — `COCKPIT_WEB_LOG_DIR`. Каталог имеет
права `0700`, файлы `0600`. Имя файла — UTC-день **приёма сервером**:
`YYYY-MM-DD.ndjson`. Хранится текущий и 13 предыдущих UTC-дней, не более
20 МиБ на день. При повторе после неопределённого исхода файл может содержать
дубль; reader объединяет записи по `(page, seq)`.

Браузер держит кольцо до 500 записей и 1 МиБ. Обычная запись ограничена 4 КиБ,
запись с дампом — 32 КиБ, сам плоский дамп — 100 записей и 24 КиБ. Дамп получают
ручная отметка всегда и ошибка — не чаще раза в минуту. `seq` включает debug,
поэтому пробелы в номерах серверного файла сами по себе не означают потерю.

Панель показывает фактический охват кольца и число недоставленных записей:
вытесненных из очереди, не сохранённых в storage, отброшенных как невалидные и
отсечённых суточной квотой. Штатная ротация кольца и подавленные повторы потерей
не считаются. Сводка `log.loss` пишется после подтверждённой отправки, только
если эти счётчики изменились.

## Отметка и чтение

В «Настройки → Сервер → Журнал окна» введите краткий комментарий и нажмите
«Отметить сбой»: отметка уходит на сервер сразу вместе с предысторией недавних
событий окна. Без доступа к настройкам есть команда
`window.__cockpitLog.mark('описание')` в DevTools. Состояние «Сохранено на сервере»
появляется после ACK именно этой отметки. При уровне «Выключено» отметка
недоступна. При сбое запишите время, раздел и что именно произошло.

Скачать сегодняшний файл можно там же кнопкой «Скачать журнал за сегодня (UTC)».
На серверной машине CLI читает тот же каталог:

```bash
node server/scripts/web-log.mjs --since 2h --level warn --ev 'api.*' --dump
node server/scripts/web-log.mjs --day YYYY-MM-DD --page '<page-id>' --json
```

`--since` фильтрует по серверному `rx` и читает только дни, попадающие в интервал.
`--level warn` включает `warn` и `error`; `--ev` допускает только `*` в роли
шаблона. Текстовая строка — время окна `t`, уровень, событие, маршрут, ключ
`page:seq` и данные. `--dump` раскрывает предысторию выбранных записей независимо
от фильтра уровня: в тексте она печатается под своей записью с отступом, по
порядку времени. `--json` выдаёт NDJSON с `rx` и числом повторов; строки
предыстории несут ссылку `contextOf`. Неверный аргумент завершает CLI с кодом 2 и
сообщением, что именно не так. Если каталог сервера переопределён, передайте CLI
тот же `COCKPIT_WEB_LOG_DIR`; CLI сам `.env` не загружает.

Проверка изолированного браузерного сценария:

```bash
node web/scripts/check-web-log.mjs
```

После серверных правок нужен ручной перезапуск сервера и обновление окна.
Проверка живой интеграции: сделать отметку, дождаться ACK, скачать UTC-день,
найти её по `page` в CLI и проверить охват дампа. Старая версия окна может
удерживаться Service Worker до штатного «Обновить».
Возврат из BFCache и мобильное замораживание вкладки нужно дополнительно
проверить вручную: изолированный браузерный fixture не гарантирует эти режимы.
