# Плагин «Докер»

Панель локального Docker: что поднято, на каких портах, чем занят диск и как это убрать.
Системный плагин, **по умолчанию выключен** — включается в «Настройки → Плагины → Докер».
Место в интерфейсе: правая рейка инструментов и страница `/docker`, заводское сочетание
`Ctrl+Shift+6`.

## Типы и проверка контракта

Плагин написан на TypeScript: клиент Docker Engine, сервис, нормализаторы, модуль
Fastify, store, HTTP-адаптер, форматирование, настройки и Vue-компоненты.
Общий `shared/dockerContracts.ts` описывает нормализованные
ответы HTTP и сообщения WebSocket. Типы выводятся из декодеров, поэтому форма данных
и её проверка при получении JSON имеют один источник.

HTTP-адаптер принимает ответ общего клиента как `unknown` и проверяет его до обновления
store. Некорректный обзор или сводка оставляют последние корректные данные и показывают
ошибку. Повреждённые кадры логов и статистики пропускаются; бинарный вывод терминала
не интерпретируется как JSON.

Клиент Engine возвращает `unknown`. Сервис проверяет используемые поля через
`dockerEngineDecoders.ts` до нормализации, а входные формы описаны в
`dockerEngineTypes.ts`. Необязательные поля и `null` сохраняют совместимость с ответами
разных версий демона. Ошибка формы ответа содержит путь поля без исходного значения;
inspect извлекает только разрешённые поля и не передаёт переменные окружения контейнера.

Сервер исполняет `.ts` напрямую через встроенное удаление типов Node. Минимальная
поддерживаемая версия — 22.18: с неё снятие типов включено по умолчанию, поэтому ни
`npm start`, ни `bin/cockpit`, ни `bin/restart`, ни шаблон systemd не передают флагов.
Более старую версию отвергают ворота в `bin/lib/runtime-env.sh` и в старте сервера.
Отдельного JavaScript-дубля или серверной сборки нет. Импорты используют расширение
`.ts` и `import type`; `erasableSyntaxOnly` запрещает синтаксис, которому нужна генерация
JavaScript. Общие контракты объявлены ESM-пакетом через `shared/package.json`.

Установленный юнит перерисовывается из шаблона (`deploy/install.sh`) перед перезапуском.
Сам перезапуск выполняет человек после завершения агентского хода. Для прямого запуска:
`node server/src/app.js`.

Типы проверяет общая команда среды: `npm --prefix server run typecheck` и
`npm --prefix web run typecheck`; они входят в `npm test` своих пакетов и накрывают весь
собственный TypeScript. `typecheck:docker` в обеих частях остаётся быстрой проверкой
одной области при работе над ней.
Для разработки и проверок нужны devDependencies: `npm --prefix server install --include=dev`.
Само удаление типов при запуске не заменяет эту проверку компилятором.

Отрицательные примеры в `tests/types/docker-contract.test.ts` и
`tests/types/docker-server-contract.test.mts` проверяют, что непроверенный JSON,
неверные параметры и недопустимые состояния остаются ошибками компиляции. Серверные
контрактные тесты пропускают реальные сериализованные ответы HTTP через общие декодеры.
Тесты транспорта используют временный unix-сокет; проверки потоков покрывают бинарный
вывод, лимиты соединений и освобождение ресурсов при обрыве во время подключения.

## Границы

- **Только человек.** Все ручки `/api/docker/*` требуют СЕССИЮ: CLI-токен агента получает
  `session_required`. Агенту докер доступен обычным Bash с его правилами подтверждения;
  надзорного канала вроде `supervised_db` у докера нет.
- **Только локальный демон.** Общение идёт через unix-сокет (`DOCKER_SOCKET_PATH`, по
  умолчанию `/var/run/docker.sock`). Удалённых хостов и `DOCKER_HOST` плагин не знает.
- **Новых полномочий не появляется.** Сервер host-native и работает под тем же
  пользователем, который и так состоит в группе `docker`.
- **Переменные окружения контейнера не отдаются.** В них живут пароли БД и токены, а
  панель открывают с планшета и показывают коллеге; кому нужен `env` — у того есть терминал.

## Что показывает

Обзор (`GET /api/docker/overview`) собирает контейнеры, compose-проекты, образы, тома и
сети за ~0.3 с. Расчёт занятого места в него НЕ входит: `GET /system/df` считает размеры
слоёв секундами (на большом хосте — 2.6 с), поэтому сводка живёт отдельной ручкой
`GET /api/docker/usage` с серверным кэшем на минуту; кнопка «Пересчитать» идёт мимо кэша.

Занятость томов считается по монтированиям контейнеров, а не по `df`: том занят, пока на
него ссылается хоть один контейнер, включая остановленный. Это совпадает с ответом Docker
и стоит миллисекунды вместо секунд.

Compose-проект — единица управления: контейнеры группируются по метке
`com.docker.compose.project`, у группы свои «Поднять / Перезапустить / Остановить».
Остановка идёт по списку контейнеров, запуск — в обратном порядке.

Панель показывает сводку работающих и незапущенных контейнеров, проектов и образов.
Проекты можно сворачивать. Поиск учитывает имя, сервис, образ, проект и порты; флажок
«Показывать незапущенные» включает остальные состояния контейнеров. Счётчик проекта
и подтверждение его остановки всегда относятся ко **всему проекту**, даже когда фильтр
скрыл часть строк. На узкой панели порты, ресурсы и действия переносятся под имя.

Проверка здоровья подписана по-русски: исправность отмечена зелёным, запуск проверки —
жёлтым, ошибка — красным. Терминал заранее отключён при `allowExec: false`, удаление
тома — при выключенном `allowVolumeRemoval` или наличии использующего его контейнера.
В диалоге удаления образа показывается его размер без обещания освободить столько же:
общие слои могут остаться заняты другими образами.

## Цифры занятого места берутся у демона

Сводка читает поля `ImageUsage`, `ContainerUsage`, `VolumeUsage`, `BuildCacheUsage` ответа
`/system/df` — те же, что показывает `docker system df`. Складывать размеры неиспользуемых
образов самостоятельно нельзя: у образов общие слои, и наивная сумма завышает
освобождаемое втрое. Тот же подвох у кэша сборки — часть записей общая. Если демон старый
и полей `*Usage` не отдаёт, сводка считается вручную и помечает себя `source: "computed"`.

## Предохранители

Опасное подтверждает человек в общем диалоге проекта, но подтверждение в браузере не
единственная преграда — сервер держит свои запреты (настройки плагина):

| Настройка | По умолчанию | Что запрещает без неё |
| --- | --- | --- |
| `allowVolumeRemoval` | выкл | удаление тома, очистку томов, удаление контейнера вместе с томами |
| `allowImagePruneAll` | выкл | очистку всех неиспользуемых образов (остаются только висячие) |
| `allowExec` | вкл | терминал внутрь контейнера |
| `logTailLines` | 500 | сколько строк лога отдаётся при открытии |
| `statsIntervalSeconds` | 3 | период среза статистики |

Запрещённое действие отклоняется кодом `volumes_forbidden` / `images_all_forbidden` /
`exec_forbidden` и до демона не доходит. Уборка идёт по целям независимо: отказ по томам
не отменяет очистку кэша сборки, а неудача возвращается строкой в отчёте.

## Потоки

Три WebSocket-канала, все под тем же гейтом плагина и сессии:

- `/api/docker/logs?id=` — логи. Кадры демона (8-байтовый заголовок у контейнера без TTY)
  разбираются на сервере, вкладке уходит готовый текст с пометкой `stdout`/`stderr`
  батчами по 80 мс. Лента в браузере хранит последние 5000 строк.
- `/api/docker/stats` — статистика. Срез снимает сервер по списку наблюдаемых контейнеров
  и шлёт одним сообщением; проценты CPU и памяти считаются по формуле `docker stats`
  (дельта тактов × ядра, вычтенный cache), чтобы цифра сходилась с терминалом.
- `/api/docker/exec?id=` — оболочка в контейнере (`bash`, иначе `sh`). Контракт сообщений
  тот же, что у раздела «Терминал»: вкладка шлёт JSON, сервер — сырые байты.

Потолки: 6 потоков логов, 4 терминала, 4 наблюдателя статистики. Выключение плагина рвёт
все открытые каналы, а не только запрещает новые.

## Грабли

- **Сводка `usage` дороже обзора на порядок.** Не тянуть её в общий refresh и не звать по
  каждому действию — она затем и вынесена отдельно.
- **`docker system df` и наивная сумма расходятся втрое.** Любая новая цифра про
  освобождаемое место обязана приходить из `*Usage`, иначе панель врёт в свою пользу.
- **Порт приезжает дважды.** Один проброс демон описывает записью на каждое семейство
  адресов (`0.0.0.0` и `::`); в панели они склеены в одну строку «наружу → внутрь».
- **Ссылка на порт ведёт на хост мозга, а не на localhost.** Адрес собирает общий
  `sandboxUrl()`: с планшета `localhost` — это само устройство-окно.
