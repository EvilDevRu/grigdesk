# Проекты и их репозитории

Проект в Кокпите — одно имя для трёх вещей: профиля фабрики, каталога маршрутов и набора путей
к рабочим копиям, по которым работает плагин «Код». Раздел «Проекты» показывает эти три стороны
вместе, а паспорт проекта хранит то, что человек задал руками: название, метки и репозитории.

## Паспорт проекта

Паспорт принадлежит установке и лежит в её локальных настройках, а не в репозитории: пути
к рабочим копиям на каждой машине свои. Идентификатор проекта при этом общий для всех машин —
он же имя профиля фабрики и каталога маршрутов.

| Поле | Смысл |
|---|---|
| `id` | Идентификатор проекта: строчная латинская буква, дальше буквы, цифры, `-` и `_`, не длиннее 41 символа. Менять его нельзя. |
| `title` | Название в интерфейсе, до 120 символов. У старой записи без названия читается сам идентификатор. |
| `description` | Свободное описание, до 2000 символов. |
| `tags` | Метки для поиска: не больше 20, каждая до 32 символов. |
| `repos` | Репозитории проекта, не больше 32 записей `{ key, dir }`. Порядок значим, алиасы одного каталога допустимы. |
| `defaultRepoKey` | Ключ репозитория по умолчанию: один из ключей `repos` либо пусто. |
| `archivedAt` | Когда проект отправлен в архив; у активного — пусто. |
| `import` | Перенос путей из профиля фабрики: состояние, отпечаток, время, текст ошибки и кандидаты обеих сторон при конфликте. |
| `revision` | Целое, растёт на единицу при каждой записи. По нему форма видит, что паспорт изменили в другой вкладке. |
| `createdAt`, `updatedAt` | Время создания и последнего изменения. |

Состояния переноса: `none` — путей из профиля нет, `pending` — чтение не закончилось,
`imported` — паспорт и профиль совпали, `conflict` — разошлись, `failed` — профиль не прочитан,
`manual` — человек решил сам.

### Ключ репозитория и путь

`key` — короткая метка внутри проекта: строчная латинская буква или цифра, дальше буквы, цифры,
`-` и `_`, до 16 символов. `dir` — абсолютный путь рабочей копии; он расширяет область чтения
триажа и обновления кода, поэтому это доверенный ввод человека, а не данные из задачи.

Один и тот же каталог можно объявить двумя ключами: профиль фабрики иногда различает «бэкенд» и
«фронтенд» одной копии. Кокпит такие записи не схлопывает и ключи не переименовывает — плагин
«Код» и раздел «Проекты» показывают ровно то, что задано. Одинаковые физические корни при этом
дают предупреждение в списке.

## API

Все ручки закрыты общей авторизацией Кокпита. Тело запроса на создание и изменение — паспорт без
служебных полей; ответы описаны ниже. Инкременты B и C добавляют свои ручки позже.

| Метод и путь | Ответ | Инкремент |
|---|---|---|
| `GET /api/projects` | `{ projects }` — все проекты, включая архивные | A |
| `GET /api/projects/:id` | Подробный паспорт проекта | A |
| `POST /api/projects` | `201` и подробный паспорт | A |
| `PUT /api/projects/:id` | Подробный паспорт | A |
| `POST /api/project-tools/repositories/check` | `{ results }` — состояние каждого пути | A |
| `GET /api/project-tools/discovery` | `{ candidates, tombstoned }` | B |
| `POST /api/project-tools/import` | Предпросмотр → `{ preview }`, применение → паспорт | B |
| `GET /api/projects/:id/dependencies` | `{ items, deletable, archivable, reasons }` | есть |
| `POST /api/projects/:id/archive`, `/restore` | Подробный паспорт | есть |
| `DELETE /api/projects/:id` | `204` | C |
| `GET /api/project-tools/directories?path=` | `{ root, path, entries }` | C |

### Жизненный цикл

Проект не удаляется сразу: сначала его убирают в архив (`archivedAt`), и только оттуда —
удаление. Архив прячет проект от потребителей, но ничего не рвёт: маршруты, стенды,
правила и связи остаются на месте, а сам проект видно в списке под фильтром «Архив».

Архив не пропускают живые связи: сводка `GET /api/projects/:id/dependencies` собирается
из разделов, которые хранят ссылку на проект, и отвечает `409 active_rules` с перечнем
того, что мешает (правила Telegram и GitHub — блокирующие: они пережили бы архив и
остались бы ссылками в никуда). Ошибка самого раздела-владельца тоже запрещает архив:
«связи не проверены» — это не «связей нет».

Архив прячет проект там, где начинают новое: форма запуска конвейера не предлагает
архивный профиль и отвечает `409 archived` на попытку запуска, песочница архивного проекта
не поднимается, в новых правилах Telegram и в новых связях SSH и баз он не предлагается,
а плагин «Код» сам его не открывает. Уже созданное архив не трогает: попытки, маршруты,
поднятые стенды и заведённые связи остаются на месте, их видно и сносить их можно как
обычно, а открытый по имени архивный проект показывается полностью.

Сводка связей собирается из разделов, которые хранят ссылку на проект: опубликованный
каталог маршрутов, попытки фабрики, профили SSH и баз, цели презентаций, записи базы
знаний и правила Telegram и GitHub. Наружу уходит число и, где это безопасно, короткий
список имён: адреса чатов и репозиториев остаются в своём разделе.

Возврат из архива снимает `archivedAt`, поднимает ревизию и предупреждает о путях,
которых больше нет на диске.

Изменение и жизненный цикл несут `expectedRevision` — ревизию, которую человек видел. Без неё
запись отклоняется (`400 revision_required`), с чужой — `409 revision_conflict` и текущей
ревизией в ответе. Так две открытые вкладки не затирают правки друг друга молча.

| Код | `error` |
|---|---|
| `400` | `bad_request`, `bad_id`, `bad_key`, `bad_dir`, `dup_key`, `bad_default_repo`, `unknown_field`, `revision_required`, `bad_revision` |
| `404` | `not_found` |
| `409` | `exists`, `tombstoned`, `factory_project`, `revision_conflict`, `import_stale`, `analysis_stale`, `has_dependencies`, `dependency_check_failed`, `archived`, `not_archived`, `active_rules` |
| `500` | `prefs_corrupted` — файл настроек не читается, запись отклонена |

Состояния проверки пути: `git` — каталог с `.git`, `worktree` — рабочая копия, чей `.git`
ссылается на другой каталог, `dir` — каталог без `.git`, `missing` — пути нет, `file` — по пути
файл, `denied` — нет доступа, `timeout` — проверка не уложилась в отведённое время.

Чтение настроек и запись паспорта устроены по-разному намеренно: чтение переживает нечитаемый
файл настроек и отдаёт умолчания, а запись при нём отказывает с `500 prefs_corrupted` и файл не
трогает. Иначе одна порча файла тихо стёрла бы все паспорта.

## Читатели путей и ID проекта

Паспорт отвечает на вопрос «где лежат репозитории проекта». Ниже — кто этот ответ читает и что
обязан учитывать. Строки, которых здесь нет, путей не читают: контракт запуска, рабочий каталог
чата, песочницы и сам движок фабрики берут их из своего места и паспортом не управляются.

| Место | Что читает | Что учитывает |
|---|---|---|
| Плагин «Код», обзор раздела | ключи и пути репозиториев, список проектов | сырые ключи паспорта; архивные проекты видны, но не выбираются по умолчанию |
| Триаж (`analysis/profile.ts`) | репозитории профиля триажа | пути из паспорта; границы доверия не расширяются дальше заданных человеком |
| Обновление кода перед запуском | репозитории профиля | паспорт; для архивного проекта запуск запрещён |
| Сопоставление с профилем фабрики | `repos` паспорта и `PROFILE_TRIAGE_REPOS` | расхождение показывается, а не чинится молча |
| Корень карт знаний | рабочий каталог профиля либо единственный путь паспорта | один корень без выбора; архивные проекты не получают записей |
| Раздел «Маршруты» | список проектов | создание проекта делегируется разделу «Проекты» |
| Правила Telegram, базы и SSH | идентификатор проекта | новый выбор — только из активных; заведённые связи архивного остаются |
| Правила GitHub | идентификатор проекта | проект вписывается вручную, поэтому архив проверяет сводка связей, а не форма |
| Веб: транспорт и стор раздела | сводка и подробный паспорт | `expectedRevision` в каждой мутации; событие `projects-changed` перечитывает список |

Событие `projects-changed` приходит по общему потоку `/api/events` и несёт `{ id, revision, kind }`,
где `kind` — `created`, `updated`, `archived`, `restored`, `deleted` или `imported`. Открытая форма
на него не реагирует: черновик человека важнее чужой правки, а расхождение ревизий показывается
при сохранении.

## Раздел в интерфейсе

На широком экране слева расположен каталог с поиском, фильтром архива и сортировкой,
справа — настройки выбранного проекта. Текущий проект выделен в каталоге; название,
идентификатор и состояние видны в заголовке его карточки. Если проект ещё не выбран,
правая область предлагает выбрать существующий или создать новый.

Форма разделена на основные сведения, репозитории и связи с фабрикой. Строка репозитория
содержит метку, путь, выбор по умолчанию и действия изменения порядка и удаления.
У иконок действий есть текстовые подсказки и доступные имена. Состояние проверки пути
показывается рядом со строкой; пояснение о доступе раскрывается отдельно.

Панель сохранения закреплена у нижней границы карточки и показывает, есть ли несохранённые
изменения. Каталог и карточка прокручиваются независимо. На узком экране или при сужении
страницы панелью инструментов показывается одна область, а кнопка «К списку» возвращает
к каталогу. Поля репозиториев перестраиваются
по доступной ширине карточки, чтобы пути и действия не выталкивали друг друга за экран.
