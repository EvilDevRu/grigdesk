# Плагин «Код»

Просмотр файлов и управление Git в зарегистрированных репозиториях проектов.
Одна панель живёт в общем ToolHost: правая рейка инструментов и страница `/code`
показывают тот же экземпляр с сохранённым выбранным файлом и состоянием Monaco.
Просмотрщик файлов и дифов работает только для чтения.

В шапке находятся только проект и рабочая копия. Три раздела — «Файлы», «Изменения»
и «Коммиты» — переключает рейка из небольших кнопок-значков слева от навигатора, как
activity bar в VS Code: рейка шириной 44 px стоит первой колонкой сетки, активный раздел
выражен `aria-pressed`, а подпись каждой кнопки живёт в доступном имени и подсказке.
Счётчик «Изменений» — бейдж поверх значка; он считает уникальные пути, поэтому файл,
одновременно присутствующий в индексе и рабочем дереве, не удваивает число, и входит в
доступное имя кнопки («Изменения · 3»). Кнопки рейки меняют только навигацию и сохраняют
открытый файл, выбранный диапазон и черновик коммита; выбор раздела раскрывает скрытый
навигатор. Навигатор по умолчанию имеет ширину 320 px, меняется разделителем в пределах
220–420 px и не занимает больше 42% панели; ширина рейки вычитается из координаты
указателя до ограничения. Желаемая ширина хранится на устройстве и восстанавливается
после временного сужения как в доке, так и на странице `/code`.
Справа в шапке навигатор скрывает и показывает иконка без подписи с доступным именем
«Скрыть навигатор»/«Показать навигатор» — того же размера, что кнопки дока рядом с ней.
Синхронный каркас загрузки повторяет ту же сетку с колонкой рейки, чтобы при появлении
живой панели ничего не прыгало.

## Контекст и навигация

Контекст объединяет проект, ключ репозитория и точный путь worktree. Сервер сверяет
репозиторий с каталогом проектов, а дерево — с `git worktree list`. Основное дерево
показывается первым; недоступный репозиторий остаётся в списке с пояснением.
Сохранённый контекст проверяется при чтении localStorage. Удалённое дерево заменяется
основным или первым доступным.

Дерево файлов раскрывается по запросу. Файловые ссылки из чата сопоставляются с картой
`GET /api/code/roots`: при вложенных корнях выбирается самый длинный. Ссылка может
передать номер строки через `/code?project=…&repo=…&root=…&path=…&line=…`.
Документы `.md` и `.txt` сохраняют приоритет своего просмотрщика. Неизвестный локальный
путь показывается текстом. Карта корней кэшируется на минуту; ошибка обновления
сохраняет последнюю корректную карту.

Кнопка «Ссылка» в обратную сторону копирует абсолютный адрес открытого файла. На
разделе файлов адрес включает текущую строку Monaco; для diff строка остаётся нулевой,
потому что у сравнения две стороны. Если браузер не даёт Clipboard API, общий диалог
показывает тот же адрес для ручного копирования.

Обычное файловое дерево также читает дешёвый снимок `/git`: изменённые файлы получают
Git-статус и цвет, а каталоги с изменениями внутри — точку. Если один путь есть и в
индексе, и в рабочем дереве, видимый статус рабочего дерева имеет приоритет. Снимок
меток обновляется после хода агента и при возвращении браузерной вкладки вместе с
открытым файлом, без повторного чтения раскрытых каталогов.

Поиск над деревом стартует с двух символов после паузы 300 мс. Пути файлов сравниваются
без учёта регистра, содержимое ищется буквальной строкой через `git grep -F` среди tracked
и untracked-файлов; бинарные и скрытые пути исключаются. Ответ ограничен 50 именами,
500 совпадениями и 512 КБ stdout, а превышение явно отмечается. Клик открывает файл на
найденной строке обычным файловым API; Enter выбирает первый видимый результат. Поздний
ответ прежней строки или рабочей копии не меняет список.

Намерения открыть файл выполняются последовательно. Неправильное намерение с известным
идентификатором потребляется один раз и не блокирует следующие. Смена контекста
делает запоздалый ответ предыдущего запроса неактуальным. Модели и редакторы Monaco
освобождаются при замене и закрытии панели.

## Git

Раздел «Изменения» разделяет индекс относительно HEAD и рабочее дерево относительно
индекса. Один путь может присутствовать в обеих группах с разными дифами. Выбор
адресуется парой «группа + путь». Список и дерево показывают те же изменения;
раскрытие новых каталогов сохраняет каталоги, ранее свёрнутые человеком. Раздел
«Коммиты» отдельно показывает журнал и, после выбора диапазона, его сводку и файлы:
рабочие группы больше не выталкивают историю за нижнюю границу панели.

Переключатель «дерево/список» относится ко всему разделу «Изменения» и стоит отдельной
строкой над группами, а не в заголовке первой из них. Пустая рабочая группа не рисуется:
при чистом дереве панель показывает короткое положительное состояние. Выбранный
диапазон сохраняется при возврате к «Изменениям»; заметное действие «Сбросить диапазон»
не даёт скрытому фильтру выглядеть обычным diff рабочего дерева.

`GET /api/code/:project/git` отдаёт только метаданные строк: статус, счётчики,
бинарность и старый путь переименования. Стороны выбранного файла панель лениво читает
через `GET …/file-diff?group=staged|work&path=…` и кеширует до нового снимка `/git`.
Пока ответ идёт, прежние модели другого файла сняты; поздний ответ уже покинутого
выбора отбрасывается. Неизвестный или исчезнувший путь получает `404 no_file`.
Приёмка задач этим разделением не затронута: `taskDiff` и `/api/tasks/:id/diff`
по-прежнему содержат обе стороны всех файлов.

Журнал в разделе «Коммиты» содержит до 50 последних коммитов и прокручивается сам. Пока
диапазон не выбран, он занимает всю доступную высоту; при выборе ограничивается сверху, а
ниже появляются сводка и файлы диапазона. Сводка — заголовок группы файлов в две строки:
отрезок с кнопками обзора и сброса, под ним число файлов, итог строк и число невыбранных
коммитов внутри отрезка. Обычный клик переключает коммит, Shift-клик добавляет весь
промежуток от последнего якоря. Выбранные строки задают непрерывный
отрезок от родителя самого старого выбранного коммита до самого нового; невыбранные
коммиты внутри отрезка входят в результат и показываются отдельным числом. Для корневого
коммита левой стороной служит пустое дерево. Список отрезка читает
`GET …/commits-diff?from&to`, а стороны файла — `file-diff` с `group=commits`, `base`
и `to` из проверенного ответа. Сервер принимает только hex object id, проверяет оба
коммита и прямой порядок; отказы: `400 bad_commit`, `404 no_commit`, `400 bad_range`.
Группа коммитов неизменяема: у неё нет stage/unstage.

Режим «с текущими изменениями» (кнопка «+ текущие» у заголовка «Коммиты», настройка устройства
`cockpit-code-commits-work`, по умолчанию включён) делает правой стороной отрезка рабочее
дерево: коммиты и несохранённые правки читаются одним дифом, как обычный diff задачи, а
неотслеживаемые файлы входят как новые. Заголовок группы и бейдж шапки получают «+ текущие».
При включённом режиме и выбранных коммитах слитый диф открывается по клику на файл в любой
группе: тот же путь есть в группе коммитов — редактор показывает его, а строка рабочего дерева
остаётся выбранной; новый файл только с диска в отрезок тоже входит, и его слитый диф равен
собственному. Так человеку не нужно искать тот же файл именно в группе коммитов.
Режим действует только для отрезка до HEAD — для более старого конца кнопка недоступна с
подсказкой и флаг молча не применяется; сервер на такой запрос отвечает `400
work_needs_head`. В запросах это `work=1` у `commits-diff`, `branch-diff`, `file-diff` и
`patch`; у `file-diff`/`patch` с флагом второй ревизии `to` нет, а ответ отрезка несёт
`range.work`.

«Вся ветка» использует тот же read-only вид и `GET …/branch-diff`. Для worktree задачи
база — общая точка HEAD и ветки основного дерева; для основного дерева — его upstream.
Ответ возвращает полный диапазон и число собственных коммитов, включая честный ноль.
Если у основного дерева нет ветки либо upstream, действие заранее недоступно, а сервер
дублирует защиту отказом `409 no_base`. Выбор отдельного коммита закрывает режим ветки.

Открытая панель тихо обновляет текущий Git-снимок после `chat-done` и при возвращении
браузерной вкладки в видимое состояние. Параллельные сигналы не размножают запросы:
они дают один повтор после уже летящего чтения. Ручная кнопка использует ту же очередь.
В разделе файлов перечитывается только выбранный файл; неактивная панель сеть не будит.
Выбор файла, отрезок коммитов и раскрытие каталогов переживают принятое обновление.

Шапка редактора разделена на два ряда. Первый называет путь и basename; справа остаются
частые действия «История», «Спросить агента» и popover «Действия файла» с авторством
строк, копированием ссылки и обновлением. Второй ряд существует только у сравнения и
явно называет обе стороны: `HEAD → индекс`, `индекс → рабочая копия`, `наша версия →
рабочая копия` для конфликта либо короткие object ID диапазона. Обычный файл не получает
Git-счётчик и настройки diff.

Настройки сравнения собраны в постоянном popover «Вид сравнения»: «Рядом / В одну
колонку», перенос длинных строк и игнорирование пробелов по краям строк. Предпочтения
сохраняются на устройстве в localStorage. Для выбранных коммитов и режима «Вся ветка»
рядом со сторонами показывается сводка по числу файлов, добавленным и удалённым строкам.
Если в группе больше одного файла, соседние стрелки и счётчик `N / всего` позволяют
пройти diff без возврата в дерево. Эта навигация не появляется у обычного файла и в
истории одного файла.

Кнопка «Обзор» в каждой группе собирает ограниченный unified patch и показывает все
его файлы одной прокручиваемой страницей с хунками и номерами обеих сторон. Патч
ограничен 2 МБ и 300 файлами; неотслеживаемые файлы входят как новые. Заголовок или
строка возвращают обычный Monaco-диф выбранного файла. Обзор кешируется только до
следующего Git-снимка, а его парсер сохраняет полные хунки при обрезанном хвосте.
В tab-порядке остаётся одна строка патча; стрелки вверх/вниз переводят этот фокус по
строкам. Поэтому большой patch не создаёт тысячи последовательных tab-остановок.

«Спросить агента» создаёт новый чат с редактируемым черновиком и ничего не отправляет
самостоятельно. Для обычного файла в черновик входят абсолютный путь, текущая строка и
до 80 выделенных строк; для Git-дифа — серверный patch одного файла до 200 строк.
Тройные обратные кавычки не закрывают ограждение. Чат из task-worktree получает id
задачи и стартует в нём, а из основного дерева остаётся обычным чатом.

Unmerged-состояния Git (`UU`, `AA`, `DD`, `AU`, `UA`, `DU`, `UD`) показываются только в
рабочей группе единым статусом `U` и красной меткой `!`. Левая сторона diff берётся из
нашей стадии индекса `:2:`, правая — из рабочего файла с маркерами конфликта. У такой
строки нет разрушительного отката: после ручного разрешения кнопка «+» выполняет обычный
`git add` с подписью «Пометить разрешённым».

Обвязка Monaco (`web/src/shared/monaco.ts`) подключает фичу `codicon` — шрифт значков
редактора. Знаки «+»/«−» изменённых строк и стрелки свёрнутых участков дифа — глифы этого
шрифта; `editor.api` его не тянет, и без фичи они рисуются пустыми квадратами. Тема
`cockpit-dark` задаёт фон изменённых строк и полей номеров не бледнее 14% и 20%.
Диагональная заливка свёрнутых неизменённых областей приглушена до вторичного слоя,
чтобы большие пустоты не были контрастнее добавленного и удалённого кода.

Кнопки шапки редактора сохраняют общий 30-пиксельный размер. Каталог в пути сжимается
раньше basename; полный путь остаётся в подсказке и доступен через копирование ссылки.
При ширине самого редактора меньше 760 px «История» и «Спросить агента» переходят в
popover действий файла, поэтому функции не исчезают и верхний ряд не переполняется.
Popover закрывается по Escape с возвратом фокуса на кнопку открытия.

Адаптивность определяется контейнерами CodePanel и редактора, а не шириной окна и не
признаком dock. При ширине CodePanel 760 px и больше навигатор и редактор стоят рядом.
Ниже 760 px видна одна область: до открытия файла — навигатор, после открытия — тот же
смонтированный Monaco. Кнопка со словесным доступным именем «К файлам», «К изменениям»
или «К коммитам» возвращает навигатор; рейка разделов остаётся слева и в узкой раскладке,
и нажатие любого её раздела тоже возвращает навигатор. Расширение восстанавливает обе колонки,
ширину навигатора, позицию и выделение. Если сам редактор уже 760 px, side-by-side diff
временно складывается в одну колонку без изменения сохранённого предпочтения; причина
показана в «Виде сравнения». Локально для этого раздела Monaco использует шрифт 13 px,
строку 20 px и вертикальные отступы 8 px; общие настройки read-only редакторов не меняются.

«История» заменяет дерево слева журналом выбранного файла до 50 записей. Сервер
использует `git log --follow`, поэтому после rename старые коммиты несут прежнее имя.
Выбор записи открывает стороны файла между первым родителем и самим коммитом; корневой
коммит сравнивается с пустым деревом. «Назад» восстанавливает прежний файл и режим,
а смена рабочей копии безусловно закрывает историю.

Переключатель Blame добавляет к строкам текстового файла приглушённые подписи с коротким
хешем, автором и относительным временем. Результат считается по рабочей копии через
`git blame --line-porcelain`; незакоммиченные строки явно помечаются «не в коммите» и не
наследуют чужой хеш. Наведение показывает тему, а клик по подписи открывает diff этого
коммита для файла. Режим хранится в `cockpit-code-blame`, повторно запрашивается при смене
файла и недоступен для изображений, бинарных и слишком больших файлов. Сервер ограничивает
ответ 20 000 строками и возвращает `413 too_big` сверх этого потолка.

- Действия строки лежат в одной обойме с заранее зарезервированной шириной, поэтому
  hover и фокус не двигают имя и не скрывают счётчик. Stage/unstage (`+`/`−`) остаётся
  прямым действием, а разрушительные «Откатить»/«Удалить» находятся в popover «Ещё».
  На точном указателе обойма проявляется по hover/focus, на touch видна постоянно.
  При ширине навигатора меньше 300 px статистика всех строк скрывается согласованно,
  сохраняя итог группы и полный путь в подсказке.
- У строки каталога та же обойма: «+»/«−» переносит в индекс или обратно все файлы группы
  под этим каталогом (граница — по «/», `src` не захватывает `src-other`); подпись
  называет каталог и число файлов. Пути берутся из свежей группы и уходят порциями не
  больше серверного потолка в 500 путей, так что большой каталог не получает отказ.
- Заголовок группы изменений сворачивает её дерево (шеврон, `aria-expanded`); счётчик и
  итог строк остаются в заголовке. Свёрнутые группы запоминаются на устройстве в
  `cockpit-code-collapsed-groups`. Журнал коммитов живёт в отдельном разделе рейки,
  поэтому его доступность не зависит от высоты рабочих групп. Заголовок остаётся сверху
  при прокрутке, а у диапазона коммитов прямо в нём есть
  действие сброса: длинный список файлов не может спрятать выход обратно в журнал.
- Stage и unstage работают с выбранными строками либо со всей группой. Имена
  передаются Git как буквальные пути, включая старое имя переименованного файла:
  символы вроде `:(glob)` не должны захватывать соседние файлы.
- Tracked-правку рабочего дерева можно вернуть к индексу через «Откатить»; staged-часть
  того же файла сохраняется. Неотслеживаемый файл удаляется отдельным действием.
  Оба пути требуют общего danger-диалога со словами «без возможности отмены»; общий
  откат группы никогда не удаляет новые файлы.
- Композер закреплён снизу раздела «Изменения» и не перекрывает прокручиваемый список.
  При пустом индексе он свёрнут до блока «Коммит · Индекс пуст» с подсказкой
  «Подготовьте файлы кнопкой +»; форму можно раскрыть и заранее написать сообщение.
  Первое появление staged-файлов автоматически раскрывает её только при высоте панели
  не меньше 600 px и пока человек сам не выбрал состояние. Черновик переживает
  сворачивание и смену раздела. Amend и soft reset находятся в popover «Ещё»; активный
  amend меняет заголовок на «Изменение последнего коммита» и имеет явный выход.
  Fetch/push вынесены из формы в отдельный нижний ряд, а полное сообщение ошибки
  показывается через компактный `UiInlineMessage`, без однострочного обрезания.
- Commit берёт только уже подготовленный индекс. Автоматического `git add` нет.
- «Дополнить последний коммит» разрешено только для локального HEAD: у ветки нет
  upstream либо она опережает его. Режим подставляет полное сообщение HEAD, допускает
  переименование без staged-правок и не предлагает force-push опубликованного коммита.
- Соседнее действие отменяет только последний локальный коммит через soft reset:
  после общего danger-подтверждения его изменения возвращаются в индекс, а полное
  сообщение — в композер. Для опубликованного, detached и корневого HEAD оно недоступно.
- Push не использует force. При отсутствии upstream публикует текущую ветку.
- «Проверить удалённый репозиторий» выполняет только `fetch --prune` и сразу обновляет локальные
  счётчики ahead/behind, не делая merge или rebase. Без remote действие недоступно;
  ошибка доступа предлагает настроить ключ или credential helper и не раскрывает URL.
- Мутации одного worktree выполняются последовательно; ошибка освобождает очередь.
- Общий `git.ts` также обслуживает приёмку задач: `taskDiff` сохраняет сравнение с HEAD.

Генерация названия коммита получает только staged diff, его статистику и недавние
заголовки. Модель берётся из настройки плагина. Разрешён только одноразовый
`runUntrusted` без инструментов, cwd, MCP и продолжения сессии. Обычный executor
не используется как запасной вариант. Ответ должен содержать единственное поле
`title` с непустой строкой; её потолок — тот же, что у ручного сообщения коммита
(`COMMIT_MESSAGE_MAX`): это страховка от ответа с diff внутри, а не правило стиля.
Длину и стиль названия задают недавние коммиты репозитория, числа в prompt нет.
Отвергнутый ответ попадает в журнал сервера с выдержкой. Генерация сама не делает
коммит.

## Типы и границы

Самостоятельная реализация плагина написана на TypeScript: Fastify-модуль,
Git-хелперы, генератор названия, панель, route/loading-компоненты, Monaco,
клиентское дерево, файловые ссылки и HTTP-адаптер. Общая оболочка Cockpit и штатные
Node-тесты могут оставаться на JavaScript.

`shared/codeContracts.ts` содержит декодеры ответов и типы, выведенные из них.
`web/src/shared/codeApi.ts` принимает JSON общего клиента как `unknown` и проверяет
все используемые поля до записи в состояние. Повреждённый ответ не становится
успешным снимком; при обновлении открытый файл, диф и введённое название не затираются.
При выборе другого файла прежняя модель снимается до запроса, чтобы старый текст
не оставался под новым именем после ошибки. Ошибка
декодирования содержит путь поля без отклонённого значения. Посторонние поля
отбрасываются. Raw-изображения остаются потоком байтов.

Серверные ответы проверяются компилятором по общим DTO. Данные запроса, результаты
JS-каталогов и модельного транспорта проходят проверку формы на входе в плагин.
Строгий режим включает `noUncheckedIndexedAccess`. Сервер использует NodeNext,
`import type`, расширения `.ts` и `erasableSyntaxOnly`.

Node исполняет серверный TS сам: минимальная версия — 22.18, где снятие типов
включено по умолчанию. Флагов запуска нет ни в командах, ни в юните; версию проверяют
`bin/lib/runtime-env.sh` и старт сервера, отказывая с понятным сообщением. Отдельной
серверной сборки и JavaScript-дублей нет. После изменения серверных файлов основной
процесс перезапускает человек после завершения агентского хода.

## Доступ и файлы

Маршруты `/api/code/*` закрыты общим auth guard и проверкой включённого плагина.
Выключенный плагин возвращает `403 plugin_disabled`. Правила доступа не зависят
от клиентского списка корней.

Сервер отклоняет выход за выбранный корень, скрывает `.git` и `.state` на любой глубине,
а также фактические каталоги переписки Cockpit из конфигурации. Одноимённые каталоги
других проектов сами по себе не скрываются. Текстовый просмотр ограничен 1,5 МБ;
бинарные и слишком большие файлы получают соответствующие признаки.

Raw-просмотр разрешает растровые PNG, JPEG, GIF, WebP, BMP и ICO до 10 МБ. SVG
исключён. Ответ содержит `nosniff` и приватный запрет кэширования.

## Проверка

Типы проверяет общая команда среды: `npm --prefix server run typecheck` и
`npm --prefix web run typecheck`. Они входят в `npm test` своих пакетов и накрывают весь
собственный TypeScript, а не отдельный раздел. `typecheck:code` остаётся быстрой
проверкой одной области при работе над ней.
Отрицательные примеры в `tests/types/code-contract.test.ts` и
`tests/types/code-server-contract.test.mts` запрещают ослаблять контракт до
непроверенного JSON или стирать различия между успешным результатом и отказом.

Серверные тесты проверяют сериализованные HTTP-ответы общими декодерами. Git-действия,
включая commit, push, unborn, переименования и конкуренцию, выполняются только во
временных репозиториях. Модель заменяется контролируемым транспортом. Компонентные
тесты используют настоящий HTTP-адаптер и декодеры, проверяя гонки запросов,
повреждённые ответы, очередь намерений и освобождение Monaco.
