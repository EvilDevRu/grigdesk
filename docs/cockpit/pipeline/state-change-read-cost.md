# Перечитывать по каждому state-change можно только дешёвое

На этой грабле умерла карточка «Слоты запуска» на странице конвейера, и удалили её именно
поэтому. Она перезагружалась по каждому SSE `state-change`, а тот при живом прогоне приходит
раз в 300 мс (`plugins/sse.js` — дебаунс `fs.watch` по `~/.factory/state`). Каждый запрос
спавнил `factory slots` — процесс движка с таймаутом 20 с. Пока он шёл, приходило следующее
событие, ответ возвращался уже устаревшим и отбрасывался сторожем свежести, а флаг загрузки
сбрасывал только самый свежий запрос — который тут же вытеснялся следующим.

Итог: блок навсегда пустой и навсегда в состоянии «обновляю», плюс шторм процессов на мозге.
Тесты этого не видели — фейковый API в них отвечает мгновенно, и ни один не слал событие
поверх летящего запроса.

Правило: на `state-change` вешать только дешёвое чтение. Дорогое (shell-out, обход каталогов)
— по своему событию, по явному действию или по редкому poll, и обязательно с single-flight,
чтобы перекрывающиеся вызовы не выедали друг друга.
