# Транзакционный узел БЕЗ пары instrument делает маршрут заложником формы запуска

Соседняя беда той же семьи, но опаснее: узел с `policy.filesystem = transactional-write`
законен где угодно, а работать может только при открытой транзакции инструментации. Если
пары `instrument` в маршруте нет, транзакцию открывает сам узел — но лишь при наличии
файла scope (`_route_v2_transaction_before`, строки про
`ROUTE_V2_INSTRUMENTATION_SCOPE_FILE`). Файл создаётся из `--instrumentation-file`
**при `start`** и только там: у `resume` такой опции нет вовсе.

Отсюда инверсия, которую в определении маршрута не видно: список файлов, куда агент
будет ставить временные логи, приходится назвать РАНЬШЕ, чем план решит, что вообще
менять. В маршруте диагностики это нормально (файлы диктует воспроизведённый баг), в
маршруте реализации — нет.

Цена ошибки максимальная из возможных: отказ приходит не на старте, а на заходе в сам
узел, то есть **после** `build` и `review` — час работы и деньги уже потрачены. В журнале
при этом одна строка `dispatcher остановлен fail-closed (код 78)`, каталога сторожа у
узла нет, `logs/runs/<TASK>/<STAGE>/` не создан вовсе: агент не запускался, и выглядит
это как поломка движка, а не как незаполненный вход.

Живой случай: маршрут `feature` одного из профилей нёс узел `trace`
(`transactional-write`) без `instrument`. Прогон типизации фронта дошёл до него за час,
упал 78, и `resume` упирался бы туда же — контракт не выполняется детерминированно.
Узел убран, трассировка осталась в `debug`, где для неё есть штатная пара
`instrument` → `proof`.

Правила:

- **`transactional-write` без `instrument` в том же маршруте — ошибка проектирования.**
  Либо ставь пару, либо не бери политику;
- запуск такого маршрута из UI формой блокируется («Маршрут требует хотя бы один файл
  инструментации»), а **через API — нет**: пустой scope доезжает до движка и взрывается
  на середине. Проверка формы не является контрактом;
- справка движка обещает требование только для узла `instrument` («Маршрут с
  транзакционным узлом instrument требует хотя бы один --instrumentation-file при
  start»), тогда как код проверяет ЛЮБОЙ транзакционный узел. Читать надо политику
  узлов, а не эту строку;
- сторож проектных маршрутов должен запрещать транзакционный узел там, где нет
  `instrument` (`profiles/<профиль>/routes/definition.test.mjs`) — иначе удалённая мина
  вернётся следующей правкой определения.
