# «Ход завис — молчит N мин» сразу после «Продолжить» = молчание считали по журналу убитого хода

Симптом: прогон оборвался по TERM (выключили машину, остановили прогон). Утром человек
жмёт «Продолжить», и в первую же минуту приходит «Ход завис — #<TASK>» с текстом
«<этап>: молчит 599 мин». Число равно времени с последней записи хода, оборванного
накануне. Новый ход в это время ещё готовится и журнала не завёл, а через минуту уже
работает.

Причина: обработчик TERM в движке останавливает раннер, но этап в реестре остаётся
`running`, а `ACTIVE_RUN_<STAGE>` — ссылкой на убитый ход. Это fencing-токен: его
сбрасывает только фиксация результата, а заменяет регистрация следующего хода
(`run_state_begin`). До неё возобновлённый оркестратор проходит подготовку узла
(проверку исполнителей, lease) — у живого прогона это около минуты. Всё это время
`readRunSilence` брал возраст журнала убитого хода и выдавал его за молчание агента.
Демон уже жив, поэтому сводка выглядела как работающий прогон с зависшим агентом.

Правило: молчать может только ход, чей раннер жив.

- `activeRunArtifacts(..., liveOnly)` сверяет паспорт хода из его `meta.env` с `/proc`:
  `PID` и `STARTTIME` — поле 22 `/proc/<pid>/stat`, launcher записывает его при старте.
  Номер без времени старта ничего не доказывает: после перезагрузки его получает
  посторонний процесс.
- Раннер ушёл — `silence: null`, и в модалке этапа прочерк вместо цифры. Паспорта нет
  (launcher ещё не дописал `meta.env`) — ход считается живым, как раньше.
- Лента действий (`readAgentLive`) фильтр не применяет: после обрыва она по-прежнему
  показывает, что ход успел сделать.
- Обрыв при мёртвом демоне сообщает `detectStall` («Конвейер оборвался»), а не детектор
  молчания: у них разные вопросы.

Родственная беда — [«Нет событий N мин» на штатной паузе](active-run-freshness.md): там
`ACTIVE_RUN` у не бегущего этапа, здесь — у бегущего этапа с мёртвым раннером.

Проверка — `tests/server/factory-activity.test.js` («a run whose runner is gone is not read
as silence»): завершившийся раннер, чужой процесс под тем же номером и живой раннер.
