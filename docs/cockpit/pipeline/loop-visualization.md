# Петля агентов видна без наведения

Режим задаёт `loop: { lead, worker }` закреплённого маршрута. `buildRouteGraph` сохраняет
пару для редактора и просмотра; `FactoryStateAdapter.routeDef` передаёт её из бандла и
добавляет в граф задачи `loopProgress: { round, stage, maxRounds }` из `LOOP_*` реестра.
Это проекция для интерфейса, а не источник разрешений или решений движка. Неизвестное
значение остаётся `null`; нулевой круг означает постановку до первой передачи исполнителю.
Счётчик обычных возвратов `loops` режим петли не включает и номер круга не заменяет.

В карточке, включая свёрнутую, `LoopStatus` показывает номер круга с потолком, этап и
текущую работу пары. Число пройденных узлов в полосе прогресса остаётся отдельным показателем.
В `FactoryGraph` обе передачи пары видны независимо от переключателя возвратов: синие
стрелки «Задание на круг» и «На проверку». Над узлами подписаны роли. Возврат ведущего
является штатной работой, поэтому красный цвет обычных фактических возвратов к нему не относится.

Движется только связь, входящая в выполняющийся узел пары; вокруг его значка вращается
дуга. Нужны одновременно `daemonAlive=true`, `status=run` и отсутствие `stall`.
Первичная постановка не изображает проверку ещё не полученного результата. После начала
кругов стартовая связь не анимируется одновременно с передачей пары. На паузе, остановке,
приёмке и в эталонной схеме петля статична. При `prefers-reduced-motion` движение отключено,
но подписи, направление стрелок и выделение активного агента сохраняются.

Проверки: `tests/server/routes-loop-mode.test.js` проводит пару через опубликованный бандл
и граф задачи; `tests/web/factory-graph.component.test.js` проверяет передачу, первый вход,
счётчики, паузу, приёмку и эталон. Изменение DTO требует ручного перезапуска сервера после
обновления кода; старая версия API не содержит пару и счётчики.
