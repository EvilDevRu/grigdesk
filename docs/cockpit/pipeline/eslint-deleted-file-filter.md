# VERIFY встал «ESLint не стартовал: No files matching the pattern» = в diff удалённый файл, статика линтовала его

Симптом: VERIFY feature-маршрута встал на человеке с комментарием «ESLint не стартовал:
Oops! Something went wrong! … No files matching the pattern "src/…/Компонент.vue" were
found» (finding `verify-check-tool-unavailable`, владелец `environment`). Стенд при этом жив,
ESLint на месте, а названный файл в дереве ОТСУТСТВУЕТ.

Причина: сборка удалила файл по плану (компонент заменён общим модулем), а статика
`feature-verify.py:static_checks` брала список файлов из `changed_paths` — это
`git diff --name-only HEAD` + untracked, и удалённые там тоже есть. ESLint на несуществующем
пути не «чист», а падает кодом 2 — движок честно считает это отказом инструмента и зовёт
человека. `php -l` на удалённом PHP дал бы то же с владельцем `build`. Квадратные скобки
`[id]` в пути ни при чём: на существующем файле ESLint 9 их принимает.

Что сделано (16.09.2026): статика (php -l, Pint, ESLint) и подбор тестов light-режима
(`diff_tests`) берут только существующие файлы (`present()` в `static_checks`). Проверка —
`profiles/<PROFILE>/tests/feature-verify-check.sh` (фейковый eslint в фикстуре записывает
аргументы; удалённый файл до него не доходит).

Как продолжить живую задачу: это command-узел, агента у него нет — «перейти сюда» на `verify`
после починки скрипта профиля, resume перезапустит его с новым кодом. На 8702 повторный
VERIFY нашёл настоящее стилевое замечание Pint у сборки и сам вернул курсор на BUILD.
