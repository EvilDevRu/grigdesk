# Пустая карточка Входящих = сообщение приехало в формате rich (Bot API 10.1)

Симптом со стороны человека: во Входящих карточка пустая, задача из неё получается
бессодержательной («в обращении нет текста»), а в самом Телеграме у этого сообщения есть
и текст, и видео. Автоматика такие карточки молча пропускает, и обращение исчезает
бесследно.

Причина не в разборе и не в приватности бота: с **Bot API 10.1 (11.06.2026)** содержимое
приезжает деревом `message.rich_message.blocks`, а привычные `text`, `caption`, `video`
у такого сообщения ПУСТЫ. Нормализатор знал только плоскую форму, поэтому в архив падал
ряд `text:"" media:[]` — терялось не вложение, а всё содержимое целиком.

Как опознать:

```text
archive/<chatId>/<месяц>.ndjson: {"text":"","media":[], ...}   # в Телеграме сообщение непустое
```

Быстрая проверка — переслать сообщение боту в личку: запишется так же пусто, значит дело
в форме сообщения, а не в правах бота в группе. Чтобы увидеть поля апдейта, достаточно
временно залогировать `Object.keys(update.message)` в поллере: у rich там нет ни `text`,
ни медиаполей, зато есть `rich_message`.

Как достать содержимое, пока сервер ещё на старом коде: `forwardMessage` боту в его же
личный чат — ответ Bot API отдаёт объект Message целиком, включая `rich_message` с
`file_id`; копию потом убирает `deleteMessage`. `copyMessage` не годится: он возвращает
только идентификатор копии.

Где чинится: `server/src/lib/telegram/updates.ts` — блоки разворачиваются в плоский
контракт (текст склеивается из абзацев и подписей, файл берётся из медиа-блока).
Две ловушки разбора:

- подпись медиа-блока приходит НЕ строкой, а оформленным фрагментом (`{type:"url",
  text, url}`), поэтому текст читается рекурсивно по `text`, иначе ссылка теряется;
- виды вложений обязаны совпадать со списком `MEDIA` в `telegram/inboxChannel.ts`.
  Разъехались списки — `attachmentOf` роняет разбор архивного ряда ЦЕЛИКОМ
  (`telegram_inbox_invalid_archive`), то есть карточка не собирается вовсе, а не
  теряет одно вложение. Стык закреплён `tests/server/telegram-rich-message-inbox.test.js`,
  сам разбор — `tests/server/telegram-rich-message.test.js`.

Побочная деталь того же разбирательства: `fetch` из Node к `api.telegram.org` с хоста
рвётся на TLS (`ECONNRESET`), потому что в VPN уходит только IPv4-маршрут, а undici
успевает уйти в IPv6. `curl -4` с тем же токеном работает — при ручных проверках Bot API
это экономит полчаса ложной диагностики «Телеграм недоступен».
