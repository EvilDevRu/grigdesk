Протокол route v2 (ветка `wip/pr-review-checkpoint`, июль 2026) затеян из-за инцидентов v1:
схема исполнялась с ошибками — на этапе с запретом записи агент писал trace-verify-инструментацию
(старый guard по именам файлов + автооткат маскировали нарушение), плюс несостыковки между
тремя источниками правды (profile.sh, graph.json, шаблоны агентов с промптами через sourcing bash).

Принятый курс: **агент — переиспользуемая сущность-шаблон (только рекомендация), маршрут — immutable
content-addressed бандл со своими промптами по узлам**; исполняемая политика модели — только
`runners.env`; файловые политики узла явные (`state-only`/`workspace-write`/`transactional-write`),
запись при отладке легализована транзакцией инструментации вместо ложного «readonly».

**Why:** без этого контекста правки движка выглядят как параноидальное ужесточение; на деле каждая
(доказательный workspace-guard, вырезанный автооткат, trusted identity) — ответ на конкретный отказ.

**How to apply:** при доработках v2 держать принцип «один владелец у каждой сущности» и fail-closed:
рантайм не должен молча игнорировать поля бандла (retry/fanout/command на июль 2026 не реализованы —
предложено отклонять такие бандлы до реализации). См. [[no-project-hardcode-in-engine]].
