# Пробный профиль движка для 3a

Синтетический профиль для задачи фабрики на устройстве (без платных вызовов).
Контракт профиля — `docs/engine/PROFILE-CONTRACT.md`; проверка — `bin/factory-check`.
Профиль создаётся на машине приёмки по образцу локального `profiles/<имя>/`
(каталог вне Git) и кладётся в `FACTORY_HOME/profiles/probe3a/` пробной установки.

Обязательная проводка пробы:

- `runners.env`: исполнитель `qwen` (настоящий CLI из поставки GrigDesk),
  `OPENAI_BASE_URL=http://127.0.0.1:47900/v1`, `OPENAI_API_KEY=probe-3a-synthetic-key`
  (значения из `device-fixture.mjs`, синтетический ключ, не секрет).
- Первый этап маршрута: запуск qwen-раннера в проекте; результат этапа обязан
  содержать уникальную метку `probe-3a-<runId>-answer-N` из ответа фикстуры
  (проверка по ledger и `fixture-requests.jsonl`).
- Второй этап: хук ждёт барьер тестового API
  (`curl http://127.0.0.1:47900/barrier`) — во время этого ожидания выполняется
  `adb shell am force-stop local.grigdesk.mobile.probe`.
- После повторного открытия APK: `bin/factory <T> resume` продолжает с последней
  подтверждённой границы этапа; результат первого этапа не переигрывается.

Состояние задач — во внутреннем приватном каталоге probe-приложения
(`GRIGDESK_HOME` сервиса), не в каталоге основного клиента.

Статус: профиль и проводка проверяются на DEVICE-приёмке (DEVICE PENDING);
исполнитель подготовил фикстуру, оболочку и команды (см. ../README.md).
