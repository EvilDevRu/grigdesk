# Кокпит — общие правила

Подробные контракты Кокпита живут в `docs/`; здесь — обязательные правила и карта.
Контракт браузерного журнала: [журнал окна](docs/cockpit/guide/web-log.md).

## Язык

Всё общение и комментарии в коде — **на русском**. Тексты интерфейса также русские.

## Читаемость кода

- Разделяй пустыми строками imports, типы, входной контракт, состояние, вычисления,
  действия и lifecycle. Проверки, подготовка, эффект и возврат внутри функции не слипаются.
- Несколько statements, полей объекта и веток не ужимаются в строку. Block-body всегда
  многострочный с фигурными скобками; строки кода ограничены 110 символами.
- Перед нетривиальной именованной функцией нужен многострочный русский комментарий о цели,
  инварианте, эффекте или причине. Очевидные короткие getters/adapters/callbacks — исключение.
- Vue SFC — `PascalCase.vue`, TypeScript — `lowerCamelCase.ts`; порядок SFC:
  `template → script → style`.

## Контекст и работа в общем дереве

- `docs/` — источник истины; отдельной памяти исполнителя нет. При расхождении проверь факт и
  исправь канонический документ в том же заходе.
- Общая документация не содержит реальных профилей, доменов, task ID и локальных путей.
- Незакоммиченные изменения принадлежат человеку: меняй только область задачи, не откатывай,
  не переформатируй и не прибирай соседнее. Не делай commit/push/PR и не меняй ветку без
  прямой просьбы.
- **Чужие процессы — тоже человеческие.** Не останавливай то, чего не запускал сам, даже если
  машина перегружена: `ppid=1` и `systemd --user` значат «отвязан намеренно, чтобы пережить
  ход», а не «брошен», а растущий лог в `.state/artifacts/` значит, что результата ждут.
  При перегрузе — назови виновников человеку и спроси, а не прибирай сам.
- Временные скриншоты, дампы и результаты проверок сохраняй в `.state/artifacts/`:
  этот каталог исключён из git.
- Не читай переписку и приватное состояние; не публикуй секреты и runtime identifiers.
- Если проверке нужен пароль или ручной шаг, коротко спроси человека через панель действий
  и жди ответа. Сначала закончи независимое; обходной стенд — только после отказа, с явным
  ограничением.

## Границы реализации

- Сервер — Fastify-модули в `server/src/modules/<тема>/`, общая логика — в `server/src/lib/`.
  Новый `/api` закрыт общим auth guard; публичность — явное исключение.
- Web-компоненты лежат в `web/src/views/` или `web/src/shared/`, состояние — в Pinia stores.
  Поток SSE один на вкладку: свой `EventSource` компонент не создаёт.
- **UI имеет одну публичную границу.** Product-код импортирует controls/dialogs только из
  `web/src/ui.ts`; native controls принадлежат primitives. Системный `confirm()` запрещён —
  используется общий диалог проекта. SFC не заводит локальный control skin.
- Новый исполнитель ИИ — отдельный файл в `server/src/lib/executors/`; ядро чата и Vue не
  ветвятся по вендору. Возможности объявляет адаптер, модели берутся из живого каталога.
- B24-сессией владеет сервер. Мутации фабрики идут через `factory`; `flock` на `orch.lock`
  запрещён. Профили и пути приходят из config/env/настроек — хардкодов проекта нет.
- Auth закрывает весь `/api`, чтение и WebSocket. Недоверенный текст не получает
  tools/workspace/MCP/session без безопасного контракта; опасные действия подтверждает человек.

## Сервер, проверка и выкладка

- Cockpit host-native; браузер — окно. Realtime использует общий `/api/events`.
- **Агент из чата — дочерний процесс сервера: перезапуск изнутри такого хода убивает
  исполнителя и ответ.** После серверных правок проси ручной перезапуск; сам процесс не
  останавливай и не перезапускай.
- Сначала запускай относящиеся `node --test`, затем `bash tests/run-all.sh`. Сборка web пишет
  в используемый `web/dist`: `npm --prefix web run build` запускают после зелёных тестов.
