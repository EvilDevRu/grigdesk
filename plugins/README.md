# Пользовательские плагины

Плагин = папка `<папка данных>/plugins/<id>/`:

- `plugin.json` — манифест: `{ "id", "api": 1, "name", "description", "version", "nav": {"path","label","icon","group?","order?"}, "web": "web", "settings": [{"key","label","type","options?","default"}] }`
- `server.js` — опционально: default-экспорт fastify-плагина, роуты под `/api/ext/<id>/…`. Регистрируется на старте сервера (вкл/выкл — рестарт).
- `web/` — опционально: своя страница (`index.html` и что угодно рядом, без сборки). GrigDesk
  раздаёт папку под `/api/ext/<id>/web/` только включённому плагину и показывает страницу
  панелью-iframe в правой рейке (`nav.group: "dock"`) или страницей по ссылке в сайдбаре.
  Адрес страницы всегда `/ext/<id>` — `nav.path` у такого плагина не участвует. Страница
  живёт на том же origin с той же сессией и ходит в `/api/…` сама: в свои роуты из
  `server.js` и в общие ручки GrigDesk. Ядро её код не исполняет; снёс папку — пункт исчез.
- `docs/README.md` — опционально: документация плагина для агентов GrigDesk (раздел
  «Документация» ниже). Место постоянное, манифест его не настраивает.

Включение — «Настройки → Плагины» (по умолчанию пользовательский плагин выключен).

`placements` — `[{"slot","default?"}]`: слоты интерфейса, которые плагин умеет занимать
(контракт — `docs/grigdesk/guide/plugins.md`); незнакомый слот пропускается с предупреждением.
Тумблеры мест — в настройках плагина. Загрузка модульной панели api2 не регистрирует размещения в слотах: они пока
только объявляются.

Роуты `server.js` автоматически заперты в префикс `/api/ext/<id>/` (перекрыть системные пути
нельзя). Поле `api` — версия контракта (`1` или `2`); несовместимый плагин не поднимается.
Код плагина исполняется в процессе GrigDesk с его правами — устанавливай только доверенный.

`nav.group` выбирает размещение ссылки: `rail` — основная навигация (и значение по
умолчанию для отсутствующего/невалидного поля), `tools` — агрегатор «Инструменты»,
`dock` — правая рейка встроенных панелей. `nav.order` задаёт порядок внутри группы;
при равенстве элементы сортируются стабильно по подписи и id.

Для прежнего формата api1 пункт появляется только у ВКЛЮЧЁННОГО плагина,
чья страница существует во фронте.
Страницы системных плагинов собраны в бандл; у пользовательского плагина страница — его
папка `web/` (выше). Плагин без `web` пункта в навигации не получает: ссылка вела бы в
никуда, и клиент честно её скрывает. В формате api1 Vue-код плагина в SPA не загружается: панель — общий
iframe, а произвольный код из JSON в реестр `shared/tools/registry.ts` не попадает.

## Модульная панель (api: 2)

Доверенный плагин может привезти готовый браузерный ESM с default-экспортом
Vue-компонента: объект с `setup`/`render` или функцию. Шаблон должен быть скомпилирован
заранее. Runtime-компилятор шаблонов не предоставляется. Пакет кладут папкой; установка
api2 из Git и каталог сайта в эту порцию не входят.

```json
{
  "id": "my-panel",
  "api": 2,
  "name": "Моя панель",
  "version": "1.0.0",
  "webModule": {
    "dir": "ui",
    "entry": "panel.js",
    "css": ["panel.css"],
    "locales": { "ru": "ru.json", "en": "en.json" }
  }
}
```

`dir` — собственный непустой подкаталог пакета, остальные пути относительны ему.
Entry имеет расширение `.js` или `.mjs`; `css` и `locales` необязательны. Абсолютные
пути, выход из каталога, схемы URL, query/hash, скрытые компоненты и ссылки запрещены.
Языки, кроме ru/en, не подключаются. Все объявленные ресурсы должны существовать.
В `/api/plugins` поле `web` остаётся строкой или null; отдельное поле `webModule`
содержит entry/css/locales с адресами `/api/ext/<id>/module/…`, без файловых путей.
Выдача закрыта общей сессией и регистрируется только для включённого при старте плагина.

Без `nav` валидный модуль получает ссылку по имени плагина с иконкой `plugin` и группой
`dock`. Явные `nav.group`/`order` сохраняются. Адрес панели — `/ext/<id>`; от 900 px
она также доступна в рейке и разворачивается во всё окно. Кнопки «Открепить» нет.
Если объявлены и `web`, и `webModule`, открывается модуль; при его отказе остаётся
сообщение об ошибке. Формат api1 и его iframe сохраняются.

Импортируйте Vue из `vue`, а UI только из `@grigdesk/ui`: оба имени карта модулей
разрешает в экземпляры текущего окна. Фасад UI открывает все runtime-экспорты
[web/src/ui.ts](../web/src/ui.ts): кнопки и поля, выбор и вкладки, составные контролы,
диалоги, подтверждения, подсказки, сообщения, тосты, язык и диагностику слоёв.
Не включайте свою Vue/UI в bundle, не создавайте app, DialogHost, TooltipHost или
EventSource. Общие hosts дают диалоги поверх окна и единый порядок Escape.

Панель получает props `context`, `active`, `compact`, `presentation`.
`context` содержит:

- `pluginId` — id пакета;
- `api.get/post/put/patch/del` — общий клиент с сессией и обработкой 401, только `/api/…`;
- `locale.value` — readonly текущий язык;
- `settings.value` — глубоко readonly актуальные эффективные настройки;
- `t(key, params?, fallback?)` — перевод из своих JSON-словарей ru/en с именованными
  параметрами; запасной язык ru, затем явный fallback или сам ключ.

Смена языка и настроек обновляет панель без пересоздания и потери ввода.
Настройки сохраняются через общий раздел настроек плагина. CSS выпускается отдельно и
перечисляется в `css`: обычный CSS-import внутри готового ESM не поддержан. Ограничивайте
селекторы своим корнем панели; CSS не изолирован. Стили самой UI-библиотеки уже есть в окне.

Пример исходника с render-функцией:

```js
import { h } from 'vue';
import { UiButton, confirmDialog } from '@grigdesk/ui';

export default {
  props: ['context'],
  setup(props) {
    return () => h(UiButton, {
      onClick: () => confirmDialog(props.context.t('question')),
    }, () => props.context.t('open'));
  },
};
```

Сборка (esbuild — зависимость проекта автора):

```sh
npx esbuild src/panel.js --bundle --format=esm --outfile=ui/panel.js --external:vue --external:@grigdesk/ui
```

Положите CSS и ru/en JSON рядом в `ui`. Для SFC сначала скомпилируйте компонент обычной
сборкой автора, сохранив эти же external. Общие компоненты не нужно копировать в пакет.

Ядро запускается независимо от карты модулей. Если карта недоступна или указывает на
другие экземпляры Vue/UI, панель объясняет несовместимость на языке окна. Загрузка
ограничена 30 секундами; ошибки JS/CSS/переводов и отрисовки остаются внутри панели.
Это граница ошибок доверенного кода, а не sandbox. В dev правка загруженного графа UI
вызывает полную перезагрузку, чтобы внешние импорты сохранили общую identity.
Изменённый модуль или стили плагина подхватываются после перезагрузки окна; повтор после
ошибки загрузки — тоже.

Перед включением api2 обновите сервер и пакеты окон desktop/Android. Обнаружение и
включение с перезапуском остаются прежними. События, управление доком, слоты, отдельное
окно и пакет типов автора сюда не входят. Устройство ядра —
[модульные панели](../docs/grigdesk/plugins/plugin-ui-modules.md).

## Документация

Документация плагина живёт в нём самом, а не в GrigDesk: она приезжает с пакетом и
уходит вместе с ним. Структура всегда одна:

```text
docs/
  README.md        — оглавление
  <тема>.md        — документы
```

GrigDesk сам находит `docs/README.md` у включённых плагинов и в каждом ходе чата
называет агенту путь к оглавлению вместе с именем и описанием из манифеста. Выключил
или удалил плагин — его документация из подсказки исчезла. Агент Claude получает
право читать `docs/` без вопроса человеку, даже если разговор идёт в другой папке.

Оглавление устроено как README областей `docs/grigdesk/`: заголовок, строка о том, что
делает плагин, затем разделы «Контракты», «Устройство», «Грабли» — по строке-ссылке
на документ. Документ — один факт или контракт, имя — короткое английское
`kebab-case.md`, текст — русский. Ссылки только относительные: установленная копия
лежит не там, где репозиторий. Документация едет на любую установку, поэтому в ней
нет секретов, путей и имён конкретной машины. `docs/` — обычная папка, `README.md` —
обычный файл: ссылка на их месте не принимается. Устройство —
[документация плагина](../docs/grigdesk/plugins/plugin-docs.md).

## Версия для установки из git

Манифест может указать `minGrigDeskVersion: "X.Y.Z"` и
`install: { "npm": [".", "server"] }`. Каждый выбранный каталог содержит
`package.json` и `package-lock.json` v2/v3. Без `install.npm` корневой lockfile
выбирает корень автоматически. Runtime dependencies требуют lockfile; Git/file/URL
зависимости и workspaces не поддержаны. Npm scripts при подготовке не исполняются.
Пакет повторно проверяется после npm; подробности и пределы —
[контракт установки](../docs/grigdesk/plugins/user-plugin-install.md).

Публикуйте тег `vX.Y.Z`, совпадающий с `version` в `plugin.json`; предпочтителен
аннотированный тег. Установленную копию не правят: разработка и выпуск версии
происходят в репозитории плагина. Рекомендуемый `.gitignore`:

```gitignore
node_modules/
__pycache__/
.runtime/
.env
.env.*
```

## Данные и остановка для замены

`options.dataDir` — отдельный каталог для долговечных данных, браузеров и cache.
Он остаётся на месте при update/rollback. `options.lifecycle` — mutable объект:
`busyReason` служит диагностикой, `prepareReplace(signal)` возвращает удерживаемый
lease. Плагин с фоновой работой обязан закрыть новый допуск, остановить своих
workers/внешних CLI и дождаться завершения до возврата lease. Один busyReason
этого не делает; legacy server без hook требует выключения и ручного рестарта.

Пример для плагина **без фоновых работ**; `replacing` также проверяют его изменяющие
handlers перед новым действием:

```js
let replacing = false;

options.lifecycle.busyReason = () => null;
options.lifecycle.prepareReplace = async (signal) => {
  if (signal.aborted || replacing) {
    throw new Error('Замена сейчас недоступна.');
  }

  replacing = true;

  return {
    async finish(outcome) {
      if (outcome === 'reverted') {
        replacing = false;
      }
    },
  };
};
```

`installed` и `blocked` сохраняют остановку до перезапуска. Не переносите этот
пример на измеритель с процессами: его атомарная остановка и восстановление —
отдельный контракт. Подробнее — [runtime lease](../docs/grigdesk/plugins/plugin-install-runtime.md).
