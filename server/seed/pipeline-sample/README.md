# Общий образец конвейера

Каталог `profile/` копируют вручную в новый локальный каталог конфигурации.
Это ресурс комплекта, а не действующая конфигурация: исходный `project.json` содержит
незаполненные поля, capability `route-v2` выключена. Автоматической установки нет.

Все проектные значения задаются только в `profile/project.json`: репозитории и ветки,
правила продукта, режим работы, команды проверок и подготовки, интерфейс и адреса стенда,
стек, запреты, разрешения, способ сдачи, исполнители и точные модели. Инструкции этапов
и определения маршрутов одинаковы для разных проектов.

Маршруты без разведки:

- `feature`: план по TDD для более слабой модели → независимый скептик другой моделью →
  утверждение плана → тесты до кода → сборка → командная проверка → приёмка → аудит →
  приёмка человеком → сдача.
- `small`: сборка → командная проверка → ревью с мелкими исправлениями → перепроверка →
  приёмка за 15 минут → приёмка человеком → сдача.
- `debug`: воспроизведение → диагноз → сборка → командная проверка → ревью → перепроверка →
  приёмка → приёмка человеком → сдача.

Первый агент составляет пункты постановки и карту с разделом «Как принято у нас».
План и диагноз начинаются разделом «Коротко для человека». Приёмка проверяет всю задачу;
пропуск, недоступность обязательного стенда и решение человека останавливают маршрут.
Ошибку закреплённых тестов BUILD возвращает TESTS, не переписывает её сам.

`isolated` создаёт независимые локальные Git-копии без hardlinks, сети и стенда. Проверка
идёт командами. Копии и коммиты сохраняются после `down.sh`; их адрес есть в отчёте сдачи.
В source ветка задачи при способе `commit` не появляется. Место для копий очищает владелец
после получения результата. `shared` использует чистый checkout и уже работающий стенд;
его процессы и данные образец не создаёт и не останавливает.

Для проекта с интерфейсом браузер обязателен. Интерфейс вместе с `isolated` допускается,
но приёмка остановится у человека: стенда в этом режиме нет. Для работы с интерфейсом
выберите `shared`. Сейчас transport требует оба URL вида `http://<host>:<port>` с одним
хостом, явными портами и без пути; HTTPS не поддерживается. Ограничение относится и к
`shared` без интерфейса. Health проверяется только объявленными argv-командами.

Можно использовать одного поставщика ИИ, но автору и скептику нужны разные модели.
`configure.py --factory <absolute-factory-cli>` проверяет описание и через штатный CLI
создаёт canonical `runners.env`. Само чтение `profile.sh` ничего не исполняет из проекта.

Сдача выбирается в декларации: `commit` (умолчание) оставляет локальный коммит в копии;
`merge` делает только fast-forward целевой рабочей ветки без PR; `pull-request` отправляет
ветку и вызывает объявленную команду PR. Remote копируется из source, не остаётся ссылкой
клона на локальный checkout. Сдача требует утверждённой приёмки и точного pin попытки.
В CLI сдачи пути перечисляются отдельно: `--path <repo>:<relative-path>`; чужие файлы не
попадают в коммит. Допускаются только имена файлов, включая удалённые tracked-файлы;
каталоги отвергаются, шаблоны не разворачиваются. В shared способ `pull-request` отказывает
до stage, commit или push: отдельной ветки задачи в этом режиме нет. Для PR нужен isolated.
PR-команда получает подстановки отдельных аргументов `{branch}`,
`{target}`, `{repo}` и должна повторно находить существующий PR после прерванного вызова.

Короткая приёмка small проверяет всю постановку за 15 минут; дополнительный обзор ограничен
одной мобильной шириной, консолью, журналом и ближайшим соседом. Ревью исправляет только
однозначные мелочи: до 30 строк на замечание и до 3 файлов всего, без миграций, зависимостей,
контрактов и env. Если хоть одно замечание крупнее, ревью ничего не правит и возвращает блокеры.

`checks.tests` требует безопасную обёртку проекта и ровно один аргумент `{files}`: файлы
подставляются отдельными argv. Пустой охват не запускает весь набор. `checks.style` отдаёт
JSONL `{path,line,rule,message}`; учитываются только добавленные строки diff. `prepare`,
`style`, `build` могут быть пустыми. Все команды исполняются без shell и с timeout.

Порядок ручного подключения, публикации с CAS и включения capability описан в
`docs/grigdesk/pipeline/profile-sample.md` и `docs/engine/NEW-PROJECT.md` исходников GrigDesk.
Publisher получает модуль схемы через абсолютный `GRIGDESK_ROUTES_KIT`; в комплекте это
помощник `server/runtime/helpers/routes-publish-kit.mjs`. Публикация требует явный store
и expected catalog hash; текущая конфигурация машины по умолчанию не выбирается.
