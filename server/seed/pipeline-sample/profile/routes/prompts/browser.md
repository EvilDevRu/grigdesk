# Приёмка всей задачи

## 1. Проверка постановки целиком

Проверь всю задачу целиком: постановку, все критерии, решения человека, карту соседей и режимов,
правила продукта, «Как принято у нас» и diff. План — справка, объём не сужается.
Если интерфейса нет, приёмка выполняется без браузера: объявленные тесты и конкретные команды
доказательства каждого критерия. Если интерфейс есть, браузер обязателен: открой заданный стенд,
пройди все сценарии постановки и докажи каждый критерий, включая требуемые им данные и режимы.
Не поднимай стенд. Интерфейс + isolated без стенда или недоступный shared останавливают у человека.
Невозможность доказательства не означает успех; «пропущено» не продолжает маршрут.

## 2. Дополнительная проверка интерфейса и соседей

Проверь пустые и неудобные данные, узкое и широкое окно, консоль, относящийся журнал,
соседние сценарии и режимы карты. В small объём этой части уточняет browser-budget.md;
все пункты части 1 остаются обязательными.

## 3. Доказательства и результат

Сохрани t<task>.acceptance.json в workspace.stateDir: schema=1, taskId, attemptId, runId,
mode=commands|browser, criteria[{criterion,status:passed,evidence:<адрес сохранённого доказательства>}].
Нужна запись для каждого acceptanceCriteria, а без них — для каждого пункта постановки.
В description пункты отделяются маркерами Markdown: 1., 1), -, * или + в начале строки.
В criterion перенеси текст пункта без маркера, сохрани переносы строк и убери пробелы по краям
каждой строки. Текст до первого пункта тоже требует отдельной записи; без списка — вся постановка.
Для browser дополнительно url заданного стенда и browserEvidence с адресом сохранённого evidence.
Хост проверяет отчёт точного запуска после результата, screenshots не доказывают себя структурой.
Продуктовый дефект — failed build/tests/plan по раннему источнику, недоступность — environment,
решение — human. Done только после всех проверок и сохранения доказательств.
